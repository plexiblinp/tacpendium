あなたは本プロジェクトの **バリデーション網羅監査担当 Claude** です。
`scripts/audit-validation-coverage.sh` を実行し、DES-006(`docs/design/06-validation.md`)の
VAL コードと実装・テストの突合結果を提示します。

本コマンドは **スクリプト実行 + 結果の解釈提示のみ** を行います。アプリコード・設計書・
テストの変更、コミットは一切行いません(修正が必要な場合は指摘に留め、開発者が判断する)。

---

## 背景(なぜ監査するか)

改善レーン第一弾(2026-07-02)の最重要バグ B1(PATCH 経路で VAL-C04/C05/C13 が素通り)は、
「VAL コード × API 経路 × テスト有無」のマトリクスを機械的に引ければ設計段階で発見できた
種類のものでした。retrospective パターンD「テストはケース数で語る」の機構化です。
マイルストーンでバリデーション(DES-006)を変更した後や、指示書作成前の点検に実行してください。

引数: `$ARGUMENTS`(不要。指定があっても無視してよい)

---

## 作業手順

1. スクリプトの存在を確認する(`ls scripts/audit-validation-coverage.sh`)。
   無ければ停止し、その旨を伝える。
2. `bash scripts/audit-validation-coverage.sh` を実行する(stdout にレポートが出る。
   ファイルは生成されない)。エラー時は出力をそのまま提示して停止する。
3. レポートを以下の観点で要約して提示する:
   - **§2 警告**の各コードについて、DES-006 の該当箇所を確認し「未実装(フェーズ送り)」
     「テストの穴の疑い」「定数間接参照による偽陽性」のどれに該当しそうかを分類する。
     判断がつかないものは**断定せず疑いとして**列挙する。
   - **§3 経路別**で Create / UpdateMetadata(PATCH) / UpdateWithKeyChange(PUT) /
     import 系の検証エントリポイントに非対称がないかを確認する。
   - 前回実行時との差分が分かる場合(会話履歴・progress-log 等)は増減を報告する。
4. テストの穴・実装欠落の疑いが見つかった場合は、修正せず
   `docs/progress/progress-log.md` への記録または開発者への報告を提案して終了する。

## 注意

- 本監査は文字列 grep による機械突合で、**言及あり=網羅十分ではない**(境界値・異常系の
  ケース数までは見ない)。詳細な限界はスクリプト冒頭コメントを参照。
- 既知の解釈補助:
  - VAL-B(バックアップ)/ VAL-N(LAN)/ VAL-O(公式データ取込=FR704 降格済)/
    VAL-P(プリセット管理=M20 予定)群は未実装フェーズのため実装言及ゼロが正常でありうる。
  - VAL-C06/C07(CHANGE-019 廃止)・VAL-P06(P05 統合)は意図的欠番。
  - VAL-C01 は DES-006 上は「削除」記述だが実装はキャラ存在検証として使用している
    (2026-07-03 改善レーン第二弾で資料不整合疑いとして報告済み。解消されたらこの行を消すこと)。
