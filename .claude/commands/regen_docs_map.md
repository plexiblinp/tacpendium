あなたは本プロジェクトの **docs-map 再生成担当 Claude** です。
`scripts/generate-docs-map.sh` を実行して `docs/handover/docs-map.md`
(設計担当 Web 版 Claude 向けの「文書ID ⇄ 実パス・役割マップ」)を最新化し、差分を提示します。

本コマンドは **スクリプト実行 + 差分表示のみ** を行います。コミット・ステージング・
プッシュは一切行いません(Git 操作は開発者が行う)。

---

## 背景(なぜ再生成するか)

本プロジェクトは **Web 版 Claude = 設計/指示書担当**、**Claude Code = 実装担当** という分業で、
Web 版はリポジトリのファイル構成を直接見られません。そのため指示書の前提条件などで
`docs/design/02-architecture.md` を「**DES-002**」のように **文書ID で参照** しがちです。
`docs-map.md` は **文書ID → 実パスの逆引き表** と **docs 配下のディレクトリ別役割マップ** を
実ファイルから決定論的に抽出した資料で、実装担当の無駄な探索や「読まずに着手」による品質低下を
防ぎます。ドキュメントを追加・改訂したマイルストーン完了時などに再生成してください。

引数: `$ARGUMENTS`(不要。指定があっても無視してよい)

---

## 作業手順

1. スクリプトの存在を確認する(`ls scripts/generate-docs-map.sh`)。
   無ければ停止し、その旨を伝える。
2. `bash scripts/generate-docs-map.sh` を実行する。
   - 成功メッセージ(`✅ 生成しました: ...`)を確認する。
   - エラーで失敗した場合(抽出破損ガードで `exit 1`)は出力をそのまま提示し、原因を報告して
     停止する(`docs-map.md` を手編集して取り繕わないこと)。
3. `git diff -- docs/handover/docs-map.md` を実行し、差分を表示する。
4. 差分を要約して報告する。観点:
   - §1 文書ID 逆引き表の **行の増減**(新規文書の追加 / 削除、ID・バージョンの変更)
   - §2 ディレクトリ別役割マップの変化(design / handover の **ファイル増減**、各フォルダの **件数増減**)
   - 日付行のみの変更か、実体(事実)の変更かを区別する
   - 差分が無い場合は「docs 構成に変化なし(冪等)」と報告する
5. **コミットはしない。** 内容を確認の上で開発者がコミットする旨を伝えて終了する。

---

## 注意

- 本スクリプトは grep/awk/sed による静的抽出です。文書ID/バージョンは各文書冒頭のメタデータ表
  (`| 文書ID |` / `| バージョン |`)の最初の行、各ファイルの役割は先頭 `# ` 見出し(タイトル)を
  採用します。手書きの概要は持ちません。詳細は生成物冒頭「本資料の限界」節を参照。
- §2 の **粒度方針(どのフォルダをファイル単位/フォルダ単位で出すか)とフォルダ役割文** は
  スクリプト内の config です。フォルダ構成が変わった場合は `scripts/generate-docs-map.sh` を更新します。
- 生成物以外のファイルは変更しないこと(スコープ厳守)。
