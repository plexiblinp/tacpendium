あなたは本プロジェクトの **リソース枯渇監査担当 Claude** です。
`docs/audits/resource-exhaustion-audit-runbook.md`(以下「ランブック」)を正本とする
差分監査を実施し、レポート 1 本を生成します。

本コマンドは **調査のみ** です。アプリコード・設定・依存を一切変更しません
(書き換えてよいのは、生成するレポートと、ランブック §3 ベースライン表の更新のみ)。
判断に迷う項目は判定せず **「要確認」として申し送る** こと(ランブック §6 の
フォールバック規則。過大評価より申し送りが安全)。

---

## 背景(なぜ監査するか)

本アプリはゲーム(SF6)と同時起動される前提であり、PC のフリーズ・スワップ・
ディスク飽和を絶対に許容できない(初回監査 `docs/audits/20260804-resource-exhaustion-audit.md`)。
機能追加のたびに同じ物差しで差分を検査し、上限のない書き込み・停止経路のない常駐処理・
リークの混入を早期に検出する。

引数: `$ARGUMENTS`(比較基点コミット)

---

## 作業手順

1. **ランブックを読む**: `docs/audits/resource-exhaustion-audit-runbook.md` の全文を Read する。
   手順・判定規則・ベースライン表・レポート様式のすべてはランブックが正本であり、
   本コマンドと矛盾する場合は**ランブックを優先**する。
2. **比較基点の確定**: `$ARGUMENTS` のコミットを使う。空の場合は
   `docs/audits/` の最新レポート冒頭に記載のコミットを探し、それも無ければ停止して
   開発者に比較基点を質問する。`git diff --stat <基点>..HEAD` で規模を確認し、
   監査対象(*.go / web/src / migrations)に変更が無ければ「監査対象の変更なし」と
   報告して終了する。
3. **機械チェックの実行**: `bash scripts/audit-resource-scan.sh <基点コミット>` を実行する。
   末尾の COUNTS ブロックをランブック §3 ベースライン表と突合し、**乖離のあった行だけ**を
   スクリプト出力の該当節から精読対象として拾う。COUNTS が `-1`(スキップ)の項目は
   レポートに「未実行(理由)」として必ず申告する。
4. **差分精読**: 変更ファイル一覧のうち COUNTS 乖離に関わるもの+新設の
   goroutine / useEffect / 書き込み経路を Read し、ランブック §2 の各判定規則を適用する。
   静的解析の新規指摘(本番コード分)はランブック §2-D の分類で仕分ける。
5. **レポート生成**: ランブック §7 の様式で
   `docs/audits/YYYYMMDD-resource-exhaustion-audit-delta.md` を Write する。
   重大度はランブック §6 の基準・格上げ規則に従う。既知未是正項目
   (R-1/M-1/M-2/M-4 等)は再掲せず状態(未是正/解消済み)のみ記す。
6. **ベースライン表の更新**: ランブック §3 の表を今回の COUNTS・実測値で Edit する
   (監査タスクの一部。これ以外のランブック本文は書き換えない)。
7. **コミット**: レポートとベースライン更新を `docs(audit): ...` でコミットする。
   push は行わない(リモート実行で `claude/` ブランチ上にいる場合のみ、
   `git push origin claude/<ブランチ名>` の単一形で push してよい)。

## 注意

- スクリプトが無い・実行エラーの場合は出力をそのまま提示して停止する(自力で
  grep を再現しようとしない。コマンド打ち間違いによる偽陰性を防ぐため)。
- アプリコードの修正・リファクタ・依存追加は指摘に留める。設計に関わる直し方は
  「設計判断事項」として申し送る。
- 一時ファイルはセッションの scratchpad へ。リポジトリ内に一時ファイルを作らない。
