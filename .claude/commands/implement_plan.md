## 引数バリデーション（最初に必ず実行）

引数: `$ARGUMENTS`

### ステップ1: 引数の存在確認

引数が空または未指定の場合:
- 作業を停止し、`docs/instructions/` 直下のファイル一覧を表示して、以下を伝える

```
引数が指定されていません。
指示書のファイル名、または接頭語を引数に指定してください。
例: /implement_plan M20-01
例: /implement_plan M20-01-initial-presets-three.md
```

### ステップ2: 引数の正規化と完全一致の確認

引数から次を取り除いて **指示書指定** を得る。以降の手順ではこの正規化後の文字列を使う。

- 先頭の `docs/instructions/`（フルパスで渡された場合。取り除かないとパスが二重になる）
- 末尾の `.md`

照合は **大文字小文字を区別しない**（`m7-02-e2e-scenarios.md` のような小文字始まりの実ファイルがあるため）。

`docs/instructions/{指示書指定}.md` が存在するか確認する（`find` または `ls` で確認）。
- 存在する場合: それを確定ファイルとして **ステップ3-2**（実施済みチェック）へ進む
- 存在しない場合: ステップ3-1 へ

### ステップ3-1: 候補ファイルの探索と確定

**探索対象は `docs/instructions/` の直下のみ**とする（`ls docs/instructions/*.md`）。
`reviews/` `templates/` `phase1/` `phase2/` `phase3/` の各サブディレクトリは **含めない**。

> **★直下限定である理由**: `reviews/` を含めると `M20-01` が `M20-01-initial-presets-three.md` と
> `reviews/M20-01-review-checklist.md` の 2 件に当たり、接頭語指定が常に曖昧化する。
> phase サブディレクトリ配下（M13〜M18 の過去指示書）を対象にしたい場合は、開発者がフルパスを引数に渡す。
> なお **ステップ3-2 の `docs/progress/` 探索は逆に再帰**である。この非対称は意図的なもの。

一覧に対し、**以下の順で照合し、最初に候補が得られた段階で打ち切る**:

| 順 | 規則 | 引数 `M14-03` での結果 |
|----|------|----------------------|
| 1 | **セグメント境界の前方一致**: ファイル名が `{指示書指定}-` で始まる | `M14-03-distribution-seed.md` の **1 件** |
| 2 | **単純な前方一致**: ファイル名が `{指示書指定}` で始まる | 上記 ＋ `M14-03a-*`〜`M14-03e-*` の計 6 件 |
| 3 | **部分一致**: ファイル名が `{指示書指定}` を含む | 同上 |

> **★規則1が要（かなめ）である。** 本プロジェクトには `M14-03` と `M14-03a`〜`M14-03e`、
> `M19-04` と `M19-04b`〜`M19-04d` のように、**枝番付きの兄弟が同じ数字で始まる**組が実在する。
> 単純な前方一致だけだと `M14-03` が 6 件に当たり、毎回選択を求める羽目になる。
> 「指示書指定の直後が `-` であること」を要求すれば `M14-03` は 1 件に確定し、
> `M14-03a` と指定すれば `M14-03a-*` の 1 件に確定する。

**候補が1件**: 以下を表示して確認を求め、承認後のみ続行する。
**承認後は、以降のすべての手順でこの候補ファイル名を用いる**（引数の文字列をそのまま使わないこと）
```

  docs/instructions/{候補ファイル名}
このファイルで続行してよろしいですか？「はい」と返答いただければ続行します。
```

**候補が2件以上**: **停止・終了しない**。番号付きで候補を提示して選択を求め、回答を得た候補で続行する
```

**候補が0件**: 作業を停止し、以下を表示して終了する
```

### ステップ3-2: 実施済みチェック（安全網）

接頭語指定は打鍵が短い分、**別サブと取り違える危険が上がる**。確定した指示書について、
既に実施済みの成果物が無いかを `docs/progress/` の **ファイル名** で確認する。

確定ファイル名から **タスク識別子**（ファイル名の先頭2セグメント、`-`区切り。例 `M1-03-combo-crud-api.md` → `M1-03`）を取り、次を実行する。
**`docs/progress/` は `phase1/` `phase2/` `phase3/` のアーカイブを含めて再帰探索する**（ステップ3-1 の直下限定とは非対称）。

```bash
find docs/progress -type f -name '*.md' -printf '%P\n' | grep -iE "(^|[-/])<タスク識別子>(-|\.)"
```

> **★境界付きで照合すること**（識別子の直後が `-` か `.`、直前が行頭か `-` か `/`）。
> 単純な部分一致だと `M19-04` が `m19-04b-review.md` / `m19-04c-*` / `m19-04d-*` まで拾い、
> **枝番のサブの成果物を本体の実施済み証跡と誤認する**。直前の `-` を許すのは
> `20260802-M19-04-manual-input-list-developer-decision.md` のような日付接頭辞付きを拾うため。

**1件以上ヒットした場合**: 既に実施済みである可能性が高い。以下を提示して確認を求め、
**承認が得られるまで「作業手順」へ進まない**
```
⚠ この指示書は既に実施済みの可能性があります: docs/instructions/{確定ファイル名}
  docs/progress/ に以下の成果物があります:
    {ヒットしたファイルのパス一覧}
  それでもこの指示書で続行しますか？（再実施・追補が目的であれば「はい」）
```

**0件の場合**: 何も表示せず「作業手順」へ進む。

> **本検査は証跡の有無を見るだけの安全網であり、実施済みか否かの判定機ではない。**
> 例えば `M14-03` は指示書が存在するが、実作業は枝番 `M14-03a`〜`M14-03e` に置き換えられており、
> 本体 ID での証跡は 0 件になる。**ヒットしなかったことを「未着手の保証」と読まないこと。**

## 作業手順（バリデーション通過後に実行）

1. 指示書本体（**確定した指示書パス** = `docs/instructions/{確定ファイル名}`）を読む
   （引数の文字列をそのまま連結しないこと。ステップ3-1 で選んだ候補を必ず使う。
   　`CLAUDE.md` は Claude Code が起動時に自動ロードするため、明示的に読み直す必要はない）
2. 指示書が参照している設計書（docs/design/ 配下）を必要に応じて読む
3. 計画を提示する際、以下を含めること
   - 作業対象ファイル一覧と作業順序
   - 不明点・推測で進める箇所（あれば明示）
4. 計画への承認を待ってから実装に入ること

> **Plan Mode タイムアウト対策（未回答事項の扱い）**
>
> Claude Code の仕様変更により、Plan Mode は一定時間で自動タイムアウトし、開発者の回答を得ないまま Plan Mode を抜けて「編集承認」扱いになることがある。これを防ぐ手段は無いため、以下で代替する。
>
> 1. **未回答・未決の事項は、プラン（提示）の末尾に「■ 未決事項（要回答）」として箇条書きで必ず明示し、開発者の返答を待つ。** 各項目に (a) 何が未決か (b) こちらの推奨案・暫定案 (c) 回答が無いと何が困るか を書く。
> 2. **重要な未決事項を抱えたまま編集が承認された場合（タイムアウトによる自動承認を含む）は、実装・編集・成果物生成を行わない。** 代わりに「重要な未決事項が残っているため作業を保留しました。以下について回答をお願いします」と連絡し、未決事項を再掲して停止する。
> 3. 推奨案どおり進めても実害の無い軽微な事項に限り、推奨案を採用した旨を明記した上で続行してよい。重要度の判断に迷う場合は「重要」側に倒し、停止して確認する。

## 完了時: 書いた報告の「閉じない強調」を自分で検査する（必須）

<!-- COMPLETION-REPORT-MD-EMPHASIS -->

この手番で `docs/progress/` へ**新規に作ったファイル**（完了報告・その他の新規レポート）を、`check-md-emphasis.sh` の**ファイル引数モード**へ渡す（2026-09-07・`D-761` 案 A）。

```bash
bash scripts/check-md-emphasis.sh docs/progress/<この手番で書いたファイル>.md
```

- **非ゼロで終わったら、自分で直してから完了とする。** 直しかたは「閉じ `**` の直前の約物を強調の外へ出す」（`**A（B）**は` → `**A**（B）は`）。
- **★`docs/progress/` は常時走査の対象ではない**（2026-09-07 に外した）。**⇒ ここで見なければ、誰も見ない。**
- **★外した理由は「見なくてよくなった」ではない。** 常時走査は「増やした本人が直す」を前提とするが、**完了報告は歴史記録として書き換えない**（`D-274` (3)）。**2 つの規則が食い違い、誰も直さないまま床だけが上がっていた。⇒ 変わったのは検査の時点だけである。**
- **★読めない行が残ると、次の担当が事実を取り違える**（`M20-07` と `M21-06` が独立に申し送った）。**この 1 行はその実害を防ぐためにある。**
- **★継続更新ファイル（`docs/progress/progress-log.md` 等）は渡さない。** 同ファイルは**歴史記録としての既存の検出行**を持ち、それらは直さない（`D-274` (3)）。**渡すのはこの手番で作った／書き足した報告書だけである。**
- **★検出が出たら、行番号で「自分が書いた行か」を判定し、自分の行だけを直す。** 既存行の是正は別の手番である。
- **★フェンス（3 連バッククォート）内のコード引用は構造上かならず偽陽性で当たる**（`followup` の `md-emphasis-check-fenced-block-false-positive`）。**逐語引用が理由で直せない行は、直さずに完了報告へその旨を 1 行残す。**
