**★開発者の逐語**（2026-09-08）**＝「本アプリは起動すると、コンソールの黒窓が開くのですが、一般向けではないです。」**

**★★したがって `M32`**（説明書・`README`）**より前に置く。⇒ 起動方式が変わると、説明書に書く手順が丸ごと変わるためである。**

## 2. ★★受領した実装方式（**設計卓は方式を採否していない。⇒ §5-1 の判断が要る**）

**★出所＝`docs/progress/M34-RESEARCH-01-report.md`。★本 MS の起票と同時に置いた。**

| 要素 | 実装方法 |
|---|---|
| `exe` の直接起動 | **引数なしの起動を常駐モードとして扱い、HTTP サーバとトレイを起動する。⇒ 起動用 bat は不要** |
| **★★黒窓の非表示** | **Windows 向けビルドに `-ldflags "-H=windowsgui"` を指定する** |
| 通知領域への常駐 | **Go 標準ライブラリから Win32 API を呼び出す。`Shell_NotifyIconW` でアイコンを登録し、メッセージループで操作を受ける** |
| ブラウザ画面 | **ローカル HTTP サーバを起動し、その URL を既定ブラウザで開く。★ローカル利用では `127.0.0.1` で待ち受ける** |
| トレイの操作 | 右クリックに「ブラウザで開く」「データフォルダを開く」「終了」／ 左ダブルクリックでも画面を開く |
| 終了 | **画面とトレイから共通の終了処理を呼び、HTTP サーバを停止してアイコンを削除する** |
| 二重起動 | **ポート使用中の場合に既存の同一アプリかを判別し、既存画面だけを開いて後から起動したプロセスを終了する** |
| ログ・起動エラー | **ログはファイルへ出力し、起動失敗は Windows のメッセージボックスで知らせる** |
| CLI との共存 | **CLI のサブコマンド実行時だけ `AttachConsole` で親コンソールへ接続する** |

**★★流用元が在る**——**`autopilot-combomgr/projects/moves-input-tool` で実装済みであり、デスクトップ統合部分は Go 標準ライブラリのみで構成され、本体への移植を想定して分離されている。**

| 流用できるもの | 中身 |
|---|---|
| `internal/desktop/` | **通知領域アイコン、ネイティブ確認・警告ダイアログ、ブラウザ・フォルダ起動** |
| `cmd/movestool/gui.go` | **HTTP サーバ・トレイ・ブラウザをまとめる常駐ランチャ** |
| `cmd/movestool/console_windows.go` | **CLI のコンソール接続と、GUI 起動時の不要なコンソール切り離し** |
| `scripts/build-windows.ps1` | **黒窓を出さないビルド指定と、成果物が GUI サブシステムになっていることの検証** |

## 4. ★★危険（**どの方式を採っても当たる**）

### 4.1 ★★【最重要】`-H=windowsgui` は標準出力を消す

**★同フラグは「窓を出さない」ではなく「GUI サブシステムとしてリンクする」である。⇒ 標準出力・標準エラーの接続先が無くなる。**

| # | 帰結 |
|---|---|
| **★★1** | **`log/slog` の出力先が既定のままだと、ログが黙って消える。⇒ ファイル出力**（`lumberjack`）**が前提条件になる。★本プロジェクトは既に `lumberjack` を持つので、追加ではなく「確実に通す」ことの確認である。** |
| **★★2** | **起動に失敗したとき、利用者には何も見えない。⇒ メッセージボックスが必須である。★これが無いと「ダブルクリックしても何も起きない」という最悪の形になる。** |
| **★3** | **`fmt.Println` が残っていると、それも消える。⇒ `CLAUDE.md` §10 が本番コードで禁じているので在らないはずだが、実査が要る。** |

### 4.2 ★★CLI との共存

**★本プロジェクトの `cmd/` が CLI サブコマンドを持つかを、設計卓は読めない**（武装中）**。⇒ 持つなら `AttachConsole` の分岐が要り、持たないなら不要である。★§5-2 の確認事項。**

**★★`-tags=debug` のデバッグビルドが在る**（`CLAUDE.md` §11）**。⇒ そちらも GUI サブシステムにするのか、コンソールのまま残すのかを決めること。**

### 4.3 ★★他のプラットフォーム

**★本方式は Windows 専用である。⇒ `-H=windowsgui` も `Shell_NotifyIconW` も他 OS に無い。**

**★★ビルドタグでの分離が要る**（`*_windows.go` / `*_other.go`）**。⇒ 分離を誤ると、Windows 以外でビルドが通らなくなる。★開発は devContainer**（Linux）**で行われるので、`go build ./...` が通らなくなると開発が止まる。**

**★★これは配布方針そのものに触れる。⇒ `DES-001` が単一バイナリ配布をどう定めているかを実査すること。**

### 4.4 ★★二重起動の判別

**★「ポート使用中なら既存の同一アプリかを判別する」は、判別方法を決めないと成立しない。⇒ 別のソフトが同じポートを使っている場合に誤判定すると、他人のプロセスへ画面を開きに行く。**

**★★本プロジェクトは `internal/infra/netutil` を持つ**（`CLAUDE.md` §3）**。⇒ 既存のポート探索と噛み合わせること。★LAN 共有の設計**（`0.0.0.0` で待つ）**と `127.0.0.1` 固定は両立しない。⇒ §5-3。**
