## 0. この指示書の特殊性

### 0.1 製造担当として起動し、調査だけ実施して閉じる

**製造担当セッションを起動し、§4 の事実列挙 → §5 のレポート作成 → クローズ。** **実装は本調査の対象外である**（後続サブで別指示書として出す）。

**許可**: `view` / `cat` / `sed -n` / `grep` / `rg` / `find` / `ls` / `git log` / `git show` / `wc` / SQL の `SELECT`。

**禁止**: 編集系・書き込み系のすべて（本番コード・テスト・マイグレ・seed・`docs/design/` 配下・`docs/handover/` 配下）。

> **★書き込みの例外は 2 つだけである。両方とも許可であり、片方を落とすと DoD と禁止表が正面衝突する。**

### 0.3 判断・提案を含めない（judgement-free）

**事実列挙と、事実から機械的に導ける分類だけを行う。** 「ここを直すべき」「この案がよい」といった設計結論は含めない。

**★ただし disposition の付与は本調査の職務である**（§4 の C 軸）。**これは「判断」ではなく「照合の結果」として行う**——**照合先（現行コード ／ 完了報告 ／ 設計書 ／ `followup-backlog`）を必ず 1 つ以上示し、示せないものは `要判断` に倒す。**

- **例外は 2 つ**——**(1) 想定外の発見**（調査中に既存の記録と矛盾する事実を見つけた場合）／**(2) 明らかな矛盾**（設計書どうし、または設計書と実装の食い違い）。**この 2 つは §5 の末尾へ「想定外の発見」として書く。**
