## 0. この指示書の特殊性

### 0.1 ★★★方式は (a) seed 側で確定している（**製造は選ばない**）

**`M30-05` が 2 案を挙げ、2026-09-12 に開発者が裁定した。⇒ 逐語＝「Seed側を修正します」。**

| 案 | 採否 | 理由 |
|---|---|---|
| **★★(a) seed 側**——ガイルの `move_code` を接尾形へ揃える | **★★★採る** | **根は seed の命名の揺れであり、実装は「変種は接尾形」という規約どおりに動いている。⇒ 直すべきは根である** |
| (b) 実装側——接頭形も畳めるよう検出を広げる | **★採らない** | **揺れを実装が吸収する形であり、次に別の接頭形が現れたらまた広げることになる。⇒ 揺れが永続化する。★`perfect_timing_` という特定の接頭辞を実装が知ることにもなる** |

**★★先例が 2 回ある**——`M35-02`（`ryu` の `axe_kick`）／ `M35-03`（ラッシュ版 4 件の `original_move_code`）**。⇒ `move_code` の改名の手順は確立している。★どちらも読むこと。**

### 0.2 ★★何が起きているか

**同じ UI 概念なのに、画面の見え方が割れている。**

| キャラ | `move_code` | 形 | 画面での見え方 |
|---|---|---|---|
| luke | `flash_knuckle_perfect_light` | **接尾形** | 変種軸（通常 / ホールド / ジャスト）で選べる |
| **guile** | `perfect_timing_light_sonic_boom` | **★接頭形** | **別ファミリー 3 行として並ぶ** |

**★機序＝`splitSpecialVariant` の変種接尾辞**（`_max_holding` / `_holding` / `_perfect`）**は接尾形しか見ない。⇒ 接頭形で書かれた同じ概念は畳まれない**（`web/src/features/combo/inputResolution.ts:200-232` 付近。**★行番号は `M30-05` 時点のものであり、実物で取り直すこと**）**。**

**★★誰も壊していない。⇒ テストも lint も型検査も緑であり、実機で 2 キャラを並べて見る以外に気づく経路が無かった**（実際、開発者の実機確認で初めて出た）**。**

### 0.3 ★★★本サブはファミリー総数を変える（**先行サブの不変条件を壊す側である**）

**畳むと「素＋ジャスト」の 2 変種になり、行数は 3 本減る。⇒ ファミリー総数は 372 → 369 になる。**

**★★これは本サブの*成果*であって欠陥ではない。⇒ ただし `M30-04` / `M30-05` / `M30-06` はいずれも「372 が不変であること」を完了条件・テストに書いている。★それらを本サブが更新する。**

**⇒ `M30-06` の main へのマージを待ってから着手すること**（§前提サブ）**。**

### 0.4 ★射程は小さい（**★ただし実測で確かめること**）

**【ジャスト】を持つのは 2 キャラだけである**（`M30-05` の実測＝guile 10 行 ／ luke 3 行）**。★別ファミリーになるのは `sonic_boom` / `somersault_kick` / `sonic_cross` の 3 本。**

**★★【ホールド】/【最大ホールド】は全数が接尾形であり、同じ揺れは 1 件も無い**（同実測）**。⇒ 本サブは【ジャスト】だけを扱う。**

**★これらはすべて写しである。⇒ 段 1 で数え直すこと。**

### 0.5 ★★★意図した赤の一覧（**2026-09-12 追加＝`M30-06` の申し送り・`D-846`**）

**★★総数が 372 → 369 へ動くため、先行 3 サブが置いた床のうち次が赤くなる。⇒ これは*意図した*赤である。**

| 床 | 何が動くか |
|---|---|
| `web/src/features/combo/specialFamilyLabel.roster.test.ts` | **総数 372 ／ 識別子 digest `b54d118…` ／ 表示名 digest `a7ee6db5…` の 3 つとも動く**（行が 3 本消えるため） |
| `web/src/features/combo/moveSurfacing.roster.test.ts` | **総数 372 ／ `is_derived` の並び 194:178 が動く** |
| `web/src/features/combo/specialFamilyRepresentativeName.roster.test.ts` | **反例群・重複組が動きうる**（**★cammy の行が対象に入る場合**） |

**★★★自動で貼り替えないこと。⇒ 差分を目で見て、消えた 3 行が*ガイルの【ジャスト】3 行そのもの*であることを確かめてから、新しい値を書くこと。**

**★機序＝これらの床は「変わっていないこと」を測る型である。⇒ 期待値を機械的に上書きすると、床そのものが消える。★テスト自身がその旨を警告している。**

**★★数を減らす方向の変更で床が赤くなったときは、*減った分が意図した分と一致するか*を必ず示すこと**（`372 - 369 = 3` ＝ ガイルの `perfect_timing_*` 3 行）**。⇒ 「赤かったので直した」では通らない。**

## 4. 危険な箇所

### 4.1 ★★★`preset_aliases` の追随を忘れる

### 4.2 ★★★golden の追随を連番の `grep` で済ませる

**`SUPP-001` §5.5.4 規約 (16) が明記している**——**連番の `grep` は「やった」という体裁を保ったまま取り落とす。⇒ 変わる列名で `grep` すること。★終端が HEAD のテストも対象である。**

### 4.3 ★★372 を不変として持っている場所を取りこぼす

**`M30-04` / `M30-05` / `M30-06` の 3 サブが 372 を床にしている。⇒ 1 か所でも残ると赤になり、赤を消すために床を緩める誘惑が出る。★緩めずに、正しい新しい値へ更新すること。**

### 4.4 ★実測を写す

**§0.4 の数字はすべて `M30-05` からの写しである。⇒ 段 1 で数え直すこと**（`M30-05` 教訓 1）**。**
