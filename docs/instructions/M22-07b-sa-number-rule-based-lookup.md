### 4.2 ★既存の導出規則をそのまま使う

**`M22-07` は既存の規則を使い回して SA / CA の全数から番号を導いている**（導けなかった行 0）。**⇒ 本サブも同じものを使う。再実装しない。**

> **★`M22-07` の契約テストが「該当行すべてが衝突組に居ること」まで固定している。** **⇒ この固定を崩さないこと。**

### 4.3 ★★第 3 段は、前 2 段が 0 件のときだけ引く

**これが本サブで最も重要な設計である。**

`DES-004` §5.0.2 規約 3 は「段を足しても前の段の答えを変えないこと」を求めている。**⇒ 本サブはこれを「気をつけて守る」のではなく「構造的に守れない形にできない」ようにする。**

| # | 内容 |
|---|---|
| 1 | **★前 2 段のいずれかが 1 件以上を返したら、第 3 段は引かない。** **⇒ 前段の答えは定義上変わりようがない** |
| 2 | **★「もっと積極的に引いたほうが解決率が上がる」と考えないこと。** **上がるかもしれないが、そのとき変わるのは利用者が既に登録したレシピの表示である**（§4.4） |
| 3 | **★この構造そのものをテストで固定すること**（§5.1-3）。**「いま 0 件だから通っている」ではなく「1 件以上のとき第 3 段が呼ばれない」を主張する** |

### 4.4 ★3 件数で示す（`DES-004` §5.7.4）

**`M22-07` が測った基準値に対して、次の 3 つを件数で示すこと。**

| # | 数えるもの | 合格 |
|---|---|---|
| (a) | **答えが変わった入力** | **0** |
| (b) | **解決しなくなった入力** | **0** |
| (c) | **新たに解決した入力** | **N**（これが成果） |

**★(a) か (b) が 0 でなければ止めて報告する。** **「良くなったから」で進めない**——**利用者が既に登録したレシピの表示が変わる。**

**★`M22-07` は (a) 0 / (b) 0 / (c) 0 で終わっている。** **⇒ 本サブは (c) を 0 から動かすサブである。**

### 4.5 ★多義は捨てず、候補として返す

**A / B / C は §5.5 の「衝突組は両方落とす」に当たって多義の組を捨てる。** **E は §5.0.2 規約 1 により「未確定 ＋ 候補提示」へ倒れる。**

**★これは案 E を選んだ理由の 1 つである**（`CHANGE-120` §1.1-3）。**⇒ 多義を「解決できないから捨てる」形にしないこと。** **候補として返す経路に乗せる。**

### 4.6 ★次のキャラ波では何もしない

**規則であるため、新キャラの `moves` 行に対しても自動で当たる。** **⇒ `DES-004` §5.4 の再適用の対象にならない。**

**★これが案 E を選んだ理由の 2 つ目である**（`D-437` が警告した「人が再投入しないと新キャラだけ空になる」問題が、SA 番号については構造的に消える）。

**⇒ 完了報告に「新キャラ波で走らせるものが無いこと」を明記すること。** **`CHANGE-120` §2-e がその反映先を押さえている。**
