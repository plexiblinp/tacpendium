## 1. 背景と目的

### 1.1 背景

M19-04 は `moves` に 3 列（`startup_basis` / `chain_cancel_total` / `fastest_unreachable`）と関連テーブル 1 本（`move_derivations`）を足す。当初の設計推奨は **DB backfill 専用**（CSV / seedgen には列を足さない）だったが、開発者判断で **CSV にも値を持たせる**ことになった。理由は、手入力ツールから編集を再開できること、および今後のゲームアップデート時に編集経路が要ることである。

この変更により、設計側が事実を持っていない領域が生じた。とくに **M18-01 で「seedgen へ新列を出力する」案が原理的に不成立として撤回された前例**があり、同じ壁に当たるのかどうかを実査せずに指示書を書くことはできない。

また、キャラクターの充足状況が **30 キャラ中 seed 済み 10・CSV 作成済み 17**（開発者申告 2026-07-31）であり、`M19-DESIGN-07` §4-2 が前提にした「seed 済み 15 キャラ」と食い違っている。加えて、ボード裁定 D-13 は「`jump_neutral` / `jump_forward` / `jump_back` の `total` は **12 キャラ全数一致**」と記録しており、**10・12・15 の 3 つの数が並立している**。**backfill の母数そのものを実値で取り直す必要がある。**

### 1.2 目的

§4 の全項目を、実コード・実マイグレ・実 DB の `view` / `grep` / `SELECT` で確認し、**§5 の様式で報告する**。列名・関数名・件数はすべて実値で書く。確認できなかった項目は「**未確認**」と明記する（推測で埋めない）。

### 1.3 この調査でやらないこと

- 実装・マイグレ作成・seed 変更・コード変更・CSV 編集を**一切しない**。
- 最終決定をしない（**材料の提示のみ**）。
- DES / REQ 本体を変更しない。
- **手入力ツール（別 go module・`.gitignore` 配下）を調査対象としない**（開発者判断 2026-07-31）。本体側は「ツールへどういう CSV を渡してほしいか」を伝えるだけで、ツールの内部は見ない。**CSV 契約の判定は本体側の受け口（seedgen・パーサ）だけで行う。**

## 4. 調査項目

### A. seedgen と golden の固定範囲

- **A-1**: `internal/seedgen` が `moves` の INSERT に出力している**列を全数列挙**する（該当関数名・ファイルパス・行を添えること）。**CSV に存在するが INSERT に出していない列**があれば、その列名と、理由が書かれたコメントがあれば原文で引く。
- **A-2**: golden テストが**どの生成物を byte-identical で固定しているか**を全数列挙する（テストファイル・対象マイグレ番号・再生成コマンド）。
- **A-3**: `internal/seedgen` に**新しい列を出力させた場合、A-2 のどの golden が壊れるか**を、実際に壊さずに（コードとテストの読解で）特定する。**壊れるものが 1 つも無い場合も「無い」と明記する。**
- **A-4**: `is_projectile` を seedgen 出力にしなかった判断の**一次記録**（コミットメッセージ・コード内コメント・指示書・完了報告のいずれか）を探し、**実際の理由を原文で引用**する。設計側は「golden の byte 比較とマイグレ実行順序（`000026` / `000030` が `000039` より前）」と理解しているが、**これを裏取りする**。一次記録が見つからない場合は「見つからない」と報告する。

### B. CSV → DB へ値が入る経路の全数

- **B-1**: 現在 `moves` に書き込みを行う経路を**全数列挙**する（マイグレ／seedgen 生成物／ランタイム API ハンドラ／管理用コマンド／テストヘルパ）。各経路について、**生きているか塞がれているか**を実コードで判定し、根拠（ルート登録の有無・ハンドラの実体）を添える。
- **B-2**: `/api/import/moves` および `/api/import/moves/preview` に相当するハンドラ・ルートが**現在も登録されているか**を実査する。登録されていれば、その `INSERT` / `UPDATE` の**対象列と競合解決（upsert）の挙動**を実コードで示す。
- **B-3**: 画面18（moves 編集）から `moves` を更新する経路の**対象列**を列挙する。**新列を足したとき、この経路が新列を素通しするのか NULL で潰すのか**が読み取れる箇所（DTO・model の `db:` タグ・repository の UPDATE 文）を示す。

### C. 「CSV 側が空」を上書きにしないための規則の置き場所

- **C-1**: 既存のマイグレ・コードの中に、**「値がある行だけ更新し、空の行は既存値を残す」**パターンの実装例があるか全数探す（`COALESCE`・`WHERE ... IS NOT NULL`・条件付き `UPDATE` など）。あれば実 SQL を引用する。
- **C-2**: seed の再投入・再生成が**既存 DB に対して行われる運用が実在するか**を確認する。配布は単一バイナリで、利用者の DB は既にマイグレ適用済みである点を踏まえ、**実際に「CSV 再取込」が起こる状況**を実コード・運用文書から特定する。**起こらないなら「起こらない」と明記すること**（契約 §2 F-4 の前提そのものが変わるため、本調査で最も影響の大きい項目のひとつである）。

### D. backfill 母数の実測（★仮データの混入確認）

> **本軸は開発者の実測作業量に直結する。** 仮データが母数に混ざっていると、捨てられる行に対してフレームメーターの実測が費やされる。

- **D-1**: `characters` の**全行**を列挙する（`id` / `code` / 行数）。
- **D-2**: **キャラごとの `moves` 行数**を列挙する。あわせて `category` 別の内訳を出す。
- **D-3**: **c_viper / dhalsim の `moves` 行の実態**を報告する。行が存在する場合、**それがどのマイグレで投入されたかを特定**し、手入力 CSV 由来か、移動 system move 等の一括投入由来かを示す。**「moves が 0 行か」を実値で確認する**（前提事実 7 の検証）。
- **D-4**: `M19-DESIGN-07` §4-1 の母数を**実値で取り直す**——`is_derived = false` の行数／`category = 'rush_variant'` の行数／それ以外の行数。**設計文書の 640 / 156 / 約 148 と一致するか**を明記し、不一致ならキャラ別の内訳を添える。
- **D-5**: D-4 の各母数に **c_viper / dhalsim の行が何行含まれるか**を出す。**0 行なら「0 行」と明記する。**
- **D-6**: `code` に `jumping_` を含む行数（`fastest_unreachable` の C 型機械付与の母数）を実値で出す。
- **D-7**: **`jump_neutral` / `jump_forward` / `jump_back` の `total` を持つキャラが何体あるかを実値で数える。** ボード裁定 D-13 は「**12 キャラ全数一致**」と記録しているが、開発者申告の seed 済みは **10 キャラ**、`M19-DESIGN-07` §4-2 は「**15 キャラ**」を前提にしている。**この 3 つの数の食い違いを実値で解消する**（どれが何を数えた値なのかを、数えた対象・単位・基準時点つきで報告する）。

### E. 手入力 CSV の列契約

- **E-1**: `character_data/*.csv` の**ヘッダ行を実際に読み**、列名を順序どおり全数列挙する。**20 列という前提が実態と一致するか**を確認する。**ファイルによってヘッダが違う場合は差分を出す。**
- **E-2**: CSV の列定義の**正典がどこにあるか**を特定する（DES-002 §7.5 か、seedgen 内の構造体か、両方か）。両方にある場合、**食い違いがあるかを実値で突合**する。
- **E-3**: CSV に**列を末尾追加**したとき、パース側が壊れるか許容するかを実コードで判定する（**列数の固定チェックか、ヘッダ名解決か**のどちらであるかを示す）。
- **E-4**: 1 技が**複数の親を持つ**関係（`move_derivations` 相当）を CSV で表現している既存の列があるか探す。無ければ「**無い**」と報告する。
