## 2. ★★★設計卓が本手番で見つけた衝突（**射程 5**）

**★★★SCANOSS の evidence を `docs/progress/evidence/m26-04-scanoss/` へ置いたが、`scripts/public-snapshot-manifest.txt` は `ALLOW docs/**` である。⇒ evidence は公開スナップショットに丸ごと載る。**

**★★★追補報告 §7.1 は「これらを公開リポジトリへ常時掲載したり、非公開履歴全体を開示したりはしない」と述べている。⇒ 方針と実装が食い違っている。**

**★★とくに `scan-review-chronology-initial.csv` は、非公開リポの初出 commit SHA と author date を持つ見込みである**（**★設計卓は同ファイルを実見していない。⇒ 実査が要る**）**。**

| # | 論点 |
|---|---|
| **★★1** | **公開する値打ち＝「SCANOSS を回し、81 件をこう判断した」を出せるのは OSS として良い。⇒ `scan-matches-initial.csv` は出してよい見込み** |
| **★★★2** | **公開する損＝chronology は非公開リポの SHA と日付を持ち、しかも公開リポにその SHA は存在しない。⇒ 第三者は検証できない。★検証できない主張を出しても、時系列の疑いは晴れない** |
| **★★3** | **⇒ 設計卓の推し＝*ファイル単位で*決める。chronology だけ `DENY` へ入れ、match の一覧は公開する** |

**★★★決めるのは開発者である**（`CLAUDE.md` §10＝公開・法務の自己判断禁止）**。⇒ 製造は候補と根拠を出すところまで。**
