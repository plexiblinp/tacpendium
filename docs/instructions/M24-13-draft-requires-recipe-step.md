## 1. 背景と目的

### 1.1 ★★やることは「既存 VAL の適用範囲を広げる」だけである

**開発者の逐語（2026-08-29）＝「仮登録がレシピの『ステップ 0 本』を許すことを見直します。ステップのみ仮登録でも必須とします。理由としては、ステップが入っていない仮登録があっても、何に使おうとしたものか後から全く分からないからです。」**

**`VAL-C09`＝「レシピが空（ステップ数0）でないか」（ERROR）が本登録用に既に存在する**（`DES-006` §2.1）。

**⇒ ★これを仮登録でも適用する。★★新しい VAL を作らない。**

**★理由**——**`DES-006` §2.1 が自ら書いている規約＝「同じ条件にする」ではなく「同じ 1 本を呼ぶ。条件で書くと 2 本目が書き起こされて静かにずれる」。**

### 1.2 ★★`VAL-D02` は 1 文字も変えない

**逐語＝「レシピ中の `move_id` は指定されていれば存在検証、未指定（NULL）は許容」。**

**⇒ 技が未指定のステップは引き続き許される。★数えるのは「ステップの本数」だけである。**

### 1.3 ★★`move_id` の NULL は 2 つの目的で使われている（**混同しないこと**）

| # | 形 | 位置づけ |
|---|---|---|
| **1** | **`move_id` NULL ＋ `modifiers.type`**（`parry_drive_rush` / `cancel_drive_rush`） | **★★非技ステップの正規表現である**（`DES-004` §2.2 の逐語＝**「技ステップ以外（ラッシュ類など）は `modifiers.type` で識別し、`move_id` をNULLとする」**）。**本登録でも普通に存在する** |
| **2** | **`move_id` NULL ＋ `modifiers.type` も無し** | **★`VAL-D02` の「未指定（NULL）は許容」が指す仮登録固有のケース** |

**★★どちらも「ステップ 1 本」として数えること。** **★本サブは `move_id` の中身を見ない。**

**設計卓は実装ソースを読めない。★以下の面の指定はすべて実査項目である**（§3.3）。**★「ある」も「無い」も断定していない。**

**★★ただし「うろ覚え」は守る**——**技が未指定のステップは引き続き許される**（§1.2）。

|---|---|
| **形** | **★★`M24-11` が `VAL-C02` を閉じた手をそのまま使う**——**判定を登録と同じ書き込みトランザクションの内側で `*sql.Tx` を使って行う**（`DES-006` §2.3 の先例） |
