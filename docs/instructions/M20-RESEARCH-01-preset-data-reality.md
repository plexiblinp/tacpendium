## 0. この指示書の特殊性

### 0.1 製造担当として起動 + 調査だけ実施して閉じる運用

製造担当セッションを起動し、**§4 の事実列挙 → §5 のレポート作成 → クローズ**で完了する。**実装は本調査の対象外**であり、後続サブの別指示書で行う。**本調査の結果が出るまで M20 の overview（サブ分割）は確定しない。**

### 0.2 read-only 厳守

- 使ってよい: `view` / `grep` / `rg` / `find` / `ls` / `git log` / `git show` / `SELECT` 文（**開発用 DB のコピーに対して**）。
- 使ってはならない: ファイルの作成・編集・削除（**§2.1 のレポート 1 本を除く**）／`INSERT` `UPDATE` `DELETE` `CREATE` `ALTER` `DROP`／マイグレの新規作成・編集／`seed` の変更／`go test` 以外のビルド生成物の commit。
- **DB を読むときは原本を開いたまま書き込む操作をしない。** **§0.5 の環境ごとの取り扱いに従うこと。**
- **使い捨て DB の作成は許可する**（マイグレをクリーン適用する目的に限る）。**作成先はリポジトリ外の使い捨て領域**（`/tmp` 配下等）とし、**リポジトリ内の `*.db` を作成・上書き・削除しない。**

### 0.3 判断・提案を含めない（judgement-free）

**事実列挙のみを行う。** 「ここを直すべき」「この案がよい」といった修正方針・設計結論は書かない。**ただし次の 2 つは判断ではないため記録する**——**(1) 想定外の発見** ／ **(2) 明らかな矛盾の事実指摘**。

**★数字には「何を・どの単位で・どの基準時点で数えたか」を必ず併記する**（教訓 `E-16` / `E-93`）。

**★「0 件」を報告するときは、検査が動いていることを先に確かめ、「見つかった件数」と「検査した件数」の両方を出す**（教訓 `E-84`）。「0 件」は **(a) 対象が無い** と **(b) 検査が対象を見ていない** の 2 通りに読め、出力が同一である。

## 1. 背景と目的

### 1.1 背景

M20 はプリセット管理・カスタムプリセット・`recipe_cache` 無効化・命名クラスタを扱う。**設計卓は実装ソースを読めない**（`design-desk-arm.sh` による武装）ため、**サブ分割とスキーマ承認に必要な実態を製造の実査で取る。**

**対象データの実態が未知の重量サブは、指示書化の前に read-only 実態調査を回す**（教訓 `M17-D5`）。**M20 は「手入力 CSV から既定プリセットを生成する」という、母数も衝突数も未知の作業を含むため、この型にあたる。**

### 1.2 目的

**§0.4 の 6 軸について、実値で母数と内訳を確定させる。**

### 1.3 この調査でやらないこと（read-only 厳守）

- **生成規則の設計**（どの技をどう表記するか）。**§4-A の全数を出すまで決めない**（**D-267** ／ 教訓 `E-123`＝**測る前に判定法を決めない**）。
- **一意制約の設計**（列を足すか・スコープをどこに置くか）。**§4-B の衝突数を出すまで決めない。**
- **`recipe_cache` の eager / lazy の再判断**。**§4-D の実件数を出すまで決めない。**
- **コードの修正・マイグレの作成。**
