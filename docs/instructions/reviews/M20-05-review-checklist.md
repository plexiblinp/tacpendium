## 9. ★このレビューで判定してはいけないこと

- **eager か lazy か**——**`D-292` / `D-303` で確定済みである。** **「毎回全部再計算するのは無駄だ」は本サブへの指摘にしない**（**実測は 53 エンティティである**）。
- **実在確認をどの層へ置いたか**——**§9.2-1 で「委ねる」とされている。** **要件を満たしているかだけを見る。**
- **書き込み本体と再計算の成否を 1 つに畳み込んだかどうか**——**§9.2-2 で「委ねる」とされている。**
- **再計算の失敗の見せ方**——**§9.2-3 で「委ねる」とされている。** **伝わるかだけを見る。**
- **エイリアス編集の直後に古い表記が一瞬見えること自体**——**開発者が許容している**（**D-356**）。**「同期させるべきだ」は本サブへの指摘にしない。**
- **`config.toml` の env 上書き値の焼き付き**——**改善レーンの担当である**（followup `config-toml-write-back-env-asymmetry`）。
- **`*config.Config` への無同期リード/ライト**——**followup `preset-config-unsynchronized-read`。** **本サブの範囲外である**（指示書 §1.3）。
- **`P-34` の 27 行に与える値の良し悪し**——**本サブは値を決めない。** **列挙の網羅と分類だけを見る。**
- **★書き込みと再計算が 2 トランザクションに分かれていること自体**——**D-360 で裁定済みである。** **「保存は成功したが再計算に失敗した」状態は設計どおりであり、`D-356` で開発者が許容した形と同じである。** **「単一トランザクションにすべきだ」を指摘にしない。**
- **★`SUPP-001` §7.5.4 と一致していないこと自体**——**明示的な例外である**（§4.4-6）。**完了報告に書かれているかだけを見る。**
- **★`punishfinder` に diff があること自体**——**D-360 の例外である**（§2）。**範囲が「注入された既定値を渡す」だけかを見る。**
- **★起動時の告知を画面に出していないこと**——**本サブでは行わないと確定している**（**D-358**）。**「利用者が気づけない」を本サブへの指摘にしない。** **要ると判断した時点で別に足す。**
