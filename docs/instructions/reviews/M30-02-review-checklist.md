## 7. ★★「緑でも壊れているもの」を探す観点（**本書の値打ち**）

| # | 観点 |
|---|---|
| **★★1** | **★`testid` を変えたテストは、変えた本人が同時に直す。⇒ 「テストが緑」は「セレクタが正しい」を意味しない**（両方を同じ手で書き換えたなら、両方が間違っていても緑になる）**。★spec 側だけ見て、実装で本当にその id が出ているかを 1 度確かめること** |
| **★★2** | **★`SD-020` の「既定非表示」は、テストの初期状態が非表示なら何もしなくても緑になりうる。⇒ 表示に切り替えて出ることまで見る試験か** |
| **★★3** | **★強度の判定は `M30-01` の `parseSpecialCode` と隣り合う。⇒ 本サブが強度の解釈を変えると、必殺技タブの母集団が黙って動く。★母集団の件数を固定した試験が在るなら、それが動いていないかを見る** |
| **★★4** | **★実測の母集団を疑う**（`M-145`）**。⇒ 「強度なし技」を数えたとき、`moves` テーブルを数えたか `character_data/*.csv` を数えたか。★後者なら 283 行を取り落としている** |
