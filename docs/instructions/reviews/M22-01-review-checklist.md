### 0.2 レビューの基本姿勢

**★最重要ゲートは 2 つ。どちらも「破っても緑になる」型である。**

1. **`password_hash` が API へ漏れていないこと**（指示書 §4.2）。**★これは「うっかり」で成立する穴である**——**`SecurityConfig` に足したフィールドが DTO の変換で機械的に運ばれる形になっていると、ハッシュが平文の LAN 上を流れる。** **画面には何も出ないため、誰も気づかない。**
2. **`password_enabled = false` のとき、1 バイトも挙動が変わらないこと**（同 §4.9）。**★既定が OFF である以上、いまの全利用者は OFF のまま使い続ける。** **⇒ 本サブで最も広く影響する性質でありながら、新機能のテストは ON の経路を通すため、OFF が壊れても緑のままになる。**

**★次点は 2 つ。**

3. **ログにパスワード・ハッシュ・セッション ID が出ないこと**（同 §4.8）。**★本サブで初めてマスク対象の実データが発生する**——`M22-RESEARCH-01` §9-B-8 が「マスキングを固定するテストは在るが、マスク対象の実データは発生しない」と実測している。**「テストが在る」は「効いている」ではない。**
4. **保護対象から外す経路の列挙が正しいこと**（同 §4.5-2）。**★ログイン自身を除外し忘れると、ログインすらできなくなる。**
