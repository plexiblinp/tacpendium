## 1. 設計・パターンとの照合（最重要）

### 1.1 filler 規則の是正（指示書 §4.1）
- [ ] filler 候補が **`total ≥ 1` かつ `category != 'target_combo'`** で実装されている。
- [ ] 除外が**一箇所に集約**されている（SQL の WHERE かアプリ側フィルタのどちらか。**二重実装していない**）。
- [ ] **`is_derived = true` を一律除外していない**（`is_derived` を「単独入力不可」と読み替えていない＝§9.1-4）。
- [ ] **`rush_variant` を filler から除外していない**（通し値の起点はニュートラル起点で確定済み）。
- [ ] **`setup_only = true` の技が filler 候補に含まれている**（撤回済み仕様が再混入していない）。
- [ ] 判別不能な状態前提技（`denjin_charge` 等）を**機械除外していない**（告知で吸収する方針＝§4.1）。

### 1.2 負 KA の専用応答（指示書 §4.2）
- [ ] `KA < 0` で **200** ＋ **専用理由コード** ＋ `items` が空配列。**400 を返していない**。
- [ ] KA が NULL の場合は既存どおり **400 ＋ `knockdown_advantage_required`**（不変）。**負 KA と同一コードにしていない**。
- [ ] UI に **「有利フレームがマイナスのためセットプレイはありません」**（開発者確定文言）が表示され、KA NULL の文言と**区別**されている。ja/en parity。

### 1.3 打ち切り仕様の是正（指示書 §4.3・**本サブの中核**）
- [ ] **グルーが全解をランキングしてから `limit` で切っている**。エンジンの `MaxResults` による打ち切りが**ランキングより前に結果を決めていない**。
- [ ] **`limit` を小さくしたとき、残るのが N 降順（gap は G 昇順）の上位**であり、**少手数順の上位ではない**（§5.2 の検証があるか）。
- [ ] `SuggestionsResponse` に **`totalFound`** が追加されている（既存フィールドは不変）。
- [ ] **`truncated` の意味が「エンジンの安全上限に到達」に限定**されている。`limit` で切っただけの状態で `true` になっていない。
- [ ] **`alreadyAdopted` が返却する `items` の分だけ算出**されている（打ち切り前の全件で回していない＝N+1 の解消）。
- [ ] `limit` に**上限があり、超過指定が丸められる**（エラーにしていない）。
- [ ] **`MaxResults` 安全上限・`limit` 既定・`limit` 上限が、§3.3-1 の実測に基づいて決められ、根拠が完了報告にある**（実測なしに数値が決まっていない＝§9.1-5）。

### 1.4 gap モード（指示書 §4.4）
- [ ] 受理帯が **帯の下限・上限（`NLo`／`NHi`）で一般化**され、`budgetMax = KA + 2 − NLo − Startup`／受理 `0 ≤ remaining ≤ NHi − NLo`／`N = remaining + NLo` になっている。
- [ ] **meaty モードが `NLo = NMin`・`NHi = Active` に写像**され、**既存テストが無改修で通る**（挙動不変）。
- [ ] gap モードが **`NLo = Active + Gmin`・`NHi = Active + Gmax`** で実装されている（**帯が target ごとの `Active` に依存する**）。**独自の別式を持ち込んでいない**。
- [ ] **`G = N − active`** の恒等式が成立し、gap では **`N > active`**（meaty と完全に排他）になっている（`N = KA + 2 − S` を維持したまま導かれている）。
- [ ] **探索構造（反復深化・少手数優先・枝刈り・`sanitize`・`computeMaxDepth`）が温存**されている。
- [ ] **枝刈りが帯に入る解を切り落としていない**（`NLo > Active` で `budgetMax` が小さい入力で下限側・上限側の両方が列挙される＝§5.1-9）。
- [ ] `NLo > NHi` が**エラーではなく空結果**。`Active < 1` は gap でも `ErrInvalidTargetActive`。
- [ ] API が `mode=meaty|gap`／`g_min`／`g_max` を受け、**`mode` 省略時 meaty**（後方互換）。
- [ ] **`mode=gap` で `n_min` が無視**され、**`mode=meaty` で `g_min`／`g_max` が無視**される（いずれもエラーにしていない）。
- [ ] `g_max` が **13 で丸め**られ、`g_min < 1` が 1 に丸められ、`g_min > g_max` が空結果。**`G` の範囲を実装都合で広げていない**（§9.1-6）。
- [ ] `SuggestionDTO` に **`mode`／`g` が追加**され、**`n` の型・意味が変更されていない**（gap で `n > active` になるのは恒等式どおりで正しい）。
- [ ] gap モードの `sort=n` が **G 昇順**で、かつ **`G` を直接比較**している（`N` で並べても `G` 順にならない＝target ごとに `active` が異なるため）。`sort=target` は meaty と同じ。
