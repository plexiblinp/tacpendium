## 1. 【最重要】§4.3 の実測と判定

- [ ] **実測表**が**キャラ別（6 キャラ分）**にあるか（§3.3-3 の (a)〜(e)）: (a) 正準形違反／(b) **過長 code（40 字超）の件数＋実例＋最長字数**／(c) 公式英語名の誤りに由来すると推定される code（**luke が本命**）／(d) 同一キャラ内 `move_code` 重複／(e) `name_ja` の接頭語欠落。**実例（`move_code` と `name_ja` の対）**があるか。
- [ ] **判定が「類型あり 4 体（m_bison / rashid / jamie / luke）」と「類型なし 2 体（marisa / jp）」を切り分けて書かれている**か。**類型に該当しない 2 体でも同じ問題が出たなら「量産波では全キャラで本観点を見る」、出なければ「類型のあるキャラに限って見る」**という形で、量産波の前提に落ちているか。**対照群を一緒くたにして平均で語っていないか。**
- [ ] **過長 code の実害判定**が **実コードでの確認に基づいている**か: **`move_code` に長さ制約が無いか**（DDL）・**CSV 往復に影響しないか**・**画面18／レシピ表示でレイアウトが壊れないか**（E2E で確認したか）。**「実害なし＝許容」「実害あり＝どこで壊れるか」のいずれかで明示**されているか。**推測（「たぶん大丈夫」）で済ませていないか**。
- [ ] **luke（公式英語名の誤り）の判定**があるか。**juri（第一波・投入済み・同類型で実害なし）と同じ結論か**、違うなら理由が示されているか。
- [ ] **量産波（M14-03f 以降）への申し送り**（残キャラで同じ問題が出る見込みと扱い＝「以降は品質問題なしで量産できる」or「この観点だけは毎回見る」）があるか。

## 2. `move_code` を是正していない（重点）

- [ ] **`move_code` の再採番・自動リネーム・自動修正を一切していない**か（**CSV が正**）。
- [ ] **過長 code を短縮していない**か（**正準形としては合法**＝機械的に落とさない・判断は開発者）。
- [ ] 正準形（`^[a-z0-9_]+$`）に反する code があった場合、**生成を止めて報告**しているか。
- [ ] **dup 検出時に自動リネーム・自動 skip をしていない**か（**生成 fail ＋一覧報告**が正）。

## 3. 変換インフラの再利用（「二度作らない」）

- [ ] **M14-03b の seedgen を再利用**しているか（**新規実装・コピー実装・手作業生成をしていない**）。
- [ ] **変換規則が無改変**か＝**既定生成物 `000026` が byte-identical**（**golden ＋ `-check` の結果が完了報告にある**）。**1 byte でも差分があれば重大**。
- [ ] seedgen の拡張が要った場合、**M14-03c §4.3.1 の 3 条件**を満たし Plan Mode で提示されているか。索引器（`internal/moveindex`）が**無改変**か。
- [ ] **生成マイグレ 1 本につき golden テスト 1 本**があるか。

## 4. seed の健全性

- [ ] **新規連番**（実査で確定・**M14-03d の消費分の次**）で追加され、**既存マイグレが非改変**か。**消費した連番が完了報告に明記**されているか。**M19-04 と並列で走った場合、M19-04 が宣言した消費予定本数の次から払い出しているか**（ボード D-104）。
- [ ] **★前提マイグレ 2 本が本サブで作られているか**（**`characters` 行の投入**・**移動 system move 9 種の投入**）。**「M14-03b で全キャラ投入済み」を前提にして飛ばしていないか**——**既存 seed マイグレは適用時点に存在した行にしか効かず、`NOT EXISTS` ガードは冪等性のためであって後から増えた行を遡って埋めない**（§3.2 訂正・§3.3-10／11）。**実査結果が完了報告にあるか。**
- [ ] **★`INSERT … FROM characters c WHERE c.code='X'` 型に対して、投入件数を固定するテストがあるか**（§3.3-12）。**親行が無いとエラーではなく 0 行投入になり、マイグレは成功する**（サイレント no-op）。**テストが無い＝事故を検出できない。**
- [ ] **alias（`official_ja_move`）が対で投入**されているか（生 code フォールバックが出ない）。**FK 依存順**（moves → preset_aliases）。
- [ ] **移動 system move 9 種を再投入していない**か（CSV に含まれていても **drop**）。**`drive_parry` は通過**か。
- [ ] **dup スキャン**が 6 キャラ（or 縮小投入分）に適用されているか。**キャラ間の衝突は起きない**（`character_id` で分離）ことを踏まえ、**キャラ内衝突と alias 衝突**を見ているか。
- [ ] **clean マイグレ由来 DB から構築**され、**dev DB 残渣が混入していない**か（**構築方法と証跡が報告にある**か）。**dev DB の事前退避**。
- [ ] 冪等性・down 整合・`dbtest.Setup` 全テスト通過。件数前提テストの追従。

## 5. 非破壊（重点）

- [ ] **他キャラ非波及**（件数で確認）。**ryu・第一波 9 キャラ・manon の moves/alias/custom_states が不変**か。
- [ ] 本体ランタイムに取込経路を復活させていない（FR704 降格の維持）。

- [ ] **★既知 flakiness の判定根拠が完了報告にあるか**——3 回走らせて毎回異なる spec が 1 件落ちる（**単独実行では green**）。**落ちた spec を単独実行して green なら本波の回帰ではない**と判定してよいが、**その判定の根拠が書かれているか**（followup `e2e-flaky-isolation`）。**「flaky なので無視した」だけの記述は不可。**

## 9. 重大な問題（完了承認を妨げる）

- **§4.3 の実測表・判定が無い / 判定が曖昧**。**過長 code の実害判定が推測**（実コード確認に基づいていない）。
- Plan Mode 13 項目のいずれかが未確認のまま実装（推測実装）。**とくに 3（6 キャラ CSV の実測）・10／11（前提マイグレの要否）・13（`chain_cancel_total` 列の存在）を飛ばした**。
- **★前提マイグレを作らずに seed を流した**（**`characters` 行が無い状態で `INSERT … FROM characters` を流すと、エラーではなく 0 行投入でマイグレが成功する**＝サイレント no-op）。**投入件数を固定するテストが無い。**
- **★`chain_cancel_total` の列が無いのに UPDATE を書いた**（`no such column` でマイグレが失敗する）。
- **★`chain_cancel_total` を「total − 4」等の規則で埋めた**。**実測資料でなく CSV から読んだ／CSV へ転記した**。**マリーザ・ルークの 2 技構成を 3 技として扱った**。
- **★`internal/seedgen` の `CustomHeader` を直した**（**ヘッダの provenance は既知の誤りだが、直すと golden 4 stem が byte 単位で全部変わる**＝followup `seedgen-header-provenance`）。
- **`move_code` を是正した**（再採番・自動リネーム・自動修正・**過長 code の短縮**）。
- **dup 検出が非 0 で自動リネーム・自動 skip して投入した**。
- **seedgen の変換規則を改変した**（**`000026` の golden が byte-identical でない**）。**新規実装・コピー実装・手作業生成した**。
- **input-tool（別 module）を修正した**（スコープ外＝報告のみ）。
- **移動 system move 9 種を seedgen 経路で再投入・削除した**。**`drive_parry` を巻き込んだ**（※**本波 6 キャラ分を前提マイグレで新規投入するのは正しい**＝§4）。
- **他キャラ（ryu・第一波・manon）に波及した**。
- **dev DB 残渣が混入している**（clean 構築の証跡が無い）。
- スキーマを変更した。既存マイグレを改変した。`dbtest.Setup` を破壊した。down 整合が無い。
- **配布 blocker を「解除した」と報告している**（解除は全キャラ充足時点＝最終波）。
