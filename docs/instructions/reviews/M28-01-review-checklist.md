| # | 危険 | なぜ検出しにくいか |

## 8. 重大な問題の判定基準（完了承認を妨げる）

1. **旧データディレクトリを削除している。**
2. **移行の順序が「コピー → 検証 → 退避」になっていない、または (d) で旧が壊れる。**
3. **歴史記録が書き換わっている。**
4. **一括置換で `scripts/check-*.sh` を巻き込んでいる**（**★ベースラインが黙って動いた場合を含む**）。
5. **`go build` / `go test` / `pnpm test` / `make e2e` のいずれかが赤。**
6. **`docs/design/` を編集している。**
7. **`.claude/` を編集している。**
8. **CHANGE 番号・マイグレ連番を自採番している。**

## 9. 軽微な問題の判定基準（持ち越し許容）

- 綴りの揺れのうち、コメント内の 1〜2 件の取り残し（**★報告に載っていれば可**）。
- 起動ログの文言。
- `README.md` / `README.txt` の案の粒度。

## 10. レビュー完了の判定

- 束 A / B / C と §4〜§7 をすべて見た。
- 重大が 0 件、または重大の是正が完了している。
- **★§0.3 の 8 項目を欠陥として挙げていない。**
