## 0. レビュー担当への前置き

### 0.1 レビュー前の準備

1. 指示書 **v1.0.0** と `CHANGE-136` 通知書を全文読む。
2. 完了報告 `docs/progress/M24-11-completion-report.md` を読む。
3. **★★`DES-006` §2.3 を読む。** **とくに「NULL 同士は一致」と「`deleted_at IS NULL` を外してはならない」の 2 か所。**
4. **★`DES-002` §4.2 の DSN の `_pragma` ブロックと §6.4（同時実行制御）を読む。**
5. **★★`SUPP-001` §7.1.1 を読む**（**本サブの最大のリスクがそこに在る**）。

### 0.2 レビューの基本姿勢

コードを変更せず、指摘のみを行う。

**★★本サブは「緑になったか」では判定できない。** **同時実行の欠陥は、直さなくても出ないことがある。** **⇒ 機序と破壊確認で判定する。**

### 0.3 ★★重大でないもの（**誤判定しないこと**）

| # | これは欠陥ではない |
|---|---|
| **1** | **★★§4.3 の「書き込み tx の内側から非 tx を撃つ箇所」が見つかり、直さずに報告されていること。** **指示書 §4.3 が「直すと射程が広がるものは報告する」を正しい結末としている**〔**★契約 F-1 の凍結パッケージ内なら触れない**〕 |
| **2** | **★★§4.4 の「手当てが要る check-then-act」が直されていないこと。** **指示書 §4.4 が「一覧を作るところまで」と定めている**〔**`VAL-P05` は凍結パッケージ内である**〕 |
| **3** | **★★§4.5 の既存データの重複が消されていないこと。** **指示書が「検出だけ行い、消さない」と定めている**〔**利用者のデータである**〕 |
| **4** | **★保存ボタンの二度押しが直っていないこと**（§1.3-5。**`M24-04` の面**） |

指摘は **重大 / 高 / 中 / 低** で分類し、各件に**根拠**（ファイル:行 または 出力の逐語）を添える。

## 8. 重大な問題の判定基準（完了承認を妨げる）

1. **★再現テストの「直す前に赤」または「直した後に緑」が欠けている**（1-1）。
2. **★「直った」の根拠が緑の回数だけである**（1-2）。
3. **★検証に `*sql.DB` 直読みが残っている**（1-6）。
4. **★`migrations/` に差分がある**（2-1）。
5. **`DES-006` §2.3 の判定条件が変わっている**（2-2）／ **`deleted_at IS NULL` ／ `is_draft = 0` が変わっている**（2-3）。
6. **DSN の `_pragma` 4 種・`file:` 形式が変わっている／`Exec` 流しへ戻っている**（2-4）。
7. **マイグレーション接続の `FK=OFF` を揃えにいっている**（2-5）。
8. **楽観排他の対象・粒度が変わっている**（2-6）／ **契約 F-1 の凍結パッケージに差分がある**（2-7）。
9. **`check-*.sh` の判定ロジックを緩めている**（2-10）。
10. **★「書き込み tx の内側から非 tx を撃つ箇所」の全数が無い**（3-4）。
11. **★`PUT` が従来どおり通るテストが無い**（5-4）。
12. **DSN を守るテスト**（5-6）／ **`CHANGE-125` の 4 件**（5-7）／ **楽観排他**（5-8）**が落ちている。**
13. **★破壊確認 1 で赤くならない**（6-2）／ **破壊確認 3 が赤くならず報告も無い**（6-3）／ **全件緑のまま「実施した」で終わっている**（6-4）。
