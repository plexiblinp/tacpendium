- M19-RESEARCH-01／-02 report の窓方式の定義（`N = KA+2−S`）を把握しておく。

## 1. 設計・パターンとの照合（最重要）

### 1.1 受理帯方式の正しさ
- [ ] 予算が `budgetMax = KA + 2 − NMin − target.Startup` で計算されている（指示書 §4.1.3）。
- [ ] 受理条件が **`0 ≤ remaining ≤ target.Active − NMin`** の**帯**である。`remaining == 0` や `S == KA + 1` のような**等値になっていない**（§4.1.3・§9.1-4）。
- [ ] N が `remaining + NMin` で得られ、かつ `KA + 2 − S` と一致する（§4.1.3）。
- [ ] 境界条件が表どおり（`Active < 1` → `ErrInvalidTargetActive`／`NMin > Active` → **空結果**／`NMin < 1` → **1 に丸め**／`budgetMax < 0` → 空結果）（§4.1.4）。**`NMin > Active` をエラーにしていないこと**。

### 1.2 移植の健全性
- [ ] 移植先が `internal/service/setplay` で、**stdlib 以外の import が増えていない**（`go.mod` 差分で確認）（§4.1.1・§7.1）。
- [ ] **別リポ `autopilot-combomgr/projects/setplay-suggestion` が変更されていない**（§2.2）。
- [ ] 反復深化・枝刈り・`sanitize`・`computeMaxDepth` の既存構造が温存されている（§4.1.5）。
- [ ] `Suggestion.TotalFrames` の意味変更（KA → S）に伴い、移植テストの期待値が修正され、**件数が完了報告に記載**されている（§4.1.6）。

### 1.3 グルー・API
- [ ] target 候補が `startup ≥ 1` かつ `active ≥ 1` で絞られている（§4.2）。
- [ ] target 条件が §4.2 の 3 条件（`startup ≥ 1 ∧ active ≥ 1`／**`is_derived = false`**／**`is_aerial = false`**）で実装されている。
- [ ] **`target_move_id` 明示指定時は条件 2・3 を適用しない**（条件 1 は適用する）（§4.2）。
- [ ] `is_derived` が **BE 内の SELECT で参照**されており、API 露出が必須化されていない（UI 表示に使う場合のみ §2.3 例外条項に従う）（§4.2）。
- [ ] `target_move_id` による**明示指定モード**が存在する（§4.2-3・§4.3）。
- [ ] filler 候補が `total ≥ 1` の**全技**である。**`setup_only` による絞り込みを実装していない**（§4.5）。**`setup_only = true` の技が filler 候補に含まれている**（セットプレイ専用 move ＝除外してはならない）。
- [ ] エンドポイントが `GET /api/combos/:comboId/setplay-suggestions` で、`n_min`／`sort`／`target_move_id` を受ける（§4.3）。
- [ ] KA が NULL のコンボで **400 系**を返し、UI が理由表示できるエラーコードを含む（§4.3）。

### 1.4 ランキングと DTO
- [ ] ランキングが **N 降順 → 手数昇順 → Σtotal 昇順 → Name 昇順**（`sort=steps` で第 1・第 2 キー入替）（§4.4）。

- [ ] DTO の `role` 値域に **`"parent"` が定義**され、`counted` フィールドが**存在**する（本サブでは出力しない／常に true）（§4.4）。

## 9. 重大な問題の判定基準（完了承認を妨げる）

- **受理条件が帯になっていない**（`remaining == 0` のまま、または `== KA+1` 等の等値に変更されている）。窓方式の中核であり、これが崩れると golden-case が再現しない。
- **マイグレーション・新テーブル・新列が追加されている**（本サブは中央スキーマ非依存で完結する設計。moves 系の列追加は中央帰属＝§9.1-2）。
- **既存 FR011 候補機能が壊れている**（API シグネチャ変更・表示の消失・挙動変更）。
- **golden-case が 4/4 に達していない**、または実測せずに「通った」と報告している。
- **`selectedIds` を提案の入口に使っている**（DES-005 §5.13a の誤流用・E-20 の 1 本動線を崩す）。
- **`setup_only` による filler 絞り込みを実装している**（コンボ登録 UI から技が消える副作用＋golden-case 全滅のリスク＝§4.5）。
- **採択保存で `parent_combo_id` を渡していない**（VAL-S05 違反＝保存が必ず失敗する）。
- **制約告知が毎回表示になっている**、または**初回にも出ない**（§4.6.3 の意図＝初回だけ伝えて以降は邪魔しない、を満たさない）。
- **`M19-LIMITATION-NOTICE` マーカーが欠落している**（次回改修時に文面の更新漏れが確実に起きるため、軽微ではなく重大とする）。
- **提案 UI 面を再設計している**（既存要素の移動・削除。M18-03／E-1 と交差する面のため＝§9.1-1）。
- **提案が自動確定している**（FR307 違反）。
- **スコープ外（through target・表記展開・GC-2 対応）に手を出している**、または `moves` に列を追加している。
- **製造担当が DES 本体を直接編集している**。
- **Plan Mode の実査（§3.3）を経ずに実装している**（特に `moves.active` 充足率・非攻撃技の分布を確認せず target 列挙を実装している）。
- 推測実装（§9.1 の項目を独自解釈で進めている）。
- 別リポ `setplay-suggestion` のソースを変更している。

## 10. 軽微な問題の判定基準（持ち越し許容）

- `setups.name` 自動生成フォーマットの細部（VAL-S06 を満たす限り）。
- ソート切替 UI の配置・見た目。

- `MaxResults` 既定値の維持／変更（根拠と実測が報告されていれば）。
- 新規ファイルの分割粒度（既存構成に沿っていれば）。
