## 8. 重大な問題の判定基準（完了承認を妨げる）

- **識別キー変更編集で検証結果が失われる**（§4.2 の要件不達。**利用者データの消失**）。
- **`ON DELETE CASCADE` だけで足りると判断している**（削除しか守らない）。
- **`result` に NULL を入れて三値を表している**、または「未検証」を意味する `result` の値を作っている。
- **既存テーブルに ALTER を打っている**、または **`moves` に触れている**。
- **マイグレ連番を自採番している**（中央払い出しを経ていない）。
- **セットプレイ編集画面に成立条件 UI を置いている**（`comboId` を持たず保存先を特定できない＝M19-01 の `SetupSelectorModal` と同型の失敗）。
- **紐付けが存在しない組への書き込みが通る**。
- **検証日時・timestamps の列を先回りして追加している**。
- **`OKI_TECH_TYPE_LABELS` を使わず第 3 の語彙を作っている**、または `combos.position` の値を `in_corner` に流用している。
- **BE で日本語固定文字列を組んで保存している**。
- **M19-01／M19-02 の delivered 契約が壊れている**（提案の非永続・gap の定義・打ち切りの構造・採用保存の経路）。
- **項目10 の既存挙動が壊れている**（常時展開・行クリックでの遷移・紐付け解除）。
- **コンボ詳細の面を再設計している**（既存要素の移動・削除。M18-03 系／E-1 と交差する面＝§9.1-1）。
- **採用ダイアログで不成立を記録できる**、または**チェックしないと採用できない**。
- **スコープ外**（一覧の絞り込み・提案ロジックへの反映・検証日時・`moves` 系）に手を出している。
- **Plan Mode の実査（§3.3）を経ずに実装している**（特に §3.3-1 を実査せず §4.2 の方式を決めている）。
- **§5.6 の否定形確認が未実施**。
- 推測実装（§9.1 の項目を独自解釈で進めている）。

## 9. 軽微な問題の判定基準（持ち越し許容）

- 2×2 グリッドの見た目・アイコンの選択・凡例の配置。
- 3 状態の操作形式（巡回トグル／選択肢／その他）。要件を満たしていれば可。
- `note` 入力欄の出し方（インライン／展開）。
- モデル・リポジトリ・エンドポイント・i18n キーの命名の細部（既存規約に沿っていれば）。
- インデックスの要否（追加した場合に根拠があれば）。
- 取得方式（同梱 / 専用エンドポイント）の選択（N+1 になっていなければ）。
