## 0. ★★レビュー担当への前置き

**★★★本サブが作るのは 1 行の不変条件である。**

```
start_position_mass IS NULL  ⇔  position = 不問
```

**★★これは `POST` / `PUT` では着手前から成り立っていた。⇒ 穴は `PATCH` だけである。★新しい規則を作るサブではない。**

| # | 本サブ固有の不合格 |
|---|---|
| **1** | **★★★`PATCH` で `position` が変わりうる**（**★`normalizePositionAndMass` をそのまま呼んだ形を含む**） |
| **2** | **★★★`carry_distance_mass` が埋まる** |
| **3** | **★★`position` が不問の行のマス数が埋まる** |
| **4** | **★★既存行を黙って埋め戻した** |
| **5** | **★CSV の取り込みが落ちるようになった** |

## 1. 束 A — ★★★`PATCH` から `position` が動かないこと（**最重要**）

| # | 観点 |
|---|---|
| **A-1** | **★★★`PATCH` 経路が `position` を 1 バイトも書かないか。⇒ SET 句・入力 struct・サービス層のいずれにも現れないか** |
| **A-2** | **★★★`normalizePositionAndMass` をそのまま `PATCH` から呼んでいないか。⇒ 同関数は*導出*も行う**（指示書 §0.3） |
| **A-3** | **★★★破壊確認が在るか＝区分をまたぐマス数を `PATCH` へ投げても `position` が変わらないこと**（§5-3）**。⇒ 画面からは起きないが、契約として押さえる必要がある** |
| **A-4** | **★★同じ破壊確認の逆向きが在るか＝補完を外すと NULL のまま保存されること。⇒ 無ければ「補完が効いた」ことの証拠にならない** |
| **A-5** | **★`PUT` の挙動が変わっていないか。⇒ `normalizePositionAndMass` の既存呼び出し 2 か所**（Create / UpdateWithKeyChange）**が無傷か** |
| **A-6** | **★重複判定キーの扱いが変わっていないか。⇒ `extractKeyFields` / `hasKeyChanges` に差分が無いか** |

## 2. 束 B — ★★★不変条件そのもの

| # | 観点 |
|---|---|
| **B-1** | **★★★`POST` / `PATCH` / `PUT` の 3 経路すべてで不変条件が成り立つ実測が在るか**（§5-1）**。⇒ 1 経路だけで閉じていないか** |
| **B-2** | **★★区分が決まっている行でマス数を `null` にして保存 → 代表値が入るか** |
| **B-3** | **★★★`position` が*不問*の行 → NULL のままか。⇒ 埋まっていたら不合格**（指示書 §0.1） |
| **B-4** | **★★元から NULL の行でメモだけを `PATCH` したときも代表値が入るか。⇒ これは意図した形である**（`D-864`。**★報告に 1 行在るか**） |
| **B-5** | **★NULL に 2 つ目の意味**〔「未測定」「クリア済み」等〕**を持たせていないか**（指示書 §4.2） |
