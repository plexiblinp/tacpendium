## 1. 背景と目的

### 1.1 背景

セットプレイ提案は**フレーム計算のみで候補を導出している**が、その計算が**連打キャンセルを考慮していない**ため、**物理的に入力できないレシピを提案している**（弱P を 2 発つなぐとき、実機 22F で済むところを 26F として計算している）。

原因は、`moves.startup` / `moves.total` に「**単独で出したときの値**」と「**連携の中で出したときの通し値**」が**同じ列に混在しており、行を見ても判別できない**ことである。

本サブは**その区別を持つ列を足し、値を入れる**ところまでを行う。**値の消費は M19-05。**

### 1.2 目的

1. `moves` に **3 列**と関連表 **1 本**を追加する。
2. **機械で決まる値を backfill する**（条件式で書ける）。
3. **人手判断が要る行の一覧を出力し、開発者が記入した値を反映する**（Phase 2・条件付き）。
4. ザンギエフの連打版 3 行を `moves` へ登録する。
5. **確定反撃サーチに一切干渉しないことを、実装で担保する。**

### 1.3 スコープ外（やらないこと）

- **新列をエンジン・既存 API に露出させない**（契約 F-3。消費は M19-05）。
- **`internal/service/punishfinder/` に触らない**（契約 F-1）。
- **`moves.startup` / `moves.total` の既存値を 1 行も書き換えない**（契約 F-2）。
- **`is_derived` / `is_aerial` の値やロジックを触らない**（契約 F-5。**DES-004 の説明文言の是正のみ**が反映対象で、それは実装後に親が行う）。
- **`internal/seedgen` の既存生成関数（`writeMovesInsert` 等）に触らない**（§4.2 の三点更新と、Phase 2 の**新規ファイル**のみ）。

- **DES 本体を編集しない**（設計書の改訂は実装後に親が行う）。

**★「total − 4」で埋めてはならない。** 実測資料 §1 が、**同一の単発値が最大 3 通りの実消費に割れる**ことを多重検算つきで示している（例：`5/3/8/15` が 11 / 11 / 12 / 13）。**未実測の技を規則で埋めることは禁止**であり、本サブでも**資料に無い行は NULL のままにする**。

**投入方法**: **手書きの UPDATE マイグレ**（`is_projectile` の 000041 と同型＝値の一次源が DB / CSV / マイグレのどこにも無いケース）。**値を持つ行だけを列挙して UPDATE する。**

**★件数を固定するテストを必ず書く**（§5-1）。写像を誤ると**別の技に値が入る**が、これは**エラーにならない**。

### 4.5 rush 生成経路への `startup_basis = 'through'` 明示

`internal/repository/move/rush.go` の `insertRushVariantSQL`（明示列挙 INSERT）に **`startup_basis = 'through'` を追加する**。

**★理由**: 新列は列挙されないと DDL の DEFAULT（`unknown`）で入る。**機械 backfill は 1 回きりのマイグレなので、その後に生成される rush 行だけが `unknown` のまま残る**——**型エラーにも実行時エラーにもならない「静かに壊れる」型**である。

**`chain_cancel_total`（NULL）と `fastest_unreachable`（false）は DEFAULT のままでよい。**

### 4.6 ザンギエフ連打版 3 行の INSERT マイグレ

- 実測値は **`M19-DESIGN-07` §1-3 に確定済み**。**追加実測は不要。**
- **手書き INSERT マイグレ**とする。**`zangief.csv` には足さない。**

**★CSV に足さない理由**: CSV に行を足すと `Generate` が読む行が増えて **`000026` の生成物が変わり golden が壊れる**。再生成しても**既存 DB には届かない**（適用済み連番は再実行されない）ため**手書きマイグレは別途必要**であり、CSV にも足すと**同じ 3 行が 2 か所に存在してどちらが正か分からなくなる**。**乖離は followup `csv-edit-vs-golden-divergence` に紐づける**（ボード D-94）。

- **新規行にも新列の値を明示的に与えること。** **【2026-08-02 是正】旧版の括弧書き「`startup_basis` は連打版なので `through` が妥当」は誤誘導だったため削除した**——**正は `standalone`** であり、根拠は **DESIGN-07 §9-1**（「`basis=standalone` ＋ 親参照（グループ員）を付与 → 既存導出で単独入力不可が成立」）である。**旧版が指していた §1-3 は su/act/rec/total の実測値表であって `startup_basis` に言及していない**（製造が委任先の節を開いて食い違いを発見し、正本を採った＝ボード D-127 で受理）。
- **ただし実測値列は転記マイグレへ集約してよい**（`chain_cancel_total` を新規行の INSERT で与えず、実測資料からの転記マイグレでまとめて投入する形）。**値の一次源を 2 か所に散らさず、1 つの件数固定テストで担保できる**ためである。**★その場合、転記マイグレは INSERT マイグレより後の連番でなければならない。** 前に置くと**新規行が 0 件更新になり、それはエラーにならない**。**両マイグレのコメントに順序制約を明記すること**（ボード D-126）。
- **確定反撃サーチの候補集合が変わる可能性がある。** §5-2 の canary で増分を必ず測り、**内訳を報告する**。
