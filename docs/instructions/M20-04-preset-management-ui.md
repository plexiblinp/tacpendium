## 1. 背景と目的

### 1.1 背景

**プリセットは M20-01〜03 で「読める・引ける・一意である」状態まで来た。** **しかし利用者から見ると、まだ 1 つも操作できない。**

| 実測（2026-08-12・M20-01。**§3.3 で再確認する**） | 状態 |
|---|---|
| `/presets` ルート | **router.tsx に未定義。** Header にリンクはあるが **disabled** |
| `internal/api/preset/` | **読み取り 2 本のみ**（`GET /api/presets` ／ `GET /api/presets/:id`） |
| `internal/service/preset/` | **`doc.go` のみ** |
| 組み込みプリセットの保護（403） | **未実装** |
| 上限検査（`DES-006` VAL-P05・8 件） | **実装 0 件** |

**★つまり本サブは「画面を作る」サブではなく、「書き込み経路をはじめて作る」サブである。** **`preset_aliases` へ INSERT する本番コードは、2026-08-13 時点で 1 つも存在しない**（M20-03 の実査）。**本サブがその最初の 1 本になる。**

### 1.2 目的

1. **プリセット一覧画面**（`DES-005` §5.10）**と プリセット編集画面**（§5.11）**を作る。**
2. **組み込みプリセットをコピーしてカスタムプリセットを作る**（`DES-004` §6.1。**コピー時にエイリアスを実体化する**）。
3. **保護と上限を実装する**——**組み込みは削除も編集もできない**（403）／**全体 8 件**（組み込み 3 ＋ カスタム 5）。
4. **削除で孤児行を残さない**（**P-04 により `ON DELETE CASCADE` が発火しないため**）。

### 1.3 このサブで作らないもの（スコープ外）

| 対象 | 理由 |
|------|------|
| **`recipe_cache` の再計算・トリガ接続** | **M20-05。** **★本サブは `recipe_cache` を読み書きしない**（§2.2-1）。**編集後に stale になることを完了報告に書く**（§4.7） |
| **ベースプリセット更新時の追従**（自動反映 / 固定の選択） | **`DES-004` §6.3 が「実装時に検討する」としている領域だが、本サブでは作らない。** **ベースが更新されるのはアプリのアップデート時であり、いま起きない** |
| **エイリアスの一括編集・検索・インポート** | **スコープ外。** §5.11 は「各エイリアス欄を直接編集」と定めている |
| **多言語（`alias_text_en`）の編集** | **★スコープ外。** **`alias_text_en` は生成規則が入れる列であり**（`DES-004` §5.4）、**利用者が編集する対象として設計されていない。** **編集 UI を作ると、規則の再適用で消える**（§4.6） |
| **`P-04`（`PRAGMA foreign_keys` が効かない）の根治** | **既知課題。** **本サブは「CASCADE に頼らない」ことで回避する**（§4.5） |
| **カスタムプリセットの共有・エクスポート** | フェーズ4 以降 |

## 4. 詳細仕様

### 4.1 サービス層の新設（★`M20-05` との境界）

**`internal/service/preset/` を本サブが新設する。**

| 本サブが持つ | `M20-05` が足す |
|---|---|
| **CRUD**（作成＝コピー ／ 名前とエイリアスの更新 ／ 削除） ／ **保護**（403） ／ **上限検査** ／ **コピー時のエイリアス実体化** ／ **削除時の子行削除** | **`recipe_cache` 再計算の接続**（eager）／ **F12-2** ／ `SUPP-001` §7.1・§7.2 の as-built 是正 |

> **★`M20-overview` §3 の M20-05 の行は「preset サービス層の新設」と書いているが、正確ではない**（**2026-08-13 に是正済み**＝ボード **M-53**）。**層そのものは書き込み経路を持つ本サブが作らざるを得ない。** **M20-05 が足すのは、その層へのトリガの配線である。**

### 4.2 API（`DES-002` §4）

| メソッド | パス | 内容 |
|---|---|---|
| `POST` | `/api/presets` | **カスタムプリセット作成**（**コピー元 `base_preset_code` ＋ 名前**）。**応答は作成されたプリセット** |
| `PUT` | `/api/presets/:id` | **名前とエイリアスの更新。** **★組み込みは 403** |
| `DELETE` | `/api/presets/:id` | **削除。** **★組み込みは 403。** **子行を明示的に消す**（§4.5） |

**★エラーの形**

| 状況 | 応答 |
|---|---|
| 組み込みを編集・削除しようとした | **403** |
| 上限（8 件）を超える作成 | **ERROR**（`DES-006` VAL-P05。**★ステータスは既存の VAL エラーの流儀に合わせる**＝§3.3-2 で実査） |
| **一意制約違反**（同一プリセット・同一キャラで 2 つの技が同表記） | **★400 系で返し、どの表記が衝突したかを利用者へ伝える。** **500 にしない**——**利用者の入力誤りであり、監視から見ると偽の障害になる**（**D-275** の同型） |
| 存在しない `id` | 404 |

### 4.3 コピー時のエイリアス実体化（★最重要）

**カスタムプリセットは、ベースの全エイリアスを自分の行として持つ**（`DES-004` §6.1・§6.2）。**参照ではなく複製である。**

| # | 仕様 |
|---|------|
| 1 | **ベースの `preset_aliases` を全行コピーし、新しい `preset_id` で INSERT する** |
| 2 | **★`character_id` を必ず入れる**（`DES-004` §5.7-1）。**★同列は nullable であり、入れなくても INSERT は通る。** **入れ忘れた行は `UNIQUE(preset_id, character_id, alias_text)` に当たらず、制約を静かにすり抜ける** |
| 3 | **`alias_text_en` もコピーする**（**編集 UI は作らないが、値は引き継ぐ**＝§1.3） |
| 4 | **1 トランザクションで行う。** **途中で失敗したら 1 行も残さない**（§3.3-8 で件数を見積もる） |
| 5 | **`presets.base_preset_code` にベースの `code` を記録する**（`DES-004` §6.3） |
| 6 | **★`presets.id` は AUTOINCREMENT に任せる。** **欠番を詰めない**（§3.3-3） |

> **★テストで固定すること**——**コピー直後、`character_id` が NULL の行が 0 件であること。** **★これは「落ちないバグ」の唯一の検出手段である**（`CHANGE-100` §4 のリスク欄 ／ M20-03 設計伝達レポート §4-3）。

### 4.4 保護（`SUPP-001` §7.3）

| # | 仕様 |
|---|------|
| 1 | **`presets.is_builtin = true` は削除不可**（403） |
| 2 | **★組み込みプリセットのエイリアスは編集不可**（403）。**旧記載「編集は可能」は誤りだった**（**D-290**） |

|---|------|
| 1 | **★CASCADE に頼らない。** **サービス層で子行（`preset_aliases`）を明示的に削除してから親を消す** |
| 2 | **1 トランザクションで行う** |
| 3 | **★削除後に孤児行が 0 件であることをテストで固定する**（**CASCADE が将来効くようになっても、この実装は正しいままである**） |
| 4 | **`config` の `[defaults] preset_id` が削除対象を指している場合の扱いを決めて報告する**（§3.3-6。**設計卓の見込みは「削除を拒否する」だが、覆ってよい**＝§9.2） |

|---|------|

> **★§3.3-5 の実査結果によっては停止条件 1 が発動する**（§9.4）。

### 4.8 否定形確認（撤回した仕様の残骸の全文走査）

|---|---|
| `5` を伴うプリセット数の主張（`len(presets) != 5` 等） | **★組み込みは 3 種である**（M20-01）。**残骸は「組み込みが 5 個ある」前提の箇所。** **`preset_id = 5`（`srk`）は正常な値であり残骸ではない** |
| `10` を伴う上限の主張 | **★上限は 8 件である**（組み込み 3 ＋ カスタム 5）。**旧記載「10 件」は失効** |
| 「組み込みプリセットのエイリアスは編集可能」に相当する記述・分岐 | **★編集不可が正である**（**D-290**）。**コメント・doc・UI 文言も対象** |
| `ON DELETE CASCADE` に依存した削除 | **発火しない**（**P-04**）。**★DDL に書かれていること自体は残骸ではない**——**残骸は「CASCADE が消してくれる前提のコード」だけ** |

> **★走査キーワードは「撤回した仕様の残骸を探す網」であって、その文字列の全面禁止ではない**（テンプレート §2.2 の記入指針）。**否定形確認は、サブの完了時点ではなく最後にコードを触った時点で回すこと。**
