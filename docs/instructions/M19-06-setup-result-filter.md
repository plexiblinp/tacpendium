## §2. 詳細仕様

### 2.1 ★絞り込みの意味論（**設計卓が確定した 4 点**）

> **★【2026-08-09・D-271】開発者裁定 B により、判定の単位が「セル（`tech_type` × `in_corner` の組）」へ変わった。以下の本文は裁定前の定義である。**
> **(a) 軸の「全て」は、対象セルそれぞれで問うた答えの OR である**（セルを問わず 1 回だけ問う形ではない）。
> **(b) `unverified` は「未記録のセルが 1 つ以上残っている」である**——**「1 セルも記録が無い」ではない。**
> **(c) ★3 値は排他ではない。** 画面端では成立し画面中央では不成立のコンボは、**`ok` にも `ng` にも該当する。**
> **(d) ★`ng` の「`ok` が 1 つも無い」はセル内に限定される**（コンボ全体ではない）。
> **★検算の形が変わった**——**「3 値の合計＝セットプレイを持つコンボ数」は成立しない。** 代わりの不変条件は **「個別指定の結果 ⊆ 全ての結果」＝単調性**である。
> **★軸を両方指定したときの結果は裁定前と完全に一致する**（対象セルが 1 つに定まるため）。

#### (a) EXISTS 意味論——**いずれか 1 つのセットプレイで成立すれば該当**

コンボは複数のセットプレイを持ちうる（`combo_setups`）。**「このコンボは後ろ受け身で成立する」とは、いずれか 1 つのセットプレイで `back_tech` の `result='ok'` があること**である。

**★「すべてのセットプレイで成立」ではない。** **セットプレイは選択肢であり、1 つでも成立すれば、そのコンボで当該状況に対応できる。**

#### (b) 3 状態を扱う——**`ok` / `ng` / `unverified` を混ぜない**

`combo_setup_results.result` は **`ok` / `ng` の 2 値**（`internal/model/setup.go` の `SetupResultOK` / `SetupResultNG`）。**「未検証」は行の有無で表現される**（`DES-005` §5.6 項目10）。

| 絞り込み値 | 意味 | 述語 |
|---|---|---|
| `ok` | **確認して成立する** | `EXISTS(... AND result='ok')` |
| `ng` | **確認して成立しない** | `EXISTS(... AND result='ng')` **かつ** `NOT EXISTS(... AND result='ok')` |
| `unverified` | **まだ確認していない** | **セットプレイを 1 つ以上持つ**が、当該セルの行が **1 つも無い** |
| （未指定） | 絞り込まない | — |

**★`ok` と `ng` を単純な否定関係にしないこと。** 複数セットプレイのうち一部が `ok`・一部が `ng` の場合、**(a) の EXISTS 意味論により `ok` に該当する。** **`ng` は「ok が 1 つも無い」ことを含意させる。**

**★語彙は既存を再利用する。** `web/src/constants/setup-result.ts` に **`SetupResultState = SetupResultValue | "unverified"`** と **`SETUP_RESULT_UNVERIFIED`** が既にある。**第 3 の語彙を作らないこと**（`DES-005` §5.6 の流儀）。

#### (c) ★セットプレイを 1 つも持たないコンボは、どの値にも該当しない

**`unverified` にも含めない。** **「成立条件」はセットプレイに対して定義されるので、セットプレイが無ければ問いが成立しない。**

**★「該当なし（圏外）」と「未検証」を混ぜない。** **これは `chain_cancel_total` の NULL に 2 種類あった件（ボード D-137／D-143）と同じ形である。** 混ぜると、後から「どちらだったのか」を復元できない。

#### (d) `tech_type` と `in_corner` は独立に指定する

**2×2 の 4 セルから 1 つを選ばせるのではなく、2 つの軸を独立に指定させる。** 各軸に「不問」がある。

| 軸 | 値 |
|---|---|
| `tech_type` | **`OKI_TECH_TYPES` の各値**（`internal/model` と `web/src/constants` の正典を実査すること） ／ **不問** |
| `in_corner` | **画面端** ／ **画面中央** ／ **不問** |

**★既存の一覧フィルタの流儀に合わせる。** `ListFilter` の `Position` / `HitType` / `OpponentStance` はいずれも `*string`（**nullable ＝ 不問あり**）である。

**★ラベルの正典は `OKI_TECH_TYPE_LABELS`（`DES-005` §5.6 項目10）と画面端＝「相手が画面端」／「画面中央」。** **第 3 の語彙を作らない。**

### 2.2 バックエンド

**`internal/repository/combo/repository.go` の `ListFilter` に項目を追加する。**

現行 13 フィールド——`CharacterID` / `TagIDs` / `StarterMoveIDs` / `Position` / `HitType` / `OpponentStance` / `IsDraft` / `IncludeDeleted` / `OnlyDeleted` / `Sort` / `Order` / `Limit` / `Offset`。

**追加する 3 項目**（**★名前は既存の命名に合わせること**）:

| 項目 | 型 | 意味 |
|---|---|---|
| 成立状態 | `*string` | `ok` / `ng` / `unverified`。**nil ＝ 絞り込まない** |
| 受け身種別 | `*string` | **nil ＝ 不問** |
| 画面端 | `*bool` | **nil ＝ 不問** |

**★3 項目は独立だが、成立状態が nil のときは他の 2 つも効かせないこと**（軸だけ指定しても絞り込みにならない）。**この扱いを実装コメントに明記する。**

**★論理削除されたコンボの扱いは、既存の `IncludeDeleted` / `OnlyDeleted` に従う。** 本サブで新しい規則を作らない。

> **★【2026-08-09 追加・D-270】論理削除された `setups` は 3 述語すべてから除外する**（開発者裁定 2026-08-09）。**v1.0.0 は「論理削除されたコンボ」だけを規定し、同じ語で呼ばれる別の対象＝`setups` を書き落としていた**（**設計卓の誤り**）。**除外しないと「画面上セットプレイが無いコンボが `unverified` に出る」「削除済みセットプレイの `ok` で拾われる」という食い違いが起きる。** **正典は `DES-003` §3.19**（**画面ではなくデータ定義の側に置く**——**将来べつの面が同じ表を引くときに辿れるようにするため**）。
