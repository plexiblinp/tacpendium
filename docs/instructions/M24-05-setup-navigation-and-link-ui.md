### 1.3 ★★`CO-002` の核心——**「役割が被っている」は事実だが、穴が 1 つ開く**

**開発者の逐語（`SM-062`・memo line 134）＝「編集の既存から紐付けボタンもういらない。起き攻めフレームが一致するものだけ候補としたため役割が被ってる。視覚的にわかりやすいので、候補表示の方を採用し紐付けボタンは消したい。」**

**★「役割が被っている」は設計書の事実と一致する**——**`DES-005` §5.6 項目11 の逐語＝「詳細画面の『既存から紐付け』モーダル（`LinkExistingSetupModal`）の候補抽出も、本『転用可能なセットプレイ候補』と同様に『同一キャラ + 同一 `knockdown_advantage` + 当該コンボ未紐付け』に絞り込む」**（M12-03/6.5-1）。

**★★ただし同じ節にもう 1 行ある＝「候補が0件の場合は本セクション自体を非表示」。**

**⇒ 候補 0 件のとき、紐付けボタンも消えると、画面から紐付ける入口が完全に消える。**

**★★2026-08-29 決着**（`D-588`・開発者裁定）——**開発者の逐語＝「KA 不一致のセットプレイを紐付けする事はないです。ヒューマンエラーの元なので予定通り消してください。」** **⇒ 予定どおり消す。★候補 0 件でもセクションを出し「候補はありません」と書く**（§4.1）。 **★★「ヒューマンエラーの元」は消す理由そのものである**——**KA が一致しないセットプレイを紐付けられること自体が誤操作を生む。⇒ 後任が「入口が消えるから戻そう」と言ったときの根拠になる。設計書へ残すこと。**
