## 4. 危険な箇所

### 4.1 ★★★golden `000026` が動く。⇒ 版固定契約テストが在りうる

**⇒ `SUPP-001` §5.5.4 規約 (16) の手順を踏むこと。★段 1-6 で先に `grep` し、在れば歯止め 4 つを守って追随する。**

**★★歯止め (a)＝その golden を再生成した手番でのみ触ってよい。⇒ 本サブは `000026` を再生成するので、`000026` の版に固定されたテストだけが対象である。★他の版のテストは触らない。**

### 4.2 ★★★`original_move_code` を直しただけでは既存 DB は直らない

**⇒ `moves.original_move_id` の backfill が別に要る**（§2.2-5）**。★新規 DB は seed で埋まるので、テストは緑のまま通りうる。**

**★★これは `M35-02` の教訓 §7-4 と同じ族である＝新規 DB では `UPDATE` が 0 行に当たる。⇒ ログに行が出ていることと効いたことが一致しない。**

### 4.3 ★★`preset_aliases` は行が増える。⇒ `down` が `DELETE` になる

**⇒ `M35-02` は 1 対 1 置換だったため `down` も置換で済んだ。★本サブは違う。**

**★★`000074` で `preset_aliases.character_id` が追加されている。⇒ `INSERT` するとき、この列を落とさないこと。★NULL でも `INSERT` は通り、alias は表示にも出るので動作では気づけない**（`M31-04` 教訓 §7-1）**。★`000075` の UNIQUE 索引 2 本の構成列でもある。**

### 4.4 ★★軸を混ぜること

**⇒ 「`original_move_code` が dangling」と「入力面に出ない」は別の族である**（§0.3）**。★`M35-02` が 1 度混ぜた。⇒ 件数の一致は同一性の証拠にならない。**
