## 4. 詳細仕様

### 4.1 B-1: 入口の一本化

- 入口を「**ZIP** または **combos.csv（setups.csv 同時可）**」に統一。**setups 単独アップロード UI を除去**。
- **CSV 契約は不変**（2 CSV 構造・ZIP 往復対称は維持）＝**UI 動線のみの変更**。
- 「セットプレイだけ足したい」という実ユースケースは **B-6「セットプレイのみ取込」が引き受ける**（単独入口の代替）。

### 4.2 B-2: エラーの日本語化（register 分離の適用）

- **FE で VAL コード → 日本語文言へ写像**（`ja.json`）。例: `[VAL-ENUM] opponent_size: unknown ...` → 「相手の体格に未知の値があります（3 行目）」。
- **BE は不変**（簡潔な内部表現のまま）＝**CHANGE-066 の register 分離にそのまま適合**（画面表示ラベルは正典／検証エラーは内部表現）。
- **VAL コードは折りたたみ（詳細展開）で残す**（サポート・レビュー用に消さない）。
- **未写像コードは英語原文フォールバック**（写像漏れで情報が消えない）。
- **i18n 両ロケール**（`en.json` にもキーを投入＝parity テスト。**仮英訳可**）。

### 4.3 B-3: プレビューの表示名

- 既存の表示解決機構（一覧の `StarterMoveCode` → ラベル補完・`official_ja_move` エイリアス）を **preview 表示へ流用**（**新規実装しない**）。
- **未投入キャラ・未知 code は生 code 表示のまま**（**それ自体がエラーの手がかり**＝隠さない）。

### 4.4 B-4: `local_id` 非表示

- **表示から除去**。**CSV 契約上は列を維持**（setups の親参照キー）＝**表示だけの話**。
- エラー行の特定は**行番号**で行う。

### 4.5 B-5: 実行フィードバック

- **実行完了トースト**（**成功 N 件／スキップ N 件／エラー N 件**の要約）＋**結果一覧への自動スクロール**。
- **実行中はボタン無効化＋進行表示**。

### 4.6 B-6: 重複挙動の改訂（**本サブの核**）

- **「新規追加」を廃止**（dup キー〔VAL-C02＝character / starter / position / opponent_stance / hit_type / opponent_size〕が同一のまま挿入するため**必ず再衝突する**＝選択肢として成立していない）。
- **「セットプレイのみ取込」を追加**: 重複した combo は **skip** し、**その combo に紐づく setups の `parent_combo_local_id` を「重複相手の既存コンボ id」へ解決して取り込む**。
  - **setups 側の重複判定（新規設計点・開発者承認済み）**: **同名＋同レシピが一致するものはスキップ／名前だけ一致は取り込む**（別紙 §4-(4)）。
- **選択肢は「skip（既定）／セットプレイのみ取込」の 2 択**。**「上書き」枠を UI 設計上予約**（**実装しない**＝M13-i 繰越。**選択肢 UI を作り直す今、枠を用意しておくことで 3 度目の改修を避ける**）。
- **非波及**: 親解決は **`DuplicateKey`・`recipe_hash`・`RecomputeComboCache` に波及させない**（setups の追加は combos の同一性を変えない）。
