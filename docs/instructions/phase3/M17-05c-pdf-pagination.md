## 1. 背景と目的

### 1.1 背景

**開発者指摘 A-4**（2026-07-09）: **PDF/PNG が 1 ページに全コンボを詰め込むため、量が多いと可読性が最悪**。**M13-g（既知の繰越）と同件**として合流（別紙 §「M13 繰越との合流整理」）。

**承認済みの方針**（別紙 §4-(5)）: **PDF を分割の主役にし、PNG は現状維持**（＋枚数上限の注意書き）。**PNG 分割は要望が続けば後続**。

**あわせて canvas 16384px 制約の解消**（別紙 A-4）。PNG は canvas でレンダリングするため、**長尺 1 枚のままだと上限に当たって静かに壊れる**（切れる／空になる）恐れがある。**PNG を分割しない方針を採る以上、上限に当たったときの振る舞いを決める必要がある**。

### 1.2 目的

- **PDF を複数ページへ分割**する（**分割規則の設計**が本サブの核）。
- **PNG は 1 枚のまま**とし、**canvas 上限に当たる場合の振る舞いを決めて実装**する（**静かに壊れないようにする**）。

### 1.3 このサブで作らないもの（スコープ外）

- **PNG の分割**（複数ファイル出力）＝**要望が続けば後続**（別紙 §4-(5) の承認どおり）。

## 4. 詳細仕様

### 4.1 分割の基本方針

- **PDF＝分割の主役**（承認済み）。**PNG＝1 枚のまま**（§4.5 の上限対処のみ）。
- **出力文書の内容・レイアウトは変えない**（CHANGE-052／068）。**「どこで切るか」だけを足す**。
- **切れ目で意味が壊れないこと**が要件（**1 コンボの情報が 2 ページに割れて読めなくなる、比較の列が見出しを失う、等を避ける**）。

### 4.2 単独出力（§5.6 相当・カード縦積み）の分割 — **推奨案**

- **コンボ 1 件ずつがカードとして縦に積まれる**構造なので、**カード境界でページを切る**（**カードを跨いで切らない**）。
- **1 枚のカードが 1 ページに収まらない場合**（28 項目＋長いレシピ＋セットプレイ）は、**カード内で切ってよい**が、**継続ページに「どのコンボの続きか」が分かる見出しを再掲**する。
- **ページ番号**（`N / M`）を入れる。

### 4.3 複数出力（§5.8 比較表相当・行 28 × 列 N）の分割 — **推奨案**

比較表は **2 方向に溢れうる**（**列＝コンボ数**／**行＝項目 28**）。**両方向の規則が要る**:

- **列方向（横）**: **1 ページあたり N 列（コンボ）**で切る。**各ページに項目名の列（見出し列）を再掲**する（**再掲しないと右ページが読めない**）。**N は実測で決める**（横幅に収まる最大数）。
- **行方向（縦）**: 28 項目が 1 ページに収まらない場合、**行で切る**。**継続ページにコンボ名（列見出し）を再掲**する。
- **切る順序**（推奨）: **列 → 行**（＝まず「コンボ 1〜N 列の全項目」を出し、次に「N+1〜2N 列の全項目」）。**理由＝比較は「同じコンボ群を縦に読む」行為**であり、列を跨いで項目を追う方が読みにくい。**ただし実物で判断してよい**（Plan Mode で提示）。
- **ページ番号**（`N / M`）＋**どの範囲か**が分かる表示（例「コンボ 1–4 / 全 12」）。

> **§4.2／§4.3 は推奨案**。**実測（何件・何項目で溢れるか）に基づいて Plan Mode で最終形を提示**し、**開発者の判断を仰ぐ**こと。**机上の数値（N＝4 等）を決め打ちしない**。

### 4.4 オプション UI を作らない（推奨）

- **分割は既定挙動**とし、**「分割する/しない」のオプションを作らない**（**溢れたら切る**のが常に正しく、切らない選択に価値がない）。
- **これにより M17-05b（エクスポートダイアログ）と完全に独立**になる（**オプションの置き場を調整しなくてよい**）。
- **オプションが要ると判断したら報告**（§3.3-5＝**推測で足さない**。05b のダイアログとの整合が要る）。

### 4.5 【要判断】PNG の canvas 上限（16384px）

- **PNG は 1 枚のまま**（分割しない＝承認済み）。**上限に当たったときに静かに壊れてはならない**。
- **Plan Mode で実測する**: (a) **何件で 16384px に当たるか**、(b) **現状の振る舞い**（切れる／空になる／エラー／ブラウザ差）。
- **振る舞いの候補**（**実測を添えて提案すること**）:
  1. **上限に当たる件数を超えたら、実行前に警告**して**件数を減らすよう促す**（＋**PDF を勧める**）。〔**設計担当の暫定案**〕**分かりやすく壊れない**・**PNG は現状維持という承認方針に忠実**。
  2. **スケールを落として収める**（可読性が落ちる＝**量が多いと可読性最悪という A-4 の指摘に逆行**するため非推奨）。
  3. **上限で切って出す**（**静かに情報が欠ける**＝**不可**）。
- **枚数上限の注意書き**（別紙 A-4）＝**上限に当たる件数を UI に明示**する（実測値に基づく）。**文言は仮でよい**（確定は開発者）。

2. **分割規則の最終形**: 〔何を〕1 ページあたりの列数・切る順序（列→行 か 行→列 か）。〔なぜ〕**実物の読みやすさで決まる**（机上で最適解を出しにくい）。〔暫定案〕**列 → 行**（比較は「同じコンボ群を縦に読む」行為のため）。**Plan Mode の実測・提案が出た時点でご判断ください**。
