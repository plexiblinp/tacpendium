## 0. 本サブの位置づけ（先に読む）

- **本サブ＝⑯オンボーディングのみ**。M6 初期体験系の延長で、**初回起動時に何をすべきか（新規登録の位置・主要メニュー）**を分かるようにする。
- **⑰上級者モードは対象外**（M15-05 の登録画面セクション折り畳みで「入力項目を隠す」目的が達成済み。別建ての上級者モードは作らない）。
- **独立領域＝並列実行可**（登録画面レイアウト M15-05① とは別。⑯は導線/初回ガイド）。

---

## 1. 背景と目的

### 1.1 背景

- **FB⑯**（followup-backlog §A）: **初回起動時に何をすべきか不明**。**新規登録の位置・メニュー可読性**が課題（M6 初期体験系の延長）。
- **非スキーマ**（表示制御＋UI 状態）。「初回か」の判定は **UI 状態**（localStorage・`browser-storage.ts` 経由。CLAUDE.md §10.X が UI 状態保持を許容＝DES-005 §5.4 表示列カスタマイズ・§6.4.1 と同格。**DB 永続化対象データではない**）。
- **入力の実体**（code-facts §1）: ナビは Header/Footer（`/settings` 等）・ホーム。新規登録導線は ホーム／フッター／一覧（DES-005 §5.7 CHANGE-039＝マイコンボには無し）。オンボーディング用の既存空状態/ガイドの有無は §3.3 で実査。

### 1.2 目的

完了時に達成される状態:

- 初回起動/初訪時に、**何をすべきか（新規登録の位置・主要メニュー）が分かる**導線（初回ガイド/空状態の案内等）。
- **押し付けず・スキップ可・再表示可**。「初回か」は UI 状態（localStorage）で判定。
- **メニュー可読性**の改善（FB⑯）も併せて検討。
- 既存機能・データ・API 不変（非破壊・非スキーマ）。

### 1.3 このマイルストーンで作らないもの（スコープ外）

- **⑰上級者モード**（M15-05 折り畳みで実現済み・別建てしない）。
- DB スキーマ・API・データ・`ConfigResponse`（backend 設定）の変更（⑯は表示制御＋UI 状態）。
- チュートリアルの高度化（動画・多段ツアー等）＝最小の初回導線に留める。
- M16 依存の表記／他 M15 サブ（タグ色=M15-04／表示=M15-05／入力方式=M15-03）。

## 4. 詳細仕様

### 4.1 初回オンボーディング

- 初回起動/初訪時に、**新規登録の位置・主要メニュー**が分かる導線（空状態の案内・初回ヒント等・§3.3-2 で形式確定）。**押し付けず・スキップ可・再表示可**。
- 「初回か」の判定は **UI 状態（localStorage・`browser-storage.ts` 経由）**（DB 非対象）。

### 4.2 メニュー可読性

- Header/Footer の可読性を向上（FB⑯・§3.3-3 の範囲）。過度な改変・既存遷移の変更はしない。

### 4.3 test-id

- 既存規約を grep 実値確定 → 初回ガイド/導線に必要な test-id を付与（範囲限定・digest §4）。

## 5. テスト要件（ケース数で確認）

- **初回オンボーディング（Vitest）**: 初回（UI 状態未設定）でガイド/案内表示・スキップ/再表示・2 回目以降は非表示（設定どおり）。「初回か」判定が localStorage UI 状態。
- **メニュー可読性（Vitest）**: 既存遷移が不変で可読性が向上（非回帰）。
- **既存 E2E 非回帰**: `make e2e` 全通過・**永続 dev DB 残渣非依存**。
