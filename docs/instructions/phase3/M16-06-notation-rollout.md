## 1. 背景と目的

### 1.1 背景

M16 で確定した ④ taxonomy（M16-04）・① 始動/消費（M16-02）を、ユーザー向け表記へ翻訳・正典化する **M16 末尾の rollout**（旧 M15-07）。順序依存（誤ラベル防止のため taxonomy/始動消費 確定後）を満たしたため着手する。回収する論点は次の 4 本。

- **FB⑥（技/非技ラベル・新規登録/編集のみ・as-built 訂正 v1.0.1）**: 「技/非技ステップ」表現が分かりにくい。M15-03（CHANGE-057）で入力区分プルダウンは「共通システム（移動・その他）」へ改称済み。**Plan Mode 実査で、排除対象の生表現は rendered UI に不在（残存はコメント/テストのみ）と確定**。実対象は表示層の off-vocabulary fallback 2 箇所の最小整合（§4.4）。対象は新規登録/編集のみ（開発者確定）。
- **A-3 ＋ FB⑨⑪⑬（始動/消費の横断正典化）**: 現状 **比較=「始動残量」／詳細=「開始残量」の同一概念 2 表記が並立**（DES-005 §5.4 vs §5.6）。**en の始動 `(start)`／消費 `consumed` の語法非対称**もある。詳細・比較・入力欄・エクスポート・custom_states（サンシンボル）を横断して正典化（ja/en parity）。
- **A-1（消費エクスポート項目）**: 消費は詳細・比較に出るがエクスポート（`combo-io`・`ExportItemKey`）に未掲載＝「始動はエクスポートできるが消費はできない」非対称。消費項目を新設。
- **F-1(a) 残（始動欄クランプ非対称）**: 消費入力欄は UI 上限クランプ済み・始動入力欄はクランプなし。**始動欄も対称にクランプ**（開発者確定）。BE/CSV の範囲非連動は不変。

### 1.2 目的（確定した正典語彙・開発者確定 2026-07-07）

- **始動残量（ja）**: 「開始残量」「始動残量」の並立を **「コンボ開始時の◯◯ゲージ残量」に統一**（◯◯＝ドライブ／SA）。長いが誤解を防ぐ正典。**消費（ja）はそのまま**（「◯◯ゲージ消費」）。
- **en parity**: 始動＝`{Drive/SA} gauge at combo start`、消費＝`{Drive/SA} gauge consumed`（英語圏で自然・ja と同じく誤解を防ぐ・`(start)`/`consumed` の語法非対称を解消）。**製造は英語ネイティブ視点で自然さを最終チェック**し、不自然なら §確認事項へ差し戻す。
- **FB⑥**: 新規登録・編集画面の step 表示から「技/非技ステップ」の生表現を排除し、M15-03 で確立した user 語彙（共通システム=移動・その他／技）へ揃える。
- **A-1**: `saConsumed`/`driveConsumed` の `ExportItemKey`＋UI トグル＋export-model 行を新設。既定は**始動項目と対称**。
- **F-1(a)**: 始動入力欄も消費と対称に UI クランプ（`clampNumericString` 相当）。BE/CSV 非連動は不変。

### 1.3 このサブで作らないもの（スコープ外）

- **スキーマ/DB/API/DTO/CSV の変更**（非スキーマ）。始動/消費のデータ（M16-02）・taxonomy のデータ（M16-04）は確定済み・不変。

## 4. 詳細仕様

### 4.1 始動/消費ラベルの横断正典化（A-3・FB⑨⑪⑬）

- **ja**: 始動＝「コンボ開始時の{ドライブ／SA}ゲージ残量」に統一（「始動残量」「開始残量」の並立解消）。消費＝「{ドライブ／SA}ゲージ消費」（不変）。詳細・比較・入力欄・custom_states/サンシンボル（FB⑬）を横断。
- **en**: 始動＝`{Drive／SA} gauge at combo start`、消費＝`{Drive／SA} gauge consumed`（parity）。
- ラベル定義を SSOT へ集約（散在時）。ja/en 両ロケール parity。

### 4.2 消費エクスポート項目（A-1）

- `ExportItemKey` に `saConsumed`/`driveConsumed` を追加。UI トグル（既存エクスポート項目 UI）・export-model 出力行・画像/クリップボード/PDF 描画。**既定は始動項目と対称**（始動が既定表示なら消費も既定表示）。ラベルは §4.1 正典。

### 4.3 始動入力欄クランプ（F-1(a)）

- 始動入力欄（`drive_available_at_start`／`sa_available_at_start`）に消費入力欄と同じ UI クランプ（`clampNumericString` 相当）を適用。**BE/CSV の範囲非連動は不変**（① 方針）。入力挙動を消費と対称化。

### 4.4 FB⑥（新規登録/編集の技/非技ラベル・as-built 最小整合 v1.0.1）

- **前提（Plan Mode 実査確定 2026-07-07）**: 排除対象の「技ステップ/非技ステップ」生表現は **rendered UI に不在**（M15-03/CHANGE-057 で user 語彙化済み・残存はコメント/テストのみ）。生表現排除は既に達成＝**その旨を完了報告に記録**。
- **実対象＝表示層の off-vocabulary fallback 2 箇所の最小整合**:
  - (1) `SetupRecipeEditor:38` の短縮「共通システム」→ **正典「共通システム（移動・その他）」**（M15-03 語彙 SSOT へ整合）。
  - (2) `StepRow:92` の生 `modifiers.type` コード fallback → **非技 type の正典ラベル（SSOT）へルーティング**（ad-hoc な新ラベルを作らない）。既知 type（`parry_drive_rush`/`cancel_drive_rush`）はラベル表示、未知 type は既存 `StepRow:94`「(不明なステップ)」プレースホルダへ落とす（生コードをユーザーに出さない）。
- **対象外（現状維持）**: 詳細/比較/出力（開発者確定）。エッジ/エラー fallback（`StepRow:94`「(不明なステップ)」・`SetupRecipeEditor:41`「技 #id」）は生表現でなく安全なプレースホルダ＝FB⑥（技/非技 語彙）の範囲外。
