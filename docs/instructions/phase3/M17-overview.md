## 1. 目的・位置づけ

- **M17＝発信者の流通基盤**。発信者（コンボの生産者）が自分のデータを記録・発信・流通させる経路を強化する 4 機能群（reorg ③④⑤＋command 解決 段階2）を集約する。フェーズ3 の継続（新フェーズではない）。
- **性格**: スキーマ追加を伴う（G-j メディア 3 列・G-k command 索引源）が、いずれも**後方互換・列末尾追加/新テーブル**で既存を壊さない（破壊的マイグレは無い）。M16 の破壊的整理（taxonomy・dash）とは対照的に、M17 は「拡張の継ぎ足し」。
- **上位依存**: **M14-03b（配布 seed・配布 blocker）完了が前提**。取込ヘルパー（④）・command 解決（④'）は全キャラ move マスタ／command 索引源を照合先とするため、M14-03b の seed と moveindex IF が土台。M17-01（メディア）のみ M14-03b 非依存。
- **次 MS への申し送り**: M18（確定反撃・G-b/c/d/e・`is_projectile`）／M20（プリセット A-1 実データ・command 索引と表示エイリアスの分担維持）。
- **反復型の扱い**: ③（M17-05）は「先に固めず協議しながら改善」（phase3-overview §M17）。本 overview で項目を確定（§2.3）した分から着手し、追加は随時。

## 4. 主要設計判断・調査結果の反映

### 4.1 ④ 取込ヘルパーと段階投入の衝突（後段・充足判断つき）

phase3-overview §M17 ④ の前提「全 30 キャラ seed 済み」は M14-03b の段階投入（開発者決定 2026-07-09）で崩れる。④ は投入済みキャラに限れば成立（未投入キャラは全行未解決＝人レビュー行きになるだけで壊れない）するが、実用性はキャラ充足に比例。よって **M17-04 を後段に置き、M17-03 完了時点の充足状況で「投入済みキャラ限定で先行」か「M18 以降へ繰り延べ」かを判断**する二段構え。④'（段階2）・G-k はキャラ別に閉じる（索引に無いキャラで発動しないだけ）ため段階投入と衝突せず、M17-02 で先行できる。

### 4.2 G-k＝index-only の物理方式（専用索引テーブル・暫定承認済み）

判断3（`moves.command` 列は復活しない）は確定。索引データの実行時の持ち方は**専用索引テーブル案**（例 `move_commands(move_id FK, token_key, …)`）を採用（開発者暫定承認 2026-07-09。正式承認は M17-02 着手直前ゲート）。seed マイグレで投入・M14-03b の moveindex IF が構築主体・ユーザ追加 move への command 付与の将来経路も開く。ビルド時 embed 案は第二波 seed 追補・ユーザ追加 move と不整合のため不採用。**token→索引キー正規化**（レポート §9.9 語彙→numpad 等）は M14-03b が「索引キー＝CSV 正準表記そのまま・正規化層は後付け位置」と切ってあるため、M17-02 で正規化層を差し込む（M14-03b 手戻りなし）。

### 4.3 「特殊技優先」・フォールバックの置き場

「特殊技が定義されていれば特殊技を優先」（command-resolution-request §1-2）と未定義フォールバック（通常技へ落とす）は、**共通索引モジュールでなく消費者側（段階2 解決サービス）**に置く。取込照合側（M17-04）はフォールバック不要＝未解決を人レビューへ返すため挙動が分岐する。共通 IF は「未解決を未解決のまま返す」に固定（M14-03b §4.8）。

### 4.4 command 索引の 1:N と派生技フラグ（M17-02 の設計点・RESEARCH-02 反映）

RESEARCH-02〔T12〕で command→move_code が全 30 キャラ 442 グループで 1:N と判明（大半は必殺技＝段階2 スコープ外）。**開発者確定（D・2026-07-09）＝派生技フラグ `is_derived` で「非派生技のみ索引化」**（別紙 command-index-resolution-design v2.1.0）。派生技は索引に載せず直接指定へ（簡易解決で満足に入力できないため非対応）。これにより将来アップデートで後発の本体特殊技が既存派生技と command かぶりで追加されても非派生技のみで一意化（priority の都度運用が不要）。非派生技が複数残る稀ケースのみ id 最小タイブレーク＋曖昧は未解決。判定源は入力ツール側＋人間判断（本体は値信頼）。`condition_ja`/`condition_en` は verbatim 保全（M17-02 の正規化層設計時の考慮）。**アップデート追従の運用手順は FR702 によりフェーズ4 送り**（M17 は仕組み＝フラグ導入まで）。索引器の器は M14-03b §4.8 で確立済み（非派生のみ・id タイブレーク・LookupAll）。

### 4.5 ③ import/export の項目確定（別紙・承認済み）

開発者指摘 A-1〜A-4・B-1〜B-6 を別紙 `M17-05-export-import-item-inventory.md` で棚卸し、確認事項 5 件は承認済み（2026-07-09）。要点: エクスポート画面は段階廃止（第1段でダイアログ化・第2段で除去）・B 群は import 体験再設計 1 クラスタ・B-2 は register 分離（CHANGE-066）で BE 不変・B-6「セットプレイのみ取込」は既存コンボへ setups 親解決。M13 繰越（M13-g→A-4 合流・M13-i/j 繰越）。

### 4.6 メディア列のスコープ（文字列参照まで・承認済み）

G-j は**文字列の保存・表示・CSV 往復まで**（**as-built: M17-01 完了・CHANGE-068 三点セット済。§5.13 の出力項目は 25→28 へ増えた**＝M17-05b/05c の設計時に前提を更新すること）（アプリはファイルを開く/配信/再生しない）。`link`（インターネット URL）はクリック可能（http/https 限定・`rel="noopener noreferrer"`）で遷移する。`video_path`/`image_path`（ローカル相対パス）は**文字列表示のみでクリック遷移しない**（開発者確認 2026-07-09）。よって CHANGE-049 級のパス検証は不要（文字列扱い）。検証は緩（DES-006 に「閲覧不可は許容」明文化）。動画実体配布・容量設計はスコープ外（phase3-overview §M17 ⑤ precedent）。

### 4.7 失効 dash 記述の是正（M17-02 に同梱）

DES-002 §7.5 の「前後ステップ＝modifiers.type」旧記述は M16-04 で失効。M17-02 の DES-002 §7.6 改訂（helper IF）に是正を同梱。SUPP-001 §3.3.3 の同種記述は自由改訂で同時是正。

### 4.8 表示解決・recipe_cache の非波及（レビュー観点）

④/④' は move_code 確定後に既存登録経路へ乗るため recipe_cache（SUPP-001 §7）非波及＝新経路が `RecomputeComboCache` を迂回しないことをレビュー観点化。G-j 3 列・段階2 解決はいずれも dup キー（VAL-C02）・recipe_hash 非対象。M20（プリセット A-1 実データ）へ「解決＝command 索引／表示＝プリセットエイリアス」の分担維持を申し送り。
