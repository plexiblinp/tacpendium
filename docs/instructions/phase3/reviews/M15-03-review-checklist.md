## 1. 設計・パターンとの照合（最重要）

### 1.1 死守契約 3 点（指示書 §1.1・§4.1・§4.3）
- [ ] **公式表記のみ解決**（汚い/簡易入力を認識しない・段階1 は方向ゾーンのみ見る決定論ルックアップ）。
- [ ] **モーション解析なし**（236/214/623 の列・溜めを認識しない）。
- [ ] **出口が `move_code`**（当該キャラ `moves` から一致解決した `moveId`）。

### 1.2 段階1 決定論引き当て（指示書 §4.1）
- [ ] DES-004 §2.1 整合（ニュートラル→`standing_*`／下→`crouching_*`／上→`jumping_*`・強度接尾辞）。
- [ ] 移動のみジャンプ（`jump_neutral` 等）を対象に含めていない。
- [ ] 未定義 variant のフォールバック（§3.3-3 確定）が安全に劣化（クラッシュ/誤引き当てなし）。
- [ ] **純関数**（`moves` 引数・`moveId|null`・副作用なし）。**command 非依存**（段階2 を先取りしていない・`raw_data.command` 参照なし）。過剰共通化なし（YAGNI）。

### 1.3 入力方式ボタン化＋プルダウン残置（指示書 §4.2・最重要の是正点）
- [ ] **既存プルダウンを廃止していない**＝「全技から選ぶ」網羅フォールバックとして残置し、**区分（カテゴリ）で絞り込んで表示数が減る**か。別技（moves 別行）がプルダウンで入力可能か（取りこぼしなし）。
- [ ] カテゴリタブで入力面が切り替わり、通常技＝段階1／特殊技等＝直接指定になっているか。
- [ ] **ラッシュ版トグル**が `category∈{normal,unique}∧is_aerial=false` の**単発非空中技のみ**に効き、通常技のジャンプを無効化しているか。多段（target combo）を対象にしていないか。
- [ ] ISSUE-002（modifier 専用ボタン・DES-005 §5.7）と整合し、既存挙動（始動技自動推定・並び替え/削除・info-mark）が不変か。モバイル/LAN タップ（arch §10）。

### 1.4 直接指定 UI（指示書 §4.3）
- [ ] 特殊技＝ワンプッシュで `unique` move を選べるか（段階2 コマンド解決を先取りしていない）。
- [ ] 必殺技＝ファミリー＋弱/中/強＋**OD 4 種フラット**（ドリルダウンなし）。存在する強度のみ活性（move データ駆動）。
- [ ] **236 等のモーション実演 UI が存在しない**（死守2）。SA/システム/DI が直接指定で入るか。

### 1.5 modifier flags（指示書 §4.4）
- [ ] OD 組（`od_lm`/`od_mh`/`od_lh`）・`first_hit_cancel`・`neutral_jump`・`forward_jump` が**既存 `modifiers.flags`（JSON）**に載るか（**新規列/テーブルなし**）。
- [ ] `ModifiersEditor` の**固定選択式**（自由入力不可・DES-004 §2.3）で付与/解除でき、**既存 flag マスタの実値を grep 確定**してから列挙値を足したか（命名衝突なし・digest §4）。move_code は基底のまま（別技化していない）。

### 1.6 test-id・DES 直接編集禁止（指示書 §4.5・§7.4）
- [ ] 既存 `combo-editor-*` を grep 実値確定 → `recipe-*` を同系統・別 topic で採用。範囲が本サブの触れる箇所に限定（フル sweep なし）。
- [ ] DES-004/005（・003）CHANGE 要否判定が完了報告にあり、**製造が DES を直接編集していない**（要なら設計担当が CHANGE-057 束ねで起票）。**別技命名の新設をしていない**（既存使用）。

## 9. 重大な問題の判定基準（完了承認を妨げる）
- **死守契約 3 点のいずれか違反**（簡易/汚い入力を解決・モーション解析・出口が `move_code` でない・236 実演 UI を作った）。
- **既存プルダウンを廃止した**（残置＋区分絞り込みが正）。別技がプルダウンで入力できず取りこぼしている。
- Plan Mode 実査（§3.3 #1〜#7）のいずれか未確認のまま実装（推測実装）。
- **既存 `VirtualController`/`ModifiersEditor` を実査せず自作再発明**（playbook §4.6/§4.9）。
- **現行 seed で段階1 が引けるか実査せず**固定前提のまま実装／未定義 variant でクラッシュ・誤引き当て（digest §3）。
- **既存 flag マスタ／`combo-editor-*` を grep 確定せず** flag/test-id を思い込み命名し衝突（digest §4）。または `recipe-*` がフル sweep に膨張。
- **段階2（command 依存の特殊技解決）を M15-03 で作り込み**／**別技ボタン面を M15-03 で作り込み**（M14-03b 後の領分）／**別技命名を新設**／**target_combo に手を出した**（M16 の越境）。
- API/データ契約・スキーマが変わっている（段階1・modifier flags は非スキーマが前提）。
- 既存操作・レイアウト・E2E が非回帰でない。i18n parity 欠落。spec が永続 dev DB 残渣依存。製造が DES 本体を直接編集。

## 10. 軽微な問題の判定基準（持ち越し許容）

- 必殺技直接指定・DI タブ配置の細部（死守＝236 実演なしを守れば可）。
- 段階1 純関数の配置・内部実装の流儀。未 seed キャラのフォールバック表示文言。
