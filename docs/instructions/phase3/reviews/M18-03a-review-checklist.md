## 1. 設計・パターンとの照合（最重要）

- [ ] `combo_punish_starters`（探す画面の作業状態）を**使う画面から引いていない**（DES-003 §3.18 の役割分担）。

### 1.2 `combo_punish_curations` の配線（指示書 §4.2）

- [ ] repository の SELECT／INSERT／DELETE が新設され、**DELETE がサロゲート id ではなく `UNIQUE(combo_id, opponent_move_id)` で指定**している（M18-02 の実装形の踏襲）。
- [ ] **UNIQUE の二重登録が弾かれる**。返し方が既存の pruning／starters と**同じ**。
- [ ] `note`（隠す理由・任意）の入力欄が FE にあり、DB の `note` 列に保存される。

## 9. 重大な問題の判定基準（完了承認を妨げる）

- **新規マイグレの作成／既存マイグレの改変／`internal/seedgen` の改変**（golden 破壊）。
- **新テーブル・新列の追加**（承認ゲート無視・委任 §6）。
- **CHANGE 番号の自採番**（中央払い出し不使用）。
- **`model.Combo`／`combos` の INSERT 列／`DuplicateKey`／`CalcRecipeHash`／`RecomputeComboCache` の改変**（M18-03b のスコープを侵している）。
- **マイリストが pruning で表示制御されている**（§4.1 の帰結違反。採用済みの反撃が黙って消える）。
- **curation が孤児になる**（`combo_punishes` 解除時に残る）。
- **片道操作が残っている**（隠したものを戻す導線が無い）。
- **【v1.0.2】`hit_type` がタブ 2 値以外の採用が、どちらのタブにも出ず第3セクションにも出ない**（silent-drop＝M18 の思想の中核違反）。**NULL の取りこぼしを含む**。
- **走査規則を FE に二重実装**している（DES-002 §4.2 違反）。
- **`hit_type` の 4 値リテラルを 4 箇所目として新規定義**している。
- **探す画面の既存操作が回帰**している（採否トグル・pruning・note・新規登録導線）。
- 未 seed／不存在 ID で 404・500 を返す。
- ブラウザストレージの使用（CLAUDE.md §10.X 違反）。
