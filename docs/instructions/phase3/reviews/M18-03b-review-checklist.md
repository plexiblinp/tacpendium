## 1. 設計・パターンとの照合（最重要）

### 1.1 対象判定（指示書 §4.1）

- [ ] `normal`／`counter`／**NULL** が materialize の対象になっている。**NULL を取りこぼしていない**。
- [ ] `punish_counter`／`just_parry_punish_counter` は対象外で、**BE でも 400 ＋理由コードで弾いている**（FE がボタンを出さないだけになっていない）。
- [ ] `counter` の生成で**ダメージが加算されていない**（二重計上していない）。

### 1.2 スコープ境界（指示書 §4.2・**設計意図の核心**）

- [ ] **「レシピを編集してから生成する」機能を作っていない**。生成物は基底のレシピをそのまま複製したものに限る。
- [ ] レシピが変わるケースを materialize で扱おうとしていない（別コンボとして孫ツリーの新規登録導線に任せる設計になっている）。

### 1.3 ダメージ計算（指示書 §4.3・**本アプリ初の自動計算**）

- [ ] 式が `base.damage + round(starterMove.damage × 0.2)`。
- [ ] **丸めが Plan Mode の実測に基づいている**。`damage % 5 <> 0` が **0 件なら整数演算（`damage / 5`）**で実装され、**丸め関数を持ち込んでいない**。1 件以上だった場合は**実装を止めて開発者実測を待った形跡**がある（推測で四捨五入・切り捨てを選んでいない）。
- [ ] **【v1.0.2】実測結果のコメントに「基準時点・一次源」が入っている**（E-24／L-4）。整数除算は例外を出さず静かに切り捨てるため、前提が崩れても気づけない。
- [ ] 縁 3 パターン（`base.damage` NULL／`starter_move_id` NULL／始動技 `moves.damage` NULL）で**生成を止めず、理由を返している**（silent に 0 加算していない）。

### 1.4 コピー範囲（指示書 §4.3）

- [ ] `combo_steps`／`combo_oki_options`／`combo_tags` が**複製されている**（`combos` の INSERT だけで済ませていない）。
- [ ] **`combo_setups` は複製されていない**。
- [ ] `knockdown_advantage`・状況系・ゲージ系・`drive_damage`・`memo`・メディア 3 列がコピーされている。
- [ ] `is_draft` が基底から引き継がれている。
- [ ] `hit_type` に **`model.HitTypePunishCounter` を参照**して設定している（**リテラルを増やしていない**）。
- [ ] `materialized_from_combo_id` に基底 id が入っている。
- [ ] `version`／timestamps／`deleted_at` を**コピーしていない**。
- [ ] 子テーブル複製が **PUT 経路の既存機序を再利用**しており、独自実装になっていない（**L-1**＝Plan に実機序の引用がある）。

### 1.5 API とトランザクション（指示書 §4.4）

- [ ] **`POST /api/combos/{id}/materialize`** が新設され、`opponentMoveId` を必須で受ける。
- [ ] **`CreateRequest` に `materializedFromComboId` を足していない**（出自の詐称経路を作っていない）。
- [ ] 処理順が「対象判定 → **FR301** → ダメージ → INSERT → 子テーブル → `combo_punishes`」で、**FR301 が INSERT より前**にある。
- [ ] **全体が 1 トランザクション**。途中失敗で何も残らない。
- [ ] **【v1.0.2】基底コンボの採用が解除されている**＝`combo_punishes(基底, 相手技)` と同キー curation が削除され、基底が第3セクションから外れる。**基底コンボ自体は残る**。
- [ ] **【v1.0.2】FR301 で既存一致だった場合も基底の採用が解除される**（生成はしないが基底はキューから出る）。
- [ ] **【v1.0.2】未採用の基底からの変換で何も消さない**（冪等・no-op）。
- [ ] **【v1.0.2】`combo_punishes` と `combo_punish_curations` をペアで削除**している（孤児を作らない・03a §4.1 と一貫）。
- [ ] **【v1.0.2】応答が契約どおり**＝生成でも既存一致でも **200**（`alreadyExisted` で区別）。対象外 `hit_type` は **400 ＋ 理由コード**。加算スキップ理由コードが §4.3 の縁 3 パターンと 1:1。
- [ ] **クライアントに steps を往復させていない**（サーバ内で基底の `Steps` を複製）。
- [ ] 規則が **BE 一元化**され、FE にダメージ計算や `hit_type` 決定が漏れていない。

## 9. 重大な問題の判定基準（完了承認を妨げる）

- **新規マイグレの作成／既存マイグレの改変／`internal/seedgen` の改変**（golden 破壊）。
- **新テーブル・新列の追加**（承認ゲート無視・委任 §6）。
- **CHANGE 番号の自採番**。
- **`DuplicateKey`／`CalcRecipeHash`／`RecomputeComboCache` の判定内容を変えた**（とくに `materialized_from_combo_id` を混ぜた）。
- **`CreateRequest` に `materializedFromComboId` を足した**（出自の詐称経路を作った）。
- **丸め規則を実測なしで決めた**（`damage % 5` が 1 件以上なのに四捨五入等を勝手に選んだ）。
- **`counter` の生成でダメージを加算した**（二重計上）。
- **NULL の `hit_type` を materialize の対象から落とした**（silent-drop）。
- **加算できないときに生成を止めた、または黙って 0 加算した**（M18 の思想の中核違反）。
- **`combo_setups` を複製した**（意味の変わる紐づけを持ち込んだ）。
- **FR301 を INSERT の後に置いた**（重複が一度作られてしまう）。
- **materialize または引き継ぎが原子的でない**（片方だけ残る）。
- **編集経路の引き継ぎで `combo_punishes` が消える**（本サブの目的未達）。
- **materialize endpoint に対する UI 導線が無い**（到達不能な実装＝03a で問題視した状態の再生産）。
- **レシピを編集してから生成する機能を作った**（§4.2 のスコープ境界違反）。
- **案C・手動確認レーン登録・curation 登録・`Header.tsx` に手を出した**（03c のスコープ侵食）。
- **CSV export に `materialized_from_combo_id` が出た**。
- 既存コンボ CRUD・CSV 往復・`divergence_test` の回帰。
