## 7. 【v1.0.1 新設】M17-04 連携口の非回帰（回帰ゲート）

> **背景**: 本サブが改造する `ComboImportPage`（`/import/combo`）には、**M17-04 が DES-005 §5.14 の連携口**（取込ヘルパー → router state 経由の自動プレビュー）を入れている。実装は **StrictMode の二重マウント対策**（`setTimeout(0)`＋cleanup＋ref＋`previewM.data` 購読）で、**B-1／B-5 が触る pending・mutation ライフサイクルと同じ場所**にある。**「触るな」ではなく「壊れていないことを証明せよ」が本節の趣旨**（playbook §4.14）。

- [ ] **回帰 E2E が green** か: **取込ヘルパーで `combos.csv` 生成 → `/import/combo` 遷移 → 自動でプレビューが走る**が **B-1／B-5 の改造後も通る**か。**`isPending` が固まっていない**か。
- [ ] **取込ヘルパー（§5.19）・`web/src/features/intake/` に差分ゼロ**か（**`git diff` の結果が完了報告にある**か）。
- [ ] **§5.19 側に VAL→日本語の写像を作っていない**か（**取込ヘルパーは i18n キーなし・日本語直書き**＝§2.5 の固定 ja 境界。**取込ヘルパー由来 CSV の検証エラーは §5.14 の import プレビューで出る＝B-2 の写像がカバーする**）。

## 9. 重大な問題（完了承認を妨げる）

- Plan Mode 8 項目のいずれかが未確認のまま実装（推測実装）。とくに **1（setups 重複判定）・2（親解決）**。

- **BE のエラーメッセージ・VAL コード体系を変えた**（**register 分離の違反**＝B-2 は FE 写像）。
- **`DuplicateKey`・`recipe_hash`・`RecomputeComboCache` に波及した**（親解決が cache 再計算を呼ぶ等）。
- **「新規追加」が残っている**（廃止されていない）。
- **setups の重複判定が承認基準と違う**（同名＋同レシピ一致でスキップ／名前だけ一致は取込む、でない）。
- **親解決が動かない**（重複 combo を skip すると setups も落ちる／別コンボへ誤って紐付く）。
- **「上書き」を実装した**（M13-i は繰越＝**枠の予約のみ**）。
- **独立 setup チェックボックスを作った**（CHANGE-051 の確定＝コンボ行単位）。
- **未知 code を隠した**（生 code 表示がエラーの手がかり）。
- **【v1.0.1 追加】M17-04 の連携口を壊した**（取込ヘルパー → 自動プレビューが動かない／`isPending` が固まる。**回帰 E2E が赤のまま完了報告した**）。
- **【v1.0.1 追加】取込ヘルパー（§5.19・`web/src/features/intake/`）に手を入れた**（**M17-04 の領域**。連携口の router 層リファクタ＝§G-15 を無報告で実装した、を含む）。
