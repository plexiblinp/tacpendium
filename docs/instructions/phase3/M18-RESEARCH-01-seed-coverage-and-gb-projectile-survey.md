## 4. 調査項目

> 各項目：**実 SQL／実コードを view し grep で全数を取る**。列名・関数名・件数は**実値**で報告。**確認不能は「未確認」と明記**。

### A. seed 充足（相手技データの網羅）
- **A-1**: 全 seed キャラ×技で `on_block`／`recovery` が **入っている技数・NULL の技数**を実 SQL の集計で数える（キャラ別・全体）。**何を母数に数えたかを併記**（攻撃技のみか・全 category か。E-16/E-18）。
- **A-2**: 検出条件 `on_block ≤ -4` に該当する技数（＝ガード確反の母集団規模感）を実値で。
- **A-3**: 距離依存クラス（波動拳等・飛び道具）に**該当しそうな技を列挙**（現状フラグが無いため、`category`／`code`／`name` からの手掛かりで候補列挙・判定はしない）。値が空になりやすい技の実例も。

### B. G-b ジャストパリィ有利算出（飛び道具）の実装前詰め材料
- **B-1**: §3.2 の判定式を **seed 実データ数件で突合**（`on_block` 反転・`recovery` そのままが有利フレームとして符号整合するか。矛盾例があれば事実として記録）。
- **B-2**: `is_projectile` を立てる対象の**判定材料**を実データで集める（飛び道具に相当する技が seed 上どう表現されているか＝`category`・`code`・`properties`／raw_data 等）。**判定基準の確定はしない・材料のみ**（基準確定と列追加は後続の G-b CHANGE）。
- **B-3**: 飛び道具・距離依存技を走査から外す方式の材料（`recovery` が NULL／空の分布、`on_block` が距離で単一値化できない技の実例）。distance pruning（G-d）と同線であることの事実確認。

### C. 後続指示書の前提となる既存事実（read-only 裏取り）
- **C-1（E-19）**: **FR301 dup キーの判定キーの実体**を実コード／実 SQL で引く（`hit_type` を含むか・キー構成）。**まず M16-RESEARCH-01-report を参照**し、現行実コードと差が無いか突合（材料が古ければ実コードを正とする）。
- **C-2**: 検出走査で `on_block` が NULL の技の件数（`recovery` NULL と併せ、スキップ対象の母数）。
- **C-3**: `combo_punishes`／`moves.is_projectile` が現行 DB スキーマ・DDL に**存在しないこと**を実 DDL で確認（M18 新設の前提裏取り）。
