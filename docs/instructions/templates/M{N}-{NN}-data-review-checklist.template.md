## §1. 着手前（Plan Mode）の報告

- [ ] 指示書 §3 の**全項目**が報告されている。
- [ ] **マイグレ連番が `ls migrations/` の実査で払い出されている**（記憶や見込みで書かれていない）。**予約帯を作っていない。**
- [ ] **想定と食い違った項目があった場合、実装に入る前に報告されている**（`PARENT-E21`）。
- [ ] **一次源に対応する行が見つからなかったものが、黙って落とされていない**（「なし」と明記されているか）。

---

## §2. 凍結インターフェース

- [ ] 変更した行が**指示書 §0.2 の解除範囲ちょうど**。→ 超えていれば **R-1**。
- [ ] **解除していない `is_projectile` / `is_aerial` が変わっていない。**
- [ ] `internal/service/` ／ `internal/seedgen/` に **diff 0**。→ あれば **R-2**。
- [ ] **★`recovery` と `on_block` を変更している場合、それが解除に含まれているか。** 両方とも契約 F-1 の名指し列である。
- [ ] **解除範囲を超えた変更があった場合、設計伝達レポート §2 に記載があるか**（記載があれば「重大」ではなく「要説明」として扱う）。

---

## §3. マイグレの構成

- [ ] 指示書 §1.1 の段構成どおりに**連番が分かれている**。
- [ ] **値を変えない段が、本当に値を変えていない**（canary が段の直後で動いていないこと）。
- [ ] **1 行 1 UPDATE でキーが明示されている**（契約 F-4 (2')）。→ 条件式で束ねていれば「要説明」。
- [ ] **(c) 既存値の保護が入っている、または入れなかった理由が設計伝達レポートに書かれている**（**D-231**＝目的は保護であって形の指定ではない）。

---

## §4. down 整合

- [ ] **down で元の値へ戻る。re-up で復帰する。**
- [ ] **★down のスコープ条件が up の反転になっていない**（`SUPP-001` §5.5 (5)）。**up のガードを持ち込むと 0 行にしか当たらない。**
- [ ] **down の巻き添えが固定されている**（他レーンの同じ列を巻き込んでいない）。

## §5. CSV・golden・DB の三点

<!-- 記入指針: CSV を触らないサブでは本節を「本サブは CSV に触らない」で閉じる -->

- [ ] **是正列が golden に載るか載らないかで、UPDATE を当てる位置が正しく変わっている**（指示書 §2.1）。
- [ ] **golden に載らない列が、改名後・新 code で当てられている**（載る列と同じ扱いにしていないか）。
- [ ] **手入力ツールで CSV を往復させていない**（**D-218**）。
- [ ] **CSV の列順が変わっていない。** **空欄が `false` で埋まっていない。**
- [ ] **CSV の既存列の差分が、是正対象ちょうど。**
- [ ] **`seedgen -check` が `OK`。golden の stem 数が実測値で green。**

## §6. テスト

- [ ] **比較区間が自サブに閉じている**（始端＝自サブの直前、終端＝自サブの最終連番）。**`m.Up()`（HEAD 終端）が使われていない。**
- [ ] **★「HEAD の最終状態で固定されているか」は問わない。** `SUPP-001` §5.5 (1)(2) と衝突する。**HEAD スコープの検査が要るなら `migrate_head_test.go` の `TestRun_HEAD_*` へ置く。**
- [ ] **投入した行と投入しなかった行が対で固定**されている（同 (3)）。**★「投入した件数」だけでは、規則を広く当てすぎても検出できない。**
- [ ] **三点更新を採った列が、件数で固定されていない。** 追随マイグレは**新規 DB では 0 行に当たり、件数テストは常に成功して何も守らない。**
- [ ] **投入行が `move_code` つきの全数リストで固定**されている。
- [ ] **終端の定数が明示されている。**

## §7. canary

- [ ] **段ごとに測られている**（指示書 §1.1 の各段の直後）。
- [ ] **期待値が書き換えられていない。** → 書き換えられていれば **R-3**。
- [ ] **値を変えない段で動いていない。** → 動いていれば「要説明」（別経路で候補集合が変わっている）。
- [ ] **動いた場合、増分が `move_code` つきで全数列挙されている。**
  - [ ] 候補の**出現・消失の件数**
  - [ ] 値が変化した件数と、その**内訳の全数説明**
  - [ ] **説明できない差分が 0 件**
- [ ] **★変化の方向が報告されている**（判定を締める方向か、緩める方向か）。**緩める方向の変化は、実機で成立することを個別に説明すること。**
- [ ] **★分類ごとに主張が閉じている。** 「すべて N 行のいずれか」のような文が分類の境界をまたいでいないか（またぐと再測定者が「未説明の差分がある」と読む）。
- [ ] **★基準を現ツリーで取り直しているか。** 三点更新を挟むと**基準ファイルが陳腐化する。**

## §8. ガード（**D-189**）

- [ ] 指示書 §3 で報告されたガードが、**期待値そのままで green。**
- [ ] **★版と値が対で書き分けられている。** 別の版の値を転用していないか（`is_projectile` の v39 = 104 を HEAD 用に転用して落ちた実例がある）。
- [ ] **完了報告に、本サブで守ったガードの所在（ファイル名＋テスト名）が明記**されている。

## §9. 転記の正しさ

- [ ] **改名がある場合、転記キーが `move_code` 単独になっていない**（`name_ja` との対で確認されている）。**★`move_code` だけだと別の技を上書きしてもエラーにならない。**
- [ ] **`NOT EXISTS` ガードが入っている**（新規 DB での UNIQUE 衝突の回避）。
- [ ] **一次源に無い値を推測で埋めていない。** 推測した箇所が**全数、設計伝達レポートに列挙されている**（CLAUDE.md §9-2）。
- [ ] **★親が一意に定まらない関連を埋めていない。** 埋めずに報告に回しているか。**`INSERT ... SELECT` は親を取り違えてもエラーにならず 0 行でも成功する。**

## §10. 否定形確認

- [ ] 指示書 §5 の各項目について、**走査キーワードで実際に走査した結果**が完了報告にある。
- [ ] **走査対象に 3 系統すべて**が含まれている——**本番コード／テスト資産（コメント・ヘルパ名・fixture・定数）／設計文書・指示書・overview**。
- [ ] **★除外対象が尊重されている。** 改名マイグレ自身とその検証テストが旧識別子を持つのは**正常である**（0 件は達成不能）。
- [ ] 指示書に §5 が無い場合、「**本サブでは撤回・改名は無い**」と明記されているか（節の欠落と、対象が無いことは違う）。

## §11. 報告

- [ ] **投入内訳で、意味が違う「投入しない」が別々に数えられている**（`unknown` / `保留` / 対象外 / 空欄 等）。→ 同一視されていれば **重大**。
- [ ] **対象行数と変化行数が分けて報告**されている。**一致して変化しなかった行も「一致を実査で確認した」として残っている。**
- [ ] **既知の限界**（機械判別できない対象・網羅の保証が無い範囲）が明記されている。
- [ ] **本サブの後に残る未確定の行数と内訳**（後続サブの入力）。
- [ ] **`docs/progress/progress-log.md` への追記**が行われている（**D-191**）。
- [ ] **設計伝達レポート §2** が「なし」でない場合、**F-1 の 3 条件の形**——(a) 一次源 (b) canary の全数差分の説明 (c) 変更した列と行の明示——で書かれている。

## §13. ★本チェックリスト自身の検査（**発行前に設計担当が行う**）

<!-- 記入指針: 以下 4 項目は M19-04c で実際に起きた欠陥である。発行前に必ず実行すること。 -->

- [ ] **本書と対の指示書の間に、節番号の食い違いが無い。**
  → M19-04c では見出しの「（§2.3）」「（§2.4）」が指示書の実際の節番号とずれていた。
- [ ] **メタ表の「対象指示書」が、配置時の実ファイル名と一致している。**
  → M19-PHASE2 で食い違った実例がある。
- [ ] **指示書が禁じていない事項を「重大」として求めている項目が無い。**
  → M19-04c では「既存マイグレの diff が 0 か」が指示書の「4 本の改変は許容」と正反対に併存していた。
- [ ] **達成不能な条件を重大として求めていない。**
  → M19-04c では「旧 code の文字列がリポジトリに残っている」を重大扱いしたが、**改名マイグレ自身が旧 code を名指しする必要がある**ため達成不能だった。
- [ ] **§0.3（重大でないもの）が埋まっている**（該当が無ければ「該当が無い」と明記されている）。
