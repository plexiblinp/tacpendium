## 0. この指示書の特殊性

### 0.1 コードを 1 行も変えない

**★★差分が空であることが完了条件である**（§5-6）。**`LICENSE` ファイルも本サブでは置かない。** 置くのは `CHANGE-151` 反映後である。

### 0.2 ★★判断を 1 か所だけ行う

本サブは事実の列挙が主だが、**1 つだけ判断を含む**——**このパスは層 A / B / C / D / 未割当 のどれか**、という割当である。

**★判断の基準は §2.2 に置いた。基準に当てはまらないものは「未割当」と書くこと。★推測で層へ入れない。**

### 0.3 ★★なぜこの調査が要るのか

**開発者の逐語（2026-09-02）＝「問題ない認識ですが、念のため、コード、ゲームデータ、汎用モジュールが何なのかを、最後に具体的な、そのファイルが格納されているフォルダなどのレベルまで明確にしたいです。」**

**⇒ 三層の採否そのものは合意されている。確定していないのは「どのパスがどの層か」である。**

**★★これが決まらないと `LICENSE` を置けない。** 層ごとに別ファイルを置く設計であり、**置き場が決まらないと SPDX ヘッダも書けない。**

### 2.2 ★★三層のパス割当（`A1` の前提・**本サブの主題**）

**★★リポジトリ直下から順に、すべてのトップレベル要素を 1 つずつ層へ割り当てる。**

**設計卓が観測したトップレベルは次のとおりである**〔`.agents` `.claude` `.codex` `.devcontainer` `.editorconfig` `.gitattributes` `.github` `.gitignore` `AGENTS.md` `CLAUDE.md` `Makefile` `README.md` `README.txt` `character_data` `cmd` `config.toml.example` `docs` `embed_migrations.go` `embed_web_release.go` `embed_web_stub.go` `go.mod` `go.sum` `human-notes` `internal` `migrations` `scripts` `web`〕。**★設計卓は 27 件と数えた。⇒ 数え直すこと**（`playbook` §4.40）。

**割当の基準**:

| 層 | SPDX | 基準 |
|---|---|---|
| **A. アプリ本体** | `AGPL-3.0-or-later` | **配布バイナリの動作に寄与するソース。★テスト・ビルド設定・CI もここ**（本体と不可分） |
| **B. ゲームデータ** | `CC-BY-SA-4.0` | **キャラクター・技・フレームデータ・手入力配布データ。★「事実」を集めたもの** |
| **C. 汎用モジュール** | `MIT` | **ゲーム非依存で、単体で他プロジェクトへ持ち出せるもの** |
| **D. ブランド** | ライセンス対象外 | **ロゴ・名称。★商標として別管理** |
| **未割当** | — | **上記のどれにも当てはまらない、または判断材料が足りないもの** |

| # | 確かめること |
|---|---|
| **★★1** | **トップレベルの全件（数え直した実数）を 1 件ずつ層へ割り当てる。★「未割当」を使ってよい。むしろ迷ったら未割当にする** |
| **★★2** | **`migrations/` を 1 ファイルずつ層 A / 層 B へ分ける**。**★設計卓の観測では `.up.sql` は 80 本、うち `seed` を名に持つものが 35 本ある。★数え直すこと。★★ただし「名前に `seed` が付く＝層 B」ではない**——**`seed_games` / `seed_presets` / `seed_initial_tags_user1` / `seed_combos_durability` はアプリの初期データであってゲームデータではない可能性がある。⇒ 中身を見て判定すること** |
| **★★3** | **`character_data/` の中身を層 B として扱ってよいかを判定する**。**★`*.csv` は手入力配布データである。★`seed-progress.md` 等の文書が同居していないか。★同居していたら層が割れる** |
| **★★4** | **`internal/seedgen/` の扱い**——**★「ゲームデータを生成するコード」はコードである（層 A）。生成物が層 B。⇒ 境界がここに在る。明示すること** |
| **★★5** | **層 C の実体が現在このリポジトリに在るか**。**★骨子は「メモ機能（一人SNS）等のゲーム非依存部・別リポジトリで育成」と書いている。★メモ機能は本体外へ出た**（Recurfold＝独立アプリ）。**⇒ 「層 C に該当するファイルは現時点で 0 件」という結論もありうる。0 件なら 0 件と書くこと** |
| **★★6** | **層 D の実体**——**ロゴ画像・アイコン・名称が入ったファイルが在るか。★`web/public/` 等。★無ければ「無い」と書く** |
| **★★7** | **`docs/` の層**——**★骨子は `docs/` に言及していない。★`docs` はアーカイブ含め全部公開する方針である**（開発者判断）。**⇒ 層 A か、独立した層か、未割当か。判断材料を挙げたうえで割り当てること** |
| **★★8** | **`CLAUDE.md` / `.claude/` / `AGENTS.md` / `.codex/` / `.agents` の層**——**★これらは公開してよい**（`D-637` (3)）。**⇒ どの層に置くかは別問題である** |
| **★9** | **`.devcontainer` の層**——**★公開物から外すことが決まっている**（`P-47`）。**⇒ 「公開しない」と「層の割当」は別である。層としては何かを書くこと** |
| **★10** | **利用者生成データ（コンボ・セットプレイ・タグ・プリセットのユーザー行）が、上記のいずれにも含まれないことを確認する**（骨子 §5＝**「完全にユーザーのもの」**）。**★これはファイルではなく DB の行である。⇒ ファイル割当表に現れないことを明示すること** |

### 2.3 ★AGPL-3.0-or-later との互換性判定

| # | 確かめること |
|---|---|
| **★★1** | **§2.1 で棚卸しした direct 依存のうち、`AGPL-3.0-or-later` の配布物へ取り込めないものが在るか。1 件ずつ判定すること** |
| **★2** | **判定の向きを取り違えないこと**——**★不許可なのは「AGPL の配布物に取り込めないライセンス」である。★MIT / BSD / ISC / Apache-2.0 / MPL-2.0 / LGPL / GPL-3.0 はいずれも AGPL-3.0-or-later 側へ取り込める。⇒ 詰まるのは限られた組み合わせだけである** |
| **★3** | **`AGPL-3.0-or-later` と `CC-BY-SA-4.0` が同じ配布物に同居することの扱い**——**★コードとデータは別の層であり、混ぜない設計である。⇒ 「同居してよいか」ではなく「境界が引けているか」を確かめること。境界＝§2.2-2 の `migrations/` の分割と §2.2-4 の `seedgen` の境界** |
| **★4** | **判定できないものは「判定できなかった」と書く。★★法的助言ではないため、断定を避けた記述にすること** |
