## 1. 背景と目的

### 1.1 背景

**`preset_aliases` に実データが入っているのは `official_ja_move` だけである**（`SUPP-001` §3.4 ／ 軸 C-5）。**`numeric` と `srk` は空で出荷されており、選択しても `DES-004` §5.3 のフォールバックで `official_ja_move`（日本語の技名）が出ていた。**

**M20-01 で初期プリセットは 3 種になった。** **本サブは残る 2 種を埋める。**

**★1 回きりの backfill を作ってはならない。** **適用時点の行だけを対象とし、以後 INSERT される行を静かに取り残す**（**D-181**）。**実例＝M19 で機械 backfill が第三波 seed より前にあったため、625 行が既定値のまま取り残された。** **`character_data` は 17 キャラ分しか揃っておらず、後続の seed 波が確実に来る。**

**⇒ 本サブが作るのは「17 キャラ分を入れるマイグレ」ではなく「規則」である。**

### 1.2 目的

完了時に、次の状態が成立している。

1. **`numeric` と `srk` のエイリアスが、生成規則によって投入されている。**
2. **規則が seed 波ごとに再適用できる形で存在し、その責務が seed 波側の手順に明記されている。**
3. **`preset_aliases` に `alias_text_en` 列があり、記法自身が語を持たない 30 種だけが埋まっている**（**D-321**）。
4. **OD 技 4 件の `command` が CSV に入り、`move_commands` の索引に載っている**（**D-318**）。
5. **「何も押さずに派生する技」28 件が全件列挙され、報告されている**（**D-315** ／ **P-34**。**本サブでは投入しない**）。
6. **生成後の `(moves.character_id, alias_text)` の重複が全数測られている**（**M20-03 の一意制約の前提**＝**D-306**）。

## 4. 詳細仕様

### 4.1 `preset_aliases` への `alias_text_en` 列の追加

**`ALTER TABLE preset_aliases ADD COLUMN alias_text_en TEXT;`**（**NULL 可**）。

**★規則 4 点。**

- **(a) NULL 可とする。** **既存 1,653 行は無改変である。** **NOT NULL ＋ 既定値にしない**——**「英語表記を持たない」と「空文字である」を区別できなくなる。**
- **(b) 埋めるのは 30 種だけである**（**D-321**）。**`micro_forward` / `micro_back` の 2 code と、28 件の派生。** **28 件の値は本サブでは入れない**（§4.8）。**⇒ 本サブが実際に埋めるのは 2 code × 19 キャラ ＝ 38 行 × 2 プリセット ＝ 76 行。**
- **(c) `official_ja_move` には 1 行も入れない。** **同プリセットは日本語の公式技名そのものであり、英語版を持たないと確定している**（**D-289**）。
- **(d) 一意制約を足さない。** **`alias_text_en` を含む一意性の設計は M20-03 が持つ**（**D-317** の帰結で、**一意にすべき単位が 2 列の合併集合になった**）。

**★down は列を落とす。** **SQLite の `ALTER TABLE ... DROP COLUMN` の可否を実査してから書くこと**（バージョン依存）。**使えない場合はテーブル再作成による復元になるが、その形は `SUPP-001` §5.5 の忠実復元の要求と衝突しうる**——**判断が要るなら §9.3 で報告すること。**

### 4.2 OD 技 4 件の `command` 補記（**D-318**）

**開発者から受領した確定値である**（一次源はゲーム内表示で、repo のどこにも無い）。

| キャラ | `move_code` | `command` |
|---|---|---|
| `guile` | `sonic_blade_od` | `d dl l plus p p` |
| `jp` | `triglav_od` | `d d plus p p` |
| `jp` | `departure_od` | `d dl l plus p p` |
| `lily` | `condor_spire_od` | `d dr r plus k k` |

**★3 段で行う。**

**(i) CSV へ挿入する。** **上の値を逐語で。** **挿入前に §3.3-4 で空欄であることを実査済みであること。**

**(ii) 検算する。** **3 つとも行うこと。**

- **トークン語彙に適合するか**（`docs/seed-data/official-data-edge-cases.md` §3.4 の実測出現表に `d` `dl` `dr` `l` `r` `plus` `p` `k` がすべて載る。**新しいトークンは 1 つも含まれない**）。
- **同キャラの同系統技と矛盾しないか**（例＝`guile` の `sonic_cross1_od` は `r plus p p` として既に登録されている。**元技と派生でモーションが違うこと自体は開発者確認済みで正しい**が、**他に同系統が実在する場合は並べて報告する**）。
