## 1. 背景

- 本体アプリ: ストリートファイター6 のコンボを登録・閲覧・管理するローカル/LAN 用 Web アプリ。Go（modernc.org/sqlite）+ React + TypeScript、単一バイナリ配布。
- FR701 ツール: カプコン公式サイトのキャラクター別フレームデータページ（HTML）をパースし、本体が取り込める CSV を出力する**別バイナリ**。
- 重要な制約（REQ-001 / DES-002 §7）:
  - **自動クローリングは行わない**。利用者がブラウザでフレームデータページを開き「名前を付けて保存」した HTML ファイルを入力とする。
  - 対応言語は**日本語版・英語版の2つ**のみ（他言語は非対応）。
  - ツールは **HTML → CSV** までを担う。CSV から DB への反映、`total`（全体硬直）の算出、手動修正は**本体側**（FR704 / FR703）。
- 用途: フェーズ2（先行リリース準備）で、クラシック操作5体（リュウ / ケン / イングリッド / C.ヴァイパー / ダルシム）のデータ整備に使う。

## 2. 入力仕様: 公式フレームデータ HTML

### 2.1 入力ファイル

- キャラ1体につき、**日本語版 HTML と英語版 HTML の各1ファイル**。
- ページタイトル例:
  - 日本語: `リュウ フレームデータ｜STREET FIGHTER 6（ストリートファイター6）｜CAPCOM`
  - 英語: `Ingrid FRAME DATA | STREET FIGHTER 6 | CAPCOM`
  - → タイトルからキャラクターを同定でき、日英の取り違え・別キャラ混入を検知できる。

### 2.2 テーブル構造（11 ヘッダ列グループ → 15 リーフ列）

ヘッダは以下の11グループ。一部はサブ列に展開される（リーフ計15列）。日英で構造・順序は同一、言語のみ差。

| # | 日本語ヘッダ | 英語ヘッダ | サブ列（リーフ） | 本体での反映先 |
|---|------------|-----------|----------------|---------------|
| 0 | 技名 | Move Name | 技名 | preset_aliases（official_ja_move）※正規化（§4.4） |
| 1 | 動作フレーム | Frame | 発生 / 持続 / 硬直（Start-up / Active / Recovery） | startup / active / recovery |
| 2 | 硬直差 | Recovery | ヒット / ガード（Hit / Block） | on_hit / on_block |
| 3 | キャンセル | Cancel | C / SA / SA2 / SA3 / ※ | **取込しない** |
| 4 | ダメージ | Damage | ダメージ | damage |
| 5 | コンボ補正値 | Combo Scaling | 始動 / コンボ / 即時 / 乗算（Initial / Combo / Immediate / Multiplier） | combo_scaling（JSON） |
| 6 | Dゲージ増加 | Drive Gauge Increase | ヒット（Hit） | drive_gauge_increase |
| 7 | Dゲージ減少 | Drive Gauge Decrease | ガード / パニッシュカウンター（Block / Punish Counter） | drive_gauge_decrease_guard（ガード）/ パニッシュは**取込しない** |
| 8 | SAゲージ増加 | Super Art Gauge Increase | SAゲージ増加 | super_art_gauge_increase |
| 9 | 属性 | Properties | 属性 | properties（コード値へ正規化、§4.5） |
| 10 | 備考 | Miscellaneous | 備考 | raw_data（notes） |

- 表記の注意:
  - 持続は範囲表記（例 `4-6`）。本体の `active` は**持続フレーム数**（`4-6` なら `3`）。CSV にどう出すかは §4 で定義。
  - 弾系などで硬直が「全体 N」表記になる場合がある。
  - 備考に「空振り時硬直 N フレーム増加」等の特記がある場合がある。
- 取込しない列（理由）:
  - キャンセル列 … 本体はコンボ成立可否判定を行わない（FR306）ため利用機能なし。
  - パニッシュカウンター時の Dゲージ減少・硬直差 … 利用機能なし（算出可能）。

### 2.3 カテゴリ区切り（6セグメント）

テーブル内に単一セル行でカテゴリ見出しが入り、以下6セグメントに分かれる（日英同順）。

| 日本語 | 英語 | 本体 category |
|--------|------|--------------|
| 通常技 | Normal Moves | normal |
| 特殊技 | Unique Attacks | unique |
| 必殺技 | Special Moves | special |
| スーパーアーツ | Super Arts | super_art |
| 通常投げ | Throws | throw |
| 共通システム | Common Moves | （§4.7 のスコープに従いフィルタ） |

## 3. 出力仕様: FR704 CSV 契約（本体取込の入力）

本体の DES-002 §7.5 が正本。以下を厳守すること。

### 3.1 基本方針

- 日本語版・英語版の両 HTML を**行対応でマージ**し、**1キャラ分を1つの CSV** として出力する。
- 文字コード UTF-8、1行目をヘッダ行。
- `move_code` / `character_code` は**ツールが決定論的に採番**する（§4.2）。本体は受領 code を信頼する。
- CSV は公式の**発生・持続・硬直**を保持する（**total は持たない**）。`recovery`（硬直）は CSV のみで本体 DB へは永続化されない（本体が startup・active・recovery から `total` を算出）。
- **英語公式技名は CSV に含めない**（`name_en` 列なし）。英語版 HTML は属性のコード値正規化と行マージ整合・code 検証に**内部利用**する（英語ロケールはフェーズ3以降）。

### 3.2 CSV 列（契約）

| CSV列 | 反映先 | 備考 |
|-------|--------|------|
| character_code | characters.code | upsert キー `(game_id, code)`。ツール採番 |
| move_code | moves.code | upsert キー `(character_id, code)`。ツール採番 |
| category | moves.category | §2.3 の写像（normal/unique/special/super_art/throw/drive_impact 等） |
| name_ja | preset_aliases（official_ja_move） | **正規化した技名**（§4.4） |
| startup | moves.startup | 発生 |
| active | moves.active | 持続フレーム数（範囲 `4-6`→`3`） |
| recovery | （moves 非永続） | 硬直。本体が total 算出に使用。DB 保存されない |
| on_hit | moves.on_hit | 硬直差ヒット（符号付き） |
| on_block | moves.on_block | 硬直差ガード（符号付き） |
| drive_gauge_increase | moves.drive_gauge_increase | |
| drive_gauge_decrease_guard | moves.drive_gauge_decrease_guard | |
| drive_gauge_decrease_punish | moves.drive_gauge_decrease_punish | 公式「Dゲージ減少／パニッシュ」※本体は将来用に列保持。出力要否は §9 確認事項 |
| super_art_gauge_increase | moves.super_art_gauge_increase | |
| damage | moves.damage | |
| combo_scaling | moves.combo_scaling（JSON文字列セル） | 始動／コンボ／即時／乗算 |
| properties | moves.properties | **コード値へ正規化**（§4.5） |
| is_aerial | moves.is_aerial | §4.6 |
| setup_only | moves.setup_only | 既定 false（手動付与想定） |
| notes | moves.raw_data | 公式「備考」。本体の要確認強調・total 手修正の参照元 |

> 注: §2.2 で「取込しない」とした パニッシュカウンター時の硬直差については列を設けない。Dゲージ減少のパニッシュ分（drive_gauge_decrease_punish）は本体に列が存在するため、CSV に出すかは §9 の確認事項とする。

## 4. 変換規約（ツールの責務）

### 4.1 日英マージ

- 各 HTML をカテゴリセグメント単位で読み、（カテゴリ, セグメント内の行位置）で日英を対応付ける。日英は同順前提。
- 対応が崩れる行を検知したら、要確認として報告する（取り違え防止）。

### 4.2 code 採番（決定論的）

- `character_code`・`move_code` を、同一入力に対し同一の値を返す決定論的規則で採番する（再取込の冪等性 = 本体 upsert の前提）。
- 命名規則は委任先が提案し、開発者承認を得ること（例の方向性: 英語版の技名・カテゴリ・入力をもとにスネークケース化。`stand_light_punch` / `throw_forward` 等）。本体既存 seed の code 規約（DES-003 / SUPP-001）と矛盾しないこと。

### 4.3 キャラクター同定

- ページタイトルからキャラクターを同定し、想定キャラ・言語と一致するか検証する。

### 4.4 技名の正規化（official_ja_move 用、DES-004 §3.2 / CHANGE-023）

- (a) 末尾の**キャラ固有フレーバー名を除去**: `（…）` と `: …`。
  - 例: `立ち弱P（ジャブ）` → `立ち弱P`、`ドライブインパクト（震撃）` → `ドライブインパクト`、英語 `Drive Impact: Shingeki` → `Drive Impact`。
- (b) **通常投げは位置で汎用名を自動採番**: 通常投げセグメントの出現順で、1件目 = `前投げ`、2件目 = `後ろ投げ`（SF6 公式は前投げ→後ろ投げ順で安定。例: リュウ 背負い投げ→前投げ、巴投げ→後ろ投げ）。キャラ別のダメージ・フレームは保持（固定値化しない）。並び順が想定外のキャラは要確認報告（本体 FR703 で補正）。
  - 英語汎用名（フェーズ3以降の英語ロケール用、現状は出力不要）: `前投げ`=`Forward Throw`、`後ろ投げ`=`Back Throw`。
- 想定外の語形は要確認として報告する（過剰除去の防止）。`move.code` は表示名と独立なので本正規化の影響を受けない。

### 4.5 properties の正規化（→ コード値）

属性をコード値へ正規化する。英語版は単字コードで明快なので、英語版を基準にすると素直。

| 日本語 | 英語 | コード値 |
|--------|------|---------|
| 上 | H | high |
| 中 | M | mid |
| 下 | L | low |
| 投 | T | throw |
| 弾 | P | projectile |
| 空弾 | MP | air_projectile |

- 複数属性（弾系の「上・弾」等、稀）は主属性をコード値、残りを notes（raw_data）へ。

### 4.6 is_aerial（空中判定、CHANGE-022）

- 公式技名に「ジャンプ」または「（ジャンプ中に）」を含む技は `is_aerial = true`、それ以外は `false`。
- 接頭辞の付かない空中技（ジャンプから出す特殊技等）は自動判定できないため `false` のままとし、本体 FR703 で利用者が手動 true 化する（要確認報告に含めると親切）。

### 4.7 取込スコープ（DES-002 §7.5「取込対象」/ CHANGE-023）

- **取込対象（moves 化する）**: 通常技 / 特殊技 / 必殺技 / スーパーアーツ / 通常投げ / ドライブインパクト（共通システム内の attack）。ターゲットコンボが公式に存在する場合はそれも含む。
- **取込対象外（出力しない）**:
  - 前方ステップ / 後方ステップ … 本体ではコンボ内 modifiers.type（dash_forward / dash_back）で表現。
  - パリィドライブラッシュ / キャンセルドライブラッシュ … 本体 modifiers.type（parry_drive_rush / cancel_drive_rush）。
  - ドライブパリィ / ジャストパリィ（打撃・飛び道具）… 非攻撃（ダメージ=0）でコンボのステップにならない。
  - ドライブリバーサル（ガード時・起き上がり時）… 攻撃だがコンボ部品でない。
- **判別**: カテゴリセグメント + 共通システム内のダメージ値（=0 のシステム動作は対象外）で判別する。共通システムから取り込むのは実質ドライブインパクトのみ。

### 4.8 ラッシュ版（生成しない）

- ラッシュ版（ドライブラッシュで性能が変わる版）は公式 HTML に独立カテゴリが無く、ツールは生成しない。本体 FR703 編集器が、対象の通常技・特殊技（`category ∈ {normal, unique}` かつ `is_aerial = false`）を元に生成する。

### 4.9 検証（ツール側、NFR104）

- 入力 HTML の構造検証（期待するヘッダ・カテゴリ構成の確認）。
- キャラクター同定（§4.3）。
- 数値データの妥当性チェック（負値・極端値の検出）。
- 本体側の検証（取込プレビューの寛容表示・セキュリティ無害化・DB 制約チェック・行単位取込）はツールの責務外（DES-002 §7.4）。

## 9. 開発者への確認事項（委任先へ引き継ぐ未確定点）

1. **code 命名規則**: 決定論採番の具体規則（英語名ベースのスネークケース等）の方向性で良いか。本体既存 seed の code 規約との整合確認。
2. **drive_gauge_decrease_punish の CSV 出力**: 本体に列は存在するが、取込対象外（パニッシュ関連）の整理と矛盾しないか。出力する／しないの確定。
3. **ツールの技術スタック**: 独立選定（Go で揃える vs パース容易な言語）の方針。
4. **要確認報告の受け渡し**: ツールが出す「要確認」（投げ並び順の例外・接頭辞なし空中技・過剰除去候補・日英対応崩れ）を、CSV 内の印（列）にするか、別レポートにするか。本体 FR703 の取込プレビューとの接続方法。
5. **ターゲットコンボの公式表現**: 公式 HTML 上でターゲットコンボがどのセグメント・表記で現れるか（5体で確認）。
