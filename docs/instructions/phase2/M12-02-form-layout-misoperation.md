## 1. 背景と目的

### 1.1 背景

- M12 先行リリース仕上げのうち、**誤操作・スクロール負荷**の系統(M12-overview §2)を解消する。メモの横断原則「何らかのボタンを押すのにスクロールを多用するものは見つけ次第直す」に該当する 4 項目。
- 対象はコンボ登録・編集(DES-005 §5.7)・セットプレイ登録・編集(§5.9)・コンボ詳細のセットプレイ表示(§5.6 L270 アコーディオン)。
- **実態確認の前提(§4.10/M10-4)**: 仮登録トグル・保存/キャンセルボタン・エラー表示の**実描画位置**と、C-13 の「展開機構」が詳細(§5.6)か一覧(§5.4)かは、DES-005 の記述と実装で差がありうる。**着手前確認(§3.4)で実態を確定してから実装する**。

### 1.2 目的

本指示書完了時、以下を達成する(4 項目):

- **C-04 エラー位置の統一**: バリデーション警告(FR305、非ブロッキング)の表示位置を、コンボ登録・編集とセットプレイ登録・編集の**両方で保存ボタンの直上に統一**する。スクロールして保存しようとした位置でエラーを確認できる状態にする。
- **C-09 キャンセルボタンのスクロール負荷**: 登録・編集系のキャンセル(戻る)ボタンが**最下部までスクロールしないと押せない**現状を解消し、フルスクロール不要で押せる状態にする。
- **C-13 セットプレイ展開機構の除去**: セットプレイの展開機構(アコーディオン)を無くし、**最初から展開済み**(各セットプレイのレシピが常時表示)にする。**クリックによる編集画面への遷移は維持**する(「展開したいのに編集へ遷移しがち」の混同を、展開アクション自体を無くすことで解消)。
- **C-15 仮登録トグルの位置**: 新規登録画面で**仮登録トグル(is_draft)をフォームの最上部**に配置し、スクロールせず最初に見える状態にする。

### 1.3 このマイルストーン(指示書)で作らないもの

- 表記・文言、ソート/フィルタ、戻り保持(M12-01)。
- 表示項目・入力/検証(C-03 セットプレイ名必須 / C-10 / C-11 / C-12 始動技プルダウン除去 = M12-03)。
- 起き攻め表示(R-1 = M12-03)。
- キャラクター選択方式統一(N-29 = M12-04)。
- 重複判定キー編集の (a)(b) 保存方式・セットプレイ引き継ぎ処理(§5.7、本指示書はレイアウトのみ。挙動は不変)。
- リアルタイム重複検知の警告(§5.7 L310、画面上部)の位置変更(別機構。C-04 はバリデーション警告が対象。§3.4.4 で区別を確認)。

## 4. 詳細仕様

> 各項目は §3.4 の実態確認結果に基づき、対象コンポーネント・位置を確定してから実装する。

### 4.1 C-04 エラー位置の統一

- バリデーション警告(FR305、非ブロッキング)を、**コンボ登録・編集とセットプレイ登録・編集の両方で「保存ボタンの直上」に表示**する。
- スクロールして保存ボタン付近に来たときにエラーが視認できる配置にする。検証内容・タイミング・非ブロッキング方針(仮登録中は警告抑制、§5.7 L373)は**不変**。
- リアルタイム重複検知の上部警告(§5.7 L310)は別機構として**現状維持**(§3.4.4 で区別。重複検知も移動すべきかは Plan Mode で確認)。
- → DES-005 §5.7/§5.9 にエラー表示位置の規定を追記 = **CHANGE 候補**。

### 4.2 C-09 キャンセルボタンのスクロール負荷解消

- 登録・編集系のキャンセル(戻る)ボタンを、**フォーム最下部までスクロールせずに押せる**ようにする。
- 実装方式は製造担当の裁量(例: 保存/キャンセルを下部 sticky にする、上部にもキャンセル導線を置く 等)。**end-state =「フルスクロール不要でキャンセルできる」**。
- 既存のキャンセル時確認ダイアログ(§5.7 L367)は不変。
- スマホ/PC 双方で成立すること(§5.7 レスポンシブ L379-381)。
- → 配置変更が DES-005 §5.7/§5.9 表示項目の位置規定に及ぶ場合は CHANGE 候補。

### 4.3 C-13 セットプレイ展開機構の除去(展開済み既定)

- §3.4.5 で特定した対象画面で、セットプレイの**展開機構(アコーディオンの開閉)を除去し、最初から展開済み**(各セットプレイのレシピが常時表示)にする。
- **セットプレイ行クリック → 編集画面への遷移は維持**する(§5.6 L283)。展開アクション自体を無くすことで「展開したいのに編集へ遷移する」混同を解消する。
- アコーディオンの開閉状態保持(該当する場合)・開閉アイコン(▶/▼)は除去。`onUnlink` 等の他アクションは維持。
- 対象が一覧の行展開(§5.4 L203/L224)に及ぶ場合の扱いは Plan Mode で確認(M12-01 の一覧表示と競合しないこと)。
- → DES-005 §5.6 L270(アコーディオン展開 → 常時展開表示)の改訂 = **CHANGE 候補**。

### 4.4 C-15 仮登録トグルの最上部配置

- 新規登録モードで、仮登録トグル(is_draft)を**フォーム最上部**(スクロールせず最初に見える位置)に配置する。
- 編集モードでの仮登録の扱い(本登録切替等)は不変。
- → DES-005 §5.7 表示項目順(現 #3)の改訂 = **CHANGE 候補**。

## 10. 開発者への確認事項(文末集約)

1. **C-04 のリアルタイム重複検知(§5.7 L310)の扱い**
   なぜ: C-04 は「エラー位置をボタンの上に統一」だが、コンボ編集には別途リアルタイム重複検知の上部警告(L310)がある。両者を同じ位置に寄せるか、重複検知は上部のままにするかで体験が変わる。
   暫定案: バリデーション警告(FR305)のみ保存ボタン直上へ統一し、リアルタイム重複検知の上部警告は現状維持(役割が異なるため)。これでよいか。

2. **C-13 の対象画面**
   なぜ: セットプレイの「展開」は詳細(§5.6 アコーディオン)と一覧(§5.4 行展開 ▶/▼)の双方にありうる。
   暫定案: 着手前確認で「展開したいのに編集へ遷移」の混同が起きている画面(`SetupAccordionItem` の使用箇所=詳細の見込み)を特定し、そこの展開機構を除去。一覧の行展開(§5.4)は M12-01 の表示と競合しうるため、対象に含めるかは特定結果を見て Plan Mode で確認。詳細のみを既定対象とする方針でよいか。
