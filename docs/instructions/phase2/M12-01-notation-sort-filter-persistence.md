## 1. 背景と目的

### 1.1 背景

- M12 は先行リリース仕上げ(フェーズ2 最終マイルストーン)。本指示書は先行リリースの妨げ(誤操作・スクロール負荷・表記の不正確さ)のうち、**表記・文言**と**ソート/フィルタ UX**と**戻り時のフィルタ消失**を解消する(M12-overview §2 の M12-01 群、15 項目)。
- 対象画面はコンボ一覧(DES-005 §5.4)・マイコンボ(§5.5)を中心に、タグ選択・ゲージ/始動技の表示文言を含む。
- **重要な前提(§4.10/M10-4)**: メモ由来の項目(C-18/C-19/C-17 等)は、実装のソート/フィルタ項目が DES-005 §5.4 の記述と乖離している可能性がある(§5.4 L199 のソート項目に opponent_stance は無く、L204 では始動状況グループに position/hit_type が含まれる)。**実態を着手前確認(§3.4.2)で確定してから実装する**(「あるはず」で進めない)。

### 1.2 目的

本指示書完了時、以下を達成する(15 項目):

**表記・文言**
- C-06: 「DR」表記を「ドライブラッシュ」へ(**起き攻め以外の DR 表記のみ**。起き攻めの DR は R-1=M12-03 のラベル統一に委譲、§3.4.3 / §9.1)。
- C-16: タグ未入力時の表示を「タグを選択...」→「タグを選択、または、新規登録」へ。
- C-20: 内部値の画面表示を消す(例「始動技(starter_move_id)」→「始動技」)。
- C-21: ゲージ表記「(0〜6)」→「(0〜6本)」(**日本語ロケールのみ**)。
- C-22: link を日本語ロケールで「目押し」表示(**日本語ロケールのみ**)。

**ソート/フィルタ UX**
- C-02: ソートの既定を「始動状況」→「更新日時」へ。
- C-05: フィルタリセットボタンを一覧に露出。
- C-07: マイコンボの件数表示がステータス切替タブと紛らわしい点を解消。
- C-17: マイコンボとコンボ一覧のソートの不一致を解消(整合/部品化)。
- C-18(方針転換): 相手スタンスはフィルタに温存し、**一覧項目に控えめ表示**を追加(不問が多いため目立たせない)。
- C-19: ソート確認用に、ポジション・ヒット種別を一覧本体に表示。
- C-23: フィルタ表示列の選択ウィンドウが、1 列消すごとに閉じてしまう問題を解消(連続トグル可能に)。
- C-24: タグが増減・長くなった際の一覧フィルタ表示の崩れを解消。

**戻り時のフィルタ保持**
- C-01 + N-30: 一覧以外の画面(詳細/編集/登録)から一覧へ戻った時、フィルタ(キャラクター含む)・ソート・仮登録トグルを保持する。

### 4.2 ソート/フィルタ UX(C-02/05/07/17/18/19/23/24)

- **C-02 ソート既定変更**: 既定ソートを「始動状況」→「更新日時」へ(`useComboListFilters` の初期値 + DES-005 §5.4 L199/L201 の「デフォルト」記述)。降順(新しい順)を既定とする。マイコンボ(§5.5 L253)も同様に更新日時既定へ揃える(C-17 と連動)。→ **DES-005 §5.4/§5.5 改訂 = CHANGE 候補**。
- **C-05 フィルタリセット**: `ComboTable` の `onClearFilters`/`hasActiveFilters`(既存機構)を、一覧のフィルタ領域にリセットボタンとして露出。`hasActiveFilters` が true のときのみ活性。
- **C-07 マイコンボ件数表示**: ステータス切替タブ(`MyComboStatusTabs`、各タブに件数 counts)と、件数表示が紛らわしい点を解消(タブのカウントバッジと別表示の区別を明確化。具体表現は §3.4.2 の実態に基づき決定)。
- **C-17 ソート整合**: マイコンボとコンボ一覧のソート実装の不一致を解消。§3.4.2 で特定した差異を、共通ソート定義の参照(部品化)で揃える。DES-005 §5.5 L253「同様」に実装を一致させる。
- **C-18 相手スタンスの一覧控えめ表示**(方針転換): 相手スタンス(opponent_stance)は**フィルタに温存**(ソートからは除去しない=§3.4.2 分岐)。**一覧本体に相手スタンスを控えめに表示**(コンボは「不問」が多いため、不問は非表示または淡色等で目立たせない。具体表現は §3.4.2 の表示項目実態に合わせる)。→ DES-005 §5.4 表示項目に追記 = CHANGE 候補。
- **C-19 ポジション・ヒット種別の一覧表示**: ソート確認用に position / hit_type を一覧本体で識別できるよう表示(§3.4.2 で「始動状況グループに既存」なら強調/明示、不可視なら追加)。→ DES-005 §5.4 表示項目 = CHANGE 候補。
- **C-23 列選択ウィンドウの連続トグル**: `ColumnVisibilityMenu` で 1 列の表示/非表示を切り替えるたびにウィンドウ(Popover/メニュー)が閉じる現状を、**閉じずに連続トグルできる**よう修正。
- **C-24 タグ表示の崩れ**: タグが増減・長文の際に一覧フィルタ表示が崩れる点を解消(`TagBadgeList`/フィルタ領域の折返し・省略・最大表示等のレイアウト調整)。

> C-18/C-19 の「一覧本体表示」は、§3.4.2 の DES-005 §5.4 L202-215 表示項目との対応表に基づく。新規表示列は表示列カスタマイズ(L200)の対象に含めるか否かを Plan Mode で確認する。

### 4.3 戻り時のフィルタ/ソート/キャラ保持(C-01 + N-30)

- 一覧以外の画面(コンボ詳細/編集/登録、§5.4 のアクション遷移先)から一覧へ戻った時、**フィルタ(キャラクター選択・タグ・状況・仮登録トグル)とソート**を保持する。
- 保持手段は、既存の列表示(L200=ブラウザストレージ)・展開状態(L224=セッション)と同系統(`useSessionStorage` 等の in-app セッション保持)。**セッション跨ぎの恒久化は行わない**(P3、§1.3)。
- N-30(編集/登録から戻った時のキャラフィルター維持)は本保持に包含される(キャラクター選択もフィルタ状態として保持)。
- → DES-005 §5.4 に「フィルタ/ソートの保持挙動」を追記 = CHANGE 候補。

## 10. 開発者への確認事項(文末集約)

1. **C-06 の起き攻め DR の委譲**
   なぜ: C-06「DR→ドライブラッシュ」の主対象は起き攻め状況の区分だが、起き攻めラベルは R-1(M12-03)で統一的に作り直す。同じ i18n キーを M12-01 と M12-03 で二重に触ると競合・手戻りが生じる。
   暫定案: 起き攻めの DR ラベルは **M12-03(R-1 ラベル統一)に委譲**し、M12-01 では「起き攻め以外」の DR 表記のみ対象とする(着手前確認で起き攻め以外の DR が 0 件なら、C-06 は M12-01 では対応なし=全て M12-03)。この整理でよいか。

2. **C-18/C-19 の一覧表示列を「表示列カスタマイズ」の対象に含めるか**
   なぜ: 相手スタンス(C-18 控えめ)・position/hit_type(C-19)を一覧本体に出す際、既存の表示列カスタマイズ(DES-005 §5.4 L200、ブラウザストレージ保存)の ON/OFF 対象に含めるかで挙動が変わる。
   暫定案: 既定では表示(C-18 は控えめ)し、表示列カスタマイズの対象に含めて利用者が非表示にもできるようにする。可否をご判断いただきたい(含めない=常時表示も可)。
