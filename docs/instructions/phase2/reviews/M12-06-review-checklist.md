## 0. レビュー担当への前置き

### 0.1 レビュー前の準備
- 必読: `M12-06-integration-e2e-and-release-decision.md` v1.0.0、DES-002 §4.2(presence-detection)、m12-design-session-handover §3.2、既存 E2E spec(`e2e/` 配下)。
- **前提ゲート**: (1) M12-01〜05 完了。(2) §3.4 着手前確認(既存 spec 棚卸し / presence-detection 対象項目 / 実行基盤)が完了報告にあるか。

### 0.2 基本姿勢
- E2E spec の検証。**配布判定(§7)は開発者ゲートでありレビュー対象外**(spec の品質と棚卸しの網羅を見る)。
- 最重点 = (a) E-1 が保持/クリアの両方を検証、(b) 実装方式非依存(test-id ベース)、(c) 棚卸し対応表の網羅、(d) 既存 spec 非回帰・過剰作成なし。

### 0.3 報告フォーマット
- 各節「OK / 重大(§7)/ 軽微(§8)/ 質問(§9)」。

## 1. 着手前確認 + 設計判断
- [ ] §3.4.1 既存 E2E spec の全数棚卸し対応表が報告され、**E-1 相当が既存に無い**(or 部分存在)ことが確認されているか。
- [ ] §3.4.2 presence-detection 対象 nullable 項目(DES-002 §4.2)が HEAD 確認され、E-1 の検証対象項目セットが確定しているか。
- [ ] §10 設計判断(E-1 最優先 / 実装方式非依存 / 配布判定は開発者 / 過剰作成回避)に沿っているか。

## 2. E-1 回帰 spec(最重点)
- [ ] **保持検証**: 多項目メタデータのコンボを 1 項目だけ編集 → 保存 → リロード/再取得で**他項目が全保持**をアサートしているか。
- [ ] **クリア検証**: 1 項目を present+null でクリア → 当該項目のみ NULL・**他項目は保持**をアサートしているか。
- [ ] 検証対象が §3.4.2 で確定した項目セット(複数型をまたぐ)を覆っているか。
- [ ] **実装方式非依存**(test-id ベース・特定 DOM に依存しない)。

## 3. 統合 E2E の棚卸し・穴埋め
- [ ] フェーズ2 主要フロー(5体登録・閲覧 / 取込データ表示 / custom_states / コンボ CRUD / 比較 / セットプレイ / 仮登録昇格)の対応表が作成されているか。
- [ ] 不足分のみ穴埋めし、**既存 spec で足りるフローに重複 spec を増やしていない**か。

## 4. 既存挙動の温存(非回帰)
- [ ] M12-01〜05 で整備済みの既存 E2E spec を壊していない。
- [ ] アプリ本体(FE/BE)・DES・seed・マイグレに変更がない(本サブは E2E spec のみ)。

## 5. 実行・報告
- [ ] E-1 spec がローカル実行可能な範囲で緑(実機は開発者ゲート)。
- [ ] 棚卸し対応表・追加 spec のケース数・実機ゲート手順が完了報告にある。

## 6. ドキュメント
- [ ] §7 配布判定チェックリストの実施が**開発者ゲート**として扱われ、製造担当が判定していない。
- [ ] E-1 が検証する nullable 項目セットが完了報告に明記されている。

---

## 7. 重大な問題の判定基準(完了承認を妨げる)
- E-1 spec が**保持またはクリアのどちらかを検証していない**(presence-detection 回帰ネットとして不完全)。
- E-1 が特定 DOM 実装に依存し、実装変更で容易に壊れる記述になっている。
- 既存 E2E spec を**壊している**(非回帰違反)。
- アプリ本体/DES/seed/マイグレを変更している(本サブのスコープ逸脱)。
- 棚卸し対応表が無い、または主要フローに明白な抜けがあるのに穴埋めされていない。

## 8. 軽微な問題の判定基準(持ち越し許容)
- spec の記述スタイル・命名・ファイル配置の好み(検証意図が満たされていれば可)。
- 穴埋め spec の網羅度が「主要フロー」を超えた網羅(過剰でない範囲なら可)。

## 9. 質問・確認事項のフォーマット
- 「指示書 §X.X / DES-002 §4.2 に対し spec が Z。意図確認したい」の形で根拠併記。

## 10. レビュー完了の判定
- §1〜§6 全 OK、§7 重大ゼロ、前提ゲート + §3.4 棚卸し報告が揃っている。特に **§2 E-1 の保持/クリア両検証**・**実装方式非依存**・**§4 非回帰**を確認。§8 軽微は持ち越し可。配布判定(§7 指示書)は開発者実施のためレビュー対象外。
