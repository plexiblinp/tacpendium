## 0. レビュー前の準備・報告フォーマット

- M8-02 指示書 v1.0.0(特に §1.3 スコープ外・§3.4 着手前確認・§4 詳細)と M8-RESEARCH-01 レポートを読む。
- Plan Mode 質問書と開発者回答、完了報告(progress-log)を読む。
- `docs/instructions/M8-02-review-report.md` に出力(判定: 合格/要修正 / 重大指摘 / 軽微指摘 / 確認要約)。

## 1. 基盤導入

- [ ] `@playwright/test` が `web/package.json` の devDependencies にあり、`e2e` script が追加されている。
- [ ] `playwright.config.ts` が存在し、testDir(`e2e/`)・baseURL(`http://localhost:5173`)・webServer(§3.4.3 合意方式)・chromium project が設定されている。
- [ ] ポートが現行値(vite 5173 / backend 47318)で、旧シナリオの陳腐化ポート(3000 / 8080)を使っていない。

## 2. test-id 規約と付与

- [ ] test-id 規約(`data-testid="{feature}-{element}"`)がドキュメント化されている。
- [ ] **付与は最小限**: spec が触る操作要素のうち Radix の `role`+`name` で一意に取れないものに限定。role で取れる要素に testid を乱付けしていない。
- [ ] testid 付与は属性追加のみで、コンポーネントのロジック・構造・見た目を変更していない。

## 3. スモーク/回帰 spec

- [ ] §3.4.1 で合意したフロー(初回 1〜3 本)の spec が `e2e/` にある。
- [ ] セレクタが `getByRole` / `getByLabel` 優先で、足りない箇所のみ `getByTestId`。
- [ ] **視覚・レイアウト・レスポンシブのアサートを入れていない**(機能の成否のみ検証、§1.3)。
- [ ] spec が特定 seed の件数に過度に依存していない(M9 で seed 再生成に変わるため、§3.4.4)。

## 4. スコープ遵守(設計意図)

- [ ] 視覚・レスポンシブ・LAN 実機・操作感 UX を自動化していない(手動 E2E に残す、§1.3)。
- [ ] CI(GitHub Actions 等)を新設していない(本フェーズはローカル実行、§1.3)。
- [ ] 全 177 シナリオの spec 化や全 UI 要素への testid 付与をしていない(段階導入)。
- [ ] アプリの挙動・API・DB スキーマに手を入れていない(E2E は外側からの検証)。

## 5. 実行とテスト

- [ ] `pnpm e2e`(または `make e2e`)で webServer 起動 → spec 実行ができる。
- [ ] 既存ユニットテスト(Go test / Vitest)が非破壊。
- [ ] 開発者のローカル実行結果(スモーク spec 通過)が完了報告に記載されている。

## 6. ドキュメント

- [ ] progress-log に M8-02 完了報告(導入内容・spec 一覧・Plan Mode 確認結果・ローカル実行結果)が追記されている。
- [ ] 追加付与した testid 要素が完了報告に列挙されている(§9.2)。

## 7. 重大な問題の判定基準

- アプリ挙動・API・スキーマの変更(E2E はテストのみのはず)。
- 視覚/LAN/CI の自動化など §1.3 スコープ外への逸脱。
- testid 乱付け(role で取れる要素への不要付与)でコンポーネントを汚染。
- spec が起動・実行できない(基盤として不成立)。

## 8. 軽微な問題の判定基準

- spec の網羅が薄い(段階導入のため初回は最小で可、後続で拡充)。
- 規約ドキュメントの軽微な不足。
- 完了報告の testid 列挙・実行結果の記載漏れ(追記を求める指摘)。

## 9. 完了判定

- §1〜§6 を確認し §7 重大指摘 0 件なら「合格」。1 件以上なら「要修正」。§8 軽微指摘は合格を妨げないが report に列挙。
