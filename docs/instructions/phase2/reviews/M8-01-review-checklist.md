## 0. レビュー担当への前置き

### 0.1 レビュー前の準備

- M8-01 指示書 v1.0.0 を読む(特に §1.3 スコープ外・§2.3 変更しないもの・§4 詳細仕様)。
- DES-003 §3.3(L258-337、moves スキーマ8列)・§7(マイグレーション方針)、DES-002 §4.2(L135、GET エンドポイント)、CHANGE-022 §3.1 / §5 を参照する。
- 製造担当の Plan Mode 質問書(`docs/instructions/M8-01-plan-mode-questions.md` 等)と開発者回答、完了報告(progress-log)を読む。

### 0.2 レビューの基本姿勢

- 本マイルストーンは **加算的スキーマ移行**。最重要は「既存挙動の非破壊」と「スコープ遵守(後続 M9 の責務を先取り実装していないこと)」。
- 機械的な列・フィールド一致だけでなく、§5 の設計意図(器のみを用意し、算出・正規化・取込は実装しない)に沿っているかを確認する。

### 0.3 レビュー結果の報告フォーマット

`docs/instructions/M8-01-review-report.md` に出力:


## 1. 設計書本体との照合(最重要観点)

### 1.1 moves 8列の定義(DES-003 §3.3 L267-280)

up.sql で追加された各列が DES-003 §3.3 の定義と一致するか:

- [ ] `startup` = INTEGER NULL 可(CHANGE-025。旧 NOT NULL を撤回)。
- [ ] `active` = INTEGER NULL 可(範囲表記を本数へ正規化した値を格納する設計、L268 / L331)。
- [ ] `total` = INTEGER NULL 可(CHANGE-025。算出不能行は NULL)。
- [ ] `on_hit` = INTEGER NULL 可。
- [ ] `on_block` = INTEGER NULL 可。
- [ ] `drive_gauge_decrease_guard` = INTEGER NULL 可。
- [ ] `is_aerial` = INTEGER NOT NULL DEFAULT 0(真偽列の物理表現規約。SUPP §2.7)。
- [ ] `setup_only` = INTEGER NOT NULL DEFAULT 0(真偽列の物理表現規約。SUPP §2.7)。
- [ ] 8列以外の列を追加・変更していないこと。

### 1.2 マイグレーション方針(DES-003 §7 / SUPP-001 §2.7・§3.6)

- [ ] ファイル名が `NNNNNN_add_moves_frame_columns.up.sql` / `.down.sql` 形式で、番号が既存最新 + 1(§3.4.1 の Plan Mode 確認結果と一致)。
- [ ] up / down が対になり、down で追加列が除去され元のスキーマへ戻る。
- [ ] 既存マイグレーションファイル(000001〜000012)を書き換えていないこと。

### 1.3 エンドポイント(DES-002 §4.2 L135)

- [ ] `GET /api/moves?character_id={id}` のレスポンスに8フィールドが追加されている(実装整合)。

## 2. API 整合性

- [ ] レスポンスは8フィールドの**追加のみ**。既存フィールドの削除・改名・型変更がない(§2.3)。
- [ ] JSON タグが camelCase(`onHit` / `onBlock` / `driveGaugeDecreaseGuard` / `isAerial` / `setupOnly`、その他は `startup` / `active` / `total`)。CLAUDE.md §4・既存 DTO の規約と一致。
- [ ] エラーレスポンスは既存の共通型(`model.APIErrorResponse`、DES-002 §4.3)を流用し、本指示書で独自エラー型を新設していない(本指示書はエラー経路を追加しないため、新設している場合は指摘)。

## 5. 設計意図との整合(機械チェックを超える観点)

本マイルストーンの設計思想は「**スキーマと型の器のみを用意し、値の生成は後続に委ねる**」:

- [ ] `total` の算出ロジック(発生 + 持続 − 1 + 硬直 + 備考補正)を **実装していない**(M9-02 の責務、指示書 §1.3 / §1.4)。既存 seed 行は NULL のままで算出値は入っていない(CHANGE-025)。
- [ ] `properties` のコード値正規化を **実装していない**(M9-02 の責務)。`properties` 列定義が不変(§2.3)。
- [ ] CSV 取込(`POST /api/import/moves`)・取込プレビュー・ラッシュ版生成・`is_aerial` 手動トグル UI を **実装していない**(M9 の責務)。
- [ ] startup/total が NULL 可で扱われ(一時 DEFAULT/backfill なし = CHANGE-025)、算出不能行が NULL になっている。

> いずれかが先取り実装されている場合、スコープ逸脱として §9 重大指摘とする。

## 9. 重大な問題の判定基準(M8 完了承認を妨げるレベル)

- API 既存フィールドの削除・改名・型変更(後方互換破壊)。
- `properties` の変更、または `total` 算出 / properties 正規化 / CSV 取込の先取り実装(スコープ逸脱)。
- マイグレーション up が既存 seed 行で適用失敗する（本指示書に NOT NULL かつ DEFAULT なしの列追加は無いため、これが起きれば設計逸脱）。
- down が元スキーマへ戻らない(ロールバック不能)。
- 8列の型・制約が DES-003 §3.3 と不一致。
- マイグレーション番号の衝突・不連続。
- 既存挙動(コンボ一覧・詳細・編集)の破壊。

---

## 10. 軽微な問題の判定基準(後続への持ち越しを許容)

- コメント・命名の軽微な規約逸脱。
- バックエンド / フロントエンドテストの網羅が一部薄い(致命的でなく後続で補える範囲)。
- 完了報告の down.sql 方式・DTO の NULL 表現の記載漏れ(追記を求める指摘)。
