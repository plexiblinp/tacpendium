## 1. 目的・位置づけ

M12 は先行リリース(近しい関係者への試用提供)に向けた仕上げ。完了 = **フェーズ2 完了 = 先行リリース実施点**。

本マイルストーンの肝は **「フェーズ2 でやるべき事を全件処遇すること」**。残フェーズ2 項目(必須残 R-1 / 候補 C-01〜24 / 取込 N-30・N-29・N-28)すべてに明示的処遇(M12 で実装 / フェーズ3+ へ根拠付き送り)を付け、§2 で可視化する。あわせて先行リリースの妨げ(誤操作・スクロール負荷・表記の不正確さ・不具合)を優先実装し、検証データ/seed を整理し、統合 E2E と配布判定を行う。

## 4. 主要設計判断・調査結果の反映

### 4.1 R-1(M12-RESEARCH-01 で確定 → M12-03 で修正)
- 「中段化」は move `properties`(段)由来ではなく、`ja.json` `comboDetail.oki.meaty*` の **ラベル誤訳「中段攻め」**(`oki_meaty_*` = 重ね/重ね攻め)が真因(調査 §0.3/§0.8)。
- 同一 6 BOOLEAN のラベルが **編集/詳細/比較で3系統不統一**、表示方式も相違(詳細=6行 / 比較=2行集約・shimmy 畳込・shimmy DR 表現不可 / 有利フレーム整形 生値 vs +nF)、表記揺れ「その場受け身」vs「中央受け身」。
- M12-03 で **ラベル統一 + 表示方式統一**を設計。表記正典は DES-003(「その場受け身」「重ね」)・DES-004。CHANGE 要否は DES-005 §5.6/§5.8 表示方式・DES-004 表記を view 確認のうえ確定。

### 4.2 C-12(M12-RESEARCH-01 で確定 → M12-03 で判断)
- `autoStarterMoveId` は category 非依存・全種別対応で **推定破綻 0 件**。手動プルダウン除去の category 面の安全性は確認済。
- ただし「**手動選択 ≠ レシピ先頭 move**」の乖離ケースが存在し、`starter_move_id` は重複判定キー。プルダウン除去でこの乖離表現が失われる是非を M12-03 で判断(domain 確認事項)。

### 4.3 個別明確化(開発者確定)
- **C-11**: ドライブダメージは **-6〜6・小数許容**(コンボ中に相手ドライブゲージが回復しうる/1本未満の増減が多い)。M12-03 着手時に DES-003 の drive_damage 列定義(型・範囲)を view 確認し CHANGE 要否を確定。
- **C-13**: 展開機構を無くし **最初から展開済み**(クリック遷移はそのまま)。
- **C-18**(方針転換 2026-06-22): 当初「ソート項目から相手スタンスを除去」だったが再検討の結果、**相手スタンスはフィルタに温存**(必要)。代わりに **C-19 同様、一覧項目にも相手スタンスを表示**する。ただしコンボは相手スタンス「不問」が多いため **控えめ表示**(目立たせない)。→ C-18 は M12-01 §4.2 の表示項目追加(C-19 と同 family)へ移す。
- **C-01**: 真意は「一覧以外から戻った時のフィルタ消失」解消(= N-30 同族)。保持手段は in-app ナビゲーション用(既存 `useSessionStorage` / React state)で、セッション跨ぎの恒久ブラウザストレージ(フェーズ3 送りの virtual-controller 系)とは別物。
- **N-29**: キャラクター選択のみ対象。6画面(一覧/新規登録/マイコンボ/コンボ比較追加ダイアログ/技マスタ編集/設定)一括。

### 4.4 据え置き(再協議不要)
- seed scope は据え置き確定(handover §3-b)。先行リリース3体は `scope` なし。
- custom_states 消費は非モデル化(notes 管理)。PATCH クリアは presence-detection 単一トライステート(CHANGE-043)。

## 開発者への確認事項

1. **M12-01 の分割方針**
   なぜ: M12-01 は 15 項目で、過大域に達する場合の内部分割は連番繰り下げ(M12-02 以降)を伴うため、custom コマンドの ID 安定性に影響する。
   暫定案: まず単一指示書での収まりを検証し、過大域(1000行超)に達した場合のみ「M12-01=表記」「M12-02=ソート/フィルタ+戻り保持」へ分割し、以降を繰り下げる。この方針でよいか(番号安定を優先して**最初から2分割**する選択肢もある)。

2. **code-facts の再生成タイミング**
   なぜ: 調査で code-facts ヘッダ(`3e0f4bf`)と HEAD(`2e64851`)の不一致が判明。M12 製造前に HEAD で再生成しておくと、各指示書 §3.4.1 の鮮度確認が安定する。
   暫定案: M12-01 製造投入前に `/regen_code_facts` を一度実施し、本書・各指示書の参照 commit を更新する。

3. **本 overview の投入可否と次の着手**
