## 1. 背景と目的

### 1.1 背景

- M12 先行リリース仕上げのうち、**正しさ(R-1 不具合)と表示項目・入力/検証**の系統。R-1 は先行リリースの妨げとなる不具合(必須残)。C-12/C-03/C-08/C-10/C-11 は使い勝手・正しさの改善。
- **R-1 の真因は M12-RESEARCH-01 で確定済み**(報告書 `docs/progress/M12-RESEARCH-01-report.md`):
  - 「中段化」は move `properties`(段)由来ではなく、**詳細(§5.6)の i18n ラベル誤訳「中段攻め」**(`oki_meaty_*` は meaty=重ね/重ね攻めであり中段ではない)。
  - 同一 6 BOOLEAN のラベルが **編集(「重ね」「中央受け身」)/詳細(「中段攻め」「DR」)/比較(良ラベル)で 3 系統不統一**。
  - 表示方式も相違(詳細=6 行個別、比較の**実装は 2 行集約で DES-005 §5.8 spec〔その場/後ろ受け身 × DR無/有 + シミー 2 行 = 6 BOOLEAN 表示〕とも乖離**)。
  - 表記揺れ「その場受け身」(詳細/比較・DES 正典)vs「中央受け身」(編集)。
- **C-12 の安全性も確定済み**: `autoStarterMoveId` は category 非依存・全 10 種別対応で推定破綻 0 件。`effectiveStarterMoveId = 手動 ?? 自動`。乖離は「手動選択 ≠ レシピ先頭 move」のときのみ(VAL-C03 が WARNING で既に検出)。
- C-11: `drive_damage` は現状 `*int` / DES-003 `INTEGER`。-6〜6・小数化は**スキーマ・モデル・検証・入力 UI の変更**を伴う(設計判断=§10)。

### 1.2 目的(6 関心)

- **R-1**: 起き攻め 6 BOOLEAN のラベルを **編集/詳細/比較で統一**(正典語彙 = 重ね/シミー・その場/後ろ受け身・ドライブラッシュ、DES-003 §3.x・DES-005 §5.8)し、誤訳「中段攻め」・略記「DR」・表記揺れ「中央受け身」を解消。**詳細と比較の表示方式を統一**(§10-3)。
- **C-12**: コンボ編集の始動技プルダウンを除去し、`starter_move_id` を自動推定(レシピ先頭)に一本化。二重入力を解消(§10-2)。
- **C-03**: セットプレイ名を必須化(現状任意)。
- **C-08**: 新規登録時のセットプレイ紐付け候補を `knockdown_advantage` 一致のもののみ表示(現状は候補が多すぎる)。
- **C-10**: `drive_damage` をコンボ詳細画面に表示(現状非表示)。
- **C-11**: `drive_damage` を -6〜6・小数許容の範囲入力に(スキーマ変更、§10-1)。

### 1.3 このマイルストーン(指示書)で作らないもの

- 表記・ソート/フィルタ・戻り保持(M12-01)/ フォーム/レイアウト誤操作(M12-02)/ キャラ選択方式統一(M12-04)。
- custom_states の消費モデル化(非モデル化確定)。
- 起き攻め 6 BOOLEAN の**意味・列構成の変更**(R-1 はラベル・表示方式の統一であり、列・データは不変)。
- C-06 の起き攻め以外の DR 表記(M12-01。起き攻めの DR は本サブの R-1 に含む)。

## 4. 詳細仕様

### 4.1 R-1 起き攻め表示の統一(ラベル + 表示方式)

- **ラベル統一**: 編集/詳細/比較の起き攻め 6 BOOLEAN ラベルを **正典語彙へ統一**:
  - 誤訳 **「中段攻め」→「重ね(攻め)」**(meaty。詳細 §5.6)。
  - 略記 **「DR」→「ドライブラッシュ」**(起き攻め区分。C-06 起き攻め分を含む)。
  - 表記揺れ **「中央受け身」→「その場受け身」**(編集 `OKI_FIELDS`。DES-003/§5.8 正典)。
  - シミーは「シミー」で統一。
- **表示方式統一**(§10-3 で確定): 詳細と比較で同一の起き攻め表示方式に揃える。**確定方向 = 両画面とも「重ね(その場受け身)DR無/有・重ね(後ろ受け身)DR無/有・シミー(その場受け身)・シミー(後ろ受け身)」の 6 項目を同一ラベル・同一レイアウト方針で表示**。有利フレーム(knockdown_advantage)整形も詳細/比較で統一。なお**実装後に開発者が表示細部を直接 Claude Code へ調整依頼する場合がある**(結果は設計担当へ展開・本指示書/DES へ反映)。
- **データ・列・意味は不変**(VAL-C11 整合検証も不変)。i18n とレンダリングの統一のみ。
- → **CHANGE 候補**: DES-005 §5.6(誤訳修正・表示方式)/ §5.8(実装を spec へ整合 or spec を実装へ追従、方向は §10-3)。`ja.json` の起き攻めラベルは i18n でラベル統一(en.json は変更しない=フェーズ3)。

### 4.2 C-12 始動技プルダウンの除去

- コンボ編集(§5.7 #4)の始動技選択プルダウンを**除去**し、`starter_move_id` を **`autoStarterMoveId`(レシピ先頭 move)に一本化**(§10-2 で確定)。FE は自動推定値を送る(またはレシピ先頭から導出)。
- 二重入力を解消。重複判定キー(VAL-C02)に効く `starter_move_id` は自動推定値で確定。
- **VAL-C03**(starter≠レシピ先頭 WARNING)は **BE バリデーションとして維持**(開発者確定 §10-2)。UI からプルダウンを除去し FE は自動推定値を送るため通常フローでは常時一致するが、**API 直叩き等の不正/異常リクエスト対策**として BE 検証を残す(プロジェクトの「サーバー側エラー応答 = API 単体使用時の防御」= DES-006 VAL-S05 補足と整合)。**DES-006 VAL-C03 は不変**。
- レシピ先頭が変わると starter も追従。レシピ空時の扱い(starter null)を確認。
- → **CHANGE 候補**: DES-005 §5.7(#4 始動技選択 UI の除去・自動推定化)。DES-006 は不変(VAL-C03 維持)。

### 4.3 C-03 セットプレイ名の必須化

- セットプレイ名(§5.9 #2、現状「任意」)を **必須**にする。`SetupBasicInfoForm` の name 入力 + 検証(新 **VAL-S06**: セットプレイ名が空でないか、ERROR)。
- フロント第一防衛線(必須 UI)+ BE service 検証(DES-006 §1.1 責任分担)。
- → **CHANGE 必須**: DES-006 §3(VAL-S06 新設)/ DES-005 §5.9(#2 任意→必須)。

### 4.4 C-08 セットプレイ紐付け候補の knockdown 一致フィルタ

- 新規登録時のセットプレイ紐付け候補(`SetupSelectorModal` 等)を、**`knockdown_advantage` が一致するもののみ**表示する(現状は候補過多)。
- §5.6 L271-274 の「転用可能なセットプレイ候補」(同一キャラ + knockdown 一致)と同じ絞り込み基準を、新規登録時の紐付け候補にも適用。
- → **CHANGE 候補**: DES-005 §5.7(item 10 紐付け候補の絞り込み)。

### 4.5 C-10 ドライブダメージの詳細表示

- コンボ詳細(§5.6)に `drive_damage` を表示する(現状非表示)。C-11 の表示形式(小数 -6〜6)に従う。
- → **CHANGE 候補**: DES-005 §5.6(表示項目に drive_damage 追加)。

### 4.6 C-11 ドライブダメージの -6〜6・小数化

- `drive_damage` を **-6〜6・小数許容**(相手ドライブゲージ削り量の本数。回復で負値、1 本未満の増減のため小数)に変更。
- **格納型**(§10-1 で確定): DES-003 `INTEGER`→`REAL`、model `DriveDamage *int`→`*float64`(開発者確定)。SQLite 型親和性を踏まえ非破壊マイグレーション(§3.4.3)。
- **検証**: 範囲 -6〜6(DES-006 に新 VAL。CHECK 制約は不使用 L394 = BE/UI 制約)。UI 入力は小数許容・範囲制限(既存ゲージ入力と異なり**負値・小数を許容**)。
- **表示**: 詳細(C-10)・編集(§5.7 #9)で小数表示。
- → **CHANGE 必須**: DES-003(drive_damage 型・値域)/ DES-006(範囲 VAL)/ DES-005 §5.7(#9 入力仕様)。

## 10. 確定した設計判断(開発者確定 2026-06-22)

> 当初「開発者への確認事項」だった 3 件は以下のとおり確定。本文(§4.1/§4.2/§4.6)に反映済み。

1. **C-11 drive_damage の格納型 = REAL / `*float64`**(確定)。SQLite 型親和性で既存 INTEGER 列に REAL も格納可のため非破壊。model を `*float64` 化、表示は小数で丸め。scaled int は不採用。
2. **C-12 始動技は自動推定一本化、ただし VAL-C03 は維持**(確定)。UI のプルダウンは除去し `starter_move_id` をレシピ先頭から自動確定するが、**VAL-C03 バリデーション自体は不正/異常リクエスト対策として BE に残す**(API 直叩き等の防御。DES-006 VAL-C03 不変、VAL-S05 補足の「API 単体使用時の防御」と整合)。手動始動技≠レシピ先頭の乖離表現は UI 上は廃止。
3. **R-1 表示方式 = 詳細/比較とも 6 BOOLEAN 同一ラベルで表示・DES-005 §5.8 spec へ整合**(確定)。**実装後に開発者が表示細部を直接 Claude Code へ調整依頼する場合がある**(結果は設計担当へ展開し、本指示書/DES へ反映)。
