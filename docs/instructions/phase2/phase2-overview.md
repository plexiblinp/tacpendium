## 1. 目的・位置づけ

フェーズ2 は「先行リリース準備」。到達点は次の状態。

- クラシック操作5体（リュウ / ケン / イングリッド / C.ヴァイパー / ダルシム）が、UI から登録・閲覧できる。
- moves が正式スキーマ（フレームデータ列を含む）でデータを保持し、公式データを取込パイプラインで投入できる。
- custom_states による開始時状態（電刃などの boolean 状態）をコンボに付与できる。

マイルストーン番号は **M8 以降の連番を継続**（フェーズ番号 1〜4 とマイルストーン番号 M0〜 は別軸）。フェーズ2 は **5 大マイルストーン（M8〜M12）** で構成し、各大マイルストーンは関心数・複雑度に応じてサブユニット（M{N}-{NN}）へ分割する（粒度は playbook のモデル運用基準に従う）。

> 本書は handover §3 の「順序ベース目安（M8〜M14 の7段）」を、関心数を抑える方針で **5 大MS（M8〜M12）に統合**した確定構成。handover §3 の M13（UX）・M14（seed 整理）は本書の M12（先行リリース仕上げ）に統合した。

---

## 2. スコープ

**フェーズ2 に含む**:

- moves フレームデータ基盤（スキーマ・取込・手動修正）。
- 公式データ取込パイプライン（FR701 別ツール → FR704 アプリ取込 → FR703 手動修正）。
- クラシック5体の登録 UI 解禁（ComboEditor のキャラ固定解消）。
- custom_states 開始時状態（boolean 中心）。
- 先行リリースの仕上げ（UX 修正・検証データ整理・統合 E2E・配布判定）。

**フェーズ2 に含まない（フェーズ3 以降）**:

- 英語ロケール整備（official 英語技名プリセットの新設・英語 UI）。
- custom_states の消費セマンティクスのモデル化（本フェーズは開始時状態の付与のみ。消費はコンボ notes で管理）。
- 他ゲーム対応（NFR407）等のフェーズ4 項目。

## 3. マイルストーン構成（M8〜M12）

| 大MS | 名称 | ゲート/依存 | CHANGE 見込み |
|------|------|------------|--------------|
| M8 | moves フレームデータ基盤 | フェーズ2 のゲート。後続が依存 | CHANGE-022 / CHANGE-023（反映済み） |
| M9 | 公式データ取込パイプライン | M8 完了が前提 | m9-overview で要否判断 |

### M8 — moves フレームデータ基盤（ゲート）

- 内容: moves スキーマに発生 / 持続 / 全体硬直 / 硬直差 / Dゲージ減少ガード / is_aerial / setup_only を追加し、FR704 CSV 契約・技名正規化規約・取込スコープを確定する。
- サブユニット:
  - **M8-01**: スキーマ移行（マイグレーション）。既存 seed のフレーム列 backfill / 一時デフォルト / seed 再生成のいずれかを製造担当が選択。`total` 算出式（開発者定義）を着手前確認。
  - **M8-02**（E2E 基盤・横断ワークストリーム、CHANGE-024）: Playwright 前倒し導入の基盤（`@playwright/test` + `playwright.config` + test-id 規約 + ローカル実行スクリプト + 高価値フローのスモーク/回帰 spec）。**moves ゲートの依存ではなく** M8 スキーマ確定後に並行導入。以降 M9〜M12 の機能追加に合わせ spec を漸進拡充。視覚/レスポンシブ/LAN/実機は手動 E2E 継続、CI は本フェーズ非構築。
- 状態: スキーマ設計は **CHANGE-022 / 023 + FR701 実データ訂正 CHANGE-025/026/027 反映済み**、M8-01 製造完了。E2E 基盤は **CHANGE-024 反映済み**、M8-02 製造はこれから。
- ゲート理由: 取込ツール・CSV 取込・登録 UI がすべて moves 構造に依存するため最初に固める。

### M9 — 公式データ取込パイプライン

- 内容: 公式 HTML → CSV → DB の取込パイプラインと手動修正を実装する。
- サブユニット:
  - **M9-RESEARCH**: 取込ツールの技術スタック選定と公式 HTML 構造の精査（SUPP-001 §4.3）。
  - **M9-01**: FR701 取込ツール（CSV 出力）。**別チャットの設計担当へ委任**（phase2-tool-delegation-brief-fr701-importer）。本体と並列で進行。
  - **M9-02**: FR704 アプリ側 CSV 取込（`/api/import/moves`、プレビュー + 行単位 upsert、total 算出、properties 検証）。
  - **M9-03**: FR703 手動修正（取込プレビューのグリッド編集、ラッシュ版生成、is_aerial 手動トグル、投げ並び順の例外補正）。
- 依存: M8 完了が前提。M9-01 は別チャットで並列、M9-02 は CSV 契約（DES-002 §7.5）に依存、M9-03 は M9-02 の取込結果に作用。
- CHANGE 見込み: 取込プレビュー / グリッド編集 / サイズ上限等の挙動を m9-overview で設計し、本体 UI（DES-005）への追記要否を判断。

### M10 — 複数キャラ登録 UI

- 内容: ComboEditor のリュウ固定を解消し、クラシック5体を登録対象にする。
- サブユニット（handover の A-1 / A-2 に対応）:
  - **M10-01（A-1）**: ComboEditor のキャラクター選択化。
  - **M10-02（A-2）**: リュウ固定に依存した UX の解消。
- 依存: M9 でクラシック5体のデータが投入された後に実用上必須（閲覧系は既に複数キャラ動的化済み、登録系のみフェーズ1 でリュウ固定）。

### M11 — custom_states 開始時状態

- 内容: 開始時状態（電刃などの boolean 状態）を custom_states でコンボに付与・表示・参照できるようにする。
- 方針: **boolean 中心**。状態の**消費（コンボ中でどう減るか等）はモデル化せず**、消費はコンボ notes で管理する（フェーズ2 のスコープを開始時状態の付与に限定）。
- 依存: M8 と独立に進行可能（moves 取込に依存しない）。
- CHANGE 見込み: 開始時状態の保持・参照が既存 DES（DES-003 §3.x の custom_states 定義）で表現できるかを M11 着手時に確認し、追記要否（DES-003 / DES-004 / DES-006）を判断。

### M12 — 先行リリース仕上げ

- 内容: 先行リリースに向けた UX・検証データ・配布の仕上げ。
- サブユニット:
  - **M12-01**: UX・正しさ修正（Memo 候補のバンドル）。
  - **M12-02（A-3）**: 検証データ / seed 整理。migration 000012 の耐久 seed 36 件を、無効化マイグレーションで除去（新規 DB 構築時に再投入されない状態にする）。
  - **M12-03**: 統合 E2E テスト + 先行リリース配布判定。
- **先行リリースの実施点**: M12 完了後（フェーズ2 全体の完了後）。

> - **M12-03**: 表示項目・入力/検証 + R-1/C-12 修正。

## 4. 依存関係（要約）

- **M8 がゲート**: M9 / M10 は M8 のスキーマ確定に依存。M8 設計は確定済み、残りは M8-01 の製造。
- **M9-01（FR701 ツール）は並列**: 別チャットで設計・製造。本体側 M9-02 は CSV 契約を介して疎結合。
- **M11 は準独立**: M8 のスキーマ確定後ならいつでも着手可（取込パイプラインに非依存）。M9 / M10 と並走できる。
- **M12 は最後**: UX 修正・seed 整理・統合 E2E・配布判定は他大MS の成果が揃ってから。

## 6. 先行リリースの判定（M12-03）

先行リリース配布の判定は M12-03 で行う。判定の観点（チェックリストは M12 設計時に具体化）:

- クラシック5体が UI から登録・閲覧できる（M9 / M10）。
- 公式データ取込パイプラインが動作し、5体分のデータが投入済み（M9）。
- custom_states 開始時状態が付与・表示できる（M11）。
- 耐久 seed が除去され、配布 DB がクリーンな初期状態（M12-02）。
- 統合 E2E が通過（M12-03）。
