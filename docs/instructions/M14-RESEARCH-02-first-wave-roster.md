## 0. この指示書の特殊性

### 0.1 調査だけ実施して閉じる運用

- 本セッションは §4 の事実列挙 → §5 レポート作成 → クローズ。第一波キャラの**最終決定は開発者**が行い、実装は M14-03b（別セッション・別指示書）が担う。

### 0.2 read-only 厳守

- view / grep / find / ls と、保持データの読み取りのみ。編集系・書き込み系は §5 レポートファイルの作成を唯一の例外とする。公式データ・repo・seed を一切変更しない。

### 0.3 判断の扱い（本調査の例外）

- 原則は事実列挙（judgement-free）。ただし本調査に限り、**§5-E「第一波候補案」の 1 節のみ**、§4 の事実に基づく候補提示を許可する（開発者決定 2026-07-09）。候補案は必ず「どの事実（§4 のどの行）がどの選定基準を満たすか」の根拠付きで書き、候補案以外の節に評価・推奨を混ぜない。

### 0.4 本調査の主目的

## 1. 背景と目的

### 1.1 背景

配布 seed（M14-03b）は手入力律速のため段階投入とする。第一波キャラは、単なる人気順・リリース順でなく、**seed インフラ・M17 command 解決・custom_states 表示など後続機能の検証面を最大化する特性**で選びたい。特性の一次情報（各技のコマンド種別・状態の有無・ターゲットコンボの実在）は公式データにあり、それを保持する本担当が最短で調査できる。

### 1.2 目的

- §4 の各軸を保持データの実査で確認し、§5 の様式で `M14-RESEARCH-02-report.md` として報告する。

### 1.3 この調査でやらないこと

- 第一波の最終決定（候補案の提示まで。決定は開発者）。
- seed SQL・変換系・マイグレの作成（M14-03b）。
- 公式データ・repo・DES/REQ の変更。

## 4. 調査項目（事実列挙）

### 4.1 軸A: キャラ別特性マトリクス

全キャラについて、公式データから次を表で列挙する（1 キャラ 1 行）。

1. **溜めコマンド技の有無・件数**（M17 段階2 で「直接指定」に落ちる区分）。
2. **一回転（360）系コマンド技の有無・件数**（同上）。
3. **単方向＋ボタンの特殊技の件数**（M17 段階2 の決定論解決の主対象。例: 前＋中P 型）。
4. **空中特殊技・空中必殺技の有無・件数**（M17 で「直接指定」）。
5. **ターゲットコンボ相当（段数付き行）の有無・件数**（seed 契約 (d) の検証対象）。
6. **キャラ固有状態の種別**（ストック型 int／レベル型 int／フラグ型／インストール型・コンボ中に増減し得るか＝増える動作と減る（消費する）動作が公式データ上どちらも読み取れるか。seed 契約 (e)・show_delta 方向性の材料。とくに Mai/Lily/Juri/Kimberly は状態名・値域・増減の根拠行を明記）。
7. **通常投げの件数**（3 件以上のキャラは採番経路の検証対象）。
8. **同名・類似名の技の有無**（move_code `_2` フォールバック・dup スキャンの検証対象になり得る行）。
9. **技の総行数**（手入力コストの目安）。

### 4.2 軸B: seed 契約カバレッジ

- 軸A の 1〜8 を M14-03b の検証観点（target_combo passthrough／custom_states show_delta＋2 値／command 索引の多様性〔単方向・溜め・一回転・空中の全区分〕／`_2` フォールバック／投げ採番）へ対応付け、**各観点を踏めるキャラ集合**を列挙する（評価せず対応表のみ）。

### 4.3 軸C: テリー CSV の例外事項の類型化と横展開

- 手入力完成済みはテリー 1 キャラのみ（例外事項を複数抱えるため先行選定・開発者情報 2026-07-09）。本軸では、**テリーの手入力 CSV／入力ツール対応で表面化した例外事項を類型として列挙**し（例外の種類・該当行・ツール側でどう扱ったか）、**公式データ上で同種の例外を持つ他キャラを類型ごとに対応付ける**。第一波に「例外を意図的に踏むキャラ」と「例外の少ない量産しやすいキャラ」を配合する材料になる。テリー CSV が本環境から参照できない場合は、参照できない旨と公式データ側から推定できる例外類型のみを記録する。

### 4.4 軸D: M16-RESEARCH-01 の dup 測定軸

- M16-RESEARCH-01-report.md を参照できる場合、dup 実測（0 件）の**測定対象・測定キー・母集団**を原文の該当節付きで転記する（M14-03b の再測定が同軸で比較できるようにするため）。

## 6. 注意事項

- 公式データに無い情報（ゲーム内挙動の記憶・攻略知識）で表を埋めない。**データに行として存在する事実のみ**を書き、根拠（どのデータのどの行/見出しか）を添える。
- Mai/Lily/Juri/Kimberly の状態増減（§4.1-6）は M14-03b で開発者が show_delta を確定する直接材料になるため、根拠行の明記を最優先する。
