## 0. この指示書の特殊性

### 0.1 ★★★本サブは「実査して記録する」ものであり、直すサブではない

**★★`A6` の 3 件は、設計卓が実装を読めないため断定していない**（`D-653`）**。⇒ 本サブが最初に読む。**

**★★★見つけた不足をその場で直すかは、実査の結果で決まる。⇒ 直す前に、何が無いかを先に全部並べること。★「1 件見つけて直して終わり」にしないこと。**

### 0.2 ★★シークレット走査は「プライベートのうちに」やる

**★★★開発者の逐語**（2026-09-02）**＝「〇〇を消したというログを残してしまう可能性があるので、正式なマイルストーンにもせずプライベートのうちに実施」。**

**★★したがって本サブが用意するのは走査の手順と許可リストであり、実行と是正は開発者の手番である**（`M26-overview` §3 の注記）**。**

**⇒ 製造は走査を「回して結果を報告する」ところまでやってよいが、検出物の削除は開発者へ返すこと。★削除は履歴に残る。**

**★★★【2026-09-10 決着＝`D-807`】`secret-scan-before-release` は本サブで実施する**（開発者の逐語＝「Secret-scan-before-release は M26-04 で実施」）**。⇒ 別サブを立てない。**

### 0.3 ★★許可リストは `M26-02` の成果を使う

**★★`M26-02` が公開スナップショットの許可リストを作っている。⇒ 本サブはそれを母集団として走査する。**

**★★★除外されるものも走査すること。⇒ 公開されないファイルにシークレットが在っても、開発リポの履歴には残る。★「公開しないから安全」ではない。**

### 0.4 ★★外部へ投げてよい問いは 1 本だけである

**★`M26-overview` §7 が定めている＝Gitleaks と betterleaks のどちらを使うかだけは最新事情に依存する。⇒ `/ask_external_ai` で 1 本だけ確認する。**

**★★それ以外は外部に投げないこと。⇒ 本リポジトリの内容を外部サービスへ渡さない。**

## 4. 危険な箇所

### 4.1 ★★★「設計書にそう書いてある」を実装の証拠と読むこと

**⇒ `A6` の 3 件はまさにそれを疑っている。★`DES-002` §8 に「強く推奨します」と書いてあることは、警告が実装されている証拠にならない。**

### 4.2 ★★★走査を「回した」を「安全である」と読むこと

**⇒ 道具は既知のパターンしか見ない。★検出 0 件は「パターンに当たるものが無い」であって「シークレットが無い」ではない。⇒ 報告にはそう書くこと。**

### 4.3 ★★除外されたファイルを走査から落とすこと

**⇒ 公開されなくても、開発リポの履歴には残る。★`M26-02` の除外規則は「公開しない」であって「無い」ではない。**

### 4.4 ★★`A2` と SCANOSS を混ぜること

**⇒ 別物である**（`A2` は依存の license、SCANOSS はコード片の由来）**。★混ぜると、どちらかが実質未実施になる。**
