## 4. ★★危険（**先に読むこと**）

### 4.1 ★★最大の危険＝三点のうち 1 つを落とすこと

**★★`move_code` は `preset_aliases` の解決キーである**（`DES-004` §2.1 の警告）**。⇒ CSV だけ直すと、既存 DB の別名が古い `code` を指したまま残る。**

**★★golden を再生成しないと、`TestGolden_*MatchesRegeneration` が赤になる。⇒ そこで気づけるが、気づく前にマイグレを書くと手戻りする。⇒ 順序は CSV → golden → マイグレ。**

### 4.2 ★★2 番目＝ライセンスの層

**★`ryu` の技名は SF6 の事実である。⇒ 層 B である。★ファイル名に `_data_` を入れないと層 A へ静かに落ちる。⇒ 誰も赤くならない。**

**★`bash scripts/check-migration-license.sh` を回して層 B と判定されることを確かめること。**

### 4.3 ★3 番目＝件数で固定すること

**★`SUPP-001` §5.5.4 (6)＝「三点更新を採ったら、追随マイグレを件数で固定しない」。⇒ `UPDATE ... WHERE move_code = 'axe_kick_2'` の影響行数をテストで固定しないこと。**

### 4.4 ★4 番目＝陽性対照を採らないこと

**★「直った」を示すには、直す前に「壊れている」ことを実測しておく必要がある。⇒ 後だけ見ると、もともと動いていたのか分からない。**
