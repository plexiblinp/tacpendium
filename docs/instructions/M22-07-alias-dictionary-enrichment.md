## 4. 詳細仕様

### 4.1 増やす前に測る

| # | 内容 |
|---|---|
| 1 | **★増やす行を決める前に、「いま何が解決できていないか」を実測する。** **これが基準値になる** |
| 2 | **★測るのは `M20-07` が作った逆引きの実装そのものである**（`SUPP-001` §5.5 (11″)）。**自作の近似で数えない** |
| 3 | **★母集合を明記する**——**何を入力集合として測ったか**（技名 ／ 既存エイリアス ／ 想定される利用者の表記）。**「何を・どの単位で・どの基準時点で数えたか」を併記する**（`E-93` / `E-16`） |
| 4 | **★測れないなら、測れない理由を報告して止まる**（§9.3-3）。**「測らずに増やす」は本サブの目的そのものに反する** |

### 4.2 増やす対象は 2 種類に分かれる

| 種別 | 例 | 誰が値を出すか |
|---|---|---|
| **(a) 機械的に導ける別名** | **SA 番号**（`SA1` / `SA2` / `SA3`）——**`moves` の属性や `move_code` の構造から導ける見込み** | **★製造が実測して全数を列挙し、規則で導く** |
| **(b) ドメイン知識が要る別名** | **キャラ通称**（「ライズ」「フレア」等） | **★開発者。設計卓が受けて値を決める** |

**★(a) と (b) を混ぜない。** **(b) は本サブでは投入しない**——**値を持っていないため。** **⇒ (b) の候補を全数列挙して報告し、設計卓へ渡すこと**（**`P-34` と同じ形**＝**列挙は製造、値決めは設計卓・開発者**）。

**★(a) についても「導ける」は仮説である。** **§3.3-4 の実査で導けないと分かったら、(b) 側へ回して報告すること。**

### 4.3 増やしても既存の答えを変えない

| # | 内容 |
|---|---|
| 1 | **★「新たに解決する」だけを行う。** **既に解決していた入力の答えを変えない** |
| 2 | **★これは `M21-06` の `D-381` で受理された形と同じである**——**(a) 答えが変わった入力 0 ／ (b) 解決しなくなった入力 0 ／ (c) 新たに解決した入力 N**。**この 3 つを件数で報告すること** |
| 3 | **★(a) か (b) が 0 でない場合は、止めて報告する**（§9.3-4）。**「良くなったから」で進めない**——**利用者のレシピの表示が変わる** |
| 4 | **★衝突組は両方落とす**（`DES-004` §5.5）。**⇒ 増やした行が既存と衝突すると、既存まで解決しなくなる。** **これが (b) が 0 でなくなる主な経路である** |

## 4.9 否定形確認（撤回した仕様の残骸の全文走査）
