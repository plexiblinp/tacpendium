## 4. 危険（**★起きやすい順**）

### 4.1 ★★★最大の危険＝**緑にすることを目的にしてしまう**

**★141 本と 17 本は、消せば緑になる。⇒ そして誰も気づかない。**

**★★★主張を捨てたかどうかは、分類の内訳でしか見えない。⇒ 消した本数と書き直した本数を必ず分けて報告すること。**

**★★「141 本を処理した」は報告ではない。⇒ 何本消し、何本書き直し、何本諮ったかが要る。**

### 4.2 ★★2 番目＝**生きた誤参照を「直った」と誤認すること**

**★`000007` を指す 4 箇所は、*エラーにならない*。⇒ 指す先が存在するからである。**

**★★★機械では捕まらない。⇒ 段 1-1 で名指しして直すこと。★`grep` で「`000007`」を数えても、正しい用法と誤参照が混ざる。**

### 4.3 ★★3 番目＝**移行手順を「テーブルごとの `INSERT`」で作ること**

**★`combos` / `tags` / `setups` の外部キーと `sqlite_sequence` を同時に運ばないと、投入順で FK 違反になる**（`M33-overview` §4.3）**。**

**★★乾式で通ったことを出力で示すこと。⇒ 「こう書けば動く」で終えない。**

### 4.4 ★★ガードを「直した」で満足すること

**★`M33-02` の教訓＝破壊確認は「赤になったか」ではなく「*どの規則が*赤にしたか」まで見る。⇒ 規則 (3)**〔凍結表と食い違う〕**が赤くしたのを、規則 (4) が効いたと読んだ実例が在る。**

**★★★塞いだなら「塞ぐ前の形で赤くなること」を、塞がなかったなら「いまも緑で通ること」を、どちらも出力で示すこと。**

### 4.5 ★`code-facts` を再生成して「新しくなった」で終えること

**★再生成は差分を作るだけである。⇒ 差分の中に*誤り*が無いかは別に見る。★とくに §10 はマイグレの面であり、本サブで大きく動く。**
