## 1. 目的・位置づけ

**M22 は「LAN の中で複数人が同じデータを触っても壊れない」ことを作るマイルストーンである。**

**性格**——

- **★横断関心事である。** **全 API に薄く触る**（`parallel-ops` §12）。**⇒ 単独直列を既定とし、面が交差しないサブ 2 本だけを worktree 並列に置く**（契約 §3.3）。
- **★既存の実装が想定より進んでいる。** **`combos.version` / `setups.version` と、更新系 DTO の `version` フィールドは実在する**（契約 §1.4）。**⇒ 楽観排他は「作る」ではなく「効かせる／粒度を決める」である。**
- **★スキーマ変更は未確定。** **要否は `M22-RESEARCH-01` の実測を見てから決める**（契約 §4.2）。**「列を足さない」という結論もありうる。**
- **★セキュリティ方式は開発者の承認事項。** **設計卓は選択肢とトレードオフを整理するところまで**（`CLAUDE.md` §10 ／ **D-386 (4)**）。

**達成目標**——

1. **一人で使うときは、いままでどおり何も増えない**（`FR502`）。
2. **複数人で使うとき、誰かの編集を黙って消さない**（`FR501` ／ `FR406`）。
3. **消さなかったことが利用者に分かる**（競合したときの見せ方）。
4. **スマートフォンからの接続が QR で始められる**（`FR407`）。
5. **設定変更系の API が、意図しない出所から叩かれない**（`F12-8` ／ CORS/CSRF）。
6. **取込の別名辞書が、実測に基づいて増えている**（`G-14b` の残り半分）。

**★達成目標に含めないもの**——**権限管理・監査ログ・所有者の付与**。**`FR013`（必須・フェーズ1）が「コンボ・セットプレイは作成者の概念を持たない」「監査ログは実装しない」と定めており、M22 はこれを変えない**（契約 F-1）。

**次マイルストーンとの依存**——**M23（データバージョン管理）とは順序依存がある見込み**：**ゴミ箱・復元は「誰が消したか」を持たない**（`FR013`）**ため認証に依存しないが、競合検出の粒度（§4.2）が確定してから設計するほうが安い。** **M21-07 とは面が交差しない**（契約 F-4）。

## 4. 主要設計判断・調査結果の反映

### 4.1 ★「認証はあるが所有者は無い」——`FR013` との関係

**`REQ-001` FR013（必須・フェーズ1）が既に定めている。**

> コンボ・セットプレイは作成者の概念を持たず、ローカルネットワーク内の全ユーザーが等しく閲覧・編集・削除できる。（…）**監査ログ（誰がいつ編集したか）は実装しない**：ゴミ箱機能（FR601）で誤訂正に対処できるため、匿名運用で十分と判断する

**⇒ 開発者裁定 D-386 (3)「所有者を持たせない」は、新しい判断ではなく既存の必須要件の確認である。**

**帰結を書き出す**（playbook §4.11）——

| # | 帰結 |
|---|---|
| 1 | **`combos` / `setups` へ `user_id` を足さない。** ⇒ **既存データの移行は発生しない** |
| 2 | **ログインは「誰が入っているか」を示すだけで、できることは変わらない** |
| 3 | **★`FR013` は「タグ・プリセットは作成者のみ編集・削除可能（他ユーザーは参照のみ）」と書いている。** **`tags.user_id` は NOT NULL、`presets.user_id` は nullable で実在する**（`code-facts` §10）。**⇒ 認証を入れると、この従来方針が初めて実効化しうる。** **★実効化するかどうかは M22 の設計判断であり、確認事項 3 で開発者へ回す** |

### 4.4.1 ★開発者の手動確認が要るサブと、要らないサブ（**2026-08-15 確定**＝**D-398**）

### 5.2 ★指示書を連番順に作らない場合の理由

**本 overview の承認後、`M22-RESEARCH-01` の三点セットを先に発行する。** **`M22-01` 以降の指示書は RESEARCH の結果を待つ。**

>
> **★成立した理由は 2 つある。** **(1) どちらも認証の方式に依存しない**（上記）。**(2) どちらも実装の事実に触れる箇所を §3.3 の着手前実査へ送ってあり、RESEARCH の結果を先取りしていない。** **⇒ RESEARCH の結果で指示書を書き直す必要は生じない見込みである**（**★`M22-06` §3.3-1 は `M22-RESEARCH-01` レポート §6 を起点にすると書いてあるが、これは「レポートが在れば使う」であって依存ではない**）。
