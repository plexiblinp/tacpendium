## 0. この指示書の特殊性

### 0.1 ★★3 件だが、直す面は 2 つある

**DB を直すだけでは足りない。⇒ `character_data/*.csv` も直すこと。**

**★先例がある**——**`startup_basis` / `chain_cancel_total` / `fastest_unreachable` は `seedgen` が SQL へ出力しないため golden が守らず、DB だけが進んでいる**（`followup` `csv-db-frame-cost-columns-drift`）。**★本サブは逆向きの同型である**——**CSV を直さずに DB だけ直すと、次の seed 再生成で元へ戻る。★戻ったことはエラーにならない。**

### 0.2 ★なぜ「ついで」で直せなくなったか

**★`P-17` は 2026-08-02 に起票され、「開発者の全キャラ点検の完了を待って独立サブとする」としていた。⇒ `D-161` で全点検を行わない方針が確定した時点で待つ理由は消えていたが、以後 1 か月どのサブにも割り付かなかった**（`D-723`）。

**★★2026-09-05 に `character_data` の投入が完了したため、「何かのついでに」という窓そのものが無くなった**（開発者の逐語）。**⇒ 単独の運び手が要る。**

### 0.3 ★★なぜ `M28` か

**`move_code` のリネームは配布 DB の識別子が変わる。⇒ 「破壊的変更の窓」の族である**（`checklist` §4）。

**★公開後に変えると利用者のデータに影響しうる。⇒ 公開前が安い**（`D-725`）。

### 0.4 ★code のリネームは id 参照を壊さない

**`combo_steps.move_id` ／ `preset_aliases.move_id` ／ `move_derivations` ／ `combos.starter_move_id` は、いずれも `moves.id` を参照している**（`DES-003`）。**⇒ `moves.code` を書き換えても紐付きは切れない。**

**★危ないのは「code を文字列で名指ししている箇所」だけである**（§2.3）。
