## 1. 背景と目的

### 1.1 背景

**開発者が 2026-08-14 に再現を確認した欠陥である**（ボード **D-383** ／ followup `physical-input-active-while-modal-open`）。

| # | 観測された事実 |
|---|---|
| 1 | **修飾情報の編集ダイアログを表示中に物理入力を行うと、モーダルの裏でレシピにステップが入る**（**キーボード・コントローラとも**） |
| 2 | **★ダイアログのメモ欄にフォーカスがあると、キーボードは裏へ流れないが、コントローラは流れる** |

**★(2) の非対称が原因の所在を示している。** `DES-005` §6.5.1 (1) の編集可能ガードは **DOM のフォーカスを見るもの**であり、**キーボード経路にしか存在しえない**。**Gamepad は DOM のフォーカスを経由しないため、同じガードが構造的に掛からない。**

**⇒ 必要なのは「モーダルが開いている間」という別の軸である。**

**★現行の設計書はこの軸を持っていない。** 破られている節は 1 つも無い——

- **§6.5.1 (1)** は「編集可能な要素にフォーカスがある間は発火しない」だが、**ボタン・セレクトは編集可能ではないため対象外**である。
- **§6.4.3 項目 5** は「入力面が 1 つも表示されていない間はポーリングを回さない」だが、**モーダルが開いても入力面は表示されたままである**（裏に居るだけ）。

**⇒ 本サブは「実装の修正」ではなく「定めが無かったところに定めを置く」作業である**（`CHANGE-105`）。

### 1.2 目的

完了時に、次の状態が達成されている。

1. **モーダルが開いている間、物理入力（Gamepad ／ キーボード）は受け手の面の状態を変えない。** 技ステップも操作（削除・保存・修飾トグル・モードの出入り）も起きない。
2. **その軸は 1 か所にだけ存在する。** 供給元ごとに置かれていない。
3. **モーダルを閉じたあと、押しっぱなしのボタン・キーが「押されたまま」になっていない。**
4. **モーダルを閉じた瞬間に、開いている間の入力がまとめて入らない。**
5. **コマンド技入力モード中にモーダルが開いても、方向列が溜まらない。**
6. **モーダルでない重なり**（トースト・ツールチップ等）**では、従来どおり入力が効く。**

## 4. 詳細仕様

### 4.1 軸は 1 つだけ、合流層または受け手の側に置く

**★これが本サブの最重要要件である。**

| # | 内容 |
|---|---|
| 1 | **「モーダルが開いている間」という条件を、供給元（Gamepad の rAF ループ ／ キーボードの `KeyboardEvent` ハンドラ）ごとに置かない。** **合流したあとの 1 か所に置く** |
| 2 | **★理由**——**供給元ごとに置くと、次の供給元を足したサブで同じ穴がもう一度開く。** **`M21-05` が 2 つ目の供給元を、`M21-06` がモードを足した時点で、既に 2 度この形を通っている** |
| 3 | **★これは `DES-005` §6.4.3 項目 4′ が「1 個なのは受け手・判定・配送であって供給元ではない」と書き分けた形と同じである。** **同じ場所に同じ理由で置く** |
| 4 | **★置き場所の候補が 2 つ以上ある場合は、Plan Mode で選択肢と根拠を提示すること。** 実装が独断で選んでよいのは、**実査の結果 1 か所しか成立しない場合だけ**である |

### 4.2 観測は止めない。作用だけを止める

| # | 内容 |
|---|---|
| 1 | **押下・解放の追従は、モーダルが開いている間も続ける** |
| 2 | **★止めると、モーダルが開いた瞬間に押されていたボタン・キーの解放を観測できず、閉じたあとに「押されたまま」が残る** |
| 3 | **★これは `DES-005` §6.5.1 (1) 項目 3 と同型の失敗である**——同項は「解放のイベントはガードを通さない。通すと、押下中にフォーカスが編集欄へ移ったとき解放が捨てられ、そのキーが恒久的に『押されたまま』になる」と定めている。**本サブの軸でも同じことが起きうる** |
| 4 | **★症状は「押していないのに入り続ける」であり、原因がモーダルにあると分からない。** ⇒ **§5.1 の契約テストで固定する** |

### 4.3 溜めない

| # | 内容 |
|---|---|
| 1 | **モーダルが開いている間の入力を保持しておき、閉じた瞬間にまとめて流す形は採らない** |
| 2 | **★理由**——**利用者から見ると「ダイアログを閉じたら知らないステップが増えた」になる。** **原因を言語化できない形の壊れ方である** |
| 3 | **モーダルが開いている間に始まり、閉じたあとに終わる入力（開く前から押しっぱなし等）の扱いは、`§4.2` の観測継続と矛盾しない形で決めること。** **★Plan Mode で方針を提示すること** |

### 4.4 コマンド技入力モード（`DES-005` §6.4.4）

| # | 内容 |
|---|---|
| 1 | **モード中にモーダルが開いたら、方向列を溜めない** |
| 2 | **★モードから強制的に出すかどうかは as-built で決めてよい。** **ただし選んだ側の理由を完了報告に書くこと** |
| 3 | **★強制退出を選ぶ場合の注意**——**利用者が意図せずモードを失う。** **「入る条件」と「出る条件」は別物であり、可用性の条件を出口にも掛けると閉じ込め／意図しない退出のどちらかになる**（playbook §4.4.1） |
| 4 | **モードの出入りそのものも操作の 1 つである**（§6.5 の弱K）。**⇒ モーダルが開いている間は、モードの出入りも起きない** |

### 4.5 対象は「モーダル」であって「重なり」ではない

| # | 内容 |
|---|---|
| 1 | **★守りたい不変条件は「利用者の注意と入力が別の面へ向いている間、レシピは変わらない」である** |
| 2 | **★この不変条件が成り立つときに観測される形（特定のセレクタ・属性値）を、要件として書かない**（**D-380**。**形で書くと、別の理由で形が違うだけの正しい実装を止める**） |
| 3 | **⇒ 判定の手段は §3.3-3 の実査で決める。** **決めた手段と、その手段が「モーダルでない重なり」を拾わないことの確認を、完了報告に書くこと** |
| 4 | **★抑止が広すぎる形は、利用者からは「たまに入力が効かない」としか見えない。** **狭すぎる形は今回の欠陥がそのまま残る。** **どちらも実機でしか分からないため、DoD に開発者の実機確認を置く**（§7） |

### 4.6 既存の名指しの抑止を畳むか

| # | 内容 |
|---|---|
| 1 | **現行の抑止条件のうち「キー登録ダイアログを開いているか」は、特定のモーダルの名指しである**（§3.3-1 で実査する） |
| 2 | **★一般の軸が入るなら、名指しは重複になりうる**（`E-76`＝同じ情報を 2 か所に持つと必ずドリフトする） |
| 3 | **★ただし単純な包含関係ではない**——**キー登録ダイアログは「押されたキーを捕まえる」という固有の要求を持ち、他のモーダルとは求めるものが違う** |
| 4 | **⇒ 畳めるかを実査し、畳める／畳めないの判断と理由を Plan Mode で提示すること。** **★どちらでもよい。決めずに両方残すことだけを避ける** |

2. **行を跨ぐ文脈（`-A1 -B1`）またはファイル単位（`grep -rl`）でも回す。**
3. **数値で書かれた実測値は、数値のパターンでも探す。**
4. **★陽性対照を 1 つ混ぜる**——**当たるはずの既知の 1 件が拾えることを確かめる。** **「0 件だった」は「無い」ではなく「走査が壊れている」かもしれない。**
5. **★当たったファイルは全文を目で見る。** 走査が当たることと、当たった結果を正しく仕分けることは別の技能である。
6. **走査コマンドそのものを完了報告へ残す**（件数だけでは数え方が再現できない）。

## 5. テスト要件

### 5.1 必須テスト（Vitest）

**★本サブの中核は「破壊確認」である**（`SUPP-001` §5.5 (10′)）。

| # | 確認項目 | 破壊確認 |
|---|---|---|
| 1 | **モーダルが開いている間、技ステップが受け手の面へ配送されない** | **軸を外すと赤くなること。** **★赤くならなかったら「テストが弱い」より先に「別の機構が代わりに守っている」を疑い、特定して同じ層に置き直す** |
| 2 | **モーダルが開いている間、操作（削除・保存・修飾トグル・モードの出入り）が起きない** | 同上。**★4 操作すべてについて確かめる**——**1 つだけ通っていても他が漏れる** |
| 3 | **★モーダルが開いている間も、押下・解放の追従は続く** | **モーダルを開く → 押す → 閉じる → 離す** の順で、**閉じたあとに「押されたまま」が残らないこと。** **★この項目が本サブで最も落としやすい** |
| 4 | **★閉じた瞬間に、開いている間の入力がまとめて入らない** | **モーダルを開く → 複数回押す → 閉じる** で、**ステップが 1 つも増えないこと** |
| 5 | **モーダルでない重なりでは、従来どおり配送される**（**★対照実験**） | **★これが無いと、全部を抑止していてもテストは緑になる**（`SUPP-001` §5.5 (10′)） |
| 6 | **コマンド技入力モード中にモーダルが開いても、方向列が溜まらない** | 軸を外すと赤くなること |
| 7 | **★軸が 1 か所にしか無いこと** | **供給元ごとの分岐が生えていないことを、テストまたは静的な確認で固定する。** **★形で固定しない**——**守りたいのは「供給元を足しても穴が開かない」という性質である。** ⇒ **「新しい供給元を模した入力を合流層へ渡すと、モーダル中は同じく抑止される」という形が素直** |

### 5.2 E2E シナリオ（Playwright）

**新規 spec の作法は `/add_e2e_spec` に従う。** **★資源ごとに 1 ファイルへ寄せる**（followup `e2e-shared-global-resource-parallel` ／ **D-362**）。

| シナリオ | 手順 | 期待 |
|---|---|---|
| **A: モーダルの裏でステップが入らない**（キーボード） | レシピ入力面を開く → 修飾情報の編集ダイアログを開く → **ダイアログ内のボタンにフォーカスを当てた状態で**技キーを押す → ダイアログを閉じる | **ステップ数が変わらない** |
| **B: 対照 — モーダルを閉じていれば従来どおり入る** | 同じ画面・同じキーで、**ダイアログを開かずに**押す | **ステップが増える** |
| **C: 閉じたあとに押しっぱなしが残らない** | ダイアログを開く → 技キーを押しっぱなしにする → ダイアログを閉じる → キーを離す | **閉じたあとにステップが増えない。かつ、その後の通常入力が正しく効く** |

> **★A と B は 1 組である。** **A だけを見ると、全部を抑止していても緑になる。**
>
> **★E2E の「押しっぱなし」は、イベントが 1 回しか飛ばない書き方になりやすい**（`M21-05` の実測）。**リピートを模す必要があるなら、その旨と実現方法を完了報告に書くこと。**
