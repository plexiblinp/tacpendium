## 1. 背景と目的

### 1.1 背景

**M20-02 が `numeric` 1,245 行 / `srk` 1,260 行を投入した。本サブはそこへ一意制約を張る。**

**★当初の前提は M20-02 の実測で崩れ、2026-08-13 に設計し直した**（**D-343** → **D-344**）。

| # | 測ったもの | 実測（M20-02 完了報告 §1-7） |
|---|---|---|
| 1 | `(preset_id, alias_text)` の重複キー | `official_ja_move` 60 ／ `numeric` 124 ／ `srk` 125 |
| 2 | `(character_id, alias_text)` の重複キー | **714** |
| 3 | **同一キャラ内で 2 つの「別の技」が同表記**（`count(DISTINCT moves.code) > 1`） | **全プリセットとも 0 件** |
| 4 | `alias_text_en` の重複 と `alias_text` との交差 | どちらも **0 件** |

**★#2 の 714 は「同じ技が、複数のプリセットで同じ表記になっている」件数である。**

```
preset=numeric, character=ryu, alias_text='236LP'  → move=hadoken_light
preset=srk,     character=ryu, alias_text='236LP'  → move=hadoken_light
```

**`srk` は `numeric` の機械変換ではなく、通常技だけ接頭辞が変わり**（`5`→`st.` / `2`→`cr.`）**必殺技は数字のままである。** **⇒ 必殺技・SA が 2 プリセットで同値になる。**

**★守りたい不変条件は #3 である**——**「同一キャラ内で 2 つの異なる技が同表記にならない」。** **714 は無害な重複である**（同じ技を指しているため、逆引き `SELECT DISTINCT m.code` は 1 件に畳む）。

**★鍵に `preset_id` を入れると、714 の重複は消える。** **重複はすべてプリセットを跨いで発生しているためである。** **残る違反は #3 だけで、実測 0 件。**

### 1.2 目的

1. **`preset_aliases` へ `character_id` を非正規化で持つ**（`moves` からの backfill）
2. **`UNIQUE(preset_id, character_id, alias_text)` を張る**（§4.2）
3. **部分インデックス `UNIQUE(preset_id, character_id, alias_text_en) WHERE alias_text_en IS NOT NULL` を張る**（§4.3）
4. **DB で守れない「交差」を検査で守る**（§4.4）
5. **生成器が `character_id` を出すようにする**（§4.5）

## 4. 詳細仕様

### 4.1 `character_id` の追加と backfill

| # | 仕様 |
|---|------|
| 1 | **`preset_aliases` へ `character_id INTEGER` を追加する。** **`moves.character_id` からの非正規化である**（**複製であって移動ではない。`moves` 側は触らない**） |
| 2 | **既存の全行を backfill する**——`UPDATE preset_aliases SET character_id = (SELECT m.character_id FROM moves m WHERE m.id = preset_aliases.move_id)` **相当**。**★backfill 後に NULL が 0 件であることを確認し、件数を報告すること** |
| 3 | **★`NOT NULL` にするかを §3.3-4 の実査で決めて報告すること。** **設計卓の見込みは「できるなら `NOT NULL`、テーブル再構築が要るなら nullable のまま ＋ テストで NULL 0 件を固定」。** **覆ってよい。覆ったら理由を書く**——**★再構築の risk が費用に見合うかは、参照側の実物を見ないと判断できない** |
| 4 | **FK を張るかを決めて報告すること。** **設計卓の見込みは「張らない」**——**`move_id` の FK が既にあり、`character_id` はその推移的な複製であるため。** **覆ってよい** |
| 5 | **down は追加した列を落とす。** **★`SUPP-001` §5.5.2 (5)「down は up の反転ではない」に注意し、`moves` 側へ影響しないことを確認する** |

### 4.2 UNIQUE 本体

```
UNIQUE(preset_id, character_id, alias_text)
```

**★これが守りたい不変条件そのものである**——**「同一プリセット・同一キャラで、2 つの異なる技が同じ表記を持たない」。**

| # | 仕様 |
|---|------|
| 1 | **現状の違反は 0 件である**（§3.3-2 で再確認する） |
| 2 | **★`(character_id, alias_text)` に張ってはならない。** **714 件に当たって落ちる。** **714 はプリセットを跨いだ重複であり、`preset_id` を鍵に入れることで正しく分離される** |
| 3 | **★既存の `UNIQUE(preset_id, move_id)` は残す。** **意味が違う**——**同じ技に同じプリセットで 2 つのエイリアスを持たせない**（1 技 1 表記）。**本サブの制約は「2 技が同表記にならない」であり、逆向きである** |

### 4.3 `alias_text_en` の部分インデックス

```
UNIQUE(preset_id, character_id, alias_text_en) WHERE alias_text_en IS NOT NULL
```

| # | 仕様 |
|---|------|
| 1 | **部分インデックスにする。** **`alias_text_en` は NULL が大半である**（`DES-004` §5.3。**値が入っているのは移動系 2 code のみ・76 行**）。**SQLite は NULL を互いに異なるものとして扱うため実害は無いが、意図を明示するために `WHERE` 句を書く** |
| 2 | **現状の違反は 0 件である**（M20-02 完了報告 §1-7 の #4） |
| 3 | **★`P-34` の 27 件が将来投入されると `alias_text_en` が増える。** **そのとき本制約が効いてくる** |

### 4.4 DB では守れないもの（★検査で守る）

**「ある技の `alias_text` が、別の技の `alias_text_en` と一致する」交差は、列を跨ぐ条件であるため UNIQUE では表現できない**（**D-317** が想定した形）。

| # | 仕様 |
|---|------|
| 1 | **交差の検査をテストで固定する**——**同一 `(preset_id, character_id)` の中で、ある行の `alias_text` が別の行の `alias_text_en` と一致しないこと。** **現状 0 件**（§3.3-2 で再確認） |
| 2 | **★`DES-004` §5 へ「投入は生成器を通す」を規約として書く必要がある**——**制約は DB で守るが、交差は守れないため。** **★これは設計卓の手番である**（`CHANGE-100`）。**製造は §3.3-6 の実査結果を報告するに留める** |

### 4.5 生成器の追随

**M20-02 の生成器が `preset_aliases` へ INSERT している。** **`character_id` を出力へ追加すること**（§3.3-5）。

**★出さないと、`NOT NULL` を採った場合は落ち、nullable の場合は NULL 行が入って制約をすり抜ける。** **後者のほうが危険である**（**落ちないため気づけない**）。

**⇒ 生成器のテストで「出力に `character_id` が入っていること」を固定すること。**

### 4.6 既存テストの追随

**`preset_aliases` のスキーマを固定しているテスト資産が実在するなら追随する。** **無ければ「無い」と書く**（`E-84`）。

| # | 撤回・変更した定義 | 走査キーワード | 何が残っていたら残骸か |

| 2 | **「`alias_text` の一意制約は無い」の記述** | `一意制約は無い` ／ `一意制約なし` | **`DES-003` §3.9 の該当記述は `CHANGE-100` が更新する**（**設計卓の手番**）。**★製造は設計書を触らない。** **実装コード・テスト内のコメントが対象** |
