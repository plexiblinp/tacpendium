## 1. 背景と目的

### 1.1 いまどうなっているか（`M22-RESEARCH-01` の実測）

| 項目 | 実測 |
|---|---|
| ログイン・セッション | **★0 件**（Cookie の発行も検証も無い。`credentials: "same-origin"` が 4 か所あるが、**送るべき Cookie を発行する側が無い**） |
| `SecurityConfig` | **`PasswordEnabled bool` の 1 個のみ**。読む箇所 7 件はすべて**値の運搬・表示**であり、**認証判断に使う箇所は 0 件** |
| `users` 表 | **実在**。seed（`000007`）が `id=1, name='default'` を 1 行入れるだけ。**読む・書くコードは 0 件** |
| 利用者 ID | **`defaultUserID int64 = 1` として 3 か所にリテラル固定**（参照 10 か所） |
| ミドルウェア | **3 本のみ**（`RequestID` → `Logger` → `CORS`。すべて `e.Use` の全体適用） |
| `golang.org/x/crypto` | **`v0.46.0` が indirect で依存グラフに実在**。`bcrypt` / `scrypt` / `argon2` の 3 パッケージすべてが `GOMODCACHE` に実在。**★本体のソースが import している箇所は 0 件** |

**⇒ 認証は「直す」のではなく「無いところへ骨格を作る」仕事である。**
