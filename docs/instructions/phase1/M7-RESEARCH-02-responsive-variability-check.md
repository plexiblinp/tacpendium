## 0. この指示書の特殊性(最初に読むこと)

### 0.1 本指示書は「製造担当として起動し、調査だけ実施して閉じる」運用です

本指示書は通常の製造指示書(`M{N}-{NN}-*.md`)とは異なり、**コード変更・ファイル新規作成・テスト実行を一切行いません**。M7-03(系統 C: レスポンシブ仕上げ)の指示書を設計担当が確定するための前提情報を、コードベースから事実列挙形式で抽出することだけが目的です。

製造担当 Claude Code セッションを Sonnet 4.6 で起動し、本指示書に従って調査レポートを作成・出力したら、そのセッションは閉じます(製造作業は行いません)。

本指示書は **本プロジェクト 4 例目の調査専用指示書** です(初例 = M5-RESEARCH-01 比較 API 設計調査 / 2 例目 = M6-RESEARCH-01 設定 API + LAN バインド調査 / 3 例目 = M7-RESEARCH-01 shadcn/ui 統一導入の前提調査 = 自作ラッパー 26 件網羅特定済み)。

M7 では **RESEARCH 分割初運用** の後半。前半(M7-RESEARCH-01)で自作ラッパー UI コンポーネント網羅は完了済み、本指示書はレスポンシブばらつき調査を担当。

### 0.2 read-only 厳守

以下を **絶対に行わない** こと:

- ファイルの新規作成・編集・削除(調査レポート出力以外)
- `git` コマンド(`git status` 等の参照系も含めて、本指示書では使わない)
- `go build` / `go run` / `pnpm build` / `pnpm test` 等のビルド・テスト実行
- マイグレーション実行(`go run ./cmd/combomgr` でアプリを起動しない)
- 動作確認・スクリーンショット取得(開発者の責任範囲、playbook §14)
- npm / pnpm の install 系コマンド
- 設定ファイルの変更
- `rm`、`mv`、`cp` 等のファイル操作

使ってよいツールは **`view` / `bash`(grep / cat / ls / find / wc 等の参照系のみ)** に限定します。`view` で複数ファイルを横断的に読むことが本作業の中核です。

判断に迷ったら何もせずに **Plan Mode で開発者に確認** してください。

### 0.3 判断・提案を含めない

調査結果は **事実の列挙のみ** とし、「こうするべき」「こちらが推奨」「ブレークポイントを揃えるべき」のような判断・提案を含めないでください。判断は設計担当 Claude が調査結果を受けて行います。

ただし、調査中に発見した **明らかな矛盾・想定外の事象** は §5 完了報告の「特記事項」欄に **事実として** 記載してください(例: 「DES-005 §4.4 規定のブレークポイントと実装で使用されている値が一致しない」のような事実報告は OK、「これを統一すべき」のような提案は NG)。

### 0.4 本調査の主目的(設計担当からの背景共有)

開発者の認識として、以下が **既知の課題** として記録されている。本調査は、その課題の実態を実コードで事実列挙することが主目的:

- **R-1 持ち越し課題**(handover §3.5): M1〜M4 期間のレスポンシブ対応にばらつきがある(M5-01 / M6-02 / M6-03 期間担当が認識、M1〜M4 期間の各画面で Tailwind ブレークポイント使用状況が不統一)
- **M6-04 シナリオ G 検証結果**(handover §3.5): 既存画面のスマホ表示は「レイアウト崩れがある可能性があるが機能上は動作する」状態で M6 を完了

**想定される結果**(調査前):

- **項目 A**: 各画面の Tailwind ブレークポイント(`sm:` / `md:` / `lg:` / `xl:`)の使用密度が画面ごとに **大きく異なる**(M1-06 / M2 / M3 期間実装の画面は使用数少なめ、M5-01 比較画面は PC のみ実装、M6-02 設定画面 / M6-03 スマホ専用ホームは強くレスポンシブ意識した実装)
- **項目 B**: スマホ表示で崩れる可能性がある箇所が複数発見される(横スクロール / 固定幅 px / `min-w-` の使用、テーブル系コンポーネントが顕著の見込み)
- **項目 C**: DES-005 §4.4 規定のブレークポイント(`sm` 未満 = スマホ / `sm`-`lg` = タブレット / `xl` 以上 = PC)との実装の整合性確認、規定からの逸脱箇所の事実列挙

**想定外の発見が価値**: 想定外に「全画面がレスポンシブ完備」「特定画面で `xl:` 以上のみ使用」「`@media` クエリを生 CSS で記述している箇所がある」等が判明した場合、M7-03 のスコープ判断に大きく影響するため **特記事項として詳細に報告** すること。M5-RESEARCH-01 / M6-RESEARCH-01 / M7-RESEARCH-01 で「想定外の事象は事実として詳細に報告」という運用が確立されている。

### 0.5 結果の扱い(設計担当からの背景共有、調査担当の作業には影響しない)

本調査結果は **M7-03(系統 C: レスポンシブ仕上げ、R-1 + R-2 + R-3 持ち越し解消)** の指示書スコープ決定に使用される。調査結果次第で M7-03 の対象画面リストが変わる(全画面修正か、優先度の高い画面のみか)。調査担当は事実列挙のみ行い、判断は設計担当に委ねる。

## 8. 注意事項・判断に迷ったら

### 8.1 推測で進めてはいけない事項

- 画面ファイルの所在 → 必ず `find` / `ls` で実コードベースで確認(想定パスと異なる場合あり)
- ブレークポイント使用数 → 必ず `grep` の実出力で集計
- DES-005 §4.4 規定値 → 必ず原文を引用(数値を記憶で書かない)
- 共通 UI 要素(Header / Footer)の配置場所 → 必ず実コードで確認

### 8.2 推測で進めてよい事項(その旨を明示)

- ブレークポイント使用クラスの種別判別(レイアウト系 / フォントサイズ系 / 表示切替系等)で名称から推測する場合 → 推測である旨を明示

### 8.3 不明事項発見時の対応

- 画面ファイルの所在が想定と異なる → §4.1 (a) 集計表に実パスを記録 + 想定パスとの差分を §特記事項に記録
- 設計書本体記述と実装の乖離を発見 → §4.5 + 特記事項に詳細記録(判断・提案ではなく事実として)
- 画面の所在が見当たらない(M6-02 設定画面・初回ウィザード等)→ `find web/src -type d -name 'config' -o -name 'wizard'` 等で広く検索、それでも見つからない場合は「特記事項に『画面ファイル所在不明』」と事実記録
- 本指示書記述外の事象を発見 → 特記事項に詳細記録

### 8.4 Plan Mode で計画提示時に含めるべき項目(任意実施の場合)

Plan Mode を使う場合は以下を含めることが望ましい:

- §3.4 着手前確認の結果(画面ファイルの所在把握、DES-005 §4.4 規定の確認)
- §4.1 / §4.2 / §4.3 / §4.4 / §4.5 各項目の調査順序
- 想定所要時間の見積もり
