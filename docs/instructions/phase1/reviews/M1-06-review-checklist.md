## 0. レビュー担当の作業手順

1. 本ファイル、対象指示書本体、CLAUDE.md、DES-005 v2.6.0 §5.7、SUPP-001 §2.1 §2.2 §3.2 §3.3 を読む
2. M1-03 のサービス層・API も読み、PATCH/PUT 判定がフロント側で正しく実装できているか確認
3. 製造ターミナルで作成されたファイル群を `view` ツールで読む
4. 下記チェックリストに沿ってレビュー実施
5. レビュー結果を `docs/progress/m1-06-review.md` に出力

**重要ルール:**

- コードは一切変更しない
- ファイル作成は `docs/progress/m1-06-review.md` のみ
- Git 操作はしない
- 不明点があれば報告書に記載し、推測で進めない

---

## 1. 設計準拠性

- [ ] DES-005 v2.6.0 §5.7 の入力項目を網羅しているか
  - キャラクター、ダメージ、状況コード(position/opponent_stance/hit_type/opponent_size)
  - starter_move_id、ドライブゲージ、SAゲージ、有利フレーム(CHANGE-003 ラベル)
  - 起き攻めBOOLEAN(**6個**、CHANGE-001)
  - メモ、タグ、仮登録トグル
- [ ] opponent_stance の選択肢に `any`(CHANGE-003)が含まれているか
- [ ] SUPP-001 §2.1 仮登録モード時のバリデーション緩和(レシピ空OK等)が動作するか
- [ ] SUPP-001 §2.2 編集2方式分離(PATCH/PUT)の判定がフロント側で実装されているか
  - 判定対象フィールド(character_id、recipe、starter_move_id、position、opponent_stance、hit_type、opponent_size)が正しい
  - PUT 時に確認ダイアログが表示される
- [ ] HANDOVER-001 §3.1 のキー変更編集の挙動(再登録・古いコンボはゴミ箱)が UI で説明されているか
- [ ] 仮想コントローラを実装していないか(本指示書 §1、§4 で明示禁止、技セレクタ UI で代替)
- [ ] バリデーション結果(WARNING/ERROR)の表示が実装されているか
- [ ] 重複警告(VAL-C02 ERROR)の表示が実装されているか

## 2. コード品質

- [ ] TypeScript: `strict` 有効、`any` 使用がないか
- [ ] 関数コンポーネント + Hooks のみ
- [ ] フロント: ブラウザストレージAPI 使用なし
- [ ] フォーム状態管理が適切(React state、useReducer、または zod 等)
- [ ] サブコンポーネントへの適切な分割

## 3. UI 品質

- [ ] 保存中の loading 表示
- [ ] 保存後の遷移(コンボ詳細画面への遷移)
- [ ] エラー時の挙動(楽観衝突 409、サーバーエラー 500)
- [ ] 仮登録トグルの視覚的識別性

## 4. テスト網羅性

- [ ] `hasKeyChanges` のテスト(キー変更あり/なしの主要パターン)
- [ ] (任意) RecipeBuilder の動作テスト

## 5. 禁止事項

- [ ] `localStorage`、`sessionStorage`、`IndexedDB` の使用なし
- [ ] `console.log` の本番コード残存なし
- [ ] **仮想コントローラの本格実装をしていないか**(M2 へ持ち越すべき)
- [ ] 設計書に記載のない機能の追加なし

## 6. 統合確認

- [ ] router.tsx に `/combos/new`、`/combos/:id/edit` が登録されているか
- [ ] M1-05 の一覧画面の「編集」リンクが正しくこのページに遷移するか
- [ ] M1-05 の「新規登録」ボタンが正しくこのページに遷移するか
