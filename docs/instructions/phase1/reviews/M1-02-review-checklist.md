## 0. レビュー担当の作業手順

1. 本ファイル(レビューチェックリスト)、対象指示書本体、CLAUDE.md、SUPP-001、DES-003 を読む
2. 製造ターミナルで作成されたファイル群を `view` ツールで読む
3. 下記チェックリストに沿ってレビュー実施
4. レビュー結果を `docs/progress/m1-02-review.md` に出力

**重要ルール:**

- コードは一切変更しない
- ファイル作成は `docs/progress/m1-02-review.md` のみ
- Git 操作はしない
- 不明点があれば報告書に記載し、推測で進めない

---

## 1. 設計準拠性

- [ ] DES-003 §3.1〜§3.13 の全13テーブルが作成されているか
- [ ] DES-003 §3.4 combos の起き攻めBOOLEANが **6カラム**(CHANGE-001、7カラムでない)
- [ ] DES-003 §3.4 combos の `opponent_stance` 許容値に `any` が含まれている(CHANGE-003)
- [ ] DES-003 §3.4 combos に `version`、`is_draft`、`deleted_at`、`recipe_cache` カラムがある
- [ ] DES-003 §3.5 combo_steps の `modifiers` が JSON 文字列カラムである
- [ ] DES-003 §4 のインデックスが追加されているか
- [ ] SUPP-001 §2.7 のマイグレーションツール選定通り `golang-migrate/migrate v4` + `iofs` + `embed.FS` か
- [ ] SUPP-001 §3.1 リュウ1キャラのみ投入(他キャラの seed が混入していないか)
- [ ] SUPP-001 §3.4 プリセット5種レコード作成、`official_ja_move` のみエイリアス投入(他4種のエイリアスは空)
- [ ] DES-004 §2.1 の技 code 命名規則(snake_case、適切なプレフィックス)に従っているか
  - 注: 技マスタの「正確な技構成(リュウが何の特殊技を持つか等)」は推測 OK のためレビュー対象外。**技 code の命名形式のみ確認する。**

## 2. マイグレーションの実装品質

- [ ] up.sql / down.sql が対応していて、down→up の往復で元に戻るか
- [ ] 外部キー制約が正しく設定されているか
- [ ] WALモード、外部キー有効化、busy_timeout が DB 接続時に設定されているか
- [ ] マイグレーション実行のエラーが slog に正しく記録される実装か

## 3. Go コード品質

- [ ] エラーラップが `fmt.Errorf("...: %w", err)` 形式で実装されているか
- [ ] `context.Context` がマイグレーション関数の引数にあるか
- [ ] モデル構造体に godoc コメント(public な型のみ)
- [ ] `panic` 使用回避(初期化失敗時の main 内のみ可)

## 4. 完成度

- [ ] `make run-server` で起動時に自動マイグレーションが動作する実装か
- [ ] 2回目起動時にマイグレーションがスキップされる(no-op)実装か
- [ ] DB ファイルが OS別 アプリデータディレクトリに作成される実装か(または config.toml で指定したパス)
- [ ] `make test` が全通過する状態か

## 5. 禁止事項

- [ ] DB破壊的操作(DROP TABLE 以外)が誤って入っていないか
- [ ] `localStorage` 等のフロント禁止項目に触れていないか(本指示書はGo側中心だが念のため)

## 6. テスト網羅性

- [ ] `internal/infra/db/db_test.go` で WAL モード・外部キー有効化が確認されているか
- [ ] `internal/infra/migration/migrate_test.go` で初回マイグレーション・冪等性・テーブル存在確認・seed データ存在確認がされているか
