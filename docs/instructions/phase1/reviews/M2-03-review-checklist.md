## 0. レビュー担当への前置き

本チェックリストは M2-03 指示書(`docs/instructions/M2-03-trash-page.md`、v1.0.0)に対するレビュー観点を整理したものである。M2-03 はバックエンド(完全削除 API 新設、`only_deleted` フィルタ追加、Restore 修正の条件付き)とフロントエンド(ゴミ箱画面、復元・完全削除 UI、一括操作)の両方を扱うため、レビュー観点も両側面を網羅する。

### 0.1 レビュー前の準備

1. M2-03 指示書(本指示書本体)を一読する
2. 製造担当の実装完了報告(自己テスト結果、curl レスポンス、E2E 動作確認手順書、§3.4 着手前確認結果)を確認する
3. 関連する設計書を確認する(必読: DES-005 §5.4 / §5.15、DES-003 §3.4、SUPP-001 §7.1 / §7.2、M1-03 §4.1 / §4.10、M1-04 §4.3.2 / §4.3.3)
4. ローカルでビルドを実行して動作することを確認する:
   - バックエンド: `make build` または `go build ./...` が成功する
   - フロントエンド: `pnpm build` が成功する
5. ローカルでテストを実行して通過することを確認する:
   - バックエンド: `make test` または `go test ./...` が全通過
   - フロントエンド: `pnpm test` が全通過

### 0.2 レビューの基本姿勢

retro-2-M2.md §3.2 / §3.3 に基づく姿勢:

- **機械的チェックを超えて設計意図を読む**: 各項目が「動くか」だけでなく「設計書の精神に沿っているか」を確認する
- **設計書本体との照合を優先する**: 指示書ではなく設計書を真の情報源として、実装が乖離していないかを確認する
- **疑問は遠慮せず提起する**: M1 期間で「指示書記述の曖昧さ」「責任所在の不明確さ」が複数回問題化した(retro R-02 / R-03)
- **条件付きスコープの判断を厳密に確認する**: M2-03 は §4.6 の Restore 修正が条件付きスコープのため、製造担当が条件判断を誤っていないかを特に注意して確認する

## 5. 設計意図との整合(retro R-08 §3.2.2 対応)

機械的チェックを超え、設計書の精神に沿っているかを確認する観点。

### 5.1 完全削除の安全策の思想(指示書 §4.1.1)

- [ ] 「ゴミ箱経由でしか完全削除できない」という安全策が機能している(409 拒否)
- [ ] フロント側で `deleted_at IS NULL` の通常コンボに対して完全削除ボタンが表示されないか、そもそも UI 動線がゴミ箱画面からのみ完全削除できる構造になっている

### 5.2 専用一括 API を新設しない設計判断(指示書 §4.2)

- [ ] フロント側で単体 API の並列呼出を採用、専用一括 API を新設していない

## 9. 重大な問題の判定基準

以下のいずれかに該当する場合は **重大な問題**として開発者に即座に報告する:

- 完全削除 API の安全策(409 Conflict)が動作せず、通常コンボが完全削除できてしまう実装ミス
- `only_deleted` パラメータが既存 `include_deleted` と整合しない(優先順位仕様違反)
- M1-03 の既存 `Restore` 実装で `RecomputeComboCache` 呼出が未実装だったにもかかわらず、§4.6 の追加実装が行われていない(または逆に、既に呼出が存在するのに重複実装している)
- 専用の一括 API が独自に新設されている(指示書 §4.2 の方針違反)
- M1-04 の `RecomputeComboCache` / `DeleteComboCache` メソッド本体が変更されている(呼び出すのみが原則)
- 既存マイグレーションに変更が加えられている(本指示書のスコープ外)
- combo_steps テーブルのレコードが完全削除後に残っている(CASCADE が機能していない)
- M1-03 / M1-04 / M1-05 / M2-01 / M2-02 の既存テストが失敗している(リグレッション)
- E2E シナリオ A〜F のいずれかが動作しない、または動作確認手順書が未提出
- 完全削除 API の curl レスポンスが提出されていない、または異常系(404 / 409 / 400)が動作していない

## 10. 軽微な問題の判定基準

以下は **軽微な問題**として開発者に報告するが、修正は M2-04 以降への持ち越しを許容する:

- ゴミ箱画面のスタイル(色、配置)が SF6 風でない、Tailwind デフォルトのままで素朴
- 残日数表示の文言・色が地味
- ヘッダのゴミ箱リンクのアイコンが未配置
- 一括操作の進捗表示がスピナー有無のみで、件数進捗が出ない
- ルート列の「(レシピ表示なし)」表示が無味乾燥
- ゴミ箱画面のキャラ切替が独立 SelectBox で、コンボ一覧と統一感がない

これらは M7 仕上げまでに改善されればよい。
