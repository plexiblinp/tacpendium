### 0.2 レビューの基本姿勢

本指示書は **持ち越し課題 P-01 の独立清算** であり、スコープは極めて狭い(フロント単一ファイル + テストファイル)。レビュー観点も狭く絞られる。以下を意識する:

- 製造担当が指示書通り実装したか機械的に確認
- 既存テスト回帰がないか確認
- §3.4 着手前確認(特に §3.4.1 の console.warn 検出ゼロ)が報告に含まれているか確認
- M2-04 設計担当ミスの再発(retrospective-log §1 パターン A)が本指示書で再発していないか確認

## 9. 重大な問題の判定基準

以下のいずれかに該当する場合、**重大な問題** と判定し M4-00 完了承認を保留する:

- §1.2 / §1.3 のチェック項目で 2 件以上の未充足がある(指示書本体との乖離が大きい)
- §3.4.1 着手前確認の「console.warn 検出ゼロ」が報告に含まれていない、または検出結果が「ゼロでない」場合に Plan Mode で停止していない
- 視覚的 UI 警告(M2-04 §4.2 実装)が削除・変更されている(§4.1.4 違反、既存挙動破壊)
- 既存 4 ケースが回帰している(`pnpm test` で失敗)
- `console.log` などの不要な console 出力が本番コードに残されている
- M2-04 / M3-05 の他ファイルに本指示書のスコープ外の変更が含まれている

## 10. 軽微な問題の判定基準

以下に該当する場合、**軽微な問題** と判定し M4-00 完了承認は許容するが、次マイルストーン担当または開発者への記録として残す:

- 警告文言の細部が指示書例と多少異なる(「50 文字を超えています」を含めば許容、§9.2 推測 OK 範囲)
- テストケース名が指示書例と異なるが、検証内容は §4.2.1 通り
- スパイのリセット方式が `mockRestore` か `restoreAllMocks` かで揺れているが、テストが全通過している
- §3.4.4 で確認した既存 spy 方式の踏襲が完全でないが、新規 3 ケースは正しく動作する

## 12. レビュー完了の判定

すべて以下を満たす場合、レビュー完了として開発者に「重大な問題なし」と報告する:

- §1 / §3 / §4 / §6 / §7 / §8 の機械的チェック項目がすべて通過
- §5 設計意図整合(P-01 解消の本質、retrospective-log §1 パターン A 再発防止)が確認されている
- §9 重大な問題に該当する項目がゼロ
- §10 軽微な問題が存在する場合は記録されている

不通過の場合は §9 / §10 のどちらに該当するかを明示し、§11 フォーマットで開発者に質問または修正要求を行う。
