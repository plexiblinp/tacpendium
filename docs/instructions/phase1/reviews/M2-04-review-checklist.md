## 0. レビュー担当への前置き

本チェックリストは M2-04 指示書(`docs/instructions/M2-04-notes-display-and-integration.md`、v1.0.0)に対するレビュー観点を整理したものである。M2-04 は M2 全体の **統合・仕上げマイルストーン** という性質上、レビュー観点は以下の3つに重点を置く:

1. **新規機能(notes 表示)の設計書整合性**
2. **持ち越し課題6件の確実な消化**(M2-01 連絡事項1 / M2-03 連絡事項1〜3)
3. **過去マイルストーン(M2-01 / M2-02 / M2-03)の既存挙動の非破壊性**

### 0.1 レビュー前の準備

1. M2-04 指示書(本指示書本体)を一読する
2. 製造担当の実装完了報告(自己テスト結果、curl レスポンス、E2E 動作確認手順書、§3.4 Plan Mode 確認結果)を確認する
3. 関連する設計書を確認する(必読: SUPP-001 §3.3.4、DES-004 §5、M1-04 §4.2.1、M1-05 §4.2.2、M2-01 §4.6、M2-02 §4.4、M2-03 §4.5 / §4.7 / §4.8)
4. ローカルでビルドを実行して動作することを確認する:
   - バックエンド: `make build` または `go build ./...` が成功する
   - フロントエンド: `pnpm build` が成功する
5. ローカルでテストを実行して通過することを確認する:
   - バックエンド: `make test` または `go test ./...` が全通過
   - フロントエンド: `pnpm test` が全通過
6. **特に重要**: M1-04 / M1-05 / M1-06 / M2-01 / M2-02 / M2-03 の既存テストが **すべて通過** していることを確認する(リグレッションがないこと)

### 0.2 レビューの基本姿勢

retro-2-M2.md §3.2 / §3.3 に基づく姿勢:

- **機械的チェックを超えて設計意図を読む**: 各項目が「動くか」だけでなく「設計書の精神に沿っているか」を確認する
- **設計書本体との照合を優先する**: 指示書ではなく設計書を真の情報源として、実装が乖離していないかを確認する
- **疑問は遠慮せず提起する**: M1 期間で「指示書記述の曖昧さ」「責任所在の不明確さ」が複数回問題化した(retro R-02 / R-03)
- **統合の品質を重視する**: M2-04 は M2 全体の最終マイルストーン。E2E シナリオ F(統合シナリオ)が真に動作しているか、過去のマイルストーンが連動して機能しているかを丁寧に確認する
