### 0.2 レビューの基本姿勢

- 本タスクは **削除が中心**。「追加された不具合」だけでなく **「削除し残し」「削除し過ぎ(温存対象の巻き添え)」の両方** を見る。
- **grep 系の完了条件は必ず自分で実行し、結果(ヒット件数・該当行)をレビュー報告書に明示する**(M7-11 反省 = grep 完了条件の見落とし再発防止)。「指示書に書いてあるから OK」ではなく実行して確認する。
- 「ゲージ」という語は (1) 消費量(削除対象)、(2) 増加量(moves、温存)、(3) 開始残量(combos、温存)の 3 概念に分かれる。**カラム名/キー名の語形でなく、所属テーブル・用途で削除/温存を判定する**。

### 0.3 レビュー結果の報告フォーマット

- レビュー報告書冒頭に **§1 / §7 の grep 実行結果(コマンド + ヒット件数)を必ず転記**する。
- 各章の合否 + 重大問題(§9)/ 軽微問題(§10)の一覧。
- 重大問題ゼロ + grep 全数性確認済みで「完了承認可」と判定(§12)。

## 9. 重大な問題の判定基準(M7-04-1 完了承認を妨げるレベル)

以下のいずれかがあれば **完了承認不可**:

- §1.1 の grep がコード領域で 1 件以上残存(削除し残し)
- §7.1 の温存対象が削除されている(削除し過ぎ = 巻き添え)
- ビルド / 型チェック / `go test` / `npm test` のいずれかが失敗
- バグ #5 が解消されていない(昇格時エラーが依然崩れた表示)
- 過去マイグレーション(000001〜000007)が改変されている
- VAL-C08 以降がリネームされている(欠番扱い違反)
- スコープ外(M7-04-2 のプリセット/キャラ/スキーマ、バグ #6、他バグ)に手が入っている
