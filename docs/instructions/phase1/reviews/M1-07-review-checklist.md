## 0. レビュー担当の作業手順

1. 本ファイル、対象指示書本体、CLAUDE.md、SUPP-001 §4.4 を読む
2. 製造ターミナルで作成されたファイル群を `view` ツールで読む
3. 下記チェックリストに沿ってレビュー実施
4. レビュー結果を `docs/progress/m1-07-review.md` に出力

**重要ルール:**

- コードは一切変更しない
- ファイル作成は `docs/progress/m1-07-review.md` のみ
- Git 操作はしない
- 不明点があれば報告書に記載し、推測で進めない

---

## 1. 設計準拠性

- [ ] SUPP-001 §4.4 のデバッグ API 仕様(`GET /api/debug/tables`、`GET /api/debug/dump/:table`)が実装されているか
- [ ] ビルドタグ `debug` で制御される実装になっているか
  - `//go:build debug` および `//go:build !debug` の使用
  - 本番ビルドでは debug ルートが登録されない構造
- [ ] `dump/:table` に上限(100件)と truncated フラグが実装されているか
- [ ] 既存ミドルウェア(CORS、Logger)を引き続き通る実装か(別途 bypass していないか)

## 2. セキュリティ

- [ ] テーブル名のホワイトリストチェック(sqlite_master 由来)が実装されているか
- [ ] **SQL Injection 攻撃**(`combos; DROP TABLE combos;` 等のテーブル名)に対して 404 で安全に拒否されるか
- [ ] エラーメッセージで内部情報を漏らしていないか
- [ ] 書込系 API が誤って実装されていないか(read-only に限定されているか)

## 3. コード品質

- [ ] エラーラップが `fmt.Errorf("...: %w", err)` 形式
- [ ] `context.Context` がハンドラに引数として渡されているか
- [ ] 公開関数に godoc コメント
- [ ] 行のスキャン(`rows.Scan`)が安全に実装されているか(動的カラム対応)

## 4. テスト網羅性

- [ ] `ListTables` の正常系テスト
- [ ] `DumpTable` の正常系テスト(既存テーブル)
- [ ] `DumpTable` の異常系テスト(存在しないテーブル → 404)
- [ ] `DumpTable` の SQL Injection 安全性テスト

## 5. 禁止事項

- [ ] `localStorage` 等のフロント禁止項目に触れていないか(本指示書はGo側のみだが念のため)
- [ ] `console.log` / `fmt.Println` の本番コード残存がないか
- [ ] Git 操作の Bash 実行がないか
- [ ] **書込系のデバッグ API**(POST/DELETE 等)を誤って実装していないか

## 6. 統合確認

- [ ] `make build`(本番ビルド)で `/api/debug/*` が 404 になる構造か
- [ ] `make run-server-debug`(または `make build-debug`)で `/api/debug/*` が動作する構造か
- [ ] README にビルド方法が記載されているか
- [ ] Makefile にデバッグ用ターゲット(`run-server-debug`、`build-debug`)が追加されているか
