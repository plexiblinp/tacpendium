## 0. レビュー担当への前置き

本チェックリストは M2-02 指示書(`docs/instructions/M2-02-edit-ux-improvements.md`、v1.0.0)に対するレビュー観点を整理したものである。M2-02 はバックエンド(重複検知 API 新設)とフロントエンド(コピー機能、リアルタイム警告、本登録昇格 UI、PUT 確認ダイアログ整理)の両方を扱うため、レビュー観点も両側面を網羅する。

### 0.1 レビュー前の準備

1. M2-02 指示書(本指示書本体)を一読する
2. 製造担当の実装完了報告(自己テスト結果、curl レスポンス、E2E 動作確認手順書、§3.4 着手前確認結果)を確認する
3. 関連する設計書を確認する(必読: DES-005 §5.4 / §5.6 / §5.7、DES-006 §2.1 / §2.3、SUPP-001 §2.2 / §3.1、M1-03 §4.1 / §4.3、M1-06 §4.4 / §4.5.1)
4. ローカルでビルドを実行して動作することを確認する:
   - バックエンド: `make build` または `go build ./...` が成功する
   - フロントエンド: `pnpm build` が成功する
5. ローカルでテストを実行して通過することを確認する:
   - バックエンド: `make test` または `go test ./...` が全通過
   - フロントエンド: `pnpm test` が全通過

### 0.2 レビューの基本姿勢

retro-2-M2.md §3.2 / §3.3 に基づく姿勢:

- **機械的チェックを超えて設計意図を読む**: 各項目が「動くか」だけでなく「設計書の精神に沿っているか」を確認する
- **設計書本体との照合を優先する**: 指示書ではなく設計書を真の情報源として、実装が乖離していないかを確認する
- **疑問は遠慮せず提起する**: M1 期間で「指示書記述の曖昧さ」「責任所在の不明確さ」が複数回問題化した(retro R-02 / R-03)。レビューで違和感を覚えた箇所は、設計担当 Claude(M2 期間担当)経由で開発者に確認する流れで提起する
- **既存ロジック再利用の整合性を特に重視する**: M2-02 は M1-03 の `DuplicateCheckFields` / `CalcRecipeHash` を再利用する設計のため、実装が既存ロジックと完全整合しているかは厳密に確認する

## 9. 重大な問題の判定基準

以下のいずれかに該当する場合は **重大な問題**として開発者に即座に報告する:

- 重複判定キーが M1-03 §4.3 の `DuplicateCheckFields` と乖離している(独自定義を作っている、項目数が違う等)
- 重複判定の対象範囲が DES-006 §2.3 と乖離している(仮登録・論理削除済みコンボを判定対象に含めている)
- recipe_hash 計算アルゴリズムが M1-03 §4.3 と異なる実装になっている
- 編集2方式分離(`hasKeyChanges` の挙動)が破壊されている
- コピーモードで PUT が呼ばれてしまう実装ミス
- コピーモードで `hasKeyChanges` 判定が走り、確認ダイアログが表示されてしまう
- 本登録 → 仮登録の降格 UI が実装されている(FR010 範囲外、開発者確定済みに反する)
- リアルタイム警告と POST 時モーダルのどちらかが動作しない
- M1-03 / M1-06 / M2-01 の既存テストが失敗している(リグレッション)
- E2E シナリオ A〜D のいずれかが動作しない、または動作確認手順書が未提出
- 重複検知 API の curl レスポンスが提出されていない、または異常系(400)が動作していない
- **重複検知 API のレスポンスに構造化フィールドが欠落している**(指示書 §4.1.3 v1.1.0、Q2 関連): id 以外のフィールド(characterId / starterMoveId / position / opponentStance / hitType / opponentSize / stepCount)が欠落している、または `label` を返している
- **`UpdateMetadataInput` の IsDraft が `*bool` 型でない**(指示書 §2.4.2 / §4.5.2 v1.1.0、Q1 関連): `bool` 型(値型)で実装されており後方互換性が壊れている、または UPDATE SQL の組み立てで「nil の場合 is_draft を更新しない」分岐が実装されていない
- **DuplicateRealtimeWarning の表示文字列にキャラ名・始動技名が解決されずに ID のまま表示されている**(`useCharacters` / `useMovesByCharacter` での解決が漏れている)

## 10. 軽微な問題の判定基準

以下は **軽微な問題**として開発者に報告するが、修正は M2-03 以降への持ち越しを許容する:

- ローディング表示(リアルタイム警告判定中)が未実装

これらは M7 仕上げまでに改善されればよい。
