## 0. レビュー担当への前置き

### 0.1 レビュー前の準備

レビュー開始前に以下を必ず読む:

1. `CLAUDE.md`(全体方針、特に **§4 JSON タグ camelCase / 列挙定数同期ルール**、§10 禁止事項)
2. `docs/instructions/M3-05-combo-list-polish-and-error-unification.md` v1.0.0(本チェックリストの対象指示書)
3. **`docs/change-notifications/CHANGE-010-api-error-common-type.md` v1.0.0**(エラー共通化の根拠)
4. `docs/instructions/M3-overview.md` v1.0.2(**§3.5 M3-05 詳細**)
5. `docs/instructions/M3-01〜M3-04` の各指示書(統合 E2E のため全機能の前提を把握)
6. `docs/design/02-architecture.md`:
   - **§4.3 エラーハンドリング**(CHANGE-010 で改訂予定の節)
   - §4.2 主要エンドポイント
7. `docs/design/05-screen-design.md` §5.4 コンボ一覧
8. `docs/handover/design-instruction-playbook.md` v1.5.0 **§4.5 / §4.6 / §4.7 / §4.8 全ルール**
9. 製造担当の実装完了報告書

### 0.2 レビューの基本姿勢

- **設計書本体との行レベル照合を最優先**(playbook §5、retro R-01)
- **CHANGE-010 の取り込みが正しく行われているか厳格にチェック**(共通型の定義・既存ハンドラの統一・後方非互換変更のフロント対応)
- **playbook §4.7 全ハンドラ列挙原則の遵守**(エラー共通化で 3 ハンドラすべての修正対象を漏らしていないか)
- **既存独自エラー型の完全削除確認**(`tagErrorResponse` / `charErrorResponse` / `map[string]string` フラット形式の grep ゼロ)
- **combo ハンドラの後方非互換変更でフロント側が破綻していないか厳格チェック**
- **M3 統合 E2E シナリオ A〜I のすべての確認**(M3 期間最終マイルストーンとしての完成度判定)
- **playbook §4.6 UI ライブラリ実態確認原則の遵守**(shadcn/ui 不使用)
- 機械的チェックに加え、設計意図との整合を読み取る(playbook §9.3)
- 重大な問題と軽微な問題を区別する(§9 / §10 参照)

### 0.3 レビュー結果の報告フォーマット

レビュー完了時に以下のフォーマットで報告する:

```
## レビュー結果サマリ

- 重大な問題: {件数}件

## 重大な問題詳細
(各問題の節番号、対象ファイル、内容、修正提案を記載)

## 軽微な問題詳細
(同上)

## 質問・確認事項
(設計担当 Claude または開発者への確認事項)

## レビュー判定
- [ ] 重大な問題なし → 承認
- [ ] 重大な問題あり → 製造担当に修正依頼
```
