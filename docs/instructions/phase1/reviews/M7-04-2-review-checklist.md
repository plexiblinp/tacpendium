### 0.2 レビューの基本姿勢

- 本タスクは **データ追加 + 確認** が中心。「追加された不具合」だけでなく **(a) スキーマを勝手に変更していないか、(b) 複数キャラ化でリュウ(既存)に回帰がないか、(c) HTML から抽出した seed がスキーマと整合するか** の 3 点を重視。
- **データの正確性そのものは厳密に検証しない**(§0 確定 = フェーズ 3 で総入れ替え、多少変なデータ可)。レビューは「スキーマ・整合性・既存への非破壊」を見るのであって「SF6 技データの正確性」を検証するのではない(SF6 ドメインの正確性検証は本タスクの目的外)。
- **grep 系の確認は自分で実行し、結果をレビュー報告書に明示する**(M7-11 反省)。

### 0.3 レビュー結果の報告フォーマット

- 報告書冒頭に §1 / §5 / §7 の確認結果(マイグレーション up/down 結果、スキーマ非変更の確認、複数キャラ回帰チェック)を明示。
- 各章の合否 + 重大問題(§9)/ 軽微問題(§10)の一覧。

## 1. seed の整合(HTML 抽出 → スキーマ)

### 1.1 マイグレーションの健全性

- [ ] 追加 seed マイグレーションが最新 + 連番で追加されている(過去 000001〜000008 を改変していない)
- [ ] up マイグレーションで AKI / ジェイミー / ガイルの `characters` / `moves` / `preset_aliases`(official_ja_move 分)が投入される
- [ ] down マイグレーションで追加 3 キャラ分が漏れなく削除され、リュウのみの状態に戻る(`migrate down` で検証)
- [ ] up → down → up が通る(冪等性 / ロールバック健全性)

### 1.2 スキーマとの整合(HTML 抽出結果)

- [ ] `characters`: 3 キャラの `code`(`aki` / `jamie` / `guile`)/ `name_ja` / `name_en` / `game_id`(sf6)が投入され、UNIQUE 制約 `(game_id, code)` に違反しない
- [ ] `characters.custom_states`: AKI(毒)/ ジェイミー(飲酒レベル)が DES-003 §3.2 の JSON 構造(`states[].code / name_ja / name_en / subject / scope / type / value_definition`)に従う。ガイルは NULL
- [ ] `moves`: 各キャラの技が `moves` テーブル定義(DES-003 §3.3)のカラムに整合(NOT NULL カラムが埋まっている、型が合う)
- [ ] `preset_aliases`: official_ja_move 分のエイリアスが投入され、他 4 プリセットは空のまま(§4.1 = 本タスクで埋めない)
- [ ] recipe_cache: 追加キャラのコンボ登録時に全プリセット分が計算される(SUPP-001 §7、空プリセット分含む)

### 1.3 抽出の妥当性(過度に厳密にしない)

- [ ] HTML に記載のない項目を補完した場合、スキーマ耐久 + UI 確認に支障ない妥当な値か(完璧な SF6 正確性は不問、§0.2)
- [ ] 抽出ミスでスキーマ違反(NOT NULL 欠落、型不整合、UNIQUE 違反)を起こしていないか(正確性ではなく整合性の観点)

## 9. 重大な問題の判定基準(M7-04-2 完了承認を妨げるレベル)

以下のいずれかがあれば **完了承認不可**:

- スキーマ(テーブル定義)を Plan Mode 停止なしに勝手に変更している(§5)
- 過去マイグレーション(000001〜000008)を改変している / リュウの既存 seed を改変している(§1.1 / §7)
- マイグレーション up/down が通らない(§1.1)
- seed がスキーマ違反(NOT NULL 欠落 / 型不整合 / UNIQUE 違反)を起こしている(§1.2)
- ビルド / `go test` / `npm test` のいずれかが失敗(§7)
- `custom_states`(AKI / ジェイミー)がエンドツーエンドで破綻している(§3)
- 空プリセットのフォールバックが機能しない(§2)
- スコープ外(M7-05 リファクタ / 統合 E2E / LAN / 公式取り込みツール / プリセット管理 UI / 4 空プリセットのエイリアス本格整備)に手が入っている

## 10. 軽微な問題の判定基準(持ち越しを許容するレベル)

- HTML から読み取れず妥当値で補完したデータの「SF6 的不正確さ」(§0.2 = 許容、フェーズ 3 で総入れ替え)
- キャラ固有技名のプリセット扱いの軽微な暫定対応(§3.4.10 必須項目 5 で確定した範囲内)
- 代表コンボの件数が 10〜20 の範囲で前後する程度
