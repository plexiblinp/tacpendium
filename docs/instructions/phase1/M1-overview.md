## 1. 本書の位置づけ

SUPP-001 §4.1 で M0〜M7 のマイルストーン全体が定義されている。本書は M1(コア基盤)を **7つのサブマイルストーン(M1-01〜M1-07)** に細分化した構成と相互関係を示す。

各指示書を実装する Claude Code は、本書を読むことで「他の指示書と並列で動いている可能性」「依存関係」「自分の作業範囲外」を把握できる。

## 3. 依存関係

```
M1-01(骨格)
  ↓
M1-02(マイグレ・seed)
  ↓
M1-03(コンボCRUD API)
  ↓
  ├── M1-04(プリセット解決) ─┐
  ├── M1-05(一覧・詳細画面)  │ 並列可
  ├── M1-06(登録・編集画面)  │
  └── M1-07(debug API)       ─┘
                              ↓
                          M1 完了
```

- M1-01〜M1-03 は **直列必須**(後続が前のコードに依存)
- M1-04〜M1-07 は **M1-03 完了後に並列実行可能**
- M1-07 だけは特に独立性が高く、いつでも着手できる(ただし M1-01 の Echo サーバー設定は前提)

---

## 4. 並列実行時の競合に関する注意

M1-04〜M1-07 を別ブランチで並列実行する場合、以下のファイルが**複数の指示書から変更対象**になる可能性がある。

| ファイル | 変更する可能性のある指示書 | 衝突対策 |
|----------|--------------------------|---------|
| `cmd/combomgr/main.go` | M1-04(notation サービス DI)、M1-05/06(将来的に)、M1-07(debug API ルート) | マージ時に開発者が解決、各指示書で「main.go の追記箇所」を最小限にする |
| `internal/api/combo/handler.go` | M1-04 で recipe_cache 連携の関数呼出が追加される可能性 | M1-04 が後発なので M1-04 側で M1-03 の手を加える |

並列実装時は**各ブランチで commit が小さく独立している**ようにし、開発者がマージ時に競合を解決する。Claude Code は git 操作を行わない(`.claude/settings.json` で禁止済み)。

## 5. 各指示書とレビューチェックリスト

各 M1 指示書には対応するレビューチェックリストが別ファイルとして存在する。

| 指示書(製造担当向け) | レビューチェックリスト(レビュー担当向け) |
|---------------------|----------------------------------------|
| `docs/instructions/M1-01-project-skeleton.md` | `docs/instructions/reviews/M1-01-review-checklist.md` |
| `docs/instructions/M1-02-migrations-and-seed.md` | `docs/instructions/reviews/M1-02-review-checklist.md` |
| `docs/instructions/M1-03-combo-crud-api.md` | `docs/instructions/reviews/M1-03-review-checklist.md` |
| `docs/instructions/M1-04-*.md`(後続) | `docs/instructions/reviews/M1-04-*.md`(後続) |
| 以降同様 | 以降同様 |

**製造担当の Claude Code は、レビューチェックリストを読む必要はない**(自分の指示書本体に集中する)。レビュー担当の Claude Code は、指示書本体とレビューチェックリストの両方を読む。

---

## 6. 完了判定

各サブマイルストーンの完了は以下の条件:

- 指示書 §7「完了条件(Definition of Done)」を満たす
- レビューチェックリスト(別ファイル)で重大な問題がないと確認される
- 開発者が承認する

M1全体の完了は、M1-01〜M1-07 全ての完了をもって判定。
