## 0. 前提となる重要事項

### 0.1 構成・モデルの確定とターン区切り運用(開発者確定 2026-06-03)

M7-overview §4.7 の当初 M7-05 は関心数 2(リファクタ + 統合 E2E)= Sonnet 4.6 想定だったが、M7 期間中の Q 決定・完了処理で以下が編入され実質スコープが増えた:

- **バグ#6(VAL-S02 セットプレイ登録)** 修正(retrospective §6.6 M7-16、Q21 BB)
- **E-3(マイコンボのカウントバグ)** 修正(retrospective §6.6 M7-17、M7-04-2 由来)
- **window.confirm 全件 → AlertDialog 化**(retrospective §6.6、Q19 W、M7-11 由来)
- **i18n 未使用キー整理 + C-1(リュウ固定フォールバック文言)**(retrospective §6.6 M7-16 / M7-17)
- **検証用リュウデータの全クリア**(M7-04-2 §0.4、フェーズ 1 完了判定の一部)

**確定: 単一 M7-05 構成 + Opus 4.6**(分割しない)。実質関心数の増加分は Opus でカバーする。

**品質に不安がある場合の運用: Plan Mode 判断で関心ごとにターンを区切って実施する**。推奨ターン区切り(独立性 + リスクの順):

1. **バグ修正ターン(バグ#6 / E-3)**: 真因切り分けが要るため最初に独立。着手前確認(ハンドラ 400 分岐の有無)→ Plan Mode 報告 → 修正 → 回帰テスト → `git commit`。
2. **クリーンアップターン(window.confirm 全件 / i18n)**: 機械的・低リスク。grep 全件提示を必須 → `git commit`。
3. **リファクタターン(L-02 / L-03 / L-04 / M-1〜M-4)**: L-02 の CHANGE 要否判定で停止しうるため独立。L-02 → L-03 → L-04 → M の順 → `git commit`。
4. **統合 E2E + 完了ターン(系統 G)**: 系統 F の全コミット後に着手(E2E 中に F を直すと回帰基準が動くため)。回帰確認 → 検証用リュウデータ全クリア → フェーズ 1 完了判定。

ターン共通運用: ターンごとに `git commit` / 各ターン冒頭で着手前確認 → Plan Mode 報告 → 着手 / 長い grep 出力・ファイル全文の貼り戻しは要約してコンテキスト圧迫を避ける(後半ターンの品質維持、retrospective M6-13 系の留意)。

### 0.2 このマイルストーンの位置づけ

M7 期間(フェーズ 1 完了マイルストーン)の **最終サブマイルストーン**。新機能は一切作らず、「既に動くものを整える + 残課題を消化 + 全機能の回帰を確認 + フェーズ 1 完了を判定する」。完了承認をもって **フェーズ 1 が完了**し、次工程はフェーズ 2 を飛ばしフェーズ 3(公式データ取り込みツール FR701)先行の開発者意向。

## 9. 注意事項・判断に迷ったら

### 9.1 Plan Mode 停止が必須のケース

- L-02 解消が DES-006 規定改訂を伴うと判明(= CHANGE 通知書起票判断、設計担当報告)
- リファクタ中にスキーマ変更が必要と判明
- バグ#6 / E-3 の真因が想定と異なり、スコープ判断が変わる場合(真因レイヤを決めつけない = M7-16 反省)
- 統合 E2E で M1〜M6 機能の回帰(新たな不具合)を検出

### 9.2 設計担当の判断意図(製造担当が誤解しやすい点)

- **バグ修正の真因レイヤを症状から決めつけない**(M7-16 = バグ#5 の真因はフロントでなくバックエンドのハンドラ 400 分岐欠落だった)。バグ#6 も同型の可能性が高い。
- **フェーズ 1 完了判定の「未実装」は不合格ではない**: ComboEditor キャラ選択 / custom_states 機能 / recipe_cache プリセット無効化 / プリセット管理 UI / 本格スマホ UI / i18n 英語 は **フェーズ 2/3 送り確定 = フェーズ 1 では未実装が正**。これらを「直すべきバグ」と誤認しない。
- **handover 作成は設計担当の作業**。製造担当は素材整理まで。

### 9.3 CHANGE 通知書起票判断

- 通常は設計書本体の変更を伴わない(CHANGE 不要)。L-02 が DES-006 改訂を伴う場合のみ設計担当が CHANGE 起票を判断(製造担当は起票しない)。
