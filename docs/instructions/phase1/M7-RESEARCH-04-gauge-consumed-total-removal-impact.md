## 0. この指示書の特殊性

### 0.1 製造担当として起動 + 調査だけ実施して閉じる運用

本指示書は **調査担当運用パターン**(architecture-patterns §6)に基づく事実列挙のみの調査依頼。製造担当として Claude Code セッションを起動し、本指示書 §4 の事実列挙を実施 → §5 レポートに記録 → セッションを閉じる。

### 0.2 read-only 厳守

本指示書では **コードの変更は一切行わない**。`view` / `grep` / `git log` / `git blame` / `find` / `ls` / SQL の SELECT などの読み取り系のみを使用。ファイル編集系コマンド(`str_replace` / `create_file` / `bash_tool` の書き込み系)は **使用禁止**。例外は §5 レポートファイル作成のみ。

### 0.3 判断・提案を含めない

調査結果は **事実列挙のみ**(judgement-free)。「削除して安全」「この順で消すべき」「この箇所は残すべき」等の判断・提案・削除可否の結論は **含めない**。観察された事実 + 既存コード状態 + 設計書本体規定との比較 = 設計担当が CHANGE-019 起票判断 + M7-04 指示書スコープ判断に活用するための情報供給のみが目的。**削除可否の最終判断は設計担当 + 開発者が行う**。

ただし以下 2 種類は判断 / 提案ではないため記録する:
- **想定外の発見**(削除対象が想定外の箇所で参照されていた等)
- **明らかな矛盾の事実指摘**(設計書本体規定とコードの不整合、コメントとロジックの矛盾等): 事実として列挙、解釈・解消方針は含めない

### 0.4 本調査の主目的

| 軸 | 主目的 |
|----|--------|
| **§4.1 削除対象の使用箇所網羅** | `drive_gauge_consumed_total` / `sa_gauge_consumed_total`(および camelCase 形 `driveGaugeConsumedTotal` / `saGaugeConsumedTotal`)が **コードベース全体のどこで参照されているか** をバックエンド・フロント・マイグレーション・テスト・i18n を横断して **全数列挙**(削除時に修正が必要な箇所の完全なマップを作る) |

| **§4.3 バリデーション影響の特定** | VAL-C06 / VAL-C07 が削除対象カラムにどう依存しているか + 削除時にバリデーションロジックがどうなるかを事実列挙(設計担当の確認済み事項 = VAL-C06/C07 も廃止方針だが、コード上の依存構造を事実確認する) |

### 0.5 背景(削除方針の経緯)

- M7-RESEARCH-03(2026-05-30)で、`drive_gauge_consumed_total` / `sa_gauge_consumed_total` は **DB カラム・SQL・DTO・フロント型は存在するが、combo_steps から集計して保存するロジックが未実装** = 常に NULL であることが判明した。
- 当初方針(Q11 γ-2 / Q15 温存、M7-02 期間確定)は「M7-04 で集計ロジックを実装してカラムを生かす + VAL-C06/C07 を復活させる」だった。
- **2026-06-02 開発者方針転換**: これら 2 カラムは有意義な情報でないため、使用箇所・バリデーション影響がなければ **削除** とする。集計実装方針(Q11 γ-2 / Q15 温存)は撤回。VAL-C06 / VAL-C07 も設計書本体から廃止予定。
- ただし `moves` テーブルの `drive_gauge_increase` / `super_art_gauge_increase`(ゲージ **増加** カラム)は **今回の削除対象外**(今回の問題から独立、温存する)。本調査でもこれらは削除対象として扱わない(§4.4 で「混同しないこと」を明示)。

### 0.6 結果の扱い

調査結果レポート(`docs/instructions/M7-RESEARCH-04-report.md`)は設計担当 Claude が読んで、以下を判断する材料として使用する:
- 削除の安全性判断(利用者影響のある機能 = ソート / CSV エクスポート等が削除対象に依存しているか)
- CHANGE-019 のスコープ確定(設計書本体 DES-003 / DES-005 / DES-006 のどの記述を改訂するか)
- M7-04 への削除系統の組込方法(製造規模に応じて M7-04-1 / M7-04-2 分割の判断材料)

## 7. 注意事項

### 7.1 read-only 厳守の徹底

本指示書では **コードの変更は一切行わない**。`view` / `grep` / `git log` / `git blame` / `find` / `ls` / SQL の SELECT 等の読み取り系のみを使用。書き込み系は §5 レポートファイル作成のみ例外、それ以外への書き込みは禁止。

### 7.2 judgement-free の徹底

調査結果は **事実列挙のみ**。削除可否の結論・修正方針・推奨は含めない。

事実列挙の典型例:
- ✅「`repository.go` 209 行の INSERT SQL に `drive_gauge_consumed_total, sa_gauge_consumed_total` が含まれる」
- ✅「一覧画面のソート UI 選択肢に『ゲージ消費』順は存在しない」(機能影響の事実)
- ✅「VAL-C06 は `combo.DriveGaugeConsumedTotal` が nil の場合 247 行で早期 return する」(依存構造の事実)
- ✅「`drive_gauge_increase` は `moves` テーブルのカラムで、削除対象 `drive_gauge_consumed_total` とは別シンボル」(区別の事実)
- ❌「このカラムは削除して安全」(判断 = 禁止)
- ❌「VAL-C06 も削除すべき」(提案 = 禁止)

### 7.3 全数性の徹底(本調査の核心)

本調査の価値は **削除時に修正が必要な箇所を 1 件も取りこぼさないこと**。grep は snake_case / camelCase / 部分一致の 3 系統すべてで実行し、ヒットしたファイルを領域別に漏れなく分類する。「調べていない領域」を残さない。判断に迷う箇所は「判断せず事実だけ記録」する(削除可否は設計担当が判断)。
