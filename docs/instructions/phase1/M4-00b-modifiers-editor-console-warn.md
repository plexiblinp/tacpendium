## 4. 詳細仕様

### 4.1 ModifiersEditor への console.warn 発火ロジックの追加

#### 4.1.1 機能要件

- §3.4.2 で特定した対象フィールド(以下「対象フィールド」と記す)の長さが 50 文字を超えた瞬間に `console.warn` を 1 回発火する
- 50 文字以下に戻った後、再度 50 文字を超えた場合は再発火する
- 視覚的 UI 警告(M2-04 §4.1 で実装済み)は維持する(削除・変更しない)
- **M4-00 で RecipeBuilder に追加した console.warn と同等パターン** で実装する(将来課題 §8.3 警告ヘルパフック統一の前提)

#### 4.1.2 実装パターン(M4-00 と同形)

M4-00 §4.1.2 と同構造で `ModifiersEditor.tsx` に追加する:

```tsx
// 既存の ModifiersEditor コンポーネント内に追加
// <対象フィールド名> は §3.4.2 で特定した変数名(例: modifiersNotes、notes 等)
useEffect(() => {
  if (<対象フィールド名>.length > 50) {
    console.warn(`<対象フィールドラベル> が 50 文字を超えています: ${<対象フィールド名>.length} 文字`);
  }
}, [<対象フィールド名>]);
```

- `useEffect` の依存配列は `[<対象フィールド名>]`
- 発火文言は「<対象フィールドラベル> が 50 文字を超えています: N 文字」(N は実際の文字数)
  - `<対象フィールドラベル>` は M4-00 の `draftNotes` に倣い、対象フィールド名そのまま(例: `modifiers.notes` または変数名 `notesValue` 等、§3.4.2 で確定)
- 50 文字以下の場合は何もしない(if 文の else 不要)

#### 4.1.3 配置位置

`ModifiersEditor.tsx` の既存 `useEffect` 群の末尾に追加する。既存ロジック(flags / type / notes 編集系)の動作に影響を与えないよう、独立した `useEffect` ブロックとして追加する。

#### 4.1.4 視覚的 UI 警告との両立(M4-00 §4.1.4 と同方針)

M2-04 §4.1 で実装済みの視覚的 UI 警告(赤ボーダー + 文字数メッセージ)は **維持する**。本指示書は console.warn を **追加** するもので、視覚的 UI 警告は触らない。両者が同じ閾値(50 文字)で発火することで、ユーザーは UI で気づき、開発者はコンソールで気づける構造になる(M4-00 後の RecipeBuilder と対称)。

### 4.2 ModifiersEditor.test.tsx へのテスト 3 ケース追加

#### 4.2.1 追加するテストケース(M4-00 §4.2.1 と同種)

`web/src/features/combo/components/ModifiersEditor.test.tsx` に以下 3 ケースを追加する。既存ケースは変更しない(回帰しないこと)。

| ケース | 入力条件 | 期待動作 |
|--------|---------|---------|
| ケース 1 | 対象フィールドに 50 文字以下を入力 | `console.warn` が **発火しない**(spy の呼出回数 0) |
| ケース 2 | 対象フィールドに 51 文字以上を入力 | `console.warn` が **1 回発火**、警告文言に「50 文字を超えています」が含まれる、N 文字数の数値が一致 |
| ケース 3 | 50 文字超を入力 → 50 文字以下に減らす | 50 文字超時点で 1 回発火、減らした後の追加発火がないこと(spy の呼出回数 1 が維持) |

#### 4.2.2 実装方針(M4-00 §4.2.2 と同形)

- `vi.spyOn(console, 'warn')` を `beforeEach` で設定、`afterEach` でリセット(M4-00 と同方式)
- M4-00 で確立された spy 方式を踏襲(§3.4.4 で確認)
- ケース 2 の文言確認は部分一致(`expect.stringContaining`)で行う
- ケース 3 は React Testing Library の `rerender` または useState を経由した状態変化で実現

#### 4.2.3 テスト構造の例

```tsx

import { render } from '@testing-library/react';

    // ケース 2 の実装
  });

  it('50 文字超 → 50 文字以下に減らした際、追加発火がない', () => {
    // ケース 3 の実装(rerender 経由)
  });

```

完全実装は製造担当が決定する。既存テストとの命名衝突や `describe` ブロックの統合可否は実装時に判断する。
