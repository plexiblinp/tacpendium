## 1. 背景と目的

### 背景

M1-03 でコンボ CRUD API が完成。本指示書ではコンボの登録・編集画面を実装し、M1 完了時に「**ユーザーがブラウザでリュウのコンボを登録できる**」状態を実現する。

ただし、**仮想コントローラはプロトタイプから除外**(SUPP-001 §4.1 M1 最小版定義、M0 指示書での確定方針)で、M1-06 では**仮想コントローラそのものは実装しない**。代わりに「技を選んで追加するシンプルなセレクタUI」で代替する。本格的な仮想コントローラは M2 で実装する。

### 目的

- コンボ登録画面(`/combos/new`)を実装
- コンボ編集画面(`/combos/:id/edit`)を実装
- レシピ入力 UI: **技セレクタUI(セレクトボックス + 追加ボタン + 並び替え + 削除)** で代替
- 編集の2方式分離(PATCH/PUT)に対応 — フロント側で「どちらの方式が必要か」を判定するか、サーバーから返ったエラーで判定するかを明確化
- 重複チェック警告の表示
- バリデーションエラーの表示
- 仮登録モードトグル

### このマイルストーンで作らないもの

- 本格的な仮想コントローラ(M2)
- セットプレイ同時登録(M4)
- 下書き自動保存(M6)
- タグ付けUI の高度化(M3、M1-06 では既存タグから選択するだけ、新規タグ作成は M3)
- 状況・ゲージ等の入力 UI 高度化(M2 以降)

## 4. 詳細仕様

### 4.1 登録・編集画面の URL

- `/combos/new`: 登録画面(空フォーム)
- `/combos/:id/edit`: 編集画面(該当コンボのデータをフォームに事前入力)
- `ComboEditorPage` 1コンポーネントで両ケースを扱う(URL から判定)

### 4.2 基本情報入力エリア(`ComboEditorBasicFields.tsx`)

DES-005 v2.6.0 §5.7 の入力項目に従う:

- キャラクター: 現状リュウ固定(M1段階)、UI 上はセレクトボックスで表示(リュウのみ選択可能)
- ダメージ: 数値入力(任意)
- 状況コード: position、opponent_stance(`any` 含む、CHANGE-003)、hit_type、opponent_size(SUPP-001 §3.2 のラベルマップを使用)
- starter_move_id: レシピ1ステップ目から自動推定 + 手動上書き可能
- ドライブゲージ消費・SAゲージ消費: 数値入力
- knockdown_advantage(有利フレーム): 数値入力(CHANGE-003 でラベル「有利フレーム」、3桁相当の幅)
- 起き攻めBOOLEAN(6個、CHANGE-001): チェックボックスグループ
- メモ: テキストエリア
- タグ: 既存タグから複数選択(新規タグ作成は M3 で実装、M1-06 ではセレクト UI のみ)
- **仮登録トグル**: チェックボックスで `is_draft` を切替

### 4.3 レシピビルダー(`RecipeBuilder.tsx`、本指示書の中核)

#### 4.3.1 UI構造

```
┌─────────────────────────────────────────┐
│ レシピ                                   │
├─────────────────────────────────────────┤
│ [技を選択 ▼] [追加]                       │
├─────────────────────────────────────────┤
│ 1. 立ち弱P     [↑][↓][編集][削除]       │
│ 2. 立ち中P     [↑][↓][編集][削除]       │
│ 3. 中波動拳    [↑][↓][編集][削除]       │
└─────────────────────────────────────────┘
```

#### 4.3.2 技セレクタ

- 「技を選択」セレクトボックスは、現キャラ(リュウ)の技を全表示
- 表示テキストは `name_ja`(M1段階で他言語不要)
- カテゴリ別グループ化(`<optgroup>`)を使うと選びやすい(通常技、必殺技、SA、システム技、ラッシュ版)
- 「追加」ボタンで選択中の技をレシピ末尾に追加

#### 4.3.3 ステップリスト

- 各ステップ行: ステップ番号、技名、修飾情報(あれば表示)、操作ボタン(↑↓編集削除)
- ↑↓ で順序入れ替え
- 「編集」で modifiers を編集するモーダル(または展開エリア)を表示
  - flags の選択(just / delay / link / low_jump)
  - 非技ステップの場合は type を選択(parry_drive_rush / cancel_drive_rush / dash_forward / dash_back)
- 「削除」で当該ステップ削除

#### 4.3.4 modifiers 編集 UI(任意で実装、最小版では省略可)

M1-06 段階では、modifiers 編集の UI を「**ステップ追加時のオプション選択**」程度に簡素化してもよい。

- ステップ追加時に「flags(チェックボックス) just/delay/link/low_jump」を選べる
- 非技ステップは「種別(セレクト) parry_drive_rush 等」を選べる
- 既存ステップの modifiers 編集は、削除して再追加でもよい(最小実装)

これは Plan Mode で開発者と方針確認するのを推奨。

#### 4.3.5 「仮想コントローラはここに M2 で実装」プレースホルダ

レシピビルダーの上部または下部に、薄いグレー枠で「仮想コントローラ(GUIパッド/HitBox/レバーレス/ジェネリック)は M2 で実装予定」と表示しておくと、フェーズ感が伝わる。**これは必須ではなく、開発者判断**。

### 4.4 編集の2方式分離(PATCH/PUT の選択)

M1-03 のサービス層が PATCH/PUT を分けている。フロント側でどちらを呼ぶか判定する。

#### 4.4.1 判定ロジック

クライアント側で「キー変更編集」と「メタデータ編集」を判定する。**判定対象フィールド**(SUPP-001 §2.2 で定義済みの重複判定キー):

- character_id
- recipe(combo_steps の move_id 列 + modifiers の完全一致)
- starter_move_id
- position
- opponent_stance
- hit_type
- opponent_size

これらのいずれかが変更されていれば PUT、それ以外なら PATCH を呼ぶ。

#### 4.4.2 編集前データの保持

- 編集画面マウント時に `useCombo(id)` で取得したデータを **初期値**として React state に保持
- 保存ボタン押下時に、初期値と現在値を比較して変更箇所を判定
- 比較ロジックは `web/src/features/combo/utils.ts` の `hasKeyChanges(initial, current)` 関数として実装

#### 4.4.3 確認ダイアログ

PUT 時(キー変更編集) → 「**この編集はコンボの再登録となります(古いコンボはゴミ箱へ移動)。続行しますか?**」と確認ダイアログを表示。HANDOVER-001 §3.1 の挙動を反映。

### 4.5 バリデーション結果の表示(`ValidationDisplay.tsx`)

API レスポンスの `validations` フィールドを表示:

- `severity = "error"` → 赤色のエラーメッセージ、フォームの該当フィールド付近に強調表示
- `severity = "warning"` → 黄色の警告メッセージ、フォームの該当フィールド付近にアイコン+ホバーで詳細

#### 4.5.1 重複警告(`DuplicateWarning.tsx`)

VAL-C02 が ERROR で返ってきた場合、特別に重複警告モーダルを表示し、「既存コンボの詳細を見る」ボタンで該当コンボに遷移できるようにする(API 側で重複コンボの ID を返してくれるならそれを使う、なければシンプルにエラーメッセージ表示でよい)。

### 4.6 保存時のフロー

1. ユーザーが「保存」ボタンを押下
2. クライアント側で最低限のフォーマットチェック(ダメージが数値か等)
3. 編集の場合、PUT/PATCH 判定
4. API 呼出(POST /api/combos、PATCH /api/combos/:id、PUT /api/combos/:id)
5. レスポンス処理:
   - 201/200 + WARNING 0件 → 成功、コンボ詳細画面に遷移
   - 200 + WARNING あり → 確認モーダル「以下の警告がありますが続行しますか?」
   - 400 ERROR あり → ValidationDisplay で表示、フォームに留まる
   - 409 楽観衝突 → 「他のユーザーが更新したため再読込してください」と表示、再読込ボタン
   - 500 → エラー表示

### 4.7 router.tsx の追加

```tsx
<Route path="/combos/new" element={<ComboEditorPage />} />
<Route path="/combos/:id/edit" element={<ComboEditorPage />} />
```

`ComboEditorPage` は `useParams()` で `id` を取得し、ない場合は新規登録モードとして動作。
