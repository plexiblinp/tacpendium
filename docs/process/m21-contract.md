### 1.3 ★PoC のスコープ（本実装を含まない）

**PoC が答えるのは「実装できるか」ではなく「何を測ればよいかが決まるか」である。**

| # | 測ること | なぜ PoC でないと決まらないか |
|---|---|---|
| **(i)** | **実行環境で Gamepad API がそもそも取れるか** | **取れないなら実機確認が全面的に開発者手番になり、M21 の進め方自体が変わる**（指示書の書き方・DoD・レビュー観点がすべて動く） |
| **(ii)** | **ポーリング周期と入力遅延の実測** | 判定窓の単位が決まらない |
| **(iii)** | **同時押しのズレ幅の分布**（FR107） | **閾値を 1 つ間違えると利用者の入力が黙って落ちる** |
| **(iv)** | **チャタリングの実波形**（FR108） | 同上 |

> **★PoC の成果物に「閾値」を書かせない。「分布」を出させる。**
> **理由**——**測る前に判定法を決めてはならない**（**D-267** ／ **E-123**）。**M19 の見込み値は繰り返し失効した**（除外は 3 行の見込みに対し実測は桁違い／ある案は見積りの 2.7 倍）。
> **同時押し判定とチャタリング対策は、机上で選んだ閾値が「動いているように見えて一部の入力を落とす」型であり、失敗が silent である。**

## 5. 凍結インターフェース

| # | 凍結対象 | 内容 | 崩れたときの症状 |
|---|---|---|---|
| **F-1** | **`recipe_cache` の読み書き契約** | **★M20 が所有する。M21 は読み書きしない**（`parallel-ops` §12 のレーン割り条件 (a)）。**M20 契約の F-1 と同じ条項であり、片方だけ直さないこと** | **M20 は並行性バグの修正そのものを含む。** M21 が同時に触ると **stale の原因がどちらのレーンか切り分けられない** |
| **F-2** | **`preset_id` 単一値の契約** | `RecipeResponse.presetId` ／ queryKey `["combo", comboId, "recipe", presetId]` ／ config `[defaults] preset_id` の形を変えない（**D-291**）。 **★★2026-08-31 に FE 側の実体が判明した**（`M24-08` の実査・`D-619` の検算）——**`combo.recipe` の queryKey は `combo.detail(id)` の invalidate 10 箇所に前方一致で落とされており、これが本契約の FE 側の実体である。** **⇒ `queryKey` を平坦化すると前方一致が外れ、レシピが静かに更新されなくなる。** **★本契約は「モデルの契約であって表記法の凍結ではない」**（**D-619**。**実査 21 箇所でリテラル説を支持する記述は 0 件だった**）——**が、平坦化だけは挙動を変えるため別途の起票が要る。** | プリセット解決の 3 面が同時に壊れる |
| **F-3** | **コマンド入力解決の死守契約 3 点** | **公式表記のみ解決 ／ モーション解析はしない（決定論ルックアップに徹する） ／ 出口は必ずキャラ別 `move_code`**（`phase3-overview` §2.3） | **★物理モーション入力は「モーション解析はしない」と衝突して見える。** **衝突しない**——**段階 1・2 の決定論解決は表記 → `move_code` の索引引きであり、物理モーション入力は「利用者の実入力 → どの技を指したか」の別の問いである。** **ただし出口が `move_code` であることは共通で、これは破らない** |
| **F-4** | **`moves` の意味論と値** | M19 の新列と `is_derived` / `is_aerial` / `is_projectile` の**意味・値・使われ方を変えない** | `setplay` と `punishfinder` の候補集合が静かに変わる |
| **F-5** | **FB⑦ の前提** | **前ジャンプ・垂直ジャンプの move 化は M16 ④ で先行決定済み**という前提に載る。**前提が成立していなければ、独自に決め直さず設計卓へ上げる** | **前提が偽のまま入力系を作ると、入力できる技と登録できる技がずれる** |

| **F-6** | **配信経路の前提** | **採用案は案C＝Go サーバが localhost でフロントを配信し、起動時にブラウザを自動で開く**（`DES-001` §2.3・§6）。**WebView ではない。** **LAN 越しのスマホは `http://<LAN IP>` で到達するため secure context ではない**（`DES-002` §3.2・§3.3・§3.4 の LAN 利用）。**⇒ Gamepad API の取得可否・制約は経路ごとに違いうる。PoC で測るまで断定しない**（**E-117**） | **「WebView だから使える」という案A 由来の前提で設計すると、LAN 経路で silent に動かない面ができる** |

> **★F-3 の「衝突して見えるが衝突しない」は、指示書 §3.4 にも書くこと。**
> **理由**——**製造は契約の全数列挙と突合するため、素直に読むと「モーション解析はしない」に反すると判断して正しく止まる**（**E-105** の逆向き＝**発行側が書かないと適用側が不要に止まる**／**E-79** 「前提」と「順序の指定」を書き分ける）。
