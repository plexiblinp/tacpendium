- **重複判定キー**（`internal/service/combo/duplicate_keys.go`）と**一覧フィルタ**（`internal/repository/combo/repository.go` の単純等値）で **NULL と `any` は別の値**である。

### 7-1. ★★破壊確認 2 は、最初の形では緑のままだった（隠さず記す）

**指示書 §5.3 の予測「E2E (2) が赤くなる」は、当初書いた素朴なケースでは成立しなかった。**

- 当初のケース＝「保存 → 一覧へ遷移 → 確認ダイアログが出ていないこと」。
- **機序**——**通常の保存はプログラム側から `navigate()` で一覧へ遷移する。この遷移は離脱ガードを通らない**（ガードが捕まえるのはリンクのクリック・ブラウザバック・`requestLeave` を通した操作である）。**⇒ dirty が落ちていようがいまいが確認は出ない。何も観測していなかった。**
- **⇒ 観測できる経路へ作り直した**: **1 ステップ目を「技以外」にすると始動技（先頭の *技* から自動で決まる）と食い違い、サーバが `VAL-C03` の警告を返す** → 「保存完了 — 警告があります」で**画面に留まる** → その状態で離れようとする。**保存は済んでいるのだから確認は出ないはずである。**
- 作り直した後、破壊確認 2 は**赤になった**（`★保存が成功したのに離脱ガードが張られたままである`）。
- **`D-572`「期待経路は『壊す対象』からではなく『その観測が何を見ているか』から立てること」の実例である。**

### 7-2. ★harness 由来の赤を証拠にしかけた（記録）

破壊確認 1・3 の 1 回目は `pnpm exec playwright test` を直に叩いたため **`PW_EXECUTABLE_PATH` が渡らず、ブラウザが起動できずに赤**になった。**これはテストが観測した赤ではない。** `PW_EXECUTABLE_PATH=/opt/pw-browsers/chromium` を付けて採り直し、**期待どおりの assert メッセージで赤になることを確かめてから証拠に採った。**
