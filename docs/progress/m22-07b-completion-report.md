## 3. ★第 3 段の位置と、「前 2 段が 0 件のときだけ引く」を構造的にどう満たしたか（§4.3）

**条件分岐ではなく、早期 return の直列で満たした。**

- 第 1 段が 1 件以上を返せば **その時点で return** する。第 2 段も同じ。
- **⇒ 第 3 段のコードへ到達する条件が「前 2 段がいずれも 0 件」以外にない。** 「気をつけて守る」余地が無い。
- **★「もっと積極的に引けば解決率が上がる」形にしていない**（§4.3-2）。上がるとしても、変わるのは利用者が既に登録したレシピの表示である。

**★これを「いま 0 件だから通っている」形で検査していない**（§4.3-3・チェックリスト §1-2）。
`TestThirdStage_DoesNotOverrideEarlierStages` は、**第 1 段（および第 2 段）と第 3 段が同じキーに別々の答えを持つ索引**を合成して組み、**前段の答えが返ること**を主張する。対照として「第 3 段はちゃんと別の答えを持っている」ことも同じテスト内で確かめており、主張が空振りしないようにしてある。

**★実データにはこの状況が存在しない**——素の `SA1` を `alias_text` に持つ行は **0 行**であるため、実データだけを見る検査では段順の入れ替えを検出できない。**合成 fixture が要るのはそのためである。**
