**H-3. 静止した軸を持つ機体で、キャリブレーションが恒久的に進まなくなる**

- **箇所**: `web/src/features/gamepad/components/GamepadCalibrationDialog.tsx:91-100` ＋ `normalize.ts:187-197`。
- **失敗シナリオ**: `detectPressedBinding` は `|axes[i]| >= threshold` を「押されている」とみなす。**静止時に `-1` を返す軸を 1 本でも持つ機体**（Firefox の XInput 系でトリガーが `axes` として静止 −1 で現れる形、および一部 DirectInput 機体の未使用軸）では、`detectPressedBinding` が**毎フレーム非 null を返し続ける**。ダイアログは `pressed === null` になったときだけ `awaitingReleaseRef` を `false` に戻すため、**`awaitingReleaseRef` が永久に `true` のまま**になり、利用者が何を押しても `recordBinding` が 1 度も呼ばれない。画面には「押してください」が出続け、**エラーも警告も出ない**。「この入力を飛ばす」だけが動くため、**全項目を飛ばす以外の操作ができない**＝キャリブレーションが機能しない。
- **なぜ高か**: 本サブの load-bearing な部分は「**我々が持っていない機体で動くこと**」であり（指示書 §4.3・D-328）、この不具合は**まさにその未検証機体（アケコン／Firefox）でこそ発現する。** 開発者手番 1 は所有 2 機種（USB・Chrome）でしか確認しないため、**手番を通しても検出されない可能性が高い。** かつ純粋関数側は厚くテストされているのに、**この押下エッジ判定にはテストが 1 件も無い**ため、レビューが最後の砦になっている。

**H-4. `requestAnimationFrame` ごとに React state を更新しており、レシピ入力面を開いている間ずっと再描画が走る**

- **箇所**: `web/src/features/gamepad/useGamepadPolling.ts:113-115`（`setFrameIntervalMs`）と `:151`（`setSnapshot(toSnapshot(active))`）。
- **失敗シナリオ**: `toSnapshot` は毎フレーム**新しいオブジェクト**を返すため、参照が必ず変わり `setSnapshot` は毎回再描画を起こす。PoC の計測環境は **約 238 Hz**（完了報告 §9）。⇒ コントローラを 1 度押した後は、**利用者が何も操作していなくても毎秒 200 回超の再描画**が `GamepadStatusControl` → `GamepadStatusBadge` ＋ `GamepadCalibrationDialog` に走り続ける。`setFrameIntervalMs` は**コントローラが 1 台も無くても**標本が 60 に達した時点から中央値が動くたびに発火するため、**ゲームパッドを持たない利用者のコンボ編集画面でも**再描画が起きる（`frameIntervalMs` はどの UI にも表示されていない＝現状は完全に不可視のコスト）。

- **修正案**: `snapshot` を `useRef` に持ち、React state として公開するのは**変化したときだけ意味のある値**（`status` / `padId` / `calibrated`）に限る。生スナップショットは購読コールバック（`useSyncExternalStore` か `onFrame(cb)`）で渡す。**既存の `web/src/hooks/useIsMobile.ts` が `useSyncExternalStore` の前例を持つ**（完了報告 §1-4 が実査済み）。`frameIntervalMs` も ref に置き、必要になった時点（M21-02）で取り出す形にする。
