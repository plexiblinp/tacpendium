## 総評

本サブの核心は 2 つ、すなわち「リンクを移したのか増やしたのか」と「保存済みの列設定への当たり方」であり、どちらも実測で押さえられている。とくに束 B について、製造は指示書 §0.2 と設計卓の推し（案 c ＝キーのバージョンアップ）を実装事実で否定しているが、この否定はレビュー側で `useColumnVisibility.ts` を読んで検証した結果、正しい。保存値は `ColumnVisibility` の boolean 9 個だけで並びの情報を持たず、案 c を採ると並びと無関係な ON/OFF だけが捨てられる。設計卓の推しを実装事実で覆し、その根拠を示したうえで開発者へ返した判断は妥当である。

一方で、`DES-005` §5.4 との食い違いの申告が不足している。製造は「アクション」欄の 1 件だけを CHANGE 請求へ回しているが、同じ §5.4 には同型の食い違いが少なくとも 3 か所ある。加えて、実装が §5.4 より進んでいる箇所（コンボ一覧のステータス列）を実査で発見しながら、自分の期待値を直すだけで設計卓へ回していない。設計書の記述だけが旧のまま残る形であり、優先度較正の規定により「高」に置く。

検査の実測値は完了報告の記載と完全に一致した。単体 2,628 件 / 223 ファイル green、`tsc` exit 0、`m31-03` spec 5 passed、`m27-03` spec 8 passed、`check-import-order` の 100 / 101 も一致する。ベースラインを下げなかった判断（`D-388`）も正しい。

残件は Phase C / D 前提の 2 件（`progress-log.md` の索引行・設計伝達レポート）であり、完了報告はそれを断定せず未実施と明記している。`D-510` の型は踏んでいない。
