## 総評

**実装の中身は堅い。** 純粋関数を先に切り出し（`text-filter` / `character-sort`）、共有部品 1 本（`SearchableSelect`）へタグフィルタとキャラ選択の両方を通し、折りたたみは既存 `CollapsibleFieldset` を制御モード化して流用している。**§2.2 の不変対象はすべて守られている**——`DES-005` §4.3.1 の解決順・`combo-list-filters-v1` の読み取りが `character_id` だけであること・`ColumnVisibilityMenu` と `TagSelector` の 0 バイト差分・`internal/` の本番コード 0 バイト差分・`migrations/` 既存ファイルの無改変を、いずれも現物の差分で確認した。`000079` は `characters.name_ja` の 1 セルだけを `UPDATE` し、`code` も技名（`preset_aliases.alias_text` の「不知火流・炎舞仇桜」）も動かしていない。Go テスト 2 本がそれを機械で固定しており、`M-78`（壊す対象の実在）まで assert に入っている。

**一方で「記録」の側に穴が集中している。** 完了報告 §7.3 が緑と書いた品質チェックのうち **2 本が現在赤**（`check-md-emphasis` / `check-progress-log-index`）、§9 の変更統計は最後の 2 コミットを取り込んでいない旧値、§4 の「実測 14 コントロール / 13 ファイル」は自分の表の小計とも grep 実測（13 / 11）とも合わない。**いずれも動作は正しいままなので、テストも lint も型検査も緑になる**——本プロジェクトが「高」に置くと定めた型の指摘であり、そのとおり「高」に置いた。

**指示書 §4.3.1 の分岐表からの逸脱（漢字 1 件でも並び順を実装した件）は、逸脱の記録としては適正である。** 開発者裁定の逐語が §12-1 に引かれ、受容挙動が `character-sort.ts` の冒頭ブロックと 2 本のテストで固定され、禁じられた回避（読み仮名マップをフロントへ持つ／列を足す）はどちらも行っていない。**ただし逸脱に伴って生じた第 2 の食い違いが未報告である**——英語ロケールで並び替えキーが `name_en`、表示ラベルが `name_ja` のままであり、モック §3 の「変更後・英語」列（`C.Viper` / `Dhalsim` …）は as-built と一致していない（高-5）。
