## 3. 判定の公開インターフェース（§7.5-4・**M21-03 / M21-05 / M21-06 がこれに乗る**）

**配置**: `web/src/features/gamepad/stepDetection.ts`（**純粋関数のみ**。`navigator` / `window` / `Date` / `performance` に触らない）

```ts
// --- 判定窓（★唯一の定義。ここを書き換えれば全経路が変わる）---
export const SIMULTANEOUS_PRESS_WINDOW_MS = 90;      // ミリ秒。フレーム数では持たない
export const MEASURED_MAX_PRESS_SPREAD_MS = 45.8;    // D-324 押し始め 最大
export const MEASURED_MAX_RELEASE_SPREAD_MS = 83.3;  // D-324 離し始め 最大

// --- 入出力 ---
interface GamepadSample { result: NormalizeResult; at: number }  // at = rAF の now（単調増加）
interface StepCandidate {
  direction: LogicalButton;   // ★窓の内側で観測された「最後の非ニュートラル方向」
  buttons: LogicalButton[];   // ★決定的な順序（攻撃 6 → マクロ 3）。空にはならない
  startedAt: number;          // 窓の起点（最初の立ち上がり）
  closedAt: number;           // ★時間経過で閉じた場合は startedAt + windowMs ちょうど
  mergedCount: number;        // ★同じボタンの再立ち上がりも数える。buttons.length と一致しない
}
interface StepDetectionOptions { windowMs?: number }   // 既定 = 上記定数

// --- 中核（すべて純粋関数）---
detectSteps(samples, options?): StepCandidate[]        // 一括版。列の終端で強制確定する
createStepDetectionState(): StepDetectionState
pushSample(state, sample, options?): { state; emitted: StepCandidate[] }
flushPendingStep(state, at, options?): { state; emitted }  // ★時間経過で閉じる。押しっぱなしの確定経路
closePendingStep(state, at): { state; emitted }            // ★時間を無視してその場で閉じる
seedSample(state, sample): StepDetectionState              // ★立ち上がりを出さず押下状態だけ取り込む
pendingStartedAt(state): number | null
resolveDirection(cardinals): LogicalButton                 // ★SOCD の判断点。窓を通さない
isDirectionButton(button): boolean
DIRECTION_BUTTON_PREFIX = "direction_"

// --- 副作用層 ---
useStepDetection(options?): {
  steps: StepCandidate[];              // 確定済み。新しいものが先頭・最大 5 件
  onSample: GamepadSampleListener;     // useGamepadPolling(enabled, onSample) へ渡す。識別子は安定
  setProfile(profile): void;           // ★差し替え時のみ次サンプルを種付けに使う
  reset(): void;
}
// M21-01 側（追加のみ）
useGamepadPolling(enabled?, onSample?: (snapshot, at: number) => void)
```

**★後続サブへの申し送り**

1. **時刻は rAF のコールバック引数を渡すこと。** `Gamepad.timestamp` を渡してはならない（§3.3-1・§3.3-3）。判定は ms 単位であり、状態変化時にしか動かない時刻源では窓が壊れる。
2. **`StepCandidate` は SOCD 解決済みの `direction` しか持たない。** 生の上下左右（`NormalizeResult.cardinals`）は含まない。**M21-06（実モーション入力）が生値を要するなら、`NormalizeResult` まで配管を戻す必要がある**（本サブでは足していない——使う当てが無いフィールドを公開インターフェースへ置かないため）。
3. **押しっぱなしのときにステップが確定する唯一の経路は `flushPendingStep`（タイマー）である。** `onSample` は**スナップショットが変化したフレームでしか呼ばれない**ため、最後の立ち上がりのあと指を離すまで次のサンプルが来ない。副作用層を自作する場合は同じタイマーを持つこと。
4. **`mergedCount` は「別のボタンがまとまった数」ではない。** 同じボタンの再立ち上がりも数える。
5. **方向は「まとめる対象」ではないが、窓の内側で観測しつづける。** 集合には加えず、1 つの状態として上書きする（理由は §4-2）。
6. **`useGamepadPolling` のループは 1 本に保つこと。** M21-05（キーボード）は Gamepad API ではないため別経路になるが、**本サブの判定窓をキーボードへ適用するかは M21-05 が決める**（指示書 §1.3）。

## 4. §4.1-3 / §4.1-4 / §4.4 / §4.5-2 の判断と理由（§7.5-5）
