#### 2.6.1 ★実査（指示書 §6-4）— `navigate(-1)` の 3 先例

**素の `navigate(-1)` を呼ぶ画面コードは 0 件だった。** 指示書が言う「3 箇所」は、いずれも **navigation-guard 経由**である。

| # | 場所 | 呼ぶもの |
|---|---|---|
| 1 | `ComboEditor.tsx:877-888`（キャンセル） | `leaveBack()`（`punishReturn` が在れば `leaveTo`） |
| 2 | `SetupEditorPage.tsx:145-155`（キャンセル） | `leaveBack()`（`mode === "create"` なら `leaveTo`） |
| 3 | `SetupEditorPage.tsx:285-289`（更新保存後） | `leaveAfterSaveBack()` |

**★`useUnsavedChangesGuard.ts` は「素の `navigate(-1)` を呼んではいけない」を明記している**（番人の履歴エントリぶんの補正が要るため）。**⇒ 本サブも同じ入口を通した。** `ComboDetailPage` はガードを登録していないため補正は 0 枚だが、**第 2 の流儀を作らないために揃えた。**

#### 2.6.2 ★履歴が無い場合の扱いと、その理由（指示書 §2.6-2）

**「履歴が在れば戻る、無ければ一覧」を採った。**

**★★フォールバックを二重に書いていない**——**`<Link>` の `href` そのものがフォールバックである。** 履歴が無いときは `preventDefault()` を呼ばず、`<Link>` の既定の遷移（`/combos`）に任せる。

**この形を選んだ理由 3 つ:**
1. **戻り先の定義が 1 か所に収まる**（`to="/combos"`）。`navigate("/combos")` を別に書くと、片方だけ直す形が生まれる。
2. **中クリック・別タブで開くが従来どおり効く**（`<button>` に替えると失われる）。
3. **既存の流儀に新しい形を足していない**——`leaveBack` は既存の入口であり、判定は 2 行である。

#### 2.6.3 ★保存後の経路を評価した（レビュー 中-5）

**`一覧 → 詳細 → 編集 → 保存 → 詳細 →「戻る」` は編集画面へ戻る**（着手前は `/combos`）。

**機序**——`ComboEditor` の保存後遷移は `leaveAfterSaveTo("/combos/{id}")` であり、`NavigationGuardProvider` の `replace: true` が置き換えるのは**番人のエントリ**であって編集画面のエントリではない。⇒ 履歴は `[一覧, 編集, 詳細]` となり `idx = 2 > 0`。

**★許容する。** 理由 3 つ。

1. **ブラウザバックと同義である。** 利用者がブラウザの戻るを押しても同じ場所へ行く。**「戻る」が履歴と違う動きをするほうが驚きが大きい。**
2. **編集画面は保存済みの内容を読み直すだけで、未保存の状態を持たない**（保存で dirty は落ちている）。⇒ 戻って困る状態にならない。
3. **避ける形は「編集画面を `replace` で置き換える」だが、それは離脱ガードの履歴管理に手を入れることになる。** 本サブの射程（詳細画面の戻り先）を超え、`ComboEditor` / `SetupEditorPage` の 3 経路すべてに波及する。

**★followup 本文は「一覧→詳細・直接 URL・マイコンボ→詳細 のすべての経路に及ぶ」と述べており、保存後の経路はそこに挙がっていなかった。** 本項はその穴を埋めた記録である。

**★判定材料**＝react-router v6 が `history.state` に持つ `idx`（`NavigationGuardProvider.tsx:68` が同じ前提を書いている）。`0` なら「このタブでの最初のエントリ」＝戻り先が無い。**★判定はクリック時に読む**——描画時に固めると、同じ画面のまま履歴が伸びたときに古くなる。
