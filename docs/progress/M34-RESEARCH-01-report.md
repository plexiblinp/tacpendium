# GoアプリのWindows常駐方式

## 実現したい動作

- exeを直接実行・ダブルクリックするだけで起動する。
- 黒いコンソール窓は出さない。
- Windowsの通知領域（常駐ソフト欄）にアイコンを表示し、稼働中であることが分かる。
- 起動時に既定ブラウザでアプリ画面を開く。ブラウザを閉じてもアプリは動き続ける。
- 通知領域のアイコンから画面を開き直せる。
- 画面内の終了ボタン、またはアイコンの右クリックメニューから、確認を挟んで終了する。

## 実装方式

**GoのHTTPサーバとWindowsの通知領域アイコンを、同じexe・同じプロセスで動かす。操作画面はブラウザに表示する。**

| 要素 | 実装方法 |
|---|---|
| exeの直接起動 | 引数なしの起動を常駐モードとして扱い、HTTPサーバとトレイを起動する。起動用batは不要。 |
| 黒窓の非表示 | Windows向けビルドに `-ldflags "-H=windowsgui"` を指定する。 |
| 通知領域への常駐 | Go標準ライブラリからWin32 APIを呼び出す。`Shell_NotifyIconW` でアイコンを登録し、メッセージループで操作を受ける。 |
| ブラウザ画面 | ローカルHTTPサーバを起動し、そのURLを既定ブラウザで開く。ローカル利用では `127.0.0.1` で待ち受ける。 |
| トレイの操作 | 右クリックに「ブラウザで開く」「データフォルダを開く」「終了」を用意。左ダブルクリックでも画面を開く。 |
| 終了 | 画面とトレイから共通の終了処理を呼び、HTTPサーバを停止してアイコンを削除する。 |
| 二重起動 | ポート使用中の場合に既存の同一アプリかを判別し、既存画面だけを開いて後から起動したプロセスを終了する。 |
| ログ・起動エラー | ログはファイルへ出力し、起動失敗はWindowsのメッセージボックスで知らせる。 |
| CLIとの共存 | CLIのサブコマンド実行時だけ `AttachConsole` で親コンソールへ接続する。 |

Windowsサービスへの登録は不要。ユーザーがexeを起動し、通知領域に常駐させる方式とする。スタートアップへの自動登録は含めない。

## 流用できる実装

`projects/moves-input-tool` で実装済み。デスクトップ統合部分はGo標準ライブラリのみで構成され、本体への移植を想定して分離されている。

- `internal/desktop/`：通知領域アイコン、ネイティブ確認・警告ダイアログ、ブラウザ・フォルダ起動。
- `cmd/movestool/gui.go`：HTTPサーバ・トレイ・ブラウザをまとめる常駐ランチャ。
- `cmd/movestool/console_windows.go`：CLIのコンソール接続と、GUI起動時の不要なコンソール切り離し。
- `scripts/build-windows.ps1`：黒窓を出さないビルド指定と、成果物がGUIサブシステムになっていることの検証。
