## 4. ★論理ボタン層の公開インターフェース（§7.5-4・後続 5 サブがこれに乗る）

**配置**: `web/src/features/gamepad/`

```ts
// --- 入力（DOM の Gamepad 型に依存しない自前形。テストから直接組める）---
interface GamepadSnapshot {
  id: string; index: number;
  mapping: string;                             // ★保持するが判定には使わない
  buttons: readonly { pressed: boolean; value: number }[];
  axes: readonly number[];                     // ★本数を固定で仮定しない
  timestamp: number;
}

// --- 出力 ---
interface LogicalButtonState {
  button: LogicalButton;                       // 既存 controllerTypes.ts の型を再利用
  pressed: boolean;                            // デジタル
  value: number;                               // アナログ（0/1 のみの機体もある）
  source: "button" | "axis" | "derived";       // 斜めは "derived"
}
interface CardinalState { pressed: boolean; value: number; source: "button" | "axis"; }

interface NormalizeResult {
  states: LogicalButtonState[];
  // ★SOCD 相殺・斜め導出を行う前の生の上下左右。M21-02 が別の SOCD 規則を採れるようにする。
  cardinals?: Record<DirectionCardinal, CardinalState>;
  resolved: boolean;
}

// --- ★中核（純粋関数。navigator にも window にも触らない）---
function normalizeSnapshot(s: GamepadSnapshot, p: GamepadProfile | null): NormalizeResult;

// --- 副作用層 ---
function useGamepadPolling(enabled?: boolean): {
  status: "idle" | "connected" | "disconnected";
  // ★入力が変化したフレームでのみ新しい参照になる（静止中は再描画を起こさない）
  snapshot: GamepadSnapshot | null;
  // ★各軸の静止値。押下検出を「静止値からの変位」で行うために要る
  axesBaseline: readonly number[] | null;
  // ★state ではなく getter。観測値の更新で再描画を起こさないため
  getFrameIntervalMs: () => number | null;
};
// ★解決順: 保存済み → 標準配置の既定（mapping === "standard"）→ null（キャリブレーションへ）
function useGamepadProfiles(padId: string | null, mapping: string | null): {
  browserKey: string; profile: GamepadProfile | null;
  source: "saved" | "default" | "none";          // 既定の仮適用中かを UI が知るため
  saveProfile: (p: GamepadProfile) => boolean;   // 戻り値が成否。失敗の通知は呼び出し側
  removeProfile: () => boolean;                  // この機体の登録だけを消す
};

// --- 標準配置の既定 ---
supportsStandardDefault(mapping: string): boolean
createStandardProfile(browserKey, padId): GamepadProfile   // マクロは空で返る

// --- キャリブレーション（すべて純粋関数）---
startCalibration(profile, resume?) / startRetake(profile, target)
startPartialCalibration(profile, targets)          // 一部だけ登録（既定 ＋ マクロ用）
currentTarget(state)                                // state.mode = sequential | single | partial
recordBinding(state, binding) / confirmOverwrite(state) / cancelConflict(state)
skipCurrent(state) / abortCalibration(state) → GamepadProfile / calibrationProgress(state)

// --- 補助 ---
toSnapshot(pad: Gamepad): GamepadSnapshot          // ★ここだけが DOM 型に触れる
detectPressedBinding(snapshot, threshold, axesBaseline?): PhysicalBinding | null
cardinalsToNumpad({up,down,left,right}): 1..9      // 斜めの導出
```

**★後続サブへの申し送り**

1. **★`states` を「押されているものだけ」と読まないこと。** ボタン側は押されている（または `value > 0` の）ものだけが入るが、**方向は割当が 1 つでもあれば常に 1 つ入る**——未入力時も `direction_neutral` が `pressed: true` で入る。方向は「イベント」ではなく「状態」であるため。**型の注記側にも同じ内容を書いてある**（注記と実装が食い違うと後任がそれを複製するため）。
1'. **SOCD（相反する方向の同時入力）は `states` 側で相殺・上優先に潰れるが、`cardinals` に相殺前の生の押下状態が残る。** M21-02 が別の SOCD 規則（例＝後入力優先）を採りたい場合はこちらを見ること。既定の潰し方は**推測であり実測に基づかない**。
2. **`pressed` と `value` の両方が来る。どちらを判定に使うかは本サブでは決めていない**（M21-02 の範囲）。パッドのトリガーは 12 段階、レバーレスは 0/1（D-324）。
3. **同時押しはまとめていない。** 複数ボタンが押されていれば `states` に複数入る。**「複数ボタンが押された」という生の事実を上へ渡すところまでが本サブである**（指示書 §1.3）。
4. **`getFrameIntervalMs()` は観測値であって判定には使っていない。** M21-02 が (β) 実行時の自己校正を採る場合に使える（PoC の計測環境は中央値 4.20 ms ＝ 約 238 Hz）。**★state ではなく getter である**——rAF ごとに state を更新すると入力面全体が毎秒 200 回超再描画されるため。**`snapshot` も入力が変化したフレームでのみ新しい参照になる。** M21-03 で `snapshot` を上位へ持ち上げる際は、この性質に乗ること（毎フレーム新オブジェクトを配ると `VirtualController` / `HitBoxLayout` を含む入力面全体が再描画される）。
4'. **`axesBaseline` は「その機体の軸の静止値」である。** 押下検出は **0 からの絶対値ではなく静止値からの変位**で行う。静止時に `-1` を返す軸を持つ機体（トリガーが `axes` として現れる形）で、押下エッジ待ちが恒久的に固まるのを防ぐため。**キャリブレーション以外で押下を拾う場合も同じ扱いにすること。**
5. **`resolved: false` はエラーではない。** 未登録の機体という正常な状態であり、呼び出し側はキャリブレーションへ倒す。
