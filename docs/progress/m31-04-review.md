`web/src/features/combo/hooks/useControllerInputOmission.ts:41`

当該行（godoc ＋ フィールド宣言）: `/** プルダウンへ並べる技(omitSurfaced=false ならそのまま全件)。 */` ／ `visibleMoves: Move[];`

**本サブで `visibleMoves` は `omitSurfaced=false` でも全件ではなくなった**（`selectableMoves` が `isInputExcluded` を常時落とす）。**動作は意図どおりであり、テストも lint も型検査も緑のまま通る。⇒ 人が読む以外に検出経路が無い。** 後任はこの 1 行を読んで「OFF なら全件」を前提に別の面を作る。

- 併せて見るもの 1: 同ファイル冒頭の解説ブロック（`:15-30`）は**トグルの説明しか持たず、常時除外に 1 行も触れていない**。実体の説明は関数本体のインラインコメントにしか無い。
- 併せて見るもの 2: `omittedCount` の godoc「省かれている件数」も、**常時除外分を数えないこと**が実装コメントにしかない。

**直し方**: `visibleMoves` の godoc を実装に合わせる（例:「プルダウンへ並べる技。`INPUT_EXCLUDED_MOVE_CODES` はトグルに関係なく常に落ちる」）。

**高-2. `isInputExcluded` の godoc が、実装が保証していない範囲を断定している**

`web/src/features/combo/moveSurfacing.ts:99`

当該行（godoc ＋ シグネチャ）: `/** 入力面へ一切出さない技か(タブ・未分類タブ・全技一覧のすべてに効く)。 */` ／ `export function isInputExcluded(move: Move): boolean`

**「タブ」に効くという記述を、実装は 1 か所も持っていない。** 呼び出し元は**2 か所だけ**である——`surfaceBuckets` の `unclassified` 分岐（`:305`）と `useControllerInputOmission`（`:82`）。**`isControllerSurfaced` は本関数を呼ばず、`buckets.common` / `unique` / `superArt` / `targetCombo` / `characterState` の 5 バケットも呼ばない。**

**落ちる形**: 次の担当が `INPUT_EXCLUDED_MOVE_CODES` へ 2 件目を足したとき——たとえば `category='unique'` の code や共通技 13 の 1 つ——**未分類タブとプルダウンからは消えるが、タブには出続けて押せる。** 型検査もテストも緑である。**本ファイル自身が冒頭で「2 か所に書くと片方だけ直されて静かにずれる」と警告している、その形そのものになる。**

**直し方**（どちらでもよい。**選ぶこと自体は製造の裁量**）:
- (a) godoc を実装へ合わせて狭める（「未分類タブと全技一覧に効く。タブ側の述語は本関数を見ない」）。**最小で、いま正しい。**
- (b) タブ側にも効かせる。**★`isControllerSurfaced` の中へ入れてはならない**——「除外＝掲載済み」と読み替わり、`omittedCount` と「ON のとき残るのは未分類タブと一致する」不変条件が同時に壊れる。効かせるなら各バケットの push 直前である。
