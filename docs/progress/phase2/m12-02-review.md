## 設計準拠性レビュー結果

### C-04 エラー位置の統一 ◎
- `SetupEditorPage.tsx`: `<ValidationDisplay result={validationError} />` をフォーム上部(旧 L155 付近)から保存ボタンの直上(L182)へ移動。コンポーネント・props・検証ロジック(`parseSetupApiError` / `handleError` の中身)は不変で、純粋な位置移動。チェックリスト §3「位置のみ」を満たす。
- 保存失敗トーストを追加(L72-79)。これは ComboEditor 側に既存(L345/349/360 で確認)のトースト体験に揃えるもので、検証内容・タイミング・FR305 非ブロッキング方針は変更していない。コンボ側との「統一」が指示書 §4.1 / コミットの明示意図。
- リアルタイム重複検知 `DuplicateRealtimeWarning` は `ComboEditor.tsx` L431 で上部のまま据え置き(別機構)。誤って移動・除去していない(チェックリスト §7・§4 のクリティカル項目クリア)。
- 設計準拠の補足: セットプレイ側の `validationError` は HTTP 400 のサーバ応答由来(保存をブロックする error 系)であり、FR305(コンボの非ブロッキング警告・仮登録中抑制)とは別経路。セットプレイに仮登録概念は無いため、抑制ロジックの対象外で問題なし。

### C-09 キャンセルボタンのスクロール負荷 ◎
- `ComboEditor.tsx` L404-414 に最上部「← 戻る」を追加。`navigate(-1)` で下部キャンセル(L475)と同一挙動。下部キャンセルは温存し「両端化」する方式。end-state「フルスクロール不要で戻れる」を満たす。
- セットプレイ編集は上部「← 戻る」が既存(`SetupEditorPage.tsx` L132-149)のため未変更で妥当。
- 採用方式(両端化)と不採用案(sticky/フローティング)は `Memo_Someday.txt` に明記済み。指示書 §9.2 の「方式選択結果を完了報告に明記」要件を満たす。

### C-13 セットプレイ展開機構の除去 ◎
- `SetupAccordionItem.tsx`: `AccordionItem`/`AccordionTrigger`/`AccordionContent` を撤去し、`<div>` で常時表示化。開閉トグル(▶/▼、`aria-expanded` ボタン)が消滅。
- 行クリック→遷移(`handleRowClick`→`onEdit`)、`onUnlink`、確認ダイアログ(`AlertDialog`)はいずれも維持。テストで「開閉トグル非存在」「行クリックで遷移」「紐付け解除確認ダイアログ表示」「解除で onUnlink(1)」を網羅。
- `ComboDetailPage.tsx`: 親の `<Accordion>` を `<div className="space-y-2">` に置換、未使用 import を除去。
- レシピ表示に `whitespace-pre-wrap break-words` を追加(常時表示で長いレシピの折り返し対策)。範囲内の妥当な追補。
- 使用箇所はコンボ詳細のみで一覧に波及せず、M12-01 と非競合(チェックリスト §4 / §7 クリア)。

### C-15 仮登録トグルの位置 ◎
- `ComboDraftToggleField.tsx`(新設)に表示専用コンポーネントとして切り出し(architecture-patterns §1 のプレゼンテーション層分離に整合)。
- 新規/コピー(`mode !== "edit"`)では `ComboEditor.tsx` L418 で画面最上部(キャラクター欄より前)に描画。編集モードは `ComboEditorBasicFields` 末尾の従来位置を `showDraftToggle` で維持。
- 編集モードの仮登録扱い(`PromoteToFinalButton` 等)は不変。テストで mode=new/edit 双方の描画位置・委譲を検証。
