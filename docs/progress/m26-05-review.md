## 設計準拠性以外の指摘事項

1. コメントがコロンつき行番号で他ファイルを指している箇所が 3 つある（`Step07Password.tsx:40` / `:71`、`Step07Password.test.tsx:99` がいずれも `LanModeConfirmDialog.tsx:50-55` ・ `:118-121` を参照）。現時点の行番号は正しい（確認済み）。ただし参照先が 1 行でも動いた瞬間に静かにずれる種類の記述である。
2. Step 5 の警告は `<p className="font-semibold text-yellow-700">` で見出しを作っており、見出し要素でも `role="alert"` でもない。設定画面側は `AlertDialog`（`role="alertdialog"`）で読み上げが担保されている。ウィザードは「LAN モードを有効にする」を押した瞬間に DOM へ差し込むだけなので、スクリーンリーダー利用者には何も告げられない。本サブの要件が「告げること」そのものである以上、経路の非対称がここに 1 つ残っている。
3. E2E のセレクタは `getByTestId(CONSENT_NEXT)` を使っているが、当該ボタンは「同意して次へ」というアクセシブル名を持ち `getByRole` で取れる。`docs/design/testid-convention.md` のセレクタ優先順位は getByRole 優先である。設定画面側の `lan-consent-enable` と対称にした判断と読めるが、その旨の記載は無い。なお同規約は 2026-09-08 の `CHANGE-171` で「一覧への登録は義務ではない」へ改められているため、付与そのものに規約違反は無い。
4. i18n の新キーを `wizard.step7.*` ではなく `wizard.password.*` に置いたのは正しい（`wizard.step7` は既に「設定完了」を指しており、UI の段 7 とはずれている）。ただしこの off-by-one の罠はコード側にもドキュメント側にも書かれていない。
5. `Step05Network.tsx:44` で `lanHint`（「アクセスできます」）が警告ボックスの直上に残る。指示書 §3-8「足すだけにする」に従った結果であり違反ではないが、LAN 有効時には弱い重複表現が 2 段重ねになる。
6. セキュリティ上の性質として、本ゲートは画面内で閉じている。`PUT /api/config` に `{"server":{"mode":"lan"}}` を直接投げれば同意なしで LAN 化できる。これはチェックリスト §6-2「`A6` の他の実査項目」に当たり本サブの射程外だが、「抜けられない」を UI 層だけで担保していることは記録に残す価値がある。
