## 総評

不変条件（`D-731`）の守り方が本サブの本体であり、そこは要求水準を超えている。運び量の区分を「付けなかった」ではなく「付けられない」形にする破壊確認が 3 層で組まれ、しかも層 1 が vitest では素通りする非対称まで自ら実測して明記している。開発者裁定で PATCH 契約を拡張した逸脱も、原因 1 つ・表現 5 つまで分解して記録されており、承認の範囲を越えていない。
導出の二重化（B-2 / B-3）も、指摘された解釈は妥当であると判定した。ただしその帰結が 2 件（PATCH と PUT で「空にする」の永続結果が食い違う ／ 区分表の Go/TS 二重化が振り分けの正しさを支える載荷になった）残っており、どちらも設計卓への申し送りに入っていない。
一方で、コード外の規律に 2 件の実害がある。**`progress-log.md` への索引行が無く機械検査が赤である**こと、**import 順の後退を 2 ファイル増やしたのに完了報告が「増えていない」と書いていること**である。後者は検査が緑になったのがベースラインの余裕によるものであり、報告の実測値（100）はどの時点の実測とも一致しない。

**どちらも緩めていない。**

| スピナー母数 `9 → 13` | **緩めていない** | 母数を上げただけで、後段の「全数に `appearance-none` が付いていること」という主張は変えていない。増えた 4 欄（始動位置マス数／同％／運び量マス数／同％）は実物と一致する。**このテストは「欄が増えたら気づく」ための母数であり、狙いどおり赤くなった**という説明も正しい |

## 設計準拠性以外の指摘事項

### 1. `progress-log.md` への索引行が無い（機械検査が赤）

`bash scripts/check-progress-log-index.sh` を実行すると **`NG 作業 ID m37-01 が docs/progress/progress-log.md に現れない`** が出る（結果: 違反 1 件）。`git diff --stat 23e0f42 HEAD -- docs/` も `M37-01-completion-report.md` の 1 ファイルしか出さない。
指示書 §6-9 は「完了報告 ＋ `progress-log.md` への索引行」を完了条件に挙げており、`CLAUDE.md` §8 は「サブ完了時の追記は必須」と定めている。完了報告 §6 の「併せて更新が要るもの」表にも索引行の項目が無く、落としたことに気づいていない。

### 2. `formatPositionMass` が日本語をハードコードしている

```ts
return `${value} マス (${percent}%)`;
```

同じ `utils.ts` の 60 行ほど上に、この形を名指しで禁じる注記がある。

> `★語そのものは i18n / ja.json の 1 か所が正典であり、本関数は「どちらの語か」だけを決める。★第 2 の語彙を作らないため、呼び出し側で文字列を組み立てないこと。`

`driveDamageDirectionLabel` はこの規律に従って `Translate` を受け取る形になっている。一方 `formatPositionMass` は語をコード内で組み立てる。呼び出し元は `ComboDetailHeader` / `ComboDetailMetadata` であり、**どちらも `t()` を使う i18n 対象面**である。しかも本サブは `comboDetail.metadata.carryDistanceMass` を `en.json` にも足しているため、**英語では見出しが `Carry distance`・値が `45 マス (28.1%)` という半端な状態になる。**

現状 `web/src/lib/i18n.ts` が `lng: "ja"` 固定で言語切替の導線を確認できなかったため実害は出ていない。しかし `en.json` を保守している以上、債務であることは変わらない。編集画面のラベル（`Field label="運び量"` 等）が固定 ja なのは `DES-005` §5.7 の「編集欄は i18n 対象外」に沿っており問題ないが、**詳細画面は別の面である。**

### 3. 同じ区分を押し直すとマス数が代表値へ戻る

`OptionButtonGroup` の `activate`（`OptionButtonGroup.tsx:79`）は単一選択モードで**常に `onChange(value)` を呼ぶ**（トグルオフしない）。`setPositionBand` は band が空でない限り `startPositionMass` を代表値で上書きする。

⇒ マス数 `85`（`mid_screen` の域内）を入れた状態で「画面中央」ボタンを押し直すと、**マス数が黙って `80` に戻る。** 編集モードでは `position` が変わらないので PATCH が走り、`85` が `80` で上書き保存される。

`D-730` の「従来型（区分を選ぶと閾値の中央が入る）」が意図しているのは**区分を選び直したとき**であり、既に選ばれている区分の押し直しまで代表値で潰すことは要求していない。`setPositionBand` の中で `positionFromMass(Number(value.startPositionMass)) === band` なら `startPositionMass` を触らない、という 1 行のガードで防げる。

### 4. PATCH と PUT で「マス数を空にする」の永続結果が食い違う

`normalizePositionAndMass`（`service.go:1780`）は `Position` があってマス数が無ければ**代表値でマス数を埋める**。呼び出し元は `Create` と `UpdateWithKeyChange` の 2 か所だけで、`UpdateMetadata` は呼ばない。
