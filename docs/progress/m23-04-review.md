## 総評

チェックリスト §9 の重大判定基準 13 項目に該当するものは **0 件**である。最重要ゲート——「警告が付いても復元が中止されない」「`VAL-R01` / `VAL-R02` の非対称が保たれている」「`VAL-R02` が `M23-03` 分割後の *AllowDeleted 側* を使っている」「誤検知を防ぐテスト 3 件が揃っている」——はいずれもコード上で確認でき、しかも **テストが主張として書かれている**(`deleted_at` を直読みして復元の成立を確かめる形)。とくに完了報告 §4.2 の破壊確認(`AllowDeleted` → `Live` へ差し替えて赤くなることの実測)は、「テストが在る」と「テストが効く」を区別した数少ない例であり、本サブで最も評価できる作業である。

設計面の逸脱は見つからなかった。スキーマ・マイグレは 0 本、復元の副作用は不変、`warnings` は復元 2 経路のみで `omitempty` の二重防御、`details` は `M23-02` の形へ寄せてある。作らないと決めた 4 件も理由付きで記録されており、実装への混入も無い。

指摘は「実装が正しいのに記述だけが事実と食い違う」型に集中している。**とくに `progress-log.md` がレビュー結果を実施前に断定している 1 件は、動作もテストも lint も緑のまま残るため人が読む以外に検出経路が無く、本プロジェクトの較正基準では「高」に置く。** それ以外は中 3 件・低 8 件で、いずれも `M24` 着手と並行または将来対応で足りる。

## 設計準拠性以外の指摘事項

### 高-1. `progress-log.md` が、実施前のレビュー結果を既成事実として書いている

**該当**: `docs/progress/progress-log.md`(M23-04 エントリ・コミット `27afb4d`)

```
- **報告**: 完了報告 [`m23-04-completion-report.md`](...) ／ レビュー [`m23-04-review.md`](m23-04-review.md)
...
    5. **★レビュー「高」指摘の不採用は 0 件。**
```

**本レビューを開始した時点で `docs/progress/m23-04-review.md` は存在しなかった**(`ls docs/progress/m23-04*` のヒットは完了報告 1 件のみ)。つまり **リンク先は当時 dead reference であり、「不採用は 0 件」はレビューが行われる前に書かれた断定である**。

**これを「高」に置く理由は 2 つある。**

1. **通常の検査では検出できない。** 動作は正しく、テストも lint も型検査も緑のままである。`check-doc-refs.sh` の走査範囲はルール面ファイル(`CLAUDE.md` / `web/CLAUDE.md` / `.claude/**`)に限られ、`docs/progress/` は対象外なので機械的にも落ちない。**人が読む以外に見つける経路が無い。**
2. **後任は本文をコピーし、注記を読まない。** `progress-log.md` は横断インデックスであり(CLAUDE.md §8)、次サブ・設計卓が「M23-04 は指摘 0 件で通った」を前提として読む。**`M19-DESIGN-08` §3.1 の `D-250` と同型である**——動作が正しいがゆえに、誤った前提だけが複製される。

**求める対応**: 取り込み工程で、本報告書の実測(重大 0 件・高 1 件・中 3 件・低 8 件と、それぞれの採否)へ書き換えること。**「0 件」で結果的に正しくなる場合でも、レビュー後に書き直した事実が要る。**

> **なお、これは実装の欠陥ではない。** 製造 CLI(`implement_plan_full`)が完了報告と索引行を Phase C(レビュー)より前に commit する流れに起因する。**同じ形は M23-01〜03 でも起きうるため、恒常的な是正が要るなら設計卓の手番である**(本レビューは候補提示までに留める)。

### 中-1. 1 つの godoc の中で「§4.1」が 2 つの指示書を指している

**該当**: `internal/service/setup/restore.go` の `Restore` godoc

M23-02 期に書かれたブロック(「案 P1 の撤回により論理削除中も保たれているためである(**§4.1**)」「本サブの適用前に論理削除されたセットプレイは…(**§4.2-6**)」)の直後に、**空行も見出しも無しに** M23-04 のブロック(「★検証の結果で復元を取り消さない(**§4.1**)」)が続いている。**前者の §4.1 は `M23-02` の、後者の §4.1 は `M23-04` の節番号である。**

節番号だけを頼りに引くと、`M23-02` §4.1(紐付けの保持)を読んで「復元を取り消さない根拠」を探すことになる。**`M23-04` 側の行は文書 ID を書いているのに参照だけ裸なので、区切りが無いことと相まって混同しやすい。** 少なくとも `M23-02 §4.1` / `M23-04 §4.1` と文書 ID を添えるか、ブロック間に空行を入れること。

同じ形は軽度ながら `internal/service/combo/service.go` の `Restore` godoc にもある(こちらは `M23-04:` の見出し行があるぶんまし)。
