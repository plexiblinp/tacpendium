## 総評

**射程の管理は本サブの最大の危険どころであり、そこは合格である。** `git diff --stat` は `docs/usermanual/` と `docs/progress/` の 5 ファイルに閉じており、`M37` の影響を受けていない 14 章のうち差分が出たのは `ch03` の 1 文だけ、しかも報告が例外として明示している。本編の削除行は 3 行で全て置換の片側であり、クイックスタートを足す代わりに本編を削った形跡は無い（`I-6` / `0-1b` ／ 実測で確認）。最も落としやすい `ch20` も「影響なし」で素通りしておらず、`CHANGE-205` の 3 つの変化を挙げたうえで本文に当て先が無いことを語の実測で示している——**独立に検証したところ、`ch20` 本文に「発生」は 0 件、「候補」4 件はいずれも件数を述べておらず、製造の主張は正しい。**

**一方で、改稿で*新しく書いた本文*に、画面に存在しない UI の語が 2 件入っている。** `ch05` の「指定なし」（実装の表示語は **「全て」**）と、同じ `ch05` の「レシピキャッシュ再構築」（実装の表示語は **「キャッシュ再構築」**）である。前者は `CHANGE-209` §4 の*説明語*をそのまま UI ラベルとして 3 択に数え上げており、指示書 §4.5 が警告した「対応表を信じきる」型の取りこぼしが、表を疑うほうではなく**表の語をそのまま利用者へ出す**ほうで現れた形である。`ch08` の `onBlur` 補完の説明も、成立しない前提条件（通常入力に数字の欄は無い）を書いている。

クイックスタートは「要約を書かない」という最大の危険を回避できており、各節が画面を名指しして本編へ送る形になっている。ただし **`README.txt` への参照が 1 件フォルダ違い**であり、かつ **`README.txt` 側がまだ配布物に入らないファイル（クイックスタート）を名指ししている**。後者は製造自身が CHANGE 原稿として起票する方針を示しているが、`README.txt` は生成済みの配布ファイルであり、この手番の時点で利用者向けの dead reference が入った状態になっている。
