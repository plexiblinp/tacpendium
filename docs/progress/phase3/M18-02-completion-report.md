## 5. 製造判断(独自確定・要中央確認は無し。いずれも指示書の精神に沿う)

1. **空中技(is_aerial=1)を地上/ダッシュ経由レーンから除外**: 地上・ダッシュ経由は接地始動レーンであり、跳び込み技を「地上始動」に出すと 3 レーンの判定根拠区別が崩れる(偽陽性)。跳び込みはジャンプ経由レーンのみで扱う。指示書 §4.3.3 のレーン区別の趣旨に沿う解釈。
2. **走査ツリーのレスポンス型はサービス層(`punishfinder`)に配置**: 依存方向を正しく保つ(api→service)ため、JSON 契約型を service 側に置き handler は薄く委譲(inputresolve 同型)。
3. **走査専用投影 `ScanMove` を新設**(`model.Move` は非改変): `MoveListItem` は `damage`/`is_projectile` を投影しないため走査に流用不可。`model.Move` 拡張は divergence_test の同期負担があるため専用投影で回避。
4. **移動 move(相手技側)の手動確認レーン露出**: 相手の `dash_*`/`jump_*` は `damage IS NULL` のため規則 b で手動確認レーンに出る(「黙って落とさない」を優先。カテゴリ除外は指示書に無いため足さない)。運用上ノイズになるなら CHANGE で相手技カテゴリ絞りを検討可(要中央)。
5. **CHANGE-083/084 通知書をリポジトリへ配置**: 指示書 §2.1/§3.1 が必読とする通知書が未配置だったため、開発者から受領した正典テキストを `docs/change-notes/CHANGE-083-notification.md`・`CHANGE-084-notification.md` に配置。

**設計反映要点(追加)**: item 5 は指示書 §4.3.2／設計骨子 §3 の相手技除外規則に対する**仕様追加**(移動系・空中攻撃を反撃対象外として完全除外)。DES/指示書 への反映が必要(設計担当 Claude へ申し送り。正式 CHANGE 起票要否は中央判断)。内部の列挙値(lane/verdict)・スキーマは非改変で、表示ラベルのみの変更が中心。

### 8.2 見送り(本レポートに記録・開発者確定)
- **【item 8】レーン別採否は見送り**: 現状 `combo_punish_starters` の verdict は **(自キャラ×相手技×始動技)粒度でレーン非依存**。そのため同一始動技を「不採用」にすると**その場・前方ステップ・ジャンプ経由の全レーンがまとめて不採用**になる。本来は「その場では届かないが前方ステップなら届く」を個別に持てるべきで、是正には `combo_punish_starters` に `lane` 列を追加し UNIQUE を (self, opp, starter, lane) へ拡張する**スキーマ変更**が要る。今回は見送り、将来対応とする(開発者確定 2026-07-24)。
- **【item 3】pruning の解除・再表示 UI は見送り(followup)**: 「反撃できない技として隠す」(pruning 登録)の**解除 BE API(`DELETE /api/combo-punish-prunings`)は M18-02 で実装済み**だが、**FE の解除 UI・隠した相手技の一覧はどのマイルストーンにも設計スコープされていない**(M18-03 は materialize＋採用確定反撃画面で pruning 管理は含まない)。現状、隠した相手技は画面から消え UI 上戻す導線がない。→ **followup: 「隠した相手技」一覧＋解除 UI の設計・実装**を別途起票要(中央へ)。

### 8.3 課題(検討事項)
- **【item 6】自動判定できない相手技に紐づく確定反撃を本画面で表示したい**: 現状、「自動判定できない相手技」(旧・手動確認レーン)には反撃候補のような始動技→コンボのツリーが出ず、その相手技に対して既に登録した確定反撃(`combo_punishes`)を確認できない。手動で確定反撃を登録した後、それを探す画面で見返す導線が無い。→ 表示方法(当該相手技の配下にも採用済み確定反撃を出す等)を今後の設計課題とする。
