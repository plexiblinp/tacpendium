### 5.2 ★正本をプレーンテキストにした理由（**製造判断**）

`D-743` の逐語は「`docs/usermanual/` を正本にして html 化し、`README.txt` はそこから生成する」である。**⇒ 正本を HTML にする読み方もありえた。採らなかった。**

| # | 理由 |
|---|---|
| 1 | **HTML → プレーンテキストの変換器が要る。** 外部ツールを足せば `CLAUDE.md` §6 の新規依存であり、提案が要る |
| 2 | **`awk` / `sed` で自作すると、生成経路そのものが壊れやすくなる。** 本サブが作るのは配布物の必須成果物の生成経路であり、そこに自作パーサを置く判断は割に合わない |
| 3 | **byte 一致で照合できることが §4.4 の担保に直結する。** 変換を挟むと「変換器の揺れ」と「正本のドリフト」が同じ赤で出る |

**★html 化そのものは落ちていない**——操作説明書の本体（`tacpendium-readme.html`）が HTML である。**⇒ `D-743` の「html 化」は器の側で満たし、`README.txt` の生成はテキスト対テキストにした。**

### 5.3 スクリプトの形（`D-766` への当て方）

| モード | 動作 | 終了コード |
|---|---|---|
| **引数なし** | **照合**（正本から生成し直した内容と `README.txt` を byte 比較） | 0＝一致 / 1＝差分 / 2＝実行エラー |
| `--write` | 正本から `README.txt` を生成 | 0 / 2 |
| `--self-test` | 陽性対照・陰性対照 | 0 / 1 / 2 |
