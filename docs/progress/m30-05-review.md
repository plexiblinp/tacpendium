## 設計準拠性以外の指摘事項

### 正規表現そのものの妥当性（レビュー側で `node` 実行して検証）

`STRENGTH_AFTER_DECORATION` = `^(【[^】]*】|\[[^\]]*\])(?:弱|中|強|OD)[・･\s]*` を、実データに無い形も含めて叩いた。

| 入力 | 出力 | 評価 |
|---|---|---|
| `【ジャスト】弱ソニックブーム` | `【ジャスト】ソニックブーム` | 意図どおり |
| `【ジャスト】ODソニックブーム` | `【ジャスト】ソニックブーム` | 装飾直後の OD も落ちる（意図どおり） |
| `（ホールド）弱グラディウス`（全角丸括弧） | 無変更 | 既定は落とさない。§4.4 に合致 |
| `【A】【B】弱X`（装飾 2 連） | 無変更 | 同上 |
| `【A]弱X` / `[A】弱X`（括弧の対応不整合） | 無変更 | 同上 |
| `【ジャスト】 弱ソニック`（装飾と強度語の間に空白） | 無変更 | 同上。実データには無い形 |
| `【A】弱` | `【A】` | 空文字にはならない。`stripped \|\| nameJa` の保険も残っている |
| `弱` / `OD` 単体 | 無変更 | 保険が効く |
| `フェイタル(【ホールド】強フーリガン派生)` | 無変更 | 先頭以外の装飾を見ないことを確認 |

貪欲さの問題も出ない。`【ODセービングフォース】` のように装飾の中に強度語が入る形でも、`[^】]*` が最初の `】` で止まるため誤爆しない。`u` フラグは 3 本すべてに付いている。ReDoS は下記 低-6 のとおり本サブ由来ではない。

**取りこぼしと誤爆の実データ確認**: seed CSV の `special` 1024 行を全走査し、先頭装飾直後に強度語が来る 135 行の「強度語の直後 6 文字」を全数目視した。`中段` `強化` `空中` `中足` のような語頭一致は 1 件も無い。また `【` `[` 以外の括弧類から始まる `special` 名は 0 行である。⇒ 現データでは誤爆も取りこぼしも無い。
