## 総評

チェックリスト §8 の「重大」13 項目はすべて成立している。離脱ガード（`web/src/features/navigation-guard/`）・`editorTabs.ts`・`internal/` `cmd/` `migrations/` の差分がいずれも 0 バイトであることを実測で確認し、タブは CSS 出し分けのまま、`opponent_stance` の既定は `any` のまま、保存ボタンは両パネルの外、幅による分岐（`lg:`）は消えている。E2E の書き換えも 14 spec すべてを読み、**アサーションが減った spec は 0 本**であることを `expect(` の本数比較で裏取りした（削除された `-expect(` 6 行はすべて同一テスト内で等価な観測へ置換されている）。

### 高-1 【撤回済みの記述】`onGoToRecipe` のコメントが、撤回した `onEnd` を指したまま

`web/src/features/combo/components/ComboEditor.tsx:969-971`

**「順送りが末尾を越えたときの行き先」という経路は存在しない。** `useFieldSequence.ts` は `kind === "end"` で明示的に何もせず、完了報告 §6.5 も「当初 `onEnd` を書いていたが、テストが到達しないことを示したので撤去した」と述べている。`ComboEditorBasicFields.tsx:94-99` の Props 側 godoc は正しく「メモ欄の直後に置く『レシピへ』ボタンの動き」だけを書いており、呼び出し側だけが旧の設計を語っている。

### 高-2 【撤回済みの記述】E2E コメントが「Radix Checkbox」のまま

`web/e2e/m15-01-metadata-testid.spec.ts:76`

```

// 折り畳み「起き攻め」節は既定展開(CollapsibleFieldset defaultOpen)のため展開操作は不要。
```

第 2 段で起き攻めは `@/components/ui/checkbox`（Radix）から `OptionButtonGroup` の素の `<button role="checkbox">` へ替わった（`git show 32a5a10:...ComboEditorBasicFields.tsx` に `import { Checkbox }` があり、現行には無い）。同じ spec の 4 行上では「native select からボタン群になった」を丁寧に更新しているのに、20 行下のこの行だけ旧のままである。あわせて `CollapsibleFieldset defaultOpen` も、本サブで 4 節が**制御モード**へ移ったため経路が変わっている（既定が全展開である事実は変わらないが、根拠となる仕組みが違う）。

### 高-3 【未検証の機能衝突】順送りの `↑↓` と数字ショートカットが、物理キーボード入力（`M21-05`）と重なる

- `web/src/features/keyboard/useKeyboardInput.ts:137` — `window.addEventListener("keydown", handleKeyDown, true)`（**capture**）
- 同 `:75` — `if (isEditableElementFocused()) return;`
- `web/src/features/keyboard/editableFocus.ts` — 判定は `:read-write`。**`<button>` / Radix `Switch` は偽**
- `web/src/features/physical-input/PhysicalInputProvider.tsx:423` — `const enabled = surfaceIds.length > 0;`。`VirtualController` はレシピパネル内で**アンマウントされない**ため、基本情報タブに居ても `enabled` は真

M24-04 までの基本情報タブは停止点がほぼすべて `<input>` / `<textarea>` であり、`isEditableElementFocused()` が真を返して物理入力を素通りさせていた。**本サブは `OptionButtonGroup` のボタンと `Switch` を順送りの停止点にしたため、この前提が崩れている。**

キー登録済みの利用者（`Tab` / `Escape` / `Enter` は除外だが、**矢印キーと数字キーは登録可能**——`excludedKeys.ts` の除外表に含まれない。方向入力に矢印を割り当てるのは最も自然な使い方である）では、基本情報タブで次の 2 つが起きうる。

1. **順送りが黙って効かなくなる。** `useKeyboardInput` は自分のキーに対して `event.preventDefault()` を呼ぶ。`useFieldSequence.onKeyDown` は先頭で `if (event.defaultPrevented) return;` としているため、`↓` / `↑` を割り当てた利用者は順送りが動かない（`Enter` は除外キーなので生き残る）。

> 補足: 指示書 §9.1 は「順送りが既存の部品と衝突したときに、**既存の部品側を作り替えること**」を禁じている。したがって是正は本サブ側（`OptionButtonGroup` で `defaultPrevented` を見る／停止点にフォーカスがある間は物理入力を抑止する等）で行うか、**衝突の実在と影響範囲を実測して報告し、開発者判断を仰ぐ**のが筋である。
