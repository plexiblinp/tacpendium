## 2. 実装の形

### 2.1 前置きボタンは論理ボタン層に足すが、判定経路には流さない（★最重要の設計判断）

新しい論理ボタン **`shortcut_prefix`** を 1 つ足し、**既存の `GamepadProfile.buttons` にそのまま格納する**（新フィールドも新ストレージキーも作らない）。⇒ 二重割当の衝突検出・`withBinding` / `bindingOf`・取り直し導線・slug / ラベルがすべて既存のまま効く。

**ただし `normalizeSnapshot` が `states` から分離する** — `NormalizeResult` に `actions?: LogicalButtonState[]` を足し、`ACTION_BUTTONS` に属するキーはそちらへ入れる。

> **★これが要である。** `states` へ混ぜたまま流すと `stepDetection.pressedButtons` が拾ってステップ候補を作り、`classifyButtons` が `unknown_combination` を返す（＝前置きを押すたびに「解決できなかった入力」が読取表示に出る）。分離したことで **`stepDetection.ts` の判定ロジックは 1 行も変わっていない**（`M21-02` の判定不変。**変更は失効していた docblock 3 行のみ**＝§6.1-c）。

### 2.2 操作の配送は既存の調停へ相乗りする

`setActionHandler(id, handler)` を **`setStepHandler` と同じ形で**足し、**owner 1 面にだけ**配送する。`ownerId === null` なら何もしない。**受け手を決める仕組みは 1 行も書いていない。** ★**provider は判定層へ一切効かせない**（v1.2.0 で確定の配管を撤去したため、操作の中身はすべて受け手の面が持つ既存導線が実行する）。

```ts

export interface GamepadActionEvent { action: GamepadActionKind }
export type GamepadActionHandler = (event: GamepadActionEvent) => void;
```

### 2.3 前置きの状態機械（provider・ループは 1 本のまま）

```
prefix 立ち上がり（非latch 時） → latch。以後 detectionOnSample へサンプルを渡さない
latch 中:
  後続ボタンの立ち上がり → 対応する操作を発火 → 解除
  prefix の再立ち上がり   → 取消 → 解除
  2000 ms 経過            → 取消 → 解除
解除時: 最後に観測済みのサンプルで判定側の押下状態を同期する（seedNow）
```

**★ポーリングは増えていない**（`useGamepadPolling` のループは従来どおり 1 本。前置きの判定は既存の `handleSample` の内側に乗せた）。

## 4. 実装中に発見・是正した欠陥

**★テスト作成中に実欠陥を 1 件発見して是正した。**

当初は「前置きから抜けたら**次の 1 サンプル**を種付け扱いにする」形にしていた（プロファイル差し替え時と同じ仕組み）。しかしこれだと、**前置きがタイムアウトで抜けた直後に利用者が押した最初のボタンが種として食われ、入力が 1 つ落ちる**。

⇒ 「抜けた**その場**で、最後に観測済みのサンプルを使って同期する」形（`seedNow`）へ変更した。抜ける契機がサンプルとは限らない（タイマー）ため、最後のサンプルを ref で持っている。

> **★テストが無ければ気づけなかった。** 手で触ると「たまに 1 入力落ちる」形であり、再現条件（タイムアウトで抜けた直後）に気づくのは難しい。

## 4.1 ★前置きを押しっぱなしにしても再武装しない（意図した形・レビュー 中-1）

前置きは**立ち上がり**でのみ latch する。⇒ 押したまま「強K → 強K」と 2 回押すと、**1 回目 = 削除、2 回目 = 強K のステップ追加**になる。**再武装する形（押されている間はずっと前置き扱い）は採らなかった。**

**理由 = 前置きボタンが押されっぱなしになった機体で、入力が恒久的に不能になるため。** 現在の形なら、仮に前置きが張り付いても **latch は 1 度だけ起き、2 秒で自動解除され、以後は通常入力へ戻る**（立ち上がりが来ないため二度と latch しない）。再武装する形だと、**張り付いている間は後続ボタンがすべて操作として吸われ、削除・保存が繰り返し発火する。** 指示書 §4.4「割り当てられない機体でも壊れない形にする」と、削除が最も危険な操作であること（§4.2-2）の両方に反する。

**★ただし利用者から見た自然さは実機の感触で決まる**（§9.2-7 は抜け方を製造へ委ねている）。**⇒ §7 の実機確認へ項目を追加した**（項目 7′）。押しっぱなしで連続操作したい感触が強ければ、「張り付き検出（一定時間以上押されたままなら前置きを無効化する）」を併用したうえで再武装する形へ変えられる。
