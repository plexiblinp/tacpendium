## 2. 根拠（採点設計の出典）

- Anthropic は出力の非決定性を理由に**複数 trial**を実行し、エージェントの発言ではなく**環境の最終状態**を評価するとしている。→ 各条件 3 trial・成果物ファイルでの判定。 <https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents>
- Anthropic の 2026-04 postmortem は、内部試験を通った system prompt 変更がより広い ablation で 3% 低下を示し撤回された事例である。**少数比較は回帰を見逃す。** → §5-2 で本パイロットを確定根拠にしない理由。 <https://www.anthropic.com/engineering/april-23-postmortem>
- OpenAI Codex チームは coverage / restraint / 通常バグの保持 / actionability を併用している。→ 単一指標で採否を決めない。 <https://developers.openai.com/blog/custom-code-review-rules-for-codex>

## 3. 推論（測定値ではない）

1. **旧条件のエージェントは「`docs/handover/` 配下をすべて読め」という指示に実際には従っていない。** `docs/handover/` は 87 ファイル・約 3.0MB（日本語散文で概ね 100 万トークン規模）であり、実測の総消費 168k トークンとは 1 桁違う。**指示が守れない量だったため、旧条件でも実質は選択的読込が行われていたと考えられる。**
2. したがって **① の変更は「読ませる量を減らした」のではなく、「守れない指示を、守れる指示に書き換えた」ものだったと解釈するのが実測と整合する。** 品質が落ちなかったことと、トークンが減らなかったことは、この解釈なら両立する。
3. **正解集合として使えるのは「高」指摘だけである。** 中・低は両条件とも 0/18 だった。これらは「完了報告のこの表にこの行を足す」型のレビュアー固有の判断で、別のレビュアーが同じものを挙げる理由が乏しい。監査 §4-1 が Coverage の正解集合を「高」に限定していたのは妥当な設計だったことになる。
4. **「高」指摘は逆に再現性が非常に高い。** 6/6 が同一の行・同一の修正方向・同一の論理で到達した。機械的に確認できる欠陥（テストの比較区間）だったためと考えられる。
5. **本パイロットの信号は細い。** 実効的な正解集合が 1 件では、条件差があっても検出力が足りない。拡大時は「高」指摘を 2 件以上持つタスクを選ぶべき。

## 5. 未決事項・本評価の限界

**以下はすべて、結論を弱める方向の限界である。**

1. **`CLAUDE.md` の自動ロードは HEAD 版で固定される。** サブエージェントの harness が読むのは HEAD の `CLAUDE.md` であり、旧条件はそこへ削除節を**足し戻す**形で作った。したがって `OLD ⊇ NEW`（`CLAUDE.md` の内容について旧条件が優位）。**これは回帰を検出しにくい向きの保守的バイアスである。** この条件下で新条件が同等だったことは結論を強める方向に働くが、厳密な等価条件ではない。
2. **①（読込構成）と ②（`CLAUDE.md` 縮小）を束ねて測っている**（§J の裁定どおり）。回帰が出ていないため切り分けは不要だったが、**どちらが効いたのかは分からない**。
3. **Restraint は測っていない。** 「指摘なしが正しい安全な反例」タスクを含めていないため、**誤検出が増えていないことの証明にはなっていない**（正解集合外の「高」が 0 件だったのは傍証に留まる）。
4. **実効的な正解集合が 1 件しかない**（§3-3）。中・低が機能しないと判明したため、本パイロットの検出力は「高指摘 1 件を落とすか否か」しかない。**小さい回帰は見逃す。**
5. **汚染リスクを完全には排除できていない。** HEAD の `followup-backlog.md` 等には M19-04b 由来の項目が登録済みで、探索中に目に入り得る。正解ファイル（`m19-04b-review.md`）と `8cd9ba0` 以降のログは明示的に禁止したが、**広く読む旧条件のほうが汚染を受けやすい**。これも旧条件に有利なバイアスである。
6. **n = 1 タスク × 3 trial。** §2 の postmortem が示すとおり、少数比較は回帰を見逃す。**本パイロットは「手順が回ること」と「コスト・信号強度」を実測するのが目的であり、採否の確定ではない。**
7. **新条件は Step 1 の是正（`retrospective-digest` / `change-number-registry` の 2 行追加）を含む HEAD で測っている。** 前段がコミットした時点の新条件そのものではなく、**本セッション時点の新条件**である。
