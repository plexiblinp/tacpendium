## 総評

追補としての骨格は良い。**移動が本当に移動であることは実読で裏が取れた**——`SearchableSelect.tsx` の −38 行と既存 spec の −121 行は `lib/text-drag-capture.ts` ／ `e2e/support/drag-selection.ts` へ 1 対 1 で入っており、消えたまま復活していない行は **1 行だけ**である（高-1c）。部品統合の禁止（`M27-02a` 裁定）にも触れておらず、`useListboxKeyNav` の先例に沿って「操作の実体だけ」を共有している。フックにしなかった判断も、持ち物（state も ref も無い）に照らして妥当である。

一方で、**追補が宣言したテストの役割分担が、実際のファイルに反映されていない**。`text-drag-capture.test.ts`・完了報告 §8.5・設計伝達レポートの 3 か所が「`SearchableSelect.test.tsx` の 4 件は**結線**を見る」と書いたのに、当のファイルは「ここで固定するのは**ガードの条件**だけである」と名乗ったままであり、しかも本体レビュー低-6 で**撤回済みの根拠**（`DES-005` §5.2＝スマホ専用画面）を引き続き掲げている。動作は正しく、テストも型検査も lint も緑であり、読む以外に検出経路が無い。優先度「高」として扱う。

そのほか、`web/e2e/` がどの経路でも型検査されないこと（`web/CLAUDE.md` §3）に由来する見落としが 1 件（未使用引数）、姉妹 spec が明記していた作法を新規 spec が引き継いでいない箇所が 1 件、破壊確認の assert が主張を支えていない箇所が 1 件ある。いずれも完了承認を妨げるものではない。

### 2. `web/e2e/` は誰も検査していない（未使用引数）

`support/drag-selection.ts:290` の `popoverBox(page: Page, input: Locator)` は `page` を使わない。`web/tsconfig.json` は `noUnusedParameters: true` を立てているが `include` が `["src", "vite.config.ts"]` であり、`web/CLAUDE.md` §3 のとおり `web/e2e/` はどの経路でも型検査されない。ESLint も導入されていない（`package.json` の `lint` は `tsc --noEmit` そのもの）。**「規約はあるが対象外」という一番気づけない形**である。`page` を落とすか `_page` にする。

### 3. 姉妹 spec が書き残した作法が引き継がれていない

`m31-02-character-picker-drag.spec.ts:104-105`（`pickFromPicker` 内）に次の注記がある。

> ★`getByRole("option")` を素で使わないこと —— コンボ一覧には native `<select>` の `<option>` が在り、hidden のまま先頭に当たる（初版で実際に踏んだ）。

`m31-02b` はこれを素で 3 か所使っている（`toHaveCount(tags.length + 1)` / `getByRole("option").first()` の 2 か所）。**同じ test の後半（`page.getByRole("listbox").getByRole("option").first()`）では正しく絞っており、1 つの test の中で作法が割れている。**

今これが当たらないのは、`/combos/new` で `<select>` を持つ `RecipeBuilder` が `ComboEditor.tsx:1065` の `activeTab === "recipe" ? "" : "hidden"` によって `display:none` になっており、アクセシビリティツリーから外れているためである。**タブの隠し方が変わった日（`hidden` を `visibility` や絶対配置へ替える、基本情報タブに `<select>` が 1 つ増える）に、件数が合わずに赤くなるか、`.first()` が別要素を掴む。** 追補の主題が「片方の spec だけが古い測り方のまま残る形を作らない」であることに照らすと、**測り方は共有されたが教訓は共有されていない**。

### 4. 破壊確認の assert が主張を支えていない

`m31-02b` の末尾。

```ts
await search.fill(`${STAMP}-z`);
const last = page.getByRole("listbox").getByRole("option").first();
await last.click();
await expect(page.getByRole("listbox")).toBeVisible();
```

`click()` が何も起こさなくても `listbox` は見えたままなので緑になる。完了報告 §8.6 #2 は「マウスでも従来どおり候補を選べること＝緑」と書いているが、**選べたことは 1 度も観測されていない**。`aria-selected="true"` が 3 件になることを見れば、直前の 2 件と同じ道具でそのまま測れる。あわせて変数名 `last` が `.first()` を指しており、名前が実態と逆である。

### 5. サブ番号を名乗るファイル名

## 良かった点

- **移動であることを、主張ではなく形で示している。** コミットメッセージが「新規 4 本はいずれも `+` のみ・deletions 0」と書き、完了報告 §8.8 が `--stat` と移動元 / 移動先の対応表を置いている。レビュー側は `--numstat` の再実行と全行の照合だけで裏が取れた。**`E-225` のチェックを、次に読む者がやり直せる形で残している。**
- **「同じ形である」を数字で言えるところまで測った。** タグ欄 `[0, 9] → [9, 9]` とキャラ欄 `[0, 4] → [4, 4]` を並べ、方向（左と上）まで一致することを示している。**機序が未特定のままでも「同じ機構が効いている」の根拠になる**測り方であり、回避を 2 部品へ広げる判断をこれが支えている。
- **spec を分ける理由を、本プロジェクトの較正から導いている。** 「キャラ用 spec にタグ欄を足すと名前が実態と合わなくなる。本プロジェクトは失効した記述を高として扱うので名前の側を守った」——ルールを暗記ではなく判断基準として使っている。（接尾辞の選び方だけが惜しい＝中-7）
- **`jsdom` の穴を新しい部品でも踏み直していない。** `fireEvent.pointerDown` の属性が黙って落ちる件を `TagSelector` 側でも回避し、しかも「外すと赤になる」を実測して空回りしていないことを確かめている。**「テストを足した」で止めていない。**
- **フックにしない理由を、形式ではなく持ち物で説明している。** 「`useListboxKeyNav` がフックなのは `listRef` を持つからであり、形を揃える理由は無い」。先例に寄せることと、先例を機械的に模倣することを区別できている。
- **後片付けの型を姉妹 spec から正しく引き継いだ。** `deleteTags` へ `CreatedTag[]` を渡し、id の配列を渡すと黙って空振りすることをコメントで残している。`web/e2e/` が型検査されない領域であることを踏まえた行動になっている。
