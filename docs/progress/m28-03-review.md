**根拠:**
- `web/package.json` の `pnpm.overrides` に `"nwsapi": "2.2.25"`（`git diff 56b06cb -- web/package.json`）
- `docs/progress/M28-03-completion-report.md:242` — 「**★JSON にコメントを書けない**ため、根拠は本報告書・コミット `26cfb57`・`progress-log.md` に置いた」

**なぜ高か:** 本プロジェクトの優先度較正どおり、**撤回条件を持たない記述が実装に残る型**である。JSON はコメントを持てず、lock にも理由は残らない。次に `pnpm update` を回す担当がこの 1 行を見たとき、辿れる先は完了報告 1 本だけになる（しかもその報告は「progress-log にある」と誤って案内する）。テストも lint も型検査も緑のままなので、人が読む以外に見つける経路が無い。

**あわせて指摘する形の問題:** 既存の override 4 件はすべて**下限を引き上げる条件付き**の形である。

```
"ws@>=8.0.0 <8.21.0": ">=8.21.0",
"form-data@>=4.0.0 <4.0.6": ">=4.0.6",
"esbuild@<0.25.0": ">=0.25.0",
"@babel/core@<7.29.6": "^7.29.6",
"nwsapi": "2.2.25"          ← 新規。裸・上限固定・自己解除しない
```

上 4 件は「範囲を満たすようになれば実質無害化する」形だが、`nwsapi` は**無条件の exact pin** なので永久に効き続ける。jsdom を上げて `nwsapi ^2.3` を要求するようになったとき、この行は**黙って解決を歪める**（現状 `jsdom@25.0.1` は `nwsapi ^2.2.12` を要求しており 2.2.25 で満たせることは lock `:3524` で確認済み）。

**是正:** 追記先を実在させること（H-1 の索引行、または設計伝達レポート §4 経由で `followup-backlog.md` へ「上流が直ったら外す」候補として登録）。加えて、`web/CLAUDE.md` に override の由来を書く行を足すか、条件付き形（`"nwsapi@>=2.2.26": "2.2.25"` 等）にして意図を宣言することを推奨する。
