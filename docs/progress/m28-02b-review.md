### 高-2: `/combos/affected` を却下した根拠が事実として誤っている

完了報告 §4（§2.3-2 行）・§8-5、およびモック面 3 の注記が、いずれも次のように書いている。

> `/combos/affected` は却下——`web/src/router.tsx` の宣言順で `/combos/:id` が先に来るため、`affected` を id として拾い `ComboDetailPage` がマウントされる

**これは成立しない。** 実装は `react-router-dom` `^6.30.6`（`web/package.json:42`）の `<Routes>` を使っており（`web/src/router.tsx:1`）、v6 の `<Routes>` は**宣言順ではなくパスの specificity でランク付けして照合する**。静的セグメント（`affected`）は動的セグメント（`:id`）より高いスコアを持つため、`/combos/affected` は `/combos/:id` より先に選ばれる。同ファイル内の `/combos/new`（`:28`）が `/combos/:id`（`:31`）と共存して動いていることも同じ仕組みによる。

さらに「宣言順が効く」という前提そのものが誤って伝播すると実害が出る。後任が「順番を直せば直る」と読んで `router.tsx` の行順を入れ替える、あるいは新規ルートを「安全な位置」へ挿し込むといった、意味の無い変更を招く。

**結論（`/game-update/combos` を採る）自体は妥当である**——`/trash/combos/:id` `/punish/list` `/import/combo/helper` の流儀に合っており、チェックリスト §8-2 のとおりルート名の趣味は軽微である。直すべきは**根拠の文**であり、「専用画面は一覧の別名ではなく独立した面なので、接頭辞ディレクトリの流儀に合わせた」といった、実際に成立する理由へ置き換えること。

本指摘を「高」に置くのは、`docs/progress/m28-02b-review.md` の較正基準どおり、(1) テスト・lint・型検査のいずれも検出しない、(2) この文は `DES-005` の新節へそのまま写される位置に在り、後任は注記を読まずに本文をコピーする、という 2 点による。
