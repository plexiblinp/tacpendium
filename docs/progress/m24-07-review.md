## 総評

**本サブの最大の危険であった 2 つの契約——`recipe_cache`／`internal/service/notation/`・`preset/`（契約 F-1）と CSV 列名・ZIP エントリ名（`DES-002` §7.6）——は、いずれも守られている。** `git diff --name-only d9c1770 -- internal/service/notation internal/service/preset` は空であり、`csvcore` の差分は新設テスト 1 本のみである。とくに、**既存の往復テストは列名を変えても緑のまま通る＝契約を守る観測が PR チェック側に存在しなかった、という発見と、その穴を埋める `column_contract_test.go` の新設は、本サブで最も価値の高い成果である**。破壊確認 3 の (a)(b)(c) 三段の出力は、チェックリスト §1-2 が警告した状態が実在したことを示している。

**locale の健全性も高い。** 独立に検証したところ `ja.json` / `en.json` はともに トップレベル 30・leaf 789 で**集合一致**、`{{...}}` プレースホルダの不一致 0 件、en に日本語文字を含むのは `settings.basic.languageJa` の 1 件のみで、これは例外一覧としてテストへ書かれている（コメントで済ませていない）。品質検査 6 本は本レビューで**再実行して同一出力を確認**しており、「回していない検査の結果を報告へ書いた」形跡は無い。テストは 1 本も減っておらず skip も無い（`-it(` の 2 件はいずれもリネーム）。語彙はハード列として扱われ、決まらなかった `SM-016` は実装せず調査だけを残しており、この扱いは正しい。

**一方で、本レビューが「高」に置いたのは 4 件で、うち 3 件は「実装が変わったのに記述・呼び出し側が旧のまま残っている」型である。** とくに、**「4 面」の失効記述**が典型である——製造自身が commit `2c0e4eb` で「この型の失効はテスト・lint・型検査のいずれでも検出できないため『高』として扱う」と書いて是正に着手しながら、**母数を数えずに 3 か所だけ直した**。実測では **28 か所が「4 面」のまま**であり、**是正したファイル自身の内部**（`RecipeText.tsx` 4 行）と、**トグル部品の冒頭コメント**（4 面を名指しで列挙）が取り残されている。指示書 §3.3 が繰り返し求めた「N を数え直す」が、自分の是正作業には適用されなかった形である。もう 1 件（`labelFor` の呼び出し側未追随）は、**`jaLabel` の「キーが引けなければキーを返す」フォールバックに偶然救われて緑になっている**もので、チェックリスト §0.2 が言う「テストが緑であることが根拠にならない」第 3 の場面にあたる。
