## 2. ★止めて報告した事項（2 件）

いずれも指示書が「到達できなければ止まる／回避策を独自に作らない」と定めた経路である。

### 2.1 `go-licenses` が失敗した ⇒ 指示書 §2.1 のフォールバックへ落とした

`go run github.com/google/go-licenses@latest csv ./...` は CSV を **0 行**しか出さず `exit status 1` で終わった。**失敗要因は 2 つ。**

1. **本体に `LICENSE` が無いため自モジュールを解決できない**——**★これは本サブが解こうとしている当の課題であり、循環している。** `LICENSE` を置くのは `CHANGE-151` 反映後（指示書 §4-2）であるから、本サブの時点では原理的に解けない。
2. **`Package embed does not have module info`** が標準ライブラリで多発する。`go-licenses` の最新版 `v1.6.0`（2022 年）が **Go 1.26.4 の標準ライブラリに追随していない**と解される。

同ツール自身の `--ignore` フラグでも要因 2 が残り失敗した。**⇒ 指示書 §2.1 が明示したフォールバック**（`go mod download` ＋ モジュールキャッシュ内の `LICENSE` 読取）**を使った。7 件すべてでライセンスファイルが実在した。**

### 2.2 `govulncheck ./...` が `vuln.go.dev` へ到達できない ⇒ 開発者のローカル実行へ回す

```
$ govulncheck ./...
govulncheck: fetching vulnerabilities: Get "https://vuln.go.dev/index/modules.json.gz": Forbidden
```

**⇒ Go 側の脆弱性列は「クラウド環境では実行不可」。★「脆弱性が無い」ではなく「検査していない」。**

**★既知の偽陽性も対照として再現した**——`govulncheck -version` は走査対象がゼロで DB を引かないため、**403 の環境でも `No vulnerabilities found.` を返す。到達性の証拠に使ってはならない。**

**★followup 台帳の更新は不要。** `govulncheck-not-installed`（§L）は 2026-08-19 に「部分解消」へ更新済みで、追跡は §J の `cloud-env-cannot-reach-vuln-go-dev` が持つ。**本サブの実測はその記録を裏づけただけである。**
