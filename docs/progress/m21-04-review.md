## 設計準拠性以外の指摘事項

### 1. 変数シャドーイング（`GamepadInputProvider.tsx` `dispatchAction`）

```ts
const dispatchAction = useCallback((action, at) => {
  const ownerId = ownerIdRef.current;   // ← 外側に同名の state `ownerId` がある
```

コンポーネント本体に `const [ownerId, setOwnerId] = useState<string | null>(null)` があり、同名でシャドーイングしている。**現状は正しく動くが、この行を消すと「型も lint も通ったまま、1 レンダリング古い state を見る」形に静かに落ちる**（`dispatchAction` は `useCallback` の依存に `ownerId` を持たないため）。`owner` などへ改名するのが安全。

### 2. 文言の正確さ（`GamepadRecipeReadout.tsx`）

`ACTION_LABEL[action] + ACTION_OUTCOME_LABEL[outcome]` の連結で文を作っているため、**修飾操作の成功時が「修飾しました」になる**。実際に起きるのは「修飾の編集ダイアログを開いた」だけであり、利用者は「何かが適用された」と読む。`modifier` だけ別文言にするか、`ACTION_LABEL.modifier` を「修飾の編集」等にする。

### 3. 規約準拠（良好）

- JSON タグ／DTO の camelCase、TypeScript の `strict`、import 順、定数化（マジックストリングは `SHORTCUT_ASSIGNMENTS` / `ACTION_LABEL` の 1 表に集約）はいずれも規約どおり。
- 新規依存の追加なし。
- `TODO` コメントの新規追加なし。
- コメントの密度は高いが、いずれも「なぜそうしたか」であり、規約の求める形。**ただしその密度ゆえに、旧記述が残ったときの毒性も高い**（下記 高-1〜3）。
