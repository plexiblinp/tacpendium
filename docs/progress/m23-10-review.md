## 設計準拠性以外の指摘事項

1. **`escapeDBPath` の方式は妥当。** `url.URL{Path:...}.EscapedPath()` は `encodePath` モードであり、`?`→`%3F` / `#`→`%23` / `%`→`%25` / 空白→`%20` を落とし、`/` と `:` を素で残す。ドライバ（`modernc.org/sqlite@v1.50.0` `conn.go` `newConn`）は `file:` 接頭辞があるとき DSN を切り詰めず、常に `SQLITE_OPEN_URI` 付きで `openV2` する——当方でモジュールキャッシュの実物を読んで裏づけた。**`&` はエスケープされないが、パス部は最初の生 `?` より手前であり、SQLite の URI パス解析でも `&` は特別扱いされないため実害は無い。**
2. **DSN のパラメータ順は結果に影響しない。** `applyQueryParams` は `busy_timeout` を先頭へ寄せ、残りを辞書順に並べ替えてから実行する（同ドライバ `sqlite.go:136-166`）。**現状のアルファベット順の並びに依存した記述はコードに無い**ので問題ないが、「順序は自分で決めているつもり」で書き換えると期待が外れる点は留意されたい。
3. **PRAGMA 適用失敗の検出経路は保たれている。** 旧実装は `conn.Exec` の戻り値で拾っていたが、DSN 形では `newConn` が失敗し `Open` 末尾の `conn.Ping()` が拾う。**`Ping` を残したことが効いている**（消していたら初回クエリまで失敗が遅延した）。
4. **新規依存 0 件**（`net/url` は標準ライブラリ）。ライセンス面の論点なし。
5. **セキュリティ面の後退なし。** 外部入力がそのまま DSN へ載る経路は `config` の `database.path` だが、パーセントエンコードにより `vfs=` 等の SQLite URI パラメータを注入できない形になっており、**むしろ改善している**（旧実装では `?` 以降がクエリとして解釈され得た）。
