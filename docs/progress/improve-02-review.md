### ★7 の詳細（本レビューで最も重い不一致）

`web/src/lib/query-keys.ts` の leaf 定義は **37 件**である（combos 4 / combo 5 / setups 3 / setup 1 / setupCandidates 3 / setplaySuggestions 2 / tags 4 / presets 3 / moves 1 / move 1 / **commandIndex 1** / **motionCommands 1** / punishFinder 2 / punishList 2 / characters 1 / auth 1 / **config 1** / **users 1**）。

- 原因は生成器の awk 規則である。`/^  [A-Za-z0-9_]+: \{/` でドメインを開き、`domain != "" && /^    [A-Za-z0-9_]+:/` でメンバーを拾う構造のため、**`queryKeys` 直下のインデント 2・`{` を開かない定義**（`commandIndex:` / `motionCommands:` / `config:` / `users:`）はドメインにもメンバーにも該当せず、黙って落ちる。
- **完了報告の「実測 28 → 33 件、正本の定義名との全数突合で取りこぼし 0 を確認した」は成立していない。** 突合の母集団自体が「ネストされた 2 階層の定義」に限られていたと考えられる。
- 実害がある。**投入プロンプト §作業 4 が名指しした `CONFIG_KEY` / `USERS_KEY` は、いまや `queryKeys.config` / `queryKeys.users` である。旧 const 表は消えたが、新表にもこの 2 つが載っていない。⇒ 該当領域の情報が派生資料から純減した。**
- 新設の警告（`END { if (n < 30) … }`）は閾値 30 に対し 33 のため沈黙する。**完了報告 §7-2 #8 が「件数下限の警告を足して暫定対処した」と書いているが、本件はその暫定対処をすり抜けた実例である。**
