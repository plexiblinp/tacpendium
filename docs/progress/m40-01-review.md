## 総評

本命である射程 2 は満たされている。三層に「来歴の軸」という受け皿が実際に立ち、当てはめは「置く場所が無い」ではなく「どこへ落ちても著作権者の宣言が偽になる」という精度で実測されている。evidence もファイル単位の判定表を持ち、値打ちと損の両方が書かれている。当方の独立実測（40 桁 hex の全量走査とローカル commit 解決テスト）でも判定表の数字は 1 件も外れていなかった。
一方で、本サブが新設した機械の門には実効性の穴がある。`REUSE.toml` から shadcn の宣言ブロックを丸ごと削っても `check-third-party-attribution.sh` は緑のままであり、自己検査も同じ穴を素通りする。いずれも実リポジトリと変異版スクリプトで再現を取った。
加えて、開発者確定 5 点目の適用によって `REUSE.toml` の論拠コメントに失効した逐語引用が 1 件残った。撤回済みの記述がコード上に残る型であり、本プロジェクトの較正では「高」である。
不合格 8 項目のうち、差し戻しに当たるもの（§0-1 / §0-3）は無い。

## 設計準拠性以外の指摘事項

### 高-1. `REUSE.toml` に失効した逐語引用が残っている

`REUSE.toml:145-147` が (6) を立てる論拠として次を引いている。

```
#       「本 repo の MIT」であって「第三者の MIT」ではない(LICENSES/MIT.txt の逐語＝
#       "Copyright (c) 2026 plexiblinp")。
```

`LICENSES/MIT.txt` は本サブの後段（開発者確定 5 点目）で `Copyright (c) <year> <copyright holders>` へ戻されており、**引用された逐語は現物に存在しない**。当方の全文検索でも、この文字列を持つ追跡ファイルは `REUSE.toml` と完了報告だけであった（完了報告側は「戻した」という経緯の記述なので正しい）。

失効した記述であるうえ、**軸を立てた論拠そのものとして置かれている**。次に `REUSE.toml` を読む担当は、層 C の MIT に著作権表示が入っている前提で判断を組む。テストも lint も型検査も文書を見ないため、人が読む以外に見つける経路が無い。較正基準どおり「高」。

★直し方の案: 逐語引用を落とし、「層 C の MIT は `REUSE.toml` の `SPDX-FileCopyrightText` が示す本 repo の MIT であり、`LICENSES/MIT.txt` 本文は著作権表示を持たないテンプレートである」という現在の事実へ書き換える。`NOTICE` §6 には既に正しい説明が在るので、そこを参照する形でもよい。

### 高-2. 新設検査が、守るはずの最大の回帰を素通りする

**実測（実リポジトリで再現。確認後にファイルは元へ戻し、`git status` が空であることを確かめた）。**

`REUSE.toml` から (6-T1) の shadcn ブロックを丸ごと削除して `check-third-party-attribution.sh` を回すと、次のようになる。

```
OK  来歴ブロック 1 個を検出
OK  グロブ `docs/seed-data/**` → 追跡ファイル 8 件
OK  NOTICE の件数が実測と一致(`web/src/components/ui/**` = 21 件)
結果: 違反なし
```

EXIT=0 である。理由は 2 つ。

- **R2 は「来歴ブロックが 1 つ以上」しか見ない。** T2 が残っているので緑になる
- **R7 は NOTICE の件数と*ファイルの実数*を突き合わせるだけで、そのグロブが宣言されているかを見ない。** 宣言が消えてもファイルは 21 件のままなので緑になる

結果として、shadcn の 22 ファイルは既定ブロック `path = "**"` へ静かに戻り、`© 2026 plexiblinp / AGPL-3.0-or-later` と宣言される。**これは本検査が塞ぐと宣言した `D-777` の一般形そのものである。** スクリプト冒頭の限界節は「宣言されていない第三者素材が新しく持ち込まれたことは検出できない」と正直に書いているが、ここで起きるのは「既に宣言したものが消えた」であり、限界節が免責している範囲の外側にある。

★直し方の案（どれか 1 つで足りる）。

- `NOTICE_COUNT_RULES` のグロブが、来歴ブロックのいずれかの `path` に含まれていることを必須にする（含まれていなければ赤）。対照表を 1 つ増やすだけで済み、既存の構造に乗る
- あるいは「守るべきグロブの固定表」を持ち、その各要素が来歴ブロックに在ることを見る（`check-migration-license.sh` の凍結表と同じ型）

### 高-3. 自己検査の陽性対照が、対象の規則を隔離していない

**実測。** R3 の `fail(...)` を潰した変異版スクリプトを作り `--self-test` を回したところ、**7 対照すべてが期待どおりと判定され「自己検査: 合格」を返した。**

原因は陽性対照 1 の作り方にある。`vendor/ui/` の 2 ファイルを外へ `git mv` すると、R3（グロブ 0 件）と R7（NOTICE の件数 2 に対し実測 0）が**同時に**赤くなる。よって R3 が消えても対照は赤いままであり、**D-777 を塞ぐ当の規則の消失に気づけない。**

あわせて **R1（version）と R2（来歴ブロックが 0 個）に陽性対照が無い。** R2 は高-2 の穴と対になる規則であり、対照が無いまま残っている。

★直し方の案: 陽性対照 1 の擬似リポジトリでは NOTICE の件数記述を移動後の実数へ合わせておき、**R3 だけが赤くなる形**にする。R2 用に「来歴ブロックを 1 つも持たない `REUSE.toml`」の対照を 1 つ足す。

### 高-4. 22 ファイルの outbound 宣言が AGPL から MIT へ変わった事実が報告に無い

本サブ以前、`web/src/components/ui/**` と `web/src/lib/utils.ts` は既定ブロック (1) に解決しており、宣言は `AGPL-3.0-or-later` / `© 2026 plexiblinp` であった。(6-T1) の新設により、この 22 ファイルの `SPDX-License-Identifier` は `MIT` になる。

vendored な上流コードを上流のライセンスで宣言すること自体は妥当であり、宣言を変えろという指摘ではない。問題は次の点である。

- **本体側の改変分も同じ宣言に含まれる。** `dialog` / `alert-dialog` / `sheet` の `ModalPresenceMarker` 組み込みと `sonner` の差し替えは本プロジェクトの著作物であり、(6-T1) はそれを MIT で提供すると宣言している
- **開発者が Plan Mode で確定したのは「(a) 軸を足す」であって、「本体の改変分を MIT で出す」ではない。** roles-and-routing のハード列「公開に関わる判断」に当たる
- **完了報告にこの帰結が 1 行も無い。** §2.1 の表は「変更前は宣言が偽であった」までを書き、変更後に何が何へ変わったかの前後表が無い

★直し方の案: 宣言は現状のままでよいので、完了報告と設計伝達レポートへ「22 ファイルの宣言が `AGPL-3.0-or-later` から `MIT` へ変わり、本体側の改変分も MIT で提供される」という前後の事実を明記し、開発者へ諮ること。並記された `2026 plexiblinp` を残すか、識別子を併記の形にするかも、諮るなら同じ手番で。

### 中-2. 「二重の防壁」が機械で結ばれていない

`LICENSES/LicenseRef-Tacpendium-NotForDistribution.txt` は「実装の側は `public-snapshot-manifest.txt` の `DENY docs/seed-data/**` であり、片方だけが外れたら食い違いが見える」と述べるが、**見えるのは人が両方を読んだときだけである。** `check-third-party-attribution.sh` は manifest を 1 行も読まない（当方でスクリプト全文を確認）。`DENY` 行が消えても本検査は緑、`check-public-snapshot.sh` も「公開対象が増えた」だけなので緑である。

★直し方の案: R5 の隣に「`LicenseRef-` ブロックの各パスに対応する `DENY` 行が `public-snapshot-manifest.txt` に在ること」を足す。文字列一致で足りるうえ、陽性対照も `DENY` 行を 1 行削るだけで作れる。
