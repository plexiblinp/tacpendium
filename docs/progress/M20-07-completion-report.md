## 2. ★採った正規化の範囲と、採らなかった範囲の理由（§4.1-4）

**判定規則は「同一キャラ内で、異なる `move` が同じ正規化キーへ落ちる組が 1 組でもあれば採らない」**（§4.1-5）。全 4,184 行を走査して数えた。

### 2.1 採った範囲（第 1 段 `aliasnorm.Normalize`）

| 範囲 | 同一視 | 理由 |
|---|---|---|
| **NFKC** | **0 組** | 全角括弧 `（）`→`()`・全角数字 `１`→`1` の幅の差を吸収する。**これが D-307 の本体である** |
| **前後空白の除去** | **0 組** | 貼り付け由来の空白を吸収する |
| **大文字小文字の畳み込み** | **0 組** | `Back Microwalk` と書かれた英語表記を拾うため（裁定 3） |

**3 つを同時に掛けても 0 組である**（`NFKC+trim+lower` で distinct キー数は `NFKC+trim` と同じ 3,444。両列を投入しても 3,495 で衝突 0）。

### 2.2 第 2 段のみで落とすもの（`aliasnorm.NormalizeRelaxed`）

| 範囲 | 同一視 | 扱い |
|---|---|---|
| **末尾の `(SA1)` `(SA2)` `(SA3)` `(CA)`** | **17 組**（技データを持つ全 17 キャラ） | **第 1 段が 0 件のときだけ引く。第 2 段でも 1 件のときだけ確定する。** ⇒ 17 組は 2 件になって未解決へ倒れ、候補として人へ提示される |

**17 組はすべて同じ形である**——**Critical Art と SA3 が同一コマンドで、注記だけが両者を区別している**（例 guile `[4]646K (CA)` と `[4]646K (SA3)`、ryu `236236K (CA)` と `236236K (SA3)`）。**`(SA1)` `(SA2)` は 1 組も衝突しない**（衝突は CA と SA3 を**同時に**落としたときにだけ生まれる）。

> **★第 2 段に衝突があること自体は欠陥ではない。** **利用者が注記を省いた入力は本質的に曖昧であり、「2 件 → 未解決 → 人が選ぶ」が正しい応答である。** **欠陥になるのは片方を勝手に選んだときであり、そこは「1 件のときだけ確定」が構造的に塞いでいる。**

> **★★第 2 段で注記を落とすのは辞書側だけである**（**レビュー指摘 高-1 で是正**）。**入力側の注記は落とさない。**
>
> **実装当初は入力側にも落としていた。** その形だと、利用者が **`236236P (SA3)`**（ryu には実在しない組み合わせ。SA1 が `236236P`・SA3 は `236236K`）と書いたとき、**入力の `(SA3)` を落とした `236236p` が SA1 に 1 件で当たり、書かれていない技へ確定していた。**
>
> **★これは本サブが最も警戒していた形そのものである**——**第 1 段の衝突検査は 0 組のままで、動作は「解決できた」ように見え、既存のどのテストも赤くならなかった。** **⇒ 「緩めた側の失敗は赤くならない」という本サブの前提が、第 2 段の入力側という想定外の経路から現実になった。**
>
> **第 2 段の目的は「利用者が注記を省いた入力を拾う」ことであり、「利用者が書いた注記を無視する」ことではない**（裁定 1 の文言に沿う側を採った）。回帰テスト `TestLookup_RelaxedStageDoesNotStripTheUsersOwnTag` で固定した（対照として、注記を省いた入力は従来どおり拾えること・正しい注記つきの入力は第 1 段で確定することも同テストで主張する）。

### 2.3 ★採らなかった範囲と理由

**「NFKC を掛けた」だけでは、次の担当が「もっと広げてよい」と読む**（§4.1-4）。⇒ 広げてはいけない範囲を実測値つきで残す。

| **`(SA3)` / `(CA)` を第 1 段で落とすこと** | 17 組 | 第 2 段でのみ落とす（裁定 1） |

| **`alias_text` のデータ書き換え** | — | **D-307** で採らないと決定済み（§1.3-1）。`preset_aliases` の行の値は 1 つも変えていない |

**★上記は `internal/aliasnorm` の package docstring と `TestNormalize_DoesNotStripDistinguishingSuffix` に写してある**（完了報告だけに置くと、次の担当はコードしか読まない）。

## 3. 正規化の前後で解決できるようになった件数と、その数え方（§7.5-3）

**件数: 36 組の `(キャラ, 技)`。**

### 数え方

1. **今日の照合述語は byte 完全一致**である（`WHERE pa.alias_text = ?`・`c.code` でスコープ・全プリセットを `SELECT DISTINCT m.code` で union）。⇒ **verbatim に存在しない入力は 0 件を返す。**
2. `alias_text != NFKC(alias_text)` の **38 行**を取り、各行について `K = NFKC(alias_text)` を作る。**`K` は「利用者が半角／ASCII の IME 状態で打った文字列」そのものである。**
3. **`K` が、同一キャラの別の行の生の `alias_text` として既に存在するか**を調べる。存在するなら今日でも解決できており、増分にならない。⇒ **38 行すべてで存在しなかった（0 件）。**
4. したがって 38 行はすべて「今日は 0 件・変更後は 1 件」になる入力である。**`(characters.code, moves.code)` の distinct へ畳むと 36 組。** 38 → 36 の差は m_bison の `psycho_mine_auto_detonation` 1 技が 3 プリセットに重複していることによる。
5. **決定論は保たれる**——§2 の「NFKC で同一視 0 組」により、36 組はいずれも**ちょうど 1 件**へ解決する。**新たに曖昧になる入力は生まれない。**

**内訳（5 キャラに集中）**: ingrid 17 ／ mai 8 ／ guile 5 ／ jamie 5 ／ m_bison 1。形は `弱ソーラーフレア（前方）`・`OD花蝶扇（ホールド）`・`ODソニッククロス１`・`魔身（酔い+1）`・`サイコマイン（自動爆発）`。

### 第 2 段（SA / CA）による増分

**SA / CA 注記を持つ行は 132 行**（numeric 66 ／ srk 66 ／ official 0。`SA1` 38・`SA3` 34・`CA` 34・`SA2` 26）。注記を省いた入力について:

- **1 件に解ける**: `(SA1)` `(SA2)` を持つ技 ⇒ **番号なしで解決できるようになった**
- **2 件に割れる**: CA と SA3 の 17 組 ⇒ **未解決のまま候補 2 件として提示**（今日は 0 件で候補も出なかったため、**「候補が出る」ぶんは改善であり、確定はしない**）

### 大文字小文字の畳み込みによる増分

**`alias_text_en` の 15 種はすべて小文字 ASCII** であるため、`Back Microwalk` のような大文字混じりの英語入力が解決できるようになった。**日本語側の増分は無い**（かな漢字は畳み込みの影響を受けない）。
