## 設計準拠性以外の指摘事項

### コーディング規約

- **`m19p2CharScope`（`migrate_m19p2_test.go:284`）が宣言されているが一切参照されていない。** Go は未使用 const をコンパイルエラーにせず `go vet` も検出しないため、そのまま残っている。CLAUDE.md §4「不要なコード（コメントアウト含む）は削除する」の趣旨に反する。あわせて直前のコメントが `// charScope は…` で始まっており、**godoc 規約（識別子名で始める）とも不一致**。
- それ以外は良好。マジックナンバーはすべて名前付き定数化され、根拠がコメントで示されている。`console.log` / `fmt.Println` の混入なし。コミットは Conventional Commits 形式（`feat(M19-PHASE2/migrations)` 等）で、三点更新が 1 コミット 1 点に分割されており事故時の切り戻し粒度として適切。

### SQL

- `000064` の D セクションは `INSERT ... SELECT` で親を `IN (...)` に束ねている。**親行が 1 つも無ければ 0 行投入で成功する（サイレント no-op）**が、そのリスクはヘッダに明記され、テストが 63 対を子 × 親で個別固定しているため塞がっている。良い設計。

- `000065` に `IS NULL` ガードが無い点はヘッダで明示的に正当化されている（「値の付け替えであって空欄への投入ではない」）。契約 F-4 (2') の (c) は「CSV 以外を一次源とする**転記**」に掛かる条件であり、既存値の**是正**には適用されないという読みは妥当。

## 良かった点

1. **canary の全数差分が、第三者が再現できる精度で書かれている。** SHA256 2 値・節点数・13 始動技の節点数まで、本レビューの独立再測定と**1 つの例外もなく一致**した。数字を「測った」と書くだけの報告とは質が違う。ここまで再現できると、レビューは「主張の妥当性」ではなく「事実」を検査できる。
2. **マイグレを①②に分けた効果が実際に出ている。** ①の直後で射影が byte 一致したことで、「候補集合を動かしたのは②の 20 行だけ」が行単位で言えている。D-223 の設計判断が空振りに終わっていない。
3. **指示書の誤りを 3 件、実装を止めずに正しく処理している。** ken ノーマル版「4 行」→ 実体 3 行（`name_ja` を根拠に判別）、`wall_jump` の内部整合破れ（裁定を仰いだ）、`drink_level_4_ransui_haze_2_retreat` が一致（21 対象 / 20 変化の切り分け）。いずれも**推測で埋めず、根拠を示して報告**している。
4. **「投入しなかった行」の固定が本物である。** `m19p2UnknownRemaining` は 15 行を理由付きで列挙し、さらに「system と c_viper / dhalsim を除いた `unknown` の全数がこのリストと一致する」ことまで検査している。`SUPP-001` §5.5 (3) の「件数だけでは規則を広く当てすぎても検出できない」への、形式ではない対応。
5. **CSV に一切のノイズが無い。** 17 本すべてで `git diff` 行数と論理変更行数が一致した。D-218 が警告した手入力ツール往復の事故（空欄 → `false`、列順入れ替え）を完全に回避しており、専用スクリプトの要件 5 つが結果として証明されている。
6. **不確実な箇所で手を止めている。** jamie `freeflow_strikes` 系 16 行の親参照は、非飲酒版と飲酒版で「単発」を指す `move_code` の付き方が反転しており親が一意に定まらない——**誤ってもエラーにならない**（`SUPP-001` §5.5 (4)）ため推測せず報告に回した、という判断は正しい。lily `condor_dive_follow_up` / rashid「アサルト・ロール」も同様。
7. **down の非対称を「なぜそう書くか」ごと残している。** `000064` down のヘッダにある「C の down で `startup IS NULL AND startup_basis = 'unknown'` を使うと c_viper / dhalsim 18 行と `is_derived = 1` の 7 行を巻き添えにする」という説明は、次に触る人が同じ穴を踏まないための最良の形。
8. **ガードの所在を 3 件、ファイル名 + 行番号 + テスト名で明記している**（D-189）。`is_projectile` の 104 と 135 を別定数として書き分け、M19-04c で一度落ちた転用を繰り返していない。
9. **チェックリスト自身の欠陥（対の指示書名の誤り）も報告に上げている。** 自分の成果物の外にある不整合まで拾う姿勢は、`§12` が求めている自己矛盾検査の実践そのもの。
