## F-1. バグ#6: セットプレイ登録の VAL-S02 全幅表示

### 手順
1. 任意のコンボ詳細 → 「セットプレイ追加」→ セットプレイ登録画面へ。
2. レシピ（ステップ）を空のまま「保存」を押下。
3. **期待**: バックエンドが 400 + VAL-S02 を返し、フォーム上部に `ValidationDisplay` が**全幅**で表示される（「ボタンのような形」に崩れない）。エラーバッジ `VAL-S02` とメッセージが見える。
4. レシピを 1 ステップ以上入力して再保存 → 正常に登録され、コンボ詳細へ戻る。
5. セットプレイ編集画面でも同様にバリデーション/409 衝突表示が機能することを確認。

## F-5. L-04: ポート競合フォールバック（配布構成 = embed 単一バイナリ）

> M7-06 で配布構成（フロント embed 済み単一バイナリ）に整合（M7-05 Q3 保留分の解消）。
> dev の `go run` ではなく、配布される単一バイナリ（`make build` で生成、`-tags=embed_web`）
> を起動し、同一オリジン（`http://localhost:<actual_port>/`）でフロントが配信されることを確認する。

### 手順
1. フロント embed 済み単一バイナリをビルドする（`make build` → `./combomgr`、または配布物の実行ファイル）。
2. 既定ポート 47318 を別プロセスで占有する（例: 別ターミナルで `python3 -m http.server 47318` 等、あるいは別の combomgr インスタンス）。
3. 単一バイナリを起動する（`./combomgr`。dev の `go run` は使わない）。
4. **期待**: 起動ログに「configured port is in use; using fallback port」警告 + `actual_port=47319`（次の空き）が出力され、サーバーがフォールバックポートで起動する。
5. **期待**: `config.toml` の `[server].port` が採用ポートに書き換わる。
6. **期待**: 実ポートでブラウザが自動起動する（NFR303/304）。自動起動できない環境では起動ログ末尾に案内 URL（`http://localhost:<actual_port>`）が出力される。
7. ブラウザで `http://localhost:<actual_port>/` に直接アクセスし、同一オリジンでフロント全体が表示・動作することを確認（Vite dev server / proxy を介さない）。
8. 占有プロセスを解放し、`config.toml` のポートを戻すか確認。

### 結果

## U-1. スマホ LAN 実機検証（開発者がホスト OS で実施）

> コンテナ環境制約により製造担当は手順整備のみ。開発者がホスト OS で直接起動し、LAN 内スマホ実機からアクセスして結果を記入する（M6-04 で未検証だった分）。

### 手順
1. `config.toml` の `[server].mode` を `"lan"` に設定（または設定画面/ウィザードで LAN モードを有効化）。
2. ホスト OS（コンテナ外）で combomgr を起動（`go run ./cmd/combomgr` またはビルド済みバイナリ）。
3. 起動ログ（起動フォルダ logs/ 配下）で bind アドレス `0.0.0.0:<port>`、許可 Origin（`http://<LAN-IP>:<port>` を含む）、および "LAN access: open one of these URLs..."（検出 IP 候補の URL 列挙）を確認。
4. **（前提）ファイアウォール/ウイルス対策ソフトで本アプリの inbound を許可**しておく。許可前は PC 自身でも `http://<LAN-IP>:<port>/` が開けず、スマホからも到達不能(サーバーにログが出ない)。詳細は配布物 README.txt「スマホから接続できないとき」を参照。**サードパーティ AV（例: Norton）が Windows FW を代替制御している場合は AV 側で許可が必要**（2026-06-06 開発者環境で実確認）。
5. まず PC 自身のブラウザで `http://<LAN-IP>:<port>/`（localhost ではなく LAN IP）が開けることを確認。
6. 同一 LAN 上のスマホ実機ブラウザで `http://<ホストの LAN IP>:<port>/` にアクセス。
7. **期待**: ホーム/コンボ一覧/詳細/マイコンボ等の主要画面が表示・操作できる。
8. 設定画面の QR コード表示からスマホでアクセスできることも確認（任意）。
9. 許可してもアクセス不可の場合は、その旨と環境を記録（§13.2「検証不可能の場合は事前承認で未検証のままフェーズ1完了と明示記録」が適用可能）。
