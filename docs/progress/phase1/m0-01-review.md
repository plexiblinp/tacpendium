## 総評

10画面すべて作成済みで、ツリー構造・セットプレイ展開・仮想コントローラプレースホルダ・名前NULLフォールバック表示といったM0の主要確認ポイントは概ね適切に実装されている。Tailwind CDN使用・外部ライブラリ不使用・ブラウザストレージ不使用のコード品質基準も全ファイル遵守されている。

一方で設計書との細部不整合が3点確認された。とくに「起き攻め情報が7項目設計に対し6項目表示」は combo-detail.html と combo-editor.html の両画面で共通して発生しており、M1 実装時のデータモデル参照に影響しうるため高優先度で確認を推奨する。

## 設計準拠性以外の指摘事項

### レイアウト品質

- 全 PC 向け画面で `max-w-7xl` または `max-w-5xl` / `max-w-4xl` が使用されており、1280px 想定の幅制御が適切。
- `font-bold` / `text-lg` / `text-sm` / `text-xs` によるフォントサイズ階層が全画面で統一されており、情報階層表現は良好。
- home-mobile.html は `max-w-[414px]` + 固定フッターナビで明確にスマホレイアウトを実現しており、PC ブラウザで縮小表示してもモバイルらしく見える構造になっている。

### ダミーデータ妥当性

- combo-list.html の15件ダミーはツリー構造要件（▼展開3件・▶折りたたみ2件・仮登録2件）をすべて満たしている。
- ダメージ範囲は 800〜3500 でSF6の実態範囲内。ゲージ消費は 0 または -2 と妥当。
- **指摘**: counter_type の多様性が不足。全15件中、パニカン 1件（#8）のみで、カウンターヒットの例が存在しない。また opponent_stance「しゃがみ」の例がない。フィルタ機能の視覚確認用データとして多様性改善を推奨。

### コード品質

- 全ファイルで `<script src="https://cdn.tailwindcss.com">` を使用。Tailwind CDN 以外のライブラリは使用なし。✓
- shadcn/ui・lucide-react 等の依存ライブラリは使用なし。✓
- JavaScript の実質的なコードが存在せず、`localStorage` / `sessionStorage` / `IndexedDB` の使用なし。✓
- `console.log` の残存なし。✓
- `_shared.css` に `font-family` のみを集約するシンプルな設計。Tailwind でほぼ賄えているため妥当。

## 推奨修正（優先度別）

### 高（M1着手前に修正必須）

1. **combo-detail.html / combo-editor.html: 起き攻め情報7項目の確認・修正**
   - 設計書（DES-005 §5.6, §5.7）は「7つのBOOLEAN」と明記しているが、プロトタイプでは6項目しか表示されていない。
   - DES-003 データモデルで7つの具体フィールド名を確認し、不足の1項目を特定してプロトタイプに追記する必要がある。M1 のデータモデル実装・UI 実装に直接影響する。

2. **settings.html: デフォルトプリセット名の整合確認**
   - プロトタイプ内の選択肢名（`official_en_move`, `community_ja` 等）と SUPP-001 §3.4 の仕様（`official_ja_command`, `numeric_ja`, `numeric_en`, `srk`）が一致していない。M1 の seed データと突き合わせて表示名を確定させること。

### 中（M1着手と並行可）

3. **combo-detail.html / combo-editor.html: situation JSON（キャラ固有状態）エリアの追加**
   - DES-005 §5.6 の表示項目4「situation JSONの中身」、同§5.7 の項目5「situation JSON（キャラ固有状態、動的に表示）」に対応するエリアが未表示。
   - フェーズ1リュウのみ対応時点ではNULLのため、空状態の表示イメージとしてプレースホルダを追加する程度でよい。

4. **my-combo.html: ソートオプションに「ドライブゲージ消費」「SAゲージ消費」を追加**
   - DES-005 §5.5 ではコンボ一覧と同様のソートオプションを持つことが明記されているが、マイコンボ画面のソートプルダウンには4種類しかない（一覧は6種類）。

5. **combo-list.html: ダミーデータの多様性補完**
   - カウンターヒット（counter_type = counter）と相手スタンスしゃがみ（opponent_stance = crouching）のコンボ例を各1〜2件追加することを推奨。

### 低（将来対応）

6. **trash.html: 各コンボ行への詳細画面リンク追加**
   - DES-005 §5.15「行クリック → 詳細表示（読み取り専用のコンボ詳細）」に対応する `<a>` タグが未実装。視覚的なアクション確認用として `combo-detail.html` へのリンクを追加することを推奨。

7. **first-run-wizard.html: ステップ位置について設計変更通知書の検討**
   - SUPP-001 §2.5 は「ユーザー名入力ステップを追加」とのみ記載し位置を指定していない。プロトタイプではステップ3（ようこそ→言語→**ユーザー名**→キャラ→プリセット→LAN→完了）としているが、DES-005 §5.1 の元ステップ順（ようこそ→言語→キャラ→プリセット→LAN→パスワード→完了）にパスワードステップが今回省略されている。ステップ順の正式確定のため CHANGE-XXX 通知書の発行を検討。

## 良かった点

- **ツリー展開構造の実装が精度高い**: DES-005 §5.4 の `▼/▶` 展開構造・インデント付きセットプレイ行が仕様通り3展開2折りたたみで実装されており、視覚確認が容易。
- **SUPP-001 §2.4 のフォールバック表示**: combo-detail.html のセットプレイ3件目に名前NULL時のフォールバック表示（レシピ先頭30文字+…）が明示的なHTMLコメント付きで実装されており、後続開発者が意図を把握しやすい。
- **仮想コントローラプレースホルダの視認性**: combo-editor.html・setup-editor.html ともに `height: 300px` のグレー矩形枠＋「M1で実装」テキストで明確に示されており、スコープ外であることが一目で分かる。
- **first-run-wizard.htmlのステップインジケータ**: プログレスバー＋ステップ名テキスト＋現在位置ハイライトで、ウィザード全体の構造が1画面で把握できる。
- **combo-compare.htmlの差分ハイライト**: ダメージ最小を赤、最大を緑、ステップ数・ゲージ消費の大小も対称的に色分けされており、比較目的が視覚的に明確。
- **コード品質の徹底**: 10画面すべてで外部ライブラリ依存なし・localStorage不使用・console.log不使用のルールを完全遵守している点はM1以降の実装の手本となる。
- **home-mobile.htmlの固定フッターナビ**: `fixed bottom-0` + `max-w-[414px]` の位置固定でPC表示時もモバイルUIらしい挙動が確認できる。
