### 6.2 軽微な問題（完了承認可、改善推奨）

**[軽微-1] LAN モード表示テストが `<IP>:<port>` 形式を直接確認していない**

- **指示書の記述**（§4.1.4）: `mode === "lan"` 時、表示文字列が `<network.primaryLanIp>:<port>` 形式であることを確認する
- **実際のテスト**（SettingsPage.test.tsx L113〜118）: `screen.getByText("192.168.1.100")` で IP 単体のみを確認
- **実際のコンポーネント**（SettingsSectionNetwork.tsx）: LAN モードでは「接続先 IP アドレス」行に IP、「ポート番号」行にポートが別々に表示される（M6-02 既存実装）。`<IP>:<port>` を 1 要素に結合する行は存在しない（LAN URL 行は `http://<ip>:<port>` 形式の URL を表示）
- **判定根拠**: M6-04 は LAN モード既存ロジックの変更を禁止しているため、コンポーネント実装は正当。テストは実装を正しく反映しているが、指示書 §4.1.4 の文言（`<IP>:<port>` 形式）との乖離が残る。軽微な記述不整合と判断（チェックリスト §11 第4項に相当）
- **対応提案**: 次回マイルストーン以降の改善余地として記録。対応不要であれば m6-to-m7-handover に明記。

**[軽微-2] "ポート番号" ラベルと表示値の意味論的不整合**

- **実装**（SettingsSectionNetwork.tsx L28-32）: ローカルモード時に `t("settings.network.port")` = "ポート番号:" ラベルが "127.0.0.1:47318" を表示する
- **指示書の概念コード**（§4.1.3）: ローカルモード用ラベルとして "接続可能 IP / ポート:" を例示していた
- **判定根拠**: 指示書の概念コードは「(製造担当が実装で確定)」と明記されており規範的ではない。また指示書 §2.4(a) 「1〜2 行の表示文字列修正」という最小変更方針との整合を考えると、既存ラベルを維持したことは合理的。機能上の問題はなく、軽微と判断（チェックリスト §11 第2項に相当）
- **対応提案**: ラベルを `t("settings.network.localAddress")` などに変更することで意味論的に改善可能。m6-to-m7-handover で i18n キー追加と合わせて対応するか、開発者に判断を委ねる。
