## 総評

**設計準拠性は高い。** チェックリスト §8 の差し戻し事由（重大 1〜17）に該当するものは **0 件**である。とくに最重要項目である `§4.3`（カスタムプリセット優先）は、固定表 `noInputDerivedTargets` が `internal/seedgen` 内の非公開シンボルに閉じており、表示・逆引き経路からの参照が実測で 0 件であることを確認した（`grep` による呼出元追跡 ＋ `Test_P34_NoPresetIndependentFixedTable` が「行を消せば値も消える」ことを機械で担保）。値の正しさも、13 件すべてを `character_data/*.csv` の `name_ja` と直接突合し、**全角括弧を持つ m_bison の 1 件を含めて完全一致**を確認した。生成物は `-check` で再生成と byte 一致することを実機で再現できた。

**破壊確認の質が高い。** 1 回目の破壊確認で `Test_P34_CustomPresetWinsOnDisplay` が赤くならず、原因が「テスト側がステップに `MoveCode` を持たせていなかった」＝**空振りするテスト**であったことを自力で特定し、実態へ揃えて再確認している。チェックリスト §4-3 が求める「別の機構が代わりに守っている」の疑い方も、`csv.go` の `validate` を特定した実例として報告に残っている。

**一方で、指摘の中心は「否定形確認（§4.7）の網から漏れた失効記述」である。** 走査そのものは 2 軸で回されているが、**grep が行単位であるため複数行にまたがるコメントを取りこぼしており**、`internal/repository/preset/write_repository_test.go` に「`alias_text_en` を持つのは `micro_*` の 2 code・38 行」という**現在は偽の記述**が残っている（実測 51 行）。本プロジェクトの較正どおり「高」に置く。それ以外は中〜低であり、**M20 完了前に必須の修正は 1 件**である。

### A. 失効した記述がコード上に残っている（**否定形確認 §4.7 項目 3 の漏れ**）

**`internal/repository/preset/write_repository_test.go:130-140`**

```go
	// ★alias_text_en が複製されていること(指示書 §4.3-3)。numeric は
	// micro_forward / micro_back の 2 code に英語表記を持つ。
	...
	if enCount == 0 {
		t.Error("alias_text_en が 1 行も複製されていない(numeric は 38 行持つはず)")
	}
	t.Logf("複製実測: %d 行(うち alias_text_en 非 NULL = %d 行)", copied, enCount)
```

- 本テストは `dbtest.Setup(t)`＝**HEAD スコープ**である。本レビューで実行した実測は次のとおり。

  ```
  write_repository_test.go:141: 複製実測: 1258 行(うち alias_text_en 非 NULL = 51 行)
  ```

- **`numeric` の `alias_text_en` 非 NULL は 38 行ではなく 51 行**（移動系 38 ＋ 層 C-3 の 13）。コメントの「`micro_forward` / `micro_back` の 2 code に英語表記を持つ」も、エラーメッセージの「38 行持つはず」も、**本サブの投入によって偽になった**。
