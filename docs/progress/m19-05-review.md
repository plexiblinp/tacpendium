## 設計準拠性レビュー結果

### 1. 費用規則 4 分類（`M19-DESIGN-07` §2-1 ／ 指示書 §2.2 ／ CL §5.1〜§5.4）— ◎

- `buildProposal`（`internal/service/setplay/service.go:724-779`）で 4 分類が正しく現れている。分類 1＝前置親を `Counted=false`（`:744`）、分類 2＝合成単位 Total に内包、分類 3＝エンジンの `S = Σ単位 total + target.Startup`、分類 4＝単発／末端。**上から順に判定する形**が保たれている。
- **恒等式は壊れていない。** 前置親は `sumFiller` にも `sg.TotalFrames` にも寄与しないため S を汚さない。`assertIdentities`（`cost_test.go:42-58`）が `S` ／ `N = KA+2−S` ／ `Landing = KA+1` を固定。`G = 1 − N`（撤回済み）は本番・テストとも 0 件（完了報告 §6 で走査済み。当方でも再確認）。
- `rush_variant` に新規の手は入っていない（CL §0.3 N-5 のとおり仕様）。分類 2 の判定は `chain_cancel_total` 非 NULL ∧ 隣接のみで決まり、modifiers 等の特記に依存しない（CL §5.4 ○）。
- **軽微**: `assertIdentities` の `G = N − active` は `p.Mode == ModeGap` のときだけ検査するが、`cost_test.go` に **gap モードのケースが 1 つも無い**ため、**新しい費用規則の下で G 恒等式を通す経路が固定されていない**。G 恒等式自体は M19-02 の `refine_test.go:240` が押さえているが、そちらは合成単位も前置親も通らない。gap × 合成単位の組み合わせを 1 ケース足すのが望ましい。

### 2. 合成 filler 単位（同 §2-2 ／ 指示書 §2.3 ／ CL §5.5・§5.6）— ○

- 単位 total ＝ Σ非末端の `chain_cancel_total` ＋ 末端の `total` が長さ 1／2／3 で固定されている（`cost_test.go:162-193`）。budgetCap での自然終端も固定（`:197-221`）。エンジン（`setplay.go`）は無改修＝区分 2 が守られている（CL §5.7 ○）。M19-02 の資産（受理帯・ランキング後の打ち切り・gap・`n_max`）は非接触（CL §5.8 ○）。
- **ザンギエフ特例が書かれていない**（CL §4.8 ○）。「単独入力不可のグループ員があればその集合、無ければグループ全員」という性質による一般化で、2 分岐とも実データで発生し対で固定されている（`TestCost_CompositeUnit_ZangiefRapidGoesSecondOrLater` ／ `TestCost_CompositeUnit_NoSoloUnavailableMember`）。差し込んだ行自身の値を読むこと（15+12=27）も固定（CL §5.6 ○）。
- **△ 探索の枝刈りが厳密には保守的でない**（`service.go:537-550`）。`total = partial + *c.Total` が `budgetCap` を超えたときに `continue` しており、**その `c` を非末端として更に伸ばす経路ごと捨てている**。`chain_cancel_total < total` である以上、`partial + cct(c) + total(d) ≤ budgetCap < partial + total(c)` となる `d` が理屈上は存在しうる（成立条件は `total(d) < total(c) − cct(c)` ＝実測では 4〜5F 未満）。**現行データでは `total(d) ≥ 12` のため取りこぼしは発生しない**が、これは「実測値に依存して偶然安全」であり、コード上の根拠が無い。コメントで前提を明示するか、`partial + cct(c)` 側で別途枝刈り判定するのが安全。
- **△ 合成単位の生成量に上限が無い**（後述の「推奨修正 高」を参照）。`maxChainLen = 8`（`service.go:457`）は長さの上限であって**個数の上限ではない**。`budgetCap = KA + 2` は KA に比例して緩むため、KA が大きいほど `|グループ員|^k` が素直に立ち上がる。**KA は VAL-C10 が WARNING のみで、−600〜+600 は警告すら出ずに保存できる**（`internal/service/validation/combo.go:293-301`）。KA=600 では 3 員グループで長さ 8 まで全展開し、単位数は Σ3^k ≒ 9,840（zangief も同規模）に達する。これは**エンジンの枝刈りが効く前に確定的に発生する構築コスト**であり、その後 1 万件規模の候補が subset-sum に渡る。
