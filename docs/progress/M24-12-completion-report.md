## 6. キーボードの順送り（§4.4）

### 6.1 キーの割り当てと理由（§9.2 で実装判断に委任された範囲）

| 操作 | 割り当て | 選んだ理由 |
|---|---|---|
| 次へ / 前へ | `Enter` `↓` / `↑`、`Tab` | `Tab` は `OptionButtonGroup` へ **roving tabindex** を入れて「群全体で 1 停止」にした。**★無いとポジションだけで `Tab` を 6 回押すことになり、「Tab で次の欄へ」が成立しない** |
| **メモ欄** | **★★無効** | `Enter` は改行、`↓` はカーソル移動であってほしい（`D-578`(5)）。抜けるのは `Tab` かクリック |
| **数値入力の `↑↓`** | **★奪わない** | **ブラウザ既定の増減が使えなくなるためである。** 数値欄は 6 つあり、刻んで入れることが多い。**⇒ `Enter` では進む** |
| ボタン群の選択 | 数字 `1`〜`9` `0` | 上限 10。**★数字では次へ進まない**——複数選択（起き攻め）では続けて何個も押すため。**⇒ 単一選択も同じにして挙動を 2 種類作らなかった** |
| Boolean（キャラ固有状態の flag） | `Space`（ネイティブ）＋ **`1`＝ON / `2`＝OFF** | **★★2026-08-29 是正。当初は `Space` だけにしており、それが実装漏れだった**——**指示書 §4.4 は「Boolean は `Space` に加え `1`＝ON / `2`＝OFF」を求めていた**のに、完了報告のこの行で「独自キーを足していない」と*判断として*書いてしまい、指示書からの逸脱として扱っていなかった。**⇒ 開発者の実機確認（2026-08-29）で「キーボードでオンオフできない」として顕在化した。** ★`Space` は Radix `Switch` のネイティブ動作で効いていたためユニットも E2E も赤にならず、**押して初めて分かる形だった**。★off は `false` ではなく `undefined`（既存の消去意味論）。★`defaultPrevented` を見て `M21-05` との二重発火を避ける |
| ハイライト | **`focus-within` で描く**（薄い水色 `bg-sky-100`） | **★state ではなく CSS。** 「ハイライトも一緒に移る」がフォーカスの移動そのもので満たされ、位置を二重に持たなくて済む。**クリックで直接触ったときも同じように光る**ので、「編集モードで順送りを強制しない」とも噛み合う |

### 6.2 ★★キャラ選択・タグ選択との衝突（§3.3-7 / §4.4.3）— **衝突は実在した。解けた**

**★Radix の `PopoverContent` は Portal で body 直下へ描くため DOM 上はパネルの外にあるが、React の合成イベントは React ツリーを辿って上がってくる。⇒ 何もしないと、候補を選ぶ `Enter` / `↓` を順送りが奪う。**

**⇒ 物理的にパネルの中に居るときだけ効かせる形にした**（`rootRef.current.contains(target)`）。**★Radix の内部実装（`data-radix-popper-content-wrapper` 等）に依存していない**ので、Radix の更新で壊れない。

**★`useKeyboardInput.ts` の `isEditableElementFocused()` は流用しなかった**——`<button role="option">` は editable ではないため素通りする。

### 6.3 ★★停止点は DOM から採る
