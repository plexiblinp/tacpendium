## 1. 選定基準

要件定義書（REQ-001）から導出した技術選定の判断基準を、優先度順に整理する。

| 優先度 | 基準 | 根拠（要件ID） |
|--------|------|----------------|
| 1 | 前提ソフトウェアなしでインストール・起動できる | NFR303, NFR304 |
| 2 | 低リソース消費でゲームと同時起動可能 | NFR002, NFR003 |
| 3 | DB操作が瞬時（100ms以内） | NFR001 |
| 4 | ローカル実行を基本とし、LAN共有に拡張可能 | NFR101, FR406 |
| 5 | Claude Codeとの相性が良い（生成・修正しやすい言語） | 開発効率 |
| 6 | OSS・開発継続・扱いやすいライセンス | NFR403, NFR404 |
| 7 | 日本語または英語の情報が豊富 | 開発者要望 |
| 8 | フロントエンドでGamepad API等を扱える | FR105〜FR108 |
| 9 | 他の開発者が参加しやすい（メジャーな技術） | NFR402, NFR405 |

## 2. 技術スタック候補

### 2.1 案A：Rust + React（当初検討案。LAN 要件により §6 で不採用＝案C 採用）

Tauri（Rustベースのデスクトップアプリフレームワーク）でフロントエンドとバックエンドを一体配布する構成。

| レイヤー | 技術 | ライセンス | 用途 |
|----------|------|------------|------|
| フレームワーク | Tauri v2 | MIT / Apache-2.0 | デスクトップアプリ化、シングルバイナリ配布 |
| バックエンド | Rust (Tauri内蔵) | MIT / Apache-2.0 | API処理、ファイルI/O、HTMLパーサー |
| フロントエンド | React + TypeScript | MIT | UI構築 |
| UIライブラリ | shadcn/ui + Tailwind CSS | MIT | コンポーネント・スタイリング |
| データベース | SQLite | Public Domain | ローカルデータ保存 |
| ORM/DBアクセス | SQLx (Rust) | MIT / Apache-2.0 | 型安全なDBアクセス |
| ビルドツール | Vite | MIT | フロントエンドビルド |
| HTMLパーサー | scraper (Rust) | MIT | 公式データ取り込み |
| テスト | Vitest + Rust test | MIT | フロント・バックエンドテスト |

**メリット**

- シングルバイナリ配布が可能。利用者はexeを起動するだけで使える（NFR303, NFR304を最も自然に満たす）
- メモリ使用量が極めて小さい（Electronの1/10程度）。ゲーム同時起動に最適（NFR002）
- SQLiteはファイルベースで軽量、100ms以内の操作は容易（NFR001）
- Tauriはlocalhost起動なのでLAN共有への拡張も設計可能（FR406）
- React + TypeScriptはClaude Codeが最も得意とする組み合わせ
- Gamepad APIはWebView内のブラウザAPIとして使用可能（FR105）
- Tauri, React, SQLiteいずれも非常にメジャーで情報豊富

**デメリット**

- Rustはあなたにとって新規言語。レビュー時に学習コストがある
- ただしバックエンドのRust部分はClaude Codeが生成するため、あなたが書く場面は限定的
- Tauriのビルド環境構築がやや手間（初回のみ）

**配布方式**

- Windows: `.msi` インストーラまたは `.exe` ポータブル
- macOS: `.dmg`
- Linux: `.AppImage` または `.deb`

Pythonバックエンド + Reactフロントエンドの構成。PyInstallerでバイナリ化して配布。

| レイヤー | 技術 | ライセンス | 用途 |
|----------|------|------------|------|
| バックエンド | Python 3.12+ | PSF License | API処理、ビジネスロジック |
| Webフレームワーク | FastAPI | MIT | REST API |
| フロントエンド | React + TypeScript | MIT | UI構築 |
| UIライブラリ | shadcn/ui + Tailwind CSS | MIT | コンポーネント・スタイリング |
| データベース | SQLite | Public Domain | ローカルデータ保存 |
| ORM/DBアクセス | SQLAlchemy | MIT | DBアクセス |
| ビルドツール | Vite | MIT | フロントエンドビルド |
| HTMLパーサー | BeautifulSoup4 | MIT | 公式データ取り込み |
| バイナリ化 | PyInstaller | GPL-2.0（後述） | exe配布 |
| テスト | Vitest + pytest | MIT | フロント・バックエンドテスト |

**メリット**

- Pythonはあなたに実務経験がありレビューしやすい
- FastAPI + SQLAlchemyは情報が非常に豊富（日本語含む）
- Claude CodeはPythonの生成も得意
- BeautifulSoupによるHTMLパースは実績豊富で柔軟
- 開発速度はRustより速い

**デメリット**

- PyInstallerでバイナリ化した場合、サイズが大きくなる（100〜200MB程度）
- メモリ使用量がRustより大きい（50〜100MB程度）
- PyInstallerのライセンスはGPL-2.0だが、バンドルされるブートローダーはApache-2.0のため、生成されたexe自体のライセンスには影響しない（PyInstaller公式FAQ準拠）。ただし誤解を招くリスクはある

- LAN共有時はFastAPIをそのまま0.0.0.0でリッスンすればよいが、セキュリティの制御が自前になる

**配布方式**

- PyInstallerによるワンフォルダまたはワンファイル配布
- 起動用バッチ/シェルスクリプト同梱

- Goはあなたにとって新規言語（ただしシンプルな言語なので学習コストはRustより低い）

**modernc.org/sqliteの性能トレードオフ**

modernc.org/sqliteは純Go実装のためCGO不要・クロスコンパイル容易というメリットがあるが、書き込み性能はmattn/go-sqlite3（CGO必要）比で2〜3倍遅いことが一般に知られる。本アプリの想定規模（コンボ1000件・セットプレイ3000件、CSV一括インポート1000行上限）では実用上問題ない見込みで、CSV一括インポートも数秒オーダーで完了する想定。公式データ取り込みは別ツール側で実行されるため本体への影響は限定的。

万一性能問題が顕在化した場合のフォールバックとして mattn/go-sqlite3 + CGO への切り替えを実装時の選択肢として残す。データベース層は database/sql の標準インターフェースを使用し、ドライバ切り替えが容易な構造を維持する。

**配布方式**

- 各OS向けシングルバイナリ（exe / バイナリ）
- 起動するとブラウザが自動で開く

## 4. 推奨と判断ポイント

### 4.1 当初の総合推奨：案A（Rust + React / Tauri）

> **【確定: 案C（Go + React）採用】** 本 §4.1 は候補比較段階の当初推奨の記録である。LAN 内スマホアクセスがほぼ必須要件と判明したため、最終採用は §6 のとおり **案C（Go + React）** へ変更された（Tauri のネイティブ統合という案A の主要メリットが LAN スマホ利用シーンで活きないため）。以下は当初推奨時の評価として歴史記録に残す。

要件への適合度が最も高い。特に以下の点が決定的と考える。

- **NFR303/NFR304（簡単インストール・前提ソフト不要）** を最も自然に満たす。利用者はexeをダブルクリックするだけで、ブラウザを開く必要すらない
- **NFR002（ゲーム同時起動）** においてメモリ消費が最小で、フルスクリーンのゲームからAlt+Tabで切り替えた際にネイティブウィンドウとして即座にアクセスできる
- Rustの学習コストはデメリットだが、バックエンドのコード生成はClaude Codeが担うため、あなたの作業は主にレビューとフロントエンド（React/TypeScript）側になる

### 4.2 次点：案C（Go + React）

案Aのデメリット（Rustの学習コスト）を重視する場合の次善策。Goは言語仕様がシンプルでレビューしやすく、ライセンスも最もクリーン。ただし「ブラウザを開く一手間」が利用者体験として案Aに劣る。

### 4.3 案Bが適するケース

あなた自身がバックエンドのコードを積極的に書く・修正する予定があり、レビューよりも自分で手を動かす比率が高い場合。ただしバイナリサイズとメモリ消費の面で要件適合度は最も低い。
