## 2. 修正概要

### 2.1 `REQ-001` §6.4

**旧**（第30版まで）:

> マノンのメダルレベル、AKIの毒状態などのキャラクター固有の特殊状態は「状況」の一部として扱う。

**新**: 名指しから「マノンのメダルレベル」を外し、**扱う条件**と**扱わない理由**を足した。

- 扱うのは「その状態によってコンボの成立・分岐が変わるもの」に限る。
- 値が変わってもダメージしか変わらない状態は定義しない。
- **★マノンのメダルレベルは扱わない。理由ごと否定形で残した。** **「第30版まで名指ししていた。撤回する」と明示的に書いた**（playbook §16.3 ／ `E-258`）。
- 定義の正本が `characters.custom_states`（seed）であり、形を定めるのが `DES-003` §3.2 であることを併記した。

### 2.2 `DES-003` §3.2——**JSON 例から `medal_level` の項を落とし、正本の所在を併記した**

- **スキーマ例の 1 件目（`medal_level` / メダルLv / `type: level` / integer 1..5）を削除した。**
- **★代わりに、JSON が「形」の例示であって実データの正本ではないことと、正本が seed であることを引用ブロックで明記した。**
- **★`type: level` の as-built の実例が `sun_crest` であることを名指しし、定義本体は転記しなかった。** **根拠＝同書が第54版で自ら定めた規約**〔設計書に実測値を書くときは正本がどこかを必ず併記する。併記できないなら書かない〕。

### 2.3 `DES-003` §3.2「対応可能なケースの例」

- **1 行目**「マノンのメダルLv → subject: self, type: level」を、**キャラを名指ししない型の例**「段階を持つ恒常状態 → subject: self, type: level（as-built の実例は `sun_crest`）」へ置き換えた。
- **★★as-built の注記を足した**——**19 キャラ中 11 キャラの `custom_states` が SQL NULL である**（`M14-03d` が定義の投入をスコープ外としたため）。**「入っていない」は「扱わない」を意味しない。**
- **★撤回の記録を足した**——**マノンのメダルレベルは扱わない。理由は付与数で変わるのがダメージだけであること。** **「第62版まで 1 行目に置いていた。撤回する」と明示した。**

### 2.4 `DES-003` §3.4——**situation の例を差し替え、形式も同時に現行へ揃えた**

**旧**: `{"custom_states": {"medal_level": 3}}` ／ **新**: `{"custom_states": {"sun_crest": {"start_min": 1, "end": 3}}}`

**★形式も同時に直した理由を本文へ残した**——**旧例はスカラ形式であり、`CHANGE-067` / `M16-07` 以降は「後方互換で `end` へ写像される旧形式」である。** **code だけ差し替えると、新しく書いた例を自分で旧形式で書き起こすことになる。** **既存の記述を引き継ぐのと、自分で書き起こすのは別である。**

### 10.1 ★★母数が 0 でないことが決定的である

**「0 件」には 2 つの意味がありうる**——**「無い」と「そもそも走査対象が無い」。** **母数を添えなければ区別がつかない。**

**★使い捨て環境の走査が弱かったのはまさにここだった**（§5.2）——**`combos` が 0 行であり、0 件が何も意味していなかった。** **今回は母数が 3 件あり、そのうえで 0 件である。⇒ 「無い」が確定した。**

**★一般形＝「無い」を主張する走査には母数を必ず添える。**

**★母数 3 件という少なさは `SM-102` / `SM-063` と整合する**——**`custom_states` の定義が投入されていないのだから、`situation` の `custom_states` も書かれようがない。** **§5.2 で述べた「入力経路が無い」が、予測どおりの形で裏づけられた。**

### 10.2 ★あわせて道具立ての欠如を 1 件記録した

**担当は `sqlite3` CLI が環境に無かったため、Python 標準 `sqlite3` を `mode=ro` で使って同じ SQL を実行し、その差異を報告に明記した。**

**★振る舞いとしては正しい**——**等価であり、勝手に手段を変えて黙らなかった。**

**★★しかし機序は設計卓の側にある**——**投入プロンプトが `sqlite3` CLI の存在を仮定していた。** **今回は担当が申告したから分かったが、申告が無ければ「指定どおりのコマンドを打った」と読める報告になっていた。**

**⇒ 一般形＝投入プロンプトで具体的なコマンドを指定するときは、その道具が対象環境に在るかを確かめるか、「等価なら手段は問わない。使った手段を報告に書くこと」と明示する。**

**★アプリ本体に CLI は不要である**（ドライバは `modernc.org/sqlite`＝CGO 不要の純 Go）。**欠けているのは「アドホックに実 DB を検分する道具」だけであり、この検分は再発している**〔2026-08-23〜24 の orphan 19 件の実測＝`D-535` ／ 本件〕。**⇒ followup §S へ `sqlite3-cli-absent-for-adhoc-db-inspection` として登録した。**
