## 1. 変更の概要

**M19（セットプレイ自動提案）で実装した機能に、機能要件の裏付けが無い。**

M19 は **CHANGE-085 / 086 / 087 / 091 / 094 / 095 / 096** の 7 本で `DES-002` / `DES-003` / `DES-005` / `DES-006` を改訂してきたが、**`REQ-001` には 1 行も入っていない。** **D-28 が「FR 新設は M19 クローズ時に 1 本」と定め、スコープが確定するまで待っていたためである。**

**⇒ スコープが確定した。FR を 1 本立てる。**

**あわせて `DES-005` の誤参照を 1 件是正する**（§3）。

## 2. 変更の内容 — `REQ-001` §3.1 に **FR014** を新設

**配置**: §3.1「コンボ管理（コア機能）」の表の末尾（**FR013 の直後**）。

> **★§3.1 に置く理由**——**セットプレイ関連の機能要件は §3.1 にある**（**FR011**＝セットプレイの転用支援）。**本機能は同じコンボ詳細画面に並び、同じ `knockdown_advantage` を入力に取る。** **§3.4〔バリデーション〕は「行わないこと」を書く節であり、新機能の置き場ではない。**

**`new`（追加する 1 行）**:

| ID | 要件 | 優先度 | フェーズ |
|----|------|--------|----------|
| **FR014** | **セットプレイの自動提案**：コンボ詳細画面において、当該コンボの起き上がり有利フレーム（`knockdown_advantage`）から、**相手の起き上がりに技を重ねる（または意図的に重ねずに空振りを挟む）セットプレイのレシピを計算して提示する**。**提示された提案が自動でセットプレイになることはなく**、利用者が明示的に採用したものだけが登録される（**採用済みの同一レシピは事前照合で抑止する**）。**提案結果そのものは保存しない。** あわせて、**実機で成立を確認できた条件（受け身種別 × 画面端）を記録でき**、コンボ一覧をその**成立状態で絞り込める**。成立条件は **「確認して成立」「確認して不成立」「未検証」を区別**し、**未検証は記録の不在で表現する**（「該当なし」と「未検証」を混ぜない）。**フレームデータ由来の限界は利用者へ告知する** | **重要** | **3** |

### 2.1 ★1 本にまとめた理由と、収めた範囲

**D-28 は「1 本」と定めている。** 実装は 7 本の CHANGE に分かれたが、**利用者から見れば「提案を受け取り、試し、成立を記録し、後から絞り込む」という 1 つの機能である。**

| M19 の実装 | FR014 のどこに対応するか |
|---|---|
| M19-01・02（提案・2 モード・打ち切り） | **提示する／重ねる・重ねない／告知** |
| M19-03（成立条件の記録） | **記録できる／3 値を区別する** |
| M19-04・Phase 2・M19-05（費用モデル） | **レシピを計算する**（内部の精度。FR には現れない） |
| M19-06（絞り込み） | **成立状態で絞り込める** |
| M19-07（登録時の入力） | **記録できる**（入力の面が増えた） |

**★FR に書かなかったもの**——**費用規則・受理帯・チェーンキャンセル・`startup_basis` などの内部の仕組み。** **これらは `DES-002` / `DES-003` / `M19-DESIGN-07` が持つ。** **FR は「利用者が何をできるか」を書く場所であり、どう計算するかは書かない。**

### 2.2 ★優先度とフェーズ

- **優先度＝重要**（**FR011 と同じ**。必須ではない——**この機能が無くてもコンボ管理は成立する**）。
- **フェーズ＝3**（`phase3-overview` が「発信者の差別化機能——セットプレイ自動提案（前例なき目玉）」として本フェーズに置いている）。

## 3. ★あわせて `DES-005` の誤参照を是正する

### 3-1. 発見した誤り

**`DES-005` §5.6 項目12 は次のように書いている。**

> 「**提案が自動でセットプレイになることはない**（FR307）」

**しかし `REQ-001` の FR307 は「コンボダメージの自動計算は行わない。理由：コンボ補正の端数処理が非公開、空振り技の存在、多段技のヒット数変動などにより正確な計算が原理的に困難なため」である**（§3.4 バリデーション）。**別物である。**

**★§3.4 は FR301〜307 で終わっており、他に FR307 は存在しない**（2026-08-10 実査）。**⇒ 誤参照である。** 混入は **CHANGE-085**（M19-01 の反映）と見られる。

### 3-2. 是正

**`(FR307)` → `(FR014)` へ置き換える。**

> **★これは FR014 の新設によって初めて可能になる。** **これまで指し先が存在しなかった。** **「自動確定しない」という設計判断は M19-01 から一貫して守られてきたが、その根拠が `REQ-001` に無く、別の FR を指していた。**

### 3-3. ★同型が他に無いかを確認すること

**`DES-002` / `DES-003` / `DES-005` / `DES-006` で `FR3xx` を参照している箇所を全数 grep し、参照先が実在しかつ内容が一致することを確認すること。** **「見つかった件数」だけでなく「検査した件数」も報告する**（`E-84`）。**名指しを網羅と読まない**（**D-146**）。
