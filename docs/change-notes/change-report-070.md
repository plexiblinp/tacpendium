## 2. 修正概要

### 2.1 DES-005 §6.4

- **方向入力を 3 ゾーン → 9 方向（テンキー配列）**へ。行順 `7 8 9`/`4 5 6`/`1 2 3`・1P 右向き基準・左右反転非対応・初期 `5`・キャラ切替でリセットしない・**矢印記号は不使用**（M15-03「記号除去」の踏襲）。
- **一様フォールバック**（解決表 → ミスなら段階1 の構造引き。**9 方向 → 3 ゾーンの縮約**）。**方向ゾーンで経路を分けない**。**段階1 は索引非依存＝未 seed キャラでも動く**。
- **解決表はキャラ選択時に 1 回**・**空 entries／取得失敗でも段階1 だけで動く**・**FE は畳み済みの表を引くだけ＝規則を持たない**。
- **ラッシュ解決の一般化**（**一様解決した code に `rush_<code>` を引く**＝段階2 確定の単方向特殊技にもラッシュが効く／ラッシュ ON 中は上系非活性・斜め下は可／特殊技タブの Switch も同一経路）。
- **段階2 は代替でなく追加**（必殺技・SA・投げ・空中特殊技・溜め・一回転は解決表に載らない＝**既存の直接指定が入力手段として不可欠**）。
- **test-id `recipe-dir-{1..9}`**（**旧 `recipe-zone-*` は廃止**）・aria は既存値を維持。

### 2.2 DES-005 §5.7

- **セットプレイのレシピ入力も同一の仮想コントローラを共有するため 9 方向パッド・段階2 が有効**（**構造的帰結**）。

### 2.3 DES-002 §4.2

- **解決表は `moves.is_aerial` と `category` に依存して畳まれる**＝**技編集（`is_aerial` の PATCH）は解決表の内容を変える**＝**FE は技編集の成功時に `["command-index", characterId]` を無効化すること**。**ラッシュ版生成は無効化不要**（`is_derived=true`＝索引対象外）。

### 2.4 DES-004 §2.4.5

- **データ不整合時の縮退**＝**解決表がヒットしても技一覧に該当 code が無ければ段階1 へ縮退**（別クエリのキャッシュ齟齬・部分障害に対する「壊れない優先」。**規則の二重実装ではない**）。

## 3. 【真因】設計の書き落とし 1 件

- **事象**: **CHANGE-069 で `is_aerial` を解決表の除外条件にした**（§4-#3'）が、その帰結である「**`is_aerial` が変わると解決表が変わる**」＝**FE キャッシュの無効化契約**を **DES-002 §4.2 に書き落とした**。
- **検出**: **M17-03 のレビュー（中）が実装側で穴を検出**し修正（`useUpdateMove` → `["command-index", characterId]` の invalidate）。
- **一般化**: **「解決表が何に依存して畳まれるか」は FE キャッシュ設計に波及する**。**BE の畳み込み規則を変えたら、その入力になる列を変える経路すべてがキャッシュ無効化の対象になる**。**API 契約に「何に依存するか」を書く**と、消費者が自力で気づける。**本 CHANGE で明文化した**。

## 5. 整合性チェック結果

- **死守 3 契約（DES-004 §2.4.1）と一貫**: 公式表記のみ／モーション解析なし（**236 等を仮想コントローラで実演させていない**）／出口は必ず `move_code`。
- **「FE は規則を持たない」（DES-002 §4.2）と一貫**: 正規化・特殊技優先・タイブレークは BE。**§2.4 の縮退は「規則」ではなく「壊れない防御」**（レビューでも二重実装でないことを確認済み）。
- **一様フォールバック（DES-004 §2.4.5）と一貫**: 方向ゾーンで経路を分けていない。
- **段階1 の非依存性を維持**: 索引に依存しない＝**未 seed キャラでも動く**。**新ファイル分離により diff ゼロで機械検証**。
- **節番号**: DES-005 §6.4／§5.7、DES-002 §4.2、DES-004 §2.4.5 を**実ファイルで確認して反映**（**確認出力を切らずに全件列挙**＝E-7 の再発防止）。
