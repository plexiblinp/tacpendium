## 3. 確定した設計判断

### 3.1 gap（汚連携）モードの定義

> **target の「最終 active」が、起き上がり（`KA + 1` フレーム目）の `G` フレーム前に出る＝技を丸ごと空振りさせる。**

- 最終 active `= (KA + 1) − G`、最終 active `= S + active − 1` より **`G = N − active`**。
- 受理帯 **`[active + Gmin, active + Gmax]`**＝**target ごとの `active` に依存する**（共通定数ではない）。
- **`G ≥ 1` ⇔ `N > active`** ⇔ **meaty（`N ≤ active`）と完全に排他**。
- **恒等式 `N = KA + 2 − S` と着弾 `= KA + 1` は不変**。等値条件へは戻していない。
- **gap の `sort=n` は `G` 昇順**＝**`G` を直接比較する**。`active` が target ごとに異なるため、**`N` で並べても `G` 順にならない**。

### 3.2 ★`truncated` の意味の狭義化（既存フィールドの解釈変更）

| | M19-01（旧） | **M19-02（新）** |
|---|---|---|
| `truncated` | `MaxResults` 到達**等**で打ち切ったか | **エンジンの安全上限 `engineSafetyCap`（6000）に到達し数え切れていないときのみ true** |
| `limit` で切っただけ | true になり得た | **false**（件数の乖離は **`totalFound > len(items)`** で表現） |

**型・フィールド名は不変だが解釈が変わった＝M19-01 からの変更**である。UI 側も「安全上限到達」と「`limit` 切り」を区別し、**前者のみ「条件を絞ってください」の趣旨を表示**する。

### 3.3 負 KA と KA NULL は別コード

- **負 KA**＝**200 ＋ `knockdown_advantage_negative` ＋ `items` 空**（正常に計算した結果が 0 件）。
- **KA NULL**＝**400 ＋ `knockdown_advantage_required`**（未入力＝リクエストが処理できない）。
- UI も**文言と `data-testid` を分離**する（前者は構造的に成立しない／後者は入力を促す）。

### 3.4 実装で確定した定数（根拠値）

| 定数 | 値 | 根拠 |
|---|---|---|
| `engineSafetyCap` | **6000** | 実測 `totalFound` 最大 4884 が多数 target へ分散。**実データでは非発火の後段防御** |
| `defaultLimit` | **200** | meaty 既定種別は最大 323＝2 ページ目で全件到達 |
| `maxLimit` | **3000** | meaty 全種別 677・gap 既定種別 2875 を包含 |
| 「さらに表示」増分（FE） | **200** | — |

**性能実測（8 キャラ）**：最大負荷＝juri・KA40・gap 全種別 ＝ **4884 件 / 25.6ms**。**NFR001（100ms）に十分な余裕**。
