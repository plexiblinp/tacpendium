## 3. ★起票時のスコープを 1 文書ぶん広げた（**黙って広げていない**＝playbook §4.18）

**通知書 §5 は「`DES-003` は変更なし（DB スキーマを 1 つも変えない）」と宣言していた。** **スキーマは実際に 1 バイトも変わっていないが、`DES-003` の散文が as-built と正面から食い違っていた。**

**逐語（旧記述）**——

> **パスワード管理方針**：`password_hash` は任意カラムとし……**LAN共有モードで複数ユーザーが利用する場合、設定画面からパスワードを設定できる。ハッシュ化はbcrypt（Go標準外ライブラリ `golang.org/x/crypto/bcrypt`、BSD-3-Clause）を使用する。**

**食い違いは 2 点である。**

1. **パスワードは利用者ごとではなく全体で 1 本である**（`DES-002` §8 の逐語「全ユーザー共通の1パスワード」）。
2. **bcrypt は実装されていない**（`crypto/pbkdf2` が標準ライブラリに在ったため昇格そのものが不要だった＝§2-1）。

**⇒ 放置すると、次の担当が `users` 表にパスワードを実装しようとする。** **規律 2「as-built が指示書と違ったら DES は as-built に合わせる」の対象そのものである。**

**★新規採番は不要**（本数は 1 本のまま＝**D-323** の先例）。**先例＝`CHANGE-083` / `CHANGE-087` / `CHANGE-101`（`D-354`）。**

## 4. 親の裁定（§2 の 2 件）

### 4-1 【受理】E2E シナリオ B がサーバを ON にしていない（**D-399 (1)**）

**製造の as-built**——サーバの `password_enabled` は `false` のままで、`page.route` によって**当該ブラウザコンテキストの API 応答だけ**を 401 に差し替えている。

**★受理する。理由は 3 つ。**

1. **`D-362`（資源ごとに 1 ファイルへ寄せる）では防げない領域である。** **`fullyParallel: false` が直列化するのはファイル内だけであり、巻き添えになる相手は別ファイルである。** **⇒ サーバを ON にすると、同時に走っている他 spec が軒並み 401 で落ちる。**
2. **ON 側のサーバ挙動（誰が通り誰が弾かれるか）は Go テストで網羅されている。** **E2E が担うのは「画面がどう見えるか」だけである。**
3. **★副次的に、テストが共有状態を汚さなくなった**（`config.toml` の復元が不要になった）。**これは回避策ではなく、より良い性質である。**

**⇒ 指示書テンプレートへ一般規則として書く**（テンプレート v1.4.0）。**★ただし条件を 1 つ付ける**——**モックの照合パターンが対象以外に当たらないことを先に確かめること。** **本サブで実際に踏んだ**（`page.route("**/api/**")` が Vite が dev で配るソースモジュールのパスにも当たり、JS が 401 JSON へ化けてアプリが起動しなくなった）。**★気づけたのは対照実験（遮断しなければ 200）を置いていたからである。**

### 4-2 【受理・ただし宛先を開発者へ回す】サービス層が `ctx` を取っていない（**D-399 (2)**）

**製造の as-built**——`internal/service/auth/Service` の 6 メソッドと `SecurityStore` の 2 メソッドが `context.Context` を取らない。**`CLAUDE.md` §4 の規約からの逸脱である。**

**★本サブとしては受理する**（差し戻さない）。**理由**——**渡す先が無い**（`SecurityStore` の実体である `configsvc` が `ctx` を取らない設計であり、`M20-05` §9.4 で公開 IF の組み替えは範囲外とされている）。**取れない `ctx` を型に載せると「キャンセルが効く」という誤った期待を呼ぶ。** **逸脱は godoc と設計伝達レポートで明示済みであり、レビューも妥当と判断している。**

**★ただし恒久的な扱いは設計卓の管轄外である。** **`CLAUDE.md` は開発者のルールファイルである**（製造の指摘どおり）。**⇒ 開発者へ回した**（§6）。**放置すると、次にサービス層を新設する担当が同じ判断を毎回する。**
