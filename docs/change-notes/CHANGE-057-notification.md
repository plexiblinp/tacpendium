## 1. 変更の概要

M15-03（入力方式ボタン化＋コマンド入力解決 段階1＋直接指定 UI＋modifier flags）の実装・UI/UX 追補完了に伴い、確定した仕様を設計書本体へ反映する。**全件フロントエンドのみ・データモデル/スキーマ/API/マイグレ不変**（追補伝達書 冒頭）。死守契約 3 点（公式表記のみ／モーション解析なし／出口＝`move_code`）・非スキーマ・command 非依存も維持。

- **DES-004 §2.1**: 必殺技ファミリー名の導出ルール（接頭形・末尾形の両対応）を明記。
- **DES-004 §2.3**: `modifiers.flags` の実値を実装に同期（実装済み flag の列挙・未実装 flag の明示）。
- **DES-005 §5.7 / §6**: 仮想コントローラをカテゴリタブ式 direct-selection＋段階1 の実装形へ更新（必殺技 2 段・強度色・共通技エリア・ラッシュ Switch・全技プルダウン折りたたみ＆区分統合・用語是正）。

**新規論点（本 CHANGE では確定せず M16 へ）**: `dash_forward`/`dash_back` の **move / modifier.type 二重表現の一本化**（§5・§6 参照）。

## 2. 変更の内容

### DES-004 §2.1（必殺技ファミリー名の導出）

- **必殺技の直接指定 UI**（M15-03）はファミリー（例「波動拳」）＋強度（弱/中/強/OD）の 2 段で選択し、出口は `<技名>_<強度>`（`hadoken_light` 等）。ファミリー名は `official_ja_move` から強度ラベルを除去して導出する。
- **公式 JP 名は接頭形が主**（例「**弱**波動拳」「**OD**昇龍拳」）だが末尾形（「波動拳・弱」等）も存在するため、**ファミリー名導出は接頭・末尾の両対応**とする（`stripStrengthLabel` 相当）。§2.1 必殺技行に注記を追加。

### DES-004 §2.3（modifiers.flags 実値同期・乖離是正）

`modifiers.flags` は「方向性のみ定義・列挙値は実装時決定」（§2.3）だが、実装確定に伴い実値を同期する。**flags マスタは固定選択式**（自由入力不可・UI 担保）を維持。

| 分類 | flag（コード） | 表示（短縮表記・正） | 状態 |
|------|--------------|--------------------|------|
| タイミング系 | `just` | ジャスト | 実装済 |
| タイミング系 | `delay` | ディレイ | 実装済 |
| タイミング系 | `link` | 目押し | **実装済（§2.3 に未記載だった＝追加）** |
| 空中系 | `low_jump` | 低ジャンプ | 実装済 |
| 空中系 | `high_jump` | （高空） | **未実装（planned として明示）** |
| キャンセル系 | `first_hit_cancel` | 一段目キャンセル | **実装済（M15-03 追加）** |
| ジャンプ状態 | `neutral_jump` | 垂直ジャンプ中 | **実装済（M15-03 追加）** |
| ジャンプ状態 | `forward_jump` | 前ジャンプ中 | **実装済（M15-03 追加）** |
| OD ボタン組 | `od_lm` / `od_mh` / `od_lh` | OD(弱中) / OD(中強) / OD(弱強) | **実装済（M15-03 追加）** |

- **表示は短縮表記を正**とする（追補 2-2＝一度平易化した文言を短縮形へ差戻し）。
- **編集ダイアログ（`ModifiersEditor`）では英語 value（`(od_lm)` 等）を表示しない**（追補 2-3＝一般ユーザー向け・識別子は内部のみ）。flag コード自体は内部正典として不変。
- 微歩き・微下がりは flags でなく独立 move（§2.1）＝不変。

### DES-005 §5.7（レシピ入力領域）

- レシピ入力領域＝仮想コントローラ（§6）。**カテゴリタブ式の direct-selection＋通常技段階1**（詳細 §6）。
- **技/非技ラジオを廃止**し、**区分絞り込みプルダウン**に統合（後述 §6）。**用語**: 「非技ステップ」→「**共通システム（移動・その他）**」、修飾情報の「flags」見出し→「**補足（入力のコツ・状況）**」（追補 2-1）。**コンボ編集（RecipeBuilder）・セットプレイ編集（SetupRecipeEditor）の両方**に適用。
- 既存の始動技自動推定（読み取り専用）・各ステップ「編集」ボタン＋info-mark（M15-02）は不変。

### DES-005 §6（仮想コントローラ）

**§6.1 概要 / §6.4 入力方式を実装形へ更新**（従来の「4 種レイアウト（レバーレス/アケコン/PS5/キーボード）＋論理ボタン」記述は**物理コントローラ実入力＝M21〔旧 M18〕**の将来仕様として温存し、仮想（クリック/タップ）入力の現行形を以下に明記）:

- **カテゴリタブ**: 通常技／特殊技／投げ／必殺技／SA／システム／ドライブインパクト（ラッシュはタブでなくトグル）。タブで入力面を切替。
- **通常技＝段階1**: 方向ゾーン（立ち`5`/しゃがみ`2`/ジャンプ`8`）×6 ボタン → `standing_/crouching_/jumping_<強度>_<ボタン>` を決定論引き当て（DES-004 §2.1・非スキーマ・command 非依存）。
- **特殊技＝ワンプッシュ直接指定**。**必殺技＝2 段（ファミリー→弱/中/強＋OD）**、OD は「プレーン OD」＋「OD(弱中)/OD(中強)/OD(弱強)」を並置（非プレーンは §2.3 の `modifiers.flags`）。**モーション実演 UI は不在**（死守2）。
- **ラッシュ版トグル**（通常技・特殊技の**単発・非空中技のみ**＝`category∈{normal,unique}∧is_aerial=false`）→ `rush_<元技>`。shadcn `Switch`（iOS 風）。
- **共通技エリア（SystemRow・タブ外常設）**: ドライブインパクト（`drive_impact`）／ドライブパリィ（`drive_parry`）／前投げ（`throw_forward`）・後ろ投げ（`throw_back`）／前方ステップ（`dash_forward`）・後方ステップ（`dash_back`）／パリィドライブラッシュ（`parry_drive_rush`＝`modifiers.type`）。**いずれも既存 seed の move_code / modifier type を使用**（新規データなし）。表示ラベルは短縮（「インパクト」「パリィ」等・aria は正式名）。
- **強度色**（弱=水色/中=黄/強=赤/OD=灰）・ボタン副ラベル（LP 下に「弱P」）・技/共通技ボタンのサイズ体系・パネル枠。
- **全技プルダウン（網羅フォールバック）を既定折りたたみ**にし、展開ボタン＋説明文を付す。**区分絞り込み**に「共通システム（移動・その他）」擬似区分を統合（`nonmove:<type>` エンコードで 1 セレクタ化）。キャラ固有別技（ホールド/Lv/ジャスト等）は**このプルダウンで網羅入力＝取りこぼしなし**。
- §6.4.1 選択保持（物理レイアウト種別）は M21 の物理入力に紐づく将来仕様として温存。

## 5. 移行影響・リスク

- **dash 二重表現の実データリスク**（追補 3-1）: 同一「前/後ステップ」が入力経路で 2 表現になり得る。**canonical は system move**（§3-1）。**M15-03 現状は両表現が併存**（共通技ボタン＝move／プルダウン「共通システム」区分＝modifier.type）。
  - **近手当て（推奨・FE のみ・非スキーマ）**: プルダウン「共通システム」区分の dash 選択を **system move（`dash_forward`/`dash_back`）へ寄せ**、modifier.type dash を**新規入力経路から外す**。これで新規の不整合データを止められる（§7-1 で採否確認）。
  - **恒久（M16）**: SUPP-001 §3.3.3 / `MODIFIER_NON_MOVE_TYPES` から dash の modifier.type を**廃止**し、既存 modifier.type dash データがあれば system move へ**移行**（M16 ④「移動の system move 登録」と一体・data milestone・§6）。parry_drive_rush は modifier.type のまま。
- その他は FE のみ・非破壊（段階1・direct-selection・flags は既存 `moveId`／既存 `modifiers`〔JSON〕に載る・新規列/API/マイグレなし）。

## 7. 開発者への確認事項

1. **dash 二重表現の近手当てを M15-03 内で実施するか、M16 まで現状維持か**
   - 何を: プルダウン「共通システム」区分の dash を system move へ寄せる FE 修正（新規不整合データの停止）を M15-03 追補で行うか、M16 の恒久一本化まで現状維持（両表現併存）か。
   - なぜ: 現状維持だと M15-03 期間中も modifier.type dash の新規データが生じ得る（比較・共有で不整合）。近手当ては FE のみ・非スキーマで低コスト。
   - 暫定案: **近手当て（プルダウン dash→system move）を M15-03 追補で実施**し、modifier.type dash の廃止・既存移行は M16。実施可否をご判断ください。
