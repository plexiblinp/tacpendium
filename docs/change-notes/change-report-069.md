## 2. 修正概要

### 2.1 DES-004 §2.4（新設・本 CHANGE の正典）

- **§2.4.1 死守 3 契約**（公式表記のみ／モーション解析なし／出口は必ず `move_code`）＝「認識」でなく「**引く**」問題であることを明記。
- **§2.4.2 索引源（index-only）**＝`moves.command` 列は復活させない・索引は `move_commands`（DES-003 §3.14）・構築主体は `internal/moveindex`・**索引は広く持ちスコープの絞り込みは消費者側**。
- **§2.4.3 正規化**＝方向テンキー数字＋ボタン名・**ニュートラルは `5`**・**`plus` は写像せず削除してボタン隣接時に `+` を挿入**（**CSV に plus を書かずボタンが連続する行が実在**するため）・段階2 対象外トークンは記号へ写像してキーに残す・**`token_key` に空白を含めない**・**正規化規則の変更は索引の再生成を伴う**。
- **§2.4.4 解決表**＝**非派生のみ → `is_aerial=false` → 形状（単一方向＋強度付きボタン or ボタンのみ）→ category ガード（normal/unique/special）→ 特殊技優先 → id 最小 → 決めきれない組は載せない**の 7 段。
- **§2.4.5 段階1／段階2 の境界**＝**一様フォールバック**（方向ゾーンで分けない）＋**ドメイン事実**（下前/下後ろ＋中P）＋**段階1 は索引非依存＝未 seed でも動く**。

### 2.2 DES-003 §3.3・§3.14

- **`is_derived`**（BOOLEAN・NOT NULL・DEFAULT false・000032）＝**役割はただ一つ**（段階2 索引からの除外）・**判定原理**（「いきなり出せるか？」）・**判定源は人手付与で本体は導出しない**・**`rush_variant` は true**・dup/recipe 非対象・**model には持たせていない**（`GET /api/moves` に出ない＝UI で使うなら同期追加が要る）。
- **`is_aerial` の用途追記**＝**段階2 解決表の除外条件**として機能する・**この列の精度が段階2 の正しさに効く**・**実例**（`lily/great_spin`・`kimberly/elbow_drop`）・**空中特殊技は true 必須／空中必殺技の false は無害**。
- **§3.14 `move_commands`**（新設）＝列・**PK(move_id, token_key)**・**`UNIQUE(character_id, token_key)` を意図的に設けない**（1:N は索引段階で許容）・FK は両方 CASCADE・索引源と搭載/非搭載規則・**`token_key` に空白を含めない**（冪等性で runtime 再構築と `Lookup` が噛み合う）・**カバレッジ実測（530/306）**。

### 2.3 DES-002 §4.2・§7.5.1・§7.5

- **§4.2 解決表配信 API**＝`GET /api/characters/{id}/command-index`・**数値 ID**・**畳んだ表を返す**・**FE は規則を持たない**・**キャラ選択時に 1 回**・**存在チェックなし＝未 seed／不存在は 200＋空**（**404 を返さないのは仕様＝「壊れない」優先**）・不正 ID は 400・**FE のキー構築契約**（方向テンキー数字＋ボタン名・ニュートラルは数字なし）。
- **§4.2 rush-variant**＝**生成行は `is_derived=true`**（定数で立てる・元技からのコピーでない）。
- **§7.5.1 索引 IF（新設）**＝**取込ヘルパーと段階2 の共通基盤**（「二度作らない」）・IF 一覧・**`Lookup` は常に正規化／`AddIndexed` は正規化しない → 空白なしキーの冪等性で噛み合う**・**skip 判定の順序**・**`raw{`/`cond{` は部分文字列判定（トークン単位に置き換えてはならない）**・**消費者側の責務**。
- **§7.5 失効記述 2 件の是正**（下記 §3）。

### 2.4 DES-006 §2.6（新設）

- **VAL-* を設けない**ことと**その理由**を明記（`is_derived`＝人手付与を信頼・値域自明／`move_commands`＝seed 生成物でユーザー入力でない・健全性は生成時に担保／段階2 の解決＝**「解決できない」は正常な結果でありエラーではない**・**検証でなくデータ構造で担保**）。VAL-C02 非関与。

## 5. 整合性チェック結果

- **判断3（index-only）と一貫**: `moves.command` 列は復活していない。索引は seed／helper から再構築。
- **「二度作らない」と一貫**: 索引エンジンは `internal/moveindex`（M14-03b）の**消費者拡張**であり新規実装でない。DES-002 §7.5.1 で**取込ヘルパー（M17-04）と段階2 の共通基盤**として正典化した。
- **CHANGE-065（本体は取込値を信頼）と同型**: `is_derived` の判定源は入力ツール側の人手付与。本体は導出しない。
- **CHANGE-063（起き攻め）と同型**: dup/recipe 非関与・`RecomputeComboCache` 非波及。
- **節番号**: **DES-003 は 13 節（§3.13 combo_setups まで）＝新設は §3.14**。**起票時に「§3.12 まで」と書いたのは設計担当の検証コマンドが `head -12` で切れていたためで誤り**（製造の現物照合で検出）。**反映前に切らずに再確認し §3.14 へ反映した**。
- **DES-004 の反映先**: §2.1 近傍＝**§2.4 として新設**。**§6（カスタムプリセット）には触れていない**。
