## 3. 変更の内容（`DES-004`）

### 3.1 §3.4 — 層順の**原理**を明文化する

**★「3 接頭辞は層 B が先」という書き方をしないこと。** **原理を 1 文で書く。**

> **`command` が表記を決める行は層 A、`move_code` の構造が表記を決める行は層 B である。**

**根拠（CSV 全数実測・製造）**——**立ち技と J 攻撃の `command` は同一である。**

```
standing_light_punch : command = "p_l" → token_key = "LP"
jumping_light_punch  : command = "p_l" → token_key = "LP"
```

**`command` 列は地上／空中を表現していない。その情報は `move_code` 側にしか無い。**

**★接頭辞で書くと再び判断が割れる**（製造の実測）——**`terry/jumping_knee` は接頭辞を持つが `knee` が語彙に無いため層 A へ落ちる。** **層 B は「接頭辞 ＋ 強度 ＋ ボタン」の完全形にのみ当たる。** **4 パーツ code（`standing_heavy_punch_holding`）でも同じ問題が起きる。**

### 3.2 §3.4 — SA 注記の書式と抽出源

| 項目 | 確定値 |
|---|---|
| **書式** | **`236236P (SA1)`**——**半角スペース 1 個 ＋ 半角丸括弧 ＋ 大文字** |
| **抽出源** | **`move_code` から正規表現 `(^\|_)(sa[123]\|ca)(_\|$)` で機械抽出する。** **技名 `name_ja` からは推測しない** |
| **適用範囲** | **`super_art` / `critical_art` 一律**（衝突組だけに絞らない） |

**一律にした理由 3 点**（製造の判断・設計卓は是認する）——**(1) 同じ SA でもキャラにより注記の有無が変わると不揃いになる ／ (2)「衝突判定 → 注記 → 再判定」のループになり生成器の決定論が崩れる ／ (3) `236236P` 単体では読めない SA 番号が読み取れる。**

**★効果の実測**——**同一キャラ内で SA / CA の 2 技が `token_key` を共有する組は 23 組あり、うち 17 組が SA3 vs CA（全 17 キャラに 1 組ずつ）で注記により全数解消した。** **残る 6 組は同一 SA クラス内のため注記では解けない。**

### 3.3 §3.4 — サンプル表の 3 行は原理的に生成できない

| 行 | 生成できない理由 |
|---|---|
| **`sa1`** | **(1) 実在する `move_code` ではない**（ryu の実体は `sa1_shinku_hadoken`）。**(2) numeric の期待値 `236236HP` に対し CSV の `command` は強度指定のない `p` であり `236236P` にしかならない** |
| **`parry_drive_rush`** | **`modifiers.type` の非技ステップであり `moves` 行ではない。** `preset_aliases` は `move_id` を鍵に持つため入らない |
| **`cancel_drive_rush`** | 同上 |

**⇒ 表を実データで置き換えるか、「サンプルであって固定点ではない」旨を強める。** **★現状も末尾に「※上記は方針を示すためのサンプル」とあるが、`M20-02` の指示書 §5.1 はこの表を一致検証の対象として引いていた。** **注記が弱すぎて、設計卓自身が固定点として使ってしまった。**

**★あわせて §3.4 自身の内部矛盾も是正する**——**同じ `sa1` 行が `numeric` 列で `236236HP`、`srk` 列で `236236P (SA1)` と、強度の有無で食い違っている。** **CSV の実測は強度なしであり、`srk` 列が実データと整合する。**

### 3.4 §5 — seed 波ごとの再適用責務（★最重要）

**移動系 9 code にも「seed 波ごとの再適用」という運用責務が新設された。**

**`000072` / `000073` は移動系を「適用時点の 19 キャラを明示列挙して」投入している。** **⇒ 新キャラには当たらない。層 A / 層 B / rush 版と同じく、移動系も波ごとの再適用対象である。**

**★なぜ列挙する形になったか**（製造の是正経緯）——**当初は `characters` を CROSS JOIN する形**（キャラを列挙しない＝波を跨いで再適用不要）**で実装していたが、up は `NOT EXISTS` で既存を skip する一方 down は無条件に DELETE するため、次の波のマイグレを down すると `000072` / `000073` が入れた 171 行 × 2 プリセットまで消えた**（`SUPP-001` §5.5.2 (5)「down は up の反転ではない」に真正面から当たる形）。**up と down を同じ集合で絞るには、キャラを明示列挙するしかない。**

**⇒ 新しい運用制約**: **次の seed 波では `-mode aliases` を 2 プリセット分走らせ、`-movement-chars` にはその波で増えたキャラ「だけ」を渡す。** **前の波を混ぜると down が前の波の投入分まで消す。**

> **★落ちたときの症状が `D-181` と同一である**——**新キャラだけエイリアスが空、フォールバックで日本語技名が出るので画面は壊れずテストも緑。** **人が見る以外に発見経路が無い。**
>
> **⇒ `DES-003` §3.3 に `CHANGE-091` で同型の規約（`is_derived` の波ごと再適用＝`D-181`）が既にあるため、そこへ並べるのが自然である**（製造の提案。設計卓は同意する）。**本 CHANGE では `DES-004` §5 に書き、`DES-003` §3.3 から相互参照させる。**

### 3.5 §5 — 衝突組は両方落とす

**同一キャラ内で 2 技が同表記になる組は、どちらも投入しない。**

| プリセット | 残存衝突キー | 衝突行 |
|---|---|---|
| `numeric` | **35** | **84** |
| `srk` | **30** | **74** |

**★`numeric` だけ多い 5 キーは、すべて「空中版 vs しゃがみ版」である。** **入力が曖昧なのではなく、`numeric` 記法が「空中で押した」ことを表現できないだけである。** **`srk` では `cr.HP` と `2HP` に分かれるため衝突しない**——**`cr.` 接頭辞が偶然この曖昧を解消している。** **⇒ 恒久対応は followup `numeric-aerial-vs-crouching-collision`**（**開発者見解＝通常技全体に `j` を付ける。衝突技への例外付与ではない**）。

### 3.6 §5 — 逆引きの負債 2 件（**M20-07** の入力）

| # | 負債 | 内容 |
|---|---|---|
| 1 | **注記付き `alias_text` は完全一致で引けない** | 取込ヘルパー `FindMoveCodesByAlias` は `alias_text` の完全一致で引く。**` (SA1)` 〜 ` (CA)` は `alias_text` の一部であるため、利用者が `236236P` と書いても一致しない** |
| 2 | **`DR > 2LP` の `>` が連結子と衝突する** | **`DES-004` §4.2 が `>` を連結子と定めている。** 逆引きはステップ境界で切ってから完全一致で引くため、**切り方を決めないと `DR` と `2LP` に割れる** |

**⇒ 正規化は `M20-07`（`D-307`）の管轄である。本 CHANGE は §5 の逆引き節へ 2 件を注記するに留める。**

### 3.7 §5 — `alias_text_en` の実際の範囲

**値が入ったのは移動系 2 code だけである**——**`micro_forward` = `microwalk` / `micro_back` = `back microwalk`。** **19 キャラ × 2 code × 2 プリセット ＝ 76 行**（プリセットあたり 38）。**残る移動系 7 code と全キャラ別技は NULL。**

> **★これは `D-321` の見積り（30 種）とも食い違わない**——**同裁定は「2 code ＋ P-34 の 28 件」で 30 種としており、`P-34` の 27 件は本サブで投入していないためである**（**D-315**）。**⇒ 実装が正しい。**
>
> **★`M20-05`（表示側でロケール分岐）へ渡す前提**——**英語を持たない行が大半である。** **`alias_text_en` が NULL なのは「英語表記を持たない」であって「エイリアス未定義」ではない**（**D-317**）。

## 4. 確定した設計判断（報告への回答）

| # | 論点 | 判断 | 根拠 |
|---|------|------|------|
| 1 | **層順を原理で書くか、接頭辞で書くか** | **原理で書く** | **製造の指摘どおり。** **接頭辞で書くと 4 パーツ code と語彙外（`jumping_knee`）で再び判断が割れる。** **例外の列挙は必ず漏れるが、原理なら漏れても判断できる**（**D-331**） |
