## 2. 反映の中身

### 2.1 `DES-002` §4.2 — 版不一致時の応答（**新設**）

**★契約が 1 つも書かれていなかった。** 起票時の逐語は §6.4 の一文（「楽観的排他制御（更新時のバージョン番号チェック）を導入して上書き事故を防ぐ」）だけで、**どの資源が対象か ／ 版が合わないとき何を返すか ／ どの粒度で衝突するかが無かった。**

書いたもの——

- **409 ＋ `version_conflict`**（**資源によらず 1 つ**）
- **本文は `{"error":{"code":"version_conflict","message":"…"}}`。`details` を持たない**
- **メッセージは資源ごとに異なる**（統一するのはコードだけ）
- **★総称の `conflict` を割り当ててはならない理由**——**409 は一意制約違反でも返しており、実測で他に 10 コードある**（全数を列挙した）
- **★受け手はステータスで分岐してはならない**

### 2.2 `DES-002` §4.2 — **`PUT /api/combos/:id` に負けた側は 404**（契約の例外）

**★通知書 §7.3 で宣言したスコープ拡大。** 同経路は旧行を論理削除して新 id で採番し直すため、**旧 id を握っていた側が保存を撃つと 404 になり `version_conflict` は返らない。**

**★実装は正しい。旧行はもう無いのだから 404 が正しい。** 書いた理由は、**「版不一致は必ず 409」と読むと、キー変更編集に負けた利用者へ何も案内が出ない状態を作る**ためである（**実際に `M22-04` v1.0.0 がそう書かれており、v1.1.0 §1.3.1 で是正した**）。

### 2.3 `DES-002` §6.4 — 対象・粒度・集約の外（**全面改訂**）

- **対象は `combos` / `setups` の 2 表のみ**
- **粒度は集約。** **タグだけを変えても版が上がる**（**★副作用ではなく、集約を選んだことの帰結である**）
- **★`version` の増え方は 3 通り**（`+1` ／ `1` で採番し直す ／ 据え置き）。**`PUT` は照合に使うが加算しない**
- **★「集約の外」6 種を理由つきで書いた。** **上表は「穴」ではなく設計である**と明記した——**良かれと思って塞ぐと、塞いだ側は緑のまま、利用者が「保存できない」としか分からない状態を作る**
- **★6 番目がタグ削除の連鎖削除である**（通知書 §7.4 で宣言したスコープ拡大）。**塞がない**——**塞ぐとタグ 1 件の削除が、そのタグの付いた全コンボの版を上げ、無関係な編集を全部弾く**
- **`recipe_cache` の非同期**と**突き合わせを行う層**（`PUT` だけサービス層）を書いた

### 2.4 `DES-003` §3.4・§3.11 — `version` 列の読み方

**★`combos` と `setups` の両表について書いた。** **片方だけ書くと、次の担当が「`setups` 側は違うのか」と読むためである**（設計伝達レポート §1-3 の明示的な依頼）。

**★最も重いのは「`updated_at` で競合を判定してはならない」である**——**`updated_at` が進んでいても `version` が同じ状態が正常に起こりうる。**

### 2.5 `SUPP-001` §5.2 / §5.5.4 (13)（**通知書 §7.1・§7.2 で宣言したスコープ拡大**）

**★(13) が本サブで最も価値のある確定である。**

初版はハンドラ層 3 本の期待値に `model.ErrorCodeVersionConflict` を使っていた。**破壊確認（コードを総称 `"conflict"` へ戻す）を回したところ 3 本とも緑のままだった**——**定数の値を変えると期待値も一緒に動くためである。**

**⇒ 固定できていたのは Go 内部の一貫性だけで、線を流れる文字列ではなかった。**

**★「本番コードが定数を使うこと」（§5.2）と「テストがリテラルで固定すること」（(13)）は、両立させるべき別の要求である。** 両方を書き、**矛盾しないことを本文で明示した。**

**★一般形は「テストの期待値が被検査対象と同じ源を参照していないか」であり、エラーコードに限らない。**

> **★規約番号は (12) ではなく (13) にした。** **(12) は索引名の接頭辞（`idx_` / `ux_`・M20-03）で埋まっている。** 設計伝達レポートは「(12) 相当」と書いていたが、**実査したところ空いていなかった。**
