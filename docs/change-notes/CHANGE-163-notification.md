## 1. ★★golden の破壊確認は、射程の全区分から 1 件ずつ取る — `SUPP-001` §5.5.4 (10)

### 1.1 何が起きるか

**`seedgen` の引数なし `-check` は第一波しか再生成しない。⇒ 第一波外のキャラは壊しても緑が返る。**

| 区分 | 代表 | 引数なし `-check` |
|---|---|---|
| **第一波 9 キャラ**（`FirstWaveOrder`） | `000026` 系 | **★捕まる** |
| **第一波外**（manon＝`000045`、第三波＝`000055`、第四波＝`000084` 等） | それぞれの seed | **★★捕まらない**（`OK: 生成物は既存ファイルと一致` / exit 0） |

### 1.2 ★★実測（`character_data/` を複製し、複製側だけを壊した）

| 破壊 | 対象 | 結果 |
|---|---|---|
| A | guile のフレームを是正前へ | **`DIFF` / exit 1** ✅ |
| B | guile `sonic_break` → `sonic_break_light` へ逆改名 | **`DIFF`（up・down 2 本）/ exit 1** ✅ |
| D | kimberly を是正前へ | **`DIFF` / exit 1** ✅ |
| **★★C** | **manon `temps_lie` を是正前へ** | **★★`OK` / exit 0 ＝ 捕まらない** |
| C' | 同じ複製に `-chars manon -out 000045_...` を明示 | **`DIFF` / exit 1** ✅ |

### 1.3 ★★実害の形 — 設計卓のチェックリストが、この穴をそのまま踏ませる形だった

**`M28-04` レビューチェックリスト §6-1 は「CSV を直さずに DB だけ直した状態を作り、seed を再生成する／元へ戻ることを実測で示すこと。★★この確認が本サブの中心である」を必須の破壊確認に指定していた。**

**★★その手順を素直に実行すると、第一波外のキャラでは緑が返り、「機構が守っている」の証拠として使えてしまう。⇒ 守られていない区分を守っていることにできる。**

**★実際に `M28-04` の射程 9 行の内訳は「`000026` の golden が 8 行 ／ `000045` の golden が 1 行」であった**（計測点 `M-139`）。

### 1.4 恒久のガード

**★★`-check` ではなく `go test ./...` の `TestGolden_*MatchesRegeneration` 群である。⇒ `-check` はその部分集合にすぎない。**

## 2. ★★飛び道具の除外は「相手技側だけ」である — `DES-005` §5.20

### 2.1 設計書が 4 か所で書いていたのは、すべて相手技側の話だった

**本節 ／ `DES-002` §4.2 の `/api/punish-finder` 行 ／ `DES-004` §2.5 ／ `DES-003` §3.3 の `is_projectile` 列。⇒ いずれも始動技側に触れていない。**

| 側 | `is_projectile` の扱い |
|---|---|
| **相手技側** | **★除外する**（手動確認レーン `distance_dependent` へ回し、有利フレームの算出に到達しない） |
| **始動技側** | **★★見ていない。⇒ 飛び道具も始動技候補に入る** |

### 2.2 ★★裁定＝(a) as-built を正とする。始動技側に除外を入れない

**★理由＝`is_projectile` を除外する根拠は `DES-004` §2.5 の「着弾までが距離で変わるため `on_block` / `recovery` の単一値が有利フレームを意味しない」であり、これは相手技として有利フレームを算出する側の理屈である。**

**⇒ 始動技側が使うのは `startup` であり、同じ理屈は当たらない。⇒ 除外する根拠が無い。**

> **★製造がこの根拠を自分で立てて (a) を推し、判断そのものは設計卓へ返した**（コードを 1 行も触っていないため）**。⇒ 正しい振る舞いである。**

### 2.3 実際に効いた例

**mai の `midare_kachousen` / `flame_midare_kachousen`**（ともに `is_projectile=1`）**は、相手技側では手動確認レーンへ回るが、始動技側では候補に入る。**

**⇒ `D-158` が「6 行が確定反撃サーチの候補に入っているかは未確認」と残した点への答えが、この非対称であった。**

### 2.4 なぜ書くのか

**★走査 SQL は `is_derived` / `startup_basis` / `category` を投影すらしない。⇒ 相手技と始動技で同じ行集合を取り、除外の非対称はサービス層だけで表現されている。**

**★★書いておかないと、次の担当が「除外し忘れ」として起票する。**
