## 1. 変更の概要

### 1.1 何を確定させるか

**`DES-005` §6.6 は「必殺技（波動拳のような ↓↘→ 入力）の方向キー連続入力の UI 表現」を実装フェーズへ送っていた最後の 1 件である。** **同節は「机上の設計では最適解を導きにくい領域」と定めており、開発者判断で 3 点が確定した**（**D-377**）。

| # | 論点 | 確定 |
|---|---|---|
| 1 | **実演させるのか** | **★実演させる** |
| 2 | **入力ミスをどう扱うか** | **★入力ミスは解決しない。ただしコマンドの前方一致は許す**（`2 3 6 9 + P` は波動拳） |
| 3 | **ゆっくりな入力をどう扱うか** | **★コマンド技入力モードを持つ**（削除・保存・修飾と同じ層の操作）。**時間で切れない** |

**★論点 3 が骨格である。** **インゲームのコマンド入力は十数フレームの窓で成立するが、本アプリは「入力の記録」であって「対戦」ではない。**

### 1.2 ★設計卓が 1 つ規則を加えた（**最長一致**）

**開発者の指示は「前方一致を許す」までである。** **★これだけでは、コマンドが他方の先頭に含まれる技が短いほうへ解決される**——**SA のコマンドは必殺技のコマンドを先頭に含むためである。**

**⇒ 「候補が複数なら方向列が最も長いものを採る」を加えた。** **同じ長さで複数残るなら解決しない**（`DES-004` §5 の逆引きと同じ流儀）。

**★これは設計卓の推論であり、実データで意図と違う組が見つかったら設計卓へ上がる**（指示書 §9.4 の停止条件 2）。

### 1.3 CHANGE 対象と対象外の切り分け

| 対象か | 内容 |
|---|---|
| **対象** | 上記 3 点 ＋ **§6.6 の最後の 1 件の回収** |
| **対象**（as-built 次第） | **`DES-005` §6.2 の論理ボタン件数** ／ **§6.3.2 の登録対象件数**（**モードの操作を登録させるなら動く**） |
| **対象外** | **仮想コントローラ側のモーション実演**（**`DES-005` §6.1 の死守 2 は仮想側に掛かり続ける**） |
| **対象外** | **判定窓・判定アルゴリズム**（`CHANGE-107` / `M21-02` の as-built） |
| **対象外** | **`command` 記法の拡張**（連鎖・ホールドの表現＝`DES-004` の設計手番） |
| **対象外** | **ステップの並び替え**（followup `controller-complete-input-reorder`） |

### 2.1 ★【2026-08-14 追補＝D-379】反映先へ `DES-002` §4.2 を加えた

**製造の Plan Mode 実査で、フロントからモーション用のコマンドを読む経路が存在しないことが判明した。** **既存の解決表は単方向 ＋ ボタンだけに絞っており、多方向のコマンドは全て落ちる。** **他に本番で使える経路は無い。**

| # | 節 | 追加する内容 |
|---|---|---|
| **h** | **`DES-002` §4.2** | **★モーション用の読み取り経路を明記する。** **★あわせて「既存の解決表とは目的が違う」ことを書く**——**既存は段階2 の解決表であり**（`DES-004` §2.4.4 の形状フィルタ）、**広げると仮想コントローラの一様フォールバックが変わる。** **★同じ表の別の見え方であって、既存を緩めたものではない。** **書かないと、次の担当が「1 本に統合できる」と読んで既存を広げる** |
| **i** | **`DES-002` §4.2 または `DES-005` §6.4** | **★取得の流儀を明記する**——**キャラ選択時に 1 回取得し、入力ごとに往復しない**（**既存の解決表と同じ流儀**）。**★取得に失敗しても入力は壊れない**——**モードに入れないだけで、既存の入力経路は今までどおり動く**（`DES-005` §6.4 の「取得失敗でも段階1 だけで動く」と同じ） |

> **★契約は直さない。** **`m21-contract` の F-1 は `recipe_cache` の読み書き契約であり、`internal/service/inputresolve/` はどの条項でも凍結されていない。** **★指示書 v1.0.0 §2.2-7 が「`internal/` 全体（契約 F-1）」と書いたのが誤りであった**（**M-65**）。**⇒ 指示書 v1.1.0 で是正した。**

> **★前方一致・最長一致はフロントが行う。** **バックエンドは表を返すだけである**——**段階1 の縮約をフロントが持っているのと同じ位置づけであり、`DES-004` §2.4.4 の「FE は規則を持たない」**〔どの技が表に載るかの規則〕**には触れない。**
