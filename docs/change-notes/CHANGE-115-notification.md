## 1. 変更の概要

**`M22-03`（`CHANGE-114`）がサーバ側の契約を固める**——**版が古いと 409 ＋ `version_conflict` を返す。**

**★しかし「拒否されたあと、利用者がどうすればよいか」はどこにも書かれていない。**

**`DES-006` §11.2 が定めるのは「保存実行時にモーダルダイアログで表示」「原因と対処方法を併記」までである。** **⇒ 版不一致に固有の事情**——**利用者が時間をかけて書いたものが手元にあり、それを失わせてはいけない**——**が書かれていない。**

**⇒ 本 CHANGE がそれを書く。**

**★非スキーマ・非破壊である。** **DB のテーブル・列・制約を 1 つも変えない。** **マイグレーションを消費しない。** **★サーバ側も変えない見込みである**（`M22-04` は画面のサブである）。

### 1.1 CHANGE 対象外（切り分け）

| 項目 | 対象外の理由 |
|---|---|
| **版不一致時の応答の契約**（ステータス・エラーコード・本文） | **`CHANGE-114`（`M22-03`）の担当。** **★本 CHANGE は画面側である** |
| **★差分の自動提示**（相手が何を変えたかを並べて見せる） | **★本 CHANGE では作らない**（§4）。**コンボは本体・ステップ・起き攻め・タグの集約であり、差分を作るには専用の比較 UI が要る。** **⇒ `M22-04` の枠を超える。** **★開発者への確認事項に挙げてある**（§6） |
| **自動マージ** | **同上。** **★「どちらが正しいか」を機械が決めることになり、`FR501` の目的〔誤上書きの防止〕と正面から反する** |
| **`version` 列の追加 ／ 楽観排他の対象を増やすこと** | **`D-394` で確定済み** |
| **一意制約違反の 409 の見せ方の変更** | **`DES-005` §5.11 の as-built。** **★触らない**（§2-c） |
| **CORS/CSRF** | **`M22-05` の担当** |

### 2.2 真因の記録

**★バグ修正ではない。** **`DES-006` §11.2 は「ERROR はモーダルで表示し、原因と対処方法を併記する」と定めており、それ自体は正しい。**

**★足りなかったのは、版不一致に固有の事情である。**

| # | 版不一致が他の ERROR と違う点 |
|---|---|
| 1 | **★利用者の手元に「まだ保存されていない作業」がある。** **他の ERROR〔値の範囲・必須未入力〕は、直せばその場で保存できる。** **版不一致は直しようがない**——**相手が変えたのであって、自分の入力が間違っているわけではない** |
| 2 | **★「失敗」ではなく「防いだ」である**（`FR501`）。**⇒ 他の ERROR と同じ見せ方をすると、利用者は自分が何か間違えたと思う** |
| 3 | **★409 という同じステータスを、別の意味で既に使っている**（`DES-005` §5.11）。**⇒ 表示方針を書かないと、実装がステータスで分岐して取り違える** |

**⇒ 「ERROR の表示方針」だけでは足りず、版不一致に固有の項が要る。**

## 3. ★文言案（**指示書 `M22-04` §4.5 が参照する**）

**★本節は「そのまま使ってよい案」である。** **より良い言い回しを思いついたら変えてよい**（**★変えた場合は完了報告へ新旧を並べる**）。

**方針は `CHANGE-113` §6.1 の 5 点をそのまま引き継ぐ**（**★「バージョン」「排他」「競合」「コンフリクト」も説明なしに使わない**）。

### 3.1 版不一致で保存できなかったとき（**モーダル**）

```
ほかの人がこのコンボを変更しました

あなたが開いたあとに、ほかの人がこのコンボを変更しています。
そのまま保存すると、その変更を消してしまうため、いったん止めました。

入力した内容はこのまま残っています。

  [ ほかの人の内容を見る ]  [ 読み込み直す ]  [ 閉じる ]
```

**★「いったん止めました」が `FR501` の「防いだ」を伝える部分である**（指示書 §4.3-6）。**「エラー」「失敗」と書かない。**

**★「入力した内容はこのまま残っています」を必ず書くこと**——**利用者が最初に知りたいのは「書いたものは無事か」である。**

### 3.2 「読み込み直す」を押したとき（**確認**）

```
読み込み直しますか

ほかの人の内容を読み込みます。
いま入力している内容は失われます。

  [ 読み込み直す ]  [ やめる ]
```

**★押す前に伝えること**（指示書 §4.3-3）。

### 3.3 「ほかの人の内容を見る」を押したとき

**★別枠で開き、編集中の画面を離れないこと**（指示書 §4.3-3）。**⇒ 離れると入力が消える。**

**★文言は要らない**——**開くだけである。**

### 3.4 セットプレイの場合

```
ほかの人がこのセットプレイを変更しました
```

**★以下は §3.1 と同じ。** **「コンボ」を「セットプレイ」に置き換えるだけである。**

### 3.5 ★自分の内容で上書きする道を出す場合（**§4 の分岐で (C) を採ったときだけ**）

```
ほかの人の変更を消して、自分の内容で保存しますか

ほかの人がこのコンボに加えた変更は失われます。
先に「ほかの人の内容を見る」で確かめることをおすすめします。

  [ ] ほかの人の内容を確認しました

  [ 自分の内容で保存する ]  [ やめる ]
```

**★チェックを入れるまで押せない**（指示書 §4.3-4 の「2 段階」）。**★押しやすい位置に置かないこと。**

## 4. 確定した設計判断

| 項目 | 判断 | 根拠 |
|------|------|------|
| **入力の保持** | **★保持する。自動で読み込み直さない** | **★競合が起きるのは「利用者が時間をかけて何かを書いたあと」であり、保存を押すまで気づかない。** **⇒ 自動再読込がそのまま作業の消失になる** |
| **分岐の判定** | **★エラーコードで分岐する。ステータスで分岐しない** | **409 は一意制約違反でも使われている**（`DES-005` §5.11）。**⇒ ステータスで分岐すると、プリセット別名の重複が「ほかの人が変更しました」と表示される** |
| **差分の自動提示** | **★作らない** | **コンボは本体・ステップ・起き攻め・タグの集約であり、差分を作るには専用の比較 UI が要る。** **⇒ `M22-04` の枠を超える。** **★代わりに「相手の現在の内容を見る」導線で代替する**（既存のコンボ詳細画面を再利用する）。**★開発者への確認事項**（§6） |
| **自動マージ** | **★作らない** | **「どちらが正しいか」を機械が決めることになり、`FR501` の目的〔誤上書きの防止〕と正面から反する** |
| **上書きの道** | **★409 の応答本文に何が載るかで決める**（指示書 §4.4） | **(A) エラーコードだけ → 出さない**〔相手が何を変えたか知る手段が弱く、判断材料にならない〕 ／ **(C) 相手の内容が載る → 出してよい**〔2 段階を守ること〕 |
| **サーバ側の変更** | **★行わない** | **`M22-04` は画面のサブである。** **★本文を足させないこと**——**要ると判断したら止めて報告する** |
| **「防いだ」の伝え方** | **★「エラー」「失敗」と書かない** | **`FR501` の目的は「他の利用者の編集を誤って上書きすることを防ぐ」である。** **⇒ 防げたのだから、利用者から見ても「防げた」と読める形にする** |
