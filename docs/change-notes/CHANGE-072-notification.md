## 1. 変更の概要

**「どこから・どの形式で出すか」だけを変える**。**出力文書の内容・レイアウト・既定は不変**（CHANGE-052/068）。エクスポートの起点を **エクスポート専用画面（§5.13）から 一覧・マイコンボの選択＋モーダル（エクスポートダイアログ）へ移す**（別紙 §2 の「段階廃止案」の**第 1 段**）。**§5.13 画面は温存**（第 2 段＝画面除去は別途個別承認＝M17-overview §5 判断点）。

性質の宣言:

- **非破壊・スキーマ変更ゼロ**。**BE 全体（`internal/`）・マイグレーション 変更なし**。**CSV 契約（DES-002 §7.6）不変**。
- **既存機構の流用**: 選択 UI＝M15-02「比較対象選択」（`useSelectMode`・無改修）／export 生成関数＝M13-02（`export-data.ts`／`export-image/`・無改修）。**作り直していない**。
- **出力文書は不変**: 単独＝§5.6 相当／複数＝§5.8 比較表相当（CHANGE-052）。**メディアは URL/パスの文字列のみ**（CHANGE-068）。
- **i18n 境界を守る**: ダイアログ・一覧の UI ラベルは i18n（ja/en）／エクスポート文書内ラベルは固定 ja（M16-06 境界）。

## 2. 変更の内容

### 2.1 DES-005 §5.4（一覧の項目6・項目7・アクション）

| # | 対象 | 変更 |
|---|------|------|
| a | 項目6 選択トグル | **「比較対象選択」→「比較/エクスポート対象選択」へ再改称**。M17-05b でエクスポート導線も**同じ選択状態（`selectedIds`）を共有**するようになったため。**可視ラベルのみ・機能/遷移/データ不変**。**このトグルは M15-02（選択モード → 比較対象選択）→ M17-05b（比較/エクスポート対象選択）で 2 回改称**した（実装は `selectMode.enter` キーのみ変更・回帰テスト `m15-02-info-mark.spec.ts` を現行ラベルへ追従）。|

### 2.2 DES-005 §5.5（マイコンボ）

- マイコンボは**同一の選択トグルを共有**するため、§5.4 の項目6 再改称・項目7 ダイアログ化が**同時に適用**される旨を明示（「コンボ一覧とほぼ同様」に含まれる暗黙分の顕在化）。

### 2.3 DES-005 §5.13（エクスポート画面・温存）

- **「全選択時の行数は 25 → 28」→「全選択時の出力行数は 25 → 28」** と明記し、直下に**書き分け注記**を新設: **「28」は出力文書に印字される行数であって、ダイアログのチェックボックス数ではない。選択可能なチェックボックスは 17 個**（`export-items.ts`）。**差の内訳＝「起き攻め情報」1 チェックボックスが §5.8 準拠の 12 行へ展開**＝**17 チェックボックス → 28 出力行**。**今後この「28」を参照する指示書・DES では「チェックボックス数＝17／出力行数＝28」を書き分けること**。
- **§5.13 画面そのものの内容・既定は不変**（第 1 段では温存）。

### 2.4 DES-005 §5.13a（エクスポートダイアログ・新設）

- **対象**＝選択中コンボ（`selectedIds`）／選択ゼロなら現フィルタ全件。**一覧が取得済みの `ComboSummary[]` の id を `range=selected&ids=[...]` でそのまま渡す**＝**WYSIWYG を構造的に保証**（BE の `range=filter`/`range=mycombo` はダイアログからは不使用＝§4 参照）。
- **表示項目**＝(1) 出力形式 複数選択（**クリップボードは単独選択時のみ活性**＝排他・**複数形式は順次生成/DL・ZIP 非束ね**）／(2) 出力項目 **17 チェックボックス・既定 ON**（内容は §5.13/CHANGE-052/068 のまま）／(3) PDF/PNG オプション（**分割オプションは持たない**＝分割は M17-05c で既定挙動）／(4) 実行ボタン。
- **選択上限の分界**＝選択状態（`selectedIds`）は比較（最大 5・`MAX_COMPARE_COMBOS`）とエクスポート（BE 上限 1000・`exportRowLimit`）で**共有**し、**「比較」ボタンのみ 5 超で非活性**。**5 件上限は比較固有の制約であって選択状態の上限ではない**。
- **i18n**＝ダイアログ/一覧の UI は i18n（ja/en）／出力文書内は固定 ja。

## 4. 設計判断として記録する製造側の申し送り（DES に直接は載せないが後続に効く）

1. **選択上限の分離でバグを一度作り込んだ**（比較の「5 件上限到達の即時フィードバック」が 5 件基準から外れた）＝独立レビューで検出・是正済み（`c2f8a00`）。**§5.13a に上限の分界を明記**したのはこの再発防止のため。
2. **`range=filter`/`range=mycombo`（M13-01 由来）はダイアログから不使用になった**（`ComboExportPage.tsx` 単体では引き続き使用）。**§5.13 画面が第 2 段で除去されると利用箇所がゼロになる**＝**第 2 段の設計時に「これらの range 種別が本当に不要か」を判断する材料**（BE コード削除は今回スコープ外）。
3. **選択・エクスポート関連ロジックが `ComboListPage`/`MyComboPage` に重複実装**（`useExportSelection` 相当の共有フック未抽出）＝CLAUDE.md「3 箇所目で共通化」の範囲内だが、**3 箇所目（取込プレビュー等）が来たら抽出を検討**＝followup §E（リファクタ）へ記録。
4. **複数形式同時 DL の 300ms 待機は簡易対応**＝**実ブラウザで 3 形式以上のブロック有無は未検証**（開発者の実機確認事項・§7 参照）。

## 7. 開発者への確認事項

1. **複数形式同時ダウンロードの実ブラウザ確認**（要・製造未検証）
   - **何を**: 通常の Chrome/Edge/Firefox で **3 形式以上（CSV+PDF+PNG 等）を同時実行**した際、ブラウザの「複数ファイルのダウンロード許可」でブロックされないか。
   - **なぜ**: Playwright（Chromium headless）は自動許可のため未検出。**初回成功・2 つ目以降ブロック（ユーザーが気づきにくい）**の可能性が残る。
   - **暫定案**: まず実機確認。ブロックが出たら (a) 間隔延長／(b) 2 つ目以降はユーザークリック起点／(c) ZIP 束ね〔**指示書の「ZIP に束ねない」を CHANGE で覆す必要**〕の順で検討。**現時点では DES に「300ms 簡易対応」を書かず、確認結果を待って追記**します。

2. **選択トグルの正典ラベル管理（改称運用）**
   - **何を**: このトグルは 2 回改称（選択モード → 比較対象選択 → 比較/エクスポート対象選択）。**今後の改称も都度 CHANGE を起票する運用でよいか**、それとも **DES-005 側でこのトグルの正典ラベルを SSOT として一元管理**（改称を errata 扱いにできる形）にするか。
   - **なぜ**: 第 2 段（§5.13 画面除去）で「エクスポート」の語の露出が変わると**3 回目の改称**があり得ます。
   - **暫定案**: **当面は都度 CHANGE**（可視ラベルの変更は利用者影響があり記録価値がある）。SSOT 一元化は playbook メジャー改訂（M18・§10）で「ラベル正典の管理方針」として整理するのが安いと考えます。**この方針でよいか。**

3. **§5.4 項目7「常時表示」の追認**
   - **何を**: エクスポートボタンを**選択モード ON/OFF に関わらず常時表示**にした点（製造が指示書の暫定案を採用・個別確認なし）。
   - **なぜ**: 実装済みですが、DES に正典として固定する前に追認をいただきたい（**「選択モード時のみ表示」を望む場合は §5.13a を修正**）。
   - **暫定案**: **常時表示のまま**（選択ゼロ＝全件フォールバックがあるため、選択せずとも押せる方が動線として自然）。
