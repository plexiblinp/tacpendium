## 1. なぜ要るか

**`M31-04` が `drive_reversal` を全キャラ 31 行で投入し、確定反撃の走査に載せた。⇒ 設計書は「必要が生じたら扱う」までしか書いていない。**

**★★あわせて、実装を読んで初めて分かった as-built が 3 件ある。⇒ 書かないと、次に走査へ技を足すサブが同じ実査からやり直す。**

---

## 2. 変更内容

### 2.1 `DES-002` §4 — ドライブリバーサルを走査対象へ入れた

**`CHANGE-169` §3 が「必要が生じた」と書いた状態が実現した。⇒ マイグレ `000109` で全キャラ 31 行を投入した。**

**★取込からの除外そのものは変えていない。**

### 2.2 `DES-003` §3.3 — ドライブリバーサルの持ち方

| 事項 | 内容 |
|---|---|
| 行数 | **全キャラ 1 行ずつ**（sf6 キャラ 31 → 31 行） |
| `category` | **`system`**（`drive_parry` の前例に揃えた） |
| **★持ち場** | **`character_data/*.csv` ではなくマイグレ側**（`000025` / `000083` と同じ扱い） |
| 理由 | **CSV は攻撃技の手入力データである。⇒ 全キャラ一律の system move は CSV の母集団ではない。★`csv_db_sync_test` は CSV 行を起点に突合するため、DB 側にだけ在る行は母集団外である** |
| 値 | `damage=500`（`DES-002` §4 の逐語が一次源）／ `on_block=-6` ／ `recovery=27`（開発者・2026-09-08）／ `startup` / `active` / `total` / `on_hit` は **NULL**（一次源が無い） |

**★`drive_parry` の項の隣に 1 項として置く。**

### 2.3 ★★`DES-005` §5.20 — 確定反撃の走査は「述語 1 本」ではなく「述語 ＋ 4 つのふるい」である

**★★これが本 CHANGE で最も価値のある 1 点である。⇒ 実装を読まないと分からない。**

| 層 | 何をするか |
|---|---|
| **リポジトリ** | **絞っていない**（当該キャラの `moves` を全投影） |
| **サービス（除外）** | `is_aerial=1` ／ `category='system' ∧ code ∈ 移動 9 code` **の 2 条件だけ。⇒ `system` を一律には除かない** |

**★★4 つのふるい**（サービス pass 1）:

| ふるい | 落ちる先 |
|---|---|
| **`damage = 0`** | **完全除外**（画面に出ない） |
| **`damage IS NULL`** | **手動確認レーン `unknown_damage`** |
| **`is_projectile = 1`** | **手動確認レーン `distance_dependent`** |
| **`on_block IS NULL`**（block タブ） | **手動確認レーン `data_missing`** |

**★★★したがって「行を入れて `on_block` を入れる」だけでは成立レーンに出ない。⇒ `damage` を非 NULL かつ ≠ 0 にする必要がある。**

**★★★否定の記述に注意する＝「データが無いので走査に出ない」は成り立たない。⇒ NULL は「出ない」ではなく「手動確認レーンに出る」である**（計測点 `M-155`）**。**

### 2.4 `DES-005` §5.20 — ガード種ごとに走査から外す技が在りうる

**`justParryExcludedCodes`（現在 1 件＝`drive_reversal`）。**

- **成立レーンにも手動確認レーンにも出さない**（開発者の逐語＝「取り扱わなくてもいい」）
- **★ブロックタブからは外していない。★除外は `code` 単位である**（`category='system'` を丸ごと外していない）**。⇒ `drive_parry` は JP タブに出続ける**
- **「27F」という事実は `moves.recovery` に残っている**

**★★画面表現の追随は要らない**（2026-09-10 開発者の実機確認＝「消えている。気持ち悪さもなかった」）**。**

### 2.5 ★★★`DES-005` 第6節 — 未分類タブの等式が崩れた

**★★`CHANGE-170` §2.4 は「未分類タブ ＝ `isControllerSurfaced` の裏返し 1 本」と書いていた。⇒ 崩れた。**

```
未分類 ＝ isControllerSurfaced の裏返し ∧ 非除外
```

**★`M31-04` が `INPUT_EXCLUDED_MOVE_CODES` / `isInputExcluded()`**（`web/src/features/combo/moveSurfacing.ts`）**を新設し、2 面へ効かせた。**

| 面 | 実体 |
|---|---|
| **仮想コントローラのタブ**（**未分類を含む**） | `surfaceBuckets` の `unclassified` 分岐 |
| **全技一覧のプルダウン** | `useControllerInputOmission` の `selectableMoves`（**トグルの状態に関係なく常に落とす。★`omittedCount` には数えない**） |

**★★共通技タブの固定 13 code には触れていない。**

**★★★「入力面」に引っ越し取込は含めない**（2026-09-10 開発者判断。逐語＝「ユーザーがあり得ないコンボを入れたりとかは考えなくていい」）**。⇒ 塞ぎ忘れではなく対象外と決めた結果である。**
