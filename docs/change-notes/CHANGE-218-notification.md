## 1. ★★★値域は 1 つも増減していない

**★`hit_type` は 8 値のままである。⇒ `SUPP-001` §3.2 の値域の表は不変。**

**★★★足したのは「エディタの既定は `normal` である」の 1 行だけである**〔着手前は空＝保存時 NULL〕**。**

**★★「不問」を値域へ足していない。⇒ `M38-01` が消したのは*描画側のヘルパが足していた選択肢*であって、値域ではない**（そもそも値域に無かった）**。**

## 2. ★★★本通知書の核 — **既定値の変更は境界を動かす**

**★`DES-006` §2.3 は重複判定で「NULL 同士は一致」と定めている。**

| | 重複判定での扱い |
|---|---|
| **`hit_type` が NULL の既存行どうし** | **一致する**（畳まれる） |
| **★NULL の既存行 と `normal` の新規行** | **★★別キーになる**（他がすべて同じでも） |

**⇒ 見た目が同じコンボを重複登録できる状態が新たに生じた。**

### 2.1 ★★着手前も同じ穴は在った

**★既定が NULL だったため「NULL 同士は一致」で畳まれており、表に出ていなかっただけである。⇒ `M38-01` は穴を作ったのではなく、境界の位置を動かした。**

### 2.2 ★★母数 — **91 件**

**★開発者が実 DB で実測した**（2026-09-17）**＝`hit_type IS NULL AND deleted_at IS NULL AND is_draft = 0` ＝ 91 件。**

**★検証用 DB の数であり、そのまま残してよいと判断済み**（開発者）**。⇒ ただし実利用の DB でも同じ形が起きる。**

### 2.3 ★★寄せるマイグレは作らない（**裁定**）

| # | 理由 |
|---|---|
| **★★1** | **NULL 行は「通常と判断された行」ではなく「既定のまま保存された行」である。⇒ 寄せることは、誰も確かめていない主張をデータへ書くことになる** |
| **★2** | **`hit_type` は重複判定キーの 1 つであり、寄せると衝突しうる。★その衝突を数える手段が無い**〔`recipe_hash` は列として保存されておらず Go 側で計算している。⇒ 純粋な SQL では数えられない〕 |
| **★3** | **寄せない側の代償は小さく、`opponent_stance` の先例が在る** |

**★払い出し済みのマイグレ `000118` は未消費で返す。**

## 3. ★★★一般則を `SUPP-001` §2.2 へ刻んだ

**「重複判定キーに入る列の*既定値*を変えるときは、変更前の既定で保存された行が何件あるかを数えること。⇒ その件数が『以後の行と畳まれなくなる』母数である。」**

**★★これは「値域を変えるな」ではない。⇒ 既定値は値域ではないため、値域の同期検査**（`check-enum-sync.sh`）**には 1 件も現れない。★見落としやすい面である。**
