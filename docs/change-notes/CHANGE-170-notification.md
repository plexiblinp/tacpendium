## 2. 反映内容（`DES-005` 第6節・入力面）

### 2.1 カテゴリタブが 8 枚になった

**★現在の記述「通常技／特殊技／投げ／必殺技／SA／システム／ドライブインパクト」が失効した。**

| # | タブ | `data-testid` | 母集団（述語の逐語） |
|---|---|---|---|
| 1 | 通常技 | `recipe-tab-normal` | 段階2 解決表 → 段階1 構造引き（**不変**） |
| 2 | 特殊技 | `recipe-tab-unique` | `category === "unique"`（**不変**） |
| **3** | **ターゲットコンボ** | `recipe-tab-target-combo` | **`category === "target_combo"` の全行。★`is_derived` で絞らない** |
| 4 | 必殺技 | `recipe-tab-special` | `category==="special"` ∧ `parseSpecialCode(code) !== null`（**不変**） |
| 5 | SA | `recipe-tab-super-art` | `category ∈ {super_art, critical_art}`（**不変**） |
| **6** | **未分類** | `recipe-tab-unclassified` | **`isControllerSurfaced()` が false を返す行そのもの** |
| **7** | **キャラ固有状態** | `recipe-tab-character-state` | **`custom_states[].code`（＋語幹）を `move_code` が含む行** |
| **8** | **共通技** | `recipe-tab-common` | **固定 13 code（§2.2）。★一番右**（開発者指示） |

**★★ターゲットコンボタブが `is_derived` で絞らない理由**——**`M19-DESIGN-08` §0 の述語 `NOT (category='target_combo' AND is_derived = 1)` は filler 候補から除く側のものであり、入力面は「出す」側である。⇒ 裏返すと 126 行中 117 行が入力できず、`SM-135`「ターゲットコンボも入力に欲しい」と真逆になる。**

### 2.2 共通技タブの母集団は固定 13 code である

```
forward / back / micro_forward / micro_back /
jump_neutral / jump_forward / jump_back /
drive_impact / drive_parry / throw_forward / throw_back /
dash_forward / dash_back
```

- **13 code すべてが実 DB に 31 キャラぶん在り、`official_ja_move` の表示名も付いている。⇒ ラベルは `nameJa` をそのまま使う。**
- **★生ラッシュ**（`parry_drive_rush`）**はこの 13 に入れない。⇒ move ではなく `modifiers.type` だからである**（`DES-004` §2.1）**。★タブ内に別ボタンとして置いた。**
- **★★移設前の常設行が引いていたのは 6 code だけで、移動系 7 code**（`forward` / `back` / `micro_*` / `jump_*`）**はどの面にも出ていなかった**——**実 DB で 217 行**（7 × 31）**。⇒ 本サブで初めて入力可能になった。**

### 2.3 常設行は削除ボタンだけになった

**★`SystemRow` を削除し `DeleteRow` へ改めた。⇒ 削除だけはタブへ入れない**（どのタブに居ても直前のステップを消せる必要があるため）**。**

### 2.4 「未分類」は 1 本の述語の裏返しである

**`isControllerSurfaced()` が 通常技 ∨ 特殊技 ∨ 必殺技 ∨ SA ∨ ターゲットコンボ ∨ 共通技 ∨ キャラ固有状態 の論理和であり、未分類タブはその否定である。⇒ 同じ述語の裏返しを `SM-100` のトグルも使う。★規則を 2 か所へ書かない。**

**★キャラ固有状態タブを「掲載済み」に数える**（2026-09-08 開発者判断・案 C）**。⇒ 未分類との重なり 45 件 / 5 キャラが消えた。**

### 2.5 キャラ固有状態タブの判定軸

**★状態 code ＋ その語幹で照合する**（後置語 `_stock` / `_mode` / `_is_set` / `_crest` / `_charge` を落とした形）**。★新しい列も新しい API も足していない。**

**★実測の効き目**（定義を持つ 14 キャラ）＝mai **0 → 26** ／ ingrid **0 → 31** ／ juri 2 → 11 ／ kimberly 0 → 6 ／ yasmine 1 → 5。

### 2.6 `SM-100` のトグル

| 項目 | 内容 |
|---|---|
| 文言 | **「タブに分類済みの技を省く」**（開発者判断・案 A） |
| 既定 | **OFF** |
| **★保持** | **component-local の `useState` のみ。⇒ ブラウザストレージへ置いていない。★`web/CLAUDE.md` §1 の台帳へ新キーを足していない** |
| **★安全性** | **ON にしても入力手段が消える技は 1 件も無い**（残る集合＝未分類タブの母集団と完全に一致） |
| 対象 | **2 面**（コンボのレシピ入力・セットプレイのレシピ入力） |

## 3. ★★裁定 (2) — 実測の母集団を規約化する（`SUPP-001` §5.5 系）

### 3.1 何が起きたか

**★指示書 §2.1-3 は「`moves` に在って仮想コントローラに出ない行を全数で挙げること」と書いていた。⇒ `moves` はテーブルである。★製造は `character_data/*.csv` を「seed の正本」と見なして数えた。**

| | 製造が数えたもの | 実際 |
|---|---|---|
| 母集団 | CSV **2743 行** | `moves` **3026 行** |
| 未分類（着手時点） | **330 行**と報告 | **551 行** |

**★差の 283 行はマイグレーションが直接投入する行で、大半は移動系 system 技 217 行である。⇒ 開発者が実機で「システムの move が未分類に居る」と気づくまで、誰も検出していない。**

**★あわせて誤報が 1 件あった**——**「`dash_forward` / `dash_back` は seed に無いので押しても何も起きない」は誤りで、実 DB に 31 キャラぶん在る。**

### 3.2 ★★最も重い点

**★★誤った母集団を回帰テストで「実測の固定」として緑にしていた**（`moveSurfacing.roster.test.ts` 初版）**。⇒ テストが在ることは、確からしさの証明にならなかった。**

### 3.3 反映内容（規約 1 行）

**★★`SUPP-001` §5.5 系へ次を足す。**

```
★★seed の実測は `moves` テーブルに対して行う。
   `character_data/*.csv` は入力の一部でしかない。

⇒ マイグレーションが直接投入する行（移動系 system 技ほか）が CSV に存在しない。
★実測の差は 283 行あった（2026-09-08・M30-01）。

★★「実測」を名乗るときは、母集団が仕様の言う対象と同じかを最初に確かめる。
   ⇒ 「seed」という語が指すものは 1 つとは限らない。
     数える前に、その語が実装のどこに対応するかを 1 度たどる。

★★誤った前提を回帰テストで固定すると、誤りが「検証済み」の外観をまとう。
   ⇒ 新しく固定する数値は、それを算出した経路そのものを 1 度疑う。
```
