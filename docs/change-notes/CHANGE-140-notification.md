## 2. 変更の内容

### 2.1 ★★`CO-002`——**「既存から紐付け」を消す。ただし候補 0 件のときの穴が開く**

**開発者の逐語（`SM-062`・memo line 134）＝「編集の既存から紐付けボタンもういらない。起き攻めフレームが一致するものだけ候補としたため役割が被ってる。視覚的にわかりやすいので、候補表示の方を採用し紐付けボタンは消したい。」**

**★★「役割が被っている」は事実である**——**`M12-03/6.5-1` で「既存から紐付け」モーダル（`LinkExistingSetupModal`）の候補抽出も「同一キャラ ＋ 同一 `knockdown_advantage` ＋ 当該コンボ未紐付け」へ絞られた**（`DES-005` §5.6 項目11 の逐語）。**⇒ 2 つの面は既に同じ母集団を出している。**

**★★ただし穴が 1 つ開く。** **`DES-005` §5.6 項目11 の逐語＝「候補が0件の場合は本セクション自体を非表示」。**

**⇒ 候補 0 件のとき、紐付けボタンも消えると、画面から紐付ける入口が完全に消える。**

| 案 | 内容 | 設計卓の評価 |
|---|---|---|
| **A** | **候補 0 件でもセクションを出し「候補はありません」と書く** | **★入口が消える問題は解けない**（紐付けられる相手が居ないため）。**★ただし「機能が消えた」と誤解されるのは防げる** |
| **B** | **候補 0 件のときだけ「既存から紐付け」を残す** | **★★2 系統を残すことになり、要求（一本化）に反する** |
| **C** | **`knockdown_advantage` が一致しないセットプレイも紐付けられる手段を別に用意する** | **★射程が広がる。★そもそもそんな需要があるかが分からない** |

**★設計卓の暫定案＝A。** **★★ただし「KA が一致しないセットプレイを意図的に紐付けたいことがあるか」は開発者のドメイン知識が要る**（§7 確認事項 1）。

### 2.2 ★`SM-052` / `SM-146` / `SM-011`

| ID | 決めたこと |
|---|---|
| **`SM-052`** | **セットプレイ側のレシピ修飾（メモ）の表示をコンボ側と揃える。** **★★followup `setup-recipe-display-not-through-shared-component` と同根である**（**セットプレイのレシピ表示が `M24-03` の共通部品 `RecipeText` を通っていない・5 か所**）。**⇒ 本サブの射程へ入れる**（§3.1） |
| **`SM-146`** | **セットプレイから「その最後の技を始動とするコンボ」へ飛ぶ導線を置く。** **★「最後の技」の定義と飛び先の形は §7 確認事項 3 ＋ 実査で決める** |
| **`SM-011`** | **セットプレイ編集にコピー機能を足す。** **★コンボ側の「コピー」（新規登録モードで初期値を投入）と同じ形にする。★新しい作法を作らない** |

### 2.3 ★★`SM-088`——**セットプレイ名の自動生成**

**memo の逐語＝「セットプレイ名は自動で〇〇重ねと最後の技から生成されるようにしたい。ユーザーは入力サボっても登録できるが、自動で必須項目をコードが埋める」。**

| 論点 | 決めたこと |
|---|---|
| **★必須は外さない** | **`VAL-S06`（セットプレイ名が空でないか・ERROR・create/update 両方で空クリア禁止）を撤回しない。** **⇒ 「空でも登録できる」ではなく「空なら自動で埋めてから保存する」である** |
| **★埋めるのはどこか** | **★フロントで埋める**（利用者が保存前に見て直せる）。**★★実査項目**——BE で埋めると `VAL-S06` の位置と矛盾しうる（§3.3） |
| **★命名の規則** | **★★確定していない。§7 確認事項 2** |

**★★「〇〇重ね」は起き攻めの `attack_type` を指すと読める**（投げ重ね／シミー／打撃重ね）。**★ただし設計卓は語の対応を裏取りしていない。**
