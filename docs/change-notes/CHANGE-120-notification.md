## 1. 変更の概要

**★`M22-07` は「辞書に行を足す」ために起票されたが、制約①`UNIQUE (preset_id, move_id)`＝1 技 1 表記が塞ぎ、行を 1 行も投入できなかった**（`CHANGE-118` §7 ／ **D-438**）。

**⇒ 投入方式として 4 案 A / B / C / E が出そろい、開発者が案 E を採ることを決定した**（2026-08-18・**D-442**）。

**★案 E＝辞書ではなく規則で解く。** **逆引きの索引を組む材料が `move_code` を持っており、SA 番号は既存の規則でそこから導ける。** **⇒ 行もマイグレもスキーマ変更も要らない。**

### 1.1 ★なぜ E か（**D-440** の要約）

| # | 理由 |
|---|---|
| 1 | **行もマイグレもスキーマ変更も要らない。** **⇒ 「行を増やす作法」の問題自体が消える**（制約①に当たらない） |
| 2 | **★次のキャラ波でも自動で効く。** **規則であるため `DES-004` §5.4 の再適用が要らない。** **`D-437` が警告した「人が再投入しないと新キャラだけ空になる」問題が、SA 番号については構造的に消える。** **★A / B / C はどれもこの性質を持たない** |
| 3 | **★多義を捨てない。** **A / B / C は §5.5 の「衝突組は両方落とす」に当たって多義の組を捨てるが、E は §5.0.2 規約 1 により「未確定 ＋ 候補提示」へ倒れる。** **利用者にとっては「解決しない」より「候補が出る」ほうがよい** |
| 4 | **新しい規約を作らない。** **§5.0.2 が「段を足してよい」を既に定めている** |

### 1.2 ★A / C を採らなかった理由（**記録として残す**）

| 案 | 却下の理由 |
|---|---|
| **A**（表記の流儀としてプリセットを 1 枚足す） | **★利用者に見える害がある**——**プリセットを「選ばせない」手段が無く、選ぶと一部の技だけ番号表記・残りは §5.3 のフォールバックという混在表記になる。** **かつ「プリセット＝表記の流儀」という意味論が崩れる**（番号は流儀ではない） |
| **C**（制約①の撤回） | **★最重であり、しかも表示が不定になる。** **`DES-003` §3.9 が「再構築は写し落とし事故を持ち込む」として明示的に避けた当のものを、機能差のために持ち込むことになる** |

### 1.3 ★B は捨てていない（**保留である**）

**案 B（逆引き専用の器を別に持つ）は、ドメイン知識が要る別名＝技通称のための案であり、E とは解く問題が違う。** **⇒ 排他ではない。**

**★ただし技通称は 2026-08-18 に「いったん非対応・将来課題」と決定した**（**D-443**）。**⇒ B の要否はその判断に従属し、いまは着手しない。**
