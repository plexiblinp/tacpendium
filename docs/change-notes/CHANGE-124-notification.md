## 1. 変更の概要

**復元は現在、何も検証していない**（`M23-RESEARCH-01` H-4 の逐語）。**本 CHANGE はそこへ検証を足すが、「落とすため」ではなく「伝えるため」に足す。**

1. **`DES-006` へ「復元時のバリデーション」の節を新設する**（§2.1）。**★`VAL-R01` / `VAL-R02` の 2 件を新設し、`VAL-C08` / `VAL-S03` の適用先に復元経路を加える。**
2. **★復元経路では ERROR 種別も復元を止めない**——**`DES-006` §1.1 の「例外はブロッキング」に対する明示的な例外として書く**（§2.2）。
3. **`DES-002` §4.2 の復元 2 経路の成功応答に `warnings` が載る旨を足す**（§2.3）。**★あわせて `superseded_by_combo_id` の持ち越し 1 件を決着させる。**
4. **`DES-005` §5.15 へ、復元したときの警告の見せ方を足す**（§2.4）。

**★CHANGE 対象外**——**削除済み行と再登録の衝突**（`M23-05`）／ **ゴミ箱の列構成・導線**（`M23-06` / `M23-07`）／ **完全削除の前チェック・CASCADE 依存**（`M23-08`）／ **既存の登録・更新経路への `warnings` の遡及**（射程外）。

## 2. 変更の内容

### 2.1 `DES-006`——**新節「復元時のバリデーション」**

**新設する VAL コード 2 件。** **★接頭辞 `R` は復元（Restore）であり、本 CHANGE が最初の消費者である。**

| ID | 検証内容 | 種類 | 適用経路 |
|---|---|---|---|
| **`VAL-R01`** | **復元するコンボが紐付けているセットプレイに、論理削除されたものが含まれる** | **WARNING** | `POST /api/combos/{id}/restore` |
| **`VAL-R02`** | **復元するセットプレイが紐付いている親コンボが、すべて論理削除されている** | **WARNING** | `POST /api/setups/{id}/restore` |

**★2 件の発火条件が非対称であることを、節の本文に理由付きで書く。**

- **`VAL-R01`＝1 件でも含まれる**——**コンボ詳細のセットプレイ欄が、期待より少なく見えるため。**
- **`VAL-R02`＝すべて削除済み**——**セットプレイは親コンボ経由でしか画面に出ない**（`VAL-S05`）。**生きた親が 1 つでも残っていれば、そこから見える。**

**★既存コードの適用先を増やす 2 件**（新設ではない）。

| ID | 既存の定義 | 追加する適用先 |
|---|---|---|
| **`VAL-C08`** | レシピ中の各ステップの `move_id` が該当キャラに存在する技か（WARNING） | **復元経路** |
| **`VAL-S03`** | セットプレイのレシピ中の `move_id` が該当キャラに存在する技か（WARNING） | **復元経路** |

### 2.2 `DES-006`——**★復元経路は ERROR でも止めない**

**`DES-006` §1.1 は「例外はブロッキング：重複コンボの登録、致命的なデータ不整合のみ登録を阻害する」と書いている。** **⇒ 復元経路はこの例外に当たらない、と明記する。**

| 検証の種類 | 通常の登録・更新経路 | **復元経路** |
|---|---|---|
| WARNING | 保存続行・警告表示 | **同じ** |
| **ERROR** | **保存中止** | **★復元は続行する。警告として返す** |

**★根拠＝`D-463` / `M23-overview` §4.1。** **落とすと利用者は取り返す手段を失い、ゴミ箱が安全網でなくなる。**

**★これを設計書へ書く理由は「後から不具合として直されないため」である。** **書かないと、次に `DES-006` を読んだ担当が「ERROR なのに止めていない」を欠陥と読む。**

### 2.3 `DES-002` §4.2——**復元 2 経路の応答 ＋ 持ち越しの決着**

| 対象 | 追記する内容 |
|---|---|
| `POST /api/combos/{id}/restore` | **成功応答に `warnings` が載りうる**（**`VAL-C08` / `VAL-R01`**）。**★警告 0 件のときはキー自体が出ない。** |
| `POST /api/setups/{id}/restore` | **同上**（**`VAL-S03` / `VAL-R02`**） |
| `POST /api/combos/{id}/restore` の `superseded_by_combo_id` の注記 | **★持ち越しを決着させる。** 現行の注記は「**判断は `M23-04`**」で終わっている。**⇒ 「`M23-04` で判断し、検証を作らないと決めた」へ書き換える**（理由は §4-3） |

**★`warnings` そのものは新設ではない。** `DES-002` は既に「バリデーション警告はエラーではなく `200 OK` のレスポンスボディに `warnings` フィールドとして含める」と書いている。**本 CHANGE が足すのは、その一般規定を復元 2 経路へ具体化する記述である。**

### 2.4 `DES-005` §5.15——**警告の見せ方**

- **復元に成功したうえで警告が付いた場合は、トーストで伝える**（`DES-006` §11.1 の形。**モーダルにしない**）。
- **一括復元で複数件に警告が付いた場合は、件数を畳んで 1 枚にまとめる**（**★1 件ずつ積み上げない**）。

## 3. 真因の記録——**なぜ今まで検証が無かったのか**

**★「作り忘れ」ではない。** **復元に検証が要る状態は、`M23-02` と `M23-03` が入るまで存在しなかった。**

| いつ | 何が変わったか |
|---|---|
| **`M23-02`**（2026-08-20） | **セットプレイが「削除済みだが行としては在る」状態を取りうるようになった。** それ以前は `DELETE` が中間表ごと物理削除しており、この状態は存在しなかった |
| **`M23-03`**（2026-08-22） | **削除済みのセットプレイが、コンボ詳細からも候補一覧からも出なくなった。** **⇒ 「紐付けは残っているのに画面には何も出ない」が成立するようになった** |

**★一般形＝「除外を正しく入れると、除外されたものの存在を伝える手段が新しく要る。」** **除外そのものは正しい。足りないのは、除外されたことを利用者へ伝える経路のほうである。**

**⇒ `architecture-patterns` §11 へ 1 段落として足す**（§4-4）。

## 4. 確定した設計判断

| # | 判断 | 根拠 |
|---|---|---|
| **1** | **復元は検証結果によらず止めない。ERROR 種別も警告として返す** | **D-463** ／ `M23-overview` §4.1。**落とすとゴミ箱が安全網でなくなる** |
| **2** | **`VAL-R01` と `VAL-R02` の発火条件は非対称のままにする** | **表示に出る条件が違うため**（セットプレイは親コンボ経由でしか出ない＝`VAL-S05`）。**★揃えること自体が無償ではない**（**D-494**） |
| **3** | **★`superseded_by_combo_id` を持つ旧行の復元には検証を作らない** | **(a) 旧行はゴミ箱の一覧に出ず、一括復元でも選べない**（`M23-01` の as-built） **／ (b) 復元しても壊れる不変条件が無い**——**`PUT` は重複判定キーを変える操作であるため旧行と新行のキーは通常異なり、重複にならない。** **⇒ `architecture-patterns` §11 の段 4** |
| **4** | **★タグの紐付け消失には検証を作れない。作れないことを記録する** | **`combo_tags` は `ON DELETE CASCADE` であり、復元の時点で「何が紐付いていたか」の情報がどこにも無い。** **検出には監査ログが要り、それは `FR013` の凍結対象である** |
| **5** | **`recipe_cache` の食い違いには検証を作らない** | **復元は `RecomputeComboCache` を呼んでおり、既に解決している**（段 4） |
| **6** | **技・キャラの消失には検証を作らない** | **アプリの操作で消える経路が無い**（seed 由来のマスタデータ。**★指示書 §3.3-4 で実査させる**）。**起こりえないことに検証を書かない**（`E-117`） |

**★4 / 5 / 6 は「検討していない」ではなく「検討して作らないと決めた」である。** **⇒ `DES-006` の新節へ 1 行ずつ残す。** **残さないと、次に同じ問いが来たときにまた同じ調査をする。**
