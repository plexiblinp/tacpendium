## 1. 変更の概要

### 1.1 何を確定させるか

**`FR103` はレシピ入力の手段として「物理コントローラ（ゲームパッド・キーボード）」を挙げているが、`M21-01`〜`M21-04` が実装したのは Gamepad API の経路だけである。** **本サブが `KeyboardEvent` の経路を足す。**

**★同時に、設計書のキーボード記述が逆転する**（**D-370**・開発者判断）。

| 現行の記述 | 改める内容 |
|---|---|
| `REQ-001` 技術前提「**キーボードはデフォルト操作設定のみ対応**」 | **既定を用意せず、全キーを利用者が登録する** |
| `DES-005` §6.3「**WASD 方向入力 ＋ JIKLUO などのキーボタン。SF6 のデフォルトキー割当に準拠**」 | **同上。具体的なキー名は書かない** |

> **★理由**——**キーボードは利用者により操作設定がかなり変わる**（開発者のドメイン知識）。**推測で当てた既定は、多くの利用者にとって「間違った割当が黙って入っている」状態になる。** **`DES-005` §6.3.2 がマクロを既定に含めない理由と同じ構造である。**

### 1.2 ★起票時にスコープが 1 節から 2 文書 6 節へ広がった（**M-56 の同型**）

**`M21-overview` §3 は本サブの影響を「`DES-005` §6.3（キーボード行） ／ `REQ-001` FR103・技術前提」と見積もっていた。** **実際には §6.3.1・§6.3.2・§6.4.3・§6.5 にも及ぶ。**

**★理由は `CHANGE-108` のときと同じである**——**ある節の記述を変えるサブは、その記述が参照している表・前提・条件の節にも及ぶ。** **`CHANGE` の本数は 1 本のままである**（**D-323**）。

### 1.3 CHANGE 対象と対象外の切り分け

| 対象か | 内容 |
|---|---|
| **対象** | 上記 2 文書 6 節 |
| **対象外** | **除外するキーの具体的な集合**——**OS・ブラウザ・キーボード配列で差があり、実測が要る。** **設計書に列挙すると「対応キーボード一覧」として機能する**（`DES-005` §6.3.1 の条件 2 に反する） |
| **対象外** | **必殺技の方向キー連続入力**（**`M21-06`**＝`DES-005` §6.6 の最後の 1 件） |
| **対象外** | **ステップの並び替え**（followup `controller-complete-input-reorder`） |
| **対象外** | **判定窓・判定アルゴリズム**（`CHANGE-107` / `M21-02` の as-built。**触らない**） |

## 2. 変更の内容（`REQ-001` ／ `DES-005`）

| # | 節 | 変更内容 |
|---|---|---|
| **a** | **`REQ-001` 技術前提** | **「キーボードはデフォルト操作設定のみ対応」を差し替える**——**★既定を持たず、全キーを利用者が登録する。** **★理由を書く**（**キーボードは利用者により操作設定がかなり変わる**）。**書かないと、次の担当が「既定を用意し忘れている」と読んで足す** |
| **b** | **`REQ-001` FR102** | **実現手段を書き分ける**——**「標準配置の既定 ＋ 利用者のキャリブレーションによる上書き」は Gamepad についての記述である。** **★キーボードは第 1 段を持たない。** **同じ FR の中で 2 つの機体クラスが違う形を採ることを明記する** |
| **c** | **`DES-005` §6.3**（キーボード行） | **全面差し替え**——**具体的なキー名を書かない**（WASD / JIKLUO / SF6 デフォルト準拠を落とす）。**★「対応キーボード一覧」を作らない**（§6.3.1 の条件 2） |
| **d** | **`DES-005` §6.3.1** | **2 段の解決方式に「キーボードは第 1 段を持たない」を書く。** **★あわせて帰結を書く**——**登録しないと 1 つも入力できない。** **Gamepad は既定があったため未登録でも動いたが、キーボードは動かない。** **★これは失敗ではなく状態として出す** |
| **e** | **`DES-005` §6.3.2** | **登録対象の書き分け**（**as-built 次第**）——**★キーボードは前置きを持たない代わりに、操作 3 種をそれぞれ直接登録する。** **⇒ 件数が Gamepad の 14 件と違う。** **★§6.2 の数え方の注記と同じ手番で直す**（**CHANGE-108 で入れた「3 つの数を同じ手番で直す」の適用**） |
| **f** | **`DES-005` §6.4.3 項目 4** | **「供給元はアプリ全体で 1 個」を是正する**——**★これは Gamepad についての記述であった。** **キーボードが加わると供給元は 2 つになる。** **★受け手の調停は 1 つを共有したままである。** **⇒ 「供給元が 1 個」と「受け手が 1 面」を分離して書く** |
| **g** | **`DES-005` §6.5** | **操作 3 種がキーボードでは直接割当になることを書く**——**★前置き方式は Gamepad の制約**〔余りボタンが尽きる機体がある〕**ゆえの形であり、キーボードには当てはまらない。** **★操作の種別そのものは共有する**（**3 値。増やさない**） |
| **h** | **`DES-005`**（節は as-built 次第） | **★テキスト入力欄との衝突回避と、設定できないキーの存在を書く**（**開発者要求**）。**★どちらも「書かないと落ちる」種類の要件である**——**前者は文字を打つたびにステップが入り、後者は「登録できたのに動かない」を生む** |

## 3. 確定した設計判断

| # | 判断 | 根拠 |
|---|---|---|
| **1** | **★キー割当の既定を持たない。全キーを利用者が登録する** | **D-370**・開発者判断（**「リマップ可能にする。キーボードは利用者により操作設定がかなり変わるのでデフォルトは用意しない」**） |
| **2** | **★操作の集合は Gamepad と同じ 3 種で揃える**（削除／保存／修飾） | **D-370**・開発者判断。**★種別そのものを共有する**（別の列挙を作らない＝`E-76`） |
| 3 | **前置きボタン方式は採らない** | **`D-358` が前置きを採ったのは「余りボタンが尽きる機体がある」ためであり、キーボードにその制約は無い** |
| **4** | **★テキスト入力欄にフォーカスがある間は技入力も操作も発火しない** | **D-370**・開発者要求（**「それは大切なので記入お願いします」**） |
| **5** | **★ファンクション・Windows キー等、より高い優先度の動作を持つキーは設定不可とする** | **D-370**・開発者要求 |
| 6 | **判定層を分岐させない** | **`CHANGE-107` / `M21-02` の as-built を 2 通りにしない**（`DES-005` §6.4.2） |
| 7 | **受け手の調停・操作の配送チャネルへ相乗りする** | **`DES-005` §6.4.3 項目 4 ／ `CHANGE-108` / `M21-04` の as-built。** **別の調停を作ると 2 通りの答えが並ぶ** |
| 8 | **操作用のキーは押下集合に含めない** | **`DES-005` §6.2**（**`M21-04` の構造上の決め。同節が「`M21-05` の前提である」と明記している**） |
| 9 | **Gamepad とキーボードを排他にしない** | **「キーボードモード」を作ると、利用者は切替を意識させられる** |
