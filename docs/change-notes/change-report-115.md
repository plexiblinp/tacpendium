## 2. 反映の中身

### 2.1 `DES-005` §5.7 — 競合時の振る舞い（**新設**）

**9 項目。** 中核は 3 つ——**入力を保持したまま自動で読み込み直さない** ／ **導線 3 つ**（見る・読み込み直す・閉じる） ／ **上書きの道は出さない**。

**あわせて as-built を 2 点書いた**（通知書 §2-h）——**「読み込み直す」は画面ごとの再読込である**（部分的な state 再初期化ではない。**書かないと初期化経路が 2 本になりドリフトする**） ／ **競合モーダルは共有プリミティブを通す**（**自作オーバーレイにすると `M21-07` の物理入力抑止に参加せず、モーダルの裏でレシピにステップが入る**）。

### 2.2 `DES-005` §5.7 — **404 の 5 項目**（通知書 §2-f）

**★これは追補で足したものである。** **初版の実装は 404 を「入力を保持したまま『閉じる』だけ」で終わらせており、利用者が入力を抱えたまま保存する道を失っていた**（開発者の手動確認で観測＝**D-417**）。

**書いたもの**——**[この内容で新しく登録する]**（2 段階。成功したら新しいコンボへ移る）／ **[コンボ一覧へ]** ／ **★「新しく登録する」は上書きの道ではない**（別の行を作るのであって誰の編集も壊さない。**この一文を消さないこと**）／ **404 を一律に「ほかの人が変更しました」と読み替えない**（**本当に削除された場合にも来る**）／ **重複で弾かれたら既存の見せ方へ落とす**。

**★末尾に一般形を残した**——**「導線が出ていること」ではなく「そこから利用者が保存へ進めること」を満たすこと。** **正しい消去法の結果として選択肢が 0 になる形が実際に起きた。**

### 2.3 `DES-005` §5.9 — 相違 3 点（通知書 §2-e・§2-g）

**★2 が本 CHANGE で最も実害のあった項目である**——**着手前は `err.status === 409` だけで判定しており、同一レシピ重複が「他のタブで更新されています」と表示されていた。**

**★3（セットプレイの 404 はモーダルへ寄せない）は製造の独自判断を受理したものである**（**D-417**）。**`setups` にキー変更編集（`PUT`）が無く「作り直された」が構造的に起こらないため。** **★寄せると、まだ 1 件も作られていないセットプレイについて「ほかの人が作り直した」と述べる状態を作る**（初版が実際にそうなり、レビューが是正した）。

### 2.4 `DES-006` §11.2 — 4 ブロック

| # | 内容 |
|---|---|
| 1 | **版不一致が他の ERROR と違う 2 点**（手元に未保存の作業がある ／ 「失敗」ではなく「防いだ」）**＋ 守る 4 点** |
| 2 | **★409 は 2 種類ある。見分けはエラーコードで行い、ステータスでは行わない**（一意制約違反は実測 10 種を全数列挙） |
| 3 | **★重複エラー（`VAL-C02`）は 409 ではなく 400 `validation_failed`** |
| 4 | **★ERROR をモーダルで出すのは原則であって例外を許す**（利用者が同じ画面で直せる ERROR はインラインでよい） |

**★3 は反映の直前に是正された**（**D-418**）。**`M22-04` 指示書 §4.7.3 が「重複の 409」と書いており、そのまま設計書へ写していたら「ステータスで分岐する形」を次の担当が作っていた**——**本サブが `duplicate_setup` で直したのとまったく同じ再発である。**

**★4 は裁定である**（**D-417**）。`duplicate_setup` が ERROR でありながらインライン表示で §11.2 と整合しない状態が着手前から在った。**「モーダル」を原則としつつ例外を許す形で解いた**——**入力を直せばその場で解決できる ERROR は、モーダルで作業を遮るより該当欄の近くに出す方がよい。** **版不一致がモーダルなのは「直しようがない」からであり、同じ線引きである。**

**あわせて「重複している既存コンボへのリンク」が `POST /api/combos` の経路では未実装であることを明記した**（通知書 §2-l ／ followup `duplicate-warning-lacks-link-to-existing-combo`）。

### 2.5 `DES-005` §6.8 — 入力面以外の test-id

**★規約の射程を明記した**——**`recipe-<領域>-<識別子>` は入力面に対するものであり、それ以外の画面には及ばない。** **適用されるのは「ケバブケース ／ `<領域>-<識別子>` ／ 既存を改名しない」の部分だけである。**
