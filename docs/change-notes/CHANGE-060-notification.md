## 1. 変更の概要

M16-01（承認ゲート G-g）の実装完了に伴い、確定した内容を設計書へ反映する。`combos.drive_available_at_start` を **INTEGER→REAL** 化（マイグレ 000019・000016 技法踏襲の非破壊テーブル再構築）、入力を **0.5 刻み widget** 化し、combo↔sequence の粒度を揃えた。**始動残量は FR301 dup キー・recipe 非対象**（M16-RESEARCH-01 で実コード裏付け＝dup キーは character/starter/position/stance/hitType/size＋`CalcRecipeHash(steps)`）のため重複判定・recipe_cache 非波及。

本 CHANGE は確定反映（§2）＋製造独自判断への回答（§4）＋要設計判断（§3・A-1／§7）で構成する。

## 2. 変更の内容

### DES-003 §3.4（combos・型）

- `combos.drive_available_at_start` の型を **INTEGER → REAL**（範囲 0〜6・**0.5 刻み**・**CHECK 不使用＝BE 範囲検証＋UI 刻み担保**）。sequence 側（小数）と粒度を統一。既存整数値は無損失昇格（2→2.0）。
- 前例 `drive_damage`（REAL・CHANGE-046）と同じ型・同じ再構築技法（000016）。

### DES-005 §5.7（登録/編集・入力欄）

- ドライブ始動残量入力を **0.5 刻み widget**（`step=0.5`・非負・0〜6）に。前例＝`drive_damage` の小数入力。
- **ラベル文言の正典化（伝達メモ B-2）**: 「ドライブゲージ(0〜6本)」→ **「ドライブゲージ(0〜6本・0.5刻み)」**（`drive_damage` の「(-6.0〜6.0)」に倣い刻みを文言で明示）。**「0.5刻み」の表記を正典化**し表記ゆれを防ぐ。M16-06 表記 rollout の対象語彙と整合を取る。

### DES-006 VAL-C04（drive_available_at_start 範囲検証）

- 「`drive_available_at_start` が **0〜6 の範囲内か（小数許容）**」へ明確化。**0.5 刻みは UI（widget `step=0.5`）で担保・BE は範囲のみ検証**（伝達メモ C-1）。VAL-C13（drive_damage 小数）と同方針。create/promote 実行・PATCH 単純更新は非実行。
- エラーメッセージの数値書式を **`%g`（小数表示可）** に（伝達メモ B-3・範囲文言「0〜6」は不変）。
- **VAL-D03 の突合（伝達メモ A-2）**: DES-006 が VAL-D03（draft 時は範囲チェックのみ・NULL 許容）を独立ルールとして記すが、**実装に VAL-D03 の独立関数・定数は存在せず、draft の NULL 許容は VAL-Cxx 側の nil スキップ（`if combo.DriveAvailableAtStart == nil { return }`）で成立**している。DES-006 に「VAL-D03 は独立関数でなく VAL-Cxx の nil スキップに畳み込まれた挙動」である旨を注記し、記述と実装を突合する（M16-02/03 の draft 検証にも同前提が波及）。

## 3. 比較/一覧の drive 始動残量表示（A-1・要設計判断＝§7-1）

- **実態**（伝達メモ A-1）: `driveAvailableAtStart` を描画するのは**詳細画面（`ComboDetailMetadata.tsx`）のみ**。**一覧テーブル・比較画面（`CompareTable.tsx`）には当該表示が元々存在しない**（比較行は starter/route/damage/situation/custom_states/knockdown/oki のみ）。
- 指示書 §2.2/§5.2/§5.3 の「一覧/比較で小数表示」という追従想定は、**当該フィールドが両画面に元々無いため前提が成り立たない**（＝指示書側の想定誤り）。製造は §2.4 例外条項（実コードを正）＋スコープ厳守で**新設せず**（型変更による回帰は無い＝両画面は非参照）。設計担当の判断誤り（実コードを引かず「表示追従」と書いた）であり、実態に合わせて是正する。
- **要判断**: 比較（DES-005 §5.8）・一覧（§5.4）に drive 始動残量を**新設するか／比較非表示を正式確定するか**＝§7-1。**M16-02 の消費比較改修とセットで判断**（始動なし・消費ありの非対称回避）。

## 7. 開発者への確認事項

1. **A-1: 比較/一覧の drive 始動残量表示（M16-02 投入中のため優先）**
   何を: (a) 比較画面（DES-005 §5.8）に drive 始動残量行を**追加する**か、(b)「比較は非表示」を正式**確定する**か。一覧（§5.4 表示列カスタマイズ）に含めるか。
   なぜ: 現状は詳細のみ表示で比較/一覧に無い。M16-02 が「消費を比較軸に追加」するため、**始動を比較に載せないと『始動なし・消費あり』の非対称**が生じる。M16-02 投入中に決めると一貫する。
   暫定案: **(a) M16-02 の比較改修で drive 始動残量・SA 始動残量・drive/SA 消費を同時に比較軸へ載せる**（始動/消費の非対称を一括解消）。**一覧列は現状維持**（表示列カスタマイズへの追加は任意・過密回避）。DES-005 §5.8 はこの確定後に反映。

2. **B-1: REAL→INTEGER down 丸めの標準方針**
   何を: down マイグレの小数→整数丸めを **「切り捨て（明示 `CAST AS INTEGER`）＝M16-01 方式」を標準に一本化**してよいか。前例 000016（型親和性依存）は非標準として扱う。
   なぜ: 現在「切り捨て」と「親和性依存」の 2 方式が並立。M16-03（6bool→正規化）等の後続破壊的マイグレの down で方式が揺れると保守性が下がる。
   暫定案: **切り捨てを標準**（予測可能・レビュー容易）。retrospective-digest §5 に標準として記録し、以後の down はこれに従う。

3. **A-2: VAL-D03 の DES-006 記述の是正**
   何を: DES-006 の VAL-D03（draft 範囲チェックのみ・NULL 許容）を、**「独立関数でなく VAL-Cxx の nil スキップに畳み込まれた挙動」と明記**してよいか。
   なぜ: 実装に VAL-D03 の独立関数・定数が無く、記述と実装が乖離。M16-02/03 の draft 検証でも同前提が波及するため、正典を実態に合わせておく。
   暫定案: DES-006 に上記注記を追加（実装は VAL-Cxx の nil スキップで draft NULL 許容を実現）。
