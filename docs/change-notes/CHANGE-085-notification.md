## 1. 変更の概要
既存コンボの `knockdown_advantage`（KA）から**成立するセットプレイのレシピを提示**し、ユーザーが検証・採択したものだけを**既存機構（`setups`＋`setup_steps`＋`combo_setups`）へ保存**する機能を新設する。中核ロジックは別リポ `autopilot-combomgr/projects/setplay-suggestion` の**フレーム導出エンジン**（Go 1.24・stdlib のみ）を本体 `internal/service/setplay` へ**移植**し、受理条件を**完全一致から受理帯（窓）方式へ変更**する。

**スキーマ変更なし**（新テーブル・新列・マイグレなし。提案結果は非永続）。着手前ゲート＝反映案。

## 2. 変更の内容（DES-002 / DES-005）

| # | 対象 | 変更 |

| a | **DES-002 §4.2** | 提案エンドポイント新設 `GET /api/combos/:comboId/setplay-suggestions?n_min=&sort=&target_move_id=`。**副作用なし（非永続）**・KA が NULL なら 400 系（UI が理由表示できるエラーコードを含む）。**既存 FR011 候補 API（`/api/setups/candidates`・`/api/combos/:comboId/setup-candidates`）とは別系統**で挙動不変 |

## 3. 前提となる意味論（DES-003 §3.4・errata 済＝本 CHANGE の対象外）
`KA` ＝ダウン中の無敵時間／起き上がりは `KA+1` フレーム目／`S = Σ(filler.total) + target.startup`／`N = KA+2−S`／成立 `N_min ≤ N ≤ target.active`。**この定義は 2026-07-23 errata で DES-003 §3.4 に明文化済み**（版据置）。

## 4. 確定した設計判断

| 項目 | 判断 |
|------|------|
| 受理条件 | **帯（窓）方式**＝`0 ≤ remaining ≤ target.Active − NMin`。`==KA` / `==KA+1` の**等値にしない**（等値は N 固定になり golden-case を落とす） |
| エンジン | 別リポから**移植**（移植元は read-only・変更しない）。**stdlib 以外の依存を増やさない**＝NFR303/304 維持 |
| target 除外 | `startup≥1 ∧ active≥1` ／ `is_derived=false` ／ `is_aerial=false`。**`target_move_id` 明示指定時は後 2 者を適用しない**（逃げ道） |
| filler | `total ≥ 1` の**全技**。**`setup_only` による絞り込みは行わない**（実セマンティクス＝セットプレイ専用 move の行区分であり有用性フラグではない） |
| 永続 | **提案結果は非永続**（localStorage も使わない）。採択物のみ既存機構へ |
| 制約告知 | 初回のみ自動表示・以降は明示操作。**保守マーカー `M19-LIMITATION-NOTICE`** を制約実装箇所と i18n 文面に必須化（grep で全箇所を一覧） |
