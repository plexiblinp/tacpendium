## 1. 変更の概要
確定反撃サーチでダッシュ経由の候補（ダッシュ → 始動技）を判定するため、**移動 system move の全体フレームが必要**。調査の結果 `dash_forward`／`jump_neutral`／`jump_forward`／`jump_back` は **12 キャラ × 4 code ＝ 48 行すべてフレーム列が NULL**（投入するマイグレが 1 本も存在しない）。

**新列は作らず、既存の `total` 列へ backfill する**。**スキーマ変更なし**（DDL なし・データ投入のみ）。着手前ゲート＝反映案。

## 3. 判断の根拠

**A. 新列を作らず `total` を使う** — DES-003 §3.3 の `total` は「全体硬直＝**正準の利用値**」であり、算出式は「算出できる場合の求め方」。移動 move に全体フレームを直接入れることは語義に反しない。**先例が実在**：`character_data/rashid.csv` の `buffed_dash_forward` は `startup=1 / active=20 / recovery=0 / total=20` を持ち、算出式（`1+20−1+0=20`）と**完全整合**（`category=unique` のため seedgen の drop 対象外＝CSV から流れる経路も確認済み）。代替案（`dash_full_frames` 等の新列）は (1) 1 目的の列追加でスキーマが膨らむ、(2) ジャンプまで扱うと着地硬直用の列も要り増殖する、(3) `total` の語義と必要値が一致する——ため採らない。

**B. 投入経路は backfill マイグレ（seedgen 非改変）** — `internal/seedgen` の drop を解除すると再生成 SQL に移動 9 種が現れ、**golden テスト（`000026`/`000030` の byte-identical 比較）が必ず失敗**する。解消のため既存 seed を再生成すれば**既存マイグレ改変**に抵触。これは **M18-01 で撤回した「seedgen を is_projectile 出力へ変更」と同型**。よって `is_derived`（000032+000034）・`is_projectile`（000039）と**同型の backfill マイグレ**とする。

**C. 対象 code を移動 5 code に広げる（案 3 採用・中央判断 2026-07-23）** — 担当の推奨は案 2（`dash_forward`＋jump 3 code＝40 行）だったが、**中央は案 3（＋`dash_back`＝50 行）を採る**。理由：(1) **M19（セットプレイ自動提案）の成立判定が `S = Σ(filler.total) + target.startup` であり、移動 move は filler の典型**（起き攻めでダッシュ・ジャンプを挟む）。`dash_back` が NULL だと M19 側でその経路が落ちる。(2) 値は**同一バッチ・同一出所で既に手元にある**ため、分割すると将来のマイグレが**別の provenance** を持つことになり E-24 の観点で不利。(3) 追加コストは同一マイグレ内の 10 行のみで、スキーマ変更は増えない。**確定反撃サーチ自体は `dash_back` を使わない**（後退して反撃はしない）が、格納しても走査には影響しない。

## 4. 中央の付帯条件（承認の条件）

| # | 条件 | 理由 |
|---|------|------|
| 1 | **DES-003 §3.3 に「移動 system move の `total` は直接保持＝算出式の検算対象外」と明記**（実装後反映） | 移動 move は `startup`/`active`/`recovery` が NULL のまま `total` だけ入るため、**算出式で検算できない値**になる。rashid の先例は 4 列すべて揃っており性質が異なる。明記しないと将来「total があるのに startup が NULL＝データ不整合では？」と誤検知される |
| 2 | **backfill マイグレのコメントに値の出所を残す**（開発者提供・実測値・提供日） | 一次源が DB/CSV/マイグレに存在しないため、出所が失われると再検証不能になる（**E-24**＝件数・値には基準時点と一次源を書く） |
| 3 | 件数検算を change-report に集約 | **更新行数＝50 行**（数えた対象＝**移動 5 code〔dash_forward/dash_back/jump_neutral/jump_forward/jump_back〕× 10 キャラ**で `total IS NOT NULL` になった `moves` 行数）。内訳＝dash_forward 10／dash_back 10／jump_* 30。**c_viper・dhalsim は対象外**（§2 a-2）。E-16/E-18 |

## 6. 申し送り（followup 登録）
