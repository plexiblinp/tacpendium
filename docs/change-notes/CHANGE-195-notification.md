## 1. なぜ要るか

### 1.1 ★★★編集モードでマス数を直すと、値が黙って落ちていた

**★`M37-01` の指示書 §0.1 は「無いのは UI 配線だけ」と述べていた。⇒ 不完全であった。**

**★★実測＝`UpdateMetadataRequest`**〔`PATCH` の要求 DTO〕**にマス数 2 欄が無かった。⇒ `POST` と `PUT` にはあった。**

**⇒ 画面を配線しただけでは、編集モードでマス数・運び量だけを直したときに値が保存されない。★UI の配線だけでは成立しない形であった。**

### 1.2 ★★`PUT` へ載せる案は採らなかった

**★`PUT`**〔`UpdateWithKeyChange`〕**は旧行を論理削除して新規行を作る。⇒ 運び量を直しただけでコンボ id が変わり、旧行がゴミ箱へ積まれる。**

**★★意味の上でも誤りである＝運び量は重複判定キーではない。**

**⇒ 2026-09-13 開発者が「案 A＝`PATCH` 契約の拡張」を選択した。★指示書 §3-4 / §6-5 の「`internal/` 差分 0」を承認で外した。**

## 2. 変更内容

### 2.1 要求 DTO が 2 欄増える

```go
StartPositionMass comborepo.Optional[int] `json:"startPositionMass"`
CarryDistanceMass comborepo.Optional[int] `json:"carryDistanceMass"`
```

**★`Optional[T]` は presence-detection のトライステートである**〔`memo` / `situation` と同じ〕**。**

| 要求本文 | 意味 |
|---|---|
| キーが**無い** | **変更しない** |
| `"startPositionMass": 80` | **80 を保存** |
| `"startPositionMass": null` | **NULL クリア** |

**★★応答 DTO は変わらない。⇒ `ComboResponse` は着手前から両欄を持っていた**〔`*int` ／ `omitempty`〕**。**

### 2.2 エラー契約に 1 行増える

| 状況 | ステータス | コード |
|---|---|---|
| **マス数が 0〜160 の外** | **400** | **`VAL-RANGE`**（`validations` 配列。`field` は `startPositionMass` / `carryDistanceMass`） |

**★★`ValidateMetadataRanges` が範囲検証を呼ぶようになった。⇒ 呼ばないと、値域外が DB の `CHECK` 違反として `internal_error` の 500 で返り、`validations` 配列を伴わないため画面が理由を出せない。**

**★★★これは案 A の承認の射程内である**（`D-863`）**。⇒ 指示書 §4.3 が禁じたのは「`VAL-C16` / `VAL-RANGE` の*食い違いを直す*こと」であり、既存コードを新しい経路で*呼ぶ*ことではない。**

### 2.3 ★★★持たせなかった分岐（**誤読を防ぐため明記する**）

| # | 持たせなかったもの | 帰結 |
|---|---|---|
| **1** | **`position` は本経路に載らない。⇒ 本経路は `normalizePositionAndMass` を呼ばない** | **★マス数だけが更新され、`position` は DB の値のまま残る。★これは仕様である** |
| **2** | **マス数が「区分をまたぐ」ことを検出する分岐** | **★振り分けはフロントが行う。⇒ 区分内は `PATCH`、区分をまたぐと `PUT`** |
| **3** | **`startPositionMass` と `position` の整合検証** | **★本経路では両者が食い違いうる。⇒ フロントの振り分けにより実際には起きない** |

### 2.4 ★母集団の述語

**★本経路が触るのは*識別キーが変わらない編集*だけである。⇒ `position` / `opponentStance` / `hitType` / `opponentSize` / `starterMoveId` / レシピは本経路に載らない**〔載るのは `PUT`〕**。**

**★★マス数 2 欄はキーではないため本経路に載る。**

## 3. ★★申し送り（**本 CHANGE では直さない**）

### 3.1 `VAL-C16` / `VAL-RANGE` の食い違いの影響範囲が広がった

**★`DES-006` は `VAL-C16` を定めるが、実装は `VAL-RANGE` を返す。⇒ 着手前は `POST` / `PUT` / CSV の 3 経路だった。**

**★★`PATCH` が 4 つ目になった。⇒ 後で `VAL-C16` へ寄せる裁定を下す場合、直す箇所が 1 つ増えている。**

**⇒ `DES-006` は本 CHANGE で書き換えない。★申し送りだけ残す。**

### 3.2 ★★★`PATCH` と `PUT` で「マス数を空にする」の永続結果が食い違う

**★詳細は `followup-backlog` §DD の `position-mass-clear-differs-between-patch-and-put` と保留 `P-60`。⇒ 本 CHANGE の射程外である。**
