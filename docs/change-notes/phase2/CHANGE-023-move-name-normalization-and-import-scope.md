## 1. 変更の概要

CHANGE-022 で確定した moves スキーマ・FR704 CSV 契約を運用する前段として、公式フレームデータの実データ確認で判明した2点を設計書本体に確定する。

1. **技名の正規化規約**(DES-004 §3.2): official_ja_move のエイリアスが、公式技名からキャラ固有のフレーバー名を除去し共通的な技は汎用名を用いる、という改善内容を明文化する。
2. **moves 取込対象スコープ**(DES-002 §7.5): 公式データのどのカテゴリ・エントリを moves として取り込み、どれを取り込まないかを明文化する。

いずれも **moves スキーマの変更を伴わない**(エイリアス生成規約と取込スコープの定義のみ)。

---

## 2. 変更の理由

- CHANGE-022 v0.3.0 §7.5 は「official_ja_move のエイリアスの技名文字列は公式名」と記載したが、リュウの実データ確認で、共通システム寄りの技や通常技にキャラ固有のフレーバー名が付くことが判明した(例: `立ち弱P（ジャブ）` / `ドライブインパクト（震撃）` / `Drive Impact: Shingeki` / `背負い投げ`)。これらは official_ja_move の「改善版」方針(DES-004 §3.2)で正規化すべき対象であり、当該記載を訂正する必要がある。
- 公式「共通システム」「通常投げ」セグメントには、moves 化が不要なエントリ(非攻撃のシステム動作、modifiers.type で表現する動作、コンボ部品でない攻撃)が含まれる。取り込むべき範囲を明文化しないと、取込ツール(FR701)と本体取込(FR704)の責務が曖昧になる。
- 実データで「ダメージ>0 / =0」「カテゴリセグメント」で取込要否がきれいに判別できることが確認できたため、スコープを確定できる状態になった。

---

## 3. 変更の内容

### 3.1 DES-004 §3.2: 改善点に「技名の正規化」を追加

§3.2「公式表記改善版の改善点」の箇条書きに、次の1項を追加する(既存3項=画面端情報・連結子・アイコン代替は不変)。

> - **技名の正規化**: official_ja_move のエイリアスは公式技名から、(a) キャラ固有のフレーバー名(末尾の `（…）` および `: …`)を除去し、(b) 共通的な技は汎用名を用いる。例: `立ち弱P（ジャブ）` → `立ち弱P`、`ドライブインパクト（震撃）` → `ドライブインパクト`、`背負い投げ` → `前投げ` / `巴投げ` → `後ろ投げ`。`move.code`(内部識別子)はツール採番で表示名と独立のため影響しない。

### 3.2 DES-002 §7.5: 技名の扱いの文言訂正

§7.5 CSV 列表の `name_ja` 行コメントを訂正する。

| | 現行(CHANGE-022 v0.3.0) | 訂正後 |
|---|------------------------|--------|
| name_ja 行コメント | 「official_ja_move の『改善』は連結子・アイコン代替・状況情報が対象で、技名文字列は公式名(DES-004 §3.2 と非衝突)」 | 「official_ja_move のエイリアスは**正規化した技名**(キャラ固有フレーバーの除去・共通技の汎用名化。DES-004 §3.2)。正規化のうち末尾フレーバー除去はツールが自動、汎用名化は下記の通り」 |

### 3.3 DES-002 §7.5: 「取込対象」節の新設

§7.5 に「取込対象」を新設し、moves 化するカテゴリと取り込まないエントリを定義する。

**取込対象(moves 化する)**:

- 通常技(normal)、特殊技(unique)、必殺技(special)、スーパーアーツ(super_art)、通常投げ(throw)、ドライブインパクト(drive_impact)。ターゲットコンボ(target_combo)が公式に存在する場合はそれも含む。
- いずれも攻撃技。ドライブインパクトはキャラ固有の性能(ダメージ・フレーム)を持つため moves に取り込む(DES-003 §3.3 既定方針)。

**取込対象外(moves 化しない)**:

| エントリ | 理由 |
|----------|------|
| 前方ステップ / 後方ステップ | 非攻撃のシステム動作。コンボ内では modifiers.type(`dash_forward` / `dash_back`)で表現(SUPP-001 §3.3.3) |
| パリィドライブラッシュ / キャンセルドライブラッシュ | コンボ内では modifiers.type(`parry_drive_rush` / `cancel_drive_rush`)で表現 |
| ドライブパリィ / ジャストパリィ(打撃・飛び道具) | 非攻撃(ダメージ=0)。コンボのステップにならない 〔※ドライブパリィは CHANGE-038(2026-06-18 反映済)で取込対象へ方針転換。本行のうちドライブパリィ分は打ち消し済み。ジャストパリィは引き続き除外〕 |
| ドライブリバーサル(ガード時 / 起き上がり時) | 攻撃でキャラ固有だが、防御リバーサルでコンボ部品でないため取込対象外 |

**判別方法**:

- 公式 HTML のカテゴリ見出しでセグメント化されているため、ツールはカテゴリ単位で取込要否を判別する。「共通システム」セグメント内はダメージ値で攻撃/非攻撃を区別でき(ダメージ=0 のステップ・パリィ・ラッシュは取込対象外、ドライブインパクトのみ取込・ドライブリバーサルは取込対象外)、安定して判別可能。

### 3.4 DES-002 §7.5: 通常投げの位置自動採番

§7.5 の `name_ja` / 投げの扱いに、通常投げの正規化方法を明記する。

- 通常投げセグメントは取り込む。official_ja_move のエイリアスは**セグメント内の出現順で自動採番**する(1件目 = `前投げ`、2件目 = `後ろ投げ`。リュウは 背負い投げ=1件目=前投げ、巴投げ=2件目=後ろ投げ で一致。SF6 公式の並び順は前投げ→後ろ投げで安定)。
- キャラ別のダメージ・フレームは保持する(固定値化しない)。並び順が想定外のキャラは FR703 で補正する(セーフティネット)。
- `move.code` は throw_forward / throw_back 等をツールが採番する。
- 英語の汎用名(英語ロケール着手時=フェーズ3以降に再取込で使用)は `前投げ` = `Forward Throw`、`後ろ投げ` = `Back Throw`。

## 6. リスク

| リスク | 内容 | 緩和策 |
|--------|------|--------|
| 投げの並び順の例外 | 位置自動採番(1件目=前 / 2件目=後)が一部キャラで崩れる可能性 | クラシック5体で並び順を確認。崩れたキャラは FR703 で補正(少数) |
| フレーバー除去の過剰/不足 | `（…）` / `: …` の機械除去が、フレーバーでない括弧情報を誤除去する可能性 | official_ja_move は表示名のみ対象(command は official_ja_command が別管理)。取込プレビューで確認・FR703 補正 |
| 取込対象の判定ミス | 将来キャラで共通システムの構成が異なる可能性 | カテゴリセグメント + ダメージ値の二段判別。想定外エントリは取込プレビューで要確認強調 |
| ドライブリバーサル不要判断の見直し | 後日 DR をコンボ部品として扱いたくなる可能性 | 取込対象外は「現時点で moves 化しない」方針。必要が生じれば別 CHANGE で対象追加(スキーマ変更不要) |
