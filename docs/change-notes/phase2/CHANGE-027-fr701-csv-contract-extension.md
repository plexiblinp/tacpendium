## 1. 変更の概要

FR701 出力 CSV に **command / condition_ja / condition_en の 3 列を追加**し、FR704 取込ではこれらを **raw_data へ退避**(moves 列追加なし)とする。

- CSV 契約に 3 列を追加(ツール出力契約を確定)。
- フェーズ2 では moves に対応列を追加せず、raw_data に退避キーとして格納する(コマンド表記コンボ機能は将来仕様で、列の形を先に決めない=YAGNI)。

---

## 2. 変更の理由

- コマンドでもコンボを記述する将来仕様に向け、コマンド入力を完全復元できる情報を CSV で運ぶ開発者要望(fr701-mainline-handover §1-5)。
- 実測で、アイコン asset 名でコマンド入力を完全復元でき、日英でアイコン列が全 2,361 行一致(同調査)。
- **moves への列追加を避ける理由**: コマンド表記コンボの設計が固まる前に列の形を決めるのは逆順(YAGNI)。raw_data は CHANGE-022 で properties の残余退避に既に使う構造のため、退避キーを足すだけならマイグレーション不要・コストほぼゼロ(開発者方針 2026-06-11)。
- **スキップでなく退避を選ぶ理由**: FR703 で手動補正した moves に後日コマンド列を再取込で重ねる運用は、補正の上書き・差分突合の事故源になる。raw_data に退避しておけば将来機能着手時に再取込なしで参照できる(開発者方針 2026-06-11)。

---

## 3. 変更の内容

### 3.1 DES-002 §7.5: CSV 列に 3 列を追加

§7.5 の CSV 列表の末尾に次の 3 列を追加する。

| CSV列 | 反映先 | 備考 |
|-------|--------|------|
| command | moves.raw_data(キー `command`) | コマンドトークン列(ロケール非依存)。トークン語彙・シリアライズは TOOL-002 §9.9 を正とする。本体は将来、自前アイコンへの置換に使用 |
| condition_ja | moves.raw_data(キー `condition_ja`) | 先頭前提条件の原文(日本語) |
| condition_en | moves.raw_data(キー `condition_en`) | 先頭前提条件の原文(英語) |

### 3.2 DES-002 §7.5: raw_data 退避の方針を明記

§7.5 に次の方針を追記する。

> command / condition_ja / condition_en の 3 列は、フェーズ2 では moves に専用列を設けず、`moves.raw_data`(JSON)へ同名キーで退避する。コマンド表記コンボ機能・official_ja_command プリセット(DES-004)との接続はフェーズ3以降の将来仕様で別途設計し、その着手時に raw_data からの移送または再取込で対応する(再取込はツールが同一 code を冪等出力するため安価だが、FR703 手動補正の上書きを避けるため raw_data 退避を既定とする)。

### 3.3 DES-003 §3.3: raw_data 注記に退避キーを明記

DES-003 §3.3 の `raw_data` 行注記(「備考欄や公式 HTML 由来の生データ一式」)に、退避キーを例示として追記する。

> raw_data には備考(notes)・公式 HTML 由来の生データに加え、**コマンド・前提条件の退避値**(キー `command` / `condition_ja` / `condition_en`、CHANGE-027)、および properties の残余(CHANGE-022)を格納する。これらはフェーズ2 では保持のみで、消費機能は未実装。

## 6. リスク

| リスク | 内容 | 緩和策 |
|--------|------|--------|
| 将来機能着手時の移送コスト | コマンド表記コンボ実装時に raw_data から専用列/構造へ移す手間 | raw_data に構造化キーで保持し参照可能。再取込も冪等で安価。将来の専用列化はその時点の設計で判断 |

| トークン語彙の本体・ツール不整合 | command のトークン語彙が本体のアイコン置換とずれる | 語彙・シリアライズは TOOL-002 §9.9 を単一の正とし、本体はそれを参照(本体側で語彙を再定義しない) |
