## 1. 変更の概要

FR701 実データ全数調査に基づき、DES-002 §7.5(FR704 CSV 契約)の取込スコープ・正規化規約を訂正する。本通知書は **§7.5 文言群の影響面**を扱う(スキーマ・enum・seed は CHANGE-025、CSV 列拡張は CHANGE-027)。

1. **取込対象の訂正**(§7.5、CHANGE-023 の訂正):「攻撃技に限る」を撤回し、キャラセグメントは非攻撃を含め全行取込。共通システムの判別を「ダメージ値」→「位置+名称」へ。
2. **通常投げ節の拡張**(§7.5):3 件目以降の規定を追加。
3. **ターゲットコンボの実態化**(§7.5):独立セグメントは存在せず段数付き行として扱う。
4. **on_hit / on_block の値退避規則の明文化**(§7.5):`D` / `※N` / 範囲値の扱いと notes 付記書式。
5. **recovery 入力パターンの明記**(§7.5):total 算出の入力となる recovery 文字列の形を列挙。

いずれも CSV 契約・取込挙動の訂正で、moves スキーマは変更しない(スキーマ訂正は CHANGE-025)。

---

## 2. 変更の理由

- **1(取込対象)**: CHANGE-023 §3.3 は「moves 化するのは攻撃技に限る」「共通システム内はダメージ値で判別」としたが、(a) 非攻撃エントリもコンボレシピ・セットプレイに使うため全取込する開発者決定(2026-06-09)、(b) ドライブリバーサルがダメージ 500>0 でダメージ判別不能、により訂正が必要(fr701-mainline-handover §1-2)。
- **2(通常投げ)**: CHANGE-023 は 1・2 件目のみ規定。実測で投げは 2 件=18キャラ / 3 件=10 / 4 件=ガイル / 6 件=ザンギエフ。3 件目は空中投げとは限らない(アレックス=地上特殊投げ、ガイル=前後の空中投げ 2 種)(同 §1-3)。
- **3(ターゲットコンボ)**: 公式 HTML に独立 TC セグメントは存在せず、段数付き行として通常技・特殊技セグメント内に出現(同 §1-4)。
- **4(on_hit/on_block)**: `D`(ダウン)が 1,012 件、`※N` が 35 件、その他範囲値・`ー` 等があり、整数列へ素直に入らない値の退避規則が要る(同 §1-6)。
- **5(recovery)**: recovery は公式原文の文字列で多パターン。total 算出の入力仕様として列挙が要る(同 §1-7)。

> 各根拠データは開発者が把握済み。

## 3. 変更の内容

### 3.1 §7.5「取込対象」節の訂正(CHANGE-023 の訂正)

**現行(CHANGE-023)**:

> 公式データのうち moves として取り込むのは攻撃技に限る。判別は公式 HTML のカテゴリ見出し(セグメント)と、共通システム内ではダメージ値で行う。
> - 取込対象:通常技/特殊技/必殺技/SA/通常投げ/ドライブインパクト。ターゲットコンボが公式に存在する場合はそれも含む。
> - 取込対象外:ステップ/パリィ系ラッシュ/ドライブパリィ・ジャストパリィ/ドライブリバーサル。

**訂正後**:

> 取込の判別は公式 HTML のカテゴリ見出し(セグメント)と、共通システム内では**位置+名称**で行う(ダメージ値では判別しない)。
> - **キャラセグメント(通常技 normal / 特殊技 unique / 必殺技 special / スーパーアーツ super_art / 通常投げ throw)は、非攻撃エントリを含めセグメント内の全行を取り込む**(非攻撃エントリもコンボレシピ・セットプレイに使用するため。開発者決定 2026-06-09)。各行は所属セグメントの category へ写像する。
> - **共通システムセグメントはドライブインパクト(drive_impact)のみ取り込む**。判別は名称 `ドライブインパクト` の前方一致 + 位置で行う。ドライブリバーサルはダメージ 500>0 のためダメージ値では非攻撃と判別できず、名称・位置で除外する。
> - 取込対象外:前方/後方ステップ(modifiers.type `dash_forward`/`dash_back`)、パリィドライブラッシュ/キャンセルドライブラッシュ(modifiers.type `parry_drive_rush`/`cancel_drive_rush`)、ドライブパリィ/ジャストパリィ、ドライブリバーサル(ガード時/起き上がり時)。（※ドライブパリィは CHANGE-038(2026-06-18 反映済)で取込対象へ方針転換。本行のドライブパリィ分は打ち消し済み。ジャストパリィは引き続き除外）
> - ターゲットコンボの扱いは §3.2(本通知書)を参照。

### 3.2 §7.5: ターゲットコンボの実態化(CHANGE-023 の訂正)

**現行**: 「ターゲットコンボ(target_combo)が公式に存在する場合はそれも含む。」

**訂正後**:

> 公式 HTML に独立したターゲットコンボのセグメントは存在しない。ターゲットコンボ相当は、通常技・特殊技セグメント内の**段数付き行**(日本語 `（N段目）` / 英語 `(N)`)として出現する。**段ごとに別 move として取り込み**(公式粒度。開発者承認 2026-06-09)、所属セグメントの category(normal / unique)を付与する。**target_combo の機械判別は行わない**。category enum の `target_combo` は自動採番の対象外とし、FR703 での手動分類に用いる(enum 自体は温存)。

### 3.3 §7.5「通常投げの正規化」注記の拡張

**現行**の注記(1・2 件目の位置自動採番)に、3 件目以降・公式名退避・空中投げ判定を追加する。

**訂正後の注記**:

> 通常投げセグメントは全件取り込む。
> - **1・2 件目**: official_ja_move のエイリアスをセグメント内の出現順で `前投げ`(1 件目)/ `後ろ投げ`(2 件目)に自動採番する(全キャラで成立。開発者確認 2026-06-10)。`move.code` は `throw_forward` / `throw_back` 固定。元の公式名は notes に `公式名: …` として退避する(例: リュウ 背負い投げ → 前投げ、notes に `公式名: 背負い投げ`)。
> - **3 件目以降**: 汎用名を付けず、正規化済みの公式名を official_ja_move エイリアスに保持し、**要確認扱い**とする(3 件目は空中投げとは限らない。アレックス=地上特殊投げ、ガイル=前後の空中投げ 2 種)。`move.code` は英語表示名の機械変換で採番(CHANGE-025 §3.3)。
> - 名称または前提条件に `（ジャンプ中に）` 等を含む投げは `is_aerial = true` を付与する。
> - キャラ別のダメージ・フレームは保持する(固定値化しない)。並び順が想定外のキャラは FR703 で補正。
> - 投げ件数の実測分布: 2 件=18キャラ / 3 件=10キャラ / 4 件=ガイル / 6 件=ザンギエフ。
> - 英語汎用名(フェーズ3以降の英語ロケールで使用): `前投げ`=`Forward Throw`、`後ろ投げ`=`Back Throw`。

### 3.4 §7.5: on_hit / on_block の値退避規則 + notes 付記書式

§7.5 CSV 列表の `on_hit / on_block` 行へ値書式を追記し、notes 付記書式を新設する。

> **on_hit / on_block の値書式**(整数列へ素直に入らない公式値の退避):
> - `D`(ヒット時ダウン、1,012 件): CSV は空欄(→ moves は NULL)+ notes に `【ツール付記】ヒット時ダウン(D)`。
> - `※N`(注釈付き数値、35 件): 数値 N を格納 + notes に注釈原文を付記。
> - 範囲値・複合値・`ー` 等: CSV は空欄 + notes に原文を退避。
>
> **notes 付記書式**: ツールが付与する注記は `【ツール付記】{内容}` の形式とし、複数は `;` で連結する。本体の取込プレビューと FR703 編集器はこの書式を共有してパース・表示する。通常投げ 1・2 件目の公式名退避(§3.3 の `公式名: …`)も notes に格納する。
>
> **drive_gauge_decrease_punish は出力する**(開発者決定 2026-06-09。CHANGE-022 で「出力要否は確認事項」としていた点を解消)。

### 3.5 §7.5: recovery 入力パターンの明記

§7.5 CSV 列表の `recovery` 行へ、取り得る値パターンを追記する。

> `recovery`(硬直)は公式原文の文字列で渡る(moves 非永続)。total 算出(M9-02)の入力として、次のパターンを含む: 整数 / `全体 N` / `着地後N` / `N+着地後M` / `N-着地まで` / `[※2] 1-12`(注釈+範囲)/ 空欄。**空欄(発生・硬直とも空欄の 11 行等、算出不能)の場合は total = NULL**(CHANGE-025)。文字列パターンの解釈ロジックは M9-02 で設計する。

> 申し送り §1-7 の「total 算出仕様(M10)」は、本体計画では **M9-02**(FR704 取込時算出。M10 = 複数キャラ登録 UI)へ読み替える。
