## 確定方針

- moves に更新系エンドポイント（編集・ラッシュ生成）を設計書本体へ確定（従来 GET のみ）。
- ラッシュ版生成規則（`category ∈ {normal,unique}` ∧ `is_aerial=false` → `rush_<元技>` + `original_move_id`）をサーバ契約として確定。
- 編集グリッド（画面18＝永続データ編集）と取込プレビュー（画面17＝取込前 dry-run）は別画面・別系統。
- 手動補正は寛容（要確認状態のまま保存可）だが enum/FK/NOT NULL は検証（DES-006）。
- `GET /api/moves`（MoveResponse 契約）は不変。model.Move 集約は行わず乖離検出ガードで代替（M9-03 §4.8）。
