## 2. ★起票時のスコープを 1 文書ぶん広げた（`DES-004` §5.7）

**`CHANGE-101` §1.2 は `DES-004` §5.7 を「CHANGE 対象外（M20-03・CHANGE-100 で確定済み。本サブは従う側）」としていた。** **広げる。**

**理由**——**§5.7-2 は「既存の生成器を通す。直接 INSERT する経路を増やさない」と書いていたが、書かれた時点で存在したのは seed 投入経路だけだった。** **M20-04 が作った利用者編集の経路は生成器を通せない**（生成器は seed のための仕組みであり、利用者の任意入力を通さない）。**⇒ 規約に従えない。**

**★しかし規約が守ろうとしていた不変条件は経路の本数ではない。** **`D-317` の交差条件**（ある技の `alias_text` が、別の技の `alias_text_en` と一致する）**であり、これは DB では守れず検査に残る。**

**⇒ §5.7-2 を「経路を増やすときは、DB で守れない不変条件を守る検査を同じ経路へ置く」へ改めた。** **製造がサービス層へ交差検査を足したのは、この改訂後の規約に沿っている。**

**★あわせて §5.7-2′ を新設した**——**交差は「別キャラなら同じ文字列を入れてよい」で逃げられない。** **`alias_text_en` が入るのは移動系 2 code だけで、その値は汎用語であり全キャラで同一の文字列である**（`back microwalk` 等）。**⇒ 別キャラへ入れるのも本物の交差である**（M20-04 の実測）。

> **★スコープ拡大は黙って行わない**（playbook §4.18 ／ 先例 **CHANGE-083** ／ **CHANGE-087** ／ **D-323**）。**本節と registry に明記した。**

## 3. 起票内容から動いたもの（★3 件）

### 3.1 `GET /api/presets/{id}/aliases` を新設した

**通知書 §2.2 は e/f/g の 3 本しか挙げていなかった。** **⇒ 受理して 4 本目を載せた。**

**理由**——**編集画面（`DES-005` §5.11）を実装する手段が他に 1 つも無い。** `GET /api/presets/{id}` はメタ情報しか返さない。**差し戻し案（既存 GET の応答に含める）は、指示書 §5 (j)「既存 2 本は不変」と衝突し、かつ 1,653 行を 1 応答で返すことになる。**

**★設計の要点 2 つ**——**`character_id` を必須にした**（全件を返さない）／**`officialAliasText` を返す**（**`moves` に技の表示名カラムが無いため、記法プリセットの編集画面で「どの技の欄か」を判別する唯一の手掛かりになる**）。

### 3.2 「作成日」を `DES-005` §5.10 から外した

**`presets` にタイムスタンプ列が無く、`DES-003` §3.8 にも定義が無い。** **列追加はスキーマ変更であり、`CHANGE-101` §1 が非破壊であることの根拠を崩す。**

**⇒ 表示項目から外した。** **要ると判断した時点で、列追加を含む別の CHANGE で足す。** **★製造が独断で列を足さず、報告したのは正しい**（**D-293** の自採番禁止と同じ規律）。

## 4. `P-04` の記述が片側だけだった（★`SUPP-001` §7.3 の是正）

**旧記述「`PRAGMA foreign_keys` が接続プール全体に効いていない」は正しい。** **しかしそこから「FK は効かない」と読むのは誤りである。**

**M20-04 の実測**——**`PRAGMA foreign_keys` が `1` を返す接続を引き、`ON DELETE CASCADE` が実際に発火した。** **`presets.user_id → users(id)` の FK も発火した。**

**★検査上の帰結が重い。** **「削除後に孤児行 0 件」の観測だけでは、CASCADE に頼っていないことを主張できない**——**FK=ON の接続を引けば CASCADE が子行を消すため、CASCADE 依存の実装でもテストが緑になる。** **⇒ 指示書 §5 (g) とチェックリスト §8-4 が求めた検査は、そのままでは主張が成立しない種類のものだった。**

**製造は呼び出し順を固定する 2 本目を足して塞いだ。** **正しい対応である。**

**⇒ `SUPP-001` §7.3 を「効く接続と効かない接続が混在する」へ改め、上記の帰結を明文化した。**
