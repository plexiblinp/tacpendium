## 2. 何を変えるか

```
tacpendium-windows-amd64.zip    （公式サポート）
├── tacpendium-windows-amd64.exe
├── README.txt（起動方法・注意事項）
└── manual/
    ├── tacpendium-readme.html （操作説明書）
    └── images/                 （章ごとのスクリーンショット）
```

**★macOS / Linux の tar.gz にも同じ `manual/` を入れる。⇒ 非公式対応でも説明書は要る。**

### 2.1 ★★★`manual/` フォルダの形を採った（**設計卓の判断**）

**★対案＝単一 HTML へ画像を data URI で埋め込み、`tacpendium-readme.html` 1 ファイルだけを同梱する。⇒ 採らない。**

| # | 理由 |
|---|---|
| 1 | **★22 枚の PNG を base64 で抱えると HTML が数 MB になる。⇒ `git` の差分が毎回巨大になり、査読できなくなる** |
| 2 | **★正本は `docs/usermanual/` に画像を別ファイルで持つ形で既に確定している**（`M32-01`）**。⇒ 配布形だけ変えると、同じ資料の持ち方が 2 通りになる**（`E-76`） |

**★単一ファイル形の利点**（利用者が html を単体で移動しても壊れない）**は認めるが、上記 2 つのほうが重い。⇒ 開発者が別の判断をするなら本節を改訂する。**
