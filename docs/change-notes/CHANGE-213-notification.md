**★逐語**（2026-09-12 開発者回答。**歴史記録として残した**）：

> **zip / tar.gz を組む仕組みは存在しない。⇒ 本節が定める配布物の構成は、いまだ一度も実現されていない。★設計と as-built の乖離である。**

**★★着手前の否定形確認は徹底していた**——**`goreleaser` / `softprops` / `actions/create-release` / `ncipollo` / `gh release` / `on: push: tags:` / `on: release:` / 成果物向けの `sha256sum` / 成果物を固める `zip`・`tar -c` の 9 種を走査して全 0 件。⇒ 両ワークフローとも `permissions: contents: read` であり、リリースを作る権限すら無かった。**

## 2. as-built

| 面 | 値 |
|---|---|
| **入口** | `make release-archives`〔`build-all` を前提に持つ〕 ／ `bash scripts/build-release-archives.sh`〔`dist/` の既存バイナリから組む。**CI 用であり `M36-02` が呼ぶ**〕 |
| **出力先** | **`dist/release/`**。`.gitignore` の `/dist/` が既にカバー済みで、**成果物はコミットしない** |
| **チェックサム** | **`<アーカイブ名>.sha256` を各アーカイブの隣に 1 本ずつ**。`sha256sum` 互換の 1 行で**パスは basename**。⇒ そのディレクトリで `sha256sum -c` がそのまま通る |

### 2.1 ★★★構成の正本は 1 か所である

**★`scripts/release-targets.sh`**〔アーカイブ名 ／ 中の実行ファイル名 ／ 形式 ／ `dist/` 内のソース〕**を、組み立てと検査の両方が `source` する。**

**★★`Makefile` には名前を書いていない。⇒ 書くと 3 か所目になり、必ずドリフトする**（`E-76`）**。**

**★この形の利益は既に出ている**——**macOS の名前を寄せるときも、この 1 行を直せばどちらへでも寄せられる。**

### 2.2 ★★SHA-256 が示すものの限界

**★★★「壊れていないこと」だけである。⇒ 「このバイナリがこのコミットから作られたこと」ではない。**

**★attestation は射程 3＝`M36-02` である。★この区別は配布物の `README.txt` にも書いてある**（**出すだけで使い方と限界が無いと意味が無い**）**。**

## 3. ★★★ライセンス関係 7 件を同梱した（2026-09-16 開発者判断）

| | |
|---|---|
| **入れたもの** | `LICENSE` ／ `DATA-LICENSE.md` ／ `NOTICE` ／ `REUSE.toml` ／ `LICENSES/AGPL-3.0-or-later.txt` ／ `LICENSES/CC-BY-SA-4.0.txt` ／ `LICENSES/MIT.txt` |
| **★7 件が 1 セットである理由** | **`NOTICE` 自身が「配布物に付随する告知である」と名乗り、4 つすべてを名指ししている**〔逐語＝「ライセンス本文は `LICENSE` と `LICENSES/` 配下、パス単位の割当は `REUSE.toml`、データ層の説明は `DATA-LICENSE.md`」〕**。⇒ 部分的に入れると、同梱した `NOTICE` の参照先が欠ける** |
| **層 B の本文が要る実体** | **`//go:embed migrations/*.sql` により、`CC-BY-SA-4.0` のゲームデータのマイグレ 20 本が配布バイナリへ*実際に埋め込まれる*** |

### 3.1 ★★★`LICENSES/` はディレクトリ名ごと保つ

**★basename で平坦化しないこと。⇒ `LICENSES/MIT.txt` が `MIT.txt` として直下に落ちると、同梱した `NOTICE` の「`LICENSES/` 配下」という参照先が消える。**

### 3.2 ★承知のうえの重複

**★`LICENSE` と `LICENSES/AGPL-3.0-or-later.txt` は md5 一致で完全同一**（34,020 B × 2）**。⇒ 34KB は 12MB のアーカイブの 0.3% であり、リポジトリと同じ形を保つ利益のほうが大きい**（開発者判断）**。**

### 3.3 ★★減らすときの注意

**★先に `NOTICE` の参照先が欠けないかを見ること。⇒ 「重複しているから `LICENSE` を落とす」のような一見素直な削減が、同梱した `NOTICE` を壊す。**

**★★法務の断定は開発者の手番である。⇒ 実装で減らさない。**
