## 2. 何を変えるか

### 2.1 `DES-004` §2.1 — 命名の揺れの解消を as-built 化

**★削除ではなく「揺れが在った事実と、その解消」を残す形にした。⇒ 次に同型が現れたときの判断材料が消えるため**（同節の `od` トークン台帳 15 件と同じ趣旨）**。**

| 項目 | 内容 |
|---|---|
| 決着 | **(a) seed 側を直す**（`D-836`・開発者の逐語＝「Seed側を修正します」） |
| 是正後 | guile ＝ `sonic_boom_perfect_light`（**接尾形**）。**ルークと同じ変種軸で選べる** |
| 是正前 | `perfect_timing_light_sonic_boom`（接頭形）。別ファミリー 3 行として並んでいた |
| 帰結 | **ファミリー総数 372 → 369** |

**★命名規約そのものは変えていない。⇒ `<基底>_perfect_<強度>` は同節が既に定めている形であり、ルーク 3 件が正であった。**

### 2.2 ★★★`SUPP-001` §5.5.4 規約 **(17)** の新設（**本 CHANGE で最も重い**）

**`move_code` を改名するときは、後続の手書きマイグレが旧 code で行を解決していないかを `grep` する。**

**★機序＝golden を再生成すると新規 DB は新 code で seed される。⇒ 旧 code を書いたままのマイグレは 1 行も当たらなくなる。★エラーにならない。**

| 壊れ方 | `M30-07` の実測 |
|---|---|
| 件数の空振り | `000039` の 7 件が当たらず `is_projectile` が 0 のまま |
| **★★ガードの反転**（**空振りより重い**） | `000063` の `NOT EXISTS` が通り、**別の技が誤改名される**。**`UNIQUE` 違反も起きない** |
| 別の行への書き込み | `000064` の 10 文 ＋ `move_derivations` の子解決 |

**★★★先例 3 本**（`M35-02` / `M28-05` / `M30-02` 追補）**はこの面を踏んでいない。⇒ 先例をなぞるだけでは到達できない。★「先例が静かだった」は「面が無い」の証拠にならない。**

**★規約 (9)**（前コホート救済 UPDATE）**が対で当たる旨も併記した。**

### 2.3 ★★「既存マイグレは非改変」の例外条項を明文化

**★先例は `000063` のヘッダにしか無く、規約本文から読めなかった。⇒ 読めない先例は先例として働かない。**

**成立条件 4 つ**〔文字列で行を解決している ／ 書き換えないと静かに壊れる ／ 補償では消えない実害が在る ／ **開発者の事前承認**〕**と、書き換えるときの作法 3 つ**〔対称な置換に留める ／ ヘッダへ理由と床を記録する ／ **前コホートを再現する契約テストを新設する**〕**を置いた。**
