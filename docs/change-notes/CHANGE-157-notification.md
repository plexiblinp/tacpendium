## 0. なぜ起票したか

**★★`M26-02` は、設計書に正面から反する状態を repo へ置いた。⇒ 指示書がそう明示指示していたためであり、製造の逸脱ではない。**

| 反した先 | 逐語 |
|---|---|
| **`DES-001` §5** | 「本プロジェクト自体のライセンスは **MIT License** とする（確定。2026-06-28 開発者確定）」 |
| **`SUPP-001` §5.7** | 「**禁止ライセンス:** GPL-2.0 / GPL-3.0 / LGPL-2.1 / LGPL-3.0 / **AGPL-3.0** / **CC BY-SA** / …」 |

**⇒ `M26-02` が置いた 2 つのライセンス**〔`AGPL-3.0-or-later` ／ `CC-BY-SA-4.0`〕**が、どちらも `SUPP-001` §5.7 の禁止列に載っている状態になった。**

**★★設計卓の裁定＝受理する。⇒ 撤回ではなく明確化と差し替えである。**

## 1. `SUPP-001` §5.7 — inbound の規定であることを明確化する

### 1.1 判定

**★★`M26-01` §4.2〜§4.5 が既に判定していた**——「`SUPP-001` §5.7 は **inbound**（取り込む依存）の規定であり、**outbound**（本プロジェクトが名乗るライセンス）を AGPL にすることは §5.7 に違反しない」。

**★★設計卓はこれを追認し、根拠を 1 つ足す**——**同節の見出しそのものが「依存ライブラリ追加ポリシー」である。⇒ 節の題が既に inbound だと言っている。本 CHANGE は節の題が言っていることを本文へ書くだけである。**

**★★禁止列そのものは 1 行も変えない。⇒ AGPL の依存を取り込むことは引き続き禁止である。**

### 1.2 足す文（as-built）

**「本節は inbound（本プロジェクトが取り込む依存）の規定である。本プロジェクト自身が名乗るライセンス（outbound）は `DES-001` §5 が定める」の主旨を明記した。**

## 2. `DES-001` §5 — 三層へ差し替える

### 2.1 差し替えの中身

| 層 | ライセンス | 範囲 |
|---|---|---|
| **A** | `AGPL-3.0-or-later` | **既定**。Go / React のコード、スキーマ、`docs/design` `audits` `change-notes` `instructions`（テンプレ以外）`progress` `usermanual` |
| **B** | `CC-BY-SA-4.0` | `character_data/**`（`seed-progress.md` を除く）／ `docs/seed-data/**` ／ `migrations/*_data_*.sql` ／ **既存マイグレ 72 本（凍結・一度だけ列挙）** |
| **C** | `MIT` | `CLAUDE.md` `AGENTS.md` `.claude/**` `.codex/**` `.agents/**` `human-notes/**` `docs/human-notes/**` `scripts/**` `docs/handover/**` `docs/process/**` `docs/instructions/templates/**` |

**★★正本は `REUSE.toml`**（リポジトリルート）**。設計書は規則と層の意味を持ち、ファイルの列挙は持たない。**

### 2.2 ★★MIT を選んだ理由は AGPL でも成立する

**旧 §5 の理由は 3 つあった。⇒ そのうち 1 つ目は AGPL でも成立する。**

| 旧理由 | 三層での扱い |
|---|---|
| **「依存ライブラリのライセンスと全て互換性がある」** | **★成立する。`M26-01` §3 の実測＝direct 依存 52 件中 0 件が AGPL 非互換** |
| 「最もシンプルで利用者・貢献者にとって分かりやすい」 | **★三層は単純さを失う。⇒ 代わりに `REUSE.toml` 1 本で機械可読にした** |
| 「格闘ゲームコミュニティでの自由な利用・改変を妨げない」 | **★AGPL でも改変・再配布は妨げない。⇒ 妨げるのは「改変してネットワーク越しに提供しつつソースを出さない」ことだけである** |

### 2.3 ★★利用者が作ったデータは三層のいずれにも含まれない

**コンボ・セットプレイ・タグ・メモは利用者の著作物であり、本プロジェクトのライセンスは及ばない**（`DATA-LICENSE.md` §0 と揃える）。**⇒ 明記した。**

## 3. ★★解決規則を設計書へ書かない理由

**`REUSE.toml` の解決は「同一ファイル内では最後に一致した表だけが使われる」**（REUSE 仕様 3.3）**。⇒ 表の順序が割当を決める。**

**★★これを設計書へ写さない。⇒ 写すと、`REUSE.toml` を直したときに設計書だけが古くなる。★正本は `REUSE.toml` であると書くにとどめた。**

> **★危険の実例が報告に在る**——**既定の表を末尾へ動かすと 204 ファイル全部が AGPL に倒れる**（レビュー担当が模擬で確認）。**⇒ 順序は `check-migration-license.sh` の凍結表照合が守る。**
