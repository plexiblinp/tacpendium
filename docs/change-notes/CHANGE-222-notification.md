## 1. ★★★行を書き出すだけでは `sqlite_sequence` は再現されない

**★行 0 なのに `sqlite_sequence` に行を持つ表が実在する。**

| 表 | 跡の出所 |
|---|---|
| **`combos`** | **旧 `000016` / `000019` の表再構築** |
| **`combo_oki_options`** | **旧 `000021` の 0 行 `INSERT`** |

**★★機序＝SQLite は AUTOINCREMENT 表への `INSERT` 文の終端で、*0 行しか入らなくても* `sqlite_sequence` へ書き戻す。⇒ 累積 DB にだけ残る。**

**⇒ 畳んだ先のスキーマ本体へ明示的に `INSERT` する。**

---

## 2. ★逆に明示補正が要らない表もある

**★全 AUTOINCREMENT 表で `seq == max(id)` が成立しているなら、id を明示投入すれば `seq` は自動で追随する**（`M33-02` の実測）**。**

**★`characters` の `seq` 34 は補正不要であった。⇒ `M33-01` が見た差 3 は、削除された 3 行の id が欠番として残っているためである。**

---

## 3. ★★本リポジトリで初めての手である

**★旧 115 本は `sqlite_sequence` を 1 度も触っていない**（実測）**。⇒ 珍しい手であることを承知で使う。★だから規約として残す。**

---

## 4. 影響しないもの

- **既存のマイグレーションの書き方**（**★本規約は「seed を 1 本へ畳むとき」にだけ当たる**）
- **スキーマ・API 経路・DTO**（すべて 0）
