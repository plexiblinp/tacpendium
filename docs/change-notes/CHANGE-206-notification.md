## 1. 規約 (19)：CSV を正本として適用済みマイグレの golden を再生成してよい

**★着手前の状態＝`assertGolden` のメッセージが「★適用済みマイグレなら上書き再生成してはならない」と言い、実運用が 2 度それを破っていた**〔`000112`＝`M30-07`・`D-836` ／ 本サブ〕**。**

**⇒ メッセージと実運用が食い違ったまま置かれていた。★どちらが正かを決めた。**

### 1.1 3 点セットで行う

| | |
|---|---|
| **CSV** | **正本を直す** |
| **golden** | **追随させる**〔しないと `assertGolden` が赤のままになり、新規 DB が是正前の値で seed され続ける〕 |
| **データ修正マイグレ** | **既存 DB を追いつかせる**〔新規 DB では 0 行に当たる〕 |

### 1.2 ★歯止め

**★是正する値は 1 つに絞ること。⇒ 本サブは `is_aerial` の 1 値だけを動かし、同行の `startup=6` には触れていない。**

## 2. 規約 (20)：未マージ・未適用のマイグレは同じ番号のまま差し替えてよい

**★着手前は「適用済みマイグレは書き換えない」しか書かれておらず、*未適用の場合*が決まっていなかった。**

### 2.1 条件は 3 つ

| | |
|---|---|
| **(a)** | **`main` へ未マージであること** |
| **(b)** | **★★差分ではなく*絶対値を書く* `UPDATE` として設計すること** |
| **(c)** | **影響範囲を実査して報告すること** |

### 2.2 ★★★なぜ (b) が本体か

**★`golang-migrate` は `schema_migrations` へ版数を記録するだけで、ファイルのチェックサムを取らない。⇒ 旧内容を適用済みの DB は、書き換えても再実行されない。**

**⇒ 「未適用である」ことは機械が保証できない。★人が保証するしかない。⇒ だから、保証が外れても 1 回流せば最終状態が揃う形**〔絶対値〕**にしておく。**

---

## 3. 規約 (1) の但し書き：サービスコードを通すテストは HEAD で走らせる

**★規約 (1)＝契約テストの比較区間は「そのサブの直前 → そのサブの最終連番」で固定し、HEAD を終端にしない。**

**★★この趣旨**〔そのサブが書き換えていないことを固定する〕**は、素の SQL で見るテストには当てはまる。⇒ サービスコードを通すテストには構造的に当てはまらない。**

| | |
|---|---|
| **なぜ** | **DB の版だけを過去へ戻しても、サービスコードは常に最新スキーマを要求する。⇒ 走査の投影へ列が増えるたびに `no such column` で落ちる** |
| **実地** | **本サブの `first_hit_startup` で `migrate_m3104_test.go` が実際に落ちた** |
| **どうする** | **スキーマは `m.Up()`**〔HEAD〕**。「投入前」の状態は当該行の `DELETE` で作る** |
| **★版ごとの行数** | **素の SQL で見る `TestRun_M3104_UpContract` が押さえており、そちらは 1 行も触れていない** |

**★★★規約 (1) を撤回したのではない。⇒ 適用範囲を切り分けただけである。**
