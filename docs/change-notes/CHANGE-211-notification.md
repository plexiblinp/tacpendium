## 1. 何が問われたか

**★`DES-005` §5.13a の `CHANGE-165` 注記の逐語＝「書出に行数・バイト上限が無いのに、取込は 1000 行 / 10MiB で弾く」。**

**★★実装は書き出しも 1000 件で打ち切る**〔`internal/service/comboio/export.go` の `exportRowLimit = csvcore.DefaultMaxRows = 1000`。打ち切り時は `res.Truncated()` が立ち `export.truncation.body` の確認が出る〕**。**

**★★★レビューも製造も判断を保留した**（逐語＝「バイト数とセットプレイ行数だけを指した省略表現なのか、`exportRowLimit` を見落とした記述なのかは、本レビューでは判断できない」）**。⇒ 設計卓の裁定を要した。**

---

## 2. ★★★裁定＝省略表現である

**★根拠は同じ `CHANGE-165` の中に在る。⇒ 同 CHANGE は `X-Export-Truncated`**〔`Total > Included` か＝上限で切り捨てたか〕**を*同時に新設*している。**

**★★★書き出しに上限が無いと考えていたなら、このヘッダは意味を持たない。⇒ 切り捨てが起きることを前提にした設計である。**

**★★上限が無いのは `X-Export-Reimport-Blocked` が見ている 2 つである**〔同 CHANGE の逐語＝「セットプレイ行数 > 1000 ／ いずれかの CSV が 10MiB 超」〕**。⇒ コンボの行数ではない。**

**★あわせて同 CHANGE §「上限の定義 0 変更」が `DefaultMaxRows` / `DefaultMaxBytes` / `MAX_EXPORT_SELECTION` の 3 つを挙げている。⇒ 書き手は `DefaultMaxRows` を認識している。**
