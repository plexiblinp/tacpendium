## 1. 変更の概要

**新規登録・編集画面のエディタを作り替える。** **★開発者の提案であり、`M24-04` の完了後に決着した**（`P-44`＝`D-577` / `D-578` / `D-580`）。

| # | 変えるもの | 出所 |
|---|---|---|
| **1** | **2 カラムをやめ、1 カラム縦積みにする** | 開発者の逐語＝**「レシピは非常に長くなることがあり、現状の二カラム形式とは相性が悪く感じています」**（`D-578`） |
| **2** | **★★幅による分岐を消し、どの幅でも 2 タブにする** | **`M24-04` の as-built は lg 未満＝2 タブ ／ lg 以上＝2 カラム ＋「メタデータを隠す」である**（`DES-005` §5.7）。**⇒ 本サブは lg 以上の枝をタブへ寄せる** |
| **3** | **プルダウンをボタンへ替える**（**★キャラ選択と始動技は対象外**） | `D-578`（3）（4） |
| **4** | **キーボードだけで入力を進められるようにする**（ハイライトの順送り ／ ボタンのショートカット） | `D-577` の操作イメージ |

### 1.1 ★★本 CHANGE は `CHANGE-137` の上書きである

**`CHANGE-137`（`M24-04`）が `DES-005` §5.7 へ入れた 3 ブロックのうち、「幅で役割が変わる」の記述を本サブが置き換える。**

**★残りの 2 ブロック**〔**エラーの在り処をタブ見出しで示す** ／ **離脱ガード**〕**は置き換えない。守る。**

**★★これは「戻す」のではなく「作り替える」である**（`D-580`）——**タブの機構そのもの**〔アンマウントしない出し分け ／ タブ見出しのエラーバッジ ／ 添字付き前方一致の振り分け〕**は本サブがそのまま必要とする。**

### 8.1 ★★ゲージ欄——**スピナーを撤廃し、ラベルを変える**

**開発者の逐語＝「スピナーが大して便利ではない。マウスでスピナーを押すより数値入力する方が速い。0.5 刻みでない値が入ってもよい。0.5 刻みはスピナー前提の無根拠なイメージだった。」**

**★★不変条件が 1 つ消える。** **「0.5 刻み」は UI（`step=0.5`）だけが担保しており、BE は範囲しか検証していない**（`DES-003` の列説明 ／ `DES-006` VAL-C04）。**⇒ `step` を外すと `1.3` のような値がそのまま保存される。★開発者はこれを承知のうえで許容すると裁定した。**

| 反映先 | 何を書き換えるか |
|---|---|
| **`DES-005` §5.7** | **★ラベルの正典表**〔**ドライブ始動＝`ドライブゲージ(0〜6.0本)` ／ ドライブ消費＝`ドライブゲージ消費` ／ SA 2 欄は変更なし**〕。**★あわせて `drive_available_at_start` の行の「0.5 刻み・`step=0.5`」の記述** |
| **★`DES-003`** | **`drive_available_at_start`**〔**「0.5 刻みは UI（widget `step=0.5`）で担保」を撤回する**〕 ／ **`drive_gauge_consumed`**〔**「0〜20・0.5 刻み」の刻みの部分**〕 |
| **★`DES-006` VAL-C04** | **「0.5 刻みは UI（widget `step=0.5`）で担保」を撤回する。★「BE は範囲のみ検証」は変えない**（**元から刻みを見ていない。変わったのは UI 側だけである**） |
| **★`DES-006` §2.5** | **`drive_gauge_consumed` の「0.5 刻み」の記述。★★「範囲は UI クランプで担保」は変えない**（**クランプはスピナーとは別物であり残す**） |

**★★あわせて規則を 1 行広げる**（`DES-005` §5.7）——**小数が入ることは、上限を書ける欄では `6.0` の形で示す。上限を書けない欄では示さない。**

**★先例＝`drive_damage` は「小数許容」と書かず `ドライブダメージ(-6.0〜6.0)` と範囲で示している。** **★消費側に上限を書かないのは既存の規則に従ったものである**〔**上限をラベルに書くのは根拠が説明できるときだけ**＝`D-576`〕。

**★★新しく前面に出た論点が 1 つある**——**手入力を主にすると `6.0` / `06` / `.5` のような非正準表記が入りうる。`VAL-I05`（CSV 取込の構文検証）は非正準表記をエラーとする。⇒ CSV 出力 → 再取込が落ちないことを確かめる**（指示書 §3.3-14）。**★これは 0.5 刻みを外したから生まれた論点ではない。**

### 8.2 ★★仮登録トグル——**編集モードも最上部へ統一する**

**★`DES-005` §5.7 項目3 の「編集モードは本位置（基本情報フィールド群の末尾）を維持」を撤回する。**

**★★撤回の理由は「開発者がそう言ったから」ではない。配置の根拠だったものが本サブで消えるからである**——**元の規則は「最上部の『← キャンセル』導線と同一行に置く」であり、編集モードにはその相手が無かった。本サブでタブ化した結果、最上部の行構成そのものが変わる。**

**★ラベルを 2 つの版で同一にする**〔**`仮登録として保存(レシピ未入力や重複コンボの登録等を許容)`**〕。**★「重複コンボの登録等」は事実に合っている**——**`DES-006` §2.2 が「VAL-C01〜C11 のうち D01〜D03 以外は全て適用しない」と定めており、`VAL-C02` も仮登録では走らない。**

**★★`M24-11` が閉じた `VAL-C02` の競合とも矛盾しない**——**同判定の母集団は `is_draft = 0` であり、仮登録行は入らない。昇格（`PATCH`）の時点で判定が走る**（`DES-006` §2.3 の 4 経路の 2 番目）。
