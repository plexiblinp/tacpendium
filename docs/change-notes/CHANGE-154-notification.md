## 1. `custom_states` の `subject` — 「設置技かどうか」では決まらない

### 1.1 何が食い違っていたか

**`DES-003` §3.2 の例示**（`CHANGE-131` 追補・2026-08-25）:

> **設置技が置かれた状態から始まるコンボ**（JP・ベガ・ブランカ 等） → `subject: self`, `type: flag`（設置物の有無）

**2026-09-02 の開発者裁定**: ベガ「サイコマイン付与」の `subject` は **`opponent`**。

**⇒ ベガが名指しで `self` の例に挙がっているが、実際に投入された値は `opponent` である**（マイグレ `000094`）。

### 1.2 ★是正の中身——値を差し替えるのではなく、線引きを直す

**2 つは矛盾していない。分類の軸が違っただけである。**

| 何を見るか | 誤り | 正 |
|---|---|---|
| **技の種別**（設置技かどうか） | **★これで決めていた** | — |
| **状態が「どちらに」在るか** | — | **★★これで決める** |

- **自分の側に立つ状態**（ステージ上に自分が置いた物の有無 等） → **`subject: self`**。**自分の側の状態である。** **★as-built の実例＝ブランカの「ブランカちゃん人形」**（値域 0〜3。マイグレ `000093`）。**★★2026-09-05 追記＝初版はここに「JP の落とし穴」と書いていたが、これは実在しない技名であり除去した**（開発者の実査。計測点 `M-123`。**設計卓は武装中で `moves` を引けないため、技名を書いてはならなかった**）。
- **相手に付与するもの**（ベガのサイコマイン 等） → **`subject: opponent`**。**相手の側の状態である。**

**★「設置技」という括りは `subject` を決めない。** 設置技には**自分側に立つもの**と**相手に付くもの**の両方がある。**⇒ 見るべきは「その状態は誰に付いているか」だけである。**

**★先例と整合する**——`AKI` の毒（`subject: opponent`）は設置技ではないが相手に付く。**軸は最初から「誰に付くか」だった。**

## 2. `move_derivations` — 通常ジャンプ攻撃には親を付けない

### 2.1 何が決まったか（2026-09-04 開発者裁定）

**`jump_*`（移動 system move）を親にする行が `M14-03f` で初めて入った**（第四波 52 行 ＋ 既存キャラ 56 行＝108 行）。その過程で論点が 2 つに割れていることが判明した。

| | 中身 | 件数 | 裁定 |
|---|---|---:|---|
| **① ジャンプ攻撃そのもの** | `jumping_{light,medium,heavy}_{punch,kick}` ＋ `neutral_jumping_heavy_kick` | 全 31 キャラで **186** | **★付けない** |
| **② ジャンプ前提の必殺技・特殊技** | 空中竜巻旋風脚・ドリルキック・コンドルダイブ 等 | 第四波 21 子 ／ 既存 43 子 | **付ける** |
| ③ キャラ固有の「ジャンプする技」から出る技 | `c_viper/high_jumping_*` ← `high_jump` | 7 | **その技を親にする** |

**★③ が ① の例外に見えるのは見た目だけである。** `high_jump` は `category=unique`・command `d u` を持つ**入力技**であり、移動 system move とは別物である。

### 2.2 ★★なぜ明文化が要るか（本 CHANGE の主眼）

**① は `is_derived=false` のため `move_derivations` の候補表に一度も載らない。**

**⇒ 第四波で ② に親を付けたとき、① は判断されないまま通過していた。結果は「付けない」で正しかったが、それは偶然である。**

**★同じ機序は次の波でも起きる。** 候補抽出の母数から外れた集合は、判断されないまま通り抜ける。**⇒ 資料に線引きを書いておかないと、次の担当が ① にも付けにいく。**

**★製造は回帰ガード `TestRun_M1403f_JumpNormalsHaveNoParent` と `character_data/seed-progress.md` に落としている。⇒ 本 CHANGE は設計正本側の記述を足す。**

### 2.3 節番号の訂正

**`M14-03f` 設計伝達レポートは反映先を「`DES-003` §3.3」と書いているが、`move_derivations` は §3.20 である**（§3.3 は `moves`）。**本 CHANGE は §3.20 へ反映した。**
