## 2. 反映の内容

### 2.1 `DES-004` §3.1（組み込みプリセット一覧）

**表を 5 行 → 3 行へ。** **あわせて `presets.id` の列を新設した**（`official_ja_move`=1 / `numeric`=3 / `srk`=5）。

| # | 変更 | 根拠 |
|---|---|---|
| a | `official_ja_command` の行を削除 | **D-288**（需要を感じないため出さない・開発者判断） |
| b | `numeric_en` の行を削除 | **D-299**（`numeric` へ統合） |
| c | `numeric_ja` を `numeric` へ改称し、名称を「ナンバリング記法」へ | **D-300** |
| d | 本文「MVPで提供する5つのプリセット」→「提供する3つのプリセット」 | 同上 |
| e | **`presets.id` 列を新設し、`2` と `4` が欠番であることを明記** | **本節に無かった情報である。** `id` 値に 4 経路が依存しており、詰めないことが設計上の条件になったため正典化した |

**「いずれも編集不可とし、カスタマイズしたい場合はコピーを作成する」は不変**（**D-290** で編集不可の維持が確定している）。

**★「差分が記録されていない」ことを本文の注記として残した。** `numeric_ja` と `numeric_en` は、設計書上で一度も差分を書けていなかった——旧「方針」欄の差分（「日本語基準（L/M/H）で統一」対「技の英語準拠」）は **L/M/H がそれ自体英字であるため区別の軸になっていない**。§3.4 のサンプル表も 7 行すべて同一、§4.2 の連結子も同一、エイリアスは両方とも空だった。**本 CHANGE は「あった差分を捨てる」変更ではなく「無い差分を正典から消す」変更である。**

### 2.2 `DES-004` §3.4（サンプル表記）

**`official_ja_command` 列と `numeric_en` 列を削除し、`numeric_ja` 列を `numeric` へ改称。** **7 行の値は 1 つも変えていない。**

### 2.3 `DES-004` §4.2（連結子）

**`official_ja_command` 行と `numeric_en` 行を削除し、`numeric_ja` 行を `numeric` へ改称。** **連結子の値は不変**（`official_ja_move`=`→` / `numeric`=`>` / `srk`=`>`）。

### 2.4 `DES-004` §8（実装時に決定する項目）

**「組み込み5プリセットの全エイリアス表記」→「組み込み3プリセット」。** **★起票時のスコープに入っていなかった**（設計伝達レポート §4-1 の c）。

### 2.5 `DES-003` §6（実装時に決定する項目）

**「プリセットのエイリアス全件（組み込み5プリセット分）」→「組み込み3プリセット分」。** **★起票時のスコープに入っていなかった**（同 d）。**スキーマは 1 文字も変更していない。**

### 2.6 `DES-006` VAL-P05 とその根拠段落

**上限を「組み込み5件＋カスタム＝10件」から「組み込み3件＋カスタム5件＝8件」へ。** **カスタム側の 5 件は据え置き**（**D-300**）。**根拠段落の「1ユーザーあたりの上限は設けない（全体10件以内）」も 8 件へ是正した。**

**★あわせて「本検査は現時点で未実装である」ことを実測付きで明記した**（`internal/service/preset/` は `doc.go` のみ・上限を強制する実装は 0 件＝M20-01 の実測）。**M20-04 で実装する。**

**★起票時のスコープに入っていなかった**（同 a・b）。**M20-04 のプリセット作成機能が直接参照する検証仕様であるため、5 か所のうち最も優先度が高い。**
