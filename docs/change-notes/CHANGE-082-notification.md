## 1. 変更の概要
確定反撃を**別コンボとして一意に**識別するため、`hit_type` に**ジャストパリィ始動の確定反撃区分**を追加する。既存 `punish_counter`（ガード始動）と新区分（ジャストパリィ始動）を別値にすることで、FR301 dup キー（hit_type を含む）により同一レシピでも別コンボとして扱われ一意化する。**`combos.hit_type` は `hit_type TEXT`（DB CHECK なし）と実査確定＝マイグレ不要**。code/VAL/FE/CSV の変更。**後方互換**（新値は新コンボにのみ出現・旧 CSV/データ不変）。着手前ゲート＝反映案。

## 2. 変更の内容（DES-006 / DES-005 / REQ 候補）

| # | 対象 | 変更 |
|---|------|------|
| a | Go model | `internal/model/combo.go` に定数追加 `HitTypeJustParryPunishCounter = "just_parry_punish_counter"`（既存 normal/counter/punish_counter に追加） |
| b | VAL | hit_type 許容値 whitelist に新値（DES-006 §ヒットタイプ／重複判定は §2.3 主要項目のまま） |
| c | FE ラベル | 内部値→**「ジャストパリィパニッシュカウンター」**（DES-005・**正式表記はジャストパリィと略さない**） |
| d | CSV 写像 | import/export の hit_type 写像に新値（後方互換） |
| e | 比較/絞り込み | hit_type フィルタに新値 |
| f | 命名規約 | 保存値は `just_parry_punish_counter`（"jp" を含めない）。正式 DES/コードは「ジャストパリィ」と略さない（キャラ JP/Japan 混同回避） |

## 3. 意味多重化の整理（#3・開発者確認済）
hit_type は本来「始動技のヒット状態」を表すが、本区分は「ジャストパリィ始動」という起点も内包する。**開発者確認（2026-07-19）：ジャストパリィ後の反撃は必ずパニッシュカウンターになるため、「ジャストパリィ始動」かつ「別のヒット状態」は生じない**＝多重化の実害なし。CHECK 制約による DB 側の値縛りは**新設しない**（現行の自由 TEXT＋VAL 担保の方針を据置＝マイグレ回避）。

## 4. 確定した設計判断（プラン §2.5／§3.5・#3）

| 項目 | 判断 | 根拠 |
|------|------|------|
| ダメージ規則 | ガード始動→punish_counter（ノーマル→始動技×1.2／カウンター→不変・自動 materialize）。ジャストパリィ始動→新区分・**手入力** | 2026-07-02 確定・#3 |
| 一意化 | 別 hit_type＝FR301 dup で別コンボ。**guard_type（combo_punishes）不要化** | #3・C-1（dup キーに hit_type） |
| 重複防止 | ガード確反の自動生成前に「同一レシピ＋punish_counter」を探索。ジャストパリィ確反は手入力保存時に「同一レシピ＋新区分」で FR301 判定 | phase3-overview §M18・E-19 |
