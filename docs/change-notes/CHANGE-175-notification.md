## 2. ★★ファミリーが「基底 × 変種 × 強度」の 3 軸になった（`P4M-018`）

**★`SpecialVariant = "plain" | "holding" | "max_holding" | "perfect"`。⇒ ファミリー行と強度行の間に変種行を挟む**（`recipe-special-variant-{plain|holding|max-holding|perfect}`）**。**

| 規則 | 内容 |
|---|---|
| **畳む対象** | `<基底>_holding` / `_max_holding` / `_perfect` |
| **★★★照合順序** | **`_max_holding` → `_holding` → `_perfect`。⇒ `_max_holding` は `_holding` でも終わる。★順序を誤ると「最大ホールド」が「ホールド」として畳まれ、静かに 1 変種消える** |
| **★★畳む条件** | **剥がした基底が同じキャラの必殺技ファミリーとして実在するときだけ。⇒ 実在しなければ独立ファミリーのまま残す**（**基底が消えた変種を到達不能にしない**。**★seed 実測では孤児 0 件**） |
| **★★射程** | **`category='special'` のみ**（開発者の逐語＝「必殺技以外は対象外。通常技や特殊技など」）**。⇒ 通常技・特殊技の `_holding` 17 件には 1 行も触れていない** |
| **代表名** | **plain から採る**（**変種の `name_ja` は「【ホールド】弱グラディウス」の形で、装飾も強度語も残るため**） |
| 変種行の表示 | **変種が 1 つのファミリーでは行ごと出さない** |
| **ファミリー切替** | **変種は通常へ戻す**（**押した覚えのない変種で確定させない**） |

**★実測＝変種マーカーで終わるファミリーは 22 本**（`P4M-016` 適用後。**基底が `A1` の 3 本が合流して初めて畳める**）**。⇒ 畳んだ結果、変種を持つファミリーは 18 本。★孤児 0 件。**

### 2.1 ★★★確定するステップは変わらない

**★ホールド版は従来どおり自分の `move_id` で入り、修飾フラグは足していない。⇒ レシピ表示・保存・比較・エクスポートは 1 行も変わらない。**

**★契約の削除が 1 件ある＝`recipe-special-family-{holding 系 19 本}` が消えた**（変種として畳まれたため）**。⇒ 名指ししているテストは 0 件である**（E2E は `recipe-special-family-hadoken` のみ）**。**

## 3. ★★OD 強度組合せに活性条件ができた（`SD-020`）

**★★調査で「OD 非活性で強度組合せだけ活性」が片面で常に実在していた。**

| 面 | 着手時点 | 完了時点 |
|---|---|---|
| 仮想コントローラ側（`SpecialMovePanel`） | **実在しない**（構造的に起こらない） | **既定非表示・展開で 3 つとも出す** |
| **★★修飾フラグ側**（`MODIFIER_FLAGS`） | **★★★常に実在していた。⇒ そのステップの move が OD かを一切見ておらず、しゃがみ弱 P にも「OD(弱中)」を付けられた** | **必殺技の OD でなければ節ごと出さない** |

### 3.1 活性条件

**`isOdVariantApplicable(move)`＝`category === "special"` かつ `code` を `_` で割ったトークンに `od` を含む。**

**★★★末尾の `_od` だけを見てはいけない。⇒ `od` が `code` の途中に在る OD 必殺技が seed 全 31 キャラで 37 行実在する**〔`mai/flame_od_kachousen` ／ `ryu/denjin_charge_od_hadoken` ／ `ingrid/od_sun_shot_light` 等〕**。★末尾だけで判定すると、着手時点にできた入力ができなくなる＝機能後退である。**

**★実測で偽陽性・巻き添えはゼロ**〔`od` トークンを持つ `special` で `name_ja` に "OD" を含まない行 **0** ／ `_od` 終わりで "OD" を含まない行 **0** ／ `special` 以外で `od` トークンを持つ行 **0**〕**。**

### 3.2 ★★書く 3 点（**`DES-005` §5.7 ／ `SUPP-001` §3.3.1**）

| # | 内容 |
|---|---|
| **★★(a)** | **既定は非表示。⇒ 展開すると 3 つとも出す** |
| **★★(b)** | **活性条件は上記。⇒ 必殺技の OD でなければ節ごと出さない** |
| **★★★(c)** | **既存値は消さない。⇒ 既に値が入っているステップでは非適用でも節を出し、自動展開し、外せるようにする。★抑止しているのは新規付与だけである** |

**★★★抑止は確定させる関数の側にも要る。⇒ 画面の `disabled` は「既存を外せるようにする」ために `checked` を除外しており、「OD 技で選ぶ → 通常技へ変える → 追加」で素通りした。★`RecipeBuilder.handleAdd` で追加時にも濾す。**

**★`OD_VARIANT_ORDER` の値の集合は変えていない。⇒ 変えたのは「いつ出すか」だけである。**
