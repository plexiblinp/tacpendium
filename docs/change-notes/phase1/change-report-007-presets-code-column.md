## 1. 変更の概要

`presets` テーブルに **`code` カラム(TEXT、UNIQUE、NOT NULL)** を追加する。これにより、DES-004 §3.1 で定義されている組み込みプリセット識別子(`official_ja_move`、`official_ja_command`、`numeric_ja`、`numeric_en`、`srk`)を機械可読な形でテーブル上に表現できるようにする。

## 2. 変更の理由

### 2.1 現状の不整合

DES-003 §3.8 と DES-004 §3.1 の間に**設計上の不整合**が存在することが、M1-02 実装中のレビューで判明した。

**DES-003 §3.8 の presets テーブル定義**:

| カラム | 型 | 制約 | 説明 |
|--------|-----|------|------|
| id | INTEGER | PK, AUTOINCREMENT | 内部ID |
| user_id | INTEGER | FK(users.id), NULL可 | 所有ユーザー |
| name | TEXT | NOT NULL | プリセット名 |
| base_preset_code | TEXT | NULL可 | ベースとしたプリセット識別子(カスタム時) |
| is_builtin | BOOLEAN | NOT NULL, DEFAULT false | 組み込みプリセットフラグ |

**DES-004 §3.1 の組み込みプリセット定義**:

| プリセットコード | 名称 | 方針 |
|----------------|------|------|
| `official_ja_move` | 公式表記(日本語・技名表示)改善版 | (略) |
| `official_ja_command` | 公式表記(日本語・コマンド表示)改善版 | (略) |
| `numeric_ja` | ナンバリング記法(日本語版) | (略) |
| `numeric_en` | ナンバリング記法(英語版) | (略) |
| `srk` | SRK記法 | (略) |

DES-004 でプリセットコード(機械可読識別子)が定義されているが、DES-003 のテーブル定義にはこれを格納するカラムがない。`base_preset_code` は「カスタムプリセットの作成元参照用」であり、組み込みプリセット自身の識別には使えない。

### 2.2 不整合の影響

- **エイリアス変換ロジック(DES-004 §5、M1-04)**: 「`official_ja_move` プリセットでフォールバック」のような処理を、`name` 文字列(日本語、長い、表記ゆれリスクあり)で参照する必要が出てくる
- **サービス層実装の脆弱性**: 「公式表記(日本語・技名表示)改善版」のような長い日本語文字列をハードコードする箇所が増える
- **国際化(将来課題)**: `name` を多言語化しようとすると、参照キーも変わってしまう
- **テストの壊れやすさ**: プリセット名を1文字でも変更するとテストが壊れる

### 2.3 解決策

`code` カラム(TEXT、UNIQUE、NOT NULL)を追加し、DES-004 §3.1 のプリセットコードをそのまま格納する。これにより:

- サービス層・リポジトリ層は `WHERE code = 'official_ja_move'` のような機械可読な参照ができる
- `name` の変更がコード参照に影響しない
- 将来的な多言語対応(`name_i18n` JSON など)を行う場合も、`code` は不変キーとして機能する

## 3. 変更の内容

### 3.1 DES-003 §3.8 の presets テーブル定義(変更後)

| カラム | 型 | 制約 | 説明 |
|--------|-----|------|------|
| id | INTEGER | PK, AUTOINCREMENT | 内部ID |
| user_id | INTEGER | FK(users.id), NULL可 | 所有ユーザー(NULLは組み込みプリセット) |
| **code** | **TEXT** | **UNIQUE, NOT NULL** | **プリセット識別子。組み込みプリセットは DES-004 §3.1 で定義された値(`official_ja_move` 等)、カスタムプリセットは UUID 等の一意な値** |
| name | TEXT | NOT NULL | プリセット名(表示用) |
| base_preset_code | TEXT | NULL可 | ベースとしたプリセット識別子(カスタム時、参照先は他レコードの `code`) |
| is_builtin | BOOLEAN | NOT NULL, DEFAULT false | 組み込みプリセットフラグ |

**追加カラム1個**: `code`(`base_preset_code` の上、`name` の下に配置)

### 3.2 base_preset_code との整合性

現行設計の `base_preset_code` は「ベースとしたプリセット識別子」の TEXT カラム。これはカスタムプリセット作成時に「`official_ja_move` をベースにした」のように `code` を参照する想定だったと解釈できる。本変更により、`base_preset_code` が参照する値が明確に「他レコードの `code`」であると定義される。

(`base_preset_code` を `base_preset_id INTEGER FK(presets.id)` にする選択肢もあるが、これは別議論。本通知書では現行の TEXT のままとする)

### 3.3 組み込みプリセットの code 値

DES-004 §3.1 で定義されている値をそのまま使用:

| code | name |
|------|------|
| `official_ja_move` | 公式表記(日本語・技名表示)改善版 |
| `official_ja_command` | 公式表記(日本語・コマンド表示)改善版 |
| `numeric_ja` | ナンバリング記法(日本語版) |
| `numeric_en` | ナンバリング記法(英語版) |
| `srk` | SRK記法 |

### 3.4 カスタムプリセットの code 値

将来カスタムプリセット機能を実装する際(フェーズ1B または M3)、各カスタムプリセットには UUID v4 等の一意な値を `code` として割り当てる(具体的な命名規則は実装時に決定)。

### 3.5 マイグレーション

M1-02 が Plan Mode 段階のため、マイグレーション 000001_init_schema.up.sql の DDL を修正する形で対応(ALTER TABLE は不要)。

- **M1-05 / M1-06**: 影響軽微(直接 code を扱う場面が少ないため)

## 5. 移行影響

### 5.1 データ移行不要

M1-02 は実装着手前の Plan Mode 段階のため、マイグレーションは未実行。既存データは存在しないため、データ移行作業は不要。

### 5.2 後方互換性

API 形式は変わらない(presets API は内部実装のみ影響)。本プロジェクトは個人OSSの開発フェーズ1段階で、外部APIクライアントは存在しない。後方互換性の考慮は不要。

## 6. リスク

| リスク | 影響度 | 対策 |
|--------|------|------|
| `code` UNIQUE 制約違反(同じコードが複数登録) | 低 | seed SQL で5つの組み込みコードのみ投入、カスタムプリセット実装時に UUID 利用で一意性保証 |
| `base_preset_code` の参照整合性 | 低 | 外部キー制約は付けない方針(柔軟性のため、TEXT FK は SQLite で扱いにくい)、参照整合性はサービス層で確認 |
| 既存の M1-02 計画ファイルが既に作成済みの場合の手戻り | 低 | M1-02 が実装着手前のため影響軽微、計画ファイル更新で対応可能 |
