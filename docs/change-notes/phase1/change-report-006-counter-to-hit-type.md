## 1. 変更の概要

コンボの**始動状況を表すカラム名**を `counter_type` から `hit_type` にリネームする。これにより、ガード破壊で始まるコンボ(ドライブインパクトのアーマー破壊、バーンアウト時のクラッシュ等)を将来扱う際に、命名上の違和感なく拡張できる構造とする。

## 2. 変更の理由

### 2.1 現状の問題

現状の `counter_type` カラムは「ヒット時のヒット種別」を表す名前になっており、取り得る値も `normal`/`counter`/`punish_counter` の3種に限定されていた。しかし SF6 ではガード破壊から始まるコンボも一般的に存在する:

- ドライブインパクトのアーマー破壊からの壁やられ始動コンボ
- バーンアウト中の相手にドライブインパクトを当てた際のクラッシュカウンター始動コンボ
- ガード崩し系の状況始動

これらは厳密には「ヒット」ではないため、`counter_type`(ヒット種別)という名前のカラムには値として入れにくい。

### 2.2 変更の方針

カラム名を `hit_type` に変更することで、「ヒット状況」をより広い概念として扱えるようにする。「ガード破壊によって発生した有利状況」も「ヒット状況の一種」として包含できる名前。

`starter_situation` のような新概念導入も検討したが、認知負荷を最小化するため既存名のリネームに留める。

## 3. 変更の内容

### 3.1 カラムリネーム

| 旧 | 新 |
|----|----|
| `counter_type`(DBカラム) | `hit_type` |
| `CounterType`(Goフィールド) | `HitType` |
| `counterType`(JSON DTO) | `hitType` |

### 3.2 取り得る値

**現時点の値は当面維持**:

- `normal`(通常ヒット)
- `counter`(カウンターヒット)
- `punish_counter`(パニッシュカウンター)

**ガード破壊系の具体値は本通知書では追加しない。** 実装中に必要が生じた段階で別途 CHANGE-XXX を発行する。具体値の追加候補(参考、いずれも未確定):

- `guard_break`(ガード破壊始動、DI アーマー破壊等)
- `crush_counter`(バーンアウト時のクラッシュ等)

これらの正確な分類・命名は SF6 の知見が深い開発者の判断によって決定する。

## 5. 移行影響

### 5.1 データ移行不要

M1-02 は実装着手前の Plan Mode 段階のため、マイグレーションは未実行。既存データは存在しないため、データ移行作業は不要。

### 5.2 後方互換性

API 形式が変わるが、本プロジェクトは個人OSSの開発フェーズ1段階で、外部APIクライアントは存在しない。後方互換性の考慮は不要。
