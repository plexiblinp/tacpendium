## 1. 改訂の背景

### 1.1 発見の経緯

M7-01 製造工程完了報告(2026-05-27)で、開発者から以下のご意向を受領した:

> 指摘 3: コンボ編集画面の「既存セットプレイから紐付け」ボタンは DES-005 §5.7 item 10 で明記されているが、開発者は削除を希望。設計変更(CHANGE 通知書起票)の検討が必要。

設計担当として Q1〜Q5 の確認文書を提示(playbook v1.9.0 §8.4「Plan Mode 開発者協議方式」= 質問書ファイル方式の精神に倣う形)、開発者ご判断:

- **Q1 = (α)**: コンボ編集画面の「既存セットプレイを紐付けるボタン」のみ削除。コンボ詳細画面(§5.6)の同等機能 = LinkExistingSetupModal は温存
- **Q2 ご回答原文**: 「セットプレイとコンボの紐付けは、**コンボ登録画面またはコンボ詳細画面** から行う、が正しい。取り除くのは編集画面のみ。セットプレイの更新は詳細画面からの方がやりやすく、編集画面はコンボ編集に集中したいためである」
- **Q3 = 温存**: 「詳細画面でのみ使用。既存セットプレイの紐付けを同じく残す新規登録はまた別の仕組みの認識」(= `LinkExistingSetupModal.tsx` コンポーネント本体は温存、新規登録画面の §5.7 item 10「セットプレイ登録セクション」の **新規登録機能自体は残す**、削除対象は「既存セットプレイを紐付けるボタン」サブ機能のみ)
- **Q4 = (γ-1)**: 本ターンで CHANGE-018 通知書起票を完結 → 開発者反映 → M7-02 指示書執筆着手

### 1.2 改訂の趣旨(開発者ご意向の解釈)

「コンボ編集画面はコンボ編集に集中したい、セットプレイ更新は詳細画面の方がやりやすい」という UX 設計思想。編集画面は **コンボ本体の編集 + 関連セットプレイの新規追加(同時編集)** のみを担当し、**既存セットプレイの紐付け追加 = コンボ詳細画面の専管事項** として責務を分離する。

なお新規登録画面(編集画面と同じ UI を新規モードで使用)についても、開発者 Q3 ご回答「既存セットプレイの紐付けを同じく残す新規登録はまた別の仕組みの認識」を踏まえ、**新規登録画面でも編集画面と同様に「既存セットプレイを紐付ける」UI は提供しない** 解釈とする(別の仕組み = 新規登録時の同時セットプレイ登録 = §5.7 item 10 の他の機能で代替)。

### 1.3 改訂の必要性

DES-005 §5.7 item 10 で「既存セットプレイを紐付けるボタン」が明示されている = この記述を残したまま M7-01 追加タスクで該当 UI を削除すると、設計書本体と実装が乖離する。M7-02 製造担当(将来)が DES-005 §5.7 を読んだ際に「item 10 の機能が一部実装されていない」と誤解するリスクがある。

また DES-005 §5.9 行 391 で「セットプレイとコンボの紐付けは、コンボ登録・編集画面(§5.7 item 10)またはコンボ詳細画面(§5.6)から行う」と参照しているため、この参照も併せて更新する必要がある(編集画面が紐付け動線から外れるため、参照文も「コンボ登録画面またはコンボ詳細画面」に短縮)。
