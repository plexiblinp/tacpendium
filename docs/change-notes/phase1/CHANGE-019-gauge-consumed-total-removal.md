## 1. 改訂の背景

### 1.1 発見の経緯

`drive_gauge_consumed_total` / `sa_gauge_consumed_total`(コンボ全体のゲージ消費量キャッシュ、DES-003 §341-342)は、当初「コンボ登録・編集時に combo_steps から自動集計して保存」(DES-003 §383)し、一覧ソート(DES-005 §5.4)とバリデーション(DES-006 VAL-C06 / VAL-C07 = REQ-001 FR303)に用いる設計だった。

しかし M7-RESEARCH-03(2026-05-30)で、**集計ロジックが未実装で全行 NULL** であることが判明。当初は M7-04 で集計ロジックを実装してカラムを生かす方針(Q11 (γ-2) / Q15 温存、M7-02 期間確定)だったが、**2026-06-02 開発者方針転換**で「これらの消費量は有意義な情報でないため削除する」と決定した。

これを受けて起票した M7-RESEARCH-04(2026-06-03)で削除影響を全数調査した結果、以下が確定した:

- 削除対象 2 シンボルの使用箇所はコードファイル全体で **47 箇所**(バックエンド 19 + Go テスト 4 + フロント TS 14 + マイグレーション 2 + i18n 4 + その他)
- **書き込み経路が存在せず全行 NULL**(`CreateInput` / `buildComboFromInput` / `UpdateMetadataInput` のいずれにもフィールドなし)= データ損失なし
- **機能影響**: ソートは選択肢こそ存在するが全行 NULL で実質ソート不能 / CSV エクスポートは未実装 / コンボ詳細は既に `availableAtStart`(開始残量)表示に変更済み(M7-02 Q10 (X))で削除対象を参照しない / コンボ比較画面(CompareTable)は「ドライブ消費/SA消費」行を表示するが常に「-」かつ **DES-005 §5.8 に当該 2 行の規定なし**(コード除去は §5.8 への整合化)
- VAL-C06 / VAL-C07 は nil 早期 return で **常にスキップ**(死んだ検証)

### 1.2 改訂の趣旨(開発者ご判断の確定)

設計担当として 判断 1〜3 の確認文書を提示(playbook v1.9.0 §8.4「Plan Mode 開発者協議方式」= 質問書ファイル方式の精神に倣う形)、開発者ご判断:

- **判断 1 = FR303 論理削除**: 消費量キャッシュ列の削除は、消費量バリデーション要件 FR303(重要・フェーズ 1)の実装根拠を失わせる。「カラム削除 = 消費量バリデーション要件 FR303 ごと放棄」を確定。FR303 は CHANGE-016 と同じ論理削除パターン(打ち消し線 + 廃止注記 + 復活時手順)で処理する。
- **判断 2 = 文言修正**: FR004 / DES-005 §5.7 (b) の編集可能メタデータに挙げられた「ゲージ消費」は、実体としては編集可能な「ゲージ開始残量」(`drive_available_at_start` / `sa_available_at_start`)を指す不正確な表記(消費量キャッシュは自動計算で編集不可)。消費概念を削除する以上、編集項目に「ゲージ消費」と残るのは紛らわしいため、「ゲージ消費」→「ゲージ開始残量」に文言修正する。
- **判断 3 = M7-04 分割**: M7-04 を M7-04-1(CHANGE-019 クリーンアップ)/ M7-04-2(データ拡充)に分割。本通知書反映は M7-04-1 着手の前提条件。

### 1.3 改訂の必要性

削除対象 2 カラムは REQ-001 / DES-003 / DES-005 / DES-006 の 4 設計書に規定が分散している。カラム削除を実装するのに先立ち、これらの設計書本体から該当規定を除去 / 論理削除しないと、設計書本体と実装が乖離し、後続マイルストーン担当(M7-04-1 製造担当 / M7-05 製造担当)が「規定があるのに実装されていない」と誤解するリスクがある。CHANGE-016(FR603 廃止、REQ-001 + DES-005 の 2 ファイル横断)の論理削除パターンに倣い、4 ファイル横断の改訂を 1 本の CHANGE-019 にまとめる。
