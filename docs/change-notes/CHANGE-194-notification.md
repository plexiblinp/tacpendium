## 1. なぜ要るか

**2 件を 1 本にまとめた。⇒ どちらも `SUPP-001` に当たり、`M33-01` の同じ実測から出ている。**

### 1.1 §2.7 の本数と範囲が失効していた

| 項目 | 旧記述（実測 2026-09-06） | 実測 2026-09-13 |
|---|---|---|
| `*.up.sql` の本数 | **102 本** | **111 本** |
| 連番の範囲 | `000001`〜`000103` | `000001`〜`000112` |
| 欠番 | `000012` の 1 件のみ | **`000012` の 1 件のみ（一致）** |

**★機序＝同日以降に `000104`〜`000112` の 9 本が足された。⇒ `000104` / `000105` は `M28-02a` が実測と同日にマージしたため、旧記述の範囲から外れていた。**

### 1.2 ★★★スキーマの同一性を固定する方法が定まっていなかった

**★`M33-02` は「累積 DB と手書きマイグレが同じスキーマを作ること」を検証する。⇒ その固定方法が書かれていなかった。**

**★★素朴に `sqlite_master.sql` を連結してハッシュすると*必ず*食い違う。** 適用済み DB の生テキストは、旧系列が 111 本かけて積み上げた文字列そのものだからである。

## 2. 何を変えるか

### 2.1 §2.7 の本数と範囲を as-built へ

**★欠番が `000012` の 1 件だけである点は変えない。⇒ 今日も成立している。**

**★★あわせて注記を置いた＝本数はこれからも増えるが `M33-02` が潰す。⇒ それまでの間、ここを引く担当が「102 本」で数えないようにするための更新である。**

### 2.2 ★★★§5.5.4 規約 **(18)** の新設

**累積 DB と手書きマイグレの同一性を「`sqlite_master.sql` のテキスト」で固定しない。**

| 表 | 生テキストに残っているもの（`M33-01` の実測） |
|---|---|
| `combos` | **表名が引用符付き**〔`CREATE TABLE "combos" (`〕。表再構築で `RENAME TO` した跡 |
| `moves` | **`ALTER TABLE ADD COLUMN` の追記が 1 行に連なった形** |
| `games` | 元の閉じ括弧の後ろへ列定義が追記された形 |
| **13 表** | **旧 SQL の `--` コメントを本文として含む** |

**⇒ `pragma table_info` / `foreign_key_list` / `index_list` から構造だけを取り、テキストの見てくれを捨てる。**

**★★★正規化ハッシュは「取り方のスクリプト」と対でしか意味を持たない。** 実例＝`M33-01` で製造とレビューが独立に算出した値は `9b87a96e…` と `8a86d298…` で食い違った。**どちらも間違っていない。連結の書式が違うだけである。⇒ 渡すのは値ではなくスクリプト本体である。**

**★★「同値が取れた」の読み方にも注意を置いた。⇒ 累積 DB の `sqlite_master.sql` をそのまま別 DB で実行し直して得た同値は、*手書きでも一致する*ことを意味しない。**
