## 2. 反映の中身（`DES-005` §5.16）

### 2.1 QR ボタンの表示条件——**「無効」ではなく非描画である**（通知書 §2-a）

**通知書は「`disabled` なのか ／ モーダル側のガードなのか ／ 両方なのか」を確定させるとしていた。★実測の答えはそのどれでもない。**

- **LAN 共有モードが OFF のとき、ボタンは DOM に存在しない。** 条件レンダリングが二重に掛かっており、**モーダル側のガードはボタンより内側にある**（**⇒ ボタンが無いときには到達しない**）。
- **★「有効／無効」という語を §5.16 から外した。** **残すと、次の担当が「押せてしまうのは欠陥だ」と読んで `disabled` を足し、二重の守りを作る**——**これは通知書 §5 リスク 2 が名指しで警告していた形である。**

### 2.2 接続可能IP/ポート表示——**在る。ただし代表 IP 1 件である**（通知書 §2-b）

**★通知書は「無いなら『設計にあって実装が無い』ことを明示する」形で反映先を押さえていた。** **実測は「在る」であり、その分岐へは行かなかった。** **⇒ 代わりに粒度を書いた。**

- **3 行である**——ポート（常時）／ 代表 LAN IP（LAN 共有モード時。取得できないときはフォールバック文言）／ 接続 URL（LAN 共有モード時かつ URL が非空）。
- **★★代表 IP 1 件であり、接続可能な IP の一覧ではない。** **⇒ スマートフォンが別セグメントに居て繋がらないとき、画面には他の候補を出す手段が無い。**
- **★起動時の stdout 案内は一覧を出しており、粒度が違う**（`SUPP-001` §5.6）。**画面へ一覧を出すにはサーバ側の新設が要る。**

### 2.3 接続 URL のテキスト表示——**2 か所に在り、別物である**（通知書 §2-c）

**★通知書 §4-1 は「§2-b と同じものである可能性がある。同じなら 1 項にまとめる」としていた。実査の結論は「別物」である。**

| 場所 | 出現条件 |
|---|---|
| **QR モーダルの中**（QR の直下） | **ボタンを押さないと出ない** |
| **ネットワーク節** | **LAN 共有モード時は常に見える** |

- **どちらも通常の DOM テキストであり選択できるが、コピー用のボタンは無い。** **★§5.16 はコピーできることを要求していないため乖離ではない**——**ただし通知書 §4-1 が「入れるなら選択してコピーできる形にする」と書いていたため、現状がそこまで到達していないことを明記した。**
- **★1 項にまとめなかった。** **まとめると、次の担当が「もう 1 つ足りない」と読むか、逆に「モーダルにも出ているから節の行は要らない」と消す。**
- **開発者の 2026-08-17 の回答（「設定画面の QR コードの下に URL を出す、という意味なら既に出している」＝D-427）は、モーダル内の表示を指している。**

### 2.4 代表 LAN IP と CORS 許可 Origin——**同じ関数だが値は共有しない**（通知書 §2-d）

**★通知書は「同じ関数で決まること」を 1 行書くとしていた。それだけでは落ちるものがあった。**

| | CORS 許可 Origin | 設定 API の `network` |
|---|---|---|
| **回数** | **起動時 1 回で凍結**（`SUPP-001` §2.6.1 の 4） | **設定 API を呼ぶたびに再解決** |
| **失敗時** | **起動を中止** | **警告を出して空を返す** |
| **値の共有** | **無し**（キャッシュも共有抽象も無い） | 同左 |

**★★帰結**——**稼働中に NIC が変わると、画面に出る IP が、凍結済みの CORS 許可 Origin から乖離しうる。** **新しい IP が画面に出るが、その Origin は許可されていない。** **⇒ 「同じ関数だ」とだけ書くと、この乖離が見えない。** **通知書 §2-d 自身が「書かないと片方だけを変えて他方が壊れる」と書いていたが、その懸念は「同じ関数だ」と書くだけでは解消しなかった。**

## 3. 反映の中身（`SUPP-001` §2.6.2）——**通知書 §8 の追補による**

**★通知書 §2.1 は `SUPP-001` §2.6.2 を「変えないもの」に挙げていた。** **`M22-06` の実査で 1 行の食い違いが判明したため、§8 で宣言を部分的に外した上で改訂した。**

| # | 改訂 |
|---|---|
| 1 | **QR 埋め込み URL の表記を `http://<IP>:<Port>/` から `http://<IP>:<Port>` へ**（**★末尾スラッシュは実装に無い**）。**機能差は無いが、放置すると「仕様どおりに直した」つもりの変更が将来入る**（**D-432**） |
| 2 | **`ListPrivateIPv4()` を呼ぶのは起動時案内だけであり、設定 API からは呼ばれていない**（as-built 注記）。**⇒ §2.2 の「代表 IP 1 件」の裏付け** |
| 3 | **§2.6.2 の 5〔候補ゼロ時のエラー表示〕が到達するのは「起動時には見つかったが稼働中に NIC が失われた」場合である**（as-built 注記）。**起動時に見つからなければ CORS 側が起動を中止するため** |

**★代表 IP 決定ロジックそのもの**（除外するインタフェース・優先順位・同一優先度内の採り方）**は 1 文字も変えていない。**

**★`REQ-001` `FR407` の `http://<IP>:<Port>/` は改訂しない**——**同書の記述は URL の形の例示であって、末尾スラッシュを要件として課したものではない。** **⇒ `SUPP-001` と `REQ-001` の表記が揃わないことは意図である**（**D-432**）。
