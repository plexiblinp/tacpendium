## 2. ★受理した契約違反 2 件

### 2-1 ★★仮登録トグルのラベルを製造が変えた——**受理する**

**何に反したか＝`DES-005` §5.7 項目3 の「★ラベルは 2 つの版で同一にする〔正典＝`DRAFT_TOGGLE_LABEL`〕」**（`M24-12` の as-built）。**指示書 §9.2 が委任したのは「保存できない理由の文言」であってトグルのラベルではない。**

**★製造の理由＝旧ラベル「仮登録として保存(レシピ未入力や重複コンボの登録等を許容)」を残すと、同じ画面の下で保存ボタンが `disabled` になり「レシピを 1 つ以上入力してください(仮登録でも必要です)。」と出る。⇒ 画面が上下で正反対のことを言う。**

**★★設計卓の裁定＝受理する。理由は 2 つ。**

1. **★★「2 つの版で同一」は正典 1 本の規律であって文字列の凍結ではない。** **製造は正典 1 本を保ったまま中身を変えた。⇒ 規律は崩れていない。**
2. **★内容が事実に合う。** **「レシピ未入力」を落とすのは `VAL-C09` が仮登録でも掛かるようになった帰結である。★「重複コンボの登録等」を残すのは `VAL-C02` が仮登録で走らないことが今も事実だからである**（`DES-006` §2.2）。

**★★見つかった経路が示唆的である**——**2 回目のレビュー（高-A）で見つかった。1 回目の取り込みでは「`grep` で残存 0 を確認した」と書いたが、走査したのは E2E の spec ヘッダだけで `web/src/` を見ていなかった。★モック HTML もトグルのラベルを描いていないため、開発者の目視確認でも見えなかった。**

**⇒ 「利用者に見える文字列」は、設計書ともコメントとも別の走査面である**（playbook §4.45）。

### 2-2 ★`M24-04`(4) の E2E で、エラーの作り方をサーバ応答のスタブへ替えた——**受理する**

**何に反したか＝指示書 §2.2「`M24-12` の成果を 1 つも落とさない」／ チェックリスト 5-4「E2E の書き換えで検証内容を緩めていたら重大」。**

**★製造の理由＝元の仕掛けは「基本情報タブに居たまま、レシピ 0 件で保存する」であり、本サブがその唯一の到達経路を塞いだ。**

**★★設計卓の裁定＝受理する。理由は 3 つ。**

1. **★assert は元と同一である**（レシピ側にバッジ 1 ／ 基本情報側は 0）。**⇒ 検証内容は緩んでいない。**
2. **★先例がある**（`m22-01` / `m22-02` が `page.route` でサーバ応答を差し替えている）。
3. **★代償を Go 側で補っている**（`field` 書式を固定するテスト 2 本）。**★★しかも 2 回目のレビューで自ら訂正している**——**当初押さえたのは `VAL-C08`（WARNING）だったが、フロントは `severity !== "error"` を捨てるため、前方一致 `steps[` を本番で実際に通る唯一の生産者は `VAL-C12`（ERROR）だった。**

**★★ただし §4-2（画面から到達できる検証エラーが 0 件になった）と対で扱う。** **⇒ 「観測手段を替えてよいか」は解けたが、「その機能を今後どう位置づけるか」は残る**（§5）。

## 6. ★★裁定した 1 件——`setups[*]` はレシピタブでよいか（§4-7）

**★★エディタのタブ見出しのバッジが、同梱セットプレイのエラー（`field = "setups[1]"` 等）を「基本情報」タブへ誤計上する。しかし直す欄は「レシピ」タブのセットプレイ登録の節に在る。**

**★開発者の実機確認で裏取り済み**（逐語＝**「基本情報タブにエラーのバッジが出る動きでした」**）。

**★★設計卓の裁定＝「`setups[*]` はレシピタブ」で正しい。** **`SetupRegistrationSection` はレシピパネルの内側に在り、直す欄はそこにあるからである。**

**★★ただし前方一致へ機械的に足すだけでは足りない。** **編集モードではセットプレイ登録の欄が出ない**（`mode === "new" || "copy"` のみ）。**⇒ 編集モードで `setups[*]` の ERROR が出うるなら、直す欄がどちらのタブにも無い状態になる。**

**⇒ ★★「編集モードで `setups[*]` の ERROR が出うるか」を先に確かめること。** 出ないなら足すだけでよい。出るなら、その場合の指し示しを別途決める。

**★本サブでは直さない**（製造の判断を支持）。**★`M24-04`（`SM-148`）由来の別件であり、`M24-CLOSE` か `M25`。**

**★★重大ではない**——**エラーの文言そのものはタブの外に出るため隠れない。壊れているのは「どのタブで直すか」の指し示しだけである。★ただし `SM-148` はまさにその指し示しのために作られた機能である。**
