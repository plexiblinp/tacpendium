## 1. 変更の概要

M16-02（G-f）実装完了＋追補実行に伴い、確定内容を設計書へ反映する。combos に **SA 消費（INTEGER 0〜6）＋ drive 消費（REAL 0〜20・0.5 刻み）** の手入力列 2 本を追加（マイグレ 000020・ADD COLUMN）、詳細/入力欄/**比較（4 行）** に反映し、CSV は**任意列として列末尾追加**（後方互換）した。消費列は dup/recipe 非対象（メタデータ）。

本 CHANGE は確定反映（§2）＋ F-1 保留部（§3）＋ 製造独自判断への回答（§4）＋ 要設計判断（§7＝F-1／A-1／A-3）で構成する。

## 2. 変更の内容（確定反映）

### DES-003 §3.4（combos・消費 2 列・型差）

- **`sa_gauge_consumed`（INTEGER・NULL 可・0〜6）** ＋ **`drive_gauge_consumed`（REAL・NULL 可・0〜20・0.5 刻み）** を追加。CHECK 不使用。
- **型差を明記（伝達メモ B-3）**: **SA 消費＝整数（全層で `int`／CSV 正準整数／FE `.int()`）・drive 消費＝0.5 小数**。将来「SA を 0.5 本単位で消費」の要望が出た場合は SA も再構築型変更（M16-01 相当）が要る旨を注記。
- SA の範囲差（始動 SA 0〜3 に対し消費 0〜6）＝コンボ中に SA が溜まり始動より多く使えるため。

### DES-005 §5.6（詳細）・§5.7（登録/編集）

- §5.7: 消費入力欄 2 つ（SA 消費＝整数ステッパー・drive 消費＝0.5 小数入力）。**始動と消費をラベルで判別可能に**。
- §5.6: 詳細に消費を表示（始動と区別）。

### DES-005 §5.8（比較・追補 v1.0.1）・§5.4（一覧）

- §5.8: 比較に **ゲージ 4 行（drive 始動残量 / SA 始動残量 / drive 消費 / SA 消費）を連続ブロック**で掲載（A-1/CHANGE-060 §7-1 の非対称解消）。**比較行ラベルは「始動残量」**（開発者指定）。
- §5.4: **一覧の表示列カスタマイズには始動/消費を追加しない**（過密回避・現状維持）旨を明記。

### DES-002 §7.6（CSV 後方互換・任意列の正典化・伝達メモ B-1）

- 消費 2 列は **CSV の「任意列」として列末尾追加**（旧 CSV〔消費列なし〕の import を `VAL-I04` で落とさないため、必須列判定は `requiredImportColumns`＝全列−消費 2 列を使用）。
- **CSV 列契約を「必須列（欠けたら VAL-I04）」と「任意列（往復するが欠けても可＝後方互換の新列）」の 2 種に正典化**。**以後 combos に列を足す際は「任意列として列末尾追加」を標準**とする（後続マイルストーンの列追加が旧 CSV を壊さない運用を確立）。消費列が JSON blob 列（tags/recipe）より後ろに並ぶのは後方互換のための意図的な列末尾追加。

## 3. F-1 判断後に反映（DES-006 §2.4・消費列の検証）

- 消費列の検証（BE VAL／FE zod／範囲の扱い）は **F-1（§7-1・消費上限を強制するか＝① の再検討）** で方式が決まるため、**DES-006 §2.4 の反映は F-1 確定後**とする。
- 反映時に織り込む論点（F-1 の帰結に応じて文言確定）: **B-2**（「検証しない」は BE VAL だけでなく **FE zod の範囲 ERROR も含めて**明記＝製造が初回に範囲付き zod を書きレビュー「高」で是正した再発防止）／ **C-1**（範囲は UI ヒントのみ・BE/CSV 非強制なら SA=999 等が保存され得る）／ **C-2**（範囲 VAL 非連動でも**型・正準形の構文検証 VAL-I05 は残る**＝"2.0"/"05"/"6.50" は依然エラー）。

## 7. 開発者への確認事項

1. **F-1（最重要・差戻し）: 消費列の上限を強制するか＝① VAL 非連動の再検討**
   何を: SA 消費（0〜6）・drive 消費（0〜20）の上限を画面で強制したい（「6 本を最大に」）との差戻し。① は VAL 非連動（2026-06-26 確定）で確定済みのため、方式を判断されたい。
   選択肢:
   - **(a) UI 上限クランプのみ**: 入力欄で上限超を打てないよう FE クランプ。BE/CSV は非連動維持（記録の自由度を API/CSV に温存）。**注意**: 始動欄は現状クランプなし（保存時 zod のみ）＝消費だけクランプすると**始動/消費で入力挙動が非対称**になる。
   - **(b) 保存時範囲検証を消費にも付ける（① を精緻化）**: zod＋BE で 0〜6 / 0〜20 を強制＝**始動と同じ「保存時ブロック」に揃う**（始動は既に zod 範囲で弾く）。**DES-006 §2.4 の「消費列は検証しない」は撤回・改訂**。dup/recipe 非対象・CSV 契約は不変を維持。
   - **(c) ① 維持**: 非連動のまま（UI の max は hint のみ）。差戻し要望は満たさない。
   なぜ: F-1 で DES-006 §2.4 の反映方式（§3）が決まる。dup/recipe 非対象・CSV 契約不変は (b) でも崩さない。
   暫定案: **(b) を推奨**。始動が既に保存時 zod で範囲を弾いており、消費も同方式に揃えると**始動/消費の入力挙動が一貫**し「6 本を最大に」の要望も満たす。① の本旨（FR303 の自動キャッシュ/自動算出を復活させない）は保ちつつ、「範囲は妥当値に限定」へ精緻化する解釈（SA=999 のような不能値は元々記録の自由度の範囲外）。(a) は UI だけ塞ぐ軽量案だが API/CSV で上限超が残り、始動との非対称も生む。→ **(a)(b)(c) いずれかをご指定ください**。(b) の場合は DES-006 §2.4 を「消費も範囲検証（始動と同方針）」へ改訂します。

2. **A-1: 画像/クリップボード/エクスポートカードに消費を載せるか**
   何を: 消費は詳細・比較に表示されるが、**FE 画像エクスポート（`combo-io`・`ExportItemKey` opt-in 体系）には未掲載**。始動残量はエクスポート項目にあるため、**消費を足さないと「始動はエクスポートできるが消費はできない」非対称**が残る。
   なぜ: エクスポート項目定義（DES-005）に波及。新 `ExportItemKey`＋トグル＋export-model 行の新設が要る。
   暫定案: **M16-06 表記 rollout に「エクスポートカードに消費 2 項目追加」を含める**（始動/消費ラベル正典化と同時に横断整合）。別 CHANGE で先行させたい場合はご指定を。

3. **A-3: 始動/消費ラベルの正典化を M16-06 で回収してよいか**
   何を: 比較「始動残量」／詳細「開始残量」の**同一概念 2 表記の並立**（意図的暫定）、en の始動 `(start)`／消費 `consumed` の語法非対称。
   なぜ: 放置すると表記ゆれが恒久化。M16-06（FB⑨⑬）が「始動」明示ラベルの正典化サブ。
   暫定案: **M16-06 で詳細・比較・入力欄・エクスポートを横断して始動/消費ラベルを一括正典化**（ja/en 両ロケール parity）。本 CHANGE では現状の暫定表記のまま反映。
