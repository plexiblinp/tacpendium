## 2. 修正概要

- **新表 `combo_setup_results` を DES-003 に新設した。** 粒度は「コンボとセットプレイの組」に対する検証結果であり、**セットプレイ単体の属性ではない**（同じセットプレイを別のコンボへ転用するとコンボの終わり際の距離が違うため成立条件も変わり得る）。**「未検証」は行の有無で表現し、NULL に意味を持たせない。**
- **★節番号は末尾へ新規採番した（§3.19）。** 通知書 §5 の「§3.13 の後」は**位置の指示**であって採番の指示ではない。**§3.14 は `move_commands` で使用済み**であり、そこへ挿入すると §3.15〜§3.18 が繰り下がって既存参照が一斉に外れる。**§3.13 からの相互参照を 1 行置くことで「後に置く」という意図を、番号を動かさずに満たした。**
- **FK 強制に依存しない実装であることを明記した。** 本表は `ON DELETE CASCADE` に依存せず、`ON UPDATE CASCADE` と明示再ポイント／明示削除を併用している。
- **FK 親の段数による実装形の違いを §3.15／§3.17 に注記した。** `combo_punishes` の親は `combos`（1 段）だが、本表の親は `combo_setups`（複合キー・1 段深い）である。**後続が前者の流儀を真似すると誤る。** M19-04 の `move_derivations` が同じ形になり得るため、先回りして残した。
- **DES-005 §5.6 の操作モデル・語彙・制約を as-built で明文化した。** 操作モデルは**「セル選択 ＋ 3 択の直接指定」**であり巡回トグルではない。画面端の語彙は**「相手が画面端」／「画面中央」**。**未検証セルのメモは永続化されない。**
- **★`§2-h` を v3 へ再定式化した（撤回ではない）。** 「セットプレイ編集画面に置かない」という**画面名による禁止**を、**「保存 UI を置く面は、保存先の親が確定しているか、親と同一トランザクションでコミットできること」**という**性質による定式化**へ改めた。
- **DES-002 に API 3 本と、FK 強制の接続単位問題に対する方針を明文化した**（§3 の拡張）。

## 4. 整合性チェック結果

- **節番号の安定性**：新表を §3.14 として挿入した場合に外れる既存参照を事前に洗い出したうえで、**末尾採番＋相互参照**を選んだ。M17 期に同種の節番号事故が 2 度起きている（CHANGE-068 の「§3.3」・CHANGE-069 の「§3.13 新設」。いずれも製造の現物照合で検出）ため、**今回は反映の着手前に潰した**。
- **CHANGE-090 との順序**：両 CHANGE がともに DES-003 §3.15／§3.17 と DES-005 を触る。**090 を先に完了させてから 087 を適用**した（ボード D-34）。§3.15／§3.17 に対しては、090 が「許容した非対称」を、087 が「FK 親の段数」を、それぞれ**別の注記として追記**しており、内容の衝突はない。
- **保存 UI の原則の一貫性**：v3 は既存 5 ケース（コンボ詳細 項目10／採用ダイアログ 項目12／コンボ新規登録／セットプレイ編集画面／`SetupSelectorModal`）すべてに当てて判定が正しいことを確認したうえで採用されたものである。**v1・v2 は 2 度とも誤っており、3 版目で初めて全ケースが正しくなった**——この経緯自体を DES に残した（後続が v1 の書き方を復活させないため）。
- **語彙の単一正典**：受け身種別のラベルは既存 SSOT（`OKI_TECH_TYPE_LABELS`）を再利用し、**第 3 の語彙を作っていない**。画面端の語彙は `combos.position` の値域と整合している。
- **★アンカー一致状況（反映係が記入・2026-07-31）**：**Q-01〜Q-07 は全アンカー一致**。**`^### 3\.` の全数 grep で末尾が §3.18（`combo_punish_starters`）であることを確認**したうえで新表を **§3.19** として末尾採番した（既存節番号の移動は 0 件）。**配置上の裁量 2 件**＝(1) **Q-04**：本パッチは「§4 の DB アクセス／永続化に関する節（`internal/infra/db` の記述がある箇所）」を第一候補としていたが、**DES-002 に当該節は存在しない**ため、パッチが明示した代替先である **§4.2 の末尾**へ注記として置いた。(2) **Q-07**：「項目10 の記述の直後」の指定どおりに置くと**番号付きリスト（項目1〜13）が分断される**ため、**リスト全体の直後（項目13 の後・「アクション」の前）**に置いた。本原則は項目10 の細目ではなく §5.6 の面全体に係る内容であるため、節レベルの位置が適切と判断した。**Q-05／Q-06 は項目10／項目12 の配下にインデントした子項目として置き、リスト構造を保っている。**
- **実装詳細の非記載**：ハンドラ名・リポジトリ関数名・テスト名は DES の規定文言ではないため本文に載せていない。
