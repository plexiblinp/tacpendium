## 1. なぜ要るか

**★確定反撃サーチが「単独で出したときの発生」で候補を判定していた。⇒ ターゲットコンボのように*初段が当たるまで*が速い技を、正しく拾えない。**

**★★`startup` を書き換えて解くことはできない。⇒ 同列は技表の表示にも使われており、意味が 2 つになる。**

---

## 2. 変更内容

### 2.1 列

| | |
|---|---|
| 列名 | **`first_hit_startup`** |
| 型 | `INTEGER`・**NULL 可** |
| 意味 | **その技の初段が当たるまでのフレーム** |
| `startup` との関係 | **別物である**〔`startup`＝単独で出したときの発生〕 |
| `CHECK` | **置かない** |
| `DuplicateKey` / `recipe_hash` | **入らない** |
| `GET /api/moves` | **露出しない** |

**★列名の審査は `D-861` で通過済みである**〔`starter_startup` は特定消費者の用途を名前へ持ち込むため却下した〕**。**

**★★「NULL の間は候補から外す」は*消費者側の導出規則*であり、列の定義には書かない。⇒ 書くと、別の消費者が現れたときに列の意味を変える羽目になる。**

### 2.2 ★★CSV 契約が 24 → 25 列になった

**★末尾へ追加した。⇒ `parseRow` が位置引きであり、途中挿入はできない。**

### 2.3 ★`fastest_unreachable` の件数断定は本サブより前に失効していた

**★`DES-003` §3.3 は「候補は 16 行」と書いていたが、実測は 25 行である。⇒ 失効したのは第四波**〔`000084`〕**でキャラが増えた時点であり、本サブの変更ではない。**

**★★件数の断定そのものを外した。⇒ 数を書くと、キャラが増えるたびに失効する。**
