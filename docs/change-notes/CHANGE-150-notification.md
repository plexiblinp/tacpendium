## 3. 変更内容（5 点）

### 3.1 フェーズ4 の定義を差し替える

**旧**——「外部データ追従・拡張」。`FR702` ／ `NFR407` ／ `ISSUE-007` の 3 項目。

**新**——**「初回全体公開までにやるべきこと」。** 到達条件は次の 5 群。

| 群 | 中身 | 件数 |
|---|---|---:|
| **A 公開ゲート** | ライセンス三層の承認 ／ 依存ライセンスの棚卸し ／ 配布物のデータ来歴の切り分け ／ 法務ポスチャの追従確認 ／ 正式名の決定と反映 ／ LAN モード API の認証 ／ 段階的公開モデルの実務設定 ／ `devContainer` の公開除外 ／ 静的解析・SCANOSS | **9** |
| **B 摩擦低減** | コード署名 ／ ウイルス誤検知対策 ／ データ鮮度 ／ 操作説明書・動画 ／ 宣伝ブログ記事 ／ モダン操作の扱いの明示 | **6** |
| **`α①`** | 残キャラクター挿入の完遂 | 残 **12 体** |
| **`α②`** | `M24` で直しきれなかった「明らかに品質が低い部分」の是正 | **91 行** |
| **`α③`** | 公開用の別リポジトリ化の準備 | **8 行** |

**★`FR702`（ゲームアップデート追従）は新フェーズ4 に残る**（`D-634` (2)）。**⇒ 3 項目のうち 1 つだけが引き継がれる。**

**★フェーズ4 の終わりが初回全体公開である。**

### 3.2 フェーズ5 を新設する

**「本当に後回しでよいもの」。公開後に順次。**

- 開発プロセス・内部品質・検査・テスト・リファクタ
- 機能拡張・新機能（**★「無い」ことは「品質が低い」ことではない**）
- i18n の訳文品質（`CO-026` 英語ロケール整備を含む＝`D-634` (9)）
- 文書整備のうち利用者向けでないもの（**★操作説明書は利用者向けであり、フェーズ4 の `B4`**）

### 3.3 フェーズ6 以降を新設する

**「構想」。`future-notes` の各設計メモが置き場である。**

**★確定項目を列挙しない**（`D-647`）。開発者の逐語は「**未定だが恐らくフェーズ6 以降**」であり、メモ（一人 SNS）／他プレイヤー比較／VOD 分析／HTML エクスポートの 4 機能を確定として書くと、次に読む担当が「決まっている」と誤読する。

### 3.4 `NFR407`（他ゲーム対応の基盤整備）を「非対応」として残す

**開発者の逐語＝「そもそも別ゲー対応はやるつもりがなくなっている」**（`D-634` (2)）。

**★これは「後回し」ではなく意思の撤回である。⇒ フェーズ定義から外し、要件そのものは「非対応」として §7 に記録として残す。**

**★削除しない理由**——**`NFR407` は `REQ-001` §2 / §3 系からも参照されうる番号であり、行ごと消すと「なぜ無いのか」が分からなくなる。**（`E-111` の趣旨。**★ただし本件は完了済み文書の本文書き換えではなく、現役要件の処遇変更であるため、§7 での記録は許される。**）

### 3.5 `ISSUE-007`（モダン操作対応）を「後付け」と明記する

**フェーズ定義からは外すが、`B6`（クラシック前提の明示）はフェーズ4 に残す**（`D-634` (2)）。

**★理由は `checklist` §3.2 が既に書いている**——**モダンは「表記」と「使用可否」のレイヤーであり、キャラ・技・フレームのレイヤーを変えない。既存の器（プリセット機構と `moves` の列）で表現できるので後付けコストが構造的に低い。★ただし明示しないと「使えないアプリ」と判定される。**
