## 1. 変更の概要

**仮登録（`is_draft = true`）でも、レシピのステップ 1 本以上を必須とする。**

**開発者の逐語（2026-08-29）＝「仮登録がレシピの『ステップ 0 本』を許すことを見直します。ステップのみ仮登録でも必須とします。理由としては、ステップが入っていない仮登録があっても、何に使おうとしたものか後から全く分からないからです。」**

### 1.1 ★★着地は既存 VAL の適用範囲を広げるだけである

**`VAL-C09`＝「レシピが空（ステップ数0）でないか」（ERROR）が本登録用に既に存在する**（`DES-006` §2.1）。

**⇒ やることは「`VAL-C09` を仮登録でも適用する」だけである。★新しい VAL を作らない。**

**★★`VAL-D02` は 1 文字も変えない**〔逐語＝**「レシピ中の `move_id` は指定されていれば存在検証、未指定（NULL）は許容」**〕。**⇒ 技が未指定のステップは引き続き許される。**

**★★開発者の逐語「ステップのみ必須」と `VAL-C09` の定義（ステップ数 0 でないか）が完全に一致する。** **⇒ 「ステップ 1 本以上」か「`move_id` が入ったステップが 1 本以上」かの分岐は、`VAL-C09` の存在によって前者に決まった。**

### 1.2 ★★`move_id` の NULL は 2 つの目的で使われている（**混同しないこと**）

| # | 形 | 位置づけ |
|---|---|---|
| **1** | **`move_id` NULL ＋ `modifiers.type`**（`parry_drive_rush` / `cancel_drive_rush`） | **★★非技ステップの正規表現である**（`DES-004` §2.2 の逐語＝**「技ステップ以外（ラッシュ類など）は `modifiers.type` で識別し、`move_id` をNULLとする」**）。**本登録でも普通に存在する。仮登録の緩和とは無関係** |
| **2** | **`move_id` NULL ＋ `modifiers.type` も無し** | **★これが `VAL-D02` の「未指定（NULL）は許容」が指す仮登録固有のケース** |

**★★本 CHANGE はどちらにも触れない。★数えるのは「ステップの本数」だけである。**

> **★設計卓は 2026-08-29 に自分の説明を 1 件訂正した**（計測点 **`M-90`**）——**両者を 1 つのケースとして説明していた。`VAL-D02` の逐語だけを読み、同じ列を定義している `DES-004` を突き合わせなかった。**

## 2. 変更の内容

### 2.1 ★`DES-006` §2.2 の緩和ルールへ例外を 1 件立てる

**現行の逐語＝「VAL-C01〜C11 のうち、上記D01〜D03以外は **全て適用しない**。仮登録は「うろ覚えや机上のアイデア」の記録が目的のため（FR009、FR305）。」**

**⇒ ★「ただし `VAL-C09`（レシピが空でないか）は仮登録でも適用する」を足す。**

**★VAL-D 表へも 1 行足すかは as-built で決める**（**★`VAL-D03` が「独立した実装関数・定数を持たない」形で既に例外の書き方の先例になっている**）。

### 2.2 ★★適用する経路

**★★実査で確定する**（指示書 §3.3-2）。**設計卓は現物を読めないため断定しない。**

| # | 経路 | 見込み |
|---|---|---|
| **1** | **`POST /api/combos`（`is_draft = true`）** | **★適用する** |
| **2** | **`PUT /api/combos/{id}`（仮登録のまま編集）** | **★適用する見込み** |
| **3** | **`PATCH /api/combos/{id}`（仮登録→本登録の昇格）** | **★★既に `VAL-C09` が走っているはずである**（昇格先は本登録である）。**⇒ 変化なしの見込み。実査で確かめる** |
| **4** | **CSV 取込** | **★実査で確かめる。★適用面に入るなら、取込が落ちる行が増える** |

### 2.3 ★保存ボタンの見え方（`DES-005` §5.7）

| 論点 | 決めたこと |
|---|---|
| **形** | **★★レシピのステップが 0 本のとき、保存ボタンを `disabled` にし、理由を出す** |
| **★「消す」は採らない** | **`D-582` の断定。★ボタンが消えると「なぜ保存できないのか」の情報がゼロになる。★とくに `M24-12` でキーボード中心の入力にしたため、ボタンが消えると順送りの経路そのものが消え、Tab で保存へ到達できなくなる** |
| **★タブ依存の条件は採らない** | **レシピ未入力はどちらのタブに居ても同じ事実である。★タブ条件を足すと「レシピタブへ行けば保存できる」＝ `M24-12` §4.5 が禁じた形そのものになる** |
| **★理由の文言** | **★実装判断。★ただし「レシピを 1 つ以上入れてください」の趣旨が伝わること** |

### 2.4 ★`REQ-001` FR009 へ明確化の 1 文を足す（**開発者承認済み**）

**★★撤回ではない。** **現行の逐語＝「コンボを『仮登録』状態で登録できる（ダメージ未入力可、ルートの妥当性不問）。うろ覚えのコンボや机上のアイデアを記録するためのもの」。**

**★「レシピが空でよい」とは書いていない。★「ルートの妥当性不問」も残る。**

**⇒ ★足すのは「机上のアイデア」を「まだレシピが無い」と読む余地を閉じる 1 文である。**

**★案（as-built で確定する）**——**「★レシピは 1 ステップ以上を要する（`VAL-C09` は仮登録でも適用する）。『机上のアイデア』はレシピが空の状態を含まない。」**

**★★本 CHANGE の反映時に設計卓が書く。** **★製造は `REQ-001` を触らない。**

| 案 | 内容 | 却下の理由 |

| **A** | **新しい `VAL-D04` を作る** | **★`VAL-C09` が既にある。★★`DES-006` §2.1 が自ら書いている規約＝「同じ条件にする」ではなく「同じ 1 本を呼ぶ。条件で書くと 2 本目が書き起こされて静かにずれる」。⇒ 2 本目を作らない** |

## 8. ★★2026-08-29 の射程拡張（**v1.1.0**・`D-588`）

**`VAL-S04`（セットプレイ側の重複判定）の check-then-act 競合の是正を射程へ入れた**（開発者裁定。followup `setup-val-s04-check-then-act-race`）。

**★理由＝`internal/` の VAL であり本サブと同じ層である。** **`M24-05`（フロント中心・`internal/` 差分 0 を目指す形）へ入れるより、同じ手で閉じるほうが安い。**

| 項目 | 中身 |
|---|---|
| **`VAL-S04` の定義** | **「同一キャラの同じ親コンボに、同一レシピのセットプレイが既に紐付いていないか」（ERROR）**（`DES-006` §3） |
| **★何が起きているか** | **★★`VAL-C02` と同型の check-then-act 競合。検証が書き込みトランザクションの外に在るため、2 つの要求が両方「重複なし」を見たあと順に書ける** |
| **★手** | **★★`M24-11` が `VAL-C02` を閉じた手をそのまま使う**——**判定を登録と同じ書き込みトランザクションの内側で `*sql.Tx` を使って行う** |
| **★残っている作業** | **★`BEGIN IMMEDIATE` は既に全書き込み tx に効いている**（`M24-11` が DSN の `_txlock=immediate` で入れた）。**⇒ 残りは「判定を内側へ移す」側だけである** |
| **★★落とし穴 1** | **★★`*sql.DB` 直読みを残さないこと**——**内側へ移しても、渡された `*sql.Tx` を読みに使わなければ未コミットの行が見えず意味が無い**（`SUPP-001` §7.1.1＝`D-360`） |
| **★★落とし穴 2** | **★★followup は「3 経路」と書いているが、その N を数え直させる**——**`M24-11` で設計卓が「3 経路」と書いて実際は 4 経路だった先例がある**（`M-89` / playbook §4.40） |
| **★射程外** | **`SQLITE_BUSY` の翻訳**（followup `sqlite-busy-translation-remaining-paths`） ／ **`VAL-S07`**（削除済みセットプレイの重複＝WARNING。別の判定） |

**★★本サブの 2 つの作業は同じ層だが目的が違う**——**`VAL-C09` は「適用範囲を広げる」、`VAL-S04` は「判定の位置を移す」。★混ぜないこと。**

**★何を重複とみなすかは変えない。位置を移すだけである。**
