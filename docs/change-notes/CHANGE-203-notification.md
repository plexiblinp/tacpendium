## 1. なぜ要るか

**★開発者の要望＝「新規登録、編集の段階で modifier をつけた時の見た目と一致させたい」。⇒ `B04` の本体であった。**

**★★語彙は `M37-02` で既に揃っている。⇒ 残っていたのは*表現形式*だけである。**

---

## 2. ★★★どう実現したか（**`DES-002` §4.11 に触れていない**）

**★段 1 の実査で確定した＝`recipe_cache` は `{presetId: 表示文字列}` であり、ステップ配列も修飾の配列も持たない。**

**★★★しかしその文字列の中には*既に* `{表示語}` が入っている。⇒ 描画時にそこだけ解釈する。**

| | |
|---|---|
| 追加のクエリ | **0 本** |
| `recipe_cache` の形式 | **1 文字も変えていない** |
| 変えた場所 | **描画部品の中だけ** |

**⇒ 一覧 API が `Steps` を返さないこと**（`DES-002` §4.11 の N+1 回避）**は触っていない。**

**★★★「構造化されていない」を「作り直すか諦めるか」と読むと二択になるが、「粗く構造化されている」と読むと三択目が見える。**

---

## 3. 変更内容

### 3.1 描画は `[修飾] 技` の順である

**★開発者裁定**（2026-09-14・逐語）**＝「modifier を技の左側に出すように修正できないでしょうか？ modifier の情報を見てから技を見るという順番の方が自然です」。**

**★★★サーバ生成の文字列は `技 {修飾}` のままである。⇒ 順が逆になる。★順を書かないと、次の担当が文字列の順に合わせて戻す。**

### 3.2 ★★★波括弧は残る

| 面 | 表示 |
|---|---|
| 一覧・詳細・比較・セットプレイの**描画** | **バッジ** |
| **ホバー・エクスポート・コピー** | **★波括弧付きの生文字列** |

**★★`D-867` は生きている。⇒ 「波括弧を廃止した」ではない。★ここを取り違えると、次の担当が波括弧を消しにいく。**

### 3.3 ★★未知の `{…}` はバッジにしない

**★表示語の埋め忘れを隠さないためである。⇒ `B04` が消したかった状態を、バッジで飾って「壊れているのに整って見える」形にしない。**

### 3.4 確定反撃サーチは通らない

**★同面は本部品を通らず素の文字列を直描きしている。⇒ 従来どおり波括弧付きの平文である。★意図した現状であり、通すかは別の判断である。**

### 3.5 ★★★修飾の位置は面によって違う（**意図した非対称**）

| 面 | 位置 | なぜ |
|---|---|---|
| **読む面**（一覧 / マイコンボ / 詳細 / 比較 / セットプレイ） | **技の左** | **「修飾を見てから技を見る」順が自然** |
| **操作する面**（編集画面のステップ行） | **行の右端** | **開発者の逐語＝「編集ボタンに近いので見やすい」** |

**★★★「揃え漏れ」ではない。⇒ 次の担当が揃えにいかないこと。**

**★本サブの目的は「編集画面と*語彙と見た目*を一致させる」ことであり、*位置*まで一致させることは目的ではない。**

---

## 4. ★★開発者の手番

**★設定画面の「キャッシュ再構築」を 1 回押すこと。⇒ 保存済みの `recipe_cache` は古い表示語**〔`{低ジャンプ}`〕**を持ち続ける。**

**★★★`M37-02` の同型の申し送りと*意味が一段違う*。⇒ 「低ジャンプ」は新しい表示語表に無いためバッジにならず、素の `{低ジャンプ}` で出る。★押すまでの間、同じ画面の中でバッジ**〔新しい行〕**と波括弧付き平文**〔古い行〕**が混在する。**
