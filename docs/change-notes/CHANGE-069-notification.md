## 1. 変更の概要

M17（発信者の流通基盤）の中核として、**入力 → キャラ別 `move_code` の決定論ルックアップ**を成立させる。M14-01（000018）で `moves.command` 列を本体から除去して以降、command は**手入力 CSV にしか存在しない**。本 CHANGE は、その command を**索引として本体に確立**し（判断3＝**index-only**＝`moves.command` 列は復活させない）、段階2（単方向＋ボタンの特殊技）の決定論解決を**外部契約として正典化**する。

性質の宣言:

- **非破壊・後方互換**: `moves` への **NULL 不可 BOOLEAN 列 1 本（既定 false）**の追加と、**新テーブル `move_commands`** の新設。既存行・既存 CSV・既存 API に影響なし。
- **非 dup / 非 recipe**: `is_derived`・索引・段階2 解決は `DuplicateKey`（VAL-C02）・`recipe_hash` の対象外。`RecomputeComboCache` 非波及（解決は `move_code` 確定後に既存登録経路へ乗るため）。
- **index-only**: `moves.command` 列は**復活させない**。索引は seed/手入力 CSV から再構築する（M16 判断3・handover §2-6）。
- **エンジンを二度作らない**: 索引の構築主体は **M14-03b で確立済みの `internal/moveindex` IF**（`Lookup`/`LookupAll`/`Skipped`/`CharKeys`）。M17-02 は**新規実装せず消費者拡張**する（request §2）。

**死守 3 契約**（request §1.1・全サブ遵守）: ①**公式表記のみ解決**（汚い入力・簡易入力はサポートしない）／②**モーション解析をしない**（方向トークンの列パターンマッチ・時間依存を実装しない＝決定論ルックアップに徹する）／③**出口は必ずキャラ別 `move_code`**。

CHANGE 対象外（本通知書に含めない）: 段階2 の **UI**（M17-03・DES-005）／**取込ヘルパー本体**（M17-04）／物理コントローラ実モーション入力（M21・FR105〜108）／アップデート追従の運用手順（**FR702 によりフェーズ4 再設計**＝M17 は仕組み導入まで）。

## 4. 確定した設計判断（開発者確認 2026-07-16）

| 項目 | 判断 | 根拠 |
|------|------|------|
| **#1 `is_derived` の恒久配置** | **moves 本体の bool 列**（索引テーブル側フィルタでない） | **開発者確定 2026-07-16**。派生技の概念は索引専用でなく **UI（技ピッカーでの区別・派生技のグルーピング）でも将来使える汎用属性**＝資産価値が高い。索引テーブル内に閉じると再利用時に再スキーマ変更が要る（指示書 §11-1・design-memo v2.1.0 §5-1） |
