## 1. なぜ要るか

**2 件を 1 本にまとめた。⇒ どちらも `DES-002` §11.2 に当たり、切り分けても同じ節を 2 回改訂することになるためである。**

### 1.1 ★★★存在しない成果物名が設計書に載っていた

**★実査**（`M32-01` が製造の作業ツリーで確認）**。**

| 出所 | 何と書いてあったか |
|---|---|
| `DES-002` §11.2 | zip の中身は **`tacpendium.exe`** |
| `Makefile:70`（as-built） | 出力は **`dist/tacpendium-windows-amd64.exe`** |
| `.github/workflows/nightly-crossbuild.yml` | `make build-all` 経由で**同じ名前**を出す |

**⇒ `tacpendium.exe` という名の成果物を作るターゲットはリポジトリに存在しない。★同じ `README.txt` の中で 2 つの節が別の名前を案内する状態になっていた。**

**★★開発者裁定**（2026-09-12・逐語）**＝「`make build-windows` だと `tacpendium-windows-amd64.exe` です。GitHub 上でビルドしても同じ名前になりますね？ `tacpendium-windows-amd64.exe` で統一してください」。**

### 1.2 ★★`README.txt` がどこから来るかが書かれていなかった

**`M32-01` が生成経路を新設した。⇒ 書かないと、次に `README.txt` を直す担当が生成物のほうを編集し、次の `--write` で黙って巻き戻る。**

## 2. 何を変えるか

### 2.1 ★★★配布物名を `tacpendium-windows-amd64.exe` へ（§11.2 の zip 構成）

```
tacpendium-windows-amd64.zip    （公式サポート）
├── tacpendium-windows-amd64.exe
└── README.txt（起動方法・注意事項）
```

### 2.2 ★★図 2 か所は「ファイル名」ではなく「抽象」として書き直す（**★機械置換しない**）

**★★★製造の申し送りが正しい＝`:25`**（構成図の `単一バイナリ（tacpendium.exe）`）**と `:76`**（シーケンス図の `participant Exe as tacpendium.exe`）**は、配布物名とは意味が違う。**

**⇒ どちらも「単一バイナリである」ことを示す図であり、macOS / Linux も同じ図で表される。★ここへ Windows 固有名を入れるのは誤りである。**

| 箇所 | 変更後 |
|---|---|
| `:25` | `単一バイナリ（tacpendium 実行ファイル）` |
| `:76` | `participant Exe as tacpendium 実行ファイル` |

**★設計卓の判断である。⇒ 開発者裁定は「統一せよ」であり、その意図は「存在しない `tacpendium.exe` を消すこと」だと読んだ。★図に `tacpendium-windows-amd64.exe` と書くと、今度は macOS / Linux の図が誤りになる。**

### 2.3 ★★`CHANGE-156` の注記を限定する（**★穴の根はここである**）

**旧記述＝「本書内のバイナリ名は `tacpendium.exe`、コマンドは `cmd/tacpendium/` である」。⇒ この 1 文が `tacpendium.exe` を本書全体へ広げた。**

**⇒ 「コマンドは `cmd/tacpendium/` である」だけを残し、バイナリ名の部分を失効させた。あわせて「配布物のファイル名の正本は §11.2 である」と明記した。**

### 2.4 ★★`README.txt` の生成経路を §11.2 へ明文化（**新設**）

| 役割 | パス |
|---|---|
| 正本 | `docs/usermanual/dist-readme.txt` |
| 生成物 | `README.txt`（**ルート。★`docs/usermanual/` へ移していない**） |
| 生成・照合 | `scripts/check-dist-readme.sh`（**引数なし＝照合 ／ `--write`＝生成 ／ `--self-test`＝対照**） |

**★生成注記に日付・コミットハッシュを含めない。⇒ 含めると照合が毎回赤になり、赤が常態化して検出力を失う。**
