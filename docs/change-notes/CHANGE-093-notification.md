## 1. 変更の概要

**「単独では出せない（親からの派生でのみ出る）」の判定述語を 1 語広げる。**

**CHANGE-091 で正典化された現行述語**は `startup_basis = 'standalone'` かつ `move_derivations` に親参照を持つ行、というものである。**M19 Phase 2 で、この述語では捕捉できない行が実データに存在することが判明した。**

**スキーマ変更を伴わない。** 述語の定義のみの改訂であり、**実装は M19-05 で行う**（本 CHANGE では実装しない）。

**★バグ修正ではない。** 現行述語は CHANGE-091 の時点で正しく、**その後に判明した実データが述語の射程外だった**という形である。

---

## 2. 変更の内容（`DES-003` §3.3）

| # | 対象 | 変更 |
|---|---|---|
| a | `is_derived` 欄の【2026-08-02・CHANGE-091】ブロック内の述語 | **`startup_basis = 'standalone'`** → **`startup_basis IN ('standalone', 'unknown')`**（いずれも `∧ move_derivations に親参照あり`） |
| b | 同ブロック | **誤爆しないことの根拠を 1 文追記する**（親参照は `startup_basis` の人手付与と同一パスで付与されるため、保留の行には付かない） |

**★`is_derived` を「単独入力の可否」の代理として使わない、という CHANGE-091 の結論は維持する。** 変えるのは**代理の手段側の述語**だけである。

---

## 3. 変更の理由 — 実データが述語の射程外だった

**m_bison `devil_reverse_od` ／ `head_press_od`** が該当する（開発者確認 2026-08-07）。

| 事実 | 内容 |
|---|---|
| **単独では出せない** | シャドウライズ（弱 / 中 / 強 / OD の **4 行**）を経由しないと出せない |
| **派生元ごとに値が変わる** | シャドウライズは空中へ飛び上がる技であり、**ノーマル版と OD 版で最速派生できる高度が変わる**。そのため **`active`（地上に着地するまで当たり判定が出ている）と `recovery` が派生元ごとに変わる** |
| **格納されている値** | **OD シャドウライズから出した場合のもの**（初回実測時に、OD 以外からも派生可能である事実を失念していたため） |

**`moves` 行に `active` / `recovery` は 1 つずつしか無いため、4 通りの値を 1 行では代表できない。**

**⇒ `startup_basis` は `unknown` とした**（**D-226**）。「**この行の値は、消費側が安全に使える形になっていない**」という記録である（`startup_basis` の 3 値は「消費側が値をどう使うか」を決めるためにあり、本行は**どう使えばよいかがレシピによって変わる**）。

**⇒ 現行述語（`standalone` のみ）では除外されない。** 放置すると **M19-05 の filler 候補に残り、実機で入力できないレシピが提案されうる**——**M19 の完了条件「実機で入力不可能なレシピを出さない」に抵触する。**

---

## 4. 確定した設計判断

| 項目 | 判断 | 根拠 |
|---|---|---|
| **`unknown` を述語に含めて誤爆しないか** | **しない** | **親参照は `startup_basis` の人手付与と同一パスで付与される設計**（`internal/infra/migration/migrate_m1904b_test.go:212` のコメント）。**保留の行に親参照は付かない。`∧ 親参照あり` が保護になっている** |
| **行を分ける案**（ノーマル派生版 / OD 派生版） | **採らない** | コンボ入力の負担が実害（開発者申告）。**D-221 で行分割を明文化しない理由——ken 火砕蹴が分かれているのは「ゲーム内で別技扱い」だから——が本件には当てはまらない**（同じ技） |
| **`setup_only` を使う案** | **採らない** | 実セマンティクスが違う（「ユーザー登録のセットプレイ専用 move＝コンボ登録 UI から隠す行区分」）。**followup `M19-setup-only-filter`(c) で当初の filler 絞り込み案は撤回済み**であり、再導入は撤回済み論点の再混入（playbook §4.18） |
| **近似値を入れる案** | **採らない** | **未実測値の捏造**（D-121 と同型）。**近似値は実測値と区別がつかず、後から「これは近似だった」を追えない** |
