## 2. 修正概要

### 2.1 DES-003 §3.4（combos）

- 列表に **`link` / `video_path` / `image_path`（TEXT・NULL 可）**を追加（`memo` の直後に記載。物理は末尾 ADD COLUMN＝マイグレ 000031）。
- 「メディア 3 列の扱い」注記を新設: **同一性に非関与**（`DuplicateKey`〔VAL-C02〕・`recipe_hash` に含めない・`RecomputeComboCache` 非波及・「3 列だけ異なるコンボは重複と判定される」）／**PATCH は presence-detection 単一トライステート**（CHANGE-043・キー不在=不変更 / null=クリア / 値=更新）／**PUT でも新コンボへ引き継がれる**／**スコープ＝文字列参照まで**（開く・配信・再生・存在確認をしない・閲覧不可は許容）／**各 1 件**（配列化しない）／model は `*string`（omitempty）。
- CSV 契約は DES-002 §7.6、表示は DES-005、検証は DES-006 §6 が正、と参照を明示。

### 2.2 DES-002 §7.6・§4.2

- §7.6 に **メディア 3 列（任意列＝列末尾追加）**を追加。**export 列順＝末尾に `link` → `video_path` → `image_path`**・旧 CSV 後方互換（`requiredImportColumns` に含めない）・**verbatim 往復**（パス/URL を解決・正規化・書換しない）。
- **VAL-I10 の対称適用を明文化**（伝達メモ §3・開発者確認 2026-07-16）: セルレベルでは `memo` と同様に export で `'` 付与・import で対称剥がし。**sanitize→desanitize が完全往復するため意味単位の verbatim は不変**（式トリガ開頭値を含めテストで担保）。
- §4.2 の **presence-detection 単一トライステート対象に 3 列を加算**。PATCH 行の編集対象にメディア 3 列を明記。**PUT（識別キー変更を伴う編集＝旧論理削除→新規作成）でも 3 列が引き継がれる**ことを明記（伝達メモ §7）。

### 2.3 DES-005

- **§5.6 詳細**: 表示項目 9 として**メディア**を新設（メモの直後・メタデータの前）。**値がある項目のみ表示**（tags の hidden-when-empty 流儀。3 列すべて NULL ならセクション自体を出さない＝memo の「常時表示＋プレースホルダ」流儀は不採用＝伝達メモ §5）。**`link` は http/https 前方一致のときのみリンク化**（`rel="noopener noreferrer"`・`target="_blank"`）・**`video_path`/`image_path` は常にテキスト表示**。以降の項目番号を 10〜12 へ繰り下げ。
- **§5.7 編集**: 「その他情報」節の**メモの直後**に 3 入力欄（任意・空入力=クリア・形式強制なし・**ラベルは固定 ja**）。test-id 3 件を明記。
- **§5.8 比較**: **メディア 3 行**を追加＝**テキスト表示のみ（比較表ではリンク化しない）**（伝達メモ §5）。列ペアリング前提を崩さない。
- **§5.13 出力**: 選択可能項目に **リンク／動画パス／画像パス**（既定 ON）を追加・**全選択行数 25 → 28**（伝達メモ §8-2）・**URL/パスの文字列のみ**（実体埋め込みなし）。
- **i18n 境界を明文化**（§5.13 直後の注記）: **詳細・比較＝i18n（ja/en）／編集欄・エクスポート＝固定 ja**（M16-06 境界の踏襲＝新しい流儀を作らない。伝達メモ §6）。

### 2.4 DES-006 §6

- 「メディア 3 列の検証方針」を新設: **緩検証**（形式強制なし・import で 3 列起因のエラーを出さない）／**閲覧不可は許容**／**`link` のスキーム制限＝表示層の無害化**（**ホワイトリスト方式**＝`http://`/`https://` 前方一致のみリンク化・列挙漏れが原理的に起きない・大文字偽装/前方偽装も遮断・実体 **`web/src/lib/safe-url.ts` の `isSafeHttpUrl(value)`**）／**VAL-I08 とは別枠**（VAL-I08 は設計ルールでコード実体を持たない＝M17-01 の実査で確認。`link` は明示的なリンク用途である点が一般則と異なる）／**パス検証なし**／**長さ上限 2000 は UI（zod）のみ・BE/CSV 非強制**（memo と同一パターン。CSV import で 2000 字超を取り込んだコンボを UI 編集すると保存時 CLIENT エラーになる非対称も memo と同一で本サブ固有でない）／**VAL-I10 の対象**／**VAL-C02 非関与**。

## 4. 整合性チェック結果

- **任意列末尾追加の標準（CHANGE-061/063）と一貫**: メディア 3 列は必須列に含めず、旧 CSV を後方互換で受理する。DES-002 §7.6「必須列と任意列」の枠組みに素直に乗る。
- **PATCH トライステート（CHANGE-043）と一貫**: memo・situation と同一機構に 3 列を加算しただけで、機構自体は不変。
- **dup/recipe 非関与（CHANGE-063 起き攻めと同型）**: 「PATCH で 3 列を変更しても `RecomputeComboCache` を呼ばない」は起き攻めの前例と同型。DES-003 §3.4 と DES-006 §6 の双方で明示し、記述の分裂を作っていない。
- **i18n 境界（CHANGE-066/067 の M16-06 境界）と一貫**: 詳細/比較＝i18n・編集/エクスポート＝固定 ja。**新しい流儀を作っていない**（DES-005 に境界注記を置き、次に類似フィールドを足すサブで同じ問い合わせが再発しないようにした＝伝達メモ §6 の提案を採用）。
- **VAL-I08 との関係を明示**: 「URL は単なる文字列として扱い表示時もリンク化しない」（VAL-I08）と、「`link` はスキーム制限つきでリンク化する」（本 CHANGE）は**別枠**であることを DES-006 §6 に明記。矛盾でなく、`link` が**明示的なリンク用途の列**である点が一般則と異なる。
- **実装詳細は本文非記載**: UI 配置の細部・ラベル文言（仮）・NULL 項目の表示流儀の実装手段は DES 規定文言でないため本文には書かず、**表示条件（値がある項目のみ）と非リンクの原則のみ**を規定した。
- **節番号**: 反映前に DES-003 の節見出しを実ファイルで確認（`grep -nE '^### [0-9]+\.[0-9]+'`）。**§3.4 が combos** であることを確認して反映した。
