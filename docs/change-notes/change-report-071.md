## 4. 整合性チェック結果

- **二段の役割分担（phase3-overview §M17 ④）と一貫**: **AI に `move_code` を生成・確定させない**／**本体から LLM を呼ばない**／**② は決定論**（曖昧一致・編集距離なし）。
- **「エンジンを二度作らない」（request §2）と一貫**: **`internal/moveindex` は差分ゼロ**＝消費者拡張。**段階2 の解決サービスとは別の消費者**（**取込側はフォールバックを持たない**＝M17-overview §4.3 の分担どおり）。
- **「検証を迂回しない」と一貫**: 生成 CSV は**既存 import プレビューへ**（VAL・重複判定・取込 UI を再利用）。
- **DES-006 §2.6 と一貫**: **未解決は正常な結果**＝エラーにしない。**未解決を含んだまま前へ進む導線**（「除外」列）を **§5.19 に明記**（**「未解決を許容する設計」と「未解決があっても完走できる導線」は別物**＝本サブの実データ検証で判明）。
- **節番号**: **DES-005 の §5.x を全件列挙（19 件）して確認**し、**新設は末尾（§5.19）**とした（**既存節をリネームしない**）。DES-002 §4.2／§7.5.1／§7.6・DES-003 §3.9・DES-004 §5／§2.4.4 も実ファイルで確認（**確認出力を切らずに**＝playbook §5.4.1）。
