## 3. 補足(対話の進め方)

- 流れ: 最初のプロンプト + A〜E のファイル投入 → 設計担当の読み込み・受領確認・質問対応 → **着手前確認事項の解消**
  → **phase3-overview ドラフト(M13 以降のマイルストーン分割)を協議・確定** → 序盤サブマイルストーン指示書へ。
- **「想定で書かない、必ず引く」**: code-facts を確認し、「あるはず」で書かない(M10 期の教訓)。DB の実態 ≠ 仕様正典。
- **既存成果物の請求**(ユーザー方針): フェーズ1→フェーズ2 でフォーマットが変わった経緯があるため、phase3-overview /
  指示書 / レビューチェックリストを書く工程では **既存完成版(phase2-overview、直近 M12-06 指示書 + レビューチェックリスト等)を
  開発者へ具体的に請求**して書式の範とする。記憶でフォーマットを再構成しない。
- **CHANGE 二層運用**: 設計書本体(REQ / DES)= CHANGE(次回 050)+ 改訂、補足資料 = 自由改訂。いずれも改訂結果は開発者がコミット。
