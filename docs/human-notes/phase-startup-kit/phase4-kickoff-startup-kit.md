### 0.3 投入手順

1. **`git status` をクリーンにする。** 武装は「排除対象（`docs` / `.claude` / `scripts` 以外）に未コミットの変更がある」と `exit 1` で失敗します。
2. **Claude Code を開く**（PC なら devContainer、外出先なら `claude.ai/code`）。
3. **ブランチを `claude/desk-YYYYMMDD-N` にする**（1 セッション 1 ブランチ。`remote-ops` §6.1）。**設計卓ブランチから製造を分岐させないこと。**
4. **§2 のプロンプト 1 本を貼る**（先頭に武装コマンドが入っています）。
5. **設計卓が `bash scripts/design-desk-arm.sh` を実行して報告するのを確認する。** 報告に「作業ツリーに残した領域: docs .claude scripts」と出ていれば OK。**続けて `bash scripts/check-derived-docs.sh` の結果も報告されます。** **`code-facts` の再生成が要る**と報告されたら、それは**武装中には実行できない**ので開発者側か製造セッションで回してください。
6. **セッションを終えたあと（PC の場合）**、解除は開発者の端末で行います:
   ```
   git sparse-checkout disable
   rm tmp/.design-desk-armed
   ```
   **クラウド（`claude.ai/code`）ではセッションごとに新しい環境が用意されるので解除は不要です。**

### 3.3 製造への引き渡し

- **設計卓と製造はどちらも main から分岐し、どちらも main へマージします。** 設計卓ブランチから製造を分岐させないでください（`remote-ops` §6.1）。
  ```
  main ──┬─→ claude/desk-YYYYMMDD-N   (設計卓・docs のみ)      ──→ main
         │
         └─→ claude/m25-01            (製造・code + progress)  ──→ main
  ```
- 理由は 3 つ: ①マージが 2 段になり開発者の作業が倍になる ②ボード・registry・backlog の正本が分岐上に載って「main と分岐のどちらが正か」が曖昧になる ③設計卓は `fetch` が deny なので長命ブランチほど分岐点が古くなる。
- **★`followup-backlog.md` のコンフリクト面は消えています**（`D-382`・2026-08-14）。**同ファイルを書くのは親だけ**になったため、**製造は完了報告 §4 へ候補を並べるだけ**です。
