# 一次資料: `implement_plan_full` の工程順に構造的な穴がある

| 項目 | 内容 |
|---|---|
| 発見 | **`M23-04`（復元時のバリデーション）製造セッション** / 2026-08-22 |
| 経路 | `M23-04` 設計伝達レポート §4-3 → 設計卓が受理（ボード **D-510**） |
| 対象ファイル | `.claude/commands/implement_plan_full.md`（**開発者のルールファイル。設計卓も製造も編集しない**） |
| 位置づけ | **揮発的な検討用メモ。コミット対象外。** 正本の記録はボード `D-510` と `M23-04` 設計伝達レポート §4-3 にある |

---

## 1. 何が問題か

**完了報告と `progress-log` の索引行を、Phase B（レビュー）より前に commit する流れになっている。**

**⇒ レビュー結果を、レビュー実施前に断定して書く形が構造的に起こる。**

「担当が不注意だった」ではない。**工程がその順序を要求している以上、誰がやっても同じところで同じことが起きる。**

## 2. 実際に起きたこと（`M23-04`）

`progress-log.md` の `M23-04` エントリが、**レビュー実施前の時点で**次を書いていた。

- **「レビュー『高』指摘の不採用は 0 件」と断定していた**（まだレビューしていない）
- **`docs/progress/m23-04-review.md` へリンクしていた**（当時そのファイルは存在しない）

レビューで「高-1」として指摘され、コミット `3feb051` で実測へ訂正された。

**★結果的に「不採用 0 件」は真になった。だがそれは書いてよい理由にならない。**

## 3. なぜ機械検査で見つからないか

| 検査 | なぜ落ちないか |
|---|---|
| `check-doc-refs.sh` | **走査範囲が `docs/progress/` を含まない。** 存在しないファイルへのリンクを検出できない |
| `go test` / lint / `tsc` | **コードは正しい。** 文書だけの問題 |
| `check-progress-log-index.sh` | **「追記が在るか」を見る検査であり、「追記の内容が正しいか」は見ない** |

**⇒ 人が読む以外に見つける経路が無い。** 同型の先例＝`M19-DESIGN-08` §3.1（**D-250**）。

## 4. なぜ実害が出るか

**`progress-log.md` は横断インデックスである**（`CLAUDE.md` §8）。

- **次のサブと設計卓が、前提としてそのままコピーする。**
- **誤った断定が「済んだこと」として下流へ複製される。**
- **訂正されなければ、後から「レビューで何が起きたか」を追う手段が失われる。**

## 5. 設計卓の判断（`D-510`）

**「Phase D（索引行）を Phase C の後へ明示的に移す」が最小の是正である。**

| 案 | 評価 |
|---|---|
| **(a) Phase D を Phase C の後へ移す**（**推奨**） | **順序は工程そのものであり、守られるかどうかが担当の注意力に依存しない** |
| (b) テンプレへ「レビュー後に埋める」と注意書きを足す | **注意書きは読まれないことがある。** 順序の変更より弱い |
| (c) 検査を足す（`check-doc-refs.sh` の走査範囲を広げる 等） | **有効だが後追いである。** 書けてしまう工程はそのまま残る。**(a) と併用なら価値がある** |

**★(a) と (c) は排他ではない。(a) を先に、(c) は余力があれば。**

## 6. 直すときに確認したいこと

1. **完了報告そのものも Phase B より前に commit しているか。** 索引行だけの問題なのか、完了報告の本文にも同じ穴があるか。
2. **完了報告のどの節がレビュー結果を参照しているか。** レビュー後に埋めるべき節と、実装直後に書いてよい節の切り分け。
3. **`implement_plan`（一気通貫でない版）と `incorporate_plan` にも同じ順序があるか。** `implement_plan_full` だけの問題か、CLI 群に共通か。
4. **Phase D を後ろへ移したとき、途中で中断した場合に索引行が永久に書かれない形にならないか。** **★これが (a) の唯一のリスクである**——`M19-04b` / `04c` / `04d` で索引行が実際に落ちた前例があり、それが CLI 側へ手順を二重化した理由だった（`CLAUDE.md` §8）。**⇒ 移すなら「Phase C が終わらなくても索引行は書く。ただしレビュー結果を参照する欄だけは後で埋める」の形が安全かもしれない。**

## 7. 一般形（`retrospective-log` 行き）

**レビュー結果を参照する行は、レビュー後に埋める。**

**「結果的に当たっていた」は書いてよい理由にならない。** 断定を書いた時点で、それが観測ではなく予測であったことは記録から消える。
