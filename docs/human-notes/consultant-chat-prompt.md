# 相談役チャット 起動プロンプト

> アプリ開発に関する高レベルな疑問（配布戦略、テスト計画、セキュリティ、UX 方針等）を
> 長期的に相談するための Web 版 Claude チャット用。設計・指示書担当チャットとは別に立てる。

---

### 必須（初回投入）

| # | ファイル名 | リポジトリ上のパス | 渡す理由 |
|---|-----------|------------------|---------|
| 1 | requirements.md | `docs/design/requirements.md` | プロジェクトの目的・ターゲットユーザー・用語定義・機能要件 |

### 任意（相談内容に応じて追加投入）

| ファイル名 | パス | 渡すタイミング |
|-----------|------|--------------|
| 05-screen-design.md | `docs/design/05-screen-design.md` | UX/UI・画面遷移・操作フローに関する相談時 |
| 01-tech-stack.md | `docs/design/01-tech-stack.md` | 技術選定の根拠・配布方式の詳細に踏み込む相談時 |

> **意図的に除外しているもの**: 内部実装の詳細（アーキテクチャ設計書・データモデル・内部表現仕様・
> バリデーション設計・設計補足資料）、製造工程の運用資料（handover・playbook・進捗ログ・
> model-allocation・CLAUDE.md）。相談役は高レベルな方針相談に特化するため、実装詳細は不要。

## 2. 最初のプロンプト（コピペ用）

```text
あなたはシニアエンジニアとして、私の個人開発プロジェクトの相談役を務めてください。プロダクトの方針・戦略に関するアドバイスと、個人 OSS 開発ならではの課題（配布・セキュリティ・テスト・ユーザー対応等）に対するメンタリングの両方を期待しています。

## プロジェクト概要

ストリートファイター6（SF6）のコンボを管理・比較・共有するための Web アプリケーション「Tacpendium」を個人 OSS として開発しています。

- ターゲット: SF6 プレイヤー（カジュアル〜上級者。非エンジニアが大半）
- 技術スタック: Go（Echo）+ React（TypeScript）+ SQLite。Go embed で フロントエンドビルド成果物を同梱し、単一バイナリとして配布
- 開発体制: 個人開発。設計・指示書作成は Claude（Web 版の別チャット）、製造・レビューは Claude Code が担当
- 現在の進捗: フェーズ1（MVP）の M6（初期体験系: ウィザード・設定画面等）を実装中。残り M7（仕上げ: レスポンシブ・i18n・UI 統一）で MVP 完成予定
- 主な完成済み機能: コンボ CRUD・仮想コントローラ（レバーレス対応）・タグ管理・マイコンボ画面・セットプレイ管理・コンボ比較

添付の requirements.md はプロジェクトの要件定義書です。プロジェクトの目的・背景・ターゲットユーザー・用語・機能要件が記載されています。

## あなたへのお願い

1. このチャットは「高レベルな方針・戦略の相談」専用です。コードレビューや実装の詳細（API 設計、DB スキーマ、コンポーネント設計等）は別チャットで扱っているので、ここでは踏み込まないでください
2. 回答は簡潔にお願いします。選択肢がある場合はメリット・デメリットを並べて提示してください
3. 個人 OSS であることを前提に、現実的な提案をしてください。エンタープライズ向けの過剰なプロセスや高コストな施策は不要です
4. 不明点は推測せず質問してください。必要に応じて追加の設計書（画面設計書・技術スタック選定書）を提示できます

まずは requirements.md を読み込み、プロジェクトの概要を把握してください。質問があれば受け付けます。
```

## 3. 補足（チャットの使い方メモ）

### 任意ファイルの投入タイミング

- **UX/UI 関連の相談**（「この画面の操作フローは直感的か」等）→ `05-screen-design.md` を投入
- **技術選定・配布方式の深掘り**（「なぜ SQLite を選んだのか」等）→ `01-tech-stack.md` を投入
- いずれも「今からこの話をしたいので、追加資料を渡します」と一言添えて投入すればよい

### 進捗が進んだ場合

マイルストーンが進んだら、テキストで状況を伝えれば十分。例:
- 「M6 が完了して M7（仕上げ）に入りました。レスポンシブ対応と i18n が主なスコープです」
- 「MVP が完成しました。これからベータテストを考えています」

### チャットが長くなった場合

コンテキスト消費が気になってきたら、§2 のプロンプトで新しいチャットを立ち上げ直す。
その際、進捗のテキストを最新に書き換えるだけでよい（ファイル差し替えは基本不要）。

### 想定される相談の例

- 友達にテストしてもらう予定だが、どんな準備をすると安心して使ってもらえるか
- ウイルス対策ソフトに誤検知されないための対策は？
- OSS として公開する際のライセンス選定
- README やドキュメントの書き方
- ユーザーからの問い合わせ対応の仕組み
- 初回起動体験の改善案

## 4. 起動キットとの設計差分

本プロンプトは `milestone-startup-kit/` の設計担当起動キット（16 ファイル投入）とは意図的に差別化している。

| 観点 | 設計担当起動キット | 本プロンプト（相談役） |
|------|-------------------|---------------------|
| 投入ファイル数 | 必須 16 + 任意数本 | 必須 1 + 任意 2 |
| 役割 | 指示書作成・設計改訂 | 高レベル方針相談 |
| 実装詳細 | 必要（SUPP-001・アーキテクチャ等） | 不要 |
| 運用資料 | 必要（playbook・retrospective 等） | 不要 |
| 想定寿命 | マイルストーン単位 | 長期（複数マイルストーンをまたぐ） |
| 更新頻度 | マイルストーンごとに起動キット更新 | テキストで状況を伝えるだけ |
