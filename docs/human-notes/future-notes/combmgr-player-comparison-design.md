## 0. 一行

**無作為に選んだ他プレイヤーのリプレイを観察し、相対的な立ち位置（Tier）ごとに「自分よりできていること／できていないこと」を書き並べ、その並びから気づきを得る。** 機械は集計しない。**フォームの構造そのものが分析装置**。

---

## 1. なぜメモ機能と別軸なのか（確定）

- **メモの根本原則は「起票の素通し」**（項目なし・モード選択なし・本文一行）。本機能は**項目が要る**（相手の Tier・できてること・できてないこと）。項目のない器に構造化された比較を押し込むと、メモの中核原則を壊す。
- **データの形が違う**：メモ＝自由テキストの思考ループ／比較＝構造化レコードのセッション記録。
- よって**器を分ける。専用画面を持つ**。

---

## 2. 思想（性質）

- **科学的な差の測定ではない。** 十分なデータを取って統計的に差を求めるものは意識しない。**応用行動分析を素人がなんとなくやる**イメージ。
- **集計しない。** 長期的な監視や数値的な集計は手入力では厳しく、それは別ツールを作るべき。本機能は**必要性を感じた時にやり、ひらめき的に見つけた差分を書き込む**。
- **型にはめない＝自由入力。** 細かい違いは自由入力でないと表現できない。**マスタ語彙・AI 提案・正規化は不要**（集計しないので、語彙の統一も要らない）。
- **揮発的なデータ。** 自分も比較対象も変化するので、分析したくなった時点のスナップショット。**作業台であって書庫ではない**。

---

## 3. 記録の構造

### 3.1 主題部（セッション単位）

| 項目 | 必須 | 内容 |
|---|---|---|
| タイトル | 任意 | 未入力なら年月日 |
| 自キャラ | — | どのキャラクターの情報か |
| 対戦相手キャラ | — | 相手キャラ／**相手キャラ非依存**／**カテゴリを自由入力**（例：胴着） |
| **当時の自分の状態** | 任意 | **自由入力**。主にランクだが、それだけに留まらない運用 |

### 3.2 マトリクス

- **列＝比較対象（複数入力）。自分は列に置かない**（記録は**相対的**なので不要）。

| 比較対象の項目 | 必須 | 備考 |
|---|---|---|
| **Tier** | **必須** | 1 tier 上／同格／1 tier 下／プロ 等。**相対位置**＝ユーザー判断でよい |
| 名前 | 任意 | |
| ID | 任意 | |
| **状態** | 任意 | 自由入力。主題部の自分の状態と**同じ欄**（例：「GM だがラッシュが的確」）。Tier だけでは落ちる情報が入る |

- **行＝比較軸。3グループ構成**：

| グループ | 行の追加 | 行の性格 |
|---|---|---|
| **できていることグループ**（既定） | ＋で「できていること1、2、3…」と追加 | スロット（軸名なし） |
| **できていないことグループ**（既定） | ＋で同様に追加 | スロット（軸名なし） |
| **カスタムグループ**（1つだけ） | ＋で**空行**追加＝**軸名をユーザーが命名** | 名前付きの軸（例：対空） |

- **カスタムグループは1つでよい**（複数は作らない＝需要が見えてから）。
- **セル＝各比較軸への評価**（任意・空でよい）。

### 3.3 削除・追加の非対称（確定）

- **グループ単位でまとめて削除可能。削除時は警告**（既に書いた評価を全列分まとめて失う＝破壊的）。
- **行追加に警告は出さない**（可逆）。
- → 「破壊的操作のみ確認」の原則どおり。確認を均等に撒かない。

---

## 4. 3つの気づき（フォームが分析装置である理由）

機械は分析しない。**並びを人が見た瞬間に浮かぶ**。

| 気づき | 読み方 | 意味 |
|---|---|---|
| 同格以下が**できている**のに自分がしてない | できていることグループ × 同格/格下の列 | **やらないといけない** |
| 格上が**できていない**のに自分がやってる | できていないことグループ × 格上の列 | **努力の方向性の誤り**。認知負荷を無駄に増やしてないか？　正しいことなら**格上以上の面として自信**につながる |
| 格下ができず自分はできる | できていないことグループ × 格下の列 | **データ化で自信**につながる |

- **既定2グループ＝「グループ × 列の Tier」で読む**（行は独立したスロットでよく、行の同一性は問わない）。
- **カスタムグループ＝行を横に読む**（名前付き軸なので、列をまたいで直接比較できる）。
- → **a（既定の相対2軸）＋ b（自分で立てる軸）** が両立する構造。

---

## 5. N件目標（強制ではない）

- **N件はユーザー自身が設定する目標**。開発者による強制ではない（「N件違いを見つけるぞ」「各 tier ごとに N 人と比較するぞ」という自分で決めた挑戦）。
- **未達は警告どまり**。罰さない。目標はデータセットを貯めるためでなく、**「観察という practice をやる」ための規律**なので、記録が揮発的でも矛盾しない。
- **比較対象とする Tier もユーザーが選ぶ**（プロだけでもよいし、プロから格下まで全相対位置でもよい）。
- **本当に見当たらなければ「なし」と書いて登録できる**。
  - → **「なし」自体がデータ**。「格下から学ぶことがなかった」が続けば、**見る目が足りないのか、その tier を本当に卒業したのか**の signal になる。捨てずに記録する価値がある。

---

## 6. 揮発性の扱い（確定）

- **残すが、再浮上させない**。
  - メモは意図的に古い投稿を浮かせるが、比較記録は**逆**。自分も相手も変わっている以上、古い比較を掘り返してもノイズ。**同じアプリの中で、メモ＝再浮上する／比較＝再浮上しない**という正反対の扱いになる。取り違えないこと。
- **集計・可視化も乗せない**（脳内メーカーの対象外）。揮発的なものを積分しても意味が出ない。
- **ただし「当時の自分の状態」欄（§3.1）が文脈を保存する**ため、記録の腐り方は緩やかになる。「マスター帯で対空が安定し始めた頃の自分から見た格上」として後から読める。

---

## 7. メモ機能との関係（出口）

- **比較＝その場の観察セッション（揮発）→ 気づきをメモへ（永続・発展・収束）。**
- **durable な価値はメモへ流す**。比較で見つけた気づき（「これをやらないといけない」）は、**メモに起票して初めて永続する**。
- **ヒントを見つけたらメモを即起動できる導線**を用意する。これは単なる利便でなく、**本機能の出口そのもの**。
- 器は分けたまま、**流れは一方向**（比較 → メモ）。重複せず、両方が活きる。

---

## 8. プライバシー・エクスポート（確定）

- **リプレイは公開情報**。SF6 ではインゲームで誰でも他人のリプレイを観られ、フォローして特定個人を追うこともできる（＝ゲームの仕様）。**観察・記録そのものに問題はない**。
- **問題となるのはインターネットへの公開**のみ。
- **エクスポート時に比較対象の名前と ID をマスクできる**ようにする。**デフォルト ON、OFF も可能**（プロ等の公人に近い人や友達との比較は名前を出しても問題になりにくい）。
- **マスク OFF で SNS 等に投稿してのトラブルはユーザー責任**（対戦動画で相手名をマスクせず公開してトラブルになっても動画ソフトに責任がないのと同じ）。
- **実装の含意**：**保存はマスクせず生で、マスクは出口（エクスポート/共有）でかける**。
- 既存方針（`combmgr-battlelog-source-decision.md`：相手 ID＝第三者データはローカル限定）と整合。

---

## 9. 渡す前に詰める点（要設計）

1. **ラベルの曖昧さを回避する（重要）**。自分を列から外したため、「**できていること**」は**誰ができていることか**が宙に浮く（文脈上は「相手が自分よりできていること」）。**友人 FB で出た「ゲージが始動か消費か分からない」「技/非技ステップが分かりにくい」と同じクラスの問題**。グループ名は誰視点かが一目で分かる表記にする。
2. **マトリクスの表示**：列＝比較対象を横に並べる必要がある（気づきは列の Tier で読むため）。比較対象は数人なので現実的に収まる見込みだが、**スマホ表示（LAN 経由）は別の畳み方**が要る。
3. **既定グループの行スロットの扱い**：行追加はグループ全体（全列）に効くか、列ごとに可変長か。疎行列になってよいか。
4. **Tier の選択肢**：1 tier 上／同格／1 tier 下／プロ、を固定にするか、ユーザーが増やせるか。
5. **セッションの一覧・参照**：残すが再浮上しない（§6）ので、過去セッションをどう並べて見るか。

---

*以上。中核は「集計しない・型にはめない・揮発的」「フォームの構造が分析装置」「出口はメモ」「マスクは出口でかける」。*
