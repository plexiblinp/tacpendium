### 仕様

- **目的**：FR401 エクスポート CSV を取り込み、コンボを復元する（エクスポートの**相方**）。
- **往復（ラウンドトリップ）が成立条件**：`import(export(combos))` が**値として元のコンボに戻る**こと（正規化による差は許容、下記「契約の必達ポイント」）。列レイアウト・型・JSON セルは `reference/combomgr-csv-column-contract.md` に厳密一致させる（独自解釈で列を増減させない）。意味・型の背景は des-003、検証は des-006、表記は des-004。
- **入力**：CSV 文字列／ファイル（UTF-8・ヘッダ行・RFC 4180 エスケープ＝エクスポートと対）。
- **出力（DB に書かない）**：構造化した**取り込み結果** = 復元済みコンボDTO のリスト ＋ **行ごとの OK/NG/警告**（プレビュー的）。確定（DB 反映）は後で本体が行う前提。FR704 の「プレビュー → コミット」と同じ発想で、**本モジュールはプレビューまで**。
- **マッピング**：ヘッダ名ベースで列 → コンボDTO に対応づけ。**列順非依存**、未知列は無視（警告）、不足列・不正行は**落とさず行エラーとして報告**。
- **検証（書き込み前提＝セキュリティ重要・NFR103）**：型・必須・enum・数値範囲、サイズ上限・行数上限、壊れた/巨大/不正な入力を**安全に拒否**し、**行ごとに明確なエラー理由**を返す。検証規則は `reference/des-006-validation.md` を基準にしつつ、インジェクション的な値を素通ししない。**防御的に実装し、検証規則は設定/定数として切り出す**（規則の妥当性は人がレビュー・調整するため）。
- まずは動くものを。

### 契約の必達ポイント（特に取りこぼしやすい点）

- **21列・ヘッダ名でマッピング**（列順非依存）。21列が全て存在必須（欠け＝`missing required column` エラー）、余分列は無視、**重複ヘッダはエラー**。先頭 **UTF-8 BOM は許容して strip**。RFC 4180 / UTF-8 / 改行 `\n` / 値内 `"` は二重化。
- **厳密な型パース**：整数は `strconv.Itoa` 正準形のみ（`+5`／`007`／前後空白はエラー）。bool は `true`/`false`/空(=false)のみ（`TRUE`/`1`/`yes` 非対応）。
- **NULL と 0 を区別**：空セル＝NULL（`*int` は nil）、`"0"`＝値0。`situation` は 空セル＝DB NULL、セル値 `null`＝JSON の null（取り違えない）。
- **セル内 JSON**：`recipe`（`{move_code, modifiers}` の配列。非技ステップは `move_code:""`＋`modifiers.type` で識別。modifiers は常に存在＝空でも `{}`）、`tags`（`name` 必須、`category`/`color` は omitempty）、`situation`（**verbatim**）。
- **往復の正規化（バグではない）**：recipe/tags は unmarshal→再marshal でキー順・空白が正規化される（値は一致）。situation のみ verbatim。空スライス↔nil は nil に正規化。クォート値内の CRLF は LF に正規化（値内 CRLF は byte 完全往復しない）。
- **検証の分担**：型・必須・業務検証（des-006 の VAL-I04/I05 等）は **import 側で必ず掛ける**。一方、空レシピ(0ステップ)の本登録拒否（VAL-C09）等は**コミット時に本体が掛ける**＝import は通してよい（本モジュールはプレビューまで）。
- **スコープ外（往復に含めない）**：連携セットプレイ（combo_setups/setups/setup_steps）、整数ID（code 値で参照）、DB 管理列（id/version/created_at/updated_at/deleted_at）、キャッシュ列（step_count/recipe_cache）。

### テスト要件（決定的に検証）

- **往復一致（最重要）**：FR401 エクスポート出力（契約の出力例 1 行を含む）を取り込み、**値として元のコンボに戻る**（recipe/tags は正規化後一致・situation は verbatim 一致）。
- **厳密パースの拒否**：整数 `+5`／`007`／空白付き、bool `TRUE`／`1`／`yes` が**エラーになる**。
- **NULL と 0 の区別**：空セル→nil、`"0"`→0 が別物として復元。situation の 空セル と `null` を取り違えない。
- **ヘッダ規則**：21列の不足→`missing required column`、重複ヘッダ→エラー、余分列→無視、先頭 BOM→strip。
- 不正・エッジ入力（壊れた CSV／引用符・改行・カンマを含む値／巨大入力／行数超過）で**安全に落ちず行エラーを返す**。
- 検証拒否ケース（型違反・enum 外・範囲外）が正しく弾かれる。
- マッピング正当性（ヘッダ名 → DTO）の確認。
