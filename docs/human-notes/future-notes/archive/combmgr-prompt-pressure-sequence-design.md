# 設計担当向けプロンプト — 連携技（固め連携 / pressure sequence）の物理データモデル設計

> **セット使用**: 別紙『連携技 論理データモデル草案』(`combmgr-pressure-sequence-datamodel-draft.md`) と一緒に渡す。本プロンプト＝物理設計の依頼、別紙＝合意済みの論理骨子。
> **重要（データの根）**: これは本体スキーマへのテーブル追加＋マイグレーション。設計の根なので、**提案までで止め、私（オーケストレーター）の承認まで実装・マイグレーションに入らない**。

## プロンプト本文（ここから投入）

別紙『連携技 論理データモデル草案』と、本体のデータモデル（DES-003）・表記仕様（DES-004）・検証（DES-006）・規約（combomgr-conventions-and-lisence）を読んで。

「**固め連携（pressure sequence）**」を本体に追加するための**物理データモデルを設計**してほしい。論理骨子は別紙で合意済み。あなたの仕事は、それを **DES-003 の規約に沿った正式なスキーマ＋マイグレーション＋検証**に落とすこと。

**まず §1 として設計案を提案して。合意できるまで実装・マイグレーションには入らないで**（データの根なので承認ゲートを置く）。ドメインや既存スキーマとの整合で不明点があれば質問して。別紙の骨子を逸脱する追加・削除はせず、必要なら提案として明示して。

### 設計の前提（別紙より・逸脱しない）

- 連携は**コンボとは別テーブル**（pressure_sequence ＋ pressure_sequence_step）。ただし **step／modifiers／move の code 参照／tag／命名規約はコンボと同型に揃える**（将来マージのため）。
- ツリー表示は **starter_move_code を親キー**に、同一始動から複数連携を枝として描く。

### 物理設計で確定してほしい論点（別紙 §4）

- 各フィールドの**型・制約**。特に **`drive_gauge_drain` は小数・範囲 -6.0〜6.0**（**最新仕様**。DES-003 の「ドライブダメージは正数」より**こちらを優先**。符号・小数型・範囲チェックを確定）。パリィなし前提・連携合計のみ（step 単位は持たない）。
- `starter_move_code` / `move_code` の **moves への参照方式**（CSV 契約と同じく **code 参照**方針。整数 ID 直参照にしない）。
- **modifiers の格納形式**（コンボの recipe `modifiers`＝flags/notes/type と**同じ JSON 構造を共有**するか）。
- **非技ステップ**の扱い（コンボの `move_code:""` ＋ `modifiers.type` 方式を踏襲するか）。
- **weakness フラグ5種**（連ガ／無敵=ジャスパ割り込み／インパクト割り込み／4F割り込み／確定反撃）を**個別カラムにするか、ビットフラグ／サブテーブルにするか**＋ `weakness_note`（自由入力）。
- **whiff_or_counter**（空振り得るステップ）の持ち方。
- **tags** をコンボのタグ機構と**共有するか専用にするか**。
- **index**（`(character_code, starter_move_code)` でのツリー取得を想定）。
- **DES-006 系の検証**（必須・範囲・ステップ0件の扱い 等。VAL 番号の採番含む）。

### マージを見据えた成果物（別紙 §5）

- スキーマは、**コンボと共有する概念**（step／modifiers／code 参照／tag／命名・規約）と、**連携固有の概念**（starter_move_code／drive_gauge_drain／weakness_*／whiff_or_counter）を**明示的に区別**して設計する。
- 将来コンボと統合する際の手順が書けるよう、**この共有／固有の区分と、マージ時の判断材料を残す**（共有部分は寄せ、固有部分は専用列で残すか概念拡張するか）。

### 提案（§1）に含めてほしいもの

1. テーブル定義（カラム・型・制約・default・FK・UNIQUE）。
2. マイグレーション方針（既存データへの影響・ロールバック）。
3. DES-006 形式の検証ルール（番号・内容）。
4. index 設計。
5. マージ容易性メモ（共有／固有の区分表＋将来統合の判断材料）。
6. 別紙の骨子からの差分・判断が必要な点（あれば理由つきで）。

提案がまとまったら**いったん止めて**、私のレビュー・承認を待って。承認後に実装・マイグレーションへ進む。
