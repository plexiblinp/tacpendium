## プロンプト本文（ここから投入）

CLAUDE.md と docs/(01-tech-stack.md / 03-data-model.md / requirements.md) を読んで。

このリポジトリで「コンボの CSV エクスポート（FR401）」と「クリップボードへのテキストコピー（FR404）」の**内部ロジック**を作る。コンボのデータを受け取りテキスト（CSV / TSV）を生成するモジュールで、**本体アプリのソースは参照しない／実画面のボタンには組み込まない**（後で本体が呼び出す）。

まず私が仕様を説明する。理解のうえ §1 の計画（公開API・入力データ型・列契約・CLI/デモ・モジュール境界・スタック・**作る範囲の提案**）を簡潔に提案して。合意／プランでのスコープ提案まで実装に入らないで。不明点は質問して。

### 全体像（2つの出力は役割が違う）

- **CSV エクスポート（FR401）＝アプリ同士のデータ共有**。インポート（FR405）と**セット**で、書き出した CSV を**読み戻すとコンボが復元できる（往復＝ラウンドトリップ必須）**。→ **機械可読が最優先**。
- **クリップボード（FR404）＝アプリ外（Excel／スプレッドシート）で見やすく扱う**。読み戻しは不要。→ **貼って崩れない表示が最優先**。

この2つは**別物として別々に最適化**する（同じ列設計を無理に共有しない）。

### FR401: CSV エクスポート（往復必須）

- **ラウンドトリップ必須**：エクスポートとインポート（FR405）が**同じ列契約**を共有し、export → import で**元のコンボに復元できる**こと。
- **列は機械可読を最優先**：始動技・レシピ/手順・ダメージ・補正・タグ・セットプレイ等、**復元に必要な情報がすべて機械可読な形で入る**。人の見やすさは二の次。
- **区切りは CSV（RFC 4180 準拠）**：引用符による値内カンマ・改行・引用符のエスケープを標準どおりに。UTF-8・ヘッダ行あり。往復の堅さが命なので枯れた CSV を使う。
- **入力**：コンボDTO（03-data-model のコンボ関連カラムから定義）。母集合は**コンボ一覧 または マイコンボ**、渡され方は**単一／全件／特定フィルタ**のいずれか（比較は対象外）。**どれを渡すかは呼び出し側責務**＝モジュールは集合非依存。
- **列契約の所在**：FR405（インポート）側の列契約が未確定なら、**本担当が「往復用 CSV 列契約」を先に定義し、それを正とする**（後でインポート担当が従う）。契約は設定／定数として切り出す。

### FR404: クリップボード（TSV・閲覧用）

- **形式は TSV（タブ区切り）**：Excel・Google スプレッドシートに**そのまま貼ると崩れず列に分かれる**こと。
- 値内の**タブ・改行のエスケープ**に注意（崩れ防止）。ヘッダ行あり。
- これは**閲覧／共有用**なので、CSV（往復用）とは**別の列セットでよい**（人が読みやすい並び・表記）。
- 出力はクリップボードに置く**整形済みテキストを返す関数**を本モジュールが持つ（クリップボード書き込み API 自体は後で本体が叩く前提でよい）。

### 公開API / デモ

- 公開API（例：`exportCombosToCsv(combos, options): string` / `toClipboardTsv(combos, options): string`）。
- 単体で動かせる **CLI かデモ**（サンプルコンボ → CSV / TSV）。
- **実画面・本体UIには組み込まない**。

### テスト要件（決定的に検証）

- **往復一致（最重要）**：export(CSV) → import で**元のコンボに戻る**（検証用にパーサを本モジュールへ最小実装してよい）。
- CSV エスケープのエッジケース（カンマ／引用符／改行／Unicode／空値）。
- TSV がタブ・改行を含む値で崩れない（再分割で列が一致）。
- 既知フィクスチャでの出力一致。

### コーディング方針

- プロトだが流用前提。未実装・簡略化・暫定は**理由つき TODO コメント**。
- 列契約・エスケープ規則は設定／定数に切り出し、後から差し替えやすく。
- **CSV（往復）と TSV（閲覧）の列定義を分離**（混ぜない）。
