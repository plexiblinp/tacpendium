### 仕様

- **共通構造**：**描画コア（1つ）＋ 出力アダプタ（PNG / PDF の2つ）**。「コンボを視覚要素に描く」を一度だけ作り、各形式は薄いアダプタにする。
- **本体ソースを参照できないため、描画は2系統を用意**：
  1. **汎用エクスポートコア**：外部から渡された **DOM ノード／HTML を PNG/PDF に変換**する。→ 後で本体が自前の描画済みノードを渡せる（**見た目の最終一致は組み込み時に取る**）。
  2. **自前のデモ描画**：コンボDTO から簡易な視覚レイアウトを生成（単体テスト・確認用）。本体の見た目との完全一致は目的にしない。
- **入力**：コンボDTO（03-data-model のコンボ関連カラムから定義）。出力単位は**単一コンボ**（比較は対象外）。
- **各形式**：
  - **PNG**：ノード → ラスタライズ → PNG。
  - **PDF**：ノード → PDF（依存ライブラリは §1 で提案。重い依存は避ける方向）。
- まずは動くものを。

### 公開API / デモ

- 公開API（例：`toPng(nodeOrCombo, options)` / `toPdf(...)`）。
- 単体で動かせる**デモページ**（サンプルコンボ → 各形式）。
- **実画面・本体UIには組み込まない**。

### テスト要件

- **自動検証しやすい所**：出力が妥当な PNG/PDF バイト列か・寸法・非空、データ→レイアウトの対応。
- **見た目の正しさは自動テストしにくい**ため、デモでの**目視確認を前提**にする（ここだけは人の確認が要る、と明示）。
