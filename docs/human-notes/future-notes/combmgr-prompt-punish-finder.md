# 自律開発プロンプト — 確定反撃の算出機能

> セットプレイ提案ソルバと同じ「フレーム数値の純計算モジュール」。独立リポジトリで蒸留版ドキュメントのみ参照して作らせる用。以下をそのまま投入する。

---

CLAUDE.md と docs/(01-tech-stack.md / 03-data-model.md / requirements.md)を読んで。

これからこのリポジトリで「確定反撃の算出機能」を作る。

まず私が仕様を説明するので、理解したうえで §1 の計画(公開 API・CLI・データモデル整合・モジュール境界・スタック)を簡潔に提案して。合意できるまで実装には入らないで。
またストリートファイターや格闘ゲームの知識であなたに不足があれば質問して。

では仕様を説明する:
ストリートファイターでは、相手の技をガードした（または空振りに対応した）とき、その技の硬直差（ガード時の不利フレーム）に応じて、こちらが「確定で反撃できる」技が決まる。たとえば相手の技がガード時 -5 なら、こちらには 5 フレームの猶予があり、発生がその猶予以内に間に合う技は確定で当たる。これを確定反撃（確反）とする。

このツールは、反撃の猶予フレーム（相手技のガード時不利フレーム）と、こちらの技リスト（技名・発生フレーム・あればダメージ）を受け取り、猶予内に発生が間に合う技を 0〜複数返すことが求められる。ダメージがあれば、確定する技の中でリターンの大きいものがわかるよう並べ替えて返す。

これは単純に「単一のしきい値（猶予フレーム）に対する絞り込み＋並べ替えの問題」に言い換えられる。

算出アルゴリズムは後から改善しようはいくらでもあるので、まずは動くものを作る。

私のイメージは以下だが、シニアエンジニアとしてすでに改善ポイントがあれば直してよい。

1. 猶予フレーム N と、各技の発生フレームを受け取る
2. 発生フレームが N 以下の技だけを残す
3. （ダメージがあれば）ダメージ降順・発生昇順で並べ替える
4. 該当する技が無ければ空を返す
5. 確定する技の一覧を返す

ここで詰めておきたい論点が1つある。格ゲーの慣習に照らして提案・確認してほしい:
- 「ガード時 -N の技は発生 N 以下の技で確定」という境界（≤ か <、1フレームのオフバイワン）をどう扱うのが正しいか。猶予フレームの定義（こちらが動けるようになるフレームの数え方）も含めて確定させたい。

なお、このツールは渡しているドキュメントのプロジェクト(本体)に組み込む他、需要の高い機能であり、ストリートファイター以外にも使えるようなモジュール（発生フレームと不利フレームという数値だけで成立する汎用ロジック）である必要があります。
