# milestone-startup-kit — 使い方

開発者向けメモ。新マイルストーン着手時に、**親(設計卓)** チャットを
立ち上げるための「最初のプロンプト + 渡す資料の線引き」の完成品を置くフォルダ。

> **★2026-08-11 切替(面の移行)**: **親(設計卓)の面が Claude Web → Claude Code(メインツリー)へ移り、反映係の層は廃止された**(開発者裁定 6 件・正本 `docs/progress/20260811-design-desk-surface-study.md` §9)。Web 版は親をやめ、`docs/process/parallel-ops.html` §06 の**個別設計チャット**へ配置換え。
>
> **したがって下記 2026-07-30 の「ナレッジ常設」は親向けとしては失効した。** Code 版にはプロジェクトナレッジも Sync now も存在せず、親は repo の `docs/` を直接 Read/Edit する。**キット §1 の線引きは「ナレッジに任せる/任せない」ではなく「起動時に必ず読む/必要時に引く」になり、理由も「検索は取りこぼす」から「読ませすぎを防ぐ」へ入れ替わった**(`next_milestone_kit` 変換規則 19)。
>
> **★ただし「repo が見える」と「実装が見える」は別**——親は `scripts/design-desk-arm.sh` による**武装**(sparse-checkout で実装ソースを作業ツリーから物理排除)の状態で動く。**キット §2 の先頭に武装コマンドが入る**のはこのため。手順の正本は `docs/human-notes/design-desk-code-migration-guide.html` と `docs/process/remote-ops.md` §6。
>
> **【失効・履歴として残す】2026-07-30 切替**: 恒久資料は Web 版 Projects の GitHub ナレッジに常設したため毎回渡さない、という運用だった。**個別設計チャット(Web 版)には今も当てはまる**が、親には当てはまらない。

## 3. 次マイルストーンでの流用手順

1. `m{N}-startup-kit.md` を `m{N+1}-startup-kit.md` にコピーする
2. 下記 §4 のチェックリストの箇所をすべて書き換える
3. Web チャットにプロンプトを貼り、**§1 Ⅱ の直読パスだけ**を確認させて起動する(恒久資料はナレッジ常設＝渡さない)

## 4. マイルストーンごとに更新が必要な箇所(チェックリスト)

**ここが流用時の最重要。** 古い情報のまま投入すると、設計担当 Claude が誤った前提で動く。

- [ ] **マイルストーン番号**: 「M{N-1} まで完了 → M{N} から引き継ぎ」、スコープ名(M4=セットプレイ系、
      M5=比較系、M6=初期体験系、M7=仕上げ。正確には SUPP-001 §4.1 のマイルストーン分割表)
- [ ] **handover ファイル名**(C グループ): `m{N-1}-to-m{N}-handover.md`
- [ ] **「読む順序」の参照先**: `m{N-1}-to-m{N}-handover.md §0`
- [ ] **持ち越し課題**: 旧 ID(P-01 / L-01 …)を `m{N-1}-to-m{N}-handover.md §4` の最新課題に差し替え
- [ ] **CHANGE 起票・設計書改訂**: 「M{N-1} 期間で CHANGE-0XX を起票、DES-00X を vX.Y.Z に改訂」を
      最新の事実に。`change-number-registry.md` で確認する
- [ ] **progress-summary の対象範囲**: 「M0〜M{N-1}」
- [ ] **直近指示書(任意投入)**: M{N-1} の最後の指示書 + レビューチェックリストのファイル名
- [ ] **ファイルのバージョン注記**(playbook vX.Y.Z、SUPP-001 vX.Y.Z 等)を最新に
- [ ] **「ドキュメント体系について」段落**: M3→M4 のドキュメント整理は一度きりのイベント。M5 以降は
      「恒久情報は B グループの専用ファイルに分離済み」程度の定常的な記述に簡略化(または削除)

## 5. 流用時の注意点

- **`m{N-1}-to-m{N}-handover.md` は前マイルストーンの設計担当が作成する成果物**。これが無いとキットは
  使えない。マイルストーン完了時の handover 作成を忘れないこと(playbook §0.1)。
- **投入ファイル一覧は `milestone-startup-guide.md §2` を基準にする**。継続更新ファイル群が増減したり
  ファイルが移動した場合は、まず guide を直し、キットを追従させる。
- **アーカイブ済み handover は初回投入しない**(任意扱い)。マイルストーンが進むと旧 handover は
  `docs/handover/archive/` へ移る。C グループには **最新の handover 1 本だけ** を置く。
- **過剰投入に注意**(`milestone-startup-guide.md §4`)。設計担当は初回応答で全ファイルを読むため、
  当該マイルストーンに無関係な設計書節まで渡すと context を浪費する。設計書本体は必要に応じて
  「該当節のみ抜粋投入」でもよい。
- **個別チャットの作業メモは残さない**。本フォルダはコミット対象だが、置くのは再利用する
  `m{N}-startup-kit.md` と本 README のみ。1 回限りのメモはコミットしない。
