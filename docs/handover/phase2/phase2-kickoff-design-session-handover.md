## 2. 本セッションで確定した重要判断（フェーズ2 全体に影響）

新セッションは以下を **確定済み**として扱う（再協議不要。開発者指示がある場合は別）。

### 2.1 moves スキーマ（CHANGE-022 v0.3.0、DES-003 v1.17.0 §3.3）

- 追加8列: `startup`（発生 NOT NULL）/ `active`（持続フレーム数、範囲 4-6→3、NULL可）/ `total`（全体硬直 NOT NULL、**本体が取込時に発生・持続・硬直から算出**）/ `on_hit` / `on_block`（硬直差、NULL可）/ `drive_gauge_decrease_guard`（NULL可）/ `is_aerial`（空中判定 BOOLEAN DEFAULT false）/ `setup_only`（予約 BOOLEAN DEFAULT false）。
- **recovery（硬直）は moves 非永続**（CSV のみ。total 算出素材）。
- **properties は取込時にコード値へ正規化**（上/H→high 等。DES-003 既定値）。
- **ラッシュ可否は新規列を設けず `category ∈ {normal, unique}` かつ `is_aerial = false` で導出**。ラッシュ版（rush_variant + original_move_id）は CSV 取込スコープ外、FR703 で生成。
- パニッシュカウンター硬直差・キャンセル列は保持しない。

### 2.2 FR704 CSV 契約（CHANGE-022 v0.3.0、DES-002 §7.5）

- **name_ja → official_ja_move のみ**。**name_en は CSV 非出力**（英語版はツールが属性正規化・検証に内部利用、英語ロケールはフェーズ3以降）。
- 日英行対応マージ、UTF-8、`move_code` / `character_code` はツールが決定論採番、total 非出力（recovery を出力し本体が算出）。

### 2.3 技名正規化・取込スコープ（CHANGE-023 v0.2.0、DES-004 §3.2 / DES-002 §7.5）

- **技名正規化**: (a) キャラ固有フレーバー `（…）` / `: …` を除去、(b) 共通技の汎用名化。
- **通常投げ**: 取り込み、official_ja_move を**出現順で自動採番**（1件目=前投げ / 2件目=後ろ投げ、キャラ別データ保持、例外は FR703）。英語汎用名 Forward Throw / Back Throw。
- **取込対象**: 通常技 / 特殊技 / 必殺技 / SA / 通常投げ / ドライブインパクト（/ ターゲットコンボ）。
- **取込対象外**: 前方・後方ステップ・パリィ・キャンセルドライブラッシュ（modifiers.type）/ ドライブパリィ・ジャストパリィ（非攻撃）/ **ドライブリバーサル**（攻撃だがコンボ部品でない）。
- **is_aerial**: 取込時に公式名「ジャンプ／（ジャンプ中に）」を含む技を true、接頭辞なしの空中技は FR703 で手動 true 化。

### 2.4 議題で確定した開発者判断

- 議題1: official_ja_move のみ取込（name_en 非取込）。英語ロケールはフェーズ3以降。
- 議題2: 非攻撃の共通システムは moves 不要（ダメージ=0 はすべて modifiers.type か非モデル化）。DI のみ moves 化、DR は取込対象外。
- 議題3: 通常投げは取り込み位置で前投げ/後ろ投げ自動採番（A 案。固定値化＝B 案は不採用、キャラ別データを失わないため）。

### 2.5 フェーズ2 マイルストーン構成（phase2-overview v0.1.0）

- M8 moves フレームデータ基盤（ゲート、CHANGE-022/023 反映済み、M8-01 製造が次） / M9 公式データ取込パイプライン（M9-RESEARCH / M9-01 別チャット委任 / M9-02 FR704 / M9-03 FR703） / M10 複数キャラ登録 UI（A-1/A-2） / M11 custom_states 開始時状態（boolean 中心、消費はコンボ notes 管理・モデル化しない） / M12 先行リリース仕上げ（M12-01 UX #62/#63 / M12-02 耐久 seed 無効化マイグレ / M12-03 統合 E2E + 配布判定）。
- handover §3 の旧 7 段目安（M8〜M14）を 5 大MS に統合（M13/M14 → M12）。

### 2.6 開発者方針の継承

- 英語ロケール整備はフェーズ3以降。
- custom_states の消費はモデル化せず、フェーズ2 は開始時状態（boolean）の付与のみ。
- マイルストーン番号は M8 以降の連番（フェーズ番号と別軸）。
- setup_only はセットプレイ自動提案機能の予約列（YAGNI 適用外＝確実追加機能、トレーサビリティは列注記 + 開発者記憶、REQ-001 改訂なし）。

## 3. M8-01 製造指示書作成方針（新セッション最優先タスク）

### 3.1 スコープ

- moves テーブルへ 8 列を追加するマイグレーション（SQLite `ALTER TABLE ADD COLUMN`）。
- model / DTO へ 8 フィールド追加、`GET /api/characters/{id}/moves` レスポンスへ反映。
- `is_aerial` / `setup_only` は DEFAULT false で既存行補完。`startup` / `total` は NOT NULL。

### 3.2 §着手前確認の必須項目

1. **`total` 算出式の確定（開発者定義）**: 発生・持続・硬直から全体硬直 `total` をどう算出するか。格闘ゲーム仕様前提＝開発者領域。指示書化の前に確認。
2. **既存 seed の移行戦略**: フェーズ1 seed 行はフレーム列を持たない。`startup` / `total` が NOT NULL のため、(i) 一時デフォルト → backfill、(ii) NULL 許容 → backfill → 制約強化、(iii) seed 再生成、のいずれかを製造担当が選択。
3. **耐久 seed（migration 000012）との順序**: 耐久 seed 36 件の除去は **M12-02**（無効化マイグレ）。M8-01 のスキーマ移行と M12 の seed 除去・M9 のリュウ実データ再取込の順序に留意。
4. **既存マイグレーション番号の確認**: 次マイグレーション番号（000012 の次）を view 確認。
5. **既存 moves スキーマ・seed の view 確認**（実コード確認の省略アンチパターン警戒）。

- DES-003 v1.17.0 §3.3（moves スキーマ・列定義・注記）・§2 ER図。
- SUPP-001（マイグレーション運用・seed の扱い）。

## 5. 本セッションで適用した運用ルール（新セッション継続用）

- **コンテキスト評価運用**: 限界が近い時 or 重い作業の後だけ自己評価。毎回は省略。本セッションは M8-01 指示書着手前にこの運用で移行判断。
- **禁則表現を使わない**: `あれば／必要に応じて／実装時に決定／任意で／適切に／既に〜していれば不要／あったら／動作するはず／副次効果として／自動的に`（設計担当作成文書）。grep セルフチェックを各成果物で実施。
- **CHANGE 二層運用**: 設計書本体（REQ-001 / DES-001〜006）改訂は CHANGE 通知書必須。補足資料（SUPP-001 / handover / playbook / registry / progress / architecture-patterns / overview）は自由改訂。
- **提案 → 開発者承認 → 反映**。承認前に設計書本体を改訂しない。Git は開発者。
- **格闘ゲーム仕様・プロジェクト現状は開発者領域**（推測で書かず確認）。
- **機械レビュー運用**: 開発者が機械レビューを実施し指摘を返す。指摘は事実確認のうえ amendment（CHANGE-022 は v0.3.0 で 8 件反映）。
- **erratum 運用**: 軽微なラベル誤り等は「次回まとめて訂正」も可（M14→M12 はこの判断、ただし移行に伴い先行訂正）。
