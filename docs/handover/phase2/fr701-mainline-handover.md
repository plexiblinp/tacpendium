## 1. 契約直結(CHANGE 起票・承認が必要。ツール製造のブロッカー)

### 1-1. DES-003 §3.3: startup / total の NOT NULL 見直し(CHANGE-022 の訂正)

- **変更案**: `startup` と `total` を NULL 許容にする(または取込時の既定値方針を定義する)。
- **根拠(実測)**: 取込対象に発生空欄の行が約100件・26キャラ。さらに**発生・硬直とも空欄でダメージありの行が11件**(サガット SA2 派生4、豪鬼 百鬼襲4、キャミィ フーリガン3 ほかベガ サイコマイン自動爆発・ザンギエフ SA2)あり、total の算出(発生・持続・硬直)が成立しない。
- **ツール側依存**: TOOL-002 §8(空値出力)。

### 1-2. DES-002 §7.5「取込対象」節の改訂(CHANGE-023 の訂正)

- **変更案**: 「moves として取り込むのは攻撃技に限る」を撤回し、キャラセグメント(通常技/特殊技/必殺技/SA/通常投げ)は**非攻撃を含め全行取込**、共通システムのみドライブインパクト限定を維持。「共通システム内はダメージ値で判別」の記述を「位置 + 名称(`ドライブインパクト` 前方一致)で判別」へ改訂(ドライブリバーサルはダメージ500>0 のためダメージ判別不能)。
- **根拠**: 開発者決定(2026-06-09: 非攻撃エントリはコンボレシピ・セットプレイに使用するため全取込)+ 実測分布。
- **ツール側依存**: TOOL-002 §7。

### 1-3. DES-002 §7.5: 通常投げ節の拡張(CHANGE-023 の訂正)

- **変更案**: 3件目以降の規定を追加 — 汎用名を付与せず正規化済み公式名を保持し要確認扱い、`（ジャンプ中に）` を前提条件に含む投げは is_aerial=true、code は英語名機械変換。1・2件目の公式名は notes へ `公式名: …` として退避。
- **根拠(実測 + 開発者確認)**: 投げ件数分布 2件=18キャラ / 3件=10 / 4件=ガイル / 6件=ザンギエフ。1=前投げ / 2=後ろ投げは全キャラ成立(開発者確認 2026-06-10)。3件目は空中投げとは限らない(アレックスは地上特殊投げ、ガイルは前後の空中投げ2種)。
- **ツール側依存**: TOOL-002 §9.2。

### 1-4. DES-002 §7.5: ターゲットコンボ文言の実態化

- **変更案**: 「target_combo が公式に存在する場合はそれも含む」を改訂 — 公式 HTML に独立セグメントは存在せず、TC 相当は通常技・特殊技セグメント内の段数付き行(`（N段目）` / 英 `(N)`)として出現する。段ごとに別 move とし(公式粒度、開発者承認 2026-06-09)、所属セグメントの category で取り込み、**target_combo の機械判別は行わない**。
- **ツール側依存**: TOOL-002 §7。

### 1-5. DES-002 §7.5: CSV 拡張列(コマンド・前提条件)の追加

- **変更案**: 契約列の末尾に3列追加 — `command`(コマンドトークン列、ロケール非依存)、`condition_ja` / `condition_en`(先頭前提条件の原文)。トークン語彙とシリアライズは TOOL-002 §9.9 の表を正とする(本体は自前アイコンへの置換に使用)。
- **根拠**: 開発者要望(コマンドでもコンボを記述する将来仕様)+ 実測(アイコン asset 名で入力を完全復元可能、日英でアイコン列が全2,361行一致)。
- **本体側の追加論点**: official_ja_command プリセット(DES-004)・コマンド表記コンボ機能との接続方法、FR704 がこの3列を moves のどこへ反映するか(現スキーマに対応列なし。フェーズ2では取込スキップ/保留も選択肢)。
- **ツール側依存**: TOOL-002 §8 #20〜22 / §9.9。

### 1-6. DES-002 §7.5: on_hit / on_block の `D`(ダウン)等の退避規則の明文化

- **変更案**: 契約に値書式を追記 — `D` は CSV 空欄 + notes `【ツール付記】ヒット時ダウン(D)`、`※N` は N + notes 付記、範囲・複合値は空欄 + notes 原文。notes のツール付記書式(`【ツール付記】` 区切り・`;` 連結)を本体プレビュー・FR703 と共有。
- **根拠(実測)**: `D` が1,012件、`※N` ダメージ35件、範囲値・`ー` 等(調査レポート §8 の全数集計)。
- **ツール側依存**: TOOL-002 §8 / §9.8。確認済み: drive_gauge_decrease_punish は**出力する**(開発者決定 2026-06-09。契約の備考から「出力要否は確認事項」の記述を解消)。

### 1-7. 本体 total 算出仕様(M10)への入力パターン追加

- **変更案**: CSV `recovery` 列は公式原文の文字列で渡る。算出仕様の入力に次のパターンを含める: 整数 / `全体 N` / `着地後N` / `N+着地後M` / `N-着地まで` / `[※2] 1-12` / 空欄。空欄(1-1 の11件)の total 既定方針もここで定義。
- **ツール側依存**: TOOL-002 §8 #7。

## 2. 本体内部の整理(CHANGE または自由改訂。ツール製造はブロックしない)

- **2-1. DES-004 §2.1 / DES-003 §3.3 の code 例示更新**: code 規約を英語表示名の機械変換へ統一(`standing_medium_punch` 形式、強度は接尾辞 `_light/_medium/_heavy/_od`、ピリオド除去連結で `aki` / `c_viper` / `m_bison`、衝突時は英語前提条件サフィックス → `_2` フォールバック)。character_code も同規約(slug は同定専用)。通常投げ1・2件目は `throw_forward` / `throw_back` 固定(CHANGE-023 準拠。**既存 seed の `forward_throw` / `back_throw` とは語順が逆**だが seed 削除前提で問題なし)。`rush_<元技code>` の生成例も追従更新。SA は公式名接頭辞由来で `sa1_`〜`sa3_` に加え **`ca_`(クリティカルアーツ。SA3 と別行で全キャラに存在)** が新出する点を category / FR703 の観点で確認されたい。
- **2-2. 既存 seed クリアの移行影響**: 開発者決定(2026-06-11)により既存 seed(moves 186件・characters)は削除・ツール再生成前提。これを参照する既存 combos / combo_steps / recipe_cache の扱い(クリア or 張り替え)と手順を本体側で確定。CHANGE-022 §5 の backfill 記述も再生成前提で簡略化可能。
- **2-3. SUPP-001 §3.3.2 との境界整理**: `high_jump` 等がツール取込対象になる(ヴァイパーの特殊技セグメント)。seed 手動定義との二重登録回避と、公式 HTML に行が無いジャンプ move(`jump_neutral` 等)は seed 管理継続、という境界の明文化。

## 3. 課題記録(フェーズ4向け。開発者指示により記載)

- **3-1. モダン操作データの取得不安定**: モダン表示で保存する際、**別キャラのデータが描画された状態で保存される事象**が発生した(原因未特定。クライアント側描画のレース疑い)。本格対応(フェーズ4)時に取得手順の安定化(保存前の再読込・表示確認等の運用手順)が必要。なおツール側は本フェーズから slug + タイトル + 言語 + 操作タイプ + 日英クロスチェック(行数・セグメント・アイコン列)で誤データを検出・拒否する(TOOL-002 §4)。参考: モダンの構造自体は同型(6セグメント・15列・`p.frame_modern`)で、差分はアイコン語彙と技数のみ。今回検証した8ファイルは全て正常だった。
