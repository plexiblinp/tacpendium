## 3. 残サブの設計メモ

### 3.1 M12-05(seed 整理) — 新セッション最優先
- **スコープ**: migration 000012 の耐久テスト用 seed 36 件を、無効化マイグレーション(新規 DB 構築時に再投入されない)で除去する。
- **最重要の勘所**: `dbtest.Setup`(全マイグレ適用)への波及確認(retrospective-digest §5 / M9-1 教訓 = 破壊的 seed クリアの test 基盤影響)。マイグレ 000016(テーブル再構築)後の状態とも整合確認。B-7(move_code 連動)に注意。
- **推奨**: Opus / Plan Mode 必須(マイグレ方式は M12-03 同様、開発者が Plan Mode で選択する可能性)。
- **DES 影響**: seed はデータであり DES 本体規定外の見込み(DES-003 §6.1 配布前提と整合確認)。CHANGE 要否は着手前確認で判断。

### 3.2 M12-06(統合 E2E + 配布判定)
- **スコープ**: フェーズ2 全体の統合 E2E + 先行リリース(配布)判定。
- **勘所**: E2E E-1 回帰穴(「多項目のうち 1 項目だけ編集 → 他項目保持」の自動 spec 欠如、M11 C-2 由来)の spec 化。M12-03 の E2E(A〜F)・M12-04 の E2E は完了済み。
- **推奨**: Sonnet 寄り(統合・検証中心)。

### 3.3 §4-4 配線漏れ(修正サブ候補・要 CHANGE)— 開発者の課題再評価対象
- **事象**: 設定の「デフォルト表示キャラ」を変えても一覧/マイコンボ/新規登録/比較に効かない。各画面が `INITIAL_CHARACTER_ID=1`(リュウ、`web/src/lib/constants.ts:17`)固定で `config.defaults.characterId` を参照しない既存配線漏れ。
- **該当**: `ComboListPage.tsx:47,61` / `MyComboPage.tsx:76` / `ComboEditor.tsx:577` / `ComparePage.tsx:88` / `ComboListFilters.tsx:74,86`。消費は初回ウィザード + 設定画面自身のみ。
- **対応案**: 「文脈なし時の既定を `config.defaults.characterId` フォールバックへ」。複数画面の既定挙動変更のため **CHANGE(DES-005 §5 共通要素/§4.3) + 専用サブ**。優先順位整理: **URL/セッション文脈(CHANGE-039) > 設定既定 > リュウ**。
- 開発者が M12 中に見つけた他の課題と合わせて再評価 → M12 内に修正サブを作るか P3 かを協議(§0-4)。

## 4. 本セッション固有の運用ルール

- **出力前チェック必須**: Python による簡体字検査(simp set)+ 禁則表現 grep(「あれば/必要に応じて/動作するはず」等 → playbook §4.2 言い換え)を毎回実施。
- **確認事項は成果物末尾に集約**(番号付き・何を/なぜ/暫定案)。
- 設計担当は DES 本体を CHANGE 経由で改訂、製造担当は DES を直接編集しない。git/commit/push は開発者専任。
- VAL 番号採番は設計担当が確定(M12-03 で VAL-S06/VAL-C13 を DES-006 の S05/C12 最大の次番として検証済)。
- retrospective-log はトークン重く起動時未投入が基本(必要時に開発者が投入)。教訓は M12 完了時に確定転記(§1.3)。
- コンテキスト評価は限界が近い/重い作業の後に自己観察(m7 §8.1 同様)。
