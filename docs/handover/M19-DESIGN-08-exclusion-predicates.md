## 1. P-16 —「空振りで出せない技」の除外

### 1.1 何が決まっていて、何が決まっていなかったか

**決まっていた**（再確認しない）:

- **「除外する」という結論** — `M19-DESIGN-07` §9-2（ヒット／ガード時限定でしか派生できないチェーンコンボ・ターゲットコンボは対象外）。
- **判別軸** — **`is_derived`**。一次源は `docs/seed-data/target-combo-and-derived-flag-rules.md`（2026-07-09・開発者確認済み）。**パターン 1／2（前段のヒットまたはガードが必要）を `true`、パターン 3（空振りでも出る）を `false`** として持つ。RESEARCH-03 が実データで追認（`category=target_combo` 67 行中 **63 / 4**）。
- **恒久依存にしない** — §9-4。`is_derived` は 3 義を兼ねる（前段/状態を経ないと出せない／コマンド衝突で単独解決不能／必殺技の分岐が一意解決できない）。

**決まっていなかった**: **述語の書き方**。

### 1.2 ★述語の候補は 2 つあり、影響範囲が桁で違う

| 案 | 述語（除外条件） | 現行からの差 |
|---|---|---|
| 現行 | `category = 'target_combo'` | — （**67 行を除外**） |
| **案 α**（前任の定式化） | **`is_derived = 1`** | **除外が ~250 行へ増える**（`is_derived=1` の全体）。**うち target_combo は 63 行、残り ~187 行は現在 filler 候補に入っている行** |
| **案 β**（本書の推奨） | **`category = 'target_combo' AND is_derived = 1`** | **除外が 67 → 63 行へ減る**。**差分は +4 行のみ**（パターン 3 の 4 行が候補に入る） |

**★案 α は「`category` を `is_derived` へ置き換える」という言い方から自然に出てくるが、実際には ~187 行を新たに除外する。** その 187 行は **`is_derived` の (b)(c) の意味**（コマンド衝突で単独解決不能／必殺技の分岐が一意解決できない）で `true` になっている行であり、**「空振りで出せない」とは限らない**。

**⇒ 案 β を採る。** **メモが述べたことをそのまま実装し、それ以上をしない。**

> **★案 α が誤りだと言っているのではない。** 187 行のうち何行が実際に「空振りで出せない」かは**測っていない**。**測らずに 187 行を落とすのは、M19-02 で除去した「入力できないレシピ」の逆側の欠陥——「出せるはずの解が出ない」——を新たに作る。** **必要なら M19-05 の Plan Mode で件数と内訳を実測し、別途判断する。**

## 2. P-18 —「相手が空中にいるときだけ出せる」技

### 2.1 決着 — **軸を持たない**

`ingrid/satelite_leap` 型（相手の状態が前提）は、**3 類型メモの射程外**である（メモが軸にしているのは「一つ前の段の成立条件」であって「相手の状態」ではない）。**followup `M19-air-only-exclusion` が扱っているのも別の型**（**自分が**空中から出すが地上相手に最速で届かない技）。

**現状では `category='target_combo' AND is_derived=1` によって結果的に除外される。** **しかしそれは偶然である**——`is_derived` が**別の理由**（コマンド解決不能）で `true` になっているだけで、**「相手が空中限定」という性質はどこにも記録されていない**。

**⇒ M19 では軸を持たない。** 理由は 3 つ:

1. **実害が現時点で無い**（該当行は偶然除外されている）。
2. **母数が分からない**——`target_combo` 外に同型が何行あるかを測っていない。**測らずに列を足すのは、DESIGN-07 §7 が禁じている「用途が 1 つしか無い列」の典型になる。**
3. **`condition_ja` は使えない**（CSV に列はあるが SQL 非投入・`moves` の DB 列でもない・当該技では CSV 上も空欄＝ボード D-152）。**現時点で書き込める場所が無い。**

### 2.2 代わりにやること — **否定形の記録を残す**

**`M19-overview` §8（否定形の記録）へ 1 行追加する**（本書の発行と同時に別パッチで出す）:

> **「相手が空中限定」の軸は M19 では持たない。** `ingrid/satelite_leap` 型は現状 `category='target_combo' AND is_derived=1` で**偶然**除外されるだけで、性質そのものはどこにも記録されていない。**`target_combo` 外に同型が現れたら捕捉できない。** followup `M19-air-only-exclusion` は**別の型**（自分が空中から出す技）を扱っており、本件を含まない。

**followup を 1 件起票する**: `opponent-state-prerequisite-moves`。**「相手の状態が前提の技を、どのデータで持つか」**。M20 以降。

> **★「持たない」も決着である。** 未決のまま残すと、後続サブが「まだ決まっていない」と読んで独自に決め直す（digest M16-C1）。**「持たないと決めた」と書く。**

## 4. 3 件をまとめて 1 つのサブで扱う理由

**前任の親チャットが「同じサブで扱うほうが安い」と申し送った**（2026-08-02）。**同意する。ただし理由は「述語が同じだから」ではない。**

| 保留 | 触る場所 | 述語 |
|---|---|---|
| P-16 | `internal/service/setplay/` の filler 候補規則 | `NOT (category='target_combo' AND is_derived=1)` |
| P-18 | **どこも触らない**（記録のみ） | — |
| TP-01 | `internal/service/punishfinder/` の相手技候補 | `standalone または unknown ∧ 親参照あり` |

**述語は別である。触る場所も別である。** **同じサブにする理由は、3 件とも「既存列がたまたま除外の役を兼ねている」という同じ構造から出ており、片方だけ直すともう片方の前提が変わるからである。**

具体的には——**P-16 の緩和（4 行を候補に入れる）と TP-01 の除外（3 行を候補から外す）は、どちらも「候補集合の件数」を動かす。** **別々のサブでやると、canary の判定値が 2 回動き、2 回目の変更が 1 回目の影響と混ざって切り分けられなくなる。**

**⇒ M19-05 の中で、候補集合を動かす変更をすべて 1 回にまとめ、増分の内訳を行単位で報告させる。**
