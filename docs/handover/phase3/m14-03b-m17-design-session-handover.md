### 2.3 派生技フラグ `is_derived`（**本期の最重要判断**・再発明禁止）

- **役割はただ一つ＝段階2 のコマンド入力解決の索引から除外する**。判定原理は「**通常版とコマンドが同一で索引衝突を起こす技**」を外す。
- **判定の合言葉**: 「コントローラでこの技だけをいきなり出せるか？」**出せない → true**。
- **確定マッピング**:

| 対象 | is_derived | 理由 |
|------|-----------|------|
| 前段の技で特殊状態になってからの追加入力 | **true** | 単独で出せない |
| ターゲットコンボ 2 段目以降（パターン1・2） | **true** | 前段依存 |
| **TC パターン3（空振りでも出る・ザンギ中P中P中P型）** | **false** | 入力すれば前段の成否に関係なく出る＝単独技に近い・**空振りフレーム重視** |
| 必殺技の派生（弱→弱中強など複雑分岐） | **true** | 決定論解決に乗らない・必殺技は段階2 スコープ外 |
| 焔版など強化版（特定状態でのみ出る） | **true** | 状態依存 |
| **ジャスト版**（入力タイミング精度違い） | **true** | **command 文字列が通常版と完全同一＝索引衝突** |
| **ホールド版・溜め版** | **false** | `hold` / `charge_*` トークンで **command が通常版と異なる**＝衝突しない。かつ段階2 スコープ外トークンで自動除外 |
| TC 1 段目・通常の必殺技/特殊技・空中特殊技 | **false** | 単独で出せる |

- **判定源＝入力ツール側で人間が判断**（本体は CSV 値を信頼＝導出しない。CHANGE-065 と同型）。
- **priority 案は却下**（開発者の対案が優れていた＝教訓 D-6）。汎用の priority 列を索引専用に消費しない。
- **恒久配置（moves 本体 bool 列 or 索引テーブル側フィルタ）は M17-02 の G-k で決定**（未決・§3.3）。M14-03b は CSV 保全＋seedgen 時フィルタで閉じた（moves スキーマ不変・CHANGE 不要）。
- **アップデート追従の運用手順は FR702 によりフェーズ4 送り**（M17 は仕組み導入まで）。

### 3.5.1 【要認識共有】`character_data/mai.csv` は製造が 1 行是正している

- M14-03b の seedgen dup スキャンが **mai の SA3/CA の `name_ja` 完全一致**（「不知火流・炎舞仇桜」）を検出して生成 fail。他 8 キャラは CA に `CA ` 接頭辞で区別しているため、**開発者承認のうえ製造が `character_data/mai.csv` の ca 行 `name_ja` を「CA 不知火流・炎舞仇桜」へ是正**した（製造申し送り §3.3）。

### 3.6 【記録】c_viper / dhalsim の将来 seed 時のリスクと推奨解

- **構造**: 「**`characters` に既存だが `moves` 未 seed**」のキャラは、**友人が画面18 で自作 moves を作れる**。将来その手入力データを seed すると `UNIQUE(character_id, code)` 衝突 → **マイグレ全ロールバック → 起動不能**（M14-03b の dev DB 実例と同一機序）。
- **該当**: **c_viper（利用者あり＝開発者確認）／dhalsim（使用状況未確認）**。※ken/ingrid は M14-03b で seed 済み・友人利用なしを確認済み。
- **推奨解（案 X・「早くて綺麗」）**: **seed 前に友人の自作 move の `code` をリネーム**（`{code}` → `{code}_user`）してから公式 seed を INSERT。**`combo_steps` は `move_id`（FK）参照であり `code` 参照ではない**（DES-003 §3.5）＝**code をリネームしても友人のコンボは壊れない**・**データ損失ゼロ**。マイグレ内で `UPDATE moves SET code = code || '_user' WHERE character_id = (該当) AND code IN (seed の code 群)` の 1 文＋INSERT。
- 代替案: `INSERT OR IGNORE`（起動不能は回避するが**公式データが欠ける**＝非推奨）／自作 move 削除（**友人のコンボが壊れる**＝非推奨）。
- **判断時期**: c_viper の手入力データを投入するサブの着手前。
