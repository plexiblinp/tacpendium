## §1 製造が独自に確定した実装仕様(DES 反映が要るもの)

### 1-1【最重要・仕様追加】相手技走査から「移動 9 種 + 空中攻撃」を完全除外
- 開発者の実画面確認で「移動・跳び込みが相手技側に出るのはノイズ」との指摘を受け、**pass1 冒頭で反撃対象外を完全除外**する規則を追加した(成立レーン・手動確認レーンの双方に出さない)。
- 対象:
  - `category = system` かつ code ∈ {`forward`, `back`, `micro_forward`, `micro_back`, `dash_forward`, `dash_back`, `jump_neutral`, `jump_forward`, `jump_back`}(= 移動 9 種)
  - `is_aerial = 1`(= 空中攻撃)
- 根拠: `internal/service/punishfinder/service.go`(`isNonPunishableTarget` を pass1 冒頭)、`internal/service/punishfinder/constants.go`(`movementSystemCodes`)。
- これは指示書 §4.3.2 / 設計骨子 §3 の除外規則 a〜h に**無い追加**。
- ⇒ **DES(該当章)・指示書 §4.3.2 に「反撃対象外(移動系 system move 9 種・空中攻撃 is_aerial=1)を除外規則 a より前で完全除外」を明文化してほしい。** 正式 CHANGE 起票要否は中央判断。
- 補足: レビュー低指摘「相手側移動 system move が `damage IS NULL` で手動確認レーンに露出」(m18-02-review.md 低-3)は、本除外により**事後的に解消**(レビューは本追加前時点の実装に対するもの)。

### 1-2【最重要・制約明記】verdict(採否)はレーン非依存(レーン別採否は不可)
- 現状 `combo_punish_starters` の verdict は **(self_character_id × opponent_move_id × starter_move_id) 粒度**で、lane 列を持たない。
- そのため同一始動技を「不採用」にすると **その場・前方ステップ・ジャンプ経由の全レーンが一括で不採用**になる。「その場では届かないが前方ステップなら届く」を個別に持てない。
- 是正には `combo_punish_starters` に `lane` 列を追加し UNIQUE を `(self, opp, starter, lane)` へ拡張する**スキーマ変更**が要る(開発者確定で今回は見送り)。
- ⇒ **DES-003 の `combo_punish_starters` 定義に「現状 verdict はレーン非依存(全レーン一括採否)」の制約を明記してほしい。** レーン別採否を正式化する場合は lane 列追加を設計判断事項として起票。

### 1-3 始動技採否・pruning に note(理由)入力欄を UI 露出
- DB `note` 列・API は既存(M18-01/実装済み)だが、UI 入力欄は本サブで新設。始動技側 = 「不採用理由(任意)」、pruning 側 = 「隠す理由(任意)」。
- 根拠: `web/src/features/punish/components/PunishTree.tsx`。
- ⇒ DES-005 画面 19 に note 入力欄(2 系統)の存在を明記。

### 1-4 verdict/punish はトグル選択・再クリックで解除(DELETE)
- 採用/不採用(始動技)・確定反撃に採用(コンボ)は**押下状態付きトグル**で、選択中を再クリックすると **DELETE API で解除**(始動技 = `DELETE /api/combo-punish-starters`、コンボ = `DELETE /api/combo-punishes`)。独立 verdict バッジは押下状態に統合。
- ⇒ DES-005/006 に「verdict は再選択で解除(該当 DELETE を呼ぶ)」の挙動を明記。

### 1-5 表示ラベル確定(内部値は不変)
| 種別 | 内部値(不変) | 確定した表示 |
|------|--------------|--------------|

- ⇒ DES-005 画面 19 の文言をこれで確定してほしい(BE `model/punish.go`・スキーマは非改変、表示ラベルのみ)。

### 1-6 「前提と限界」ヒントを新設(キャラ未選択時のみ表示)
- h1 直下・セレクタ上に、両キャラ選択で消える条件表示のヒントを追加。内容 2 点:「距離は判定していない(偽陽性を含む)」「フレームデータに基づく候補(未整備技は自動判定できない相手技へ)」。
- 当初あった 3 点目「ジャストパリィが主戦場です」は、ガードが劣った機能に見える懸念で**削除**(両タブとも重要のため)。
- ⇒ DES-005 画面 19 に注意ヒントの存在を明記。

## §3 設計担当が未把握の残課題・申し送り

1. **【要起票】pruning の解除・再表示 UI が未スコープ**: 解除 BE API(`DELETE /api/combo-punish-prunings`)は M18-02 で実装済みだが、**FE の解除 UI・「隠した相手技」一覧はどのマイルストーンにも設計スコープされていない**(M18-03 は materialize+採用確定反撃画面で pruning 管理を含まない)。現状、隠した相手技は画面から消え、戻す導線がない。→ 「隠した相手技」一覧+解除 UI の設計・実装を別途起票要。
2. **【設計課題】自動判定できない相手技に紐づく既登録確定反撃の表示導線が無い**: 「自動判定できない相手技」には始動技→コンボのツリーが出ず、その相手技に対し既登録の確定反撃(`combo_punishes`)を本画面で見返せない。→ 表示方法(当該相手技の配下に採用済み確定反撃を出す等)を設計課題とする。
3. **【将来対応】レーン別採否(§1-2)**: lane 列追加+UNIQUE 拡張のスキーマ変更を要する。
4. **【環境制約・繰越】E2E は pin 一致環境での正規 `make e2e` 未実施**: 本環境は playwright pin 不一致(browser 1194 / expected 1223)のため `executablePath` 一時上書きで 2 spec green を実測(設定変更は revert 済み)。spec は決定論・自己完結。pin 一致環境での再実行は開発者環境へ申し送り。
5. **【レビュー低指摘・据え置き】始動技候補で `startup IS NULL` の自技が地上/ダッシュ経由レーンから静かに脱落**(`service.go` の `Startup != nil` ガード)。§4.3.3 の `startup ≤ 有利` を NULL が満たせない以上は妥当・§9 違反ではない。self 側 startup 欠損の可視化は運用判断(現状据え置き)。
6. `JUMP_SLACK`(初版 4・定数)は運用後に `unreachable` 分布を見て調整想定(指示書 §10-3 暫定案どおり)。
