## 3. RESEARCH-03 の結果と **filler 規則の確定**（M19-02 の主要インプット）

**結果**（`M19-RESEARCH-03-report.md`）:
- R-A: `is_derived=true`＝514行。機械分離できるのは `rush_variant`(237) と `target_combo`(63) のみ。残214行は (a)/(b) 判別困難。
- R-B: **(a)「単独入力不可」と (b)「コマンド被り」は機械判別 no**（denjin_charge/thunder_kick が (b) と同シグネチャ）。
- R-C: **`target_combo.total` の意味は判別不能**（派生部分のみ/連携全体が不明・加算検算ばらつき負値あり）。
- R-D: 現行 全技 filler で、リュウ KA=40 既定 3 種別の **210件中19件(9.0%)が target_combo filler を含む**。denjin_charge filler は 0 件。
- R-E: rush 起点（生/キャンセルラッシュ）は seed に一次情報なし＝**実機確認要**。

**★確定した filler 規則（M19-02 で実装）**:
```
filler 候補 = (total ≥ 1) かつ (category != target_combo)
```
- 根拠3点: (1) 実害の実体は target_combo filler（R-D の 9% 全数）で **category 列だけで機械除外可・新スキーマ不要**、(2) target_combo は 2 段目だけ空振り不可＝ドメイン的にも不適格、(3) **total の意味が判別不能（R-C）**なので S に足すと二重計上＝GC-2 と同型（告知で済ませず除外すべき）。
- **判別不能な (a) 相当（denjin_charge 等）は機械除外しない**（R-B で不可能・R-D で実出現 0）。残余は制約告知で吸収。
- **rush filler は維持**（有用）。
- **制約告知に1行追加**: 「状態前提の繋ぎ（電刃錬気中の技等）が候補に混じることがある」→ `M19-LIMITATION-NOTICE` 追従。
- この規則は中央スキーマ非依存＝**中央待ちにならず実装できる**。ただし filler 規則変更は M19-01 の delivered 契約の変更なので **CHANGE 起票（中央・番号中央払い出し）**が要る。

**中央へ渡す DES-003 §3.3 是正の一次源**（moves 系帰属・RESEARCH-03「中央への一次源」節）:
1. is_derived=true の付与理由は §3.3 の現行文言「いきなり出せるか」だけでは説明つかない（ジャスト版96件はコマンド衝突回避）。付与ルールは `docs/seed-data/target-combo-and-derived-flag-rules.md` の方が実データと整合。

## 7. 教訓（この一連で得たもの・M19-02 で効かせる）

1. **UI 相乗り先は「名指しの一意性」でなく「必須動線（保存・親参照）の充足」で確定**（SetupSelectorModal が comboId 欠で保存不可だった）。→ #7 の UI 調整で再度効く。
2. **永続手段（localStorage キー等）もガバナンス対象**（CLAUDE.md §10.X 公認キー表）。
3. **レビュー中のスコープ拡大も E-28（全箇所波及）の対象**（指示書は固定でも DES/overview は delivered に追従）。
4. **サブ間の前倒しは「留保理由の前提解決」を確認してから**（rush 前倒しで (e) 未確認が持ち込まれた）。
5. （正）**独立 clean-room レビューが機能した**（チェックリスト投資の回収）。
6. **中央所有の反映を「受領前」に下流へ『済み』と書かない**。
7. **反映確認は安定識別子で grep して本文を読む**（略記 grep の 0 件を未反映と断定しない＝§3.4 偽陽性の教訓）。ただし系統問題(083/084)は本物だったので監査の価値は否定されない。
8. **候補集合（target/filler）の除外規則は両側で同じドメイン原理（人間が入力できるか）に照らす**（「全技 filler」が広すぎた＝§3 の filler 規則はこの一般化）。
