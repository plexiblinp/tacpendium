## 2. 確定した設計判断（**再協議不要**）

> **前セッション（M14-03b/M17 期）の §2 も引き続き有効**（`m14-03b-m17-design-session-handover.md` §2＝**とくに §2.3 派生技フラグ `is_derived` の判定原理＝再発明禁止**）。以下は**本期に追加・確定したもの**。

### 2.1 G-k command 索引と段階2 の決定論解決（CHANGE-069・**正典＝DES-004 §2.4**）

- **死守 3 契約**: **公式表記のみ解決**／**モーション解析をしない**（236 等を仮想コントローラで実演させない）／**出口は必ずキャラ別 `move_code`**。⇒ 本機能は「曖昧なモーションを**認識**する」問題ではなく「**クリーンな入力状態を引く（決定論ルックアップ）**」問題。
- **index-only**: `moves.command` 列は**復活させない**。索引＝`move_commands`（DES-003 §3.14）。構築主体＝`internal/moveindex`（**取込ヘルパーと共通＝「二度作らない」**）。
- **索引は広く・スコープの絞り込みは消費者側**: 索引には**非派生技のすべて**（必殺技・空中技を含む）を載せる（**M17-04 が使う**）。**段階2 の解決表だけが「地上・単方向＋ボタン」に絞る**。
- **解決表の畳み方（7 段・DES-004 §2.4.4）**: 非派生のみ → **`is_aerial=false`** → 形状（単一方向＋強度付きボタン or ボタンのみ）→ category ガード（normal/unique/special）→ **特殊技優先** → **id 最小タイブレーク** → **決めきれない組は載せない**。
- **段階1／段階2 の境界＝一様フォールバック**: **解決表を先に引き、ミスなら段階1 の構造引きへ**。**方向ゾーンで経路を分けない**。**段階1 は索引非依存＝未 seed キャラでも動く**。
- **`is_derived` は moves 本体の bool 列**（索引テーブル側フィルタでない）。**判定源は入力ツール側の人手付与＝本体は導出しない**。**`rush_variant` は `is_derived=true`**（画面18 の生成時に定数で立てる）。
- **`is_aerial` の精度が段階2 の正しさに効く**（**空中特殊技は true が必須**／空中必殺技の false は無害）。**実例＝`lily/great_spin`・`kimberly/elbow_drop`**（`d plus p_h`／`d plus p_m` が しゃがみ強P／しゃがみ中P と衝突）。

### 2.2 解決表配信 API（CHANGE-069/070・**正典＝DES-002 §4.2**）

- **`GET /api/characters/{id}/command-index`**（**数値 ID**）。**BE が畳んだ表を返す**＝**FE は引くだけ＝規則を持たない**（正規化・特殊技優先・タイブレークは **Go に一元化**＝二重実装しない）。**キャラ選択時に 1 回**。
- **キャラ存在チェックをしない**＝**未 seed・不存在 ID とも 200＋空 entries**（**404 を返さないのは仕様＝「壊れない」優先**）。不正 ID は 400。
- **【重要】解決表は `moves.is_aerial` と `category` に依存して畳まれる**＝**技編集（`is_aerial` の PATCH）は解決表を変える**＝**FE は技編集の成功時に `["command-index", characterId]` を無効化する**。**ラッシュ版生成は無効化不要**（`is_derived=true`＝索引対象外）。

### 2.3 取込ヘルパー（CHANGE-071・**正典＝phase3-overview §M17 ④／DES-005 §5.19**）

- **【最重要】移行するのは「ユーザーのコンボ」であって moves ではない**（moves は M14-03 系列の seed で入る＝**照合先として参照するだけ・read only**）。
- **二段の役割分担（外さない）**: **① アプリ外プロンプト（AI）＝自由表記 → 候補トークン列**（曖昧）／**② 本アプリ＝厳密照合 → `move_code` 確定**（確実）。**AI に `move_code` を生成・確定させない**。**本体から LLM を呼ばない**。
- **フォールバックなし**（**段階2 は通常技へ落とすが、取込側は落とさない**＝**索引 IF は共通・消費者は別**）。**未解決は正常な結果**＝人レビューへ。
- **出力＝`combos.csv` のみ**（`setups.csv` は対象外）→ **既存 import 動線へ**（**検証を迂回しない**）。
- **① の出力形式＝Markdown パイプ表**（**TSV は不可**＝**AI チャットのコピーがタブを空白へ潰す**ため境界復元不能＝実データで判明）。**トークン語彙＝TOOL-002 §9.9 の 24 種**（**索引正規化と一体＝安易に増やせない**）。
- **エイリアス照合を含む**（**完全一致のみ・1 件のときだけ確定**。**`alias_text` に一意制約が無い**ため）。
- **「プロンプトをコピー」ボタン**＝**本文＋選択中キャラの moves 一覧＋カスタムプリセットのエイリアス（あれば）**を結合（**1 キャラずつ**・**キャラの取り違えが構造的に起きない**）。**プロンプト本文の正は実装後コード**（`web/src/features/intake/prompt.ts`）。
- **未解決ステップは「行ごとにドロップ/採用」**（除外列）＋**「レシピから外れる（手数が減る）」警告**（**案 3＝自由文ステップ化は将来の拡張余地**）。

### 2.4 メディア 3 列（CHANGE-068・**正典＝DES-003 §3.4**）

- **`link`／`video_path`／`image_path`**（TEXT・NULL 可）。**非 dup／非 recipe**（**3 列だけ異なるコンボは重複と判定される**）。**PATCH は presence-detection トライステート**・**PUT でも引き継がれる**。
- **スコープ＝文字列参照まで**（開く／配信／再生／存在確認をしない）。**`link` は http/https 前方一致のみリンク化**（ホワイトリスト方式・実体 `web/src/lib/safe-url.ts`）。**path は常にテキスト表示**。**閲覧不可は許容**。
- **CSV は任意列末尾追加・verbatim 往復**。ただし**セルレベルでは VAL-I10（式注入無害化）を memo と同様に対称適用**。

### 2.5 i18n サーフェスの境界（M16-06・**playbook §4.13.1 に恒久化**）

## 4. 【最重要】M17-04 は「動く」が「使える」には一段要る（§G-14）

**本期最大の発見**。次担当が**最初に理解すべき事項**。

### 4.1 何が起きたか

- **② 厳密照合は仕様どおり動く**（`internal/moveindex`・`csvcore`・`inputresolve`・スキーマ・migrations とも **`git diff` 差分ゼロ**＝「二度作らない」「契約不変」を diff で証明できる状態）。
- **しかし開発者の実データ検証（2026-07-17）で、① プロンプトが実コンボを候補トークン列に落としきれないことが判明**した。

### 4.2 原因は 2 層

- **(a) 技一覧（moves）が未注入だと技名候補が全滅する**（**運用の問題**）。初回検証は **raw prompt の直貼り**で行われ `{{MOVES}}` が空だった。→ **アプリの「プロンプトをコピー」経由（moves 同梱）が必須運用**であることが実証。**生プロンプト運用は不可**。
- **(b) SF6 頻出のシステム概念がトークン語彙 24 種で原理的に表現できない**（**設計の根本課題**）: **ドライブラッシュ（DR/CR./R.）・OD・SA1〜3・DI・パニッシュカウンター（PC）・回数（×2〜3）・選択（/）・条件（[ストック2]）・ダメージ/フレーム注記**。**語彙は索引正規化（DES-004 §2.4.3）＋`moveindex.tokenFragments` と一体で安易に増やせない**（**ここが「語彙を足せばよい」で済まない理由**）。

### 4.3 再検証で本線は機能した

- **アプリ経由（moves 同梱）で再検証したら技名候補が大幅に埋まった**（例: しゃがみ弱P／中サンライズ／SA3 コズミックレイ／ソーラーフレア／しゃがみ強P(ラッシュ)）。
- **② の実測＝54/67＝約 81% 解決**。**通常技はトークンで、必殺技/SA は技名候補 → 別名照合で解決**＝**本線（技名 → エイリアス照合）が実データで機能した**。
- **未解決 13 件は単一 move に落ちない行**（ターゲット連携 `中P~中K`・適当・2KKK/6KKK・R.系・追加派生・"..."）＝**設計どおり人レビュー行きで正常**。
- **初回の「大半が未解決」は検証条件の誤り＝過小評価**だった。

### 4.4 テコ入れの方向（**「語彙拡張」ではない**）

1. **必殺技/SA/DI は「技名候補 → エイリアス照合」を本線に据え、トークン照合は通常技の補助と位置づける**。⇒ **`preset_aliases` を SA 番号・キャラ通称（「ライズ」「フレア」等）・ラッシュ版別名まで充実させる**（**要確認: `rush_variant` に日本語別名が付いているか**＝付いていれば取込に大きく効く）。
2. **中間表現プロンプトの二段化（開発者提案）**: ①-a で略語・システム概念を自然言語へ展開（DR→ドライブラッシュ／SA3→スーパーアーツ3／×2→2回）→ ①-b で技名候補＋トークン列。
3. **DR/OD/SA/DI/PC を語彙拡張でなくステップ属性（`modifiers.type` 相当）/別列で扱う**（**トークン語彙は据え置き・システム修飾は別チャネル**）。
4. **M20 カスタムプリセット（個人辞書）の前倒し効果**（**§G-11 と直結**）。
5. **回数・選択・条件・注記は取込対象外**として memo 退避 or 人手補完。

### 4.5 残る精緻化

- **多候補ハッジ（"A or B or C"）**: AI が Lv・方向・強度不明の行で複数候補を連結 → **② は `alias_text` 単一完全一致のため引けず未解決**。〔改善案〕(i) **① で「最有力 1 件を技名候補・残りは備考へ」**（**プロンプト v1.2.0 で指示済み**）／(ii) **② の resolve で " or " を分割して候補としてレビューに提示**。
- **【運用】高性能モデルが前提**（**GPT は安定／Gemini 無料版はパース不能**）。
