## 2. M19 で確定した設計判断（**M20 に効くもの**）

1. **保存 UI を置ける面の原則（v3）**——**判定軸は「親が確定しているか／同一トランザクションでコミットできるか」であって、画面名ではない**（`DES-005` §5.6）。**M19-01 の失敗の本質は「あの画面が悪い」ではなく、親が存在しない状態で即時保存しようとしたことである。** **M19 の終わりに 4 つの面すべてがこの軸で並んだ。** **新しい保存面を作るときは必ずこの判定表に行を足すこと。**
2. **値が同じでも意味が違うものを、同じ表現に寄せない**——「未検証」と「該当なし」／「圏外の NULL」と「未実測の NULL」。**M19 は「未検証は行の不在で表現する」を貫いた**（`DES-003` §3.19）。**寄せると後から復元できない。**
3. **述語は「誰が何を問うているか」で意味が変わる**——同じ SQL 述語が、filler 候補（自分が単独で入力できるか）では正しく、相手技候補（相手が出しうるか）では偽陰性になった（**D-260**）。**共用する前に、両側が同じ問いを立てているかを確認すること。**
4. **契約には「あるべき姿」を書き、現状の取りこぼしは既知の乖離として併記する**（**D-275**）。**現状を正として書くと、揃える作業に収束先が無くなる。**
5. **黙って無視される経路は、直せないあいだ契約に書いて観測可能にする**（**D-276**）。**成功応答を返しながら捨てる形が最も悪い。**
6. **api パッケージ間の DTO 型参照を認めた。★3 例目で共有パッケージへ切り出す**（**D-273**）。**1 例では構造を決められないが、3 例あれば形が見える。決めておかないと、増えてから誰も着手しない。**

## 7. M19 教訓（**M20 に効くもの**）

**board §3.4 の D-243 以降と、`retrospective-log` へのバッチ反映分が一次源。ここは要点のみ。**

1. **★現物を持たない側は、「ある／無い」だけでなく「内容の描写」も断定しない**（**D-280**）。**描写は根拠として書かれるため、操作が正しく当たっているかぎり誰も検算しない。そして後任は根拠を信じて、別の場所へ同じ判断を適用する。**
2. **★「基準が書かれていない」と判断する前に、対象の節を全文読む**（**D-256**）。**`grep` で自分の探している語が無いことは、基準が無いことを意味しない。** M19 では「根拠が無い」が実際には「名前はあるが仕様が無い」だった。
3. **★生きた表の行数は、裁定文が持ってよい種類の数字ではない**（**D-259**）。**裁定文が持ってよいのは変わらない事実（判断・規律・根拠）であり、計数は台帳が持って参照側は都度実査する。** **同期コストを下げる最善手は、そもそも写さないこと。**
4. **★古い記述の扱いは 3 分類**（**D-274**）——**生きた設計文書＝本文を正本へ揃える**（旧本文を残すとそれが実装される）／**裁定行＝書き換えず errata 注記**（当時どう判断したかの記録）／**完了済み指示書＝書き換えず撤回マーカー**（実装指示としては読まれないが検索には当たる）。**一方の結論をもう一方へ持ち込まない。**
5. **★並列サブは互いの `E-14` 交差相手である**（**D-284**）。**同時発行した指示書は、他の並列サブが完了した後の as-built を知らない。** **M19 では実害が出なかったが、それは触る面がほとんど交差しなかった結果であって、検出の仕組みが働いた結果ではない。**
6. **★「同じ X を再利用」とだけ書くと、参照先が合っていれば満たしたと読まれる**（**D-278**）。**設計書に「既存の X と同じ」と書くときは、X の実体を 1 段だけ具体化する。** M19 では、設計書と実装が乖離したまま次のサブへ伝播し、**開発者の目視でのみ捕まった**——**UI の構造は自動テストにもレビュー報告にも映らない。**
7. **★「次の番号」の運用は、警告文ではなくテンプレートの常設項目にする**（**D-277**）。**registry は「この行は古くなる。完了報告と対で更新する運用が要る」と自ら警告していたが、その警告どおり失効した。** **警告文を書くことは運用にならない。**
8. **★指示書が X について規定していたら、「X と同じ語で呼ばれる別の対象が実装に無いか」を 1 回探す**。M19-06 では「論理削除されたコンボ」だけを規定し、「論理削除された**セットプレイ**」を書き落としていた。
9. **★実測が出るまで確定させない・机上で選ばない。** M19 の見込み値は繰り返し失効した（除外は 3 行の見込み → 実測は桁違い／案 α は見積りの 2.7 倍）。**候補集合を動かす変更は、実装を確定する前に実データで増減を測ること。**
