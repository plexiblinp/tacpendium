## §0. 結論

**M19 をクローズする。**

**引き渡したもの**——**コンボの起き上がり有利フレームから、相手の起き上がりに重なる（または意図的に重ねない）セットプレイのレシピを計算して提示し、利用者が採用したものだけを登録する機能。** あわせて**実機で確認した成立条件を記録し、一覧をその状態で絞り込み、コンボやセットプレイの新規登録時にも入力できる。**

**要件の裏付け**——**`REQ-001` FR014**（**CHANGE-097** で新設。**D-28** が「FR 新設は M19 クローズ時に 1 本」と定めていた分）。

## §4. ★既知の限界（**必ず引き継ぐ**）

### 4-1. 本 MS の完了時点で、2026-08-04 のゲームアップデートは未反映である（**D-208**）

**配布対象はクラシック全 31 キャラ**（2026-08-04 のアップデートで 30 → 31）。**seed 済みは 17 キャラ**で、**残りは未投入である。** **提案の網羅性はこの範囲に限られる。**

### 4-2. golden 5/5 の green は、実データでの動作を保証していない（**D-264**）

**GC-2（奮迅脚からの通し値）は、golden が合成 fixture で親参照を与えるため 5/5 を達成する。** **しかし実データには `ken/thunder_kick` の親参照が無く、同じ親前置は起きない。**

**⇒ 「golden が通っているから実装できている」と読まないこと。** **投入は update 波**（followup `gc2-thunder-kick-parent-reference`）。**投入時に `startup_basis` が `through` であることを実査すること**——**`standalone` / `unknown` の行に親参照を付けると、その行は filler 候補から静かに落ちる。**

### 4-3. 並列サブは互いの `E-14` 交差相手である（**D-284**）

**M19-05／06／07 は 3 本まとめて発行され同時投入された。** **3 本の指示書とチェックリストは、いずれも「他の 2 本が完了した後の as-built」を知らない。**

**★実際に起きていた**——**M19-07 の追補が採用パネルを 2×2 グリッドへ差し替えた。この面は M19-01／02 の領域であり、M19-05 が同じ機能領域を触った後、既に完了・マージ済みだった。**

**★M19 では実害が出なかった**（既存テスト 26 件が無改変で green。payload はセルの順序まで従来と同一）。**しかしそれは結果であって、検出の仕組みが働いた結果ではない。** **`M19-06` の R-5 と `M19-07` の R-7 は互いの領域ではなく `punishfinder`／`setplay` を守っており、06 と 07 のあいだには相互の検出項目が無かった。**

## §5. ★M19 で「やらない」と決めたもの（**否定形の記録**）

**これを書かないと、後任が同じ検討を最初からやり直す。**

| # | 決めたこと | 理由 |

| **2** | **R6 警告を実装しない**（**D-262**） | **参照可資料に仕様が無い。** 「R6 整合検査に使用」という言及はあるが、**何を検出し何を表示するかが定義されていない。** 仕様が無いものを実装させると製造が仕様を書くことになる |
| **3** | **`chain_cancel_total` の追加投入（TP-02）を M19 で閉じない**（**D-265**） | **未実測分は人手実測が律速であり、update 波の実測パスに載せるほうが安い。** 実測とセットでないと閉じられない |

| **5** | **「未検証」のラベル文言を変えない**（**D-271**） | 裁定 B のあと、意味は「手つかず」ではなく「**埋め残しがある**」。**意味は正典に書いたので復元できる。** 文言変更は i18n の ja / en 両方と既存の利用者の理解に触れる |
