## §1 製造が独自に確定した実装仕様（DES 反映が要るもの）

### §1-1 ★★`value_definition.options`（ラベル付き選択肢）を新設した

**格納 JSON（`DES-003` §3.2）の `value_definition` へ、任意フィールド `options` を足した。**

```json
"value_definition": {
  "kind": "integer", "min": 0, "max": 4,
  "options": [
    { "value": 0, "label_ja": "なし", "label_en": "None" },
    { "value": 1, "label_ja": "弱",   "label_en": "Light" }
  ]
}
```

- **在れば画面は数値入力ではなく選択（`OptionButtonGroup`）を出す。無ければ従来どおり数値入力である。**
- **★`type` は増やしていない。`isSupportedState` は 1 文字も変えていない**（`web/src/features/combo/customStates.ts`）。**⇒ 撤回済みの `type: composite`（`000009` → `000017` で削除）を復活させる形ではない。**
- **★`options` を持たない `level` は 1 行も変わらない**——as-built で唯一の `level` である ingrid の `sun_crest` は不変である（`internal/infra/migration/migrate_m3105_test.go` の `TestRun_M3105_SunCrestUnchanged` ／ `customStates.test.ts` の陰性対照 ／ 既存 E2E `m14-03b-custom-states-realdata.spec.ts` の 3 経路で固定した）。
- **★値域と選択肢の関係を契約にした**——`min..max` が**ちょうど**選択肢の値の集合であること（欠けても余っても赤）。`migrate_m3105_test.go` の `TestRun_M3105_OptionsWellFormed`。**⇒ 食い違うと `clampIntForDef` が別の選択肢へ黙って化ける。**
- **★`label_en` は必須である**——無いと `optionLabelFor` が `label_ja` へフォールバックし、**EN 画面に日本語が出る**。`web/src/locales/no-japanese-in-en.test.ts` は locale ファイルしか見ないためこの経路は素通りする。

**⇒ `DES-003` §3.2 へ `options`（値・`label_ja`・`label_en`）の定義と、上の 3 つの不変条件を明文化してほしい。**

### §1-2 ★★`value_definition.single_value`（int state を 1 つの値として扱う）を新設した

**`true` のとき、画面は 1 欄・表示は 1 行・ラベルは state 名だけになる。省略時は従来どおり ①`start_min` / ②`end` の 2 値である。**

**★★出所は 2026-09-10 の開発者の実機確認である。** 逐語＝

> **設置系の技が始動時、終了時に分かれているが、分ける必要はないので直して欲しいです。恐らくストック数等に釣られたものと思われるが、それらとは扱いが別。**

**★★指摘のとおりであった。** ①② は `M16-07`（`CHANGE-067`）が**ストック系のために**足した拡張であり、`custom_states` の原点は `CHANGE-040` の「**開始時状態の付与のみを扱う。消費（減少・解除・レベル技変化）は一般モデル化しない**」である（`customStates.ts` の冒頭が逐語で持っている）。**⇒ 設置系を ①② へ乗せたのは製造の取り違えである。**

| 項目 | 内容 |
|---|---|
| **対象** | 本サブが足す **14 state 全件**（うち int が 11 件。`flag` 3 件は元から 1 値） |
| **★変えないもの** | **既存のストック系 6 件**——`fuha_stock` ／ `flame_stock` ／ `windclad` ／ `blanka_chan_bomb` ／ `shuriken_bomb_stock` ／ `sun_crest`。**`single_value` を持たないため 1 文字も変わらない**（陰性対照をテストで固定） |
| **★格納形** | **`{start_min, end}` のまま両方へ同じ値を書く。⇒ 形を分岐させない**（parse / build / 後方互換の経路をどれも変えずに済む）。`normalizeIntValue` が畳む。**★片方だけに値が入った形（手書き JSON・旧データ）も、既定でない側を採って畳む** |
| **★ラベル** | **固定句を付けず state 名だけ**（`customStateIntLabel` が `single_value` のとき固定句を落とす） |
| **★撤回** | **追補前に入れていた `phrase_kind`（設置数用の固定句）は撤去した。** 1 欄になれば固定句そのものが消えるため不要になる。**⇒ レビュー 中-2 の是正**（残弾と設置数がラベル上で区別できない）**は保たれたまま、機構が 1 つ減った** |

**⇒ `DES-003` §3.2 へ `single_value` を明文化してほしい。⇒ あわせて「①② はストック系のためのものであり、開始時の状態だけを持つ state は 1 値である」を書いてほしい。★これが無いと、次に `custom_states` を足す人が同じ取り違えをする。**
