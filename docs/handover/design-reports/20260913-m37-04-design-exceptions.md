## §1 製造が独自に確定した実装仕様(DES 反映が要るもの)

### 1-1 ★★★`DES-003` §3.3 列台帳の原稿(`first_hit_startup`)

**完了条件 §6-3 が求める「名前／実セマンティクス／消費者一覧」の 3 点**(`M19-DESIGN-07` §7 の列台帳規約)。**⇒ `DES-003` §3.3 の列表へ次の行を足してほしい。**

| カラム | 型 | 制約 | 説明 |
|--------|-----|------|------|
| first_hit_startup | INTEGER | NULL可 | **その技の初段が当たるまでのフレーム**（`CHANGE` 未採番・`M37-04`・マイグレ `000114`）。**★`startup` が「その技を単独で出したときの発生」であるのに対し、本列は「1 段目が当たるまで」を表す。** ターゲットコンボの 2 段目以降を 1 行で表す行では両者が食い違う（実例＝ryu `fuwa_triple_strike_2hits` は `startup=5` だが初段の立中P は 6F）。**★`CHECK` は持たない**（既存の `startup`＝`000013` に倣った）。**★NULL の意味は「不明」で統一する。「1 段技だから不要」という第 2 の意味を持たせてはならない**——2 つの意味を 1 つの NULL に畳むと後から区別できない。**⇒ 判定側は*行の属性*で対象かどうかを決める。** **★値の付与は開発者の人手入力**（`D-857`）**＝本体は導出しない**（`is_derived` / `is_projectile` と同型）。**対象は `category='target_combo'` ∧ `is_derived` ∧ `startup_basis='standalone'` の 109 行のみで、それ以外の行は NULL のままでよい。** **★着地時点は全 3,026 行が NULL である。** `DuplicateKey`・`recipe_hash` 非対象 |

**★列台帳の 3 点を明示形で:**

| 観点 | 内容 |
|---|---|
| **名前** | `first_hit_startup` |
| **実セマンティクス** | **「この技の 1 段目が当たるまでのフレーム」というゲームの事実。** 確定反撃に限らない普遍的な性質である |
| **消費者一覧** | **現時点で 1 つだけ**——確定反撃サーチの候補判定(`internal/service/punishfinder/service.go` の `candidateStartup`)。**★`GET /api/moves` には露出していない**(`model.Move` に持たせていない＝`startup_basis` と同じ扱い)。**⇒ フロント側の対応定数も作っていない**(`CLAUDE.md` §4 の同期規約は API 露出列が対象) |

**★★列名の審査は `D-861` で通過済みである**(`starter_startup` は「始動用の」＝特定消費者の用途を名前へ持ち込むため却下)。**⇒ 本レポートは審査の再開ではなく、台帳への記載を依頼するものである。**

**★「NULL の間は候補から外す」は列には書かない**——**消費者側の導出規則である**(`M19-DESIGN-07` §7 に適合)。
