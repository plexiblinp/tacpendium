## §1 製造が独自に確定した実装仕様（DES 反映が要るもの）

### 1-1 層順は「3 接頭辞の例外」ではなく **原理** である。その原理を DES へ

**確定した規約**（D-1 を実装が受けた形）: **「`command` が表記を決める行は層 A、`move_code` の構造が決める行は層 B」。**

**根拠（CSV 全数実測）**——立ち技と J 攻撃の `command` は**同一**である。

```
standing_light_punch : command = "p_l" → token_key = "LP"
jumping_light_punch  : command = "p_l" → token_key = "LP"
```

**`command` 列は地上/空中を表現していない。その情報は `move_code` 側にしか無い。** 層 A を先に当てると (1) `DES-004` §3.4 の `5LP` に一致しない (2) 同 `j.HP` に一致しない (3) 立ち技と J 攻撃が同表記になり同一キャラ内の衝突が **6 キー × 17 キャラ = 102 キー**増える、が同時に起きる。

**★この原理で判断した境界行を 4 型記録した**（完了報告 §2.1）。特に **層 B は「接頭辞 ＋ 強度 ＋ ボタン」の完全形にのみ当てる**——`terry/jumping_knee` は接頭辞を持つが `knee` が語彙に無いため層 A へ落ちる（`internal/seedgen/generate_m2002.go` の `layerB`）。**接頭辞だけで判定すると誤った表記が付く。**

- ⇒ **`DES-004` §3.4 / §5 へ上記 1 文を原理として明文化してほしい。** 「3 接頭辞は層 B が先」という書き方だと、4 パーツ code（`standing_heavy_punch_holding`）や語彙外（`jumping_knee`）で再び判断が割れる。

### 1-2 SA 注記の書式・抽出源・適用範囲

**書式 `236236P (SA1)`**——半角スペース 1 個 ＋ 半角丸括弧。**値は `move_code` から正規表現 `(^|_)(sa[123]|ca)(_|$)` で機械抽出する**（`generate_m2002.go` の `saPattern`）。**技名 `name_ja` からは推測しない。**

**適用範囲を「`super_art` / `critical_art` 一律」に決めた**（D-5 が「実測で決めて理由を報告」としていた点）。**衝突組だけに付けても残存衝突キー数は同じ**（注記は衝突組にしか効かない）ため、差分は表記の一貫性だけである。一律にした理由は、(1) 同じ SA でもキャラにより注記の有無が変わると不揃いになる (2) 「衝突判定 → 注記 → 再判定」のループになり**生成器の決定論が崩れる** (3) `236236P` 単体では読めない SA 番号が読み取れる、の 3 点。

**効果の実測（D-3 の「注記適用後に測り直す」）**: 同一キャラ内で SA / CA の 2 技が `token_key` を共有する組は **23 組**あり、**うち 17 組が SA3 vs CA（全 17 キャラに 1 組ずつ）で注記により全数解消**した。残る 6 組は**同一 SA クラス内**のため注記では解けない。

- ⇒ **`DES-004` §3.4 / §5 へ書式と「`move_code` からの機械抽出のみ」を明文化してほしい。**

### 1-3 `alias_text_en` の形と、実際に埋まった範囲

**`ALTER TABLE preset_aliases ADD COLUMN alias_text_en TEXT`**——**NULL 可・既定値なし・一意制約なし**。down は `DROP COLUMN`（modernc ドライバで動作を実測）。

**実際に値が入ったのは移動系 2 code だけ**——`micro_forward` = `microwalk` / `micro_back` = `back microwalk`。**19 キャラ × 2 code × 2 プリセット ＝ 76 行**（プリセットあたり 38）。残る移動系 7 code と全キャラ別技は **NULL** である。

- ⇒ **`DES-003` §3.9 へ列定義を反映してほしい。** あわせて **`DES-004` §5** に「**現時点で `alias_text_en` を持つのは移動系 2 code のみ**」を書いておくと、M20-05（表示側でロケール分岐）が「英語が無い行が大半」という前提で設計できる。

### 1-4 `DES-004` §3.4 サンプル表の **3 行は原理的に生成できない**

固定点は **4 行 × 2 プリセット ＝ 8 件**へ縮めた（D-4）。生成できない 3 行の理由は次のとおりで、**規則を直しても埋まらない**。

| 行 | 生成できない理由 |
|---|---|
| **`sa1`** | (1) **実在する `move_code` ではない**（ryu の実体は `sa1_shinku_hadoken`）。(2) numeric の期待値 `236236HP` に対し CSV の `command` は**強度指定のない `p`** であり `236236P` にしかならない。**`HP` はデータから作れない** |
| **`parry_drive_rush`** | `modifiers.type` の**非技ステップ**であり `moves` 行ではない。`preset_aliases` は `move_id` を鍵に持つため入らない |
| **`cancel_drive_rush`** | 同上 |

- ⇒ **`DES-004` §3.4 の表を実データで置き換えるか、「サンプルであって固定点ではない」旨を強めてほしい。** 現状も末尾に「※上記は方針を示すためのサンプル」とあるが、**指示書 §5.1 はこの表を一致検証の対象として引いていた**ため、次のサブでも同じ齟齬が起きうる。

### 1-5 ★移動系 9 code に「**seed 波ごとの再適用**」という運用責務が新設された

**`000072` / `000073` は移動系を「適用時点の 19 キャラを明示列挙して」投入している。** ⇒ **新キャラには当たらない。層 A / 層 B / rush 版と同じく、移動系も波ごとの再適用対象である。**

**当初は `characters` を CROSS JOIN する形（キャラを列挙しない＝波を跨いで再適用不要）で実装していたが、レビュー H-2 で是正した。** up は `NOT EXISTS` で既存を skip する一方 **down は無条件に DELETE する**ため、**次の波のマイグレを down すると `000072` / `000073` が入れた 171 行 × 2 プリセットまで消えた**（`SUPP-001` §5.5.2 (5)「down は up の反転ではない」に真正面から当たる形）。**up と down を同じ集合で絞るには、キャラを明示列挙するしかない。**

**⇒ 新しい運用制約**: 次の seed 波では `-mode aliases` を 2 プリセット分走らせ、**`-movement-chars` にはその波で増えたキャラ「だけ」を渡す**。前の波を混ぜると down が前の波の投入分まで消す。手順は `character_data/seed-progress.md` に書き、生成器テスト `TestAliases_MovementDownIsScopedToItsOwnChars` が機械的に守っている。

- ⇒ **`DES-003` §3.9 または `DES-004` §5 へ「seed 波ごとの再適用責務」を明文化してほしい。** `DES-003` §3.3 には **CHANGE-091 で同型の規約（`is_derived` の波ごと再適用＝D-181）が既にある**ので、そこへ並べるのが自然だと考える。**落ちたときの症状が D-181 と同一**——新キャラだけエイリアスが空、フォールバックで日本語技名が出るので**画面は壊れずテストも緑**、人が見る以外に発見経路が無い。

### 1-6 衝突は **両方落とす**。残存衝突を全件測った（M20-03 の入力）

**同一キャラ内で 2 技が同表記になる組は、どちらも投入しない**（指示書 §9.3-5「製造は独断で片方を捨てない」を実装した形）。

| | 残存衝突キー | 衝突行 |
|---|---|---|
| `numeric` | **35** | **84** |
| `srk` | **30** | **74** |

**★`numeric` だけ多い 5 キーは、すべて「空中版 vs しゃがみ版」である**（`kimberly/elbow_drop` ／ `lily/great_spin` ／ `marisa/caelum_arc` ／ `rashid/blitz_strike` ／ `zangief/flying_body_press` が、それぞれ同キャラの `crouching_*` と `2HP` / `2MP` で衝突）。**入力が曖昧なのではなく、`numeric` 記法が「空中で押した」ことを表現できないだけである。** `srk` では `cr.HP` と `2HP` に分かれるため衝突しない——**`cr.` 接頭辞が偶然この曖昧を解消している。**

**★開発者見解を受領している**（2026-08-13）。**「この技だけ `j.` を付けるのはおかしい。通常の技全体に `j` をつけるのが正しそうだ。だがここでやるのはスコープ外」。** ⇒ 衝突技への例外付与ではなく、**空中技全体への一貫した規則**として検討されたい。

- ⇒ **`DES-004` §5 へ「衝突組は両方落とす」を明文化してほしい**（現状は指示書にしか無い）。全 35 キーの列挙は完了報告 §5.3 にある。

### 1-7 §4.11 一意性の実測 —— **単純 UNIQUE は張れない**

M20-03（一意制約）の直接の入力なので、**測定単位を明示して**渡す。**#2 / #3 / #4 はすべて `GROUP BY` したキーの数であり、行数ではない。**

| # | 測るもの | 実測 |

| 1 | `(preset_id, alias_text)` の重複キー数 | `official_ja_move` 60 ／ `numeric` **124** ／ `srk` **125**。★想定内——`5MP` は全キャラで同値、移動系は 19 行ずつ同値 |

### 1-8 注記付き `alias_text` は **完全一致で引けない**（M20-07 の負債が 1 件増えた）

取込ヘルパー `FindMoveCodesByAlias`（`internal/repository/preset/queries.go`）は **`alias_text` の完全一致**で引く。本サブが付けた ` (SA1)` 〜 ` (CA)` は `alias_text` の一部であるため、**ユーザーが `236236P` と書いても `236236P (SA1)` には一致しない。**

## §7 教訓（retrospective 行き）

> **親は本節を読まなくてよい。** 宛先は `docs/handover/retrospective-log.md` へのバッチ反映で、**実施者は設計担当**（反映担当の廃止・2026-08-11 に伴う）。

- **常設検査を新設するときは、同じ変更で依存の導入手順（devContainer / postCreate）も入れる。** 入れないと「検査表に載っているが誰も実行できない検査」ができる。**未導入時に `exit 2` を返す正しい設計であるほど、上位の統合検査が恒常的に赤くなり、赤が常態化して読まれなくなる。** ⇒ 新設 PR のチェック項目に「**新しい実行環境依存を足したか。足したならどこに書いたか**」を入れる。
- **ベースライン固定型の検査で増分の所在を追うには、「当時のツリー ＋ 判定ロジックだけ」を回す。** `git archive <ベースライン commit> <対象> | tar -x` で当時のツリーを出し、**スクリプトではなく判定ロジックの本体だけ**を直接実行して、現在の `--list` と突き合わせる。**⇒ ベースラインに一覧を保存しておく必要はない。** ★本サブでは最初「件数しか保存していないから特定できない」と結論したが**それは誤りで、スクリプトごと回そうとして `cd` で詰まっていただけ**だった。**「保存されていないから無理」と結論する前に、再現手段が本当に無いのかを疑う。**
- **ラチェット型の検査の定数は、並列レーンがあるとき製造が触ってはならない**（D-335）。**同じ 1 行を両ブランチが書き換えると、後からマージした側の古い値が勝ってラチェットが黙って緩む。** 製造は**違反そのものを直し、「現在 N / ベースライン M」の実測値を報告するだけ**にする。定数の更新は全レーンのマージ後に一括で行う。⇒ **検査スクリプト自身のコメントへ「並列期は定数を触らない」と書いておく**と、ルールの伝達漏れに耐える（本サブは D-335 を作業開始後に受領した）。
- **既存テストは「green である」ことと「効いている」ことを分けて疑う。** 本サブの H-1 は `{query, min, exact, message}` の表で `exact == 0` を「厳密一致しない」の signal に使っており、**`{..., 0, 0, ...}` の行が `n >= 0` すなわちどんな値でも PASS する**構造だった。**実査で目を通していたのに素通りした**——落ちないので気づけない。⇒ **「この行はどんな入力なら落ちるか」を 1 行ずつ言語化する**のが唯一の検出手段である。**表形式のテストで番兵値（0・空文字）を制御フラグに使うのは、この罠を作りやすい。**
- **回帰テストは「守るはずの違反を入れて落ちること」まで確認して初めて回帰テストである。** 本サブでは H-2 の回帰テストを最初 `strings.Contains(down, "'ryu'")` で書いたが、**スコープ句ごと外す破壊テストがすり抜けた**（句を外すと他波のキャラは「現れない」ため主張が成立してしまう）。**不在を主張するテストは、存在を主張するテストと対にする。**
- **静的解析で CSV を数えない。** 本サブは当初 `awk` で CSV を集計したが、**引用符付きフィールドを持つ 1 ファイルで列がずれ**、穴の件数・層別の件数・衝突件数をすべて誤った。⇒ **正本のパーサ（`seedgen.ReadFile`）を通す。**
