## §1 製造が独自に確定した実装仕様（DES 反映が要るもの）

### 1-1 ★★`POST /api/combos/{id}/materialize` が 400 `validation_failed` を返すようになった

**着手前、本経路は `ValidateComboForCreate` を一度も呼ばず、`gen := *base` で基底を複製して `InsertCombo` していた**（`internal/service/combo/service.go`）。**⇒ 必須 4 欄（`damage` / `knockdown_advantage` / `drive_gauge_consumed` / `sa_gauge_consumed`）が空の【本登録】コンボが生成できた。**

**着手前の実測（probe）**:

```
生成された combo id=2  isDraft=false
damage=<nil> knockdownAdvantage=<nil> driveGaugeConsumed=<nil> saGaugeConsumed=<nil>
```

#### (1) 応答の実 DTO（**実行結果。転記ではない**）

```json
{
  "error": {
    "code": "validation_failed",
    "details": {
      "validations": {
        "issues": [
          { "code": "VAL-C15", "field": "damage", "message": "ダメージは本登録では必須です", "severity": "error" },
          { "code": "VAL-C15", "field": "saGaugeConsumed", "message": "SAゲージ消費は本登録では必須です", "severity": "error" }
        ]
      }
    },
    "message": "バリデーションエラーがあります"
  }
}
```

#### (2) エラー契約の全行

| 状況 | ステータス ＋ コード |
|---|---|
| 生成成功 | `200` ＋ `{ comboId, alreadyExisted:false, damageAdded, damageSkipReason }` |
| FR301 で既存一致 | `200` ＋ `{ comboId, alreadyExisted:true }` |
| 基底が見つからない | `404` `not_found` |
| 基底が PC 系（生成対象外） | `400` `hit_type_not_materializable` |
| `opponentMoveId` 欠落・ID 不正 | `400` `invalid_request` / `invalid_id` |
| **★★必須 4 欄が空の本登録基底**（新設） | **`400` `validation_failed` ＋ `details.validations`** |
| 書き込みロックが取れない | `503` `database_busy` |

#### (3) 母集団の述語

**本 VAL が掛かるのは「生成物が本登録になるとき」だけである**（`gen.IsDraft == false`）。**`gen.IsDraft` は基底からの複製であるため、仮登録の基底から生成した物は仮登録であり、必須 4 欄を要求しない**（`VAL-C15` は仮登録を完全スキップする＝`M27-02b`）。

#### (4) ★★持たせなかった分岐

- **FR301 の既存一致（`alreadyExisted:true`）は `VAL-C15` の手前で返る。⇒ 必須 4 欄が空の基底でも `200` で通る。**
  **★これは意図である**——**新しい行を作らないため**。塞ぐと、既に在る確定反撃版へ到達する手段が消える。`TestM3101_Materialize_AlreadyExisted_SkipsRequiredFields` が境界として固定した。
- **既存の生成物（4 欄が空のまま在る行）の編集・保存の挙動は 1 文字も変えていない。** `PATCH` は着手前から `VAL-C15` で弾いていた（`M27-02b`）。

**⇒ 反映依頼**:
- **`DES-002` §4.2 の `VAL-C15` 経路表（`02-architecture.md:215`）**——逐語「**`Materialize`（確定反撃からの生成）｜ ★走らない ｜ `ValidateComboForCreate` を呼ばない。⇒ 必須 4 欄が空のまま本登録コンボが生まれうる**」が**失効した**。
- **`DES-002` §4.2 の materialize エンドポイント行（`:331`）**——異常応答へ `400 validation_failed` を追加。
- **`DES-002` §4.2 (1-a) の経路列挙（`:507`）**——「**5 経路**」→ **6 経路**。実測は `grep -rn NewValidationFailedError internal/api/` ＝ 6 件。**同じ段落が「`M27-02a` は (1-a) の 5 経路だけを寄せて」と数を再掲している。**
- **`DES-006` §2.1 `VAL-C15`**——「`Materialize` は本 VAL を通らない〔抜け穴。`followup` §BI〕」が**失効した**。
