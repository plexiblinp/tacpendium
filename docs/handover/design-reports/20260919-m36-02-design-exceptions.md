### §3-3 ★★`permissions` から `artifact-metadata: write` を外した

**`actions/attest@v4` の README は 3 つ（`id-token` / `attestations` / `artifact-metadata`）を挙げる。⇒ 2 つにした。**

根拠は 2 段。(a) README 自身が `artifact-metadata` を「**artifact storage record を作る**ため」と説明し、`create-storage-record` は **`push-to-registry` が true のときのもの**である（本サブはコンテナを push しない）。(b) **アクション自身の CI が `contents: read` ＋ `attestations: write` ＋ `id-token: write` だけで動いている**（URL をワークフロー冒頭に記載。**レビュアーも独立に追認**）。

**★★ただし実走で確かめていない**（§4-1）。**⇒ rc タグの実走で権限不足が出たら、理由ごと足す。** その旨をワークフローのコメントに書いてある。

### §3-4 ★SBOM の母集団を「ソースツリー全体」にした

**配布物そのものを走査していない。⇒ できないからである。** 本体は `-tags=embed_web` でフロントのビルド成果物を**バイナリへ embed** するため、**出来上がった exe を syft で走査しても拾えるのは Go モジュールだけで、埋め込まれた npm 依存は現れない。**

**★代償を明記した**——**この SBOM は配布物より*広い***（devDependencies / `web/e2e` / 開発用スクリプトも入る）。**⇒ 「配布物に入っていないものまで載る」側の誤差であり、「入っているのに載らない」側ではない。供給網の確認という用途では安全側に倒れる。**

## §7 教訓（retrospective 行き・**親は読まなくてよい**）

### §7-1 ★★★「一次情報へ到達できないとき、二次情報を*一次情報として*書く」のが最も危ない

**レビュー 高-1。** タグ署名検証の出典に**第三者の個人リポジトリの PR** を引き、その説明文を**逐語として「一次情報」欄に**載せた。**しかも同じ記述を `release.yml` のヘッダにも書いた。⇒ コードに「一次情報が言っている」と在れば、後任は裏を取らない。**

**★背景**: `docs.github.com` と `git-scm.com` が**ともに egress proxy で遮断されていた**（`EGRESS_BLOCKED`）。**⇒ しかし遮断は理由にならない。** 実際、**`git/git` リポジトリの `Documentation/config/gpg.adoc` は到達でき、そこに答えが在った**——しかも**より強い根拠**だった（「公開鍵が `allowed_signers` に無い場合、git は信頼度を `undefined` とし `verify-tag` は失敗する」＝段 1 の (4) の直接の根拠）。

**⇒ 教訓は 2 つ。(1) 公式サイトが落ちていても、*その成果物の源泉リポジトリ*は生きていることが多い。(2) それでも届かないなら、「一次情報」と書かず格付けをそう書く。★指示書 §0.2 が求めたのは URL を付けることではなく、「いつ時点の・どの格付けの正しさか」を後任が判定できるようにすることであった。**

### §7-2 ★★★`check-*` 以外の命名で `--self-test` を書くと、誰も回さない

**レビュー 高-2。** `generate-release-notes.sh` に**陰性 4 / 陽性 2 の対照を書いた**が、`check-artifact-integrity.sh` の走査は **`find scripts -maxdepth 1 -name 'check-*.sh'` ＋ 明示 3 本**であり、**名前が `check-*` でないため対象外だった**（実測で検査 18 件に不在）。

**★★しかも同ファイルには「この文言は `check-artifact-integrity.sh` が拾うマーカーである」という*事実に反する記述*を書いていた**——**既存の `check-*.sh` からコメントごと写したためである。⇒ 写した文が、写した先では偽になった。**

**★★★これは本サブが一貫して避けてきた「在るが効かない検査」そのものである**（`D-890` の核＝**検査が在ることは、検査が効くことを意味しない**）。**門については破壊確認まで置いたのに、自分が書いた生成器の自己検査が回っていないことには気づかなかった。⇒ 「効くか」を問う対象に、*自分の検査そのもの*を入れること。**
