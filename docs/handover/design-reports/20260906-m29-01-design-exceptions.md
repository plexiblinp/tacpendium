## §7 教訓（`retrospective-log` 行き・**親は本節を読まなくてよい**）

**宛先は `retrospective-log` へのバッチ反映であり、実施者は設計担当**（反映担当は 2026-08-11 に廃止・責務は設計担当へ統合）。

1. **★★レビューの前提を検証せずに取り込むと、レビューの誤りごと実装へ入る。** 本サブのレビュー（高-2）は「`M24-07` が『1 画面で 2 系統を混ぜない』と決めた」という前提で指摘したが、**`M24-07` 自身が同じ画面の `VirtualController` を i18n 化していた**（`899c4e1`）。製造は前提を確かめずに取り込み、**事実に反するコメントをコードへ書いた。** 結論（実装側を直す）は正しかったが、理由は誤っていた。**⇒ レビューが「過去の裁定に反する」と言うときは、その裁定の実物を 1 度開くこと。** 発見したのは**開発者の実画面確認**であり、テストも型検査も緑のまま通っていた。
2. **★「エディタは i18n を通さない面である」のような面単位の断定は、部品単位で崩れる。** 実際に通していなかったのは**その部品が自分で描く文字列だけ**で、内包する別部品は通していた。**⇒ 面で語らず、描画の持ち主で語ること。**
3. **★E2E の赤は「文言で判定していた」証拠であり、事故ではない。** 本サブで 4 本が赤くなり、いずれも `getByText` に語そのものを書いていた。**文言を戻せば緑に戻るが、それでは統一の目的そのものが消える。⇒ 判定側を `data-testid` か源泉のキーへ移すのが正しい。**
4. **★spec から locale の JSON を `import` できない。** Playwright は Vite を通らない Node ESM で走るため、import attribute 無しの JSON 取込みは**起動前に全体が落ちる**（`needs an import attribute of "type: json"`）。**`readFileSync` + `JSON.parse` で読むこと。★`web/CLAUDE.md` §3 のとおり e2e は型検査もされないため、`tsc` 緑では気づけない。**
5. **★同じ testid を面ごとに分けるかは「同時に画面へ出うるか」で決まる。** 本サブは `SetupInputRow` が `SetupRecipeEditor` を描くため、コンボエディタで 2 つ同時に存在した。**⇒ 共通名を付ける前に、包含関係を 1 度たどること。**
6. **★「29 件」のような集計値は、内訳が引けないなら合わせにいかない。** 指示書とチェックリストが明示的に「合わせようとしていたら、それこそが誤り」と書いていたため踏み外さずに済んだ。**⇒ 集計値を引き継ぐ指示書には、この 1 行を書いておくと効く。**
