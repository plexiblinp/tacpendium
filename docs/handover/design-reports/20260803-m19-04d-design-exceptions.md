## §1 製造が独自に確定した実装仕様（DES 反映が要るもの）

### 1-1 HEAD スコープのテストは **専用ファイル・専用の名前空間**に置く

**確定した規約**: マイグレの契約テストは比較区間を自サブに閉じる（M19-04b §1-5 → M19-04d で始端へ拡張）。**一方、「HEAD が何であっても成り立つべき不変条件」は、`TestRun_M14xx_*` のような**サブ名の名前空間へ相乗りさせず**、`migrate_head_test.go` に `TestRun_HEAD_*` として置く。**

**理由**: 相乗りさせると、後続サブの正当な変更で「そのサブのテスト」が落ち、**原因が名前から辿れなくなる**。実際に本件（`TestRun_M1904_StartupTotalUnchanged` が M14-03e の seed で落ちる）がその形で起きた。

**★契約テストと HEAD テストは扱いが違う**——契約テストが落ちたら**実装が契約を破った**ので実装を直す。HEAD テストが落ちたら**期待値を更新するのが正しい対応になり得る**。この違いを `migrate_head_test.go` の冒頭に明記した。

- ⇒ **`SUPP-001 §5.5` へ「HEAD スコープの不変条件は `migrate_head_test.go` に `TestRun_HEAD_*` で置く」を明文化してほしい。** M19-04b §1-5 で反映依頼した「区間を自サブに閉じる」と対で書くと完結する。

### 1-2 down のスコープ条件は **up の条件をそのまま反転できない**

`000062` の up は既存値保護のため `AND startup_basis = 'unknown'` を持つが、**down にこれをそのまま持ち込むと 0 行にしか当たらない**（down の時点では値が入っているため）。

**確定した書き方**: **down は「up が付与した値そのもの」を条件にする**——`AND startup_basis = 'standalone'` ／ `AND startup_basis = 'through'` ／ `AND fastest_unreachable = 1`。キャラ限定と列条件（`is_derived = 0` 等）は up と同じものを使う。

- ⇒ **`SUPP-001 §5.5` へ併記してほしい。** M19-04b §1-2（転記マイグレは `IS NULL` を条件に持つ／down は持たない）と同じ場所に置くと、up と down の非対称性が 1 か所で分かる。

## §7 教訓（retrospective 行き）

> **★親チャットは本節を読まなくてよい。宛先は反映係（Claude Code）。** 外出先では **§1〜§4 だけコピーすれば足りる。**

3. **★「規則を再適用するサブ」では、規則の細部を守るテストが書けないことがある。** `fastest_unreachable` の部分一致は、第三波データでは前方一致と結果が一致するため**本サブでは守れない**（§4-1）。**元の規則を入れたサブのテストが唯一のガードになる。** 一般化——**規則の再適用サブを作るときは、「元のガードが生きているか」を完了条件に入れる。** 元のテストを弱めると、両方のサブでガードが消える。

4. **共有テーブルは定義ファイル名から使用者を推測できない。** `expectedMovesDelta` は `migrate_m1403c_test.go` に定義され `migrate_m1403d_test.go` から使われていた。**設計卓と製造の両方が同じ 1 か所を落とした。** 機構化するなら「**共有された期待値テーブルを消す前に参照元を全数 grep する**」を着手前確認の項目に入れる（本サブの指示書 §3-5b は実際にそうなっていた＝**前サブの応答が指示書に反映された良い例**）。

5. **区間を閉じると期待値の再測定が不要になることがある。** `m1904MovesAfter = 1028` は「HEAD が 1653 になったので更新が要る」ように見えたが、**区間を v52 に閉じたら元から正しい値だった**。**「期待値が合わない」と感じたら、まず区間を疑う。** 数字を更新するのは最後の手段である。
