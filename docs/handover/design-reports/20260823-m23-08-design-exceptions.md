### 1-2. `HardDelete` の後始末の全量（`DES-003` §3.4 / §5 へ）

**`DES-003` は「`combos` の子は `ON DELETE CASCADE` で消える」という前提で書かれているが、実装はもう CASCADE に依存していない。**

#### 実装の全量（順序どおり）

| # | 操作 | 対象 |
|---|---|---|
| 1〜2 | 明示削除（**既存**） | `combo_setup_results` → `combo_setups` |
| 3〜7 | 明示削除（**`M23-08` で追加**） | `combo_steps` / `combo_tags` / `combo_oki_options` / `combo_punishes` / `combo_punish_curations` |
| 8〜9 | **参照の NULL 化**（`M23-08` で追加） | `combos.materialized_from_combo_id` / `combos.superseded_by_combo_id` |
| 10 | 行の削除 | `combos` |

#### ★self-FK 2 本の扱いが宣言と実装で違う（明文化が要る）

| 列 | スキーマの宣言 | 実装 | なぜ |
|---|---|---|---|
| `materialized_from_combo_id` | **`ON DELETE` 句なし**（既定 `NO ACTION`。`migrations/000038:6`） | **コードで NULL 化** | 宣言のままでは FK=ON の接続で完全削除そのものが `FOREIGN KEY constraint failed (787)` で落ちる（実測） |
| `superseded_by_combo_id` | **`ON DELETE SET NULL`**（`migrations/000078:13`） | **コードでも NULL 化** | **宣言はあるが発火が保証されない。** `migrations/000078:7-9` 自身が「連鎖動作は保証されない」と書いている |

**★どちらも「削除」ではなく「NULL 化」である。** materialize 生成物は基底とは独立した利用者のコンボであり、消すとデータが失われる。**★`version` / `updated_at` は動かさない**（参照が外れただけで内容は変わっていない。`UpdateWithKeyChange` の `superseded_by_combo_id` 打刻と同じ判断）。

**★スキーマは変えていない。** SQLite は制約の `ALTER` を持たず表の作り直しになるため、コードで解いている（指示書 §4.2-1 / §4.8）。

**⇒ `DES-003` §3.4 の FK 記述へ「宣言された `ON DELETE` は意図の記録であり、完全削除の実挙動は `HardDelete` が持つ」を明文化してほしい。** 現状は宣言を読んだ人が実挙動を誤解する。

### 1-3. `SoftDelete` の 0 行分岐の仕様

**述語を足したことで `RowsAffected` だけでは「存在しない」と「既に削除済み」を区別できなくなった。** 実装は行の存在を数え直して分けている。

| 状態 | `RowsAffected` | 戻り値 | HTTP |
|---|---|---|---|
| 生きた行 | 1 | `nil` | **204** |
| **既に削除済み** | **0** | **`nil`（成功）** | **204**（`deleted_at` は最初の値のまま） |
| 行が無い | 0 | `ErrNotFound` | **404** |

**★API の応答形は 1 バイトも変わっていない。** 変わったのは `deleted_at` が動かなくなったことだけである。

**根拠**: `internal/repository/combo/repository.go` `SoftDelete`。テスト＝`TestSoftDelete_SecondCallStillSucceeds` / `TestSoftDelete_SecondCallDoesNotOverwriteDeletedAt` / `TestSoftDelete_MissingRowStillReturnsNotFound`。
