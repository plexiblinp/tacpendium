## §3 製造判断（裁量内・報告のみ）

### §3-1 案 (a) を採った（指示書の推しどおり）／ 置き場は **Go 側**にした

**案の選択**は指示書が推す **(a)**（元技の `startup` が NULL なら `'unknown'`）。案 (b) は UX が変わり承認が要るため採っていない。

**置き場**（指示書 §2.2-2 が「実装判断でよい」とした点）は **SQL の `CASE` ではなく Go 側**を採った。理由 4 点:

| # | 理由 |
|---|---|
| 1 | **`CLAUDE.md` §4「列挙的文字列定数はパッケージ定数として定義」へ戻せる。** `model.MoveStartupBasisThrough` / `...Unknown` は既に在り、**SQL リテラルだけがその外に居た** |
| 2 | **`CASE WHEN ? IS NULL THEN … END` は `src.Startup` を 2 回バインドすることになる**（`startup` は同じ `VALUES` 行の中から参照できないため）。既に 14 個ある `?` の対応がさらに読みにくくなる |
| 3 | **述語に名前が付き、godoc から `DES-003` §3.3 (i) / `D-187` へ辿れる** |
| 4 | **`M19-04` §4.5 の実質は保たれる**（列は明示列挙のまま・値は常に明示的に与える。DEFAULT へ委ねていない） |

**★設計卓は「SQL 側の `CASE` を想像しているが実物を見ていない」と指示書に書いていた。** ⇒ 実物を見た結果、上記の理由で Go 側を採った。**異論があれば差し戻してほしい**（機能は同一であり、置き換えは数行である）。

### §3-2 不変条件の検出式を 2 か所に持つことにした（**共有できないのではなく、共有しないことを選んだ**）
