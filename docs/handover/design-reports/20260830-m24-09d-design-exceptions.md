## §1 製造が独自に確定した実装仕様（DES 反映が要るもの）

### §1-1 ★★テスト DB のテンプレート方式の as-built（`SUPP-001` §5.5 へ反映）

`CHANGE-145` §2.1.2 は 4 項目を挙げていたが、**「形」は製造裁量（指示書 §2.3）としていた。確定した形は次のとおり。**

| 論点 | 確定した形 | 所在 |
|---|---|---|
| **保存先** | **メモリ上の `[]byte`**（ファイルとして残さない） | `internal/testutil/dbtest/dbtest.go`（`templateBytes`） |
| 1 回性 | `sync.Once`。**失敗は `templateErr` に残し、以後すべての `Setup` を落とす** | 同（`templateOnce` / `templateErr`） |
| 除外の実現 | **`dbtest.DisableTemplate()` を `TestMain` から呼ぶ** | `internal/infra/migration/template_exclusion_test.go` |
| **除外が効いていることの観測** | **`dbtest.MigrationRunCount()`**（マイグレーション実行回数そのもの） | `internal/testutil/dbtest/dbtest.go` |
| 除外対象 | **`internal/infra/migration` の 1 本のみ** | 同（`templateExemptPackages`） |

**★保存先をファイルにしなかった理由**——**Go にはプロセス終了時に走る後片付けの経路が無く、ファイルで持つとテストバイナリ 1 本につき 1 個の DB（実測 925,696 バイト）が `/tmp` に残る。** バイト列なら `-wal` / `-shm` の混入経路も構造的に消える。

**⇒ `SUPP-001` §5.5 の小節へ、`CHANGE-145` §2.1.2 の 4 項目に加えて「保存はメモリ上のバイト列である」「除外の観測点は `MigrationRunCount()` である」を明文化してほしい。**

### §1-2 ★★`CHANGE-145` に無い機構を 1 つ足した——**除外の「逆向き」のガード**

**`CHANGE-145` §5 のリスク 2 は「除外すべきパッケージを見落とす」だけを挙げていた。逆向き（除外すべきでないパッケージが除外される）に検出器が無かった。**

**★逆向きは静かに壊れる**——**除外しすぎても、テストは全部緑のまま遅くなるだけである。** 本サブが立てた「速度は根拠にならない」の裏返しがそのまま当てはまる。

**⇒ `DisableTemplate()` が `runtime.Caller` で呼び出し元パッケージを見て、`templateExemptPackages` に無ければその場で落とす形にした**（`internal/testutil/dbtest/dbtest.go`）。外部テストパッケージ（`..._test`）は元のパッケージへ丸める。**実際に発火することを確認済み**（完了報告 §4.3.1 に出力）。

**⇒ `SUPP-001` §5.5 の除外規定へ「除外の許可一覧はコード側（`templateExemptPackages`）が持ち、一覧外からの呼び出しは実行時に落ちる」を明文化してほしい。** **★これが無いと、後任は「一覧を増やすには実装を触る」という設計意図（増やす判断を明示的にする）を知らないまま、迂回路を作りうる。**

### §1-3 ★★nightly の E2E job の as-built（`SUPP-001` §4.5 へ反映。**条件は満たされた**）

**`CHANGE-145` §2.2 は「§4.3 が成立した場合のみ反映する」としていた。⇒ 成立した。**

**CI 実機での観測**（2026-08-30・**マージ前**に開発者が本ブランチで手動起動。`Run workflow` → `Use workflow from:` でブランチを選択）:

| 項目 | 値 |
|---|---|
| **判定** | **緑** |
| **passed** | **215 passed** ／ failed 0 ／ flaky 0 |

**as-built の要点 3 点**:

1. **`web/playwright.config.ts` は 1 行も変えていない。** job は `make e2e` をそのまま呼ぶ（理由は §2-3）。

**★2 と 3 が必要だったかは切り分けていない**（どちらも通ったが、外しても通るのかは試していない）。**⇒ 「効いた」とは書けない。外すときは実測が要る。**

**⇒ `SUPP-001` §4.5 へ「E2E は nightly で回る。`pr-checks.yml` には載せない。nightly でも `workers: 1` を維持する。これが main の E2E が緑かを独立に知る唯一の経路である」を反映してほしい**（`CHANGE-145` §2.2 の 3 項目）。**★あわせて同節の逐語「CI は本フェーズでは構築せずローカル実行」は失効している**（`supp-001-detailed-design.md:570`）。
