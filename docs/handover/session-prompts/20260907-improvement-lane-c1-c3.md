## C3 — `check-md-emphasis.sh` の案 A（**本体。3 つの部分がある**）

### 何が問題だったか（**先に読むこと**）

2026-09-06 の実測で、検出が **1,052 行**、ベースラインが **436 行**、
**616 行の超過**でした。

**問題は走査範囲ではなく、直す義務の置き場です。**
床は「書いた本人が自分の追加分を直す」を前提にしています。ところが
1,052 行の主部は `docs/progress/` の完了報告であり、完了報告は歴史記録として
書き換えません（設計卓の裁定 `D-274` (3) と同じ流儀）。
**2 つの規則が正面から食い違い、誰も直さないまま床だけが上がっていました。**

**★1,052 行は 3 種の混合です。**
(i) 本物の閉じない強調 ／ (ii) 歴史記録の中の、直さない行 ／ (iii) フェンス内の擬陽性。
**1 つの数として扱うと、どれを直しても減らないように見えます。**

### やること（**★この順で**）

1. **常時走査を 5 つへ狭める。**
   `docs/process` / `docs/handover` / `docs/instructions` / `docs/design` /
   `docs/change-notes`。**除外は現行どおり `archive/` と `/phase[0-9]+/`。**
   `docs/progress` を常時走査から外します。

2. **★★`docs/progress/` を「書き込み時に見る」形にする。**
   - スクリプトに **ファイル引数モード** を足してください。
     引数で渡されたファイルだけを検査し、ベースラインと比較せず、
     **そのファイルに閉じない強調が 1 行でもあれば非ゼロで終わる**形です。
   - **サブが完了報告を書いた手番で、自分が新しく作ったファイルだけを検査する**
     運用にします。**完了条件へ 1 行足す先は 4 つです**——
     `.claude/commands/implement_plan.md` /
     `.claude/commands/implement_plan_full.md` /
     `.claude/commands/incorporate_plan.md` /
     `docs/instructions/templates/M{N}-{NN}-{slug}.template.md`。
     **★実際に存在するファイルを確かめてから足してください。**
     **★足せなかったものは、足せなかった理由を報告してください。**

   **★★(2) を落とすと、この変更は別物になります。**
   2026-08-15 に `docs/progress/` を走査へ入れた理由は今も生きています。
   **その理由＝読めない行が残ると、次の担当が事実を取り違える**
   （`M20-07` と `M21-06` が独立に挙げました）。
   **変わるのは検査の時点だけです。**

3. **狭めた後にベースラインを測り直す。**
   `bash scripts/check-md-emphasis.sh --list` を回し、新しい実測値を
   `BASELINE_BROKEN` に入れてください。
   **★スクリプト内の該当箇所に、いつ・なぜ・いくつからいくつへ変えたかをコメントで残してください。**
   既存のコメントが同じ形をしています。
   **★下がるはずです。上がったら、狭め方が効いていないので報告してください。**
