## 5. architecture-patterns.md v1.0.3 §1.1 queryKey 規約の M5+ 統一リファクタ判断

### 5.1 現状(v1.0.3)

`architecture-patterns.md` §1.1 で「コードベースには flat tuple と object 形式が混在している」と明示済み:

- combo 系: flat tuple 形式(`['combo', 42]`、`['combos']` 等)
- setup 系: object 形式(`['setups', { characterId }]` 等)

規約の核心は **number 正規化のみ**、structure は同一ドメインの既存フックの実態に揃える運用。

### 5.2 統一リファクタの判断基準

M5+ 期間で統一リファクタを検討するタイミング:

- (a) setup 系または combo 系のフックを大規模に追加する場合(混在が深まる前に統一)
- (b) UI 層リファクタ(C-2 / C-3)と同時に整理する場合
- (c) ドメインを跨いで invalidate する場面が増えた場合(混在で混乱が増える)

判断は M5 期間担当 Claude が M5 着手時に判断。**現時点では統一は必須ではなく、混在のまま運用継続**(YAGNI)。

### 5.3 リファクタ実施時の注意点

- バックエンド変更なし(クエリキャッシュの structure 変更のみ)
- 影響範囲: 該当ドメインのフック実装ファイル + invalidate を呼ぶ箇所
- テスト: queryKey に依存するテストの修正が必要
- CHANGE 通知書要否: 不要(architecture-patterns.md の改訂のみで完結、M4-15 由来教訓と整合)
