### 7.2 製造担当の Plan Mode 反問を歓迎する運用(retrospective-log v1.0.25 §6.10)

- 設計担当の暫定推奨は **検討の出発点** = 製造担当の実コード把握 + 既存パターン発見 + 別 UX 意図発見によって覆る前提で運用
- 本セッション内で **3 件連続成功**(C-2 β / 必須項目 5 b / C-4 HomePage 除外)+ 1 件追加(Q28 (A) モーダル再オープン時の前回キャラ保持、製造担当の自己判断承認)
- 製造担当の反問 = 設計品質向上の理想形、M7-04 / M7-05 でも歓迎継続

### 7.3 製造担当の自主修正 + 設計担当への確認依頼運用(retrospective-log v1.0.25 §6.9.6 + v1.0.26 §6.6 M7-13)

- 製造担当が実装中・E2E 中に発見した既存問題 → 設計担当が判断 → 開発者ご判断 → 即解消の流れ
- **CHANGE 起票しない判断基準** 4 条件:
  1. 設計書本体改訂を伴わない(CHANGE 通知書不要)
  2. 製造担当のコンテキスト範囲内で修正可能
  3. 修正範囲が極小
  4. 完了承認スコープに編入することが製造担当・設計担当・開発者の全員にとって効率的
- M7-04 / M7-05 でも同種運用継続(Q22 案 A 修正 = 本セッション編入の前例継承)

### 7.4 「こうしてはいけない」明示運用(architecture-patterns v1.0.10 §7.7)

- M7-03 製造担当伝達 3 で確立: 「こうする」パターンだけでなく **「こうしてはいけない」明示** で予防効果を生む運用ノウハウ
- §7.7 で本プロジェクト初の禁止事項明示パターン確立
- M7-04 / M7-05 + フェーズ 2 以降の同種逸脱予防に有効
- 他の正式化済みパターンへの横展開候補(architecture-patterns v1.0.10 §9 更新履歴で言及)
