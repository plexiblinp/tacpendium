## 2. M6 期間の主要決定事項

### 2.1 下書き自動保存機能の廃止(CHANGE-016)

- **判断根拠**: M6-02 / M6-03 までの動作確認結果から「過剰」と評価、YAGNI 原則
- **影響範囲**: REQ-001 FR603 / FR603a 論理削除、DES-005 §5.7 廃止注記、CLAUDE.md 物理削除、SUPP-001 §4.1 / architecture-patterns §5 論理削除注記
- **復活時の手順**: CHANGE-016 §9 復活時手順参照、論理削除パターンのため復活コストは低い

### 2.2 ウィザード `[defaults]` セクションの永続化(M6-02 v1.0.1 / 確認事項 1 案 2-c 採用)

- **背景**: M6-02 ドラフト v1.0.0 で「デフォルト表示キャラ / デフォルトプリセット」永続化を当然視したが、M6-01 で確定した `Config` 構造体に対応フィールドが存在しなかった(M6-2 反省 + retrospective-log v1.0.19 §6.1)
- **採用案**: `config.go` に `DefaultsConfig` 構造体追加 + `Config.Defaults` フィールド追加 + SUPP-001 §5.8 設定ファイル例追記
- **以降の設計担当への教訓**: ウィザード / 設定画面の表示項目 ↔ Config 構造体 ↔ SUPP-001 §5.8 設定ファイル例 の三者一致を Plan Mode 必須項目に明示する

### 2.3 ヘッダ「設定」リンク追加(M6-02 v1.0.2 / M6-6 由来)

- **背景**: M6-02 v1.0.1 で `/settings` ルート追加したが、ヘッダから遷移する手段を追加し忘れていた(URL 直入力以外で `/settings` に到達できない UX 劣化)
- **採用方式**: ヘッダのプリセットリンク disabled 化 + 設定リンク追加の 2 修正併記、§4.5.7 を 3 サブセクション構成に拡張
- **残課題**: 他ページのヘッダへの反映は別指示待ち(残課題 3、§3 参照)

### 2.4 スマホフッターの全画面共通配置(M6-03 / 案 B 採用、設計書本体規定優先)

- **指示書での推奨**: 案 C(Plan Mode で既存 Header 配置方式に揃える)
- **製造担当 Plan Mode 時の決定**: 既存 Header が per-page 実装と判明 → 論理的帰結は案 A(per-page)だが、DES-005 §4.2 規定「全スマホ画面で固定ナビ」要件を優先して案 B(`App.tsx` グローバル)採用
- **playbook §0.2 設計書本体優先の実例**: 既存実装パターン vs 設計書本体規定の優先順位を製造担当が正しく判断した好例
- **設計担当への教訓**: 案 C(既存実装に揃える)を Plan Mode 必須項目に立てる場合、「既存実装が設計書本体規定と乖離する可能性」をあらかじめ想定し、その場合の優先順位を指示書本文に明示する(M6-9 候補、後述 §4)

### 2.5 `useRecentCombos` の character_id フィルタ採用案(M6-03 / Plan Mode 中の追加質問)

- **製造担当質問**: 3 案(全キャラ横断 / `defaults.characterId` 使用 / `INITIAL_CHARACTER_ID` 使用)
- **採用**: 案 1(全キャラ横断、character_id フィルタなし)
- **判断根拠**: DES-005 §5.2「最近更新したコンボ」規定に特定キャラ縛りなし、ホーム画面の役割は「各画面への入り口 + 最近の活動の概観」
- **設計担当への教訓**: 指示書執筆時に API のオプショナルパラメータの扱い指針の網羅性確認が漏れた(M6-7 候補、後述 §4)

### 2.6 P-1 持ち越し課題のフェーズ 2 送り確定(M6-04 完了承認時 / 候補 A 再協議)

- **背景**: プリセット管理画面 `/presets`(DES-005 プリセット一覧 / プリセット編集画面の節)の実装位置づけ
- **3 案評価**: (i) M7 で作成 / (ii) 新規 M6.5 / (iii) フェーズ 2 送り
- **採用**: 案 (iii) フェーズ 2 送り
- **判断根拠**: 開発者ご指摘「複数キャラ投入後の再検討が必要な設計事項あり」(キャラクター固有技名のプリセット扱い等)、フェーズ 2 で複数キャラ追加後に再設計判断
- **設計担当推奨は案 (i)** だったが、開発者の運用判断を尊重して案 (iii) 採用
- **反映**: SUPP-001 v1.16.0 §4.1 M7 行末尾に注記追加(自由改訂、CHANGE 通知書不要、REQ-001 / DES-005 にプリセット管理機能のフェーズ分類記述が元から存在しないため)

### 2.7 残課題 4 軽微修正(M6-04)

- **内容**: 設定画面ネットワークセクションのローカルモード表示が M6-02 v1.0.2 §4.5.4 規定通り `127.0.0.1:<port>` に修正
