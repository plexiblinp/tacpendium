### 4.2 重要な設計判断(M6-03 着手前に確定すべき項目)

#### 4.2.1 スマホ判定方式

DES-005 §4.4 ブレークポイントに準拠:
- スマホ: 〜640px(`sm` 未満)
- タブレット: 641px〜1024px(`md`, `lg`)
- PC: 1025px〜(`xl` 以上)

選択肢:
- (a) Tailwind ブレークポイント(CSS のみで切替、JS なし)
- (b) JS でメディアクエリ監視 + 条件レンダリング

**設計担当の暫定推奨**: (a) Tailwind ブレークポイント(M6-02 §4.5.3 と整合、シンプル)。ただしホーム画面の場合は **PC ではホーム画面自体をスキップしてコンボ一覧へ直接遷移** する必要があり、JS による条件付きリダイレクトが必要(Plan Mode で確定対象)

#### 4.2.2 アプリ起動時のリダイレクト分岐

M6-02 v1.0.1 では「ウィザード完了後はコンボ一覧へ固定遷移」と確定(M6-overview §2.5)。M6-03 では:

- **スマホ判定 + isInitialized: true** → スマホ専用ホーム `/home`(または `/`)
- **PC/タブレット判定 + isInitialized: true** → コンボ一覧 `/combos`(または `/`)
- **isInitialized: false** → `/wizard`(M6-02 既存)

ルート設計: `/home` を新設するか、`/` をスマホ判定で出し分けるか(Plan Mode で確定)

#### 4.2.3 「最近更新したコンボ(上位 3 件)」の取得

- 既存 `GET /api/combos` を使用、`sort=updated_at_desc&limit=3` 等のクエリパラメータが既存ならそれを使用
- 既存パラメータが不在なら新規追加 or フロント側でソート + slice
- **M6-03 着手前に既存 API の Query パラメータを view 確認必須**(M6-1 反省踏襲)

#### 4.2.4 推奨モデル

Sonnet 4.6(関心数 1 + UI 規模中、Opus 4.6 ほどの複雑性なし)。Plan Mode は任意。

## 5. M6-04 指示書作成方針(下書き自動保存 + M6 統合 E2E)

### 5.1 スコープ(M6-overview §4.5 規定)

  - DB ベース?(下書き専用テーブル新設?)
  - サーバー保存 API 新設?

### 5.2 重要な設計判断(M6-04 着手前に確定すべき項目)

#### 5.2.1 下書き保存方式の選定

選択肢:

| 案 | 内容 | メリット | デメリット |
|---|------|--------|---------|
| (a) localStorage | フロント側のみで完結 | バックエンド変更不要、シンプル | LAN 共有モード時に他端末で下書き継続不可、複数ユーザー対応不可(フェーズ 2 関連) |
| (b) DB ベース(drafts テーブル新設) | 完全な永続化 | 他端末・他ユーザー対応可能 | マイグレーション + バックエンド API 追加 = M6-04 スコープ膨張 |
| (c) サーバーメモリ(セッション内のみ) | 軽量 | 実装シンプル | 再起動で消失、永続性なし |

**設計担当の暫定推奨**: (a) localStorage(CLAUDE.md §10.X 既存運用 + YAGNI、フェーズ 2 で DB 永続化に移行可能)。ただし設計書本体 FR603 の規定を view 再確認してから判断

#### 5.2.2 自動保存タイミング

選択肢:
- (a) フィールド変更時に都度保存(debounce 500ms 程度)
- (b) ページ離脱時のみ保存
- (c) 定期間隔保存(30 秒など)

**設計担当の暫定推奨**: (a) debounce(UX 上最も自然、M3-04 マイコンボ画面の挙動と整合)

#### 5.2.3 下書きキー設計

localStorage キー命名規約(CLAUDE.md §10.X 規定が存在する場合は踏襲):
- `combomgr:draft:combo:new` (新規コンボ登録)
- `combomgr:draft:combo:{id}` (既存コンボ編集)

**設計担当の暫定推奨**: 上記形式 + キー命名は Plan Mode で確定

#### 5.2.4 M6 統合 E2E シナリオ

M6-01 + M6-02 + M6-03 + M6-04 の統合動作確認:
- 初回起動ウィザード完了 → スマホホーム or コンボ一覧 → コンボ登録(下書き保存動作)→ ブラウザリロード → 下書き復元
- LAN モード設定 → 別端末から接続 → 下書き保存(同一端末 localStorage 範囲、他端末は別の下書き)
- 設定画面のデフォルトキャラ / プリセット変更 → コンボ登録画面に反映

#### 5.2.5 推奨モデル

Sonnet 4.6(関心数 1 + UI 規模中、ただし M6 統合 E2E のシナリオ作成は慎重に)。Plan Mode 必須。

### 5.3 §3.4 着手前確認の必須項目(M6-3〜M6-6 反省踏襲)

1. **対応表作成(M6-6 反省踏襲、最重要)**:
   - FR603(下書き保存)が対象とするコンボ登録・編集画面の全フィールドと、`localStorage` 等の既存ストレージ運用の対応関係
   - M6 統合 E2E がカバーすべき機能範囲(M6-01 〜 M6-04 すべて)

4. CLAUDE.md §10.X ブラウザストレージ運用ルール再確認
