## 0. このドキュメントの位置づけ

本書は M5(コンボ比較系)完了状態を整理し、M6(初期体験系)着手の現在地・持ち越し課題を M6 期間担当 Claude に引き継ぐマイルストーン固有の資料。プロジェクト恒久の運用ルール・反省・アーキテクチャパターンは B グループ(`design-instruction-playbook.md` / `retrospective-log.md` / `architecture-patterns.md` / `change-number-registry.md`)を参照する。

M6 統合可否判定(同一チャットで M5 + M6 を続けるか、M6 を新チャットで開始するか)は本書作成後に開発者と協議する想定(m4-to-m5-handover.md §0 案 3 余地、M5-overview v1.0.1 §7 想定スケジュール step 10)。判定結果に関わらず、本書は M5 完了状態の整理として価値を持つ(案 P 採用、開発者承認 2026-05-23)。

### 5.3 判定材料

| 項目 | M5 期間実績 | M6 統合採用時のリスク |
|------|----------|--------------------|
| M5 サブマイルストーン数 | 2(M5-RESEARCH-01 + M5-01) | M6 単独で 3〜4 サブマイルストーン分割見込み、合計 5〜6 サブマイルストーンを 1 チャットで扱うのは過剰の可能性 |
| M5 期間設計担当ミス件数 | 2 件 + 候補 1 件(M5-1 + M5-2 + M5-3 候補) | 3 件以上発生 = M4 期間 18 件と同種の構造的リスク再発の前兆ではないか要評価 |
| M5 期間 CHANGE 通知書起票数 | 1 件(CHANGE-015) | M6 で新規 CHANGE 起票が複数発生する場合、設計書本体改訂作業の集中で混乱リスク |
| M6 関心領域の数 | (M6 着手前) | 5 領域(ウィザード / 設定 / スマホホーム / 下書き保存 / LAN バインド)、M2 / M3 / M4 と同規模 |

### 5.4 設計担当(M5 期間担当)の見解

M5 期間設計担当ミスが 2 件発生(M5-1 + M5-2)で M5-3 候補 1 件は判断保留中。**M4 期間(18 件)よりは大幅に少ないが、3 件以上発生していると統合採用のリスク評価が必要だった**。現時点では「許容範囲内」と評価しつつ、M6 統合採用時は **M5 期間反省 3 件分の構造的問題が M6 期間に持ち込まれる** ことを意識する必要がある(同一チャット内ではコンテキスト継承で同種ミス再発リスクが残る)。

私(M5 期間担当)の推奨は **m4-to-m5-handover §0 推奨案 1(分割)に近い形**: M6 単独で 3〜4 サブマイルストーン分割が見込まれ、handover §2.1 で示した M6 スコープ 5 領域は M5 比較画面 1 画面とは規模感が大きく異なる。M5 期間でのチャット切替コストが「最近は切替のための体制が整ってきている」(2026-05-23 開発者ご回答)とのことなので、分割側の負担も軽減されている。

ただし最終判断は開発者に委ねる。

- 開発者ご回答「特に負担でもなければ、こだわりもないので、調査用のチャット 1 本で調べさせる事に異論なし」(2026-05-23)で確定
