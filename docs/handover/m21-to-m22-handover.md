## 4. ★運用の変更点（M20 / M21 の期間に決まったもの）

### 4.1 `followup-backlog.md` の書き手を設計卓のみにした（**D-382**・2026-08-14）

**製造は本表を編集しない。設計伝達レポート §4 へ候補を書き、設計卓が反映時に畳む。**

- **★理由は git である**——**同ファイルは設計卓と製造が書く唯一の共有ファイルであり、両方が既存行を編集すると main へのマージが競合し、開発者が端末でしか解消できなくなる。**
- **★例外は §J 停止時記録のみ**（製造が末尾へ直接追記する。`CLAUDE.md` §9 の停止規律）
- **★製造が書く候補には「設計卓が迷わず追加できる形」を求める**——**スラッグ ／ 何が起きるか ／ 再現条件または根拠 ／ 割付の候補と理由 ／ 新規か既存行の更新か**
- **★設計卓が迷ったら、推測で書かず開発者へ質問をリレーする**
- 反映先＝`.claude/commands/design_handover_report.md` ／ `docs/handover/followup-backlog.md` ヘッダ ／ `CLAUDE.md` §10.Y

### 4.2 設計卓ブランチの扱い

- **設計卓ブランチへ main を取り込まない。** **競合解消は main 側で行う**
- **★Claude Code on the web の PR 画面の「Resolve conflicts」は解消コミットを head ブランチに入れる。** **⇒ 設計卓ブランチが長命のうちは使わない**
- **万一 head へ解消コミットが乗ったら、その枝は捨てる**——**新しいセッションを main から開き、その手番ぶんを載せ直す**（手戻りは 1 手番分）
- **★§4.1 を守れば、そもそも競合しないはずである**（共有ファイルが無くなるため）

### 4.3 `go.mod` の indirect → direct 昇格は事前提案が要る（**開発者裁定 2026-08-14**）

**`CLAUDE.md` §6 に明記した。** **「モジュールは既に依存グラフに居た」「`go.sum` は不変」は理由にならない。** **先例＝`golang.org/x/text`（`M20-07`）。事後に開発者が承認した。**

### 4.4 実測値の置き場を契約テストへ寄せた（**開発者裁定 2026-08-14**）

**`DES-003` §3.9 の規約（`D-374`）を、マイグレの先頭コメントへも広げた**（`SUPP-001` §5.5.3.1）。**★適用済みのマイグレは改変できないため、設計書より条件が悪い。**
