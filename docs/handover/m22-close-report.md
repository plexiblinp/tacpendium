## §0. 結論

**M22 をクローズする。**

**引き渡したもの**——**LAN の中で複数人が同じデータを触っても、後から保存した側が先の変更を黙って消さない状態。** あわせて **入場（簡易パスワードとセッション）・接続導線（QR）・設定変更系 API の境界**を揃えた。

**★本マイルストーンの性格は「作る」より「効かせる／立証する」だった。** `combos.version` / `setups.version` は着手前から実在し（契約 §1.4）、CORS/CSRF の境界も既に妥当で、QR も既に実装済みだった。**⇒ M22 の成果の相当部分は「既に在るものが本当に効いているかを固定した」ことであり、本番コードの差分が 0 バイトで完了したサブが 1 本ある**（`M22-06`）。

**★数え方を先に固定する**（`E-93`＝どこからどこまで数えたかを併記する）。**本報告が数える単位は 10 である**——**実装サブ 8 本**（`M22-01`〜`M22-08`）**＋ 追補サブ 1 本**（`M22-07b`）**＋ 調査サブ 1 本**（`M22-RESEARCH-01`）。**既存記録の「全 9 サブ」は `parallel-board` §1.6 の表の行数であり、`M22-07b` を含まない**（同サブは `D-442` で後から新設され、表へ行が足されなかった）。**判定と内容は数え方によらない。**

**★本報告は「終わったこと」だけでなく「終わらせなかったこと」と「その理由」を書く。** 否定形の記録が無いと、後任が同じ検討を最初からやり直す（`E-120`）。

## §4. ★既知の限界（**必ず引き継ぐ**）

### 4-1. 平文 HTTP を前提にしている（契約 F-3）

**M22 は HTTPS を導入していない。** **⇒ パスワードは平文で LAN を流れる。** **★「安全である」と書いてはならない。書けるのは「この条件下でこう振る舞う」までである。** これは欠陥ではなく、`architecture-patterns` §10「信頼できないネットワークを前提にしない」という本アプリの設計前提の帰結である。

### 4-2. ログインはアクセス制御でも監査でもない

**`FR501` の本文が目的を明示している**——「**他の利用者の編集を誤って上書きすることを防ぐ**」。**⇒ `FR013`（コンボ・セットプレイは作成者の概念を持たない ／ 監査ログは実装しない）と整合する。** **★後任が「認証を入れたのだから所有者も持たせよう」と考えるのは自然だが、それは `REQ-001` の必須要件の改訂を要する**（契約 F-1）。

### 4-3. `PUT /api/combos/:id` に負けた側は 409 ではなく 404 を受け取る

**キー変更編集は旧行を論理削除して新 id で採番し直すため、負けた側が見に行く行がもう無い**（`D-413`）。**実装として正しく、直す対象ではない。** `M22-04` の追補が導線を 2 本用意して行き止まりを塞いだ（`D-417`）。**★M23 はこの事実の上に乗る**——§6-1 を参照。

### 4-4. `updated_at` と `version` が同期しない書き込みが実装上存在する

`recipe_cache` の更新は `version` を据え置くが `updated_at` は進む（`M22-overview` §4.2.2）。**仕様として明記済み**（followup `updated-at-version-desync-on-recipe-cache`）。

### 4-5. `PRAGMA foreign_keys` の接続単位問題（`P-04`）は解決していない

**M22 は触れていない。** `ON DELETE CASCADE` に依存している既存テーブルすべてで CASCADE が発火しない可能性が残る（`architecture-patterns` §11 ／ ボード `P-04`）。**★M23 の直接の前提になる**（§6-1）。

## §7. 残ゲート（**クローズを止めない**）

> **★M19 の先例に倣う**——**残ゲートを明記したうえでクローズすることは、規律違反ではなく正規の完了形式である**（`CLAUDE.md` §9 停止規律）。**★3 件とも「M22 の成果が動くかどうか」ではなく「体験の確認」または「別サブで扱う」性格である。**

### 7-1. 別名辞書の「増やす」は塞がれたまま（観点 7）

**`preset_aliases` の `UNIQUE (preset_id, move_id)` が、既に別名を持つ技への 2 本目の投入を塞いでいる。** 追跡＝`followup-backlog` §J `alias-dictionary-enrichment-blocked-by-one-alias-per-move`。**再開条件＝投入方式の選定**（`D-440`。§6-3）。**★M22 の目的（取込の逆引きが解ける）は `M22-07b` が規則で達成しており、本ゲートが塞いでいるのは「辞書を増やす」という手段のほうである。**

### 7-2. `DES-005` §6.8 への M22 の追記（観点 9）

**逐語の「§6 の diff が 0」は成立していない。** 追記は `CHANGE-115` / `CHANGE-119` の 2 件で、いずれも test-id 台帳への加算。**⇒ 是正は不要と判定した**（契約 F-4 の目的は満たされている）。**★記録する理由は、後任が「§6 の diff が 0」を字義どおり検算したときに食い違って見えるためである。** **★観点の書き方の側に誤りがあった**——`DES-005` §6 は「物理入力」の節番号でありながら、§6.8 だけが横断的な test-id 規約を持っている。**⇒ 次に同型の凍結を書くときは「§6.1〜§6.7」と範囲を切ること**（§8-2）。

### 7-3. セットプレイの同時編集は未確認（観点 12）

**開発者の実機確認はコンボについて実施済みだが、セットプレイ（`PATCH /api/setups/:id`）については未確認である。** **★リスクは低い**——`setups` の突き合わせは `M22-03` の契約テストで固定され、`M22-04` の見せ方は「コンボ」を「セットプレイ」に読み替えた同一仕様である（`DES-005` §5.9）。**★ただし 1 点だけ非対称がある**——**セットプレイには 404 の経路が無く（キー変更編集が無い）、409 だけが出る。** **⇒ 確認するなら「409 のモーダルが出て、入力が保持されていること」の 1 点で足りる。** **★M23 のゴミ箱・復元も同じ多端末面に乗るため、M23 の実機確認と一緒に見るのが安い。**

## §8. ★設計卓の誤りの記録

> **`E-88`〜`E-98` / `E-102`〜`E-123` と同じ趣旨**——「誰かが間違えた」ではなく **「この役割は構造的にこの形で間違える」** という記録。

### 8-1. 起票時に「実装する」前提で指示書を書いた（`M22-06`・`E-117` の型）

**`M22-06` の初版（v1.0.0）は QR を「実装する」前提で書かれていた。** **実際には `qrcode.react@4.2.0` ／ `QRCodeModal.tsx` ／ i18n 4 キー ／ テスト 3 ケースが既に在り、本番コードの差分は最終的に 0 バイトだった。** **★本レーンで 3 件目の同型である**（board §1.6 の逐語）。**⇒ 「作る」と書く前に `code-facts` を引く。**

### 8-2. 凍結の範囲を節番号で切ったが、その節が単一の主題を持っていなかった（`F-4`）

**契約 F-4 は `DES-005` §6 を「物理入力」として凍結したが、§6.8 は横断的な test-id 規約であり物理入力ではなかった。** **⇒ 凍結の範囲を節番号で切るときは、その節が単一の主題を持っているかを確認する。** **★`D-379`（`M-65`＝包括表現を使わない）の裏側である**——あちらは広すぎる指定、こちらは**節番号という一見精密な指定が、実は主題の異なる小節を巻き込んでいた**ケース。

### 8-3. 判定表の実測値を指示書へ写して、2 サブぶん古くなった（`D-413`・`E-56` の亜種）

**`M22-RESEARCH-01` の実測「`version` を持たない非 GET ルート 33 / 28 件」を、`M22-03` の着手時点で写そうとしたが、`M22-01` が `auth` 3 本・`M22-02` が `users` 2 本を足しており既に 38 / 31 件へ動いていた。** **⇒ 実測件数は指示書へ写さず、着手前実査で取り直させる。**

### 8-4. サブを後から新設したが、ボードの表へ行を足さなかった（`M22-07b`）

**`D-442` で `M22-07b` を新設したが、`parallel-board` §1.6 の表には行が足されなかった。** **⇒ 以後「全 9 サブ」という数え方が記録に定着し、本報告で数え直しが要った**（§0）。**★裁定行に書いただけでは、表を読む人には届かない。**
