## 2. 扱うテーマ（(i) と (j) を**一体で**設計する）

### (i) チェーンキャンセル

SF6 では、弱P → 弱P のように弱攻撃を続けて出すとき、**前の弱攻撃の硬直を取り消して次を出せます**。これがセットプレイ自動提案に 2 つの問題を生んでいます（開発者提起 2026-07-26）。

1. **過大計上**: 現行の提案は「空振り＝技の全体フレーム（`total`）を消費」の一択で計算しているため、弱攻撃を連続で含むレシピは**実機よりフレーム収支が長く見積もられている可能性**がある。人間の入力では使えない提案になっているかもしれない。
2. **取りこぼし**: 逆にキャンセル短縮を考慮すると**成立する新しいレシピが増える**。それを今は取りこぼしている。

### (j) 派生技フレームモデル（`startup_basis` ＋ 表記用親参照）

既に M19 から中央へ利用側要件 **R1〜R7**（`M19-DESIGN-01-central-requirements.md` v1.0.1）を提出済みでしたが、**設計主体が M19 へ移りました**。R1〜R7 は**そのまま生きた要件**です。これを満たす設計を、(i) と同じモデルの中で作ってください。

## 3. (i) と (j) が「同じ根」である理由（設計の出発点）

`moves` の `startup` / `total` は、**「その技を単独で出したときの値」なのか「連携の中で実際に消費される値」なのかを、行を見ても区別できません**。

| 現象 | 中身 | 状態 |
|---|---|---|
| **派生技の通し値** | パターン 1・2・4 × 条件 C・D の派生技は、**親の入力フレームを 1 とした実測値**を記録する（親は最速キャンセルされるため**親の `total` は消費されない**） | **記録規約は開発者確認で確定済み**（2026-07-23）。GC-2 で 1F の狂いなく検証済み |
| **`rush_variant`** | 元技 **+11 ＝ ラッシュ分＋技分の通し値** | **開発者回答 2026-07-26 で確定**＝「ニュートラル起点で、ラッシュを最速キャンセルして技を出したときのラッシュ分＋技分」。**+11 は実測で正しい**。followup (e) はクローズ済み |
| **`target_combo` の `total`** | 「派生部分のみ」か「連携全体」か**判別不能**（加算検算で乖離・負値も発生） | M19-RESEARCH-03 R-C。**判別列が現行スキーマに無い**（DES-003 §3.3 errata③ に明記済み） |
| **チェーンキャンセル** | 表の `total` は最後まで硬直した場合の値だが、**チェーンすると親技は途中でキャンセルされる**＝実消費が違う | **未着手（本委任の主題）** |

**帰結**: `S = Σ(filler.total) + target.startup` という計上式に対し、**「そのステップが実際に何フレーム消費するか」を行から決定できない**のが共通の根です。**別々に列を足すと通し値の扱いが 3 通り以上生まれる**ため、**1 つのモデルとして設計してください**（中央の整合観点）。

> **★重要な精密化（M19 指示書担当より・中央文書からの補正）**
> 中央文書は「通し値を足せば二重計上」と書いていますが、これは不正確です。**通し値それ自体は問題ではありません**。実際 `rush_variant` は通し値ですが、**親（ラッシュ発動）を別ステップとして計上していない**ため二重計上は起きておらず、現状で正しく動いています。**問題が起きるのは「通し値の技の親を、別ステップとして重ねて計上したとき」だけ**です（GC-2 がこれ）。したがって設計の対象は「値の意味」ではなく **「あるステップ列において、各ステップが実際に消費するフレーム数を決定する規則」** です。ここを取り違えると、**壊れていない `rush_variant` を「直して」しまいます**。

## 4. 前提として既に確定していること（ここは動かさない）

- **重ね判定の式**（DES-003 §3.4 に明文化済み）: `knockdown_advantage`（KA）＝ダウン中の無敵時間。相手の起き上がりは **KA+1** フレーム目。`S = Σ(先行ステップの total) + target の startup`（＝当てたい技の第 1 active の絶対フレーム）。`N = KA + 2 − S`。成立条件 `1 ≤ N ≤ active`。
- **汚連携（あえて重ねない）のギャップ** `G = 1 − N`（M19-02 で実装中）。上式から代数的に導かれます。**新しい式を持ち込まないでください**。
- **既存列の値の解釈を変えない**（中央の整合観点）。`startup` / `total` の既存値を書き換えると M18-02 の確定反撃走査・既存コンボの表示・CSV 互換に波及します。**新しい意味は新しい列に置く**のが安全側です。
  - ただし注意: **既存値の意味は現時点で一様ではありません**（通し値・単発値・段の発生が混在）。「既存の解釈を守る」は「**既に入っている数値を書き換えない**」の意であって、「意味が一つに決まっている」という意味ではありません。
- **`is_derived` は「単独入力不可」ではありません**。実態は「入力トークン単独では技を解決できない（＝コマンド索引から除外する）」であり、**単独で出せる技にもコマンド衝突回避で true が付きます**（514 行中 96 行以上）。**本件のマーカーに流用できません**（DES-003 §3.3 errata③ に明記済み）。
- **`category = target_combo` は `is_derived` と 1 対 1 ではありません**（`is_derived=false` の target_combo が 4 行実在）。
- **M19-02 では filler から `category = target_combo` を除外済み**です（`total` の意味が判別不能なため）。あなたの設計で判別できるようになれば、**この除外を解除できます**——それが本設計の成果の 1 つになります。

## 5. 開発者と詰めるべき論点（中央が挙げた 4 点＋M19 からの追加）

中央はこれらを開発者へ質問しましたが、**M19 側で会話する方針**になりました。設計にはこの答えが要ります。

1. **チェーンできる組み合わせは規則で決まるか**（弱P→弱K のように一覧化できるか）、それとも技ごとに個別か。
2. **チェーンしたとき親技が実際に消費するフレームは何で決まるか**（キャンセル可能になるフレーム＝技ごとの固定値か／入力タイミングで変動するか）。
3. **公式フレーム表の `target_combo` の「全体」は何を指すか**（1 段目から最後までか／その段だけか）。※データ側からは判別不能と結論済み（RESEARCH-03 R-C）なので、**答えは開発者または公式表の読み方からしか得られません**。
4. **通し値になっている技は rush 版と `target_combo` 以外にもあるか**（SA キャンセル・必殺技派生など）。
   > **既に一部わかっています**（M19-DESIGN-01 §3-4）: 同一 CSV 内に**通し値**（流酔拳 2 発止め su33）・**初段発生**（幻酔舞系 TC＝全変種 su12）・**段自体の発生らしき値**（乱酔旋 3 段目 su14/su4）が混在しています。**行単独で意味論を判別する手段がありません**。この既知事実を出発点にしてください。
5. **（M19 追加）チェーンキャンセルは「空振り」でも成立するか**。セットプレイの filler は**空振り**です。ヒット時・ガード時にしかチェーンできないなら、**提案の filler としては使えません**（＝(i) は「取りこぼしの回復」ではなく「過大計上の是正」だけが論点になる）。**ここで設計の規模が大きく変わります。最初に確認してください。**
6. **（M19 追加）チェーンの短縮量は「親の total を丸ごと消さない」のか**。派生技の通し値規約は「親は計上ゼロ」でしたが、チェーンは「親を途中まで出してからキャンセル」なので**部分消費**のはずです。**同じ規約で吸収できるのか、別の表現が要るのか**が設計の分岐点です。

## 6. 併せて判断してほしいこと（中央の整合観点 §3-3）

フラグが増殖しないよう、本設計と**同時に**判断してください。

### (f) `is_aerial` の意味乖離

- DES-003 §3.3 の文言は「**空中判定。ジャンプ攻撃・空中技は true**」ですが、実態は**ラッシュ可否の導出**（`category ∈ {normal, unique}` かつ `is_aerial = false`）と**段階2 解決表の除外**にも使われており、**ジャンプ入力起点の必殺技（ジェイミー無影蹴）は false** です。
- DES-003 は「**空中必殺技の false は無害**」と書いていますが、これは**段階2（コマンド索引）にとって無害**という意味です。**M19 にとっては有害**です——M19 は `is_aerial = false` を「スカラーの `S` で表現できる技」のゲートに使っているため、**false の空中必殺技がゲートを通過します**。
- **errata③ では is_aerial は是正されていません**（是正されたのは `is_derived`／`is_projectile`／`setup_only`／`target_combo` の 4 点）。**未解決です。**

### (a) B 型 air-only 技の除外

- 「最速で出しても当たらない空中技」（例: ケン空中竜巻旋風脚）は `is_derived=false`・`is_aerial=false`・basis も standalone になり、**全ゲートを通過**します。M19-01 では誤提案として出得ることを MVP 許容としました（件数は機械判別不能ゆえ未定量）。
- **(f) と (a) は同じ根です**: いずれも「**その技を単独で最速入力したとき、意図した位置に当たるか**」という軸が列として存在しないことに起因します。**別々のフラグを 2 本足さないでください。**
