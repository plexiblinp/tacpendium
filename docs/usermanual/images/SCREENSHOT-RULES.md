# 操作説明書のスクリーンショット — 撮影と貼り込みのルール

このフォルダは `tacpendium-readme.html`(本編)と `tacpendium-quickstart.html`(クイックスタート)が参照する図の置き場です。機能変更で画面が変わり、撮り直しや図の追加が要るときは本書に従ってください。

- 撮影は開発者の手番です(Claude 側でスクリーンショットを作らない)
- 貼り込み(`img` の追加・`todo` の解除)は Claude 側でよい
- 本ファイルは配布アーカイブに同梱しません(`scripts/release-targets.sh` の `RELEASE_MANUAL_EXCLUDE`)

## 1. 命名規約

- 本編の図: `ch<NN>-<slug>-<n>.png`
  - `ch<NN>` = 本編の章番号(2 桁・連番)。章を消したら後続の番号を詰める(章 id・TOC・`img src`・本ファイルの章番号をまとめて追従する)
  - `<slug>` = 章のスラッグ(例: `wizard` / `combo-editor` / `game-update`)
  - `<n>` = その章の何枚目か。入口の図など「本題の前」に置く図は `0` でもよい(例: `ch18-game-update-0.png`)
  - 例: `ch01-wizard-1.png` / `ch08-combo-editor-2.png`
- クイックスタートの図: 接頭辞 `qs-`(例: `qs-first-combo-1.png`)。本編の番号と衝突させない
- 章番号とスラッグの対応の正本は `tacpendium-readme.html` の各 `<figure>` の `img src` です。本ファイルに一覧を写さない(写すと必ずずれる)
- 形式は PNG(JPEG は UI の文字がにじむ)

## 2. 何を撮るか

画面全体を写す必要はありません。判断基準は 1 つだけです。

> 本文が名指ししている語を、読者が画面上で見つけられるか

- 複数ページある画面(初回起動ウィザード等)は、つまずきどころが起きる段だけを撮る
- 1 画面に収まらない画面(設定等)は、各セクションの見出しが見える程度でよい。中身を全部開かなくてよい
- 折りたたみ・展開がある画面は、たたんだ状態で十分。本文が展開後を語っている箇所だけ開く
- 例外: 本文が画面の「構造」を主張している箇所は、その主張が写真で裏切られないようにする(読者は本文より写真を信じる)
  - 例: 「入力欄は 2 枚のタブに分かれています」→ タブの見出し 2 つが写っていること
  - 例: 「全部で 8 段」→ 「ステップ 7 / 8」の表示が入っていること

## 3. 撮影の設定

表示幅は固定です(本編 712px / クイックスタート 632px。`.wrap` の `max-width` から padding を引いた値)。見かけの倍率は「712 ÷ 撮影時のビューポート幅」で決まり、DPR ではありません。フル HD(1920px)の全画面撮影は 0.37 倍になり、14px の文字が 5px 相当で潰れます。

- 推奨: Chrome DevTools の device toolbar を Responsive にし、ビューポート 1100 x 800 / DPR 2(PNG は 2200 x 1600px)。撮影は同メニューの Capture screenshot(ブラウザ枠が入らない)
- 横に広い表が主役の章(コンボ一覧・マイコンボ・コンボ比較など)は 1440 x 900 で撮るか、列を数本たたんでから 1100 で撮る
- スマホ専用の章(ホーム)は 390 x 740 / DPR 3(1170 x 2220px)。ここだけ倍率が反転し、390px 幅を 712px で出すと 1.8 倍に拡大されるため、DPR 2 では画素が足りない。表示側は本編の `<style>` でこの章の図だけ `max-width:340px` に抑えてある(セレクタは `figure img[src*="ch<NN>-"]`。章番号を詰めたらここも追従する)

## 4. 貼り込みのルール

- 図の枠は `<figure class="shot">` + `<img>` + `<figcaption>` の形。撮影が済むまでは `class="shot todo"`(点線の枠と背景色で未記入と分かる)にし、撮り終えたら `todo` を外す。`todo` を残すと配布物にそのまま出る
- `figcaption` には読者向けのキャプションだけを書く。「撮影は開発者の手番」「ファイル名は …」のような制作メモは書かない(配布物の読者に見える)
- 貼り込んだら、`img src` の全数が実在すること(`src` の一覧と `ls images/` の突き合わせ)と、`todo` が 0 件であることを確かめる
- 「現在準備中です」のような仮置きの文言を本文に残さない
